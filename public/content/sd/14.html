👋 Intro

Containers and images, Kubernetes architecture and core objects, autoscaling, service discovery patterns, service meshes, and running GPU workloads on Kubernetes.

Docker and Containers

🌱 Beginner

Before shipping containers, every cargo type needed different handling. The standard steel box changed everything: any crane, ship, or truck can move it. A software container is that box. Your app and everything it needs are packed together, so it runs the same on a laptop, a test server, or the cloud.

Containers share the host kernel, so they start in milliseconds and use far less memory than VMs.

🔧 Intermediate

A container is an isolated process using Linux namespaces (what it can see: PIDs, network, mounts) and cgroups (what it can use: CPU, memory). An image is a stack of read-only layers built from a Dockerfile and stored in a registry; standards are defined by the OCI.

# ---- build stage ----
FROM golang:1.23 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download                 # cached layer unless deps change
COPY . .
RUN CGO_ENABLED=0 go build -o /app ./cmd/server

# ---- runtime stage: tiny, no shell, non-root ----
FROM gcr.io/distroless/static:nonroot
COPY --from=build /app /app
USER nonroot:nonroot
EXPOSE 8080
ENTRYPOINT ["/app"]
🧠 Expert

Image hygiene: pin base images by digest, use minimal bases (distroless, Chainguard, Alpine), order layers from least to most frequently changed, use .dockerignore, run as non-root with a read-only root filesystem, never bake secrets into layers (use BuildKit secret mounts), and scan images (Trivy, Grype). Sign images (Sigstore cosign) and attach an SBOM. Containers are not a strong security boundary; for untrusted code (including code written by AI agents) use sandboxes such as gVisor, Kata Containers, or Firecracker microVMs.

Kubernetes

🌱 Beginner

If containers are shipping boxes, Kubernetes is the port authority. You tell it “I want five copies of this box running at all times,” and it finds space on ships, replaces boxes that fall overboard, and adds more when the port gets busy.

Kubernetes architecture: a declarative control plane reconciling worker nodes.

🔧 Intermediate

Core idea: declarative reconciliation. You declare desired state in YAML; controllers continuously compare actual state to desired state and act to close the gap.

Object Purpose
Pod One or more containers sharing network and storage; the scheduling unit
Deployment Stateless app; manages ReplicaSets, rolling updates, rollback
StatefulSet Stable identity and storage per replica (databases, Kafka)
DaemonSet One pod per node (log agents, CNI, GPU device plugin)
Job / CronJob Run to completion / on a schedule
Service Stable virtual IP and DNS name for a set of pods
Ingress / Gateway API L7 routing from outside the cluster
ConfigMap / Secret Configuration and sensitive values
HPA / VPA / KEDA Scale replicas on CPU, memory, or custom metrics / queue depth
PodDisruptionBudget Keep minimum replicas during node maintenance 
apiVersion: apps/v1
kind: Deployment
metadata: { name: api }
spec:
  replicas: 3
  selector: { matchLabels: { app: api } }
  strategy: { rollingUpdate: { maxUnavailable: 0, maxSurge: 1 } }
  template:
    metadata: { labels: { app: api } }
    spec:
      containers:
      - name: api
        image: registry.example.com/api@sha256:3f9a...
        ports: [{ containerPort: 8080 }]
        resources:
          requests: { cpu: "250m", memory: "256Mi" }
          limits:   { memory: "512Mi" }
        readinessProbe: { httpGet: { path: /ready, port: 8080 }, periodSeconds: 5 }
        livenessProbe:  { httpGet: { path: /live,  port: 8080 }, periodSeconds: 10 }
🧠 Expert

Scheduling and capacity: requests drive scheduling; limits drive throttling (CPU) and OOM kills (memory). Many teams set memory limit = request and omit CPU limits to avoid throttling. Use topology spread constraints across zones, PodDisruptionBudgets, and priority classes. Cluster autoscaling with Karpenter provisions right-sized nodes in seconds.

Graceful shutdown: on termination, the pod is removed from endpoints at the same time SIGTERM is sent, so add a short preStop sleep, then drain in-flight requests within terminationGracePeriodSeconds.

GPUs on Kubernetes: the NVIDIA device plugin or GPU Operator exposes nvidia.com/gpu; Dynamic Resource Allocation (DRA), now generally available, allows finer GPU requests and sharing; MIG and time-slicing share one GPU across pods. LLM serving stacks such as KServe, llm-d, NVIDIA Dynamo, and the Gateway API Inference Extension add model-aware routing and autoscaling on top. Gang scheduling (Kueue, Volcano) is needed for multi-node training jobs.

Service Discovery

🌱 Beginner

In a city where shops move every day, you need a live directory telling you where each shop is right now. Service discovery is that directory for services whose containers start, stop, and move constantly.

Client-side discovery (client picks the instance) vs server-side (a load balancer picks).

🔧 Intermediate

Instances register on startup (self-registration or a platform registrar), send heartbeats, and are removed when they stop. Implementations:

  • Kubernetes: CoreDNS resolves orders.prod.svc.cluster.local to a Service IP; kube-proxy or eBPF (Cilium) load balances to ready pods via EndpointSlices. Headless Services return pod IPs directly.

  • Consul, etcd, ZooKeeper, Eureka: registries for VMs and mixed environments.

  • Cloud: AWS Cloud Map, ECS Service Connect.

  • xDS: Envoy’s API for pushing endpoints to proxies and gRPC clients.

Service Mesh

🔧 Intermediate

A service mesh moves networking concerns (mTLS, retries, timeouts, circuit breaking, traffic splitting, telemetry) out of application code into the infrastructure. Classic meshes inject an Envoy sidecar into every pod. Newer sidecarless designs reduce overhead: Istio ambient mode (per-node ztunnel for L4 mTLS plus optional waypoint proxies for L7) and Cilium (eBPF in the kernel). Linkerd uses a lightweight Rust proxy.

📦 Use case: Zero-downtime rolling deploy

A Deployment with maxUnavailable: 0 starts a new pod, waits for readiness, then removes an old one. If the new pods fail readiness, the rollout stalls instead of taking traffic, and kubectl rollout undo reverts.

📦 Use case: Queue-driven autoscaling

KEDA scales video-transcoding workers from 0 to 200 pods based on SQS queue depth; Karpenter adds spot GPU nodes as needed and removes them when the queue drains, cutting cost compared to always-on capacity.

📦 Use case: Zero-trust service-to-service traffic

Istio ambient mode gives every workload a SPIFFE identity and mutual TLS without code changes. An authorization policy states that only checkout may call payments on POST /charges.

🔑 Takeaways

  • Containers package apps; images should be small, pinned, signed, and non-root.

  • Kubernetes reconciles declared state; probes, requests, and PDBs make it reliable.

  • Service discovery maps names to live instances; in Kubernetes it is DNS plus Services.

  • Meshes provide mTLS and traffic policy; sidecarless modes cut overhead.
