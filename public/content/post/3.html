🚀 Starting point

A tokenizer maps text to integer IDs. Byte-pair encoding starts from the 256 possible bytes (so any text can be encoded) and repeatedly merges the most frequent adjacent pair into a new token, until the vocabulary reaches its target size. Common words become single tokens; rare words stay as several pieces.

✏️ Derivation: why vocabulary size is a trade-off

Step 1. Compression \(c\) = bytes per token. English text with a 50K–150K vocabulary gets about 4–4.5 bytes per token. A fixed amount of text costs \(\text{bytes}/c\) tokens, so better compression means more text per FLOP and longer effective context.

Step 2. Cost of a bigger vocabulary: the embedding and output layers have \(VD\) parameters each. For \(V=128\)K, \(D=4096\): 524M parameters per matrix, a big share of a small model. The softmax also costs \(O(V)\) per token.

Step 3. Rare tokens: a token seen only a few times during training gets a poorly trained embedding, so very large vocabularies need very large datasets.

Step 4. Typical choices: GPT-2 50K, SmolLM2 49K, Llama 3 128K, Gemma 4 262K (multilingual), Qwen3.8 248K.

"""Byte-pair encoding: the merge algorithm from scratch, then a real tokenizer with the `tokenizers` library.

Run:  python bpe.py
"""
from collections import Counter


def train_bpe(text: str, num_merges: int):
    """Start from bytes; repeatedly merge the most frequent adjacent pair into a new token."""
    ids = list(text.encode("utf-8"))
    merges = {}
    for step in range(num_merges):
        pairs = Counter(zip(ids, ids[1:]))
        if not pairs:
            break
        (a, b), count = pairs.most_common(1)[0]
        new = 256 + step
        merges[(a, b)] = new
        out, i = [], 0
        while i < len(ids):                       # replace every occurrence of (a, b)
            if i + 1 < len(ids) and ids[i] == a and ids[i + 1] == b:
                out.append(new)
                i += 2
            else:
                out.append(ids[i])
                i += 1
        ids = out
    return merges, ids


if __name__ == "__main__":
    corpus = "low lower lowest newer newest wider widest " * 50
    merges, ids = train_bpe(corpus, num_merges=20)
    n_bytes = len(corpus.encode())
    print(f"bytes {n_bytes} -> tokens {len(ids)}   compression {n_bytes / len(ids):.2f} bytes/token")
    vocab = {i: bytes([i]) for i in range(256)}
    for (a, b), new in merges.items():
        vocab[new] = vocab[a] + vocab[b]
    print("first merges:", [vocab[t].decode() for t in list(merges.values())[:8]])

    # A production-style byte-level BPE tokenizer.
    from tokenizers import Tokenizer, models, pre_tokenizers, trainers, decoders

    tok = Tokenizer(models.BPE())
    tok.pre_tokenizer = pre_tokenizers.ByteLevel(add_prefix_space=False)
    tok.decoder = decoders.ByteLevel()
    trainer = trainers.BpeTrainer(vocab_size=400, special_tokens=["<|endoftext|>"], show_progress=False,
                               initial_alphabet=pre_tokenizers.ByteLevel.alphabet())   # all 256 bytes, so any text encodes
    tok.train_from_iterator([corpus], trainer)
    enc = tok.encode("the newest lowest widest")
    print("tokens:", enc.tokens)
    print("round trip ok:", tok.decode(enc.ids) == "the newest lowest widest")

Pre-tokenization (the ByteLevel step) first splits text on spaces and punctuation, so merges never cross word boundaries. That’s why “newest” and “newest” can be different tokens. Training a real tokenizer is the same code with train_from_iterator over a few GB of your pre-training mix.
