🚀 Starting point

Three last steps before shipping. Distillation trains a small model on a big one’s outputs (offline, as SFT on teacher samples) or its per-token distribution (on-policy, RL book Topic 180; TRL’s GKDTrainer and DistillationTrainer). Merging averages fine-tuned weights. Evaluation measures the result on benchmarks the model never saw.

✏️ Derivation: why averaging weights can work

Step 1. Fine-tuning moves weights by a task vector \(\tau_i=\theta_i-\theta_{\text{base}}\), usually small relative to \(\theta_{\text{base}}\).

Step 2. Near the base, the loss is roughly quadratic, and two fine-tunes from the same base sit in the same basin. Averaging \(\theta_{\text{base}}+\frac1k\sum\tau_i\) often keeps most of each task’s gain (model soups, task arithmetic).

Step 3. It fails when task vectors interfere: TIES and DARE first drop small or sign-conflicting entries of each \(\tau_i\), then merge.

Step 4. It never works across different bases: weights from separate pre-training runs aren’t aligned neuron by neuron.

Evaluation checklist (with lighteval or lm-evaluation-harness):

  • Decontaminate first (Chapter 3), against every reported benchmark.

  • Use the model’s chat template and the same generation settings for every model compared.

  • Report pass@1 with several samples and a confidence interval (LLM Fundamentals, Sessions 43–44), plus pass@\(k\) if you’ll deploy with retries.

  • Keep a held-out set that you never look at during development, for the final number.
