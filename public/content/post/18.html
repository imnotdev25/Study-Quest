🚀 Starting point

Beyond chat, labs build data for each skill they want: math and code with verifiers, tool use and agents with executable environments, long context with retrieval tasks, multilingual by translation. As of October 2026 the frontier is less “more SFT data” and more “more environments that can check an answer.”

  • Math: GSM8K and MATH for evaluation; DeepMath-103K, OpenThoughts and NuminaMath for training; persona-generated problems to cover more domains.

  • Code: unit-tested problems (APPS, CodeContests, LiveCodeBench for evaluation); verifiers run the tests in a sandbox. Modal’s sandboxes are one way to run untrusted generated code safely.

  • Tool use and agents: SFT on tool-call transcripts (TRL supports a tools column), then RL in environments: TRL’s environment_factory and the OpenEnv project; software-engineering gyms; search agents.

  • Personas at scale: NVIDIA keeps releasing region-specific persona sets (nvidia/Nemotron-Personas-*, 1M rows each; the UK, Germany and Vietnam sets were updated this month).

What I found trending this week (Hugging Face trending datasets and arXiv cs.CL new submissions, read October 2026): reasoning-trace distillation sets from frontier models, small RL environment releases (e.g. FineEnvs/openai-math), open RL data from model releases (XiaomiMiMo/MiMo-V2.6-RL-oss), and papers on instruction-following training data with less reward hacking (LIFT, arXiv 2610.28819) and machine-translated parallel pre-training data (arXiv 2610.28838). TRL v1.16’s experimental trainers point the same way: asynchronous GRPO, on-policy and self-distillation (SDFT, SDPO, IWOPD).

🔑 Key ideas

  • Synthetic data quality comes from the filter, not the generator: verify, judge, deduplicate, decontaminate.

  • Keep real data in the mix; accumulate, don’t replace.

  • For new capabilities, the scarce resource is now checkable tasks and environments.
