🚀 Starting point

A modern LLM is built in stages. Each stage uses the same next-token machinery from LLM Fundamentals, but different data and a different objective: pre-training (trillions of web tokens, learn language and knowledge), mid-training (higher-quality and longer data, sharpen skills), supervised fine-tuning (conversations, learn to follow instructions), preference optimization (pairs of better/worse answers, learn taste), and RL with verifiable rewards (problems with checkable answers, learn to reason). Synthetic data made by other LLMs now feeds every one of them.

The stages in order. Compute is spent overwhelmingly on the left; behaviour is shaped mostly on the right.

✏️ Derivation: how big a run can a budget buy?

Step 1. Training FLOPs \(C\approx6ND\): \(N\) parameters, \(D\) tokens. Every token costs about \(2N\) FLOPs forward and \(4N\) backward (LLM Fundamentals, Session 10).

Step 2. A GPU delivers \(\text{MFU}\times\text{peak}\) useful FLOP/s. An H100’s dense BF16 peak is \(989\times10^{12}\) FLOP/s, and good runs reach 35–50% MFU.

Step 3. Wall time \(=\dfrac{6ND}{\text{MFU}\cdot\text{peak}\cdot\#\text{GPUs}}\).

Step 4. This book’s pre-training run (Chapter 5): \(N\approx123\)M, \(D=328\)M tokens: \(6\cdot1.23\times10^8\cdot3.28\times10^8=2.4\times10^{17}\) FLOPs. At 40% MFU on one H100: \(2.4\times10^{17}/(0.4\cdot9.89\times10^{14})\approx610\) s, about 10 minutes of pure compute.

Step 5. A Chinchilla-sized version (\(D=20N=2.5\)B tokens) is \(7.5\times\) that: about 1.3 H100-hours. Llama 3 8B (\(15\)T tokens): \(7.2\times10^{23}\) FLOPs, about \(500{,}000\) H100-hours at 40% MFU. That gap is why this book pre-trains small and post-trains real models.

🔑 Key ideas

  • Same loss family everywhere; what changes is the data and which tokens count.

  • Estimate any run with \(6ND\) and MFU before spending money on it.
