🚀 Starting point

DPO needs pairs and a reference model, and it never sees its own outputs. TRL v1.16 ships alternatives that relax each of those: KTOTrainer (unpaired labels), ORPOTrainer and CPOTrainer (no reference model; experimental), OnlineDPOTrainer (fresh pairs each step; experimental) and RLOOTrainer (online RL with a leave-one-out baseline). The losses are derived in the RL book, Topics 175–178.

Trainer data reference model? choose it when
DPO pairs yes you have good pairs and want a simple, stable run
KTO single responses with a label yes your feedback is thumbs up/down, or pairs are expensive
ORPO / CPO pairs no you want SFT and preference tuning in one stage, or less memory
Online DPO prompts + a judge or RM yes offline DPO has plateaued (RL book, Topic 178)
RLOO prompts + a reward function optional you want online RL without GRPO’s std normalization
GRPO prompts + verifiers or env optional (\(\beta\)) rewards are checkable; the default for reasoning
✏️ Derivation: KTO’s reference point, in one step

Step 1. KTO scores each response by \(h=\beta\log\frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}\) and compares it with \(z_0\), a batch estimate of \(\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})\) (the kl logged above).

Step 2. Desirable: loss \(1-\sigma(h-z_0)\). Undesirable: \(1-\sigma(z_0-h)\). A good response must beat the policy’s typical drift, not just 0, so the model can’t win by moving every response’s likelihood up together.

Step 3. With unbalanced labels (say 10\(\times\) more thumbs-down), set desirable_weight so \(\lambda_Dn_D/(\lambda_Un_U)\) lands between 1 and about 4/3, the range the KTO paper recommends.
