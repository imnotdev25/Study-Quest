🧩 Analogy: paying an employee per email sent

Pay staff per email sent and you’ll get a lot of emails, not more work done. A per-tool-call bonus does the same to an agent: it learns to call tools, not to solve tasks. Shaping rewards silently redefine the task unless they’re designed so they can’t change which behaviour is best.

A \(+0.1\) per-call bonus makes the failing, spammy trajectory rank first.

2. Extra rewards can silently redefine the task

Suppose the real objective rewards successful completion:

\[r_t^{\text{task}}\]

To encourage tool use, we might add a bonus:

\[r_t' = r_t^{\text{task}} + c\cdot \mathbf 1[\text{tool called}]\]

This does not merely accelerate learning. It changes the objective. An agent may learn to call unnecessary tools because each call earns reward.

A safer construction is potential-based shaping:

\[r_t' = r_t + \gamma\Phi(s_{t+1}) - \Phi(s_t)\]

Here, \(\Phi(s)\) estimates progress rather than rewarding a particular action. Across a trajectory, shaping terms telescope:

\[G_0' = G_0 -\Phi(s_0) +\gamma^T\Phi(s_T)\]

If all compared trajectories share the same initial potential and terminal potential is handled consistently, their ordering is preserved.

Think of potential shaping as giving temporary progress credit that must be paid back unless it leads somewhere. A raw tool-call bonus is like paying a taxi by the number of turns rather than whether it reaches the destination.

Limits:

  • the potential must depend on state, not the action you want to force;

  • use the same discount factor as the RL objective;

  • terminal potentials require careful handling;

  • an incorrect or non-Markov progress signal can still cause exploitation;

  • always evaluate raw task reward separately from shaped reward.

Tensor shapes:

  • transition rewards and shaping terms: [T]

  • state potentials: [T+1]

  • discounted trajectory return: scalar

DPO can also learn unnecessary tool use if preferred traces systematically contain more calls. Because it optimizes fixed preferences, this is a data-labeling bias rather than online reward shaping.

🔍 Deeper: potential-based shaping keeps the goal

Add \(F(s,s')=\gamma\Phi(s')-\Phi(s)\) for any function \(\Phi\) of the state. Along a trajectory it telescopes: \(\sum_t\gamma^tF(s_t,s_{t+1})=\gamma^T\Phi(s_T)-\Phi(s_0)\), which doesn’t depend on the path taken. So shaped and unshaped returns differ only by terms that can’t change which policy is optimal (Ng et al., 1999). A per-call bonus is not of this form. It rewards the path, so it changes the optimum.

🔑 Key ideas

  • Reward outcomes, not activity that looks like progress.

  • If you shape, use potentials and check that trajectory rankings are unchanged.

🚶 Walkthrough: rank check

Solved with 1 call: raw 1, shaped \(1+0.1=1.1\). Failed with 12 calls: raw 0, shaped \(1.2\). The ranking flipped, so the shaping is broken. A potential \(\Phi=\)“fraction of required facts retrieved” adds the same amount to any path that ends in the same state, so the ranking holds.

Common mistakes

  • Logging only shaped reward (the raw task reward disappears from view).

  • Shaping on actions rather than states.

  • Forgetting the terminal \(\Phi(s_T)\) term with \(\gamma<1\).

Debugging experiments

Set every tool transition’s bonus to 1.0. The agent is now strongly rewarded for making trajectories longer.

Use a different discount factor inside the shaping term. The terms no longer telescope with the actual return calculation, so trajectory ordering may change.

Set the terminal potential to a large positive value. Unless terminal-state handling is consistent, trajectories of different lengths receive different residual bonuses:

\[\gamma^T\Phi(s_T)\]

Finally, log only shaped reward. Training may appear successful while actual task success, latency and tool cost deteriorate.

Solutions

Discounted return:

def discounted_return(rewards):
    powers = gamma ** torch.arange(
        rewards.shape[0],
        dtype=rewards.dtype,
    )

    return (
        powers * rewards
    ).sum()

Potential shaping:

shaping = (
    gamma * potentials[1:]
    - potentials[:-1]
)

Shaped rewards:

shaped_rewards = (
    rewards + shaping
)

Original and naive returns:

original_returns = torch.stack([
    discounted_return(
        direct_rewards
    ),
    discounted_return(
        detour_rewards
    ),
])

naive_returns = torch.stack([
    discounted_return(
        direct_rewards
    ),
    discounted_return(
        detour_rewards + tool_bonus
    ),
])

Potential-shaped returns:

direct_shaped, direct_shaping = (
    potential_shape(
        direct_rewards,
        direct_potentials,
    )
)

detour_shaped, detour_shaping = (
    potential_shape(
        detour_rewards,
        detour_potentials,
    )
)

potential_returns = torch.stack([
    discounted_return(
        direct_shaped
    ),
    discounted_return(
        detour_shaped
    ),
])

The original returns are:

\[G_{\text{direct}}=1\]

\[G_{\text{detour}} = 0+\gamma(0)+\gamma^2(1) = 0.81\]

With naïve tool bonuses:

\[G_{\text{detour}}^{\text{bonus}} = 0.2+0.9(0.2)+0.9^2(1) = 1.19\]

The bonus therefore reverses the preferred behavior.

For the detour, potential shaping terms are:

\[[0.45,\;-0.05,\;-0.5]\]

The shaped return remains:

\[0.45+0.9(-0.05)+0.9^2(0.5) = 0.81\]

The initial progress credit is later cancelled because it did not create a better terminal outcome.

Check answers

  1. It changes which trajectories maximize return, potentially making redundant calls optimal.

  2. Every intermediate potential appears once positively and once negatively with matching discount factors.

  3. Incorrect discounting, inconsistent terminal potentials, non-Markov potentials or action-specific “progress” signals can change behavior ordering.

  4. Log raw success reward, shaped reward, tool-call count, latency, monetary cost, failure rate, return by trajectory length and independent task quality.

Retrieval answers

  1. Otherwise, rewards from another prompt can propagate backward and assign fictitious credit to earlier actions.

  2. A larger \(\gamma\) discounts delayed rewards less, giving earlier actions stronger credit but often increasing variance.

Takeaway: reward the outcome, not activity that merely resembles progress. If shaping is needed, keep raw task reward visible and test whether trajectory rankings remain unchanged.
