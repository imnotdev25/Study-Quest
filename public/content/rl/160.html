2. A verifier answers “did it work?”

For mathematics, code and structured tasks, a deterministic verifier can produce:

\[R(x,y) = \underbrace{ \mathbf 1[v(x,y)=\text{pass}] }_{1\text{ if the answer passes; otherwise }0}\]

Examples include exact answers, unit tests, theorem checkers and schema validators.

The policy objective becomes success probability:

\[J(\theta) = \underbrace{ E_{y\sim\pi_\theta(\cdot\mid x)} [R(x,y)] }_{P_{\pi_\theta}(\text{success})}\]

A policy-gradient estimate is:

\[\nabla_\theta J \approx \underbrace{ (R-b) }_{\text{success relative to baseline}} \underbrace{ \nabla_\theta\log\pi_\theta(y\mid x) }_{\text{increase or decrease completion probability}}\]

Verification avoids subjective reward-model scaling, but binary rewards are sparse. If every sampled completion fails, the batch reveals no successful behaviour to reinforce.

Sampling \(K\) independent completions from a policy with per-sample success probability \(p\) gives:

\[\operatorname{pass@}K = \underbrace{ 1-(1-p)^K }_{\text{probability that at least one sample succeeds}}\]

Pass@\(K\) may look strong even when pass@1 is poor. It measures a policy-plus-search system, not single-completion reliability.

For \(K\) completions of the same prompt, a group contains useful relative information only when some pass and some fail:

\[P(0<S<K) = \underbrace{ 1-(1-p)^K-p^K }_{\text{not all failures and not all successes}}\]

Hard prompts produce mostly all-failure groups; easy prompts produce mostly all-success groups. Both yield zero centered advantage.

A within-prompt standardized signal is:

\[A_{ij} = \underbrace{ \frac{ R_{ij}-\bar R_i }{ \sqrt{ \frac1K\sum_j(R_{ij}-\bar R_i)^2+\epsilon } } }_{\text{completion }j\text{ relative to the same prompt}}\]

This will become useful for group-relative optimization, but normalization cannot create information when all rewards are equal.

Verifier correctness is crucial. A policy will exploit:

  • incomplete unit tests;

  • parser ambiguities;

  • accepted exceptions or timeouts;

  • floating-point tolerances;

  • answer leakage or formatting shortcuts.

DPO instead learns from frozen preferred/rejected pairs. Verifier-based online RL generates new completions and can discover new successes—or new verifier exploits.

Shapes:

  • success probabilities: [P]

  • sampled verifier outcomes: [N, P, K]

  • one rollout group’s rewards and advantages: [P, K]

  • toy completion-policy logits: [P, K, A]

Hints

  • Pass@1 is the average of all individual samples.

  • Pass@K uses .any(dim=2).

  • A mixed group satisfies 0 < success_count < K.

  • Theoretical mixed probability subtracts both all-failure and all-success probabilities.

  • Use unbiased=False logic: mean squared deviation.

  • Apply .detach() to advantages in the actor loss.

Debugging checks

  • Report pass@\(K\) as though it were pass@1 accuracy.

  • Normalize across unrelated prompts rather than within each prompt.

  • Divide by a zero group standard deviation without an epsilon.

  • Keep resampling only successful outputs and lose the actual deployment distribution.

  • Treat verifier exceptions or timeouts as passes.

  • Assume deterministic verification implies the specification is complete.

  • Hide all-failure group frequency behind overall average reward.

4. Checks for understanding

Solutions

Simulation and pass rates:

simulated_successes = (
    torch.rand(
        num_trials,
        num_prompts,
        group_size,
    )
    < success_probabilities[
        None, :, None
    ]
)

empirical_pass_at_1 = (
    simulated_successes
    .to(torch.float64)
    .mean(dim=(0, 2))
)

empirical_pass_at_k = (
    simulated_successes
    .any(dim=2)
    .to(torch.float64)
    .mean(dim=0)
)

Mixed-group probabilities:

success_counts = (
    simulated_successes.sum(dim=2)
)

empirical_mixed_group_rate = (
    (
        (success_counts > 0)
        & (success_counts < group_size)
    )
    .to(torch.float64)
    .mean(dim=0)
)

theoretical_pass_at_k = (
    1.0
    - (
        1.0
        - success_probabilities
    ).pow(group_size)
)

theoretical_mixed_group_rate = (
    1.0
    - (
        1.0
        - success_probabilities
    ).pow(group_size)
    - success_probabilities.pow(group_size)
)

Group advantages:

group_means = batch_rewards.mean(
    dim=1,
    keepdim=True,
)

centered_rewards = (
    batch_rewards
    - group_means
)

group_variances = (
    centered_rewards.square().mean(
        dim=1,
        keepdim=True,
    )
)

group_advantages = (
    centered_rewards
    / torch.sqrt(
        group_variances + 1e-8
    )
).detach()

informative_groups = (
    group_variances.squeeze(1) > 0.0
)

Actor loss:

actor_loss = -(
    group_advantages
    * chosen_log_probabilities
).mean()

Diagnostics:

centered_sum_error = (
    group_advantages.sum(dim=1)
).abs().max()

uniform_groups = ~informative_groups

largest_uniform_group_gradient = (
    group_gradient_norms[
        uniform_groups
    ].max()
)

For \(p=0.10\) and \(K=8\):

\[\operatorname{pass@8} = \underbrace{ 1-0.9^8 }_{\text{at least one success}} \approx0.570\]

Yet pass@1 remains only \(0.10\). Sampling found more opportunities; the underlying per-completion policy did not improve.

For \(p=0.02\):

\[P(\text{mixed group}) = 1-0.98^8-0.02^8 \approx0.149\]

Most groups still contain no successful example. Conversely, at \(p=0.90\), many groups are all successes. The first and last deterministic groups therefore have zero advantages and zero gradients.

Check answers

  1. More samples increase the chance that at least one succeeds even if the single-sample distribution is unchanged.

  2. Subtracting the group mean gives every member zero when all rewards are identical; there is no within-prompt ranking information.

  3. Generation and verification cost grow approximately linearly with \(K\), while large groups also increase memory and rollout latency.

  4. The policy optimizes what the verifier checks. Any untested requirement becomes a potential shortcut even if checked cases are scored perfectly.

Retrieval answers

  1. Set the new coefficient to \(c\beta\); then the entire shaped objective is multiplied by \(c\) without changing the task–KL trade-off.

  2. The critic should predict the real shaped-return scale. Moving normalized targets would make its units batch-dependent and obscure calibration.

Takeaway: verifiable rewards are objective only relative to the verifier’s specification. Sampling more completions helps expose rare successes, but pass@\(K\) is not pass@1—and groups with no outcome diversity provide no relative learning signal.
