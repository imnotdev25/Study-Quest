2. Your own score should not grade your baseline

Suppose \(K\) completions are sampled independently for one prompt. A group-relative advantage is often:

\[A_i = R_i-\bar R, \qquad \bar R=\frac1K\sum_{j=1}^K R_j\]

This removes prompt difficulty without training a critic. However, \(\bar R\) includes \(R_i\), so the baseline depends partly on the same sampled action whose gradient it weights.

Without standard-deviation normalization:

\[E[\hat g_{\text{inclusive}}] = \left(1-\frac1K\right)\nabla_\theta J\]

Thus, group size 2 halves the expected gradient; group size 8 retains seven-eighths.

A leave-one-out baseline avoids this:

\[b_{-i} = \frac1{K-1} \sum_{j\ne i}R_j\]

\[A_i^{\text{LOO}} = R_i-b_{-i}\]

Conditional on the prompt, \(b_{-i}\) is independent of completion \(i\)’s action, so:

\[E[ \nabla\log\pi(a_i)A_i^{\text{LOO}} ] = \nabla J\]

This is the key idea behind REINFORCE leave-one-out methods.

GRPO commonly standardizes within each group:

\[A_i^{\text{GRPO}} = \frac{R_i-\bar R} {\sigma_R+\epsilon}\]

That changes gradient scale nonlinearly. Groups with identical rewards have zero relative signal, whether every completion is excellent or every completion fails.

Tensor shapes:

  • actions, rewards and advantages: [G, K]

  • group means and standard deviations: [G, 1]

  • policy-gradient estimates: scalars

DPO instead trains from fixed preferred/rejected pairs. It does not sample an online reward group or construct a leave-one-out baseline, so it remains preference optimization rather than online RL.

Debugging experiments

  • Use K=1, for which leave-one-out is undefined.

  • Divide by zero when all rewards tie.

  • Replace failed generations with reward zero without defining failure as zero utility.

  • Backpropagate through judge rewards or baseline statistics.

  • Compare runs with different group sizes while assuming normalized gradients have equal scale.

  • Report only mean reward without the fraction of zero-variance groups.

Solutions

Exact gradient:

policy_probability = torch.sigmoid(
    theta
)

exact_objective = policy_probability

exact_objective.backward()

exact_gradient = theta.grad.detach()

sampling_probability = (
    policy_probability.detach()
)

Sampling:

actions = (
    torch.rand(
        num_groups,
        group_size,
    )
    < sampling_probability
).to(torch.float64)

rewards = actions.clone()

score_gradients = (
    actions - sampling_probability
)

Raw and inclusive estimators:

raw_gradient = (
    score_gradients
    * rewards
).mean()

group_mean_rewards = (
    rewards.mean(
        dim=1,
        keepdim=True,
    )
)

inclusive_advantages = (
    rewards - group_mean_rewards
)

inclusive_gradient = (
    score_gradients
    * inclusive_advantages.detach()
).mean()

Leave-one-out estimator:

group_reward_sums = (
    rewards.sum(
        dim=1,
        keepdim=True,
    )
)

leave_one_out_baselines = (
    group_reward_sums - rewards
) / (group_size - 1)

leave_one_out_advantages = (
    rewards
    - leave_one_out_baselines
)

leave_one_out_gradient = (
    score_gradients
    * leave_one_out_advantages.detach()
).mean()

Standardization and diagnostics:

group_variances = (
    inclusive_advantages
    .square()
    .mean(
        dim=1,
        keepdim=True,
    )
)

group_standard_deviations = (
    group_variances.sqrt()
)

standardized_advantages = (
    inclusive_advantages
    / (
        group_standard_deviations
        + epsilon
    )
).detach()

standardized_gradient = (
    score_gradients
    * standardized_advantages
).mean()

zero_variance_fraction = (
    group_standard_deviations
    .squeeze(1)
    .le(epsilon)
    .to(torch.float64)
    .mean()
)

theoretical_inclusive_gradient = (
    (1.0 - 1.0 / group_size)
    * exact_gradient
)

theoretical_zero_variance_fraction = (
    sampling_probability.pow(
        group_size
    )
    + (
        1.0
        - sampling_probability
    ).pow(group_size)
)

For the inclusive baseline:

\[R_i-\bar R = \left(1-\frac1K\right)R_i - \frac1K\sum_{j\ne i}R_j\]

The cross-completion terms vanish in expectation because completion \(j\)’s reward is independent of completion \(i\)’s score gradient. Therefore:

\[E[\hat g_{\text{inclusive}}] = \left(1-\frac1K\right)g\]

Expected results are approximately:

\(K\) Raw Inclusive Leave-one-out
\(K\) Raw Inclusive Leave-one-out
2 0.25 0.125 0.25
4 0.25 0.1875 0.25
8 0.25 0.21875 0.25
16 0.25 0.23438 0.25

At \(p=0.5\), zero-variance group probabilities are:

\[P_0(K)=2^{1-K}\]

So they are:

  • \[K=2:\ 0.5\]

  • \[K=4:\ 0.125\]

  • \[K=8:\ 0.0078125\]

  • \[K=16:\ 0.0000305\]

Standardization does not simply undo the inclusive shrinkage. It applies a reward- and group-dependent scale, while zero-variance groups remain unable to express any relative preference.

Check answers

  1. Its baseline contains \(R_i/K\), reducing the coefficient on the sample’s own reward to \(1-1/K\).

  2. It depends only on other independently sampled completions, so it is action-independent for completion \(i\), conditional on the prompt.

  3. It cannot distinguish “all excellent” from “all terrible”; both yield zero relative advantages.

  4. Gather or all-reduce the complete group’s reward statistics before constructing advantages. Never normalize partial groups independently.

Retrieval answers

  1. Mean subtraction can change signs; division by a positive standard deviation only changes scale.

  2. Compute detached rollout-level statistics once, synchronize them across workers and reuse them throughout the rollout’s PPO epochs.

Takeaway: group-relative baselines remove prompt difficulty, but the exact baseline matters. Inclusive means shrink small-group gradients; leave-one-out preserves the expected REINFORCE gradient; standardization introduces its own group-size-dependent scale and loses all signal on tied groups.
