🧩 Analogy: a fine split across words

Imagine a teacher fines a wrong essay $10 total and spreads it across its words. A 50-word wrong essay pays 20 cents per word, while a 500-word wrong essay pays only 2 cents per word. Students quickly learn that if you’re going to be wrong, be long. GRPO’s \(1/|o_i|\) normalization creates exactly that incentive.

Magnitudes of the per-token weights from this topic’s exercise. GRPO pushes the short answer 4\(\times\) harder per token than the long wrong one. Dr. GRPO treats every token equally.

2. Two biases (Liu et al., 2025, “Understanding R1-Zero-Like Training”)

GRPO’s loss for response \(i\) is \(\frac1G\sum_i\frac{1}{|o_i|}\sum_t\hat A_i\,(\cdots)\) with \(\hat A_i=\frac{R_i-\bar R}{\operatorname{std}(R)}\).

  1. Length bias, from \(1/|o_i|\): a negative advantage spread over more tokens is weaker per token, so long wrong answers are under-penalized and length grows, especially for incorrect outputs. The paper names this as the reason response length kept growing in R1-Zero-style runs.

  2. Difficulty bias, from \(\operatorname{std}(R)\): prompts that are nearly always or never solved have a small std, so their advantages are scaled up (Topic 43).

Dr. GRPO removes both: \(\hat A_i=R_i-\bar R\) (no std), and a constant normalizer (e.g. the max generation length) instead of \(|o_i|\). The resulting gradient is an unbiased policy gradient, and the paper reports better token efficiency at similar accuracy.

🔍 Deeper: why a constant normalizer is unbiased

The true objective is \(\mathbb E[R(y)]\), whose gradient is \(\mathbb E[(R-b)\sum_t\nabla\log\pi(y_t|\cdot)]\): the sum over tokens, not the mean. Dividing by \(|o_i|\) reweights each sample by a quantity the policy controls (its own length), which changes the objective. Dividing by a constant \(C\) only rescales the gradient, which is the same as a smaller learning rate.

🔑 Key ideas

  • \(1/|o_i|\) rewards long wrong answers, and dividing by std over-weights easy and impossible prompts.

  • Dr. GRPO: subtract the mean, divide by a constant.

🚶 Walkthrough: the numbers in the chart

Group: short correct (5 tokens, \(R=1\)) and long wrong (20 tokens, \(R=0\)), \(G=2\). GRPO: \(\hat A=\pm0.707\). Per-token weights \(\frac{0.707}{2\cdot5}=0.0707\) and \(\frac{-0.707}{2\cdot20}=-0.0177\). Dr. GRPO: \(\hat A=\pm0.5\), normalizer \(G\cdot L_{\max}=40\), so per-token weights \(\pm0.0125\) for both.

Common mistakes

  • Removing std but keeping \(1/|o_i|\) (half the fix).

  • Using the batch’s current max length as the constant (it changes every batch).

  • Comparing learning rates across the two without rescaling.

  3. DAPO’s token-level loss divides by \(\sum_i|o_i|\). Is that a constant? Does it have the same bias?

Solutions

import torch

lengths = [5, 20]                # short correct answer, long wrong answer
rewards = torch.tensor([1.0, 0.0])
G, L_max = len(lengths), max(lengths)


def grpo_token_weights(r):
    adv = (r - r.mean()) / (r.std() + 1e-6)              # std normalization
    return [(adv[i] / (G * lengths[i])).item() for i in range(G)]   # 1/|y_i| per response


def dr_grpo_token_weights(r):
    adv = r - r.mean()                                   # no std
    return [(adv[i] / (G * L_max)).item() for i in range(G)]        # one constant normalizer


for name, fn in (("GRPO", grpo_token_weights), ("Dr. GRPO", dr_grpo_token_weights)):
    w = fn(rewards)
    print(f"{name:9s} per-token weight: short {w[0]:+.4f}  long {w[1]:+.4f}  "
          f"total on long response {w[1] * lengths[1]:+.3f}")

Output:

GRPO      per-token weight: short +0.0707  long -0.0177  total on long response -0.354
Dr. GRPO  per-token weight: short +0.0125  long -0.0125  total on long response -0.250

Check answers

  1. The short correct one (0.0707 vs 0.0177). The long wrong answer is barely discouraged per token, so length drifts up.

  2. A constant just rescales the gradient. \(|o_i|\) depends on the sample, so it changes which samples matter.

  3. It’s shared within a batch, so it doesn’t favor one response over another inside the batch, which is much closer to unbiased than \(1/|o_i|\). It still varies between batches, which acts like a varying learning rate.

Retrieval answers: (1) Amplifies tiny, possibly noisy differences. (2) \(1/L\).

Takeaway: normalizers are part of the objective. GRPO’s two normalizers quietly change what is being optimized, and Dr. GRPO removes them.
