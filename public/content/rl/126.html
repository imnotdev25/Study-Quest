2. KL regularization gives reward scale operational meaning

Consider a KL-regularized policy over actions or completions:

\[J(\pi) = \sum_a \pi(a)r(a) - \beta D_{\mathrm{KL}} \left( \pi\|\pi_{\mathrm{ref}} \right)\]

Its exact optimum is:

\[\pi^*(a) = \frac{ \pi_{\mathrm{ref}}(a) \exp(r(a)/\beta) }{ \sum_b \pi_{\mathrm{ref}}(b) \exp(r(b)/\beta) }\]

The important quantity is the ratio:

\[\frac{r}{\beta}\]

If rewards are multiplied by \(c\) while \(\beta\) stays fixed:

\[\frac{cr}{\beta} = \frac{r}{\beta/c}\]

Thus reward scaling reduces the effective KL strength from \(\beta\) to \(\beta/c\). To preserve the same optimum, scale the KL coefficient too:

\[r'=cr \quad\Rightarrow\quad \beta'=c\beta\]

Adding one action-independent constant does not change the policy because it cancels during normalization:

\[\operatorname{softmax} \left( \log\pi_{\mathrm{ref}}+\frac{r+k}{\beta} \right) = \operatorname{softmax} \left( \log\pi_{\mathrm{ref}}+\frac r\beta \right)\]

But the limit matters: adding a constant at every token rewards longer sequences, so it is no longer action-independent when lengths vary.

Nonlinear transformations such as clipping generally change the objective. A risky action returning 100 with probability 0.02 has expected reward 2. Clipping outcomes to 1 changes its expected reward to 0.02, potentially reversing which action is preferred.

Tensor shapes:

  • reference probabilities: [A]

  • reward transformations: [C, A]

  • learned logits and policies: [C, A]

  • sampled outcomes: [N]

In LLM RL, a reward model may preserve preference ranking while its numerical scale drifts between checkpoints. PPO consumes that scale as cardinal utility. Log raw rewards, transformed rewards, KL penalties and their relative magnitudes.

If rewards are normalized, freeze the rollout-wide statistics across PPO epochs. Recomputing normalization per minibatch changes a sample’s target according to its batch companions.

DPO avoids an explicit scalar reward during optimization, but its \(\beta\) still controls the strength of policy log-ratio changes. It remains offline preference optimization, not online reward maximization.

Solutions

Closed-form policy:

def kl_optimal_policy(
    rewards,
    reference,
    kl_coefficient,
):
    optimal_logits = (
        reference.log()
        + rewards / kl_coefficient
    )

    return torch.softmax(
        optimal_logits,
        dim=-1,
    )


closed_form_policies = kl_optimal_policy(
    reward_sets,
    reference_probabilities,
    beta,
)

Learned optimization:

for _ in range(400):
    log_probabilities = torch.log_softmax(
        policy_logits,
        dim=-1,
    )

    probabilities = (
        log_probabilities.exp()
    )

    expected_rewards = (
        probabilities * reward_sets
    ).sum(dim=-1)

    kl_divergences = (
        probabilities
        * (
            log_probabilities
            - reference_probabilities.log()
        )
    ).sum(dim=-1)

    objectives = (
        expected_rewards
        - beta * kl_divergences
    )

    loss = -objectives.mean()

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

learned_policies = torch.softmax(
    policy_logits.detach(),
    dim=-1,
)

maximum_learning_error = (
    learned_policies
    - closed_form_policies
).abs().max()

Transformation diagnostics:

shift_invariance_error = (
    closed_form_policies[0]

    closed_form_policies

kl_at_optimum = (
    closed_form_policies

        closed_form_policies.log()
        - reference_probabilities.log()
    )
).sum(dim=-1)

With reference probabilities [0.8, 0.2], the probability of selecting the higher-reward action is approximately:

Transformation Rewards \(P(a_1)\)
Transformation Rewards \(P(a_1)\)
Raw [0, 2] 0.649
Shifted [10, 12] 0.649
Scaled [0, 6] 0.990
Clipped [0, 1] 0.405

Adding a constant leaves the policy unchanged. Scaling rewards by three with fixed \(\beta\) produces the effective coefficient:

\[\beta_{\text{effective}} = \frac13\]

Using:

\[\beta'=3\]

with the scaled rewards exactly restores the raw policy because the ratio \(r/\beta\) is unchanged.

For the stochastic actions:

\[E[R_{\text{safe}}]=1\]

\[E[R_{\text{risky}}] = 0.02(100)=2\]

After clipping each outcome to 1:

\[E[R_{\text{safe,clip}}]=1\]

\[E[R_{\text{risky,clip}}]=0.02\]

The KL-optimal risky-action probability therefore moves from approximately:

\[\sigma(2-1)\approx0.731\]

to:

\[\sigma(0.02-1)\approx0.273\]

Clipping did not merely stabilize optimization; it reversed the decision objective.

Check answers

  1. Scaling increases \(r/\beta\), making reward differences stronger relative to the KL penalty.

  2. Only when the added amount is independent of the action and trajectory. Per-token constants change incentives when sequence lengths differ.

  3. Preference accuracy observes ordering, while PPO depends on score differences and their scale relative to KL, value loss and optimizer settings.

  4. It may encode a deliberate bounded-utility or robustness objective that limits sensitivity to extreme outcomes—but that change must be explicit.

  5. Revisit KL coefficients, controller targets, value-loss coefficients, value clipping, critic learning rate, gradient clipping and reward-normalization statistics.

Retrieval answers

  1. Both heads backpropagate through the same transformer representation, even if their final output heads are separate.

  2. Its real influence is \(c_v\lVert g_V\rVert\) relative to \(\lVert g_\pi\rVert\), together with their gradient alignment.

Takeaway: reward scale and KL strength form one coupled choice. Preserving reward rankings is insufficient—unless \(r/\beta\) is preserved, PPO is optimizing a different policy.
