🧩 Analogy: judging a new waiter from old receipts

You want to know how a new waiter who recommends desserts would do. The old receipts are from a waiter who rarely did. Receipts from the times the old waiter did recommend dessert can be reweighted to estimate the new one, as long as there are some. A new tool router can be evaluated from old routing logs the same way.

2. Logged rewards describe the logging policy

Suppose the deployed behavior policy \(\mu\) generated tool-use logs, but we want to evaluate a new target policy \(\pi\) without deploying it.

Simply averaging logged rewards estimates:

\[J(\mu)=\mathbb E_{\mu}[R]\]

not \(J(\pi)\). Importance sampling corrects the action-distribution mismatch:

\[\rho_i = \frac{\pi(a_i\mid s_i)} {\mu(a_i\mid s_i)}\]

\[\hat J_{\text{IS}}(\pi) = \frac1N\sum_{i=1}^{N}\rho_i r_i\]

A decision common under \(\pi\) but rare under \(\mu\) receives a large weight.

Self-normalized importance sampling uses:

\[\hat J_{\text{SNIS}} = \frac{\sum_i\rho_i r_i} {\sum_i\rho_i}\]

SNIS is biased at finite \(N\), but often has lower variance. Weight clipping also reduces variance while introducing bias:

\[\bar\rho_i=\min(\rho_i,c)\]

Effective sample size diagnoses weight concentration:

\[N_{\text{eff}} = \frac{(\sum_i\rho_i)^2} {\sum_i\rho_i^2}\]

The essential support condition is:

\[\pi(a\mid s)>0 \implies \mu(a\mid s)>0\]

Old logs cannot evaluate actions the behavior policy never attempted.

Tensor shapes:

  • contexts, actions, rewards: [N];

  • behavior and target action probabilities: [N];

  • importance weights: [N];

  • reward and policy tables: [S, A].

For trajectories, ratios multiply over time. Compute them in log-space, but expect variance to grow rapidly with horizon.

DPO learns from fixed preference comparisons. Its objective is not an off-policy estimator of environmental reward, tool success or deployment utility.

🔍 Deeper: the IPS estimator for routers

Logs \((x_i,a_i,r_i,p_i)\) with \(p_i=b(a_i|x_i)\), the exact probability the deployed router assigned. \(\hat V_{\text{IPS}}(\pi)=\frac1n\sum_i\frac{\pi(a_i|x_i)}{p_i}r_i\). Requirements: exact propensities (not re-estimated after the fact), support (\(b>0\) wherever \(\pi>0\)), and diagnostics (ESS, max weight, the share of the estimate coming from the top 1% of weights). A deterministic logger (\(p\in\{0,1\}\)) supports only policies identical to it, so log stochastic routing decisions if you want to evaluate anything else.

🔑 Key ideas

  • Logged rewards evaluate the policy that produced them.

  • Counterfactual evaluation needs propensities, support and diagnostics.

🚶 Walkthrough: evaluate an opposite router

The logger picks tool A 80% and B 20%. A succeeds 0.5 of the time, B 0.9. The new router always picks B. For logged B rows, weight \(=1/0.2=5\), and \(\mathbb E[\text{weight}\cdot r]\) over all rows \(=0.2\times5\times0.9=0.9\). The true value of “always B” is 0.9. (checks out) But only 20% of the rows inform it, so ESS \(\approx0.2n\).

Common mistakes

  • Estimating \(p_i\) with a model trained later.

  • Dropping rows with \(\pi(a_i|x_i)=0\) from the denominator.

  • Evaluating a router whose actions the logger never took.

Hints

  • For action 0, its probability is 1 - tool_probability.

  • Use torch.where(actions == 1, p, 1 - p).

  • Compute log(target_probability) - log(behavior_probability).

  • IS averages weighted rewards; SNIS divides by total weight.

  • ESS is squared weight sum divided by squared-weight sum.

  • Sum context_distribution[:, None] * policy * reward_means.

Debugging experiments

  • Use behavior_tool_probability for every row, including logged action 0. The importance ratios become incorrect.

  • Set a behavior probability to zero where the target probability is positive. No amount of logged data can recover that action’s reward.

  • Recompute stored behavior probabilities with updated model weights. The denominator must describe the policy that collected the data.

  • Clip at 1.0. Variance falls, but the estimate increasingly resembles a different target policy.

  • For a multi-step trace, multiply probabilities directly. Underflow appears quickly; sum detached log-ratios before exponentiating.

Solutions

Selected-action probabilities:

behavior_action_probabilities = torch.where(
    actions == 1,
    behavior_tool_probability,
    1.0 - behavior_tool_probability,
)

target_action_probabilities = torch.where(
    actions == 1,
    target_tool_probability,
    1.0 - target_tool_probability,
)

Importance weights:

log_weights = (
    target_action_probabilities.log()
    - behavior_action_probabilities.log()
)

weights = log_weights.exp()

Value estimates:

naive_value = rewards.mean()

is_value = (
    weights * rewards
).mean()

snis_value = (
    weights * rewards
).sum() / weights.sum()

Clipping and ESS:

clipped_weights = weights.clamp(
    max=clipping_threshold
)

clipped_is_value = (
    clipped_weights * rewards
).mean()

clipped_snis_value = (
    clipped_weights * rewards
).sum() / clipped_weights.sum()

effective_sample_size = (
    weights.sum().square()
    / weights.square().sum()
)

effective_sample_fraction = (
    effective_sample_size
    / num_samples
)

Exact values:

exact_behavior_value = (
    context_distribution[:, None]
    * behavior_policy
    * reward_means
).sum()

exact_target_value = (
    context_distribution[:, None]
    * target_policy
    * reward_means
).sum()

The behavior policy’s exact value is:

\[J(\mu) = \frac12[ 0.8(0.4)+0.2(0.9) + 0.2(0.7)+0.8(0.5) ] = 0.52\]

The target policy’s value is:

\[J(\pi) = \frac12[ 0.2(0.4)+0.8(0.9) + 0.8(0.7)+0.2(0.5) ] = 0.73\]

The possible importance weights are:

\[\rho\in\{0.25,4.0\}\]

Twenty percent of samples receive weight 4, producing an asymptotic ESS fraction of:

\[\frac{1}{\mathbb E[\rho^2]} = \frac{1}{3.25} \approx0.308\]

IS and SNIS should approach 0.73. Clipping the large weights at 2 reduces variance but underweights the decisions preferred by the target policy.

Check answers

  1. Logged actions follow \(\mu\), while the desired expectation weights actions according to \(\pi\).

  2. A small subset of logged decisions dominates the estimate, implying high variance and weak target-policy coverage.

  3. Its random weight sum appears in the denominator; the ratio of two random estimators is not generally unbiased.

  4. Store the exact behavior log-probability, complete conditioning history, masks, policy version, action, reward and episode boundary.

Retrieval answers

  1. Searching thresholds creates multiple chances to select a lucky empirical result; simultaneous correction accounts for all candidates.

  2. It shrinks proportionally to \(1/\sqrt{N}\); quadrupling sample size approximately halves the margin.

Takeaway: logged rewards evaluate the policy that produced them. Counterfactual evaluation requires exact behavior propensities, adequate support and diagnostics for weight concentration.
