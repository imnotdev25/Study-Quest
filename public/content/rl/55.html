🧩 Analogy: learning taste from a stack of old reviews

Online RLHF is a chef who cooks, gets feedback, and cooks again. DPO is a chef who studies a fixed stack of “A was better than B” cards and adjusts their style to agree, without cooking anything new. It’s simpler and cheaper, but they can only learn what the cards cover.

Same shape as the reward-model loss, but the “reward” is the policy’s own log-ratio against the reference.

2. DPO learns from fixed preference pairs

A DPO example contains:

  • prompt \(x\);

  • preferred response \(y_w\);

  • rejected response \(y_l\);

  • fixed reference policy \(\pi_{\text{ref}}\).

Define the policy-versus-reference score:

\[s_\theta(x,y) = \log\pi_\theta(y\mid x) - \log\pi_{\text{ref}}(y\mid x)\]

The preference margin is:

\[\Delta_\theta = s_\theta(x,y_w)-s_\theta(x,y_l)\]

DPO minimizes:

\[L_{\mathrm{DPO}} = -\log\sigma(\beta\Delta_\theta)\]

This encourages the policy to improve the chosen response relative to the rejected response, measured against the reference.

For an autoregressive LLM:

\[\log\pi_\theta(y\mid x) = \sum_t M_t\log\pi_\theta(y_t\mid x,y_{<t})\]

so correct response masks and reduction conventions remain essential.

DPO differs from online RL:

  • it does not generate fresh actions during each update;

  • it does not observe environment rewards;

  • it needs no critic or advantage estimator;

  • it cannot explore beyond the fixed preference dataset;

  • it uses ordinary backpropagation through differentiable log-probabilities.

The reference policy in DPO is not PPO’s old rollout policy. PPO’s old policy changes after collecting each rollout batch; DPO’s reference is normally a fixed anchor.

Tensor shapes:

  • chosen/rejected token log-probabilities: [B, T]

  • response masks: [B, T]

  • chosen/rejected sequence log-probabilities: [B]

  • preference margins: [B]

  • DPO loss: scalar

🔍 Deeper: deriving DPO from the KL-regularized optimum

From Topic 29: \(\pi^*(y|x)=\pi_{\text{ref}}(y|x)e^{r(x,y)/\beta}/Z(x)\), so \(r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)}+\beta\log Z(x)\). Plug that into Bradley–Terry. \(Z(x)\) is the same for both responses, so it cancels: \[\mathcal L_{\text{DPO}}=-\mathbb E\Big[\log\sigma\Big(\beta\log\tfrac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}-\beta\log\tfrac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\Big)\Big].\] No reward model and no sampling: it’s a classification loss on fixed pairs. Not online RL: the policy never sees its own new outputs, so it can’t discover or fix failure modes outside the data.

🔑 Key ideas

  • DPO = Bradley–Terry with the policy’s log-ratio as the reward.

  • It’s bounded by pair quality, coverage and the frozen reference.

🚶 Walkthrough: one pair

\(h_w=\log\pi_\theta(y_w)-\log\pi_{\text{ref}}(y_w)=0.2\), \(h_l=-0.1\), \(\beta=0.1\). Margin \(=0.1(0.3)=0.03\). Loss \(=\ln(1+e^{-0.03})=0.678\), barely below \(\ln2\). The gradient weight \(\sigma(-0.03)\approx0.49\) is still large.

Common mistakes

  • The reference model accidentally updating (it must be frozen).

  • Mean vs sum of token log-probs (a mean introduces a length preference).

  • Prompt tokens included in \(h\).

⚙️ Algorithm: Direct Preference Optimization (DPO)
Input: preference pairs \((x,y_w,y_l)\), frozen reference \(\pi_{\text{ref}}\), policy \(\pi_\theta\), \(\beta\)
for each minibatch do
\(h_w\gets\log\pi_\theta(y_w|x)-\log\pi_{\text{ref}}(y_w|x)\) ▷ masked sums over response tokens
\(h_l\gets\log\pi_\theta(y_l|x)-\log\pi_{\text{ref}}(y_l|x)\)
gradient step on \(-\operatorname{mean}\log\sigma\big(\beta(h_w-h_l)\big)\)
log the implicit reward margin \(\beta(h_w-h_l)\) and the pair accuracy
end

Hints

  • Use log_softmax(dim=-1).

  • A chosen score is policy_log_probs[chosen] - reference_log_probs[chosen].

  • Margin is chosen score minus rejected score.

  • Use -F.logsigmoid(beta * margins).mean().

  • Preference probability is torch.sigmoid(beta * margins).

  • The training loop needs zero_grad, backward and step.

Debugging experiments

Swap chosen and rejected. Training remains numerically healthy while learning exactly the opposite ranking.

Next, remove .detach() from a trainable reference model. Both policy and reference may move, destroying the fixed anchor assumed by the objective.

Replace F.logsigmoid with:

-torch.log(
    torch.sigmoid(beta * margins)
).mean()

Large negative margins can make sigmoid underflow toward zero and the logarithm produce inf. logsigmoid is more stable.

Finally, length-normalize response log-probabilities. This may reduce length effects, but it changes the preference objective rather than merely fixing numerical stability.

4. Checks for understanding

  1. What role does the reference policy play in DPO?

  2. How does increasing \(\beta\) affect the loss?

  3. Why can DPO struggle with preferences outside the dataset’s support?

  4. What diagnostics should accompany DPO training loss?

Solutions

Policy log-probabilities:

policy_log_probs = (
    policy_logits.log_softmax(
        dim=-1
    )
)

Reference-relative scores:

chosen_scores = (
    policy_log_probs[chosen]
    - reference_log_probs[chosen]
)

rejected_scores = (
    policy_log_probs[rejected]
    - reference_log_probs[rejected]
)

Preference margin:

margins = (
    chosen_scores - rejected_scores
)

Loss and implied probabilities:

loss = -F.logsigmoid(
    beta * margins
).mean()

preference_probabilities = (
    torch.sigmoid(
        beta * margins
    )
)

Optimization:

for step in range(100):
    loss, margins, preference_probabilities = (
        dpo_objective(policy_logits)
    )

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

When policy and reference are identical:

\[s_\theta(x,y)=0\]

for every response, so:

\[\Delta_\theta=0\]

and:

\[\sigma(\beta\Delta_\theta)=0.5\]

Training increases the relative scores of responses 2 and 1 over lower-ranked responses. Response 2 should gain the most probability because it wins both of its comparisons.

Check answers

  1. It defines the baseline response probabilities. DPO learns how the chosen-versus-rejected margin changes relative to that anchor.

  2. It makes the logistic comparison steeper and usually increases gradient scale near zero, while strongly confident examples can saturate sooner.

  3. It receives no fresh exploration or reward feedback. Missing behaviors cannot be directly compared or corrected.

  4. Log preference accuracy, margin distribution, chosen/rejected log-probabilities, policy-reference KL, response length, held-out preference accuracy and independent capability/safety evaluations.

Retrieval answers

  1. PPO’s ratio must compare the current policy against the fixed behavior policy that generated those sampled actions.

  2. An individual sampled action may have become more probable under the current policy; only the correctly weighted expectation is guaranteed to equal nonnegative KL.

Takeaway: DPO is reference-relative preference classification over fixed pairs. It is simpler than online RL, but its behavior is bounded by preference quality, dataset coverage, masking choices and the fixed reference anchor.
