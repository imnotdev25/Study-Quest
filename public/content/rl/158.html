2. Broadcasting credit is not duplicating reward

A reward model or verifier often gives one score \(R_i\) after the entire response. Store it once, at the terminal token:

\[r_{it} = \underbrace{ \mathbf 1[t=L_i-1]R_i }_{\text{one terminal reward}}\]

The return from token \(t\) is:

\[G_{it} = \underbrace{ \sum_{u=t}^{L_i-1} \gamma^{u-t}r_{iu} }_{\text{future reward after choosing token }t} = \underbrace{ \gamma^{L_i-1-t}R_i }_{\text{discounted terminal score}}\]

With \(\gamma=1\):

\[\underbrace{G_{it}=R_i}_{\text{same return for every preceding action}}\]

Every generated token receives credit because every token helped construct the final response—not because the environment emitted \(R_i\) repeatedly.

This also follows from the log-derivative identity:

\[\log\pi_\theta(y_i\mid x_i) = \underbrace{ \sum_t m_{it}\log\pi_\theta(a_{it}\mid s_{it}) }_{\text{autoregressive sequence log-probability}}\]

\[\nabla_\theta J \approx \underbrace{ A_i \sum_t m_{it} \nabla_\theta\log\pi_\theta(a_{it}\mid s_{it}) }_{\text{one sequence advantage, many token gradients}}\]

A simple sequence advantage is:

\[A_i = \underbrace{R_i-b(x_i)}_{\text{return minus prompt-dependent baseline}}\]

Detach it in the actor loss:

\[L_{\text{actor}} = -\frac1B \sum_i \underbrace{ \operatorname{stopgrad}(A_i) }_{\text{fixed learning signal}} \underbrace{ \sum_t m_{it}\log\pi_\theta(a_{it}\mid s_{it}) }_{\text{trainable token log-probabilities}}\]

For \(A_i>0\), gradient descent raises probabilities of sampled tokens. For \(A_i<0\), it lowers them.

Do not confuse this with incorrectly assigning \(r_{it}=R_i\) at every token. With \(\gamma=1\), that bug makes the first-token return approximately \(L_iR_i\).

Shapes:

  • logits: [B, T, V]

  • actions, log-probabilities, rewards and masks: [B, T]

  • lengths, rewards and sequence advantages: [B]

DPO also sums completion-token log-probabilities, so its preference loss backpropagates through every completion token. But DPO has no sampled online return, return-to-go, or learned PPO value baseline.

Solutions

Return recursion:

running_return = (
    token_rewards[:, t]
    + continuation_mask[:, t]
    * running_return
)

running_return = (
    running_return
    * valid_mask[:, t]
)

Return tables:

correct_returns = undiscounted_returns(
    terminal_token_rewards,
    continuation_mask,
    valid_mask,
)

duplicated_returns = undiscounted_returns(
    duplicated_token_rewards,
    continuation_mask,
    valid_mask,
)

Advantages and sequence loss:

sequence_advantages = (
    sequence_rewards
    - prompt_baselines
).detach()

sequence_log_probabilities = (
    chosen_log_probabilities
    * valid_mask
).sum(dim=1)

sequence_actor_loss = -(
    sequence_advantages
    * sequence_log_probabilities
).mean()

Broadcast implementation and reductions:

token_actor_terms = (
    sequence_advantages[:, None]
    * chosen_log_probabilities
    * valid_mask
)

broadcast_actor_loss = -(
    token_actor_terms.sum(dim=1)
).mean()

global_token_mean_loss = -(
    token_actor_terms.sum()
    / valid_mask.sum()
)

per_sequence_token_mean_loss = -(
    token_actor_terms.sum(dim=1)
    / lengths
).mean()

Gradient diagnostics:

gradient_identity_error = (
    sequence_gradient
    - broadcast_gradient
).abs().max()

global_scale_error = (
    global_mean_gradient
    - expected_global_scale
    * sequence_gradient
).abs().max()

The correct return table is:

\[G^{\text{correct}} = \begin{bmatrix} 1.2 & 1.2 & 0 & 0 & 0\\ -0.4 & -0.4 & -0.4 & -0.4 & -0.4\\ 0.8 & 0.8 & 0.8 & 0 & 0 \end{bmatrix}\]

The duplicated-reward bug gives:

\[G^{\text{bug}}_{i,0} = \underbrace{L_iR_i}_{\text{reward counted once per token}}\]

Therefore the length-five sequence begins with:

\[5(-0.4)=-2.0\]

The sequence and broadcast losses—and their gradients—should match to floating-point precision. Padded-token gradients should be zero.

The global-token mean has the same gradient direction but rescales it by:

\[\underbrace{ \frac{B}{\sum_i L_i} }_{3/10=0.3}\]

A per-sequence token mean introduces a different factor \(1/L_i\) for every response, so it can change both relative sequence weighting and gradient direction.

Check answers

  1. Because the gradient of a sequence log-probability is the sum of gradients for all sampled token decisions.

  2. Broadcasting uses one return as credit for several actions. Repeating the reward changes the return itself and counts the environment outcome multiple times.

  3. No. A shared terminal score provides coarse credit; it cannot identify which particular token caused success or failure.

  4. Long responses contribute less per token, changing the optimization objective and often its length preference.

Retrieval answers

  1. Autoregressive sequence probabilities multiply across tokens; taking a logarithm converts that product into a sum.

  2. The controller interprets incompatible units as a large KL error and incorrectly changes the KL coefficient.

Takeaway: store a sequence reward once, but let its return train every action that preceded it. Broadcasting detached credit is correct policy-gradient accounting; duplicating environmental reward is not.
