🧩 Analogy: a talent show judge who prefers the first act

Some judges tend to prefer whoever performs first. If you always put contestant A first, A wins too often. The fix is simple: run each pair twice in both orders and average. AI judges for RLAIF have the same kind of position bias, plus length and self-preference biases.

2. The idea

RLAIF replaces human preference labels with an AI judge (Lee et al., 2023). Constitutional AI (Bai et al., 2022) adds written principles: the model critiques and revises its own outputs against them, and an AI judge applies the principles to label preference pairs for RL. It’s cheap and scalable, but the judge’s biases become the reward:

  • Position: prefers the first (or second) answer shown.

  • Length and style: prefers longer or more confident-sounding answers.

  • Self-preference: prefers outputs that look like its own.

Swap-averaging: judge both orders, and use \(\tfrac12\big(P(A\succ B\mid A\text{ first})+1-P(B\succ A\mid B\text{ first})\big)\). An additive position bias cancels exactly. You can also estimate the bias from the two orders.

🔑 Key ideas

  • An AI judge’s biases become the policy’s objective.

  • Swap order, audit with humans, and check length correlation before optimizing.

🚶 Walkthrough: bias cancellation

Judge: \(P(\text{first wins})=\sigma(2\Delta+1)\), with \(\Delta\) the true quality gap. For \(\Delta=-0.3\) (B is better): with A first, \(\sigma(0.4)=0.60\), so the judge picks A (wrong). With B first, \(\sigma(1.6)=0.83\), so \(P(A\text{ wins})=0.17\). Average \(=0.38<0.5\): B, which is correct.

Common mistakes

  • Judging each pair in one fixed order.

  • Using the same model as policy and judge (self-preference).

  • Never validating the judge against human labels on a sample.

Solutions

import torch

torch.manual_seed(0)
n = 5000
r_a, r_b = torch.randn(n), torch.randn(n)
true_a_better = r_a > r_b
position_bias = 1.0                      # judge favors whichever answer is shown first


def judge_prob_first_wins(r_first, r_second):
    return torch.sigmoid(2.0 * (r_first - r_second) + position_bias)


p_ab = judge_prob_first_wins(r_a, r_b)           # A shown first
p_ba = judge_prob_first_wins(r_b, r_a)           # B shown first
single = p_ab > 0.5
swapped = (p_ab + (1 - p_ba)) / 2 > 0.5          # average P(A wins) over both orders
bias_estimate = ((p_ab + p_ba) / 2 - 0.5).mean()
print(f"label accuracy, one order : {(single == true_a_better).float().mean():.3f}")
print(f"label accuracy, both orders: {(swapped == true_a_better).float().mean():.3f}")
print(f"estimated first-position advantage: {bias_estimate:.3f}")

Output:

label accuracy, one order : 0.867
label accuracy, both orders: 1.000
estimated first-position advantage: 0.119

Check answers

  1. The bias is antisymmetric under swapping (it favors whichever answer is first), so averaging the two orders removes it and leaves the quality term. Real judges are messier, so expect improvement, not perfection.

  2. Length or style bias, and self-preference: those follow the content, not the position.

Retrieval answers: (1) It selects outputs where the judge is wrong in its favor. (2) Randomize the order and estimate the bias.

Takeaway: an AI judge is a cheap reward model with its own biases. Debias what you can measure, audit the rest with people.
