2. Dividing by length changes the objective

For a generated sequence of length \(L\), three plausible rewards are:

\[R_{\text{sum}} = \sum_{t=1}^{L} r_t\]

\[R_{\text{mean}} = \frac1L\sum_{t=1}^{L}r_t\]

\[R_{\text{utility}} = R_{\text{task}}-cL\]

These are different objectives, not alternative implementations of the same metric:

  • positive per-token reward sums encourage longer responses;

  • mean token reward may encourage short but incomplete responses;

  • terminal reward measures task success;

  • an explicit length cost expresses the actual latency or token tradeoff.

Consider a policy choosing concise or verbose behavior. If:

\[p=\sigma(\theta)\]

is its probability of choosing verbose output, then:

\[J(\theta) = (1-p)J_{\text{concise}} + pJ_{\text{verbose}}\]

and:

\[\frac{\partial J}{\partial\theta} = p(1-p) \left( J_{\text{verbose}} - J_{\text{concise}} \right)\]

The reward definition can therefore reverse the policy-gradient sign.

Tensor shapes:

  • lengths and terminal rewards: [A, B]

  • token masks and scores: [A, B, T]

  • policy-level objectives: [A]

Here \(A=2\) behaviors, \(B\) sampled sequences and \(T\) maximum length.

For DPO, sequence log-ratios are normally masked sums over response tokens. Replacing sums with length-normalized means changes the preference objective. DPO optimizes the supplied preference pairs; it does not decide which deployment notion of utility is correct.

Debugging experiments

  • Sum a positive per-token judge score without monitoring length.

  • Average over padded slots instead of valid response tokens.

  • Include prompt tokens in the response-reward mask.

  • Treat truncation at maximum_length as successful termination.

  • Normalize reward by length without recognizing that length is policy-controlled.

  • Rescale terminal reward but leave the token-cost coefficient unchanged.

  • Compare gradient magnitudes across objectives with radically different scales.

Gradient directions:

def verbose_ascent_gradient(policy_values):
    theta = torch.tensor(
        0.0,
        requires_grad=True,
    )

    verbose_probability = torch.sigmoid(
        theta
    )

    values = policy_values.detach()

    expected_objective = (
        (1.0 - verbose_probability)
        * values[0]
        + verbose_probability
        * values[1]
    )

    loss = -expected_objective

    loss.backward()

    ascent_gradient = (
        -theta.grad.detach()
    )

    return (
        expected_objective.detach(),
        ascent_gradient,
    )


_, sum_gradient = verbose_ascent_gradient(
    sum_objectives
)

_, mean_gradient = verbose_ascent_gradient(
    mean_objectives
)

_, success_gradient = verbose_ascent_gradient(
    success_objectives
)

_, utility_gradient = verbose_ascent_gradient(
    utility_objectives
)

At \(\theta=0\), \(p=0.5\), so:

\[\frac{\partial J}{\partial\theta} = 0.25 \left( J_{\text{verbose}} - J_{\text{concise}} \right)\]

The summed token objective produces a positive gradient toward verbosity. The other objectives produce negative gradients.

The incorrect padded mean is approximately:

\[\frac{20(0.70)}{100}=0.14\]

for concise responses and:

\[\frac{80(0.65)}{100}=0.52\]

for verbose responses. A masking mistake therefore manufactures a strong verbosity preference.

Check answers

  1. Because summed reward, mean reward and explicit utility assign different values to policy-controlled length.

  2. No. A short incomplete answer can have excellent average token quality but poor task success.

  3. Use a response mask that is true only for generated, non-padding tokens; exclude prompt, padding and post-EOS positions.

  4. Log them separately and assign the intended timeout or incomplete-task outcome. Do not silently treat truncation as a normal EOS.

Retrieval answers

  1. The user average gives each user equal weight; the episode average weights users according to how many episodes they generate.

  2. Padding changes the denominator unless masked, so the result is neither a valid-user nor valid-episode mean.

Takeaway: length normalization is part of the reward specification. Monitor sequence length, EOS and truncation rates alongside reward—and verify that the chosen reward gives the intended policy-gradient sign.
