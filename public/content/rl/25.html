2. Which token deserves the reward?

Suppose an LLM produces a 200-token answer and receives reward \(+1\). Basic sequence-level REINFORCE uses:

\[L = -R_{\text{sequence}} \sum_{t=1}^{T} \log\pi_\theta(y_t\mid x,y_{<t})\]

Every generated token receives the same positive weight. This is valid coarse credit assignment: every token helped determine the final response. But it cannot identify which tokens were especially helpful or harmful.

It is like giving every member of a large project the same score without knowing who introduced the key idea or the critical bug.

Three common credit signals

1. Broadcast outcome reward

\[\hat A_t=R_{\text{sequence}}-b_t\]

Simple, but usually high variance and imprecise.

2. Token/process rewards

If an evaluator supplies intermediate rewards \(r_t\), calculate return-to-go:

\[G_t = r_t+\gamma r_{t+1} +\gamma^2r_{t+2}+\cdots\]

or recursively:

\[G_t=r_t+\gamma G_{t+1}\]

Now later rewards update earlier tokens, but not later tokens from rewards that occurred before them.

3. Prefix critic

Estimate the expected future reward after each prefix:

\[V_\phi(x,y_{\leq t})\]

Then use TD errors or GAE to estimate token advantages. This can lower variance, but an inaccurate critic introduces bias.

A subtle limitation

Return-to-go improves causal direction, but does not solve exact attribution. If token 20 introduces an error and token 100 repairs it, the final positive return may still reinforce token 20.

Process rewards can offer more detail, but only if the process evaluator is trustworthy. A flawed evaluator may reward verbose reasoning, familiar wording or superficial formatting instead of actual correctness.

For batch size \(B\) and generated length \(T\):

  • selected token log-probabilities: [B, T]

  • token rewards and returns: [B, T]

  • response mask: [B, T]

  • sequence rewards: [B]

  • policy loss: scalar

🔍 Deeper: what each token actually receives

With \(\gamma=1\) and only a terminal reward \(R\): \(G_t=R\) for every token, so every token gets identical credit.

With a critic: \(A_t=V(s_{t+1})-V(s_t)\) (plus \(R\) at the last step). By telescoping, \(\sum_tA_t=R-V(s_0)\). The total credit is the same, but now it’s redistributed: tokens where the critic’s prediction jumped up get more of it.

The risk: that redistribution is only as good as \(V\), or the process reward model. A wrong step-grader gives confident, wrong credit, which can be worse than uniform credit.

🔑 Key ideas

  • Outcome rewards are honest but coarse. Token credit is finer, but only if the evaluator is reliable.

  • Critics and process rewards redistribute credit. They don’t create extra signal.

🚶 Walkthrough: critic-redistributed credit

\(R=1\), \(\gamma=1\), critic values \(V(s_0..s_3)=(0.5,0.6,0.2,0.9)\). Advantages: \(A_0=0.1\), \(A_1=-0.4\), \(A_2=0.7\), \(A_3=1-0.9=0.1\). Sum \(=0.5=R-V(s_0)\). (checks out) Token 1 is flagged as the step that hurt, if the critic is right.

Common mistakes

  • Trusting per-token credit from a critic with low explained variance.

  • Putting \(R\) on the padding position instead of the last real token.

  • Using \(\gamma<1\) by accident, which favors short answers (Topic 122).

Debugging experiment

Remove both masks from the return recursion:

for t in reversed(range(token_rewards.shape[1])):
    running_return = (
        token_rewards[:, t]
        + gamma * running_return
    )
    returns[:, t] = running_return

The padding value 99 now propagates backward and dominates genuine rewards.

This can happen in real RLHF pipelines when padded reward, value or KL tensors enter GAE without consistent response masks.

4. Checks for understanding

  1. Is broadcasting a terminal reward to every generated token mathematically invalid?

  2. Why can process rewards reduce credit-assignment ambiguity?

  3. Why must a reward at token \(t\) not update later token \(t+1\)?

  4. Does more detailed token-level feedback guarantee a better training signal?

Solutions

Masked sequence rewards:

sequence_rewards = (
    token_rewards * response_mask
).sum(dim=-1)

This gives:

response 1: -1 + 2 = 1
response 2:  1 - 1 = 0

Broadcast outcome credit:

outcome_weights = (
    sequence_rewards
    .unsqueeze(-1)
    .expand_as(outcome_log_probs)
)

Return-to-go recursion:

for t in reversed(range(token_rewards.shape[1])):
    running_return = (
        safe_rewards[:, t]
        + gamma * running_return
    )

    running_return = (
        running_return * response_mask[:, t]
    )

    returns[:, t] = running_return

Process-credit loss:

process_loss = -(
    process_log_probs
    * returns.detach()
    * response_mask
).sum() / response_mask.sum()

Expected returns are approximately:

tensor([
    [ 0.648,  0.720,  0.800,  2.000,  0.000],
    [ 0.090,  0.100, -1.000,  0.000,  0.000],
])

For the first response:

\[G_2=-1+0.9(2)=0.8\]

The negative intermediate reward reduces earlier credit, but the later reward is large enough to keep the return positive.

For the second response:

\[G_2=-1\]

\[G_1=1+0.9(-1)=0.1\]

\[G_0=0+0.9(0.1)=0.09\]

Outcome-only credit gives the entire second response zero gradient because its total reward is zero. Process credit distinguishes its mildly helpful earlier tokens from its harmful final token.

Because:

\[\frac{\partial L}{\partial\log\pi_t} = -\frac{G_t}{N_{\text{valid}}}\]

  • positive return produces a negative log-probability gradient, encouraging that token under gradient descent;

  • negative return produces a positive gradient, discouraging it;

  • masked positions produce exactly zero gradient.

Check answers

  1. No. It is the standard sequence-level REINFORCE estimator, but its variance and attribution are poor.

  2. They reveal intermediate successes or failures hidden by one aggregate outcome.

  3. A later action cannot causally affect feedback already produced before that action.

  4. No. A biased or exploitable process evaluator can provide precisely targeted but incorrect supervision.

Retrieval answers

  1. The sequence log-probability is the sum of its selected token log-probabilities.

  2. Prompt tokens were supplied by the user and padding is artificial batching structure; neither was sampled as a response action.

Takeaway: sequence rewards answer “Was the response good?” Token credit tries to answer “Which decisions made it good?” Finer attribution can reduce variance, but only when the token or prefix evaluator is reliable.
