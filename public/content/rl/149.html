2. A positive average utility can hide an unacceptable regression

Let candidate-minus-control differences be:

\[\Delta_R = \underbrace{E[R_1-R_0]}_{\text{reward improvement; larger is better}}\]

\[\Delta_H = \underbrace{E[H_1-H_0]}_{\text{harm increase; smaller is better}}\]

Suppose deployment requires:

\[\underbrace{\Delta_R>0}_{\text{reward superiority}} \qquad\text{and}\qquad \underbrace{\Delta_H<m}_{\text{harm non-inferiority}}\]

where \(m\) is the largest acceptable safety regression.

Use opposite one-sided bounds:

\[LCB_R = \underbrace{ \hat\Delta_R -z_{1-\alpha}\widehat{SE}_R }_{\text{conservative reward improvement}}\]

\[UCB_H = \underbrace{ \hat\Delta_H +z_{1-\alpha}\widehat{SE}_H }_{\text{conservative harm increase}}\]

Promote only when:

\[\underbrace{LCB_R>0}_{\text{reward gate passes}} \quad\land\quad \underbrace{UCB_H<m}_{\text{safety gate passes}}\]

This is an intersection-union test. For one fixed candidate, no Bonferroni split is needed merely because both requirements must pass. Under the global null, at least one requirement is false; falsely promoting requires rejecting that true component at level \(\alpha\).

This differs from searching 20 candidates and promoting any winner—that does require candidate-selection multiplicity control.

A scalar objective can conceal the constraint:

\[\Delta_U = \underbrace{\Delta_R-\lambda\Delta_H}_{\text{combined utility}}\]

For example:

\[\Delta_R=0.10,\qquad \Delta_H=0.03,\qquad m=0.01\]

With \(\lambda=1\):

\[\Delta_U = \underbrace{0.10-0.03}_{0.07>0}\]

The scalar utility improves even though harm worsens three times more than allowed.

DPO similarly optimizes a scalar preference objective. Improved DPO loss or preference accuracy does not guarantee that a separately defined safety constraint passes. Online RL can use constrained objectives, but deployment still needs explicit guardrail evaluation.

Tensor shapes:

  • reward and harm differences: [R, N]

  • estimates, standard errors and decisions: [R]

  • scenario summaries: [S, 4]

Solutions

Correlated differences:

def evaluate_scenario(
    true_harm_increase,
):
    shared_noise = torch.randn(
        num_repetitions,
        episodes_per_repetition,
    )

    independent_noise = torch.randn(
        num_repetitions,
        episodes_per_repetition,
    )

    reward_differences = (
        true_reward_improvement
        + reward_noise_sd
        * shared_noise
    )

    harm_differences = (
        true_harm_increase
        + harm_noise_sd
        * (
            reward_harm_correlation
            * shared_noise
            + math.sqrt(
                1.0
                - reward_harm_correlation**2
            )
            * independent_noise
        )
    )

Estimates and standard errors:

    reward_estimates = (
        reward_differences.mean(dim=1)
    )

    harm_estimates = (
        harm_differences.mean(dim=1)
    )

    reward_standard_errors = (
        reward_differences.std(
            dim=1,
            correction=1,
        )
        / math.sqrt(episodes_per_repetition)
    )

    harm_standard_errors = (
        harm_differences.std(
            dim=1,
            correction=1,
        )
        / math.sqrt(episodes_per_repetition)
    )

Explicit gates:

    reward_lower_bounds = (
        reward_estimates
        - one_sided_z
        * reward_standard_errors
    )

    harm_upper_bounds = (
        harm_estimates
        + one_sided_z
        * harm_standard_errors
    )

    reward_passes = (
        reward_lower_bounds > 0.0
    )

    safety_passes = (
        harm_upper_bounds < harm_margin
    )

    joint_passes = (
        reward_passes
        & safety_passes
    )

Scalarized utility:

    utility_differences = (
        reward_differences
        - utility_harm_penalty
        * harm_differences
    )

    utility_estimates = (
        utility_differences.mean(dim=1)
    )

    utility_standard_errors = (
        utility_differences.std(
            dim=1,
            correction=1,
        )
        / math.sqrt(episodes_per_repetition)
    )

    utility_lower_bounds = (
        utility_estimates
        - one_sided_z
        * utility_standard_errors
    )

    utility_passes = (
        utility_lower_bounds > 0.0
    )

Return values:

    promotion_rates = torch.stack([
        reward_passes.to(
            torch.float64
        ).mean(),

        safety_passes.to(
            torch.float64
        ).mean(),

        joint_passes.to(
            torch.float64
        ).mean(),

        utility_passes.to(
            torch.float64
        ).mean(),
    ])

    diagnostics = torch.stack([
        reward_estimates.mean(),
        harm_estimates.mean(),
        reward_standard_errors.mean(),
        harm_standard_errors.mean(),
    ])

    return promotion_rates, diagnostics

The expected standard errors are approximately:

\[SE_R = \underbrace{\frac{0.80}{\sqrt{400}}}_{\text{reward uncertainty}} = 0.040\]

\[SE_H = \underbrace{\frac{0.04}{\sqrt{400}}}_{\text{harm uncertainty}} = 0.002\]

For the unsafe scenario:

\[UCB_H \approx \underbrace{0.030}_{\text{estimated harm increase}} + \underbrace{1.645(0.002)}_{\text{uncertainty margin}} = 0.0333 > \underbrace{0.010}_{\text{allowed margin}}\]

so the safety gate correctly fails.

Yet its scalarized population utility remains:

\[\Delta_U = \underbrace{0.10-1(0.03)}_{\text{reward minus harm penalty}} = 0.07>0\]

which explains why scalarization can still promote it.

Check answers

  1. Only the safe scenario satisfies \(\Delta_H<m\). The boundary is not strictly non-inferior.

  2. Approximately 5%, because the null is exactly at the one-sided boundary.

  3. No. All three scenarios have the same reward improvement.

  4. Yes. Reward gains can outweigh the penalty even while the explicit safety margin is violated.

  5. Safety requires ruling out excessive harm. Therefore, the worst plausible harm increase—the upper bound—must remain below \(m\).

Retrieval answers

  1. Empirical Bernstein uses the observed variance, which can be much smaller than the worst-case variance implied by the score range.

  2. Early low variance may only reflect that rare extreme outcomes have not appeared; the range correction protects against overconfidence.

Takeaway: deployment is often a constrained decision, not scalar reward maximization. Require evidence of reward improvement and evidence that every critical safety regression remains below its pre-specified margin.
