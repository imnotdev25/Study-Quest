🧩 Analogy: a weather app that says 90% rain

If a weather app says “90% chance of rain” on 100 days, it should rain on about 90 of them. If it rains on 60, the app is overconfident, even if it’s usually right about which days are wetter. Calibration asks whether stated confidence matches observed frequency.

2. Confidence is a claim about frequency

Suppose an outcome model predicts whether a tool-agent answer will succeed. Among predictions made with 90% confidence, roughly 90% should succeed. That is calibration.

Accuracy and calibration differ:

  • A model can rank examples correctly but be overconfident.

  • A calibrated model can still have poor accuracy.

  • A policy probability means “how often I select this action,” not “how likely this action is correct.”

For class logits \(z\), temperature scaling uses:

\[p_T(y\mid x) = \operatorname{softmax}\left(\frac{z}{T}\right)\]

where \(T>0\):

  • \(T>1\): softer, less confident probabilities;

  • \(T<1\): sharper, more confident probabilities;

  • \(T=1\): unchanged probabilities.

Fit \(T\) on a held-out calibration set by minimizing negative log-likelihood:

\[L(T) = -\frac1B\sum_{i=1}^{B} \log p_T(y_i\mid x_i)\]

A positive scalar temperature preserves every argmax, so classification accuracy stays fixed. It changes confidence and NLL.

Expected calibration error groups predictions into confidence bins:

\[\operatorname{ECE} = \sum_k \frac{|B_k|}{B} \left| \operatorname{accuracy}(B_k) - \operatorname{confidence}(B_k) \right|\]

ECE is useful diagnostically but depends on bin choices and is not smoothly differentiable. Optimize NLL; report ECE, NLL, Brier score and subgroup results.

Tensor shapes:

  • logits and probabilities: [B, C];

  • labels, confidence and predictions: [B];

  • temperature: scalar;

  • NLL and ECE: scalar.

In RL, calibrate a success, reward or outcome predictor against observed outcomes. Silently scaling policy logits changes sampling entropy, rollout log-probabilities and PPO ratios.

DPO optimizes a preference log-ratio margin on fixed comparisons. Neither that margin nor its sigmoid is automatically a calibrated probability of task success.

🔍 Deeper: measuring and fixing calibration

Expected calibration error: bin predictions by confidence, then \(\mathrm{ECE}=\sum_b\frac{n_b}{n}\big|\mathrm{acc}_b-\mathrm{conf}_b\big|\). Temperature scaling: \(p=\sigma(z/T)\) (or softmax), with one scalar \(T\) fit by minimizing NLL on a held-out calibration set. \(T>1\) softens overconfident predictions. Accuracy is unchanged, because the ranking is preserved. Not probabilities of correctness: a policy’s token probability, or a DPO margin, isn’t a calibrated “chance this answer is right.”

🔑 Key ideas

  • Confidence is only useful once checked against outcomes.

  • Calibrate on separate data and monitor for drift.

🚶 Walkthrough: ECE from two bins

Bin 1: 50 predictions at confidence 0.9, 35 correct (0.70). Bin 2: 50 at confidence 0.6, 30 correct (0.60). \(\mathrm{ECE}=0.5|0.70-0.90|+0.5|0.60-0.60|=0.10\). All the error is in the confident bin.

Common mistakes

  • Fitting \(T\) on the test set.

  • Too many bins with too little data (a noisy ECE).

  • Calibrating once and never checking again after a policy update.

Hints

  • Divide logits by temperature before softmax.

  • Use F.cross_entropy directly on scaled logits.

  • A bin contains confidence in (lower, upper].

  • Bin weight is the fraction of all examples in that bin.

  • Use temperature = log_temperature.exp().

  • Detach the original logits while fitting the scalar temperature.

Debugging experiments

  • Optimize an unconstrained raw temperature. It may reach zero or become negative, producing instability or reversed rankings.

  • Optimize the base logits with the temperature. This is no longer post-hoc calibration and can overfit the small split.

  • Fit temperature on the evaluation set. The reported calibration is then contaminated by leakage.

  • Increase the number of ECE bins. Small or empty bins make the estimate noisy.

  • Scale PPO policy logits after rollout collection. Stored log-probabilities and the new distribution will no longer describe the same policy.

Solutions

Probability calculations:

scaled_logits = logits / temperature

probabilities = scaled_logits.softmax(
    dim=-1
)

confidences, predictions = (
    probabilities.max(dim=-1)
)

Accuracy and NLL:

accuracy = (
    predictions == labels
).to(logits.dtype).mean()

nll = F.cross_entropy(
    scaled_logits,
    labels,
)

ECE calculation:

in_bin = (
    (confidences > lower)
    & (confidences <= upper)
)

if bool(in_bin.any()):
    bin_accuracy = (
        predictions[in_bin]
        == labels[in_bin]
    ).to(logits.dtype).mean()

    bin_confidence = (
        confidences[in_bin].mean()
    )

    bin_weight = (
        in_bin.to(logits.dtype).mean()
    )

    ece = (
        ece
        + bin_weight
        * (
            bin_accuracy
            - bin_confidence
        ).abs()
    )

Temperature optimization:

for step in range(500):
    temperature = (
        log_temperature.exp()
    )

    loss = F.cross_entropy(
        calibration_logits.detach()
        / temperature,
        calibration_labels,
    )

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

Final evaluation:

learned_temperature = (
    log_temperature.detach().exp()
)

with torch.no_grad():
    after = calibration_metrics(
        evaluation_logits,
        evaluation_labels,
        learned_temperature,
    )

The model is correct on two-thirds of the evaluation examples but initially reports mean confidence near one. The learned \(T>1\) softens its probabilities. Accuracy and predictions remain unchanged, while mean confidence, NLL and usually ECE improve.

Check answers

  1. Dividing every class logit by the same positive scalar preserves their ordering.

  2. NLL is smooth and rewards probability assigned to the observed label; hard ECE bins are discontinuous and bin-dependent.

  3. Distribution shift can change the relationship between confidence and correctness.

  4. Report NLL, Brier score, reliability plots, bin counts and calibration by task, tool, difficulty and important subgroup.

Retrieval answers

  1. Aleatoric uncertainty is irreducible outcome randomness; epistemic uncertainty represents limited knowledge.

  2. Deployment may penalize unsupported actions with an LCB, while exploration uses a UCB to investigate uncertain actions.

Takeaway: confidence is only useful when checked against outcomes. Calibrate on separate data, monitor drift, and never mistake policy probability or a DPO preference margin for probability of correctness.
