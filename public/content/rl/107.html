2. A model can erase the residual it must estimate

The doubly robust correction uses:

\[Y_i-m(X_i)\]

If a flexible outcome model trains on \(Y_i\) and memorizes it, then on audited rows:

\[m(X_i)\approx Y_i\]

The residual becomes artificially zero. The evaluator concludes that its predictions need no correction—even if those predictions are badly biased elsewhere.

Cross-fitting prevents this:

  1. divide episodes into \(K\) folds;

  2. train nuisance models using every fold except \(k\);

  3. predict outcomes and propensities for fold \(k\);

  4. join all out-of-fold predictions.

For episode \(i\) in fold \(k(i)\):

\[\hat\mu_{\text{CF-DR}} = \frac1N\sum_i \left[ m^{(-k(i))}(X_i) + \frac{S_i}{\pi_i} \left( Y_i-m^{(-k(i))}(X_i) \right) \right]\]

The superscript \((-k)\) means that fold \(k\)’s labels were excluded from training.

Tensor shapes:

  • outcome, audit mask, propensity and fold ID: [N]

  • out-of-fold predictions and corrections: [N]

  • fold diagnostics: [K]

For LLM evaluation, split by the independent unit—often user, source prompt or template family—not individual completions. Otherwise near-duplicate prompts can leak across folds.

For DPO, evaluating preference accuracy on pairs used to train the reward or preference model is the same leakage problem. Cross-fitting improves fixed-data evaluation; it does not turn DPO into online RL.

  • Store unaudited outcomes as zero, but always protect them with the audit mask.

  • A balanced random fold assignment is torch.randperm(N) % K.

  • For fold \(k\), train using audited & (fold_ids != k).

  • Inside the DR function, call .detach() on predictions.

  • Use torch.where(audited, residual / propensity, 0).

Solutions

Deployment population:

high_risk = (
    torch.rand(num_episodes)
    < high_risk_probability
)

incident_probabilities = torch.where(
    high_risk,
    torch.tensor(
        high_risk_incident_probability
    ),
    torch.tensor(
        low_risk_incident_probability
    ),
)

true_incidents = (
    torch.rand(num_episodes)
    < incident_probabilities
).to(torch.float64)

Targeted audit:

audit_probabilities = torch.where(
    high_risk,
    torch.tensor(
        high_risk_audit_probability
    ),
    torch.tensor(
        low_risk_audit_probability
    ),
)

audited = (
    torch.rand(num_episodes)
    < audit_probabilities
)

observed_incidents = torch.where(
    audited,
    true_incidents,
    torch.zeros_like(true_incidents),
)

naive_audit_rate = (
    observed_incidents[audited].mean()
)

Leaky predictions:

global_audit_mean = (
    observed_incidents[audited]
    .mean()
    .detach()
)

leaky_predictions = torch.where(
    audited,
    observed_incidents,
    global_audit_mean,
)

Cross-fitting:

fold_ids = (
    torch.randperm(num_episodes)
    % num_folds
)

for fold in range(num_folds):
    validation_mask = (
        fold_ids == fold
    )

    training_audit_mask = (
        audited
        & (fold_ids != fold)
    )

    training_mean = (
        observed_incidents[
            training_audit_mask
        ]
        .mean()
        .detach()
    )

    cross_fitted_predictions[
        validation_mask
    ] = training_mean

    fold_training_means.append(
        training_mean
    )

fold_training_means = torch.stack(
    fold_training_means
)

Estimators:

def doubly_robust(outcome_predictions):
    predictions = (
        outcome_predictions.detach()
    )

    corrections = torch.where(
        audited,
        (
            observed_incidents
            - predictions
        ) / audit_probabilities,
        torch.zeros_like(predictions),
    )

    return (
        predictions + corrections
    ).mean()


oracle_rate = true_incidents.mean()

outcome_only_cross_fitted = (
    cross_fitted_predictions.mean()
)

ipw_rate = (
    audited.to(torch.float64)
    * observed_incidents
    / audit_probabilities
).mean()

dr_leaky = doubly_robust(
    leaky_predictions
)

dr_cross_fitted = doubly_robust(
    cross_fitted_predictions
)

The deployment incident rate is:

\[0.076\]

Targeted auditing produces an audited incident rate near:

\[\frac{ 0.8(0.02)(0.02) + 0.2(0.60)(0.30) }{ 0.8(0.02)+0.2(0.60) } \approx0.267\]

The leaky model copies every audited outcome, so:

\[Y_i-m_{\text{leaky}}(X_i)=0\]

on all rows that could provide corrections. Its DR result therefore remains near 0.267.

The cross-fitted predictions are also near 0.267, but they did not see their own validation labels. Their honest residuals remain available. Correct inverse-probability correction moves the estimate back toward 0.076.

Check answers

  1. A model may have memorized the same labels used to calculate residuals; zero training error says nothing about unseen outcomes.

  2. No. It makes predictions honest and out-of-sample, allowing correction and uncertainty estimates to work as intended.

  3. Each audited residual is expanded by the inverse probability of observing it, restoring the deployment residual distribution.

  4. Keep all episodes from the same independent cluster—such as a user, source prompt or template family—in one fold.

Retrieval answers

\[\hat\mu_{\text{DR}} = \frac1N\sum_i \left[ m(X_i)+ \frac{S_i}{\pi_i} (Y_i-m(X_i)) \right]\]

  1. Either the outcome model or propensity model must be correctly specified, with adequate support and honest nuisance predictions.

Takeaway: an evaluator must not inspect the label whose residual it later claims to measure. Generate every nuisance prediction out-of-fold, preserve cluster boundaries, detach evaluation tensors and inspect residuals by fold.
