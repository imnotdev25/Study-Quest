2. One rollout batch becomes stale during optimization

PPO usually performs several gradient epochs over one rollout batch. The denominator remains the policy that originally collected that batch:

\[\rho_t = \underbrace{ \exp\!\left( \log\pi_\theta(a_t\mid s_t) - \operatorname{stopgrad} \log\pi_{\text{old}}(a_t\mid s_t) \right) }_{\text{current policy relative to rollout policy}}\]

As optimization continues, \(\pi_\theta\) moves away from \(\pi_{\text{old}}\). Clipping limits parts of the surrogate, but does not prevent the full distributions from drifting.

A useful sampled forward-KL estimator is:

\[\widehat{D}_{\mathrm{KL}} = \frac1N\sum_t \underbrace{ \left[ (\rho_t-1)-\log\rho_t \right] }_{\ge0\text{ for every sample}}\]

It is preferable diagnostically to just averaging \(-\log\rho_t\), which can be negative on a finite batch.

Ratio concentration can be summarized with:

\[\operatorname{ESS} = \underbrace{ \frac{ \left(\sum_t\rho_t\right)^2 }{ \sum_t\rho_t^2 } }_{\text{effective weight count}}\]

\[\operatorname{ESS\ fraction} = \underbrace{\frac{\operatorname{ESS}}N}_{1\text{ is ideal; smaller means concentrated weights}}\]

Token-level ESS is only a diagnostic because tokens from one trajectory are not independent episodes.

Useful stopping signals are:

  • approximate or exact KL exceeds a target;

  • clipping fraction grows rapidly;

  • ratio tails become extreme;

  • ESS fraction falls;

  • policy objective stops improving.

For constrained PPO, update the safety multiplier once from each new rollout’s raw episode costs. Updating it once per PPO epoch would count the same safety evidence repeatedly.

DPO also reuses fixed data for many epochs, but it is offline preference optimization. It does not have an old on-policy rollout distribution that becomes stale in this PPO sense.

Shapes:

  • logits: [B, T, A]

  • chosen log-probabilities, ratios and advantages: [B, T]

  • valid mask: [B, T]

  • valid ratios used by ESS: [N_valid]

Solutions

Masked mean and frozen rollout data:

def masked_mean(values, mask):
    return (
        values * mask
    ).sum() / mask.sum()

with torch.no_grad():
    actions = old_distribution.sample()

    old_log_probabilities = (
        old_distribution.log_prob(actions)
    )

Combined normalized advantages:

raw_actor_advantages = (
    reward_advantages
    - safety_multiplier.detach()
    * cost_advantages
) * valid_mask

advantage_mean = masked_mean(
    raw_actor_advantages,
    valid_mask,
)

advantage_variance = masked_mean(
    (
        raw_actor_advantages
        - advantage_mean
    ).square(),
    valid_mask,
)

actor_advantages = (
    (
        raw_actor_advantages
        - advantage_mean
    )
    / torch.sqrt(
        advantage_variance + 1e-8
    )
).detach() * valid_mask

PPO objective:

log_ratios = (
    new_log_probabilities
    - old_log_probabilities
)

ratios = torch.exp(log_ratios)

unclipped_surrogate = (
    ratios * actor_advantages
)

clipped_surrogate = (
    ratios.clamp(
        1.0 - clip_epsilon,
        1.0 + clip_epsilon,
    )
    * actor_advantages
)

surrogate = torch.minimum(
    unclipped_surrogate,
    clipped_surrogate,
)

actor_loss = -masked_mean(
    surrogate,
    valid_mask,
)

Post-update ratios and KL:

updated_log_ratios = (
    updated_log_probabilities
    - old_log_probabilities
)

updated_ratios = torch.exp(
    updated_log_ratios
)

approximate_kl_tokens = (
    updated_ratios
    - 1.0
    - updated_log_ratios
)

    approximate_kl_tokens,
    valid_mask,

new_log_all = torch.log_softmax(
    new_logits,
    dim=-1,

    old_probabilities
    * (
        old_log_all
        - new_log_all
    )
).sum(dim=-1)

exact_kl = masked_mean(
    exact_kl_tokens,
    valid_mask,
)

Clip fraction and ESS:

outside_clip = (
    (
        updated_ratios
        < 1.0 - clip_epsilon

    | (
        updated_ratios
        > 1.0 + clip_epsilon

    valid_ratios.sum().square()

    effective_sample_size

    valid_ratios,
    0.05,

    valid_ratios,
    0.95,

Single dual update:

updated_safety_multiplier = torch.clamp(
    safety_multiplier
    + dual_lr
    * (
        episode_costs.mean()
        - cost_limit
    ),
    min=0.0,
)

Before optimization:

\[\rho_t = \underbrace{ \exp(\log\pi_{\text{old}}-\log\pi_{\text{old}}) }_{\exp(0)} =1\]

so KL is zero and ESS fraction is one.

As epochs reuse the batch, the expected pattern is:

  • KL rises;

  • ratio tails spread;

  • clipping fraction rises;

  • ESS fraction falls;

  • early stopping triggers after several epochs.

The exact stopping epoch depends on the sampled batch and optimizer dynamics; that is why diagnostics are measured rather than assumed.

The episode-cost mean is:

\[\bar C = \underbrace{\frac{0.80+1.40}{2}}_{1.10}\]

so the multiplier changes once:

\[\nu_{\text{new}} = \underbrace{0.80}_{\text{old price}} + \underbrace{0.10(1.10-1.00)}_{\text{rollout violation}} = 0.81\]

Check answers

  1. Many small token-level ratios can cross 0.8 or 1.2 while the average full-distribution divergence remains moderate.

  2. Importance weight is concentrating on fewer samples, making the reused batch less representative of the current policy.

  3. The optimizer step itself creates the policy movement that must be checked.

  4. No. It is a practical guardrail; exact trust-region methods constrain an explicit divergence approximation.

Retrieval answers

  1. Clipping suppresses only excessive improvement. Out-of-range movement in a harmful direction still receives a corrective gradient.

  2. PPO clipping limits policy-update incentives, whereas safety requires a separate raw-cost constraint and dual update.

Takeaway: rollout reuse is useful only while the current policy remains close to the policy that generated the data. Freeze old log-probabilities, watch KL, ratio tails and ESS, and never count one rollout’s safety evidence multiple times.
