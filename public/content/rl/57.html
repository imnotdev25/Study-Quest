🧩 Analogy: the best-looking apartment listing

You scroll 50 apartment listings and pick the one with the best photos. It’s probably a good apartment, but it’s also, almost by definition, the one whose photos flatter it most. The more listings you scan, the more of the “best” score is flattering photography. That’s the optimizer’s curse, and best-of-\(N\) has it.

Selected judge error keeps rising with \(N\), roughly like \(\sqrt{\ln N}\).

2. Selecting the highest score selects positive noise

Suppose candidate \(i\) has true utility \(u_i\), but the reward model observes:

\[r_i=u_i+\epsilon_i\]

where \(\epsilon_i\) is evaluator error.

Best-of-\(N\) selects:

\[i^*=\arg\max_i r_i\]

Selection considers both quality and noise. Even when the noise has zero mean before selection, the winning candidate tends to have unusually positive noise:

\[\mathbb E[r_{i^*}-u_{i^*}]>0\]

This is the optimizer’s curse: searching harder against an imperfect proxy finds examples that exploit its errors. Increasing \(N\) may improve actual quality, but the reported reward usually improves faster.

The same effect appears during RL training. Repeated policy updates search for outputs receiving high reward-model scores, including accidentally high scores caused by misspecification.

Useful safeguards include:

  • evaluate with an independent judge not used for selection;

  • report proxy reward and held-out quality separately;

  • vary evaluator seeds or models;

  • manually inspect the largest reward disagreements;

  • test adversarial and distribution-shifted prompts.

DPO is not immune. If its chosen responses were produced by best-of-\(N\) using a noisy reward model, DPO can distill that reward model’s mistakes. DPO itself remains offline preference optimization, not online exploration.

Tensor shapes:

  • true utilities, proxy scores: [prompts, N]

  • selected candidate indices: [prompts]

  • selected scores and utilities: [prompts]

  • mean optimism and regret: scalar

🔍 Deeper: selection selects noise

Proxy \(\hat r=r+e\) with \(e\sim\mathcal N(0,\sigma^2)\) independent of \(r\). Choosing \(\arg\max_i\hat r_i\) gives \(\mathbb E[\hat r_{\text{sel}}]-\mathbb E[r_{\text{sel}}]=\mathbb E[e_{\text{sel}}]>0\). The reported score overstates the true quality. Cost: \(\mathrm{KL}(\pi_{\text{BoN}}\|\pi)=\log N-\frac{N-1}{N}\), so best-of-\(N\) is a cheap way to get large KL, and the RL policy can push further still. Cure: score the selected outputs with an independent judge or held-out labels.

🔑 Key ideas

  • Stronger search improves quality and finds judge errors.

  • Track selected proxy reward against an independent estimate as \(N\) grows.

🚶 Walkthrough: \(N=16\)

Judge noise \(\sigma=0.5\). Expected selected noise \(\approx0.5\times1.77=0.88\) reward units, so a reported 0.88 of improvement could be pure judge error. KL from the base policy: \(\ln16-\tfrac{15}{16}=2.77-0.94=1.83\) nats.

Common mistakes

  • Reporting the selected score as the quality estimate.

  • Increasing \(N\) without increasing the audit.

  • Using the same judge to select and to evaluate.

⚙️ Algorithm: Best-of-\(N\) sampling
Input: policy \(\pi\), reward model \(\hat r\), number of samples \(N\)
for each prompt \(x\) do
sample \(y_1,\dots,y_N\sim\pi(\cdot|x)\)
\(s_i\gets\hat r(x,y_i)\) for each \(i\)
return \(y_{i^*}\) with \(i^*=\arg\max_is_i\) ▷ \(\mathrm{KL}\approx\log N-\frac{N-1}{N}\) from \(\pi\)
end
audit the winners with an independent judge: larger \(N\) selects reward-model errors too

Hints

Debugging experiments

Reuse proxy_scores as the “independent” evaluation. The reported evaluation then inherits precisely the noise used for selection and cannot reveal optimism.

Set noise_std = 0. Proxy and true utility become identical, so optimism and regret should approach zero.

Increase reward noise to 3.0. Best-of-\(N\) reward rises dramatically, while actual selected quality improves much less.

Finally, copy the same candidate \(N\) times. Candidate count increases, but effective diversity does not; independent samples—not tensor width alone—create the selection effect.

Solutions

Proxy scores:

proxy_scores = (
    true_utilities + proxy_noise
)

Selection:

selected_indices = (
    proxy_scores.argmax(dim=1)
)

Gather selected quantities:

selected_proxy = proxy_scores[
    rows, selected_indices
]

selected_true = true_utilities[
    rows, selected_indices
]

selected_independent = independent_scores[
    rows, selected_indices
]

Diagnostics:

oracle_true = (
    true_utilities.max(dim=1).values
)

optimism = (
    selected_proxy - selected_true
).mean()

regret = (
    oracle_true - selected_true
).mean()

independent_error = (
    selected_independent - selected_true
).mean()

Run every \(N\):

results = [
    evaluate_best_of_n(n)
    for n in candidate_counts
]

For \(N=1\), the only candidate is also the true-quality oracle, so:

\[\text{regret}=0\]

As \(N\) increases, selected true utility generally improves. However, selected proxy score improves faster because selection increasingly favors positive evaluator errors.

The independent evaluator’s error was not used during selection, so:

\[\mathbb E[ r^{\text{independent}}_{i^*} -u_{i^*} ]\approx0\]

Its finite-sample mean will not be exactly zero, but it should not reproduce the proxy’s growing optimism.

Check answers

  1. argmax preferentially selects candidates whose noise realization is positive, making the selected noise distribution non-zero-mean.

  2. Reusing the selection judge measures success against the same exploitable errors; an independent judge provides a less biased estimate.

  3. Policy optimization repeatedly searches output space for reward-model weaknesses, making those weaknesses systematic policy behaviors.

  4. Log training reward, held-out judge scores, human ratings, judge disagreement, best-of-\(N\) optimism, reward–quality correlation and results across evaluator variants.

Retrieval answers

  1. A reversed label gives the genuinely preferred response a large negative DPO margin; its gradient approaches the maximum magnitude \(\beta\).

  2. The model may simply fit annotation errors, biases or incomplete preferences. Training loss measures dataset fit, not factuality or safety.

Takeaway: stronger search improves both quality and exploitation opportunities. Track selected proxy reward against an independent quality estimate—especially as rollout count, policy optimization or best-of-\(N\) increases.
