🧩 Analogy: two commutes with the same average

Commute A always takes 30 minutes. Commute B usually takes 25, but once a month it takes over two hours. Their averages are nearly equal. Which one would you pick if you had a flight to catch? Mean cost describes ordinary days. CVaR describes your worst days.

Both average 30 minutes. B’s worst 5% averages 125.

2. Average cost can look safe while rare failures are severe

Consider two tools:

  • safe tool: always costs 1;

  • risky tool: usually costs 0, but occasionally costs 20.

Both can have the same mean cost. The mean hides the risky tool’s rare failures—like reporting average API latency while ignoring the worst outages.

For costs, where larger is worse, upper-tail CVaR at confidence \(\alpha\) is the average cost in the worst \(1-\alpha\) fraction:

\[\operatorname{CVaR}_{\alpha}(C) = \mathbb E[ C\mid C\text{ is in the worst }1-\alpha ]\]

A useful optimization form is:

\[\operatorname{CVaR}_{\alpha}(C) = \min_\eta \left[ \eta+ \frac{1}{1-\alpha} \mathbb E[(C-\eta)_+] \right]\]

Here:

  • \(\eta\) approximates the value-at-risk threshold;

  • \((C-\eta)_+=\max(C-\eta,0)\);

  • only costs exceeding the threshold contribute excess loss.

A risk-adjusted objective might be:

\[J(\pi) = \mathbb E[R] - \lambda_{\text{risk}} \operatorname{CVaR}_{\alpha}(C)\]

CVaR is not a hard guarantee. It reduces tail cost on average; action shields are still needed for inviolable limits.

Tensor shapes in the exercise:

  • sampled costs: [strategies, rollouts]

  • threshold \(\eta\): [strategies]

  • excess costs: [strategies, rollouts]

  • mean cost and CVaR: [strategies]

DPO can learn aversion to catastrophic traces only if those failures appear in the preference dataset. Online RL can discover new failures, but rare tails require many rollouts and careful evaluation.

🔍 Deeper: VaR and CVaR

For a cost \(C\): \(\mathrm{VaR}_\alpha=\) the \(\alpha\)-quantile, and \(\mathrm{CVaR}_\alpha=\mathbb E[C\mid C\ge\mathrm{VaR}_\alpha]\), the mean of the worst \((1-\alpha)\) fraction. Rockafellar–Uryasev form, convenient to optimize: \[\mathrm{CVaR}_\alpha(C)=\min_\nu\Big\{\nu+\tfrac{1}{1-\alpha}\mathbb E\big[(C-\nu)_+\big]\Big\}.\] Sample size: to see the worst 1%, you need many more than 100 rollouts. Expect roughly \(n(1-\alpha)\) tail samples.

🔑 Key ideas

  • Means describe ordinary behaviour, and CVaR describes bad days.

  • Keep hard shields for outcomes that must never happen.

🚶 Walkthrough: CVaR\(_{0.95}\)

A: always 30, so CVaR \(=30\). B: 25 with probability 0.95 and 125 with probability 0.05, mean \(23.75+6.25=30\). The worst 5% is exactly the 125 case, so CVaR\(_{0.95}=125\). At \(\alpha=0.9\), B’s worst 10% \(=\) half 125, half 25, so CVaR \(=75\).

Common mistakes

  • Estimating CVaR\(_{0.99}\) from 100 samples (one tail sample).

  • Using the wrong tail (for rewards, the bad tail is the lower one).

  • Reporting VaR as if it described how bad the tail gets.

⚙️ Algorithm: Empirical CVaR of rollout costs
Input: costs \(C_1,\dots,C_n\) from independent rollouts, level \(\alpha\)
sort costs in descending order: \(C_{(1)}\ge C_{(2)}\ge\dots\)
\(m\gets\lceil n(1-\alpha)\rceil\) ▷ number of tail samples
if \(m<\) about 30 then warn: the tail estimate is unreliable
end
return \(\mathrm{VaR}=C_{(m)}\), \(\mathrm{CVaR}=\frac1m\sum_{i=1}^mC_{(i)}\) (bootstrap whole rollouts for a CI)

Hints

  • Use .mean(dim=1).

  • Use torch.quantile(costs, alpha, dim=1).

  • The naïve mask is costs >= threshold[:, None].

  • Use math.ceil((1 - alpha) * num_rollouts).

  • torch.topk(..., dim=1).values selects the largest costs.

  • Excess cost is torch.relu(costs.detach() - eta[:, None]).

  • Sum the two CVaR objectives before backpropagating.

Debugging experiments

Reduce the rollout count to 20. The rare event may disappear entirely, making both empirical mean and CVaR misleading.

Estimate CVaR using all values greater than or equal to the empirical quantile. When many samples equal the threshold, the “tail” may contain far more than \(10\%\) of the batch.

Set alpha = 0.99. Only the worst 1% matters, increasing estimator variance and sample requirements.

Finally, compute CVaR over rewards without changing the tail direction. For rewards, low values are bad, so use the lower tail or convert reward into a loss first.

4. Checks for understanding

  1. Why can two policies with equal expected cost have different safety profiles?

  2. Why is quantile-threshold masking unreliable when many samples are tied?

  3. Does low CVaR prove that catastrophic outcomes are impossible?

  4. What diagnostics should accompany tail-risk optimization?

Solutions

Mean and value-at-risk:

mean_costs = costs.mean(
    dim=1
)

value_at_risk = torch.quantile(
    costs,
    alpha,
    dim=1,
)

Naïve estimate:

naive_tail_mask = (
    costs >= value_at_risk[:, None]
)

naive_cvar = (
    costs * naive_tail_mask
).sum(dim=1) / naive_tail_mask.sum(dim=1)

For the risky strategy, the 90th percentile is zero. Therefore, cost >= 0 selects every rollout, and the naïve “CVaR” incorrectly becomes the ordinary mean.

Exact worst-fraction estimate:

worst_count = math.ceil(
    (1.0 - alpha)
    * num_rollouts
)

worst_costs = torch.topk(
    costs,
    k=worst_count,
    dim=1,
).values

topk_cvar = worst_costs.mean(
    dim=1
)

Differentiable objective:

excess_costs = torch.relu(
    costs.detach()
    - eta[:, None]
)

cvar_objectives = (
    eta
    + excess_costs.mean(dim=1)
    / (1.0 - alpha)
)

loss = cvar_objectives.sum()

Final optimized estimate:

optimized_excess = torch.relu(
    costs - eta[:, None]
)

optimized_cvar = (
    eta
    + optimized_excess.mean(dim=1)
    / (1.0 - alpha)
)

Risk-adjusted scores:

mean_adjusted_scores = (
    strategy_rewards
    - risk_weight * mean_costs
)

cvar_adjusted_scores = (
    strategy_rewards
    - risk_weight * topk_cvar
)

Both mean costs equal:

\[\mathbb E[C_{\text{safe}}] = \mathbb E[C_{\text{risky}}] = 1\]

For the risky strategy, the worst 10% contains:

  • 500 rollouts costing 20;

  • 500 rollouts costing 0.

Therefore:

\[\operatorname{CVaR}_{0.9} = \frac{500(20)+500(0)}{1000} = 10\]

The resulting scores are:

\[J_{\text{mean}} = [0.95,\;1.15]\]

so the mean-based objective chooses the risky strategy.

\[J_{\text{CVaR}} = [0.95,\;0.70]\]

so the CVaR-based objective chooses the safe strategy.

Check answers

  1. Expected cost discards distribution shape; one policy may concentrate the same mean into rare catastrophic events.

  2. A threshold tie can select much more than the intended tail fraction. Top-\(k\) selection controls its exact size.

  3. No. CVaR summarizes tail severity but cannot guarantee zero probability of catastrophe.

  4. Report mean, quantiles, CVaR at several \(\alpha\) values, maximum cost, failure frequency, confidence intervals and rollout count.

Retrieval answers

  1. Earlier spending changes which future actions are legal, so remaining budget is necessary to make the state Markov.

  2. Otherwise the numerator and denominator use different action distributions, creating incorrect PPO ratios even with unchanged weights.

Takeaway: means describe ordinary behavior; CVaR describes bad days. Use enough rollouts to observe the tail, and retain hard shields for outcomes that must never occur.
