🧩 Analogy: capping each person vs capping the household

A family budget caps total monthly spending. If instead you cap each person separately, the family’s spending mix changes: the big spender is cut hard, the small spender not at all. Gradient clipping is nonlinear in the same way. Clipping each microbatch’s gradient changes the direction of the final update, not just its size.

\(g_1=(3,0)\), \(g_2=(0,1)\), max norm 1. Clipping early rotates the update.

2. Gradient clipping is nonlinear

Global-norm clipping limits the size of an update:

\[\tilde g = g\cdot \min\left( 1, \frac{C}{\lVert g\rVert_2+\epsilon} \right)\]

where \(C\) is max_grad_norm.

If the gradient norm exceeds \(C\), clipping shortens the vector without changing its direction.

With gradient accumulation, the desired batch gradient is:

\[g=\sum_k g_k\]

The correct order is:

  1. accumulate every microbatch gradient;

  2. unscale mixed-precision gradients;

  3. compute the global norm;

  4. clip once;

  5. call the optimizer.

Clipping each microbatch separately gives:

\[\sum_k\operatorname{clip}(g_k)\]

which generally differs from:

\[\operatorname{clip}\left(\sum_k g_k\right)\]

This happens because clipping is nonlinear. Large opposing gradients may legitimately cancel. Clipping them before cancellation changes their relative contribution and can rotate the final update.

The same issue applies to actor, critic, entropy and KL terms. Clipping every term independently changes the intended loss coefficients.

Practical limits:

  • clipping prevents extreme updates but does not repair bad rewards or ratios;

  • clipping on every step suggests instability, not successful training;

  • with AMP, clip only after scaler.unscale_(optimizer);

  • log the pre-clipping norm, post-clipping norm and clipping frequency.

Tensor shapes:

  • each microbatch gradient: [num_parameters]

  • accumulated gradient: [num_parameters]

  • global norm and clipping scale: scalar

DPO has no critic, but its preference gradients can also spike; the same accumulation and clipping order applies.

🔍 Deeper: clip once, at the optimizer boundary

\(\operatorname{clip}(g)=g\cdot\min(1,\ c/\|g\|)\). It is not linear: \(\operatorname{clip}(g_1)+\operatorname{clip}(g_2)\ne\operatorname{clip}(g_1+g_2)\) in general. Correct order: accumulate all microbatches, then under mixed precision unscale (scaler.unscale_(opt)), then log the pre-clip norm, clip once, and step. Clipping scaled AMP gradients compares the norm against \(c\) times the loss scale, which is almost never what you meant.

🔑 Key ideas

  • Clipping changes direction when applied piecewise.

  • Accumulate, unscale, measure, clip once, step.

🚶 Walkthrough: the numbers behind the picture

Per-microbatch: \(\operatorname{clip}(3,0)=(1,0)\), \(\operatorname{clip}(0,1)=(0,1)\), sum \(=(1,1)\), which points at 45\(^\circ\). Correct: sum \((3,1)\), norm \(3.16\), clipped to \((0.949,0.316)\), which points at 18.4\(^\circ\).

Common mistakes

  • Clipping inside the accumulation loop.

  • Clipping before unscale_ with AMP.

  • Logging only the post-clip norm (it’s always \(\le c\), so it tells you nothing).

Debugging experiments

Use only:

optimizer.zero_grad()
loss.backward()

inside every microbatch iteration. Zeroing between microbatches discards earlier gradients, so the optimizer sees only the final chunk.

Next, clip the actor and critic gradients separately before adding them. This can alter the effective value-loss coefficient and hide actor–critic conflict.

With AMP, clip scaled gradients before calling unscale_. The artificial scaling factor makes nearly every update look enormous, causing excessive clipping.

Solutions

Microbatch gradients:

microbatch_gradients = [
    torch.autograd.grad(
        loss,
        parameters,
        retain_graph=True,
    )[0]
    for loss in microbatch_losses
]

Accumulated gradient:

accumulated_gradient = torch.stack(
    microbatch_gradients
).sum(dim=0)

Clipping function:

def clip_vector(gradient, maximum_norm):
    gradient_norm = gradient.norm(p=2)

    clipping_scale = torch.clamp(
        maximum_norm
        / (
            gradient_norm + epsilon
        ),
        max=1.0,
    )

    clipped_gradient = (
        gradient * clipping_scale
    )

    return (
        clipped_gradient,
        gradient_norm,
        clipping_scale,
    )

Correct clipping:

(
    correctly_clipped_gradient,
    accumulated_norm,
    global_scale,
) = clip_vector(
    accumulated_gradient,
    max_grad_norm,
)

Incorrect early clipping:

early_clipped_gradient = torch.stack(
    individually_clipped
).sum(dim=0)

The unmodified accumulated gradient is:

\[[100,0]+[-90,10]=[10,10]\]

Its norm is:

\[\sqrt{10^2+10^2}\approx14.14\]

Correct clipping rescales it to norm 5:

\[[10,10]\frac5{14.14} \approx [3.54,3.54]\]

The direction remains [1,1].

Clipping the microbatches separately gives approximately:

\[\operatorname{clip}([100,0]) = [5,0]\]

\[\operatorname{clip}([-90,10]) \approx [-4.97,0.55]\]

Their sum is approximately:

\[[0.03,0.55]\]

This points almost vertically rather than diagonally. Its norm is below 5, but it is still the wrong gradient for the intended full-batch objective.

Check answers

  1. Every component is multiplied by the same positive scalar, so component ratios remain unchanged.

  2. Each microbatch receives a different scale before cancellation, changing its relative weight.

  3. The learning rate, reward scale, loss coefficients or data may be producing consistently excessive gradients. The threshold may also be unrealistically small.

  4. The post-clipping norm often equals the threshold and hides whether the original norm was 6, 60 or 60,000.

Retrieval answers

  1. A local mean gives every microbatch equal outer weight regardless of its valid-token count; correct accumulation uses the objective’s global denominator.

  2. Large opposing gradients can cancel. The total norm alone therefore hides component magnitude and conflict.

Takeaway: gradient clipping belongs at the optimizer boundary. Accumulate the intended batch gradient, unscale it, inspect its norm and clip once.
