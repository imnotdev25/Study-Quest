2. A token is not necessarily a unit of time

Suppose a response of length \(L\) receives terminal reward \(R\). Its reward-to-go is:

\[G_t = \gamma^{L-1-t}R\]

With \(\gamma=1\), every action receives the same terminal outcome:

\[G_t=R\]

With \(\gamma<1\), earlier actions receive exponentially less credit. The first token receives:

\[G_0=\gamma^{L-1}R\]

For example:

\[0.95^{63}\approx0.0395\]

So the first token of a 64-token response receives only about 4% of its terminal reward.

The mean return within a response is:

\[\bar G_L = \frac{R}{L} \sum_{k=0}^{L-1}\gamma^k = R\frac{1-\gamma^L}{L(1-\gamma)}\]

Thus prompt-balanced averaging does not remove this length effect.

In ordinary RL, discounting can express real time preference or continuing-task uncertainty. In an LLM, token count partly depends on tokenizer choice and writing style. Two tokenizers can assign different credit to the same semantic answer.

For finite text-generation episodes, \(\gamma=1\) is often the clearest default. If shorter responses are desired, use an explicit, interpretable token cost:

\[R_{\text{adjusted}} = R-cL\]

For tool-using agents, \(\gamma<1\) may be appropriate when each step represents genuine latency, cost or delayed utility.

Tensor shapes:

  • token rewards and mask: [B, T]

  • discount factors: [G]

  • returns for every response and discount: [B, G, T]

Remember that GAE introduces another decay:

\[(\gamma\lambda)^k\]

Even with \(\gamma=1\), \(\lambda<1\) shortens how far TD residuals propagate.

DPO has no temporal discount factor. It compares sequence log-probability margins on fixed preference data; any length effect comes from sequence summation, normalization or the data—not from \(\gamma\).

Solutions

Mask and terminal rewards:

token_positions = torch.arange(
    maximum_length
)[None, :]

response_mask = (
    token_positions
    < lengths[:, None]
)

final_indices = (
    lengths - 1
)[:, None]

terminal_rewards = torch.zeros(
    batch_size,
    maximum_length,
).scatter(
    dim=1,
    index=final_indices,
    src=sequence_rewards[:, None],
)

Batched returns:

def calculate_returns(
    token_rewards,
    mask,
    gammas,
):
    returns = torch.zeros(
        batch_size,
        num_discounts,
        maximum_length,
    )

    running_returns = torch.zeros(
        batch_size,
        num_discounts,
    )

    for token_index in reversed(
        range(maximum_length)
    ):
        immediate_rewards = (
            token_rewards[:, token_index]
            [:, None]
        )

        candidate_returns = (
            immediate_rewards
            + gammas[None, :]
            * running_returns
        )

        valid_here = (
            mask[:, token_index]
            [:, None]
        )

        running_returns = torch.where(
            valid_here,
            candidate_returns,
            torch.zeros_like(
                candidate_returns
            ),
        )

        returns[:, :, token_index] = (
            running_returns
        )

    return returns

Measured credit:

first_token_credit = (

Expected first-token credit is approximately:

Length \(\gamma=1\) \(\gamma=0.99\) \(\gamma=0.95\)
Length \(\gamma=1\) \(\gamma=0.99\) \(\gamma=0.95\)
4 1.000 0.970 0.857
16 1.000 0.860 0.463
64 1.000 0.531 0.039

For \(\gamma=0.95\), the same answer represented with 8 versus 16 tokens receives:

\[0.95^7\approx0.698\]

versus:

\[0.95^{15}\approx0.463\]

The ratio is:

\[\frac{0.95^{15}}{0.95^7} = 0.95^8 \approx0.663\]

So the earlier decision receives about one-third less credit solely because the tokenizer produced eight additional tokens.

Check answers

  1. When steps represent real delay, tool cost, risk exposure or an intentionally time-preferred objective.

  2. \(c\) directly states the cost of one extra token; \(\gamma\) produces nonlinear, position-dependent attenuation.

  3. No. Sparse rewards, critic error, GAE trace decay and high-variance policy gradients still make long-range credit difficult.

  4. Different token counts change discount exponents even when semantic content is identical.

  5. Log reward and advantage statistics against response length, finish reason, tokenizer, first-token credit and total generated tokens.

Retrieval answers

  1. Place the sequence score once at the final valid response token; reward-to-go or GAE propagates it backward.

  2. For task rewards alone:

\[\sum_t r^{\text{task}}_{b,t}=R_b\]

for every valid nonempty response.

Takeaway: choose \(\gamma\) as part of the objective, not as a default constant. In token-based episodes, \(\gamma<1\) creates an exponential preference over response length and can make identical text learn differently under different tokenizers.
