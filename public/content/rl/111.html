2. A stopped recording is not necessarily a finished task

A termination means the task itself ended: success, failure, EOS or an absorbing state.

A truncation means data collection stopped: timeout, rollout limit, max_new_tokens or infrastructure interruption. Future reward may still exist.

For a TD target:

\[y_t = r_t+\gamma \left(1-\mathbb{1}[\text{terminated}_t]\right) V_{\bar\phi}(s_{t+1})\]

A common bug uses:

\[1-\mathbb{1}[ \text{terminated}_t \lor \text{truncated}_t ]\]

This treats every timeout as if the environment’s future value became zero.

Keep two masks separate:

  • valid mask: does this padded tensor position contain a real transition?

  • continuation mask: should the target bootstrap from the next state?

For [B, T] trajectories:

\[L_V = \frac{ \sum_{b,t}m_{b,t} \left( V_\phi(s_{b,t})-\operatorname{stopgrad}(y_{b,t}) \right)^2 }{ \sum_{b,t}m_{b,t} }\]

Here, stopgrad is .detach(). Standard TD takes a semi-gradient: it updates the current prediction without differentiating through its moving target.

A fixed horizon can genuinely define termination—for example, a game that lasts exactly ten moves. Then remaining time should usually be part of the state. The distinction is whether the horizon belongs to the task or merely to the collector.

For LLMs, record EOS, maximum-token cutoff, timeout and tool-budget exhaustion separately. DPO has no Bellman bootstrap, but a cutoff completion is still censored data, not automatically an ordinary complete rejected response. DPO remains fixed-data preference optimization rather than online RL.

Solutions

Initialization:

value_estimates = torch.nn.Parameter(
    torch.zeros(2)
)

optimizer = torch.optim.SGD(
    [value_estimates],
    lr=learning_rate,
)

Transition flags and masks:

truncated = (
    torch.rand(batch_size)
    < truncation_probability
)

terminated = torch.zeros(
    batch_size,
    dtype=torch.bool,
)

done = terminated | truncated

correct_continuation = (
    ~terminated
).to(torch.float64)

wrong_continuation = (
    ~done
).to(torch.float64)

continuation_masks = torch.stack([
    correct_continuation,
    wrong_continuation,
])

rewards = torch.ones(batch_size)

Detached targets:

bootstrap_values = (
    value_estimates
    .detach()[:, None]
)

td_targets = (
    rewards[None, :]
    + gamma
    * continuation_masks
    * bootstrap_values
)

predictions = (
    value_estimates[:, None]
    .expand_as(td_targets)
)

TD update:

losses = (
    predictions - td_targets
).square().mean(dim=1)

total_loss = losses.sum()

optimizer.zero_grad()
total_loss.backward()
optimizer.step()

Fixed points and diagnostics:

analytical_correct_value = (
    1.0 / (1.0 - gamma)
)

analytical_wrong_value = (
    1.0
    / (
        1.0
        - gamma
        * (
            1.0
            - truncation_probability
        )
    )
)

analytical_values = torch.tensor([
    analytical_correct_value,
    analytical_wrong_value,
])

final_biases = (
    value_estimates.detach()
    - analytical_values
)

correct_target_on_truncation = (
    1.0
    + gamma
    * value_estimates[0].detach()
)

wrong_target_on_truncation = torch.tensor(
    1.0
)

The correct learner solves:

\[V=1+0.9V \quad\Rightarrow\quad V=10\]

The buggy learner bootstraps only on the expected 80% of non-truncated transitions:

\[V = 1+0.9(0.8)V\]

\[V = \frac1{1-0.72} \approx3.571\]

Near convergence, a truncated transition therefore receives:

  • correct target: \(1+0.9(10)=10\);

  • incorrect target: \(1\).

Removing .detach() does not change this toy problem’s optimum, but it changes the gradient into a residual-gradient update and makes learning much slower. With neural critics and shared computation, it can also create unintended gradient paths.

Check answers

  1. A collector timeout does not imply that the environment’s remaining return is zero.

  2. It is terminal when the horizon is part of the task definition and no reward exists beyond it.

  3. Validity controls whether a transition contributes to the loss; continuation controls whether its next-state value enters the target.

  4. Log the finish reason, cutoff length, unfinished status and final pre-reset context. Do not silently record it as EOS or success.

Retrieval answers

  1. Length normalization changes the relative values assigned to policy-controlled sequences, potentially reversing \(J_{\text{verbose}}-J_{\text{concise}}\) and thus the gradient sign.

  2. Exclude prompt tokens, padding positions and all positions after EOS; retain only generated response tokens that actually occurred.

Takeaway: zero future value belongs to genuine terminal states. For arbitrary rollout cutoffs, preserve the final observation and bootstrap—otherwise the critic learns the collector’s patience instead of the task’s return.
