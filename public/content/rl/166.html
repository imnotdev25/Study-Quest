2. Two ways a rollout can stop — 5 minutes

An agent trajectory can end because:

  • Termination: the task genuinely ended—success, failure or a terminal state.

  • Truncation: data collection stopped—the time limit, token budget or rollout horizon was reached, but the underlying task could have continued.

Imagine pausing a chess game because the recording window ended. The game is truncated, not checkmated.

For a value estimate, the one-step TD error is:

\[\underbrace{\delta_t}_{\text{new evidence about }V(s_t)} = \underbrace{r_t}_{\text{immediate reward}} + \underbrace{\gamma(1-d_t^{\mathrm{term}})V(s_{t+1})}_{\text{bootstrap unless truly terminal}} - \underbrace{V(s_t)}_{\text{current prediction}}\]

Here:

  • \(d_t^{\mathrm{term}}=1\): true terminal transition;

  • \(d_t^{\mathrm{term}}=0\): continuing or truncated transition.

At true termination, there is no future environment return, so the next-state value is discarded.

At truncation, the future still exists outside the collected rollout, so we bootstrap from the final observation:

\[\delta_t^{\mathrm{trunc}} = r_t+\gamma V(s_{t+1})-V(s_t)\]

Treating every timeout as terminal incorrectly uses:

\[\delta_t^{\mathrm{wrong}} = r_t-V(s_t)\]

This systematically undervalues states near rollout limits.

For GAE, we need a second boundary mask:

\[\underbrace{A_t^{\mathrm{GAE}}}_{\text{multi-step advantage}} = \underbrace{\delta_t}_{\text{current TD error}} + \underbrace{\gamma\lambda c_t A_{t+1}^{\mathrm{GAE}}}_{\text{earlier errors carried backward}}\]

where

\[\underbrace{c_t}_{\text{trace continuation}} = 1- \underbrace{\max(d_t^{\mathrm{term}},d_t^{\mathrm{trunc}})}_{\text{stored episode ends here}}\]

This gives two distinct decisions:

Boundary Bootstrap in \(\delta_t\)? Carry GAE across reset?
Boundary Bootstrap in \(\delta_t\)? Carry GAE across reset?
Normal transition Yes Yes
True termination No No
Time-limit truncation Yes No

We bootstrap at truncation using the final observation, but do not allow the GAE recursion to cross into the next reset episode.

For tool agents:

  • genuine submitted answer or unrecoverable failure may terminate;

  • collector horizon or infrastructure timeout usually truncates;

  • exhausting a task-defined budget may terminate if the specification explicitly scores it as failure.

DPO does not face TD bootstrapping because it trains on fixed preference pairs rather than online transitions. It can still inherit biased treatment of incomplete responses from its dataset.

Shapes:

  • rewards, values, next values: [B, T]

  • terminated, truncated, valid masks: [B, T]

  • TD errors, advantages, value targets: [B, T]

  1. Does the terminal transition use the artificial next value 9.0?

  2. Does the truncated transition bootstrap from 0.7?

  3. Should the truncated transition’s GAE trace enter a newly reset episode?

  4. Should padded advantages be nonzero?

Hints

  • Bootstrap mask: logical negation of terminated.

  • Episode end: terminated | truncated.

  • Convert Boolean masks to the floating dtype where needed.

  • In the backward recurrence, multiply the final running advantage by valid[:, t].

  • Critic target is detached advantage plus the old value estimate.

Solutions

bootstrap_mask = (~terminated).to(torch.float64)

episode_ended = terminated | truncated
trace_continue = (~episode_ended).to(torch.float64)

td_errors = (
    rewards
    + gamma * bootstrap_mask * next_values
    - values
) * valid

advantages = torch.zeros_like(rewards)
running_advantage = torch.zeros(3)

for t in reversed(range(max_steps)):
    running_advantage = (
        td_errors[:, t]
        + gamma
        * gae_lambda
        * trace_continue[:, t]
        * running_advantage
    )
    running_advantage = running_advantage * valid[:, t]
    advantages[:, t] = running_advantage

value_targets = (advantages + values).detach() * valid

At the final valid transition:

\[\delta^{\mathrm{term}}_2 = 1-0.6 = 0.4\]

The 9.0 is ignored.

For the truncated trajectory:

\[\delta^{\mathrm{trunc}}_2 = 0+0.9(0.7)-0.6 = 0.03\]

If truncation were incorrectly treated as termination:

\[\delta^{\mathrm{wrong}}_2=0-0.6=-0.6\]

That is a large artificial negative target produced solely by the collection limit.

4. Checks for understanding — 3 minutes

  1. Why are separate bootstrap and trace-continuation masks necessary?

  2. What observation must an environment retain when it reports truncation?

  3. When should a tool-budget exhaustion be treated as termination?

  4. What training symptom might appear if every rollout-horizon cutoff is marked terminal?

Check answers

  1. Truncation needs future-value bootstrapping, but the stored recursion must stop before the reset episode. One mask cannot express both requirements.

  2. The final observation before reset. Bootstrapping from the new episode’s initial observation estimates the wrong state.

  3. When the task specification defines budget exhaustion as an actual failed outcome. An incidental collector or infrastructure limit is normally truncation.

  4. Values become artificially low near the horizon. Advantages may turn strongly negative there, encouraging premature stopping and creating horizon-dependent behaviour.

Retrieval answers

  1. They add reward for the intermediate behaviour itself, so the agent may farm tool calls rather than improve task success.

  2. Terminal potential should be zero—or otherwise handled consistently so the terminal boundary term does not change action rankings.

  3. Combined reward can rise while true task reward falls. Separate logs expose whether the policy is improving the goal or exploiting the shaping signal.

Takeaway: termination controls whether a future value exists; truncation only says that collection stopped. Bootstrap through time limits, stop traces at reset boundaries, and never bootstrap from the next episode’s initial state.
