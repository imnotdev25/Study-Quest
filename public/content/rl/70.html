🧩 Analogy: manager and worker reviews

A manager picks which project the team works on. A worker decides how to do each task. Judging the manager once per project and the worker once per task is fair. Judging the manager every hour the project runs would mean long projects count far more in the manager’s review, just for being long.

2. Two policies made two different decisions

Think of a manager choosing “research the topic” and a worker choosing each search, page and extraction step.

The manager selects an option once:

\[o_t\sim\mu_\theta(o\mid s_t)\]

After \(k\) primitive steps, its advantage is:

\[\hat A_t^{H} = \left( \sum_{j=0}^{k-1}\gamma^j r_{t+j} + \gamma^k V_H(s_{t+k}) \right) - V_H(s_t)\]

Its loss contains one log-probability:

\[L_H = -\log\mu_\theta(o_t\mid s_t) \hat A_t^{H}\]

The worker chooses each internal action:

\[a_{t+j}\sim\pi_\phi(a\mid s_{t+j},o_t)\]

Each action receives its own option-conditioned advantage:

\[\hat A_{t+j}^{L} = G_{t+j}-V_L(s_{t+j},o_t)\]

\[L_L = -\frac{ \sum_j M_j \log\pi_\phi(a_{t+j}\mid s_{t+j},o_t) \hat A_{t+j}^{L} }{ \sum_j M_j }\]

Repeating the manager’s log-probability at every worker step accidentally gives long options greater weight. Duration should enter through \(\gamma^k\), latency costs or an explicit time-based objective—not through duplicated log-probabilities.

Detach both advantages in actor losses. Otherwise, actors can change the critic computation used to grade them.

Tensor shapes:

  • manager logits: [B, O]

  • selected options and manager advantages: [B]

  • worker logits: [B, T, A]

  • worker actions, advantages and masks: [B, T]

  • both reduced losses: scalar

DPO can rank complete hierarchical traces, but it learns from fixed comparisons. Online hierarchical RL separately explores which option to select and how to execute it.

🔍 Deeper: two levels, two losses

Manager (policy over options): \(\mathcal L_{\text{mgr}}=-\sum_{\text{option starts }j}\log\mu(o_j|s_j)\,A^{\Omega}_j\), one term per selection. Worker (intra-option policy): \(\mathcal L_{\text{wkr}}=-\sum_t\log\pi_{o_t}(a_t|s_t)\,A^U_t\), one term per primitive step. The bug: writing \(\log\mu(o|s)\) at every primitive step multiplies each manager decision’s gradient by its duration \(k\). Long options get more say for no good reason.

🔑 Key ideas

  • Credit each decision once, at the level where it was made.

  • Use a manager mask that is 1 only at option starts.

🚶 Walkthrough: duration-weighted gradients

Two options, both with \(A^\Omega=+1\): one lasted 1 step, the other 9. Correct manager gradient weight: \(1:1\). With the per-step bug: \(1:9\), so the long option is reinforced 9\(\times\) more.

Common mistakes

  • One mask shared by manager and worker.

  • Computing \(A^\Omega\) from primitive-step values.

  • Bootstrapping the manager with \(\gamma\) instead of \(\gamma^k\).

Debugging experiments

Broadcast manager_advantages[:, None] into the worker loss. Every internal action then receives credit for whether the manager chose a good routine, not whether that action executed it well.

Remove .detach() from advantages produced by trainable critics. Check whether actor losses now alter critic parameters.

Compare global worker-step normalization with normalizing each option separately and then averaging. The first weights primitive decisions equally; the second weights option executions equally. Neither is universally correct—document the intended objective.

Finally, monitor manager and worker gradient norms separately. One loss can otherwise dominate shared network parameters.

Solutions

Selected log-probabilities:

manager_log_probs = Categorical(
    logits=manager_logits
).log_prob(selected_options)

worker_log_probs = Categorical(
    logits=worker_logits
).log_prob(selected_actions)

Separate losses:

safe_worker_advantages = torch.where(
    worker_mask,
    worker_advantages,
    torch.zeros_like(worker_advantages),
)

manager_loss = -(
    manager_log_probs
    * manager_advantages.detach()
).mean()

worker_loss = -(
    worker_log_probs
    * safe_worker_advantages.detach()
    * mask_float
).sum() / mask_float.sum()

Correct gradients:

correct_manager_gradient = (
    torch.autograd.grad(
        manager_loss,
        manager_logits,
    )[0]
)

correct_worker_gradient = (
    torch.autograd.grad(
        worker_loss,
        worker_logits,
    )[0]
)

Repeated-manager bug:

repeated_manager_log_probs = Categorical(
    logits=manager_logits
).log_prob(selected_options)

repeated_manager_loss = -(
    repeated_manager_log_probs[:, None]
    * manager_advantages.detach()[:, None]
    * mask_float
).sum() / mask_float.sum()

repeated_manager_gradient = (
    torch.autograd.grad(
        repeated_manager_loss,
        manager_logits,
    )[0]
)

Diagnostics:

durations = worker_mask.sum(dim=1)

correct_manager_norms = (
    correct_manager_gradient.norm(dim=-1)
)

repeated_manager_norms = (
    repeated_manager_gradient.norm(dim=-1)
)

relative_manager_weights = (
    repeated_manager_norms
    / correct_manager_norms.clamp_min(1e-12)
)

padding_gradient_max = (
    correct_worker_gradient[~worker_mask]
    .abs()
    .max()
)

With three manager decisions and seven valid worker steps, the repeated-loss relative weights are:

\[\frac{3k_i}{7} = [0.857,\;1.714,\;0.429]\]

Thus the four-step option is overweighted, while the one-step option is underweighted.

At uniform logits, the chosen manager-logit gradients are approximately:

\[[-0.167,\;0.167,\;-0.083]\]

Gradient descent subtracts these values. Positive advantages therefore raise selected logits; negative advantages lower them. Padded worker gradients are exactly zero.

Check answers

  1. The manager asks whether the selected option was better than alternative options. The worker asks whether each primitive action was good within that option.

  2. The manager sampled the option once; repetition changes its weight according to option duration.

  3. When its behavior is fixed, scripted or differentiably optimized through another objective rather than sampled.

  4. Log losses and gradient norms by level, option durations, return by option, worker advantages by position, padding gradients and performance under alternative loss normalizations.

Retrieval answers

  1. Positive option advantage means continuing is better than switching, so gradient descent lowers termination probability.

  2. With cost \(\eta\), termination is encouraged only when \(A_\Omega<-\eta\), discouraging unnecessary switching.

Takeaway: credit each sampled decision at the level where it occurred—once for option selection and once per valid primitive action.
