2. Learn the value model needed for offline evaluation

Fitted Q Evaluation—FQE—estimates the value of one fixed target policy \(\pi\) from logged transitions:

\[(s_i,a_i,r_i,s'_i,d_i)\]

Its Bellman target is:

\[y_i = \underbrace{r_i}_{\text{observed immediate reward}} + \underbrace{ \gamma(1-d_i) \sum_{a'}\pi(a'\mid s'_i) Q_{\bar\phi}(s'_i,a') }_{\text{target-policy continuation value}}\]

Then regress:

\[\mathcal L_{\mathrm{FQE}}(\phi) = \underbrace{ \frac1B\sum_i \left( Q_\phi(s_i,a_i) - \operatorname{stopgrad}(y_i) \right)^2 }_{\text{Bellman error on logged state–action pairs}}\]

Finally:

\[\hat V^\pi = \underbrace{ \frac1{N_0}\sum_{i=1}^{N_0} \sum_a\pi(a\mid s_{0,i}) Q_\phi(s_{0,i},a) }_{\text{estimated target-policy return from initial states}}\]

The expectation over \(\pi\) is crucial. Replacing it with:

\[\max_{a'}Q(s',a')\]

turns the target into Q-learning: it evaluates a greedy policy, not the specified policy.

FQE can provide the \(Q\)-model used by sequential doubly robust evaluation. But its accuracy depends on logged support. An unseen target action receives no direct regression loss; a neural network may assign it an arbitrary value while achieving tiny logged Bellman error.

Practical details:

  • Detach Bellman targets or use a target network.

  • Mask terminal transitions with \(1-d_i\).

  • Audit state–action counts and target-policy coverage.

  • Use held-out trajectories to diagnose Bellman error.

  • Preference pairs used by DPO are not sufficient FQE data; FQE needs environment transitions and outcome rewards.

Tensor shapes:

  • states, actions, rewards and terminals: [N]

  • \(Q\)-table: [S, A]

  • target policy: [S, A]

  • Bellman targets and predictions: [N]

Hints

The backward recursion is:

\[Q^\pi(s,a) = \underbrace{r(s,a)}_{\text{current reward}} + \underbrace{\gamma V^\pi(s+1)}_{\text{remaining return}}\]

\[V^\pi(s) = \underbrace{ \sum_a\pi(a\mid s)Q^\pi(s,a) }_{\text{target-policy action average}}\]

  • Construct states as 0, 1, 2 for every episode, then flatten.

  • The terminal state has no \(Q\)-row; assign its continuation value zero.

  • Initialize the target table with q_values.detach().clone().

  • Only index target_q[next_states] for nonterminal rows.

  • Encode a state–action pair as state * num_actions + action.

Exact dynamic programming:

def exact_policy_evaluation():
    q_values = torch.zeros(
        num_states,
        num_actions,
    )

    v_values = torch.zeros(
        num_states + 1
    )

    for state in reversed(range(num_states)):
        q_values[state] = (
            reward_table[state]
            + gamma * v_values[state + 1]
        )

        v_values[state] = (
            target_policy[state]
            * q_values[state]
        ).sum()

    return q_values, v_values


exact_q, exact_v = exact_policy_evaluation()

def generate_dataset(

        next_states == num_states

    rewards = reward_table[
        states,
        actions,

        states,
        actions,
        rewards,
        next_states,
        terminals,

FQE:

def fitted_q_evaluation(
    dataset,
    num_updates=600,
    target_update_period=20,
):
    (
        states,
        actions,
        rewards,
        next_states,
        terminals,
    ) = dataset

    q_values = torch.nn.Parameter(
        torch.zeros(num_states, num_actions)
    )

    optimizer = torch.optim.Adam(
        [q_values],
        lr=0.05,
    )

    target_q = q_values.detach().clone()

    losses = []

    for update in range(num_updates):
        with torch.no_grad():
            next_values = torch.zeros_like(
                rewards
            )

            nonterminal = ~terminals

            next_values[nonterminal] = (
                target_policy[
                    next_states[nonterminal]
                ]
                * target_q[
                    next_states[nonterminal]
                ]
            ).sum(dim=-1)

            bellman_targets = (
                rewards
                + gamma * next_values
            )

        predictions = q_values[
            states,
            actions,
        ]

        loss = F.mse_loss(
            predictions,
            bellman_targets,
        )

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        if (
            update + 1
        ) % target_update_period == 0:
            target_q = (
                q_values.detach().clone()
            )

        losses.append(loss.detach())

    estimated_initial_value = (
        target_policy[0]
        * q_values.detach()[0]
    ).sum()

    state_action_indices = (
        states * num_actions + actions
    )

    counts = torch.bincount(
        state_action_indices,
        minlength=num_states * num_actions,
    ).reshape(num_states, num_actions)

    return (
        q_values.detach(),
        estimated_initial_value.detach(),
        torch.stack(losses),
        counts,
    )


supported_result = fitted_q_evaluation(
    supported_data
)

unsupported_result = fitted_q_evaluation(
    unsupported_data
)

Exact values:

\[Q^\pi = \begin{bmatrix} 0.792 & 0.892\\ 0.720 & 0.920\\ 0.000 & 1.000 \end{bmatrix}\]

\[V^\pi(0) = \underbrace{ 0.2(0.792)+0.8(0.892) }_{0.872}\]

With support, learned \(Q\) and value should approach these numbers.

Without final-state action-1 support:

\[\hat Q(2,1) = \underbrace{0}_{\text{zero initialization; never directly updated}}\]

This propagates backward:

\[\hat V(2)=0\]

\[\hat V(1)=0.8(0.20)=0.16\]

\[\hat V(0) = \underbrace{ 0.2(0.144)+0.8(0.244) }_{0.224}\]

The unsupported estimate can therefore converge near 0.224 with almost zero training loss, despite the true value being 0.872.

Check answers

  1. FQE evaluates the specified policy by averaging over \(\pi\); Q-learning uses a maximizing target and moves toward a greedy policy.

  2. Bootstrapping replaces noisy returns with model predictions, reducing variance but propagating approximation or extrapolation errors.

  3. The loss checks only logged pairs. Unsupported target actions can have arbitrary values without increasing it.

  4. Use FQE as the \(Q\)-baseline, then apply importance-weighted TD-residual corrections from sequential DR.

  5. Collect targeted data, narrow the evaluated policy, or report partial bounds. Function approximation cannot manufacture identification.

Retrieval answers

  1. Sequential DR is consistent when either its cumulative propensity ratios are correct or its \(Q\)-model is correct throughout the trajectory.

  2. A terminal transition has no future environment return; bootstrapping beyond it invents reward and biases every predecessor.

Takeaway: FQE asks, “How would this fixed policy perform?”—not “Which action looks best?” Always inspect target-policy support, because a perfect fit to logged transitions can coexist with a badly wrong deployment value.
