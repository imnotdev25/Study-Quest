2. From exact expectations to sampled gradients

We want to maximize reward while limiting expected cost:

\[\max_\theta J_R(\theta) \quad\text{subject to}\quad J_C(\theta)\le d\]

The Lagrangian is:

\[\mathcal L(\theta,\lambda) = \underbrace{J_R(\theta)}_{\text{reward}} - \underbrace{\lambda}_{\text{learned cost price}} \underbrace{(J_C(\theta)-d)}_{\text{constraint violation}} + \underbrace{\beta H(\pi_\theta)}_{\text{exploration}}\]

For sampled trajectories, the policy gradient becomes:

\[\nabla_\theta\mathcal L = E\!\left[ \nabla_\theta\log\pi_\theta(A) \left(G_R-\lambda G_C\right) \right] + \beta\nabla_\theta H\]

Separate baselines reduce variance:

\[A_i^{\text{aug}} = \underbrace{(G_i^R-b_i^R)}_{\text{reward surprise}} - \underbrace{\lambda}_{\text{safety price}} \underbrace{(G_i^C-b_i^C)}_{\text{cost surprise}}\]

The minimized actor loss is:

\[L_{\text{actor}} = -\frac1B\sum_i \underbrace{\log\pi_\theta(a_i)}_{\text{credit path}} \underbrace{\operatorname{stopgrad}(A_i^{\text{aug}})}_{\text{sampled direction}} - \beta H(\pi_\theta)\]

A positive augmented advantage increases the sampled action’s probability; the leading minus sign converts gradient ascent into PyTorch’s gradient descent.

The multiplier follows raw cost—not centered cost:

\[\lambda \leftarrow \left[ \lambda+ \eta_\lambda \underbrace{(\bar C-d)}_{\substack{>0:\ \text{raise price}\\<0:\ \text{lower price}}} \right]_+\]

The limit \(d\) is absent from the actor advantage because it is constant with respect to the action. It matters in the dual update.

For an exactly unbiased minibatch baseline, exclude sample \(i\):

\[b^R_{-i} = \frac{\sum_{j\ne i}G_j^R}{B-1}\]

Using the full current-batch mean includes the sample’s own outcome and shrinks the gradient by \(1-1/B\). A baseline from earlier batches is another valid option.

Shapes:

  • actions, rewards, costs, log-probabilities, advantages: [B]

  • policy logit, entropy mean, multiplier and loss: scalar []

DPO instead optimizes preference likelihood on a fixed dataset. It has no environment cost samples or dual update, so it does not itself enforce an online expected-cost constraint.

Hints

  • Leave-one-out mean: (values.sum() - values) / (B - 1).

  • Detach both advantages and the multiplier inside the actor loss.

  • Use -mean(log_prob * advantage) - beta * entropy.

  • Update \(\lambda\) using costs.mean() - cost_limit, then clamp at zero.

  • For a Bernoulli logit, the score term is \(a-p\).

  • The analytical sampled-return gradient is:

\[p(1-p) \left[ \underbrace{(r_1-r_0)}_{\text{reward gap}} - \lambda \underbrace{(c_1-c_0)}_{\text{cost gap}} \right]\]

Debugging checks

  • Remove the minus sign from the actor loss: updates move opposite the desired direction.

  • Update \(\lambda\) from centered cost advantages: the constraint signal disappears.

  • Use an excessively large dual learning rate: cost and multiplier oscillate.

  • Forget detach(): learned critics or differentiable rewards may receive unintended actor gradients.

  • Independently rescale reward or cost without adjusting \(\lambda\): its “price” changes meaning.

Solutions

def leave_one_out_mean(values):
    return (
        values.sum() - values
    ) / (values.numel() - 1)

Actor advantages and loss:

reward_baselines = leave_one_out_mean(
    rewards
)
cost_baselines = leave_one_out_mean(
    costs
)

reward_advantages = (
    rewards - reward_baselines
).detach()

cost_advantages = (
    costs - cost_baselines
).detach()

augmented_advantages = (
    reward_advantages
    - multiplier.detach()
    * cost_advantages
).detach()

actor_loss = -(
    distribution.log_prob(actions)
    * augmented_advantages
).mean() - (
    entropy_coefficient
    * distribution.entropy().mean()
)

Dual update:

multiplier = torch.clamp(
    multiplier
    + dual_lr
    * (
        costs.detach().mean()
        - cost_limit
    ),
    min=0.0,
)

Typical training results are:

\[P(\text{risky})\approx0.28, \qquad E[R]\approx0.50, \qquad E[C]\approx0.30, \qquad \lambda\approx1.27\]

Individual iterations fluctuate because both actor and multiplier use samples. The final-window average is more informative than one final minibatch.

At the diagnostic point:

\[\begin{aligned} \nabla &= 0.3(0.7) \left[0.7-1.2(0.7)\right] \\ &= 0.21(-0.14)\\ &=-0.0294 \end{aligned}\]

Both estimators should average near -0.0294. Typical standard deviations are roughly 0.0047 for the raw estimator and 0.0033 with leave-one-out baselines.

Check answers

  1. They permit variance reduction and diagnostics for each signal while preserving the explicit reward–cost tradeoff.

  2. The multiplier must respond to actual constraint violation. Centered costs deliberately remove the mean.

  3. No. This is an expected-cost constraint; individual minibatches can exceed it.

  4. It excludes sample \(i\)’s own action-dependent outcome, preserving an unbiased score-function estimator.

Retrieval answers

  1. Increase \(\lambda\); unsafe actions then receive a larger effective penalty.

  2. The correct tradeoff depends on reward scale, cost scale and policy behavior. An adaptive multiplier responds directly to observed violation.

Takeaway: use centered reward and cost signals for a lower-variance actor gradient, but update the safety price from raw constraint violation. The actor learns what to do; the multiplier learns how expensive unsafe behavior must become.
