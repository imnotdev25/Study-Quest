2. A judge score is a noisy measurement, not ground truth

Suppose the true unsafe-outcome rate is \(p\). An automated judge has:

\[\text{TPR} = P(\hat Y=1\mid Y=1)\]

\[\text{FPR} = P(\hat Y=1\mid Y=0)\]

The observed positive rate is:

\[q = \text{TPR}\,p + \text{FPR}(1-p)\]

Rearranging:

\[q = \text{FPR} + (\text{TPR}-\text{FPR})p\]

Therefore:

\[p = \frac{q-\text{FPR}} {\text{TPR}-\text{FPR}}\]

The denominator:

\[J=\text{TPR}-\text{FPR}\]

is Youden’s \(J\). A useful judge has \(J>0\). If \(J\) is near zero, the judge barely distinguishes positive from negative cases, and correction amplifies noise by approximately:

\[\frac1{|J|}\]

for standard errors.

This correction requires a human-labelled validation sample and assumes the judge’s TPR and FPR transfer to both evaluated policies. If the candidate learns to exploit the judge, that assumption may fail.

Tensor shapes:

  • true and judged outcomes: [A, N], with A=2 policies

  • confusion matrix: [2, 2], rows true and columns predicted

  • policy rates: [A]

For RLHF, a reward model’s errors affect training trajectories, not just reported prevalence. Post-hoc rate correction can improve evaluation, but it cannot undo a policy trained to exploit incorrect rewards.

DPO similarly learns from erroneous preferences. Lower DPO loss does not establish that preference labels—or their judge—are calibrated to human outcomes.

Hints

  • Use torch.where(true_incidents, TPR, FPR).

  • Make half the validation labels negative and half positive.

  • Encode a confusion-matrix cell as 2 * truth + prediction.

  • Reshape four bincount values into [2, 2].

  • TPR is cell [1, 1] divided by row 1.

  • FPR is cell [0, 1] divided by row 0.

  • Apply the inverse measurement equation separately to each policy.

  • Freeze calibration estimates during evaluation; they are not trainable reward-model parameters.

Debugging experiments

  • Swap the confusion matrix’s true and predicted axes.

  • Apply one calibration matrix across languages where judge errors differ.

  • Calibrate on control responses but assume candidate errors are identical after reward optimization.

  • Divide by a nearly zero Youden \(J\).

  • Silently clamp impossible corrected rates without investigating model mismatch.

  • Tune the judge prompt on the same human-labelled set used to report calibration.

Solutions

Deployment outcomes:

true_incidents = (
    torch.rand(
        2,
        num_episodes_per_policy,
    )
    < true_incident_probabilities[:, None]
)

judge_positive_probabilities = torch.where(
    true_incidents,
    torch.tensor(
        judge_true_positive_rate
    ),
    torch.tensor(
        judge_false_positive_rate
    ),
)

judged_incidents = (
    torch.rand_like(
        judge_positive_probabilities
    )
    < judge_positive_probabilities
)

empirical_true_rates = (
    true_incidents
    .to(torch.float64)
    .mean(dim=1)
)

observed_judge_rates = (
    judged_incidents
    .to(torch.float64)
    .mean(dim=1)
)

Balanced validation data:

validation_truth = torch.zeros(
    validation_size,
    dtype=torch.bool,
)

validation_truth[
    validation_size // 2:
] = True

validation_truth = validation_truth[
    torch.randperm(validation_size)
]

validation_judge_probabilities = torch.where(
    validation_truth,
    torch.tensor(
        judge_true_positive_rate
    ),
    torch.tensor(
        judge_false_positive_rate
    ),
)

validation_judgments = (
    torch.rand(validation_size)
    < validation_judge_probabilities
)

Confusion matrix:

confusion_indices = (
    2 * validation_truth.to(torch.long)
    + validation_judgments.to(torch.long)
)

confusion_matrix = torch.bincount(
    confusion_indices,
    minlength=4,
).reshape(2, 2).to(torch.float64)

estimated_tpr = (
    confusion_matrix[1, 1]
    / confusion_matrix[1].sum()
)

estimated_fpr = (
    confusion_matrix[0, 1]
    / confusion_matrix[0].sum()
)

estimated_specificity = (
    confusion_matrix[0, 0]
    / confusion_matrix[0].sum()
)

Corrected rates:

estimated_youden_j = (
    estimated_tpr
    - estimated_fpr
)

corrected_incident_rates = (
    observed_judge_rates
    - estimated_fpr
) / estimated_youden_j

oracle_corrected_rates = (
    observed_judge_rates
    - judge_false_positive_rate
) / (
    judge_true_positive_rate
    - judge_false_positive_rate
)

Improvements and diagnostics:

true_safety_improvement = (
    empirical_true_rates[0]
    - empirical_true_rates[1]
)

naive_judge_improvement = (
    observed_judge_rates[0]
    - observed_judge_rates[1]
)

corrected_safety_improvement = (
    corrected_incident_rates[0]
    - corrected_incident_rates[1]
)

standard_error_amplification = (
    1.0 / estimated_youden_j.abs()
)

variance_amplification = (
    standard_error_amplification.square()
)

exact_observed_judge_rates = (
    judge_false_positive_rate
    + (
        judge_true_positive_rate
        - judge_false_positive_rate
    )
    * true_incident_probabilities
)

The expected observed judge rates are:

\[q_{\text{control}} = 0.30+(0.85-0.30)(0.20) = 0.41\]

\[q_{\text{candidate}} = 0.30+(0.85-0.30)(0.10) = 0.355\]

The naive measured improvement is therefore only:

\[0.41-0.355=0.055\]

although the true reduction is:

\[0.20-0.10=0.10\]

Correction divides the judged difference by:

\[J=0.85-0.30=0.55\]

giving:

\[\frac{0.055}{0.55}=0.10\]

But the same division amplifies standard errors by:

\[\frac1{0.55}\approx1.82\]

and variances by approximately 3.31. Calibration improves bias while potentially increasing variance.

Check answers

  1. Accuracy combines errors according to one class mixture. Deployment prevalence can differ, while TPR and FPR reveal the two error directions separately.

  2. The judge contains little information about truth, so inversion becomes numerically unstable and statistically noisy.

  3. It is invalid when errors depend on policy style, subgroup, language, response length or reward-model exploitation.

  4. No. It adjusts aggregate evaluation under stable error assumptions; it cannot reconstruct trajectories that training changed in response to faulty rewards.

Retrieval answers

  1. Random ordering supplies observations under both positions; averaging and differencing their logits identifies quality and position effects.

  2. Because sigmoid is nonlinear, averaging probabilities outside it differs from averaging logits before applying it.

Takeaway: judge outputs are measurements with sensitivity and false-positive rates—not truth. Validate them against humans, propagate calibration uncertainty, and check whether their error pattern changes after the policy learns to optimize the judge.
