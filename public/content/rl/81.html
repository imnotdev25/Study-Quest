🧩 Analogy: grading each round of a quiz

In a multi-round quiz, the score for round 2 shouldn’t depend on what the team does in round 5. When reweighting a multi-turn router’s logs, weight each reward only by the routing choices made up to that point. This is the router version of per-decision IS (Topic 38).

2. Future actions cannot cause past rewards

For a trajectory, define the cumulative importance ratio:

\[\rho_{0:t} = \prod_{j=0}^{t} \frac{\pi(a_j\mid s_j)} {\mu(a_j\mid s_j)}\]

Ordinary trajectory importance sampling weights the complete return using the final ratio:

\[\hat J_{\text{OIS}} = \frac1N\sum_i \rho_{0:T-1}^{(i)} \sum_{t=0}^{T-1}\gamma^t r_t^{(i)}\]

This is unbiased under the usual support assumptions, but unnecessarily multiplies early rewards by ratios from future decisions.

Per-decision importance sampling instead uses:

\[\hat J_{\text{PDIS}} = \frac1N\sum_i \sum_{t=0}^{T-1} \gamma^t \rho_{0:t}^{(i)} r_t^{(i)}\]

A reward at time \(t\) depends on decisions through time \(t\), not later decisions. Removing future ratios usually lowers variance.

Do not use only the current-step ratio:

\[\frac{\pi(a_t\mid s_t)} {\mu(a_t\mid s_t)}\]

Earlier actions changed the distribution of \(s_t\), so their ratios must remain in the cumulative product.

For numerical stability:

\[\log\rho_{0:t} = \sum_{j=0}^{t} \left[ \log\pi(a_j\mid s_j) - \log\mu(a_j\mid s_j) \right]\]

Tensor shapes:

  • rewards, masks and selected log-probabilities: [B, T];

  • cumulative log-ratios and ratios: [B, T];

  • trajectory returns and estimates: [B] or scalar.

In padded batches, invalid steps must contribute zero log-ratio and zero reward. For LLMs, PDIS matters when intermediate token, tool, latency or process rewards exist. With only one terminal sequence reward, PDIS and trajectory IS coincide.

DPO optimizes fixed preference pairs; it does not replace sequential off-policy evaluation of an interactive agent.

🔍 Deeper: cumulative ratios, reset per episode

\(\hat V=\frac1n\sum_i\sum_t\gamma^t\rho^{(i)}_{0:t}r^{(i)}_{t+1}\), with \(\rho_{0:t}=\prod_{k\le t}\pi(a_k|h_k)/b(a_k|h_k)\). Variance still grows with \(t\): late rewards carry long products. A typical second-moment bound grows like \(\prod_k\mathbb E[\rho_k^2]\). Bookkeeping: the product resets to 1 at each episode start, and conditioning on history \(h_k\) (not just \(x_k\)) must match how the router actually decided.

🔑 Key ideas

  • Keep past ratios and drop future ones.

  • Reset cumulative products at every episode boundary.

🚶 Walkthrough: forgetting to reset

Episode 1 ends with \(\rho_{0:2}=4\). Episode 2’s first step has true ratio \(0.5\). Correct: \(\rho_{0:0}=0.5\). Without a reset: \(4\times0.5=2\), so episode 2’s first reward is counted 4\(\times\) too much.

Common mistakes

  • One running product across the whole log.

  • Propensities conditioned on the wrong history.

  • No per-timestep ESS diagnostics.

3. PyTorch exercise — full-trajectory versus per-decision ratios

The first action becomes the second state:

\[s_1=a_0\]

The second reward is one when the next action matches that state.

Hints

  • state_one is the first action.

  • Stack the two rewards along the final dimension.

  • Selected action probability is p for action 1 and 1-p for action 0.

  • Use torch.cumsum(step_log_ratios, dim=-1).

  • Ordinary IS uses the final cumulative ratio for the entire return.

  • PDIS multiplies each discounted reward by its corresponding cumulative ratio.

Debugging experiments

  • Weight \(r_0\) with the final trajectory ratio. The mean remains correct, but variance increases.

  • Replace cumulative ratios with independent step ratios. The second-state distribution remains that of the behavior policy.

  • Compute long-horizon products directly. Expect underflow, overflow and extreme variance.

  • Let cumsum cross padding or an episode boundary. Ratios from unrelated decisions contaminate later rewards.

  • Recompute behavior log-probabilities using new weights. Stored denominators must remain detached snapshots of the rollout policy.

Solutions

Rewards:

state_one = actions[:, :, 0]

reward_zero = (
    actions[:, :, 0]
    .to(torch.float64)
)

reward_one = (
    actions[:, :, 1]
    == state_one
).to(torch.float64)

rewards = torch.stack(
    [reward_zero, reward_one],
    dim=-1,
)

discounted_rewards = (
    rewards
    * discounts[None, None, :]
)

Ratios:

behavior_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        behavior_one_probability
    ),
    torch.tensor(
        1.0
        - behavior_one_probability
    ),
)

target_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        target_one_probability
    ),
    torch.tensor(
        1.0
        - target_one_probability
    ),
)

step_log_ratios = (
    target_action_probabilities.log()
    - behavior_action_probabilities.log()
)

step_ratios = step_log_ratios.exp()

prefix_log_ratios = torch.cumsum(
    step_log_ratios,
    dim=-1,
)

prefix_ratios = prefix_log_ratios.exp()

Naive and ordinary IS:

trajectory_returns = (
    discounted_rewards.sum(dim=-1)
)

naive_estimates = (
    trajectory_returns.mean(dim=1)
)

trajectory_weights = (
    prefix_ratios[:, :, -1]
)

ordinary_is_estimates = (
    trajectory_weights
    * trajectory_returns
).mean(dim=1)

Per-decision estimates:

pdis_estimates = (
    prefix_ratios
    * discounted_rewards
).sum(dim=-1).mean(dim=1)

current_step_only_estimates = (
    step_ratios
    * discounted_rewards
).sum(dim=-1).mean(dim=1)

Exact value and diagnostics:

target_match_probability = (
    target_one_probability ** 2
    + (
        1.0
        - target_one_probability
    ) ** 2
)

exact_target_value = torch.tensor(
    target_one_probability
    + gamma
    * target_match_probability
)

means = all_estimates.mean(dim=0)

biases = (
    means - exact_target_value
)

standard_deviations = (
    all_estimates.std(
        dim=0,
        correction=1,
    )
)

rmses = (
    (
        all_estimates
        - exact_target_value
    )
    .square()
    .mean(dim=0)
    .sqrt()
)

Under the target policy:

\[\mathbb E[r_0]=0.8\]

The second action matches the first with probability:

\[P(a_1=a_0) = 0.8^2+0.2^2 = 0.68\]

Therefore:

\[J(\pi) = 0.8+0.9(0.68) = 1.412\]

Ordinary IS and PDIS should both center near 1.412. PDIS has lower variance because \(r_0\) is not multiplied by the unrelated future action ratio.

The current-step-only estimator leaves \(s_1=a_0\) distributed according to the behavior policy. Its expected value is:

\[0.8+0.9[ 0.2(0.8)+0.8(0.2) ] = 1.088\]

Check answers

  1. Earlier actions influence the state and therefore the distribution from which \(r_t\) arises.

  2. Future actions cannot causally alter an already observed reward.

  3. When all reward occurs at the final decision, both use the same final cumulative ratio.

  4. Log ratio quantiles by position, cumulative-weight ESS, maximum weight, estimate variance, padding leakage and results versus horizon.

Retrieval answers

  1. The correction uses \(r-\hat q(s,a)\).

  2. DR is consistent when either behavior propensities are correct or the conditional outcome model is correct, assuming support and suitable estimation conditions.

Takeaway: importance weight only the decisions that could have influenced each reward. Keep past ratios, discard future ones and reset cumulative products at every episode boundary.
