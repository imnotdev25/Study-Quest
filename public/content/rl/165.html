2. Helpful milestones can become loopholes — 5 minutes

Suppose the real task reward is:

  • +1: correct final answer

  • 0: otherwise

Learning may be slow because success is rare. We might add rewards for intermediate steps:

  • +0.2 for searching

  • +0.2 for using a calculator

This looks helpful, but the agent can now increase reward by calling unnecessary tools.

\[\underbrace{r'_t}_{\text{training reward}} = \underbrace{r_t}_{\text{real task reward}} + \underbrace{b_t}_{\text{handwritten tool bonus}}\]

A direct correct answer and a wasteful five-tool answer no longer optimize the same objective.

A safer construction is potential-based reward shaping. Give each state a progress score \(\Phi(s)\), then reward only the change in discounted potential:

\[\underbrace{F_t}_{\text{shaping signal}} = \underbrace{\gamma\Phi(s_{t+1})}_{\text{discounted next-state potential}} - \underbrace{\Phi(s_t)}_{\text{current-state potential}}\]

The shaped reward is:

\[\underbrace{r'_t}_{\text{reward used for learning}} = \underbrace{r_t}_{\text{environment reward}} + \underbrace{\gamma\Phi(s_{t+1})-\Phi(s_t)}_{\text{progress shaping}}\]

Across a trajectory, the shaping terms telescope:

\[\underbrace{G'_0}_{\text{shaped return}} = \underbrace{G_0}_{\text{original return}} - \underbrace{\Phi(s_0)}_{\text{same starting-state offset}} + \underbrace{\gamma^T\Phi(s_T)}_{\text{terminal boundary term}}\]

If terminal potentials are zero:

\[G'_0=G_0-\Phi(s_0)\]

Every action available from the same state receives the same constant offset. Therefore, the action ranking is preserved even though intermediate learning signals become denser.

Important limits:

  • A badly learned potential can still add variance or optimization difficulty.

  • Terminal potential must be handled consistently.

  • Timeouts and true terminal states should not be silently confused.

  • Tool costs may legitimately belong in the real objective when latency or money truly matters.

  • Process rewards that are not potential differences can redefine the task.

DPO does not solve this automatically. DPO optimizes preference pairs; if annotators prefer verbose tool traces, those preferences can teach the same unnecessary-tool shortcut offline.

Shapes:

  • environment and shaped rewards: [B, T]

  • state potentials: [B, T + 1]

  • transition mask: [B, T]

  • trajectory returns: [B]

Solutions

def discounted_returns(rewards, mask):
    running = torch.zeros(batch_size)
    returns = torch.zeros_like(rewards)

    for t in reversed(range(max_steps)):
        running = rewards[:, t] + gamma * running
        running = running * mask[:, t]
        returns[:, t] = running

    return returns

environment_returns = discounted_returns(
    environment_rewards, transition_mask
)

naive_rewards = (
    environment_rewards + 0.2 * tool_calls
) * transition_mask

naive_returns = discounted_returns(
    naive_rewards, transition_mask
)

potential_shaping = (
    gamma * potentials[:, 1:]
    - potentials[:, :-1]
) * transition_mask

potential_rewards = (
    environment_rewards + potential_shaping
) * transition_mask

potential_returns = discounted_returns(
    potential_rewards, transition_mask
)

expected_potential_start_return = (
    environment_returns[:, 0] - potentials[:, 0]
)

telescoping_error = (
    potential_returns[:, 0]
    - expected_potential_start_return
).abs().max()

4. Checks for understanding — 3 minutes

  1. Why does the tool-heavy success have a lower original return than the direct success?

  2. When is a tool penalty legitimately part of the real reward rather than mere shaping?

  3. What bug occurs if padded state potentials are allowed to enter the shaping term?

  4. Why should reward-component logging include environment reward and shaping reward separately?

Check answers

  1. Discounting places the success farther in the future:

    \[0.9^1 > 0.9^3\]

  2. When tool usage has a real deployment cost—latency, money, privacy exposure or safety risk—the penalty belongs in the task objective.

  3. Padding can create artificial potential changes after termination, adding fake rewards and breaking the telescoping identity.

  4. A rising shaped return can hide falling task success. Separate logging reveals whether the policy improves the true outcome or merely collects intermediate signals.

Retrieval answers

  1. Return-to-go records temporal precedence, not causality. Every earlier action can inherit later success.

  2. Padding is not an environment transition. Including it invents rewards, losses and gradients.

  3. A valid baseline reduces variance. It does not change the expected policy-gradient direction when it is independent of the sampled action.

Takeaway: dense feedback is useful only when you know what objective it creates. Potential differences provide progress signals while preserving the original action ranking; arbitrary milestone bonuses may quietly train the agent to farm tools.
