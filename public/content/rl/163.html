2. Training reward is not the final judge

Suppose checkpoint \(k\) scores well under the optimized proxy:

\[\widehat R_k^{\text{train}} = \underbrace{ \frac1N\sum_{i=1}^N R_{\text{proxy}}(x_i,y_{ik}) }_{\text{score directly pressured by training}}\]

We also need an independent audit \(M\): held-out tests, human review, an adversarial verifier or deployment outcomes.

Evaluate each checkpoint and a baseline on the same prompts. For a binary audit:

\[d_i^{(k)} = \underbrace{ M(x_i,\pi_k)-M(x_i,\pi_0) }_{\text{checkpoint improvement on prompt }i}\]

The estimated improvement is:

\[\widehat\Delta_k = \underbrace{ \frac1N\sum_i d_i^{(k)} }_{\text{mean paired audit difference}}\]

Its standard error is:

\[SE_k = \underbrace{ \frac{s(d^{(k)})}{\sqrt N} }_{\text{uncertainty from finite prompts}}\]

A conservative promotion diagnostic is:

\[LCB_k = \underbrace{ \widehat\Delta_k-1.96SE_k }_{\text{lower edge of a normal-approximation 95\% interval}}\]

Pairing generally reduces variance because prompt difficulty affects both policies:

\[\operatorname{Var}(M_k-M_0) = \underbrace{ \operatorname{Var}(M_k)+\operatorname{Var}(M_0) -2\operatorname{Cov}(M_k,M_0) }_{\text{positive covariance lowers paired variance}}\]

Reward overoptimization often looks like:

\[\underbrace{ R_{\text{train}}\uparrow }_{\text{proxy keeps improving}} \qquad \underbrace{ R_{\text{audit}}\uparrow\ \text{then}\ \downarrow }_{\text{real performance peaks earlier}}\]

Select checkpoints on a development audit, lock the choice, then evaluate it once on an untouched confirmation set. Repeatedly tuning against the “held-out” set turns it into another training signal.

Do not subtract proxy and audit scores to form a “gap” unless their units are genuinely comparable. Plot them separately.

DPO needs the same protection: falling preference loss or rising held-out pair accuracy does not guarantee deployment utility. DPO is offline preference optimization, while online RL can actively discover new proxy exploits.

Shapes:

  • proxy scores and checkpoint metrics: [K]

  • audit outcomes: [N, K]

  • paired differences: [N, K]

  • standard errors and confidence bounds: [K]

Hints

  • Use torch.sigmoid(skill - difficulty).

  • Outcomes are torch.rand_like(probabilities) < probabilities.

  • Preserve the baseline column with outcomes[:, [0]].

  • Standard error is sample standard deviation divided by sqrt(N).

  • torch.argmax returns a scalar tensor.

  • Divergence means positive proxy change and negative audit change.

Debugging checks

  • Evaluate checkpoints on different prompt samples, losing the paired comparison.

  • Select and report performance on the same small audit set without confirmation.

  • Repeatedly modify training after inspecting the confirmation set.

  • Report only the average and hide subgroup or safety regressions.

  • Treat KL, entropy or training reward as substitutes for independent quality.

  • Ignore multiple-checkpoint selection: the maximum noisy score is usually optimistic.

Solutions

Audit simulation:

success_probabilities = torch.sigmoid(
    latent_audit_skills[None, :]
    - prompt_difficulty
)

outcomes = (
    torch.rand_like(success_probabilities)
    < success_probabilities
).to(torch.float64)

Paired estimates:

baseline_outcomes = outcomes[:, [0]]

paired_differences = (
    outcomes - baseline_outcomes
)

audit_rates = outcomes.mean(dim=0)

mean_differences = (
    paired_differences.mean(dim=0)
)

standard_errors = (
    paired_differences.std(
        dim=0,
        unbiased=True,
    )
    / outcomes.shape[0] ** 0.5
)

lower_bounds = (
    mean_differences
    - 1.96 * standard_errors
)

Checkpoint selection:

proxy_selected_checkpoint = (
    proxy_scores.argmax()
)

audit_selected_checkpoint = (
    development_rates.argmax()
)

Divergence detection:

proxy_step_changes = (
    proxy_scores[1:]
    - proxy_scores[:-1]
)

audit_step_changes = (
    development_rates[1:]
    - development_rates[:-1]
)

divergence_checkpoints = torch.nonzero(
    (proxy_step_changes > 0)
    & (audit_step_changes < 0)
).flatten() + 1

Confirmation diagnostics:

proxy_selected_confirmation_lcb = (
    confirmation_lower_bounds[
        proxy_selected_checkpoint
    ]
)

audit_selected_confirmation_lcb = (
    confirmation_lower_bounds[
        audit_selected_checkpoint
    ]
)

The proxy selects checkpoint 6, because its proxy score is highest. Audit performance should select checkpoint 3, where latent audit quality peaks.

The final proxy-selected checkpoint is actually worse than the baseline:

\[\underbrace{ \widehat\Delta_6<0 }_{\text{optimization continued past useful improvement}}\]

Checkpoint 3 should retain a positive confirmation difference and lower confidence bound. Exact sampled values are reproducible but finite-sample dependent.

Check answers

  1. Shared prompt difficulty creates positive covariance between checkpoint outcomes; pairing subtracts much of that nuisance variation.

  2. The policy is learning features rewarded by the proxy but unsupported—or penalized—by the independent objective.

  3. Selecting the largest development estimate introduces winner’s-curse optimism. Fresh data tests the locked decision.

  4. No. Examine its uncertainty, safety constraints, subgroups and confirmation result.

Retrieval answers

  1. Training reward continues rising while an independent audit stagnates or declines, often with growing evaluator disagreement.

  2. KL measures policy drift, not correctness. A nearby policy can still exploit the proxy, and a distant policy can still be useful.

Takeaway: choose where independent quality peaks, not where the optimized score peaks. Use paired prompts for precision, a development audit for checkpoint selection, and an untouched confirmation set for the final claim.
