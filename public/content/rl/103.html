2. “Response A wins” may mean “the judge prefers the first position”

Let \(\delta\) represent the candidate’s quality advantage over control and \(b\) the judge’s first-position bias.

A simple pairwise-judgment model is:

\[P(\text{candidate wins}\mid\text{candidate first}) = \sigma(\delta+b)\]

\[P(\text{candidate wins}\mid\text{candidate second}) = \sigma(\delta-b)\]

where:

\[\sigma(x)=\frac{1}{1+e^{-x}}\]

If candidate is shown first much more often, its naive win rate mixes quality with position.

Let the observed win rates be \(p_F\) and \(p_S\). Their logits satisfy:

\[\operatorname{logit}(p_F)=\delta+b\]

\[\operatorname{logit}(p_S)=\delta-b\]

Therefore:

\[\hat\delta = \frac{ \operatorname{logit}(p_F) + \operatorname{logit}(p_S) }{2}\]

\[\hat b = \frac{ \operatorname{logit}(p_F) - \operatorname{logit}(p_S) }{2}\]

Randomizing candidate position makes both effects identifiable. A 50/50 allocation also gives both orders useful sample sizes.

Tensor shapes:

  • position, logits, probabilities and judgments: [N]

  • group counts and win rates: scalars

Clamp empirical probabilities before taking logits. A stratum with all wins or all losses otherwise produces infinity.

DPO directly trains on preference labels. If those labels contain position bias, DPO learns from that bias; it does not automatically infer which preference signal was spurious.

Hints

  • Position sign is +1 when candidate is first and -1 otherwise.

  • Sample a win with torch.rand(N) < probability.

  • Clamp each win rate to [epsilon, 1-epsilon] before torch.logit.

  • Quality is the average of the two position-specific logits.

  • Position bias is half their difference.

  • For a binomial proportion:

\[\operatorname{Var}[\operatorname{logit}(\hat p)] \approx \frac{1}{np(1-p)}\]

Debugging experiments

  • Always display the candidate as response A.

  • Randomize order but fail to record which policy became A.

  • Reverse the displayed text without reversing the associated model ID.

  • Take torch.logit of an empirical zero or one without clamping.

  • Pool judgments across different judge prompts or model versions.

  • Treat the balanced arithmetic win rate as exactly equal to \(\sigma(\delta)\).

  • Train DPO on biased preferences and interpret lower loss as unbiased alignment.

Solutions

Judgment simulation:

candidate_first = (
    torch.rand(num_judgments)
    < candidate_first_probability
)

position_sign = torch.where(
    candidate_first,
    torch.tensor(1.0),
    torch.tensor(-1.0),
)

candidate_win_logits = (
    true_quality_logit
    + true_position_bias
    * position_sign
)

candidate_win_probabilities = torch.sigmoid(
    candidate_win_logits
)

candidate_wins = (
    torch.rand(num_judgments)
    < candidate_win_probabilities
).to(torch.float64)

Naive result:

naive_win_rate = candidate_wins.mean()

naive_win_logit = torch.logit(
    naive_win_rate.clamp(
        epsilon,
        1.0 - epsilon,
    )
)

naive_says_candidate_is_better = (
    naive_win_rate > 0.50
)

Position-specific rates:

first_mask = candidate_first
second_mask = ~candidate_first

first_count = first_mask.sum().to(
    torch.float64
)

second_count = second_mask.sum().to(
    torch.float64
)

first_win_rate = candidate_wins[
    first_mask
].mean()

second_win_rate = candidate_wins[
    second_mask
].mean()

first_win_logit = torch.logit(
    first_win_rate.clamp(
        epsilon,
        1.0 - epsilon,
    )
)

second_win_logit = torch.logit(
    second_win_rate.clamp(
        epsilon,
        1.0 - epsilon,
    )
)

Quality and bias estimates:

estimated_quality_logit = (
    first_win_logit
    + second_win_logit
) / 2.0

estimated_position_bias = (
    first_win_logit
    - second_win_logit
) / 2.0

estimated_neutral_win_probability = (
    torch.sigmoid(
        estimated_quality_logit
    )
)

balanced_order_win_rate = (
    first_win_rate
    + second_win_rate
) / 2.0

adjusted_says_candidate_is_better = (
    estimated_quality_logit > 0.0
)

Approximate uncertainty:

first_logit_variance = (
    1.0
    / (
        first_count
        * first_win_rate
        * (1.0 - first_win_rate)
    )
)

second_logit_variance = (
    1.0
    / (
        second_count
        * second_win_rate
        * (1.0 - second_win_rate)
    )
)

quality_standard_error = (
    0.5
    * torch.sqrt(
        first_logit_variance
        + second_logit_variance
    )
)

quality_lower_bound = (
    estimated_quality_logit
    - z_value
    * quality_standard_error
)

quality_upper_bound = (
    estimated_quality_logit
    + z_value
    * quality_standard_error
)

Oracle probabilities:

exact_first_win_probability = torch.sigmoid(
    true_quality_logit
    + true_position_bias
)

exact_second_win_probability = torch.sigmoid(
    true_quality_logit
    - true_position_bias
)

exact_neutral_win_probability = torch.sigmoid(
    true_quality_logit
)

exact_naive_win_probability = (
    candidate_first_probability
    * exact_first_win_probability
    + (
        1.0
        - candidate_first_probability
    )
    * exact_second_win_probability
)

The exact position-specific probabilities are:

\[p_F = \sigma(-0.2+1.0) = \sigma(0.8) \approx0.690\]

\[p_S = \sigma(-0.2-1.0) = \sigma(-1.2) \approx0.231\]

With candidate first 90% of the time:

\[p_{\text{naive}} = 0.9(0.690)+0.1(0.231) \approx0.644\]

The naive analysis therefore declares the worse candidate a strong winner.

The position-adjusted calculation recovers approximately:

\[\hat\delta\approx-0.20, \qquad \hat b\approx1.00\]

and the neutral-position preference probability is:

\[\sigma(-0.20)\approx0.450\]

The balanced arithmetic rate is approximately:

\[\frac{0.690+0.231}{2} \approx0.461\]

It is useful descriptively but differs from 0.450 because averaging probabilities outside a nonlinear sigmoid is not the same as averaging logits inside it.

Check answers

  1. Random assignment supplies observations under both positions, allowing position-specific logits to separate into their sum and difference.

  2. The smaller second-position stratum dominates uncertainty in the adjusted estimate.

  3. Because \(\sigma\) is nonlinear:

\[\frac{\sigma(\delta+b)+\sigma(\delta-b)}2 \neq\sigma(\delta)\]

in general.

  1. Store prompt ID, candidate/control IDs, displayed A/B mapping, randomized position propensity, judge version, judge prompt, decoding settings, raw verdict and retry history.

Retrieval answers

  1. Positive covariance appears with a minus sign in the variance of the paired difference, cancelling shared prompt difficulty.

  2. Zero is a real outcome, not a missing-value marker. Substitution changes the estimand and can create policy-dependent bias.

Takeaway: always randomize and log A/B order. A pairwise judge can otherwise reward screen position rather than policy quality—and preference optimization will faithfully learn that corrupted signal.
