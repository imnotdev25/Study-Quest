🧩 Analogy: testing a new price without customers

A shop wants to know how a new discount policy would perform without trying it on real customers. It looks at last year’s sales under the old policy and reweights them: “customers who happened to get discounts behaved like this.” That works only if the old policy sometimes did what the new one would do.

2. Evaluate without deploying

Suppose logged trajectories came from behavior policy \(\mu\), but we want the expected return of target policy \(\pi\).

For trajectory \(i\), importance sampling assigns the ratio:

\[w_i = \prod_t \frac{\pi(a_{i,t}\mid s_{i,t})} {\mu(a_{i,t}\mid s_{i,t})}\]

The trajectory was sampled with probability \(\mu\), so \(w_i\) reweights it as if it came from \(\pi\).

Compute in log space:

\[\log w_i = \sum_t M_{i,t} \left[ \log\pi(a_{i,t}\mid s_{i,t}) - \log\mu(a_{i,t}\mid s_{i,t}) \right]\]

\[w_i=\exp(\log w_i)\]

The mask \(M\) excludes padding and post-termination placeholders.

The ordinary importance-sampling estimate is:

\[\hat V_{\text{IS}} = \frac1N\sum_i w_iG_i\]

It is unbiased when the behavior policy covers every action the target might take:

\[\pi(a\mid s)>0 \implies \mu(a\mid s)>0\]

Without this support condition, the log contains no evidence about some target-policy behavior.

A lower-variance alternative is self-normalized IS:

\[\hat V_{\text{SNIS}} = \frac{\sum_iw_iG_i}{\sum_iw_i}\]

SNIS is generally biased but often more stable.

A useful diagnostic is effective sample size:

\[\operatorname{ESS} = \frac{(\sum_iw_i)^2}{\sum_iw_i^2}\]

If 10,000 logged trajectories have ESS 100, the estimate behaves roughly as though only 100 similarly weighted examples were informative.

Tensor shapes:

  • actions, selected log-probabilities, mask: [B, T]

  • returns, log-weights, weights: [B]

  • estimates and ESS: scalar

DPO does not perform this evaluation. It optimizes a policy from fixed preference pairs; off-policy evaluation estimates a policy’s return from logged environment trajectories.

🔍 Deeper: IS estimator and effective sample size

\(\hat V_{\text{IS}}(\pi)=\frac1N\sum_i\rho_iG_i\), with \(\rho_i=\prod_t\frac{\pi(a_t|s_t)}{b(a_t|s_t)}\). Compute it as \(\exp\big(\sum_t(\log\pi-\log b)\big)\) to avoid underflow.

How much data do you really have? \(\text{ESS}=(\sum_iw_i)^2/\sum_iw_i^2\). If the log-ratio is roughly Gaussian with variance \(\sigma^2\) per step, then \(\text{ESS}/N\approx e^{-T\sigma^2}\):

10,000 logged trajectories with ESS \(=30\) means you effectively have 30.

🔑 Key ideas

  • OPE works only where the logging policy explored.

  • Low ESS means don’t trust the number.

🚶 Walkthrough: ESS from four trajectories

Summed log-ratios \((0.1,-0.2,1.5,-1.0)\), so \(w=(1.105,0.819,4.482,0.368)\). ESS \(=6.77^2/22.1\approx2.07\) of 4. One trajectory carries most of the weight.

Common mistakes

  • Multiplying probabilities directly (underflow over long trajectories).

  • Using the current policy’s probability as the logging propensity.

  • Trusting the estimate without checking the max weight.

⚙️ Algorithm: Trajectory-level off-policy evaluation with an ESS check
Input: logged trajectories with returns \(G_i\) and propensities \(b(a_t|s_t)\), target \(\pi\), ESS threshold
for each trajectory \(i\) do
if \(b(a_t|s_t)=0\) where \(\pi(a_t|s_t)>0\) for some \(t\) then flag as unsupported
end
\(w_i\gets\exp\Big(\sum_t\big[\log\pi(a_t|s_t)-\log b(a_t|s_t)\big]\Big)\) ▷ sum logs, then exponentiate
end
\(\hat V_{\text{IS}}\gets\frac1N\sum_iw_iG_i\); \(\hat V_{\text{WIS}}\gets\sum_iw_iG_i/\sum_iw_i\)
\(\text{ESS}\gets(\sum_iw_i)^2/\sum_iw_i^2\)
if ESS \(<\) threshold then report “unreliable: logs don’t cover \(\pi\)”
end

3. PyTorch exercise — evaluate a more aggressive target policy

Action 1 is required at every valid step for success. Half the episodes contain one decision and half contain two.

import torch
from torch.distributions import Categorical

torch.manual_seed(7)

batch_size = 4096
max_steps = 2

# Logged policy rarely chooses action 1.
behavior_probs = torch.tensor([0.8, 0.2])

# Candidate policy chooses action 1 much more often.
target_probs = torch.tensor([0.3, 0.7])

behavior = Categorical(probs=behavior_probs)

# Logged actions: [B, T].
actions = behavior.sample((
    batch_size,
    max_steps,
))

# First half terminates after one action.
trajectory_mask = torch.ones(
    batch_size,
    max_steps,
)

trajectory_mask[
    :batch_size // 2,
    1
] = 0.0

# Success requires action 1 at every step that occurred.
returns = (
    (actions == 1)
    | (trajectory_mask == 0)
).all(dim=1).float()

behavior_log_probs = behavior_probs.log()
target_log_probs = target_probs.log()

# Clipping reduces variance but introduces bias.

Hints

  • Index a log-probability vector using the action tensor.

  • Ratio direction is target - behavior.

  • Sum masked log-ratios over time, then exponentiate.

  • SNIS divides the weighted-return sum by the weight sum.

  • ESS uses the square of the weight sum.

  • The target succeeds with probability \(0.7^L\) in a length-\(L\) episode.

Debugging experiments

Reverse the ratio:

log_weights = (
    (
        selected_behavior_log_probs
        - selected_target_log_probs
    )
    * trajectory_mask
).sum(dim=1)

This reweights in the wrong direction and no longer estimates the target policy.

Then omit the mask. The unused second action in one-step episodes changes their weights, even though it never occurred in the environment.

Finally, set:

behavior_probs = torch.tensor([1.0, 0.0])

The log contains no action- 1 trajectories. Adding epsilon might prevent inf, but it cannot invent the missing evidence.

4. Checks for understanding

  1. Why can trajectory importance weights become extreme for long LLM outputs?

  2. Why is SNIS biased?

  3. Does a mean weight near one guarantee a reliable estimate?

  4. What should accompany every off-policy estimate in a report?

Solutions

Selected log-probabilities:

selected_behavior_log_probs = (
    behavior_log_probs[actions]
)

selected_target_log_probs = (
    target_log_probs[actions]
)

Masked log-weights and weights:

log_weights = (
    (
        selected_target_log_probs
        - selected_behavior_log_probs
    )
    * trajectory_mask
).sum(dim=1)

weights = log_weights.exp()

Value estimates:

ordinary_is = (
    weights * returns
).mean()

self_normalized_is = (
    weights * returns
).sum() / (
    weights.sum() + 1e-8
)

Effective sample size:

effective_sample_size = (
    weights.sum().square()
    / (
        weights.square().sum()
        + 1e-8
    )
)

The behavior policy succeeds with probability:

\[\frac12(0.2)+\frac12(0.2^2)=0.12\]

The target policy’s exact value is:

\[\frac12(0.7)+\frac12(0.7^2)=0.595\]

Two-step trajectories containing [1, 1] receive the largest weight:

\[\left(\frac{0.7}{0.2}\right)^2 = 12.25\]

They are rare under the behavior policy but common under the target policy. Clipping their weight at 4 reduces their contribution, so the clipped estimate is biased downward in this example.

Check answers

  1. Each token ratio enters a product. Small per-token differences can therefore produce exponentially large or small trajectory weights.

  2. Its random weight sum appears in the denominator, changing the expectation of the estimator.

  3. No. A few enormous weights can balance many tiny weights while ESS remains dangerously low.

  4. Report ESS, maximum or percentile weights, support violations, clipping rules, uncertainty intervals and results across seeds.

Retrieval answers

  1. They did not occur in the environment; including them creates fictitious probability ratios and rewards.

  2. Weight mass is concentrated on a small number of trajectories, so variance and sensitivity to individual samples are high.

Takeaway: logged trajectories can estimate a new agent only where the logging policy explored. Compute ratios in log space, mask nonexistent actions, and treat low ESS or missing support as evidence that deployment-free evaluation is unreliable.
