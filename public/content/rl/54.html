2. KL can stop stale-rollout optimization

PPO may run several optimizer epochs over one rollout batch. As the current policy moves away from the rollout policy, the data becomes increasingly stale.

For actions sampled from the old policy:

\[A\sim\pi_{\text{old}}\]

define:

\[\ell(A) = \log\pi_\theta(A) - \log\pi_{\text{old}}(A)\]

and:

\[r(A)=e^{\ell(A)} = \frac{\pi_\theta(A)} {\pi_{\text{old}}(A)}\]

The signed estimator:

\[k_1=-\ell\]

has expectation:

\[\mathbb E_{\pi_{\text{old}}}[k_1] = D_{\mathrm{KL}} (\pi_{\text{old}}\Vert\pi_\theta)\]

Individual samples—and even small minibatch means—can be negative.

A nonnegative estimator is:

\[k_3=r-1-\log r = e^\ell-1-\ell\]

Since \(x-1-\log x\ge0\), every contribution is nonnegative. Also:

\[\mathbb E_{\pi_{\text{old}}}[r]=1\]

so \(k_3\) has the same expected value as the reverse KL.

A practical PPO rule is:

\[\text{stop further epochs if } \widehat D_{\mathrm{KL}}> cD_{\text{target}}\]

where \(c\) might be 1.5 or 2. This is a heuristic safety brake, not a guarantee of policy quality.

Tensor shapes for LLM PPO:

  • stored old and current selected log-probabilities: [B, T]

  • log-ratios, ratios and KL contributions: [B, T]

  • response mask: [B, T]

  • masked KL estimate: scalar

DPO uses policy-versus-reference ratios on fixed preference pairs. It does not compare against the rollout policy or stop online epochs using rollout KL.

🔍 Deeper: which KL, measured how

The update KL is \(\mathrm{KL}(\pi_{\text{old}}\|\pi_\theta)=\mathbb E_{a\sim\pi_{\text{old}}}\big[\log\pi_{\text{old}}-\log\pi_\theta\big]\). The samples come from \(\pi_{\text{old}}\), because that’s who generated the rollout. With \(\rho=\pi_\theta/\pi_{\text{old}}\) per token: \(k_1=-\log\rho\) (unbiased, can be negative) and \(k_3=(\rho-1)-\log\rho\ge0\) (unbiased, lower variance). Stop rule: after each minibatch (or epoch), if \(\overline{\mathrm{KL}}>1.5\times\text{target}\), stop using this batch. Don’t confuse this with the reference KL (\(\pi_\theta\) vs \(\pi_{\text{ref}}\)), which regularizes behaviour and has a separate target (Topic 157).

🔑 Key ideas

  • The update KL uses the frozen rollout policy as its denominator.

  • Aggregate over valid tokens and stop before stale epochs do harm.

🚶 Walkthrough: three tokens

\(\rho=(1.1,0.9,1.3)\). \(k_1=-\log\rho=(-0.095,0.105,-0.262)\), mean \(-0.084\): a “negative KL,” which is just noise. \(k_3=(0.0047,0.0054,0.0376)\), mean \(0.016\). With target 0.01 and a 1.5\(\times\) threshold (0.015): stop.

Common mistakes

  • Recomputing \(\log\pi_{\text{old}}\) each epoch, so KL is always 0.

  • Averaging over padding tokens.

  • Using the reference model as the denominator.

⚙️ Algorithm: PPO epochs with KL early stopping
Input: rollout batch with frozen \(\log\pi_{\text{old}}\), masks \(m\), KL target \(\kappa\), max epochs \(K\)
for epoch \(=1,\dots,K\) do
for each minibatch do
PPO-clip gradient step (Topic 30)
\(\rho_t\gets\exp(\log\pi_\theta-\log\pi_{\text{old}})\); \(\widehat{\mathrm{KL}}\gets\sum_tm_t\big[(\rho_t-1)-\log\rho_t\big]/\sum_tm_t\)
if \(\widehat{\mathrm{KL}}>1.5\kappa\) then return ▷ this batch is stale: collect new rollouts
end
end
end

Debugging experiments

Sample actions from the current policy while retaining the same formula. The sampling distribution no longer matches the intended \(D_{\mathrm{KL}}(\pi_{\text{old}}\Vert\pi_\theta)\).

Next, reverse the log-ratio:

log_ratios = (
    selected_old_log_probs
    - selected_current_log_probs
)

The associated importance ratio and \(k_3\) convention must also change. A nonnegative number is not automatically the desired KL.

Finally, perform early stopping from one tiny minibatch. Sampling noise may stop an epoch prematurely; use the masked rollout-wide estimate or a stable aggregation.

Solutions

Policy quantities:

old_log_probs = old_logits.log_softmax(
    dim=-1
)

current_log_probs = (
    current_logits.log_softmax(
        dim=-1
    )
)

old_probs = old_log_probs.exp()

Exact reverse KL:

exact_reverse_kl = (
    old_probs
    * (
        old_log_probs
        - current_log_probs
    )
).sum()

Selected log-probabilities:

selected_old_log_probs = (
    old_log_probs[actions]
)

selected_current_log_probs = (
    current_log_probs[actions]
)

Sampled estimators:

log_ratios = (
    selected_current_log_probs
    - selected_old_log_probs
)

ratios = log_ratios.exp()

signed_k1 = -log_ratios

nonnegative_k3 = (
    ratios
    - 1.0
    - log_ratios
)

Early stopping:

stop_threshold = (
    target_kl * early_stop_multiplier
)

should_stop = bool(
    nonnegative_estimate
    > stop_threshold
)

The signed contribution is:

\[-\log \frac{\pi_\theta(A)} {\pi_{\text{old}}(A)}\]

It is negative whenever the sampled action became more probable under the current policy. Only its old-policy expectation is guaranteed to equal a nonnegative KL.

For \(k_3\):

\[r-1-\log r\ge0\]

for every positive ratio \(r\).

The sampled mean ratio should approach:

\[\mathbb E_{\pi_{\text{old}}}[r] = \sum_a \pi_{\text{old}}(a) \frac{\pi_\theta(a)} {\pi_{\text{old}}(a)} = 1\]

Large deviations from one can indicate small samples, support problems or incorrect ratio computation.

Check answers

  1. KL is an expectation; individual sampled log-ratios may have either sign.

  2. The denominator must remain the fixed policy that generated the rollout. Allowing it to move invalidates the ratio.

  3. Verify masks, ratio direction, whether clip fraction and KL use the same tokens, and whether sequence drift is accumulating from many individually modest token changes.

  4. No. KL measures policy movement, not reward validity, factuality, safety or downstream usefulness.

Retrieval answers

  1. Local whitening assigns credits according to arbitrary microbatch composition and can erase or reverse rollout-wide differences.

  2. Token ratios multiply across a response, so many small token-level changes can produce a large sequence-probability change.

Takeaway: PPO KL diagnostics are defined by both ratio direction and sampling policy. Use the frozen rollout policy as the denominator, aggregate over valid rollout tokens and stop stale-batch optimization before clipping statistics become misleading.
