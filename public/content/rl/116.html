2. KL is an expectation, not a per-token guarantee

For current policy \(p\) and reference policy \(q\):

\[D_{\mathrm{KL}}(p\|q) = E_{a\sim p} \left[ \log p(a)-\log q(a) \right]\]

Define the sampled log-ratio:

\[x(a)=\log p(a)-\log q(a)\]

The expectation is nonnegative, but an individual \(x(a)\) may be negative whenever the reference assigns that token more probability than the current policy.

A common Monte Carlo estimator is:

\[k_1=x\]

It is unbiased under samples from \(p\), but noisy and signed.

A second unbiased estimator is:

\[k_3 = e^{-x}-1+x\]

Because \(e^{-x}=q(a)/p(a)\):

\[E_p[e^{-x}-1]=0\]

so:

\[E_p[k_3]=D_{\mathrm{KL}}(p\|q)\]

Also:

\[e^{-x}-1+x\ge0\]

for every sample. Compute it stably as:

torch.expm1(-log_ratio) + log_ratio

Tensor shapes:

  • vocabulary logits and log-probabilities: [V]

  • sampled token IDs and KL estimates: [N]

  • LLM token log-ratios and response masks: [B, T]

In RLHF, a sampled KL penalty is often incorporated into reward and detached before calculating returns or advantages. Accidentally backpropagating through that reward creates an additional direct gradient path.

DPO uses reference-policy log-ratios inside a fixed preference loss. Its \(\beta\) controls preference-margin strength relative to the reference, but DPO does not run an online sampled-KL controller.

Hints

  • Use F.log_softmax.

  • Exact forward KL is:

\[\sum_a p(a)[\log p(a)-\log q(a)]\]

  • Sample with torch.multinomial(..., replacement=True).

  • Gather sampled values using tensor indexing.

  • Use population variance with correction=0.

  • Standard error is std / sqrt(N).

  • Sampling from \(q\) and averaging \(\log p-\log q\) estimates:

\[-D_{\mathrm{KL}}(q\|p)\]

Debugging experiments

  • Clamp every negative token log-ratio to zero.

  • Reverse current and reference log-probabilities.

  • Sample from the rollout policy but describe the mean as exact current-policy KL after many PPO epochs.

  • Include prompt or padding tokens in the KL average.

  • Sum token KL while comparing responses with very different lengths.

  • Allow gradients into the frozen reference model.

  • Use exp(x) - 1 - x with the wrong ratio orientation.

  • Update adaptive KL coefficients from one noisy minibatch rather than an aggregated statistic.

4. Checks for understanding

  1. Why can a valid token-level KL contribution be negative?

  2. Under which sampling distribution is \(k_1=\log p-\log q\) unbiased for forward KL?

  3. Why is clamp_min(0) not a valid variance-reduction method?

  4. What happens if \(q(a)=0\) for an action with \(p(a)>0\)?

Solutions

Probabilities and exact KL:

current_log_probabilities = (
    F.log_softmax(
        current_logits,
        dim=0,
    )
)

reference_log_probabilities = (
    F.log_softmax(
        reference_logits,
        dim=0,
    )
)

current_probabilities = (
    current_log_probabilities.exp()
)

reference_probabilities = (
    reference_log_probabilities.exp()
)

exact_forward_kl = (
    current_probabilities
    * (
        current_log_probabilities
        - reference_log_probabilities
    )
).sum()

exact_reverse_kl = (
    reference_probabilities
    * (
        reference_log_probabilities
        - current_log_probabilities
    )
).sum()

Current-policy sampling:

current_samples = torch.multinomial(
    current_probabilities,
    num_samples=num_samples,
    replacement=True,
)

sampled_current_log_probabilities = (
    current_log_probabilities[
        current_samples
    ]
)

sampled_reference_log_probabilities = (
    reference_log_probabilities[
        current_samples
    ]
)

log_ratios = (
    sampled_current_log_probabilities
    - sampled_reference_log_probabilities
)

Estimators:

k1_estimates = log_ratios

k3_estimates = (
    torch.expm1(-log_ratios)
    + log_ratios
)

k1_mean = k1_estimates.mean()
k3_mean = k3_estimates.mean()

k1_variance = k1_estimates.var(
    correction=0
)

k3_variance = k3_estimates.var(
    correction=0
)

k1_standard_error = (
    k1_variance.sqrt()
    / math.sqrt(num_samples)
)

k3_standard_error = (
    k3_variance.sqrt()
    / math.sqrt(num_samples)
)

negative_k1_fraction = (
    (k1_estimates < 0.0)
    .to(torch.float64)
    .mean()
)

negative_k3_fraction = (
    (k3_estimates < 0.0)
    .to(torch.float64)
    .mean()
)

Biased clamping:

clamped_k1_estimates = (
    k1_estimates.clamp_min(0.0)
)

clamped_k1_mean = (
    clamped_k1_estimates.mean()
)

Wrong sampling distribution:

reference_samples = torch.multinomial(
    reference_probabilities,
    num_samples=num_samples,
    replacement=True,
)

reference_sampled_log_ratios = (
    current_log_probabilities[
        reference_samples
    ]
    - reference_log_probabilities[
        reference_samples
    ]
)

wrong_reference_sample_mean = (
    reference_sampled_log_ratios.mean()
)

The token log-ratios are approximately:

Token \(p\) \(q\) \(\log(p/q)\)
Token \(p\) \(q\) \(\log(p/q)\)
0 0.60 0.40 \(0.405\)
1 0.25 0.30 \(-0.182\)
2 0.10 0.20 \(-0.693\)
3 0.05 0.10 \(-0.693\)

Therefore, the probability of a negative \(k_1\) sample is:

\[0.25+0.10+0.05=0.40\]

Yet the forward KL is positive:

\[D_{\mathrm{KL}}(p\|q) \approx0.0937\]

Both k1 and k3 converge to this value. Here, k3 has much lower variance and no negative samples.

Clamping instead converges near:

\[0.60\log(1.5)\approx0.2433\]

which substantially overestimates KL because it discards legitimate negative contributions.

Sampling from the reference gives:

\[E_q[\log p-\log q] = -D_{\mathrm{KL}}(q\|p) \approx-0.1004\]

Check answers

  1. KL nonnegativity applies after expectation. Tokens favored more by the reference have negative sampled log-ratios.

  2. Samples must come from \(p\), the first argument of \(D_{\mathrm{KL}}(p\|q)\).

  3. Negative terms are required for the expectation to equal KL; deleting them introduces upward bias.

  4. The forward KL is infinite. This is a support failure, not a numerical value that should be silently clipped.

Retrieval answers

  1. The inclusive unnormalized estimator is multiplied by \(1-1/K\).

  2. Completion \(i\)’s leave-one-out baseline depends only on other independently sampled completions, making it independent of \(a_i\) conditional on the prompt.

Takeaway: do not debug KL by forcing every token contribution positive. Verify ratio orientation, sampling distribution and masks; use a principled estimator such as \(k_3\) when nonnegative lower-variance samples are useful.
