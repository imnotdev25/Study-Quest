🧩 Analogy: rating a restaurant after the whole meal

You don’t rate a restaurant after the first bite. You finish the meal, then think back: “the starter was fine, but overall it was great.” Monte Carlo waits until the episode ends, looks at what actually happened, and assigns that total to every state you passed through. No model of the kitchen is needed, but you have to finish the meal before you learn anything.

MC waits for the end, then sends the actual return back to every visited state.

2. Learning without an environment model

Dynamic programming assumed that we knew:

\[P(s'\mid s,a) \quad\text{and}\quad R(s,a,s')\]

Usually, we do not.

Monte Carlo learning replaces the environment model with sampled episodes:

  1. Follow policy \(\pi\) until the episode finishes.

  2. Compute the return observed from each visited state.

  3. Average those returns.

The update target for state \(S_t\) is the actual sampled return:

\[G_t = R_{t+1}+\gamma R_{t+2}+\gamma^2R_{t+3}+\cdots\]

A simple incremental update is:

\[V(S_t) \leftarrow V(S_t) + \alpha\left[G_t-V(S_t)\right]\]

The bracketed term is the Monte Carlo error:

\[G_t-V(S_t)\]

It says how far the observed outcome was from the prediction.

This looks like the bandit update:

\[\text{estimate} \leftarrow \text{estimate} + \text{step size}\times\text{error}\]

The difference is that a bandit usually learns from one immediate reward, while Monte Carlo RL learns from a complete multi-step return.

No bootstrapping

Monte Carlo uses:

\[\text{target}=G_t\]

It does not use the current estimate \(V(S_{t+1})\). Therefore, it is model-free and non-bootstrapping.

Monte Carlo targets can have high variance. Two visits to the same state can lead to very different returns due to later action choices and environment randomness.

First-visit versus every-visit

If a state occurs multiple times in one episode:

  • First-visit MC: use only its first occurrence.

  • Every-visit MC: use every occurrence.

Both are valid tabular estimators under standard episodic assumptions, but they produce different finite-sample estimates.

Today’s exercise uses every-visit MC.

LLM connection

Generate several completions from one prompt and score each completed response. Every prefix can be paired with the eventual sequence reward.

That is Monte Carlo-style supervision:

\[V(\text{prefix}_t)\approx G_t\]

The difficulty is credit assignment: a final score tells us whether the complete answer was good, but not precisely which token caused success or failure.

🔍 Deeper: unbiased but noisy

  • Unbiased: \(V^\pi(s)=\mathbb E_\pi[G_t\mid s_t=s]\), so each observed \(G_t\) is an unbiased sample of the target.

  • Variance: with \(N\) independent returns, \(\operatorname{Var}[\hat V]=\sigma_G^2/N\). Long, random episodes mean a large \(\sigma_G^2\).

  • Incremental form: \(V(s)\leftarrow V(s)+\frac{1}{N(s)}\big(G_t-V(s)\big)\), the same shape as the bandit update, just with \(G_t\) as the target.

  • First-visit vs every-visit: first-visit uses only the first occurrence of \(s\) per episode, which gives i.i.d., unbiased samples. Every-visit uses all occurrences: it’s biased for finite \(N\), but consistent.

🔑 Key ideas

  • MC target = the real return. No model, no bootstrapping.

  • Price: you wait for the episode to end, and the variance grows with episode length.

🚶 Walkthrough: first-visit vs every-visit

Episode \(A\xrightarrow{1}B\xrightarrow{2}A\xrightarrow{3}\)end, \(\gamma=1\). Backward returns: \(G=6,5,3\) at times \(0,1,2\).

  • First-visit: \(V(A)=6\), \(V(B)=5\).

  • Every-visit: \(V(A)=\frac{6+3}{2}=4.5\), \(V(B)=5\).

Common mistakes

  • Computing returns forward, so later rewards are missing.

  • The first-visit check uses the wrong window (it must be “earlier in this episode”).

  • Keeping the running \(G\) across episodes.

⚙️ Algorithm: First-visit Monte Carlo prediction
Input: policy \(\pi\), discount \(\gamma\), number of episodes
\(V(s)\gets0,\ N(s)\gets0\) for every state
for each episode do
generate \(s_0,a_0,r_1,s_1,\dots,s_T\) by following \(\pi\)
\(G\gets0\)
for \(t=T-1\) down to \(0\) do
\(G\gets r_{t+1}+\gamma G\)
if \(s_t\notin\{s_0,\dots,s_{t-1}\}\) then ▷ first visit only
\(N(s_t)\gets N(s_t)+1\)
\(V(s_t)\gets V(s_t)+\frac{1}{N(s_t)}\big(G-V(s_t)\big)\)
end

Solutions

returns = torch.zeros_like(rewards)
running_return = torch.zeros(states.shape[0])

for t in reversed(range(states.shape[1])):
    running_return = rewards[:, t] + gamma * running_return
    running_return = running_return * valid[:, t]
    returns[:, t] = running_return

value_sum = torch.zeros(2)
visit_count = torch.zeros(2)

for episode in range(states.shape[0]):
    for t in range(states.shape[1]):
        if valid[episode, t]:
            state = states[episode, t]
            value_sum[state] += returns[episode, t]
            visit_count[state] += 1

values = value_sum / visit_count

The same state has different sampled returns because the occurrences happen at different times and therefore have different remaining rewards.

A safer general division is:

values = value_sum / visit_count.clamp_min(1)

Check answers

  1. Its target is the complete return, which is unavailable until all later rewards have been observed.

  2. No. That would introduce bootstrapping.

  3. The subsequent actions, transitions, rewards or remaining episode lengths can differ.

  4. Rewards beyond the artificial cutoff are omitted. A value estimate is often needed to bootstrap across truncation.

  5. No. Return targets are fixed sampled data; detach them if they were produced through a differentiable computation graph.

Retrieval answers

  1. Immediate expected reward plus discounted next-state value.

  2. The transition space is enormous, and we do not possess a tractable table of transition probabilities and rewards for every prefix and token.

Takeaway: Monte Carlo prediction learns by asking, “What actually happened after this state?” It avoids a model and bootstrapping, but pays with delayed updates and noisy targets.
