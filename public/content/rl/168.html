🧩 Analogy: a practice notebook of only your correct answers

Do 8 practice problems, mark them, and copy only the ones you got right into a clean notebook. Study that notebook, then try 8 new problems. You get better at the problems you can sometimes solve. But a problem you never get right never makes it into the notebook, so you never learn it. That’s rejection-sampling fine-tuning, and it’s also its main limitation.

2. The idea

Names you’ll see: STaR (Zelikman et al., 2022), ReST (Gulcehre et al., 2023), RFT, “rejection sampling,” and “expert iteration.” All follow one loop: sample several answers, keep the ones a checker accepts, fine-tune on them, repeat.

It’s secretly policy gradient. Supervised fine-tuning on kept samples maximizes \(\sum_{\text{kept}}\log\pi_\theta(y|x)\). Since the samples came from \(\pi_\theta\) and were kept when \(R=1\), this is \[\mathbb E_{y\sim\pi_\theta}\big[R(x,y)\,\nabla\log\pi_\theta(y|x)\big],\] which is REINFORCE with a 0/1 reward and no baseline. Wrong answers are simply thrown away instead of being pushed down.

🔍 Deeper: strengths and limits

  • Stable and simple: it’s just SFT, with no ratios, clipping or critic. It’s a strong baseline that’s always worth running first.

  • Learns only from successes: with no negative signal, it can’t explicitly suppress a common wrong pattern. GRPO-style methods use failures too.

  • Stuck prompts: if \(p(\text{solve})\approx0\), no sample is kept, so there’s no learning. Solutions: more samples per prompt, hints or rationalization (STaR gives the answer and asks for a reason), or a curriculum.

  • Off-policy drift: ReST reuses a fixed batch of samples for several fine-tuning epochs. That’s convenient, but the data grows stale.

🔑 Key ideas

  • Filter to correct samples, then SFT. It’s REINFORCE with a binary reward and no baseline.

  • Simple and stable, but blind to failures and stuck on never-solved prompts.

🚶 Walkthrough: how many samples do you need?

A prompt with solve rate \(p=0.05\) and \(k\) samples: \(P(\text{at least one kept})=1-0.95^k\). That’s \(0.40\) for \(k=10\) and \(0.92\) for \(k=50\). Hard prompts need many samples before they contribute anything.

Common mistakes

  • Keeping answers a lenient checker accepts but that are wrong (the model learns the loophole).

  • Many fine-tuning epochs on one batch (overfitting stale data).

  • Reporting gains averaged only over prompts that had kept samples.

⚙️ Algorithm: Rejection-sampling fine-tuning (expert iteration)
Input: policy \(\pi_\theta\), prompts with a checker, samples per prompt \(k\), iterations \(N\)
for \(n=1,\dots,N\) do
for each prompt, sample \(y_1,\dots,y_k\sim\pi_\theta(\cdot|x)\)
\(\mathcal D_n\gets\{(x,y_j):\text{checker}(x,y_j)=1\}\) ▷ optionally dedupe, cap per prompt
fine-tune \(\pi_\theta\) on \(\mathcal D_n\) with cross-entropy for a few epochs
end

Solutions

import torch
import torch.nn.functional as F

torch.manual_seed(0)

# 4 prompts, 5 candidate answers each. correct[p] is the right answer for prompt p.
correct = torch.tensor([2, 0, 4, 1])
logits = torch.zeros(4, 5, requires_grad=True)
logits.data[3] = torch.tensor([3.0, -3.0, 0.0, 0.0, 0.0])  # prompt 3 almost never right
opt = torch.optim.Adam([logits], lr=0.1)


def solve_rate():
    with torch.no_grad():
        return logits.softmax(-1).gather(1, correct[:, None]).squeeze(1)


print("start solve rate", [round(x, 3) for x in solve_rate().tolist()])
for it in range(4):
    with torch.no_grad():
        samples = torch.multinomial(logits.softmax(-1), 8, replacement=True)  # [prompts, 8]
    keep = samples == correct[:, None]                                      # filter: correct only
    prompt_ids = torch.arange(4)[:, None].expand_as(samples)[keep]
    answers = samples[keep]
    if keep.any():
        for _ in range(20):                                                 # SFT on kept samples
            loss = F.cross_entropy(logits[prompt_ids], answers)
            opt.zero_grad()
            loss.backward()
            opt.step()
    print(f"iter {it}: kept per prompt {keep.sum(1).tolist()}  solve rate {[round(x, 3) for x in solve_rate().tolist()]}")

Check answers

  1. SFT maximizes \(\sum\log\pi\) over samples drawn from \(\pi\) with \(R=1\), which is a sample estimate of \(\mathbb E_\pi[R\nabla\log\pi]\).

  2. Its solve rate is 0.002: in 8 samples, nothing is ever kept, so it never gets a gradient.

  3. More samples per prompt, a hint or rationalization (STaR), or switching to a method that also learns from failures.

Retrieval answers: (1) \(R\,\nabla\log\pi(y|x)\). (2) All rewards are equal, so every group-relative advantage is 0.

Takeaway: rejection sampling is the simplest working RL-for-reasoning recipe: sample, filter, imitate. Run it as a baseline before anything fancier, and track which prompts it never touches.
