2. The denominator defines the question

Suppose user \(u\) contributes \(n_u\) episodes, with mean policy effect \(\bar D_u\).

The episode-average effect is:

\[\hat\tau_{\text{episode}} = \frac{ \sum_u n_u\bar D_u }{ \sum_u n_u }\]

It answers:

For a randomly selected episode, what is the candidate’s effect?

The user-average effect is:

\[\hat\tau_{\text{user}} = \frac1U\sum_u\bar D_u\]

It answers:

For a randomly selected user, what is the candidate’s average effect?

When every user contributes equally, these agree. Otherwise, the episode estimand gives prolific users more influence.

The user-average can also be written using episode weights:

\[\hat\tau_{\text{user}} = \sum_{u,t} \frac{1}{U n_u}D_{u,t}\]

Neither estimand is automatically correct. Choose based on the deployment decision:

  • infrastructure load or request quality: episode average may fit;

  • user experience or user-level fairness: user average may fit.

Tensor shapes:

  • user effects and episode counts: [U]

  • padded outcomes and validity masks: [U, T_max]

  • per-episode weights: [U, T_max]

If a policy changes conversation length, tool calls or retry counts, those denominators are policy-induced. A per-turn improvement can coexist with worse per-user task completion.

DPO typically averages over preference pairs. If a few prompt families contribute most pairs, that objective and its raw accuracy are pair-weighted—not automatically user- or deployment-weighted. It remains fixed-data preference optimization.

Hints

  • Heavy users are the first 20 indices.

  • Construct the mask with:

episode_positions < episode_counts[:, None]

  • Use torch.where(mask, values, 0) before summing; NaN * 0 remains NaN.

  • Divide every user sum by that user’s valid count.

  • A valid episode from user \(u\) gets user-balanced weight:

\[\frac{1}{U n_u}\]

Debugging experiments

  • Average zero-padded tensors without a mask.

  • Report a row mean as “average user experience.”

  • Delete low-activity users because their individual estimates are noisy.

  • Weight users by conversation length when the policy itself changes length.

  • Count retries or tool steps as independent users.

  • Apply reward scaling but forget to rescale thresholds and uncertainty.

  • Join episode counts to the wrong user IDs.

Solutions

Users and effects:

heavy_users = (
    torch.arange(num_users)
    < num_heavy_users
)

episode_counts = torch.where(
    heavy_users,
    torch.tensor(heavy_episode_count),
    torch.tensor(light_episode_count),
)

true_user_effects = torch.where(
    heavy_users,
    torch.tensor(heavy_user_effect),
    torch.tensor(light_user_effect),
)

Padded episodes:

episode_positions = torch.arange(
    maximum_episodes
)[None, :]

valid_mask = (
    episode_positions
    < episode_counts[:, None]
)

unmasked_differences = (
    true_user_effects[:, None]
    + episode_noise_sd
    * torch.randn(
        num_users,
        maximum_episodes,
    )
)

padded_differences = torch.where(
    valid_mask,
    unmasked_differences,
    torch.tensor(float("nan")),
)

safe_differences = torch.where(
    valid_mask,
    padded_differences,
    torch.zeros_like(
        padded_differences
    ),
)

User summaries:

observed_counts = (
    valid_mask.sum(dim=1)
    .to(torch.float64)
)

user_sums = safe_differences.sum(
    dim=1
)

estimated_user_effects = (
    user_sums / observed_counts
)

Two estimands:

estimated_episode_average = (
    safe_differences.sum()
    / observed_counts.sum()
)

estimated_user_average = (
    estimated_user_effects.mean()
)

oracle_episode_average = (
    true_user_effects
    * episode_counts
).sum() / episode_counts.sum()

oracle_user_average = (
    true_user_effects.mean()
)

User-balanced episode weights:

user_balanced_weights = torch.where(
    valid_mask,
    (
        1.0
        / observed_counts[:, None]
        / num_users
    ),
    torch.zeros_like(
        safe_differences
    ),
)

weighted_user_average = (
    safe_differences
    * user_balanced_weights
).sum()

weight_sum = (
    user_balanced_weights.sum()
)

incorrect_padded_zero_average = (
    safe_differences.mean()
)

heavy_user_fraction = (
    heavy_users
    .to(torch.float64)
    .mean()
)

heavy_episode_fraction = (
    episode_counts[heavy_users].sum()
    / episode_counts.sum()
)

The user-average effect is:

\[\tau_{\text{user}} = 0.2(-0.20)+0.8(0.20) = 0.12\]

Most users improve.

But heavy users generate:

\[20(100)=2000\]

of the total:

\[2000+80(5)=2400\]

episodes. Therefore:

\[\tau_{\text{episode}} = \frac{ 2000(-0.20)+400(0.20) }{ 2400 } \approx-0.133\]

The candidate helps the average user but hurts the average episode because the regressing heavy users generate approximately:

\[\frac{2000}{2400} \approx83.3\%\]

of all traffic.

The zero-padded mean divides by \(100\times100\) slots rather than 2,400 valid episodes or 100 users. It estimates neither intended quantity.

Check answers

  1. Usage frequency correlates with policy effect, so episode weighting changes the population mixture.

  2. The episode-average effect, provided the sampled episode distribution matches deployment traffic.

  3. The user-average effect, or equivalently episode weights \(1/(Un_u)\).

  4. Define explicit target user weights—such as deployment share, contractual importance or fairness weights—before inspecting outcomes.

Retrieval answers

  1. Episodes from one user share persistent user-level effects; repeated episodes do not average away that shared component.

  2. Resample complete independent clusters, such as users or source tasks.

Takeaway: before computing a mean, name the random unit it represents. “Average reward” is incomplete unless you specify whether users, conversations, episodes, turns or tokens receive equal weight.
