🧩 Analogy: a campus poll vs the country

A poll of university students says one thing, but the country isn’t made of students. Pollsters reweight by age and region to estimate the national result. A canary’s traffic mix (more easy prompts, more power users) may differ from full deployment, so reweight the effect to the target mix.

2. A canary estimates value for the traffic it receives

Suppose policy effects differ across prompt groups:

\[\tau_g = E[Y(1)-Y(0)\mid G=g]\]

The canary’s average effect is:

\[\tau_{\text{canary}} = \sum_g p_{\text{canary}}(g)\tau_g\]

Deployment may have another mixture:

\[\tau_{\text{target}} = \sum_g p_{\text{target}}(g)\tau_g\]

Thus, even a perfectly randomized experiment may answer the wrong population question. Randomization identifies effects within the sampled population; it does not make that population representative.

Two equivalent estimators are useful.

Direct standardization:

\[\hat\tau_{\text{target}} = \sum_g p_{\text{target}}(g)\hat\tau_g\]

Population importance weighting:

\[w(g) = \frac{p_{\text{target}}(g)} {p_{\text{canary}}(g)}\]

Large weights mean the canary underrepresented a group important in deployment. Weight concentration reduces effective sample size:

\[N_{\text{eff}} = \frac{(\sum_i w_i)^2} {\sum_i w_i^2}\]

Transportability still requires support:

\[p_{\text{target}}(g)>0 \Rightarrow p_{\text{canary}}(g)>0\]

It also assumes the measured groups capture the important effect modifiers. Reweighting language and domain cannot fix an unmeasured difference such as unseen user expertise.

Tensor shapes:

  • group and reward: [N]

  • one-hot membership: [N, G]

  • group-specific effects: [G]

  • transport weights: [N]

These are population weights, not policy-action importance ratios. If assignment was also context-dependent, combine transport weights with the logged assignment propensities.

A DPO checkpoint can perform well on the preference-data mixture yet regress on deployment traffic. DPO optimizes that fixed dataset’s preference objective; it does not automatically transport outcomes to another user or prompt distribution.

🔍 Deeper: transport by reweighting

With pre-treatment groups \(g\), canary shares \(p_g\) and target shares \(q_g\): \(\tau_{\text{target}}=\sum_gq_g\tau_g=\sum_gp_g\frac{q_g}{p_g}\tau_g\). Costs: the weights \(q_g/p_g\) shrink the ESS, and groups with \(p_g\approx0\) can’t be transported at all (positivity). Report the transported estimate, its CI and the ESS it consumed. Use only pre-treatment features for \(g\).

🔑 Key ideas

  • A canary estimates the effect for its own traffic.

  • Transport only across supported, pre-treatment groups, and report the ESS cost.

🚶 Walkthrough: a positive canary turns negative

Easy prompts: \(\tau=+0.05\). Hard prompts: \(\tau=-0.08\). Canary mix 80/20: \(0.04-0.016=+0.024\). Deployment mix 30/70: \(0.015-0.056=-0.041\).

Common mistakes

  • Reweighting on post-treatment features.

  • Extrapolating to groups absent from the canary.

  • Reporting the transported point estimate without its (wider) CI.

3. PyTorch exercise — a positive canary becomes negative after transport

The canary mostly contains group 0. Deployment mostly contains group 2, where the candidate performs worse.

Hints

  • An arm value is its masked reward sum divided by its assignment count.

  • Use F.one_hot(groups, num_groups).

  • Group effects are candidate group means minus control group means.

  • Standardization multiplies group effects by the desired group probabilities.

  • Group transport ratio is target / canary.

  • Self-normalize weights separately within each arm.

  • Compute ESS using weights that are zero outside the relevant arm.

Debugging experiments

  • Report only the randomized canary average despite a different deployment mix.

  • Weight by canary / target instead of target / canary.

  • Use response-derived properties as if they were pre-treatment groups.

  • Estimate target frequencies from a stale deployment period.

  • Silently drop a target group absent from the canary.

  • Combine transport weights with adaptive routing but omit assignment propensities.

  • Bootstrap episodes instead of complete users.

  • Oversample a rare group and forget to restore target proportions.

Solutions

Raw canary effect:

raw_candidate_value = (
    assignment * rewards
).sum() / assignment.sum()

raw_control_value = (
    control_assignment * rewards
).sum() / control_assignment.sum()

raw_canary_effect = (
    raw_candidate_value
    - raw_control_value
)

Group-specific effects:

group_one_hot = F.one_hot(
    groups,
    num_classes=num_groups,
).to(torch.float64)

candidate_membership = (
    group_one_hot
    * assignment[:, None]
)

control_membership = (
    group_one_hot
    * control_assignment[:, None]
)

candidate_group_counts = (
    candidate_membership.sum(dim=0)
)

control_group_counts = (
    control_membership.sum(dim=0)
)

candidate_group_values = (
    (
        candidate_membership
        * rewards[:, None]
    ).sum(dim=0)
    / candidate_group_counts
)

control_group_values = (
    (
        control_membership
        * rewards[:, None]
    ).sum(dim=0)
    / control_group_counts
)

estimated_group_effects = (
    candidate_group_values
    - control_group_values
)

Direct standardization:

standardized_canary_effect = (
    canary_group_probabilities
    * estimated_group_effects
).sum()

standardized_target_effect = (
    target_group_probabilities
    * estimated_group_effects
).sum()

Population weighting:

group_transport_ratios = (
    target_group_probabilities
    / canary_group_probabilities
)

episode_transport_weights = (
    group_transport_ratios[groups]
)

weighted_candidate_value = (
    episode_transport_weights
    * assignment
    * rewards
).sum() / (
    episode_transport_weights
    * assignment
).sum()

weighted_control_value = (
    episode_transport_weights
    * control_assignment
    * rewards
).sum() / (
    episode_transport_weights
    * control_assignment
).sum()

weighted_target_effect = (
    weighted_candidate_value
    - weighted_control_value
)

ESS and exact values:

candidate_weights = (
    episode_transport_weights
    * assignment
)

control_weights = (
    episode_transport_weights
    * control_assignment
)

candidate_transport_ess = (
    candidate_weights.sum().square()
    / candidate_weights.square().sum()
)

control_transport_ess = (
    control_weights.sum().square()
    / control_weights.square().sum()
)

candidate_ess_fraction = (
    candidate_transport_ess
    / assignment.sum()
)

control_ess_fraction = (
    control_transport_ess
    / control_assignment.sum()
)

exact_group_effects = (
    candidate_success_probabilities
    - control_success_probabilities
)

exact_canary_effect = (
    canary_group_probabilities
    * exact_group_effects
).sum()

exact_target_control_value = (
    target_group_probabilities
    * control_success_probabilities
).sum()

exact_target_candidate_value = (
    target_group_probabilities
    * candidate_success_probabilities
).sum()

exact_target_effect = (
    exact_target_candidate_value
    - exact_target_control_value
)

The conditional effects are:

\[\tau_g=[0.08,\;0.06,\;-0.10]\]

Under canary traffic:

\[\tau_{\text{canary}} = 0.7(0.08)+0.2(0.06)+0.1(-0.10) = 0.058\]

The candidate appears strongly beneficial.

Under target traffic:

\[\tau_{\text{target}} = 0.2(0.08)+0.3(0.06)+0.5(-0.10) = -0.016\]

The deployment conclusion reverses.

Target values are:

\[J_0^{\text{target}} = 0.2(0.60)+0.3(0.50)+0.5(0.40) = 0.47\]

\[J_1^{\text{target}} = 0.2(0.68)+0.3(0.56)+0.5(0.30) = 0.454\]

The transport ratios are:

\[w_g= \left[ \frac{0.2}{0.7}, \frac{0.3}{0.2}, \frac{0.5}{0.1} \right] = [0.286,\;1.5,\;5.0]\]

Group 2 receives weight 5 because it represents half of deployment but only one-tenth of the canary. This concentration should reduce each arm’s ESS to roughly one-third of its raw size.

Check answers

  1. Randomization balances candidate and control within the sampled traffic. It does not make sampled traffic equal to the target population.

  2. They are equivalent when the same pre-treatment groups capture effect heterogeneity and the corresponding population probabilities and support are valid.

  3. The target population depends heavily on observations scarce in the canary, so the transported estimate will have greater variance.

  4. The target effect is not identified from that canary. Collect data for the missing group, narrow the target population or state the unsupported extrapolation explicitly.

Retrieval answers

  1. Failure to detect harm may result from wide uncertainty; it does not bound the harm below an acceptable level.

  2. For harm \(d\), noninferiority requires the one-sided upper confidence bound to satisfy \(U_d<\Delta_{\max}\).

Takeaway: a randomized canary estimates the effect for its own traffic. Before deployment, compare its context mixture with the target, transport only across supported pre-treatment groups, and report how much effective sample size the reweighting consumed.
