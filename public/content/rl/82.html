🧩 Analogy: a clinical trial needs more than a positive average

A new drug with a slightly higher average recovery isn’t approved on that alone. Regulators want a confidence interval that clears zero, ideally by a margin. Safe policy improvement asks the same of a candidate policy: deploy only when the lower bound on improvement clears the bar.

Same mean improvement. Pairing on the same episodes shrinks the interval enough to clear 0.

2. Compare policies on the same episodes

Suppose off-policy evaluation estimates:

\[\hat J(\pi_{\text{candidate}})=0.66, \qquad \hat J(\pi_{\text{baseline}})=0.60\]

The estimated improvement is positive:

\[\hat\Delta=0.06\]

But deployment needs a second question: how uncertain is that difference?

Let \(Z_i^c\) and \(Z_i^b\) be candidate and baseline OPE contributions from the same logged episode. These could come from PDIS or a doubly robust estimator. Form paired differences:

\[D_i=Z_i^c-Z_i^b\]

Then:

\[\hat\Delta=\frac1N\sum_i D_i, \qquad \operatorname{SE}(\hat\Delta) = \frac{s_D}{\sqrt N}\]

A one-sided approximate 95% lower confidence bound is:

\[\operatorname{LCB}_{0.95} = \hat\Delta - 1.645\operatorname{SE}(\hat\Delta)\]

Deploy only if:

\[\operatorname{LCB}_{0.95}>\Delta_{\min}\]

Usually \(\Delta_{\min}=0\), although deployment costs may justify a positive minimum improvement.

Pairing matters because both policies face the same easy and difficult episodes:

\[\operatorname{Var}(Z^c-Z^b) = \operatorname{Var}(Z^c) + \operatorname{Var}(Z^b) - 2\operatorname{Cov}(Z^c,Z^b)\]

Positive covariance cancels shared episode difficulty. Pairing does not always reduce variance, but computing differences preserves the actual covariance instead of discarding it.

Tensor shapes:

  • candidate and baseline contributions: [N]

  • paired differences: [N]

  • bootstrap indices: [bootstraps, N]

  • improvement, standard error and LCB: scalar

This bound assumes independent episodes and an approximately normal mean. Extreme importance weights, support failures or biased OPE invalidate the conclusion. If many candidates were screened, use an untouched evaluation set or correct for multiple comparisons.

For safety costs, reverse the direction: require an upper confidence bound on cost to remain below the limit.

DPO can produce a candidate checkpoint from fixed preferences, but its training loss does not certify improved environmental reward. The resulting policy still needs deployment-oriented evaluation.

🔍 Deeper: paired differences

\(\operatorname{Var}[\bar X-\bar Y]=\frac1n\big(\sigma_X^2+\sigma_Y^2-2\operatorname{Cov}(X,Y)\big)\). Evaluating both policies on the same episodes makes the covariance large and positive, because both see the same easy and hard prompts. Gate: deploy iff \(\mathrm{LCB}_{1-\delta}(\bar d)\ge m\), with the margin \(m\) and \(\delta\) fixed before looking at the data.

🔑 Key ideas

  • Compare candidate and baseline on the same episodes.

  • Deploy on the lower confidence bound, not the mean.

🚶 Walkthrough: correlation shrinks the interval

\(\sigma_X=\sigma_Y=1\), \(n=400\), mean difference 0.08. Unpaired: SE \(=\sqrt{2/400}=0.071\), 95% LCB \(=0.08-0.139=-0.059\) (fail). Paired with \(\operatorname{corr}=0.9\): SE \(=\sqrt{0.2/400}=0.022\), LCB \(=0.036\) (pass).

Common mistakes

  • Comparing on different prompt samples.

  • Choosing the margin after seeing the results.

  • Repeatedly checking and stopping when the LCB first clears (Topic 91).

⚙️ Algorithm: Safe policy improvement gate
Input: baseline \(\pi_0\), candidate \(\pi_1\), \(n\) shared evaluation episodes, margin \(m\), level \(\delta\) (both fixed in advance)
for \(i=1,\dots,n\) do
evaluate both policies on episode \(i\) (same prompt and seed); \(d_i\gets G^{(1)}_i-G^{(0)}_i\)
end
\(\mathrm{LCB}\gets\bar d-z_{1-\delta}\operatorname{sd}(d)/\sqrt n\) ▷ or a bootstrap/clustered bound
if \(\mathrm{LCB}\ge m\) then deploy \(\pi_1\) else keep \(\pi_0\)
end

Hints

  • Compute candidate_contributions - baseline_contributions.

  • Use sample standard deviation with correction=1.

  • Divide by math.sqrt(num_episodes).

  • Ignoring pairing adds the two separate variance estimates.

  • Use torch.corrcoef on a stacked [2, N] tensor.

  • Bootstrap the differences, or use identical sampled indices for both policies.

  • The lower bootstrap percentile for a one-sided 95% bound is 0.05.

Debugging experiments

  • Shuffle candidate contributions before subtracting. Shared episode difficulty no longer cancels.

  • Bootstrap baseline and candidate episodes independently. This destroys the paired design.

  • Treat every token as an independent sample. Correlated tokens produce a severely underestimated standard error.

  • Increase policy-specific noise from 0.15 to 1.0. The same mean improvement becomes harder to establish.

  • Select the best of 100 candidates and report its uncorrected LCB on the same data. This introduces selection bias.

  • Replace these light-tailed contributions with extreme importance-weighted terms. Compare normal and bootstrap bounds while monitoring maximum weight and ESS.

Solutions

Policy values and differences:

baseline_value = (
    baseline_contributions.mean()
)

candidate_value = (
    candidate_contributions.mean()
)

paired_differences = (
    candidate_contributions
    - baseline_contributions
)

estimated_improvement = (
    paired_differences.mean()
)

Paired lower bound:

paired_standard_error = (
    paired_differences.std(
        correction=1
    )
    / math.sqrt(num_episodes)
)

paired_lcb = (
    estimated_improvement
    - confidence_z
    * paired_standard_error
)

Pairing-ignored calculation:

pairing_ignored_standard_error = torch.sqrt(
    candidate_contributions.var(
        correction=1
    ) / num_episodes
    +
    baseline_contributions.var(
        correction=1
    ) / num_episodes
)

pairing_ignored_lcb = (
    estimated_improvement
    - confidence_z
    * pairing_ignored_standard_error
)

Correlation:

episode_correlation = torch.corrcoef(
    torch.stack([
        baseline_contributions,
        candidate_contributions,
    ])
)[0, 1]

Paired bootstrap:

bootstrap_indices = torch.randint(
    low=0,
    high=num_episodes,
    size=(
        num_bootstraps,
        num_episodes,
    ),
)

bootstrap_improvements = (
    paired_differences[
        bootstrap_indices
    ].mean(dim=1)
)

bootstrap_lcb = torch.quantile(
    bootstrap_improvements,
    0.05,
)

The expected improvement is approximately:

\[0.66-0.60=0.06\]

Because shared difficulty cancels, the paired standard error is roughly:

\[\sqrt{\frac{0.15^2+0.15^2}{500}} \approx0.0095\]

Therefore:

\[\operatorname{LCB}_{\text{paired}} \approx 0.06-1.645(0.0095) \approx0.044\]

Ignoring pairing retains the large shared variance:

\[\operatorname{SE}_{\text{ignored}} \approx0.064\]

giving an LCB near -0.045. Exact outputs vary with the sampled noise.

Check answers

  1. The paired difference directly includes covariance and answers the deployment question: \(J(c)-J(b)\). Separate intervals do not.

  2. No. The apparent gain may be sampling noise, OPE bias or unsupported extrapolation.

  3. Non-independent episodes, heavy-tailed weights, missing support, biased propensities, model leakage, distribution shift and candidate selection on the evaluation data.

  4. Report improvement, standard error, LCB, episode count, bootstrap result, importance-weight quantiles, ESS, support violations, reward components, costs and safety metrics.

Retrieval answers

  1. Reward \(r_t\) uses the cumulative ratio \(\rho_{0:t}\), containing decisions through time \(t\).

  2. Earlier actions influence the state distribution at time \(t\); the current ratio alone leaves that distribution under the behavior policy.

Takeaway: evaluate candidate and baseline on the same episodes, estimate their paired difference, and deploy only when the lower confidence bound—not merely the mean—clears the required margin.
