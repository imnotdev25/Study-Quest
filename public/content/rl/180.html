🧩 Analogy: comparing moves from the same chess position

Saying “you won the game” doesn’t tell you which move was good. But if you’ve reached the same position several times and played different moves from it, you can compare those moves directly. GiGPO finds repeated states across an agent’s trajectories and compares the actions taken from each one.

2. The idea (Feng et al., 2025, NeurIPS)

GiGPO stays critic-free and adds a second level of grouping.

  • Episode level: like GRPO, \(A^E_i=\frac{R_i-\bar R}{\operatorname{std}(R)}\) over complete trajectories from the same task.

  • Step level, “anchor states”: find environment states that appear in several trajectories, group the actions taken from each such state, and compute a relative advantage within the group from each step’s discounted return \(G_t\).

  • Combine: \(A_{i,t}=A^E_i+\omega\,A^S_{i,t}\).

It needs no extra rollouts or models: the anchor states are found in the trajectories already collected. The paper reports gains over GRPO of more than 12% on ALFWorld and more than 9% on WebShop, at the same rollout and memory cost.

🔑 Key ideas

  • Repeated states give free step-level comparisons.

  • Episode advantage plus weighted step advantage, still without a critic.

🚶 Walkthrough: state s1

Trajectories 0, 1 and 3 all reach \(s_1\) at step 1, with discounted returns \(0.95,0,0.95\). Group mean \(0.633\), std \(0.548\), so step advantages \((+0.58,-1.15,+0.58)\). Trajectory 1’s action at \(s_1\) is singled out as the mistake, which GRPO alone can’t see.

Common mistakes

  • Matching states too loosely (e.g. by observation text that hides different internal states).

  • Groups of size 1 getting non-zero advantages.

  • An \(\omega\) so large that noisy step groups dominate.

Solutions

import torch
from collections import defaultdict

gamma, omega = 0.95, 1.0
# Each trajectory: list of state ids visited, and a final episode reward.
trajs = [(["s0", "s1", "s2"], 1.0),
         (["s0", "s1", "s3"], 0.0),
         (["s0", "s4"], 0.0),
         (["s0", "s1", "s2"], 1.0)]

R = torch.tensor([r for _, r in trajs])
episode_adv = (R - R.mean()) / (R.std() + 1e-6)

# Step-level: discounted return from each step, grouped by anchor state.
steps = []                                        # (traj, t, state, G_t)
for i, (states, r) in enumerate(trajs):
    T = len(states)
    for t, s in enumerate(states):
        steps.append((i, t, s, gamma ** (T - 1 - t) * r))
groups = defaultdict(list)
for idx, (_, _, s, g) in enumerate(steps):
    groups[s].append(idx)
step_adv = torch.zeros(len(steps))
for s, idxs in groups.items():
    g = torch.tensor([steps[k][3] for k in idxs])
    if len(idxs) > 1 and g.std() > 0:
        step_adv[idxs] = (g - g.mean()) / g.std()
for k, (i, t, s, g) in enumerate(steps):
    total = episode_adv[i] + omega * step_adv[k]
    print(f"traj {i} step {t} state {s}: A_E {episode_adv[i]:+.2f}  A_S {step_adv[k]:+.2f}  A {total:+.2f}")

Check answers

  1. Both visits to \(s_2\) have the same return, so there’s no difference to learn from.

  2. Long tasks have many decisions and one final reward. Step groups tell good and bad decisions apart within a single trajectory.

Retrieval answers: (1) It’s computed from the final reward only. (2) The final answer’s reward has to be credited to tool calls made many turns earlier.

Takeaway: in agent environments, states repeat across rollouts. Use those repeats as free, critic-free step-level baselines.
