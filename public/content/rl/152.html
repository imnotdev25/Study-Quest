2. Two critics forecast two different futures

In sequential RL, immediate reward and cost do not describe everything an action causes. Maintain two critics:

\[\underbrace{V_R(s_t)}_{\text{future reward forecast}}, \qquad \underbrace{V_C(s_t)}_{\text{future cost forecast}}\]

Their one-step TD targets are:

\[y_t^R = \underbrace{r_t}_{\text{immediate reward}} + \underbrace{\gamma(1-d_t)V_R(s_{t+1})}_{\text{bootstrapped future reward}}\]

\[y_t^C = \underbrace{c_t}_{\text{immediate cost}} + \underbrace{\gamma(1-d_t)V_C(s_{t+1})}_{\text{bootstrapped future cost}}\]

The TD errors estimate separate advantages:

\[\delta_t^R = \underbrace{y_t^R-V_R(s_t)}_{\text{better or worse reward than expected}}\]

\[\delta_t^C = \underbrace{y_t^C-V_C(s_t)}_{\text{more or less costly than expected}}\]

Combine them only for the actor:

\[A_t^{\text{aug}} = \underbrace{\delta_t^R}_{\text{reward advantage}} - \underbrace{\lambda\delta_t^C}_{\text{priced cost advantage}}\]

For a finite-horizon starting-state objective:

\[L_\pi = -\frac1{BT}\sum_{i,t} \underbrace{\gamma^t}_{\text{time weight}} \underbrace{\log\pi_\theta(a_{i,t}\mid s_t)}_{\text{credit path}} \underbrace{\operatorname{stopgrad}(A_{i,t}^{\text{aug}})}_{\text{actor direction}} -\beta H\]

The critics minimize:

\[L_V = \frac12E\!\left[ \underbrace{(V_R-y_R^{\text{detach}})^2}_{\text{reward-critic error}} + \underbrace{(V_C-y_C^{\text{detach}})^2}_{\text{cost-critic error}} \right]\]

Detaching targets gives the usual TD semi-gradient: update the current prediction toward a fixed target.

The multiplier still uses the discounted episode cost:

\[C_i = \underbrace{\sum_t\gamma^t c_{i,t}}_{\text{same cost definition as the constraint}}\]

\[\lambda \leftarrow \left[ \lambda+\eta_\lambda \underbrace{(\bar C-d)}_{\text{raw violation}} \right]_+\]

Never update \(\lambda\) from cost TD errors: a correct cost critic makes their mean approximately zero, even when the policy violates the budget.

Two masks have different jobs:

  • continuation mask: prevents bootstrapping after termination;

  • valid-token mask: removes padding or nonexistent timesteps from every loss.

For LLM RL, EOS affects continuation, while prompt and padding masks determine which generated tokens contribute to policy and value losses.

Shapes:

  • policy logits and both critics: [T]

  • actions, rewards, costs and TD errors: [B, T]

  • continuation mask and discount weights: [T]

  • multiplier and cost limit: scalar []

DPO has no online reward critic, cost critic or dual update. It can learn from safety preferences, but that is not equivalent to enforcing an environment-cost budget.

Hints

  • TD targets need next_values.detach().

  • Actor advantage: reward_td - lambda * cost_td, then detach it.

  • Weight actor terms by discounts[None, :].

  • Use costs * discounts[None, :] for episode cost.

Debugging checks

  • Remove the terminal mask: torch.roll makes the last state bootstrap from the first.

  • Update the multiplier from cost_td_errors.mean(): violations become invisible.

  • Forget target detachment: gradients modify both sides of each TD target.

  • Mask padding in the actor loss but not the critic loss.

  • Use discounted actor costs but an undiscounted dual budget.

  • Standardize cost advantages without tracking the corresponding change in multiplier scale.

Solutions

Rollout:

distribution = torch.distributions.Bernoulli(
    logits=policy_logits[None, :].expand(
        batch_size,
        horizon,
    )
)

actions = distribution.sample()
action_ids = actions.to(torch.long)

rewards = reward_by_action[action_ids]
costs = cost_by_action[action_ids]

next_reward_values = torch.roll(
    reward_values,
    shifts=-1,
)
next_cost_values = torch.roll(
    cost_values,
    shifts=-1,
)

TD targets:

reward_targets = (
    rewards
    + gamma
    * continuation_mask[None, :]
    * next_reward_values.detach()[None, :]
)

cost_targets = (
    costs
    + gamma
    * continuation_mask[None, :]
    * next_cost_values.detach()[None, :]
)

reward_td_errors = (
    reward_targets
    - reward_values[None, :]
)

cost_td_errors = (
    cost_targets
    - cost_values[None, :]
)

Losses:

augmented_td_errors = (
    reward_td_errors
    - multiplier.detach()
    * cost_td_errors
).detach()

time_weights = discounts[None, :]

actor_loss = -(
    time_weights
    * distribution.log_prob(actions)
    * augmented_td_errors
).mean() - (
    entropy_coefficient
    * (
        time_weights
        * distribution.entropy()
    ).mean()
)

critic_loss = 0.5 * (
    reward_td_errors.square().mean()
    + cost_td_errors.square().mean()
)

Parameter and dual updates:

(actor_loss + critic_loss).backward()

actor_optimizer.step()
critic_optimizer.step()

with torch.no_grad():
    discounted_episode_costs = (
        costs * discounts[None, :]
    ).sum(dim=1)

    multiplier = torch.clamp(
        multiplier
        + dual_lr
        * (
            discounted_episode_costs.mean()
            - cost_limit
        ),
        min=0.0,
    )

Exact value recursion:

for t in reversed(range(horizon)):
    running_value = (
        step_expectations[t]
        + gamma * running_value
    )
    values[t] = running_value

Typical final-window results are:

\[\bar p_{\text{risky}} \approx \underbrace{0.285}_{\text{active constraint}}\]

\[J_R\approx1.85, \qquad J_C\approx1.11, \qquad d\approx1.113, \qquad \lambda\approx1.13\]

Small differences between learned and exact critic values are expected because critics continually track a changing, sampled policy.

Check answers

  1. Separate critics remain interpretable and reusable while \(\lambda\) changes. A single scalarized critic’s target changes whenever the multiplier changes.

  2. TD errors measure prediction surprise, not absolute cost. An accurate critic can predict a consistently excessive cost with zero-mean TD errors.

  3. Continuation masks stop terminal bootstrapping; valid-token masks prevent prompt, padding or nonexistent steps from entering losses.

  4. The multiplier uses raw sampled episode cost, so observed budget violations can still increase it despite critic error.

Retrieval answers

  1. Centering removes the mean cost—the exact quantity needed to detect constraint violation.

  2. Detachment prevents actor gradients from flowing into return construction, critics or the multiplier; critics receive their own regression loss.

Takeaway: let reward and cost critics answer different questions. Combine their TD advantages only when updating the policy, while the multiplier reacts independently to raw episode-level constraint violations.
