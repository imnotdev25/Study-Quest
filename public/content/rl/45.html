🧩 Analogy: one person one vote vs one word one vote

In a meeting, should each person get one vote, or each word spoken? Under “one word one vote,” whoever talks longest wins. Loss reduction asks the same question about responses: average over tokens (long responses dominate) or over sequences (each response counts equally, so each token of a long response counts less).

2. Reduction changes the learning objective

For response \(i\), the autoregressive log-probability is:

\[\log\pi_\theta(y_i\mid x_i) = \sum_{t=1}^{L_i} \log\pi_\theta(y_{i,t}\mid x_i,y_{i,<t})\]

With one sequence-level advantage \(A_i\), REINFORCE uses:

\[L_{\mathrm{sequence}} = -\frac1B\sum_i A_i \sum_t M_{i,t} \log\pi_\theta(y_{i,t}\mid s_{i,t})\]

The sum is not accidental. The probability of the complete response is the product of token probabilities, so its log-probability is their sum.

Two common alternative reductions are:

Global token mean

\[L_{\mathrm{token}} = - \frac{ \sum_{i,t} M_{i,t}A_i\log\pi_\theta(y_{i,t}\mid s_{i,t}) }{ \sum_{i,t}M_{i,t} }\]

Long responses contain more valid tokens, so they receive more total influence.

Mean within each response

\[L_{\mathrm{response\ mean}} = -\frac1B\sum_i A_i \frac{ \sum_tM_{i,t}\log\pi_\theta(y_{i,t}\mid s_{i,t}) }{ \sum_tM_{i,t} }\]

This gives each response equal aggregate weight, but it is no longer the ordinary sequence-probability policy gradient. Length normalization changes the objective rather than merely improving numerical stability.

The distinction becomes especially important because EOS is an action: response length is partly chosen by the policy.

Tensor shapes:

  • token IDs, selected log-probabilities and mask: [B, T]

  • lengths and sequence advantages: [B]

  • reduced loss: scalar

  • shared vocabulary logits and gradient: [V]

DPO similarly uses response log-probability ratios. Summing versus length-normalizing those ratios changes how short and long preference pairs influence training.

🔍 Deeper: the denominators are part of the objective

For responses \(i\) with per-token losses \(\ell_{it}\) and masks \(m_{it}\):

  • Global token mean: \(\dfrac{\sum_i\sum_tm_{it}\ell_{it}}{\sum_i\sum_tm_{it}}\). Every token counts equally, and long responses dominate.

  • Sequence mean: \(\dfrac1G\sum_i\dfrac{\sum_tm_{it}\ell_{it}}{\sum_tm_{it}}\). Every response counts equally, so per-token weight is \(1/|y_i|\).

  • Constant normalizer: \(\dfrac{1}{G\,L_{\max}}\sum_i\sum_tm_{it}\ell_{it}\). This matches the true sequence log-prob gradient, up to a constant.

Length bias: under a sequence mean, a long wrong answer’s negative advantage is spread thinly over many tokens, so each token is barely penalized and the policy drifts toward longer wrong answers. Dr. GRPO argues for a constant normalizer for this reason.

🔑 Key ideas

  • The reduction choice is a weighting choice and changes what you optimize.

  • Keep masks and denominators explicit, especially when length is learned.

🚶 Walkthrough: per-token weights

Short response: 10 tokens. Long response: 100 tokens. Token mean: each token weighs \(\tfrac1{110}\), so the short response gets \(9\%\) of the total. Sequence mean: short-response tokens weigh \(\tfrac1{20}\) each, long-response tokens \(\tfrac1{200}\) each, so it’s 50/50 per response.

Common mistakes

  • Token mean per microbatch (see Topic 52).

  • Padding in the denominator.

  • Switching reductions mid-run without changing the learning rate.

Debugging experiments

Remove the mask:

sequence_log_probs = selected_log_probs.sum(
    dim=-1
)

The four padding positions in the first row now reinforce action 0, even though those actions never occurred.

Next, replace:

lengths = torch.tensor([2, 6])

with:

lengths = torch.tensor([6, 6])

The opposing responses become symmetric, so every reduction should produce cancellation.

Finally, give the short response advantage 3:

advantages = torch.tensor([3.0, 1.0])

Under sequence sum, its total credit becomes \(3\times2=6\), matching the long response’s \(1\times6=6\). Reward scale and response length interact.

4. Checks for understanding

  1. Why is a response log-probability a sum over token log-probabilities?

  2. Which reduction gives long responses more total influence?

  3. Why can length normalization affect EOS behavior?

  4. Which reduction should be reported explicitly in an RL training implementation?

Solutions

Masked sequence log-probabilities:

sequence_log_probs = (
    selected_log_probs * float_mask
).sum(dim=-1)

Sequence-sum REINFORCE:

loss = -(
    sequence_log_probs
    * advantages.detach()
).mean()

Global token mean:

loss = -(
    selected_log_probs
    * float_mask
    * advantages[:, None].detach()
).sum() / float_mask.sum()

Per-response mean:

mean_log_probs = (
    sequence_log_probs
    / lengths.to(
        sequence_log_probs.dtype
    )
)

loss = -(
    mean_log_probs
    * advantages.detach()
).mean()

Three gradients:

sequence_gradient, sequence_loss = (
    gradient_for_reduction(
        "sequence_sum"
    )
)

token_gradient, token_loss = (
    gradient_for_reduction(
        "global_token_mean"
    )
)

response_mean_gradient, response_mean_loss = (
    gradient_for_reduction(
        "per_response_mean"
    )
)

At uniform probabilities, one action- 0 token contributes ascent direction:

\[[0.5,-0.5]\]

and one action- 1 token contributes:

\[[-0.5,0.5]\]

The short response contributes two action- 0 terms, while the long response contributes six action- 1 terms. Sequence sum therefore favors action 1.

Global token mean divides the same total gradient by eight, changing its scale but not its direction for this fixed batch.

Per-response normalization produces:

\[\frac12 \left( [0.5,-0.5] + [-0.5,0.5] \right) = [0,0]\]

because the two responses receive equal aggregate weight.

Check answers

  1. Autoregressive sequence probability is a product of conditional token probabilities; taking its logarithm converts that product into a sum.

  2. Sequence sum and global token mean both give longer responses more aggregate contribution.

  3. EOS determines length. Dividing by realized length changes the relative credit assigned to policies that terminate early or continue generating.

  4. Always report whether losses use sequence sums, global valid-token means or per-response length normalization, along with the exact mask denominator.

Retrieval answers

  1. KL is nonnegative after expectation; a sampled token may still be more probable under the reference, giving a negative log-ratio.

  2. Padding and post-termination actions never occurred in the trajectory, so including them creates fictitious gradient and KL contributions.

Takeaway: loss reduction is part of the objective. Sequence sums follow the log-probability of the sampled response; token and length-normalized means impose different weighting. Keep masks and denominators explicit—especially when EOS and response length are learned behavior.
