🧩 Analogy: a kitchen that cooks while the recipe is being edited

To keep a busy kitchen moving, cooks keep cooking from the recipe card they have, while the head chef edits the master recipe. Some dishes come out of a slightly old version. You can still learn from them, but you have to know how old each one was, and not trust very old ones too much.

2. Two mismatches

Large LLM-RL systems (verl, OpenRLHF, AReaL and others) separate a fast inference engine from the trainer and run them concurrently. That creates two gaps between the policy that sampled and the policy being trained:

  1. Staleness: the rollout used older weights \(\theta_{k-j}\).

  2. Engine mismatch: even with identical weights, the inference engine’s kernels, precision or sampling code give slightly different log-probs than the trainer.

Fix: truncated importance sampling (TIS). Record \(\log\pi_{\text{rollout}}\) at sampling time, recompute \(\log\pi_{\text{old}}\) with the trainer, and multiply each token’s PPO term by a capped, detached weight: \[w_t=\min\Big(\frac{\pi_{\text{old}}(y_t)}{\pi_{\text{rollout}}(y_t)},\ C\Big),\qquad\mathcal L=-\frac{\sum_tm_t\,\operatorname{sg}(w_t)\,\min\big(\rho_t\hat A_t,\operatorname{clip}(\rho_t)\hat A_t\big)}{\sum_tm_t}.\] This is the same idea as V-trace’s truncated weights, applied to LLM tokens. The cap trades a little bias for bounded variance.

🔑 Key ideas

  • Async training and inference engines make “on-policy” data slightly off-policy.

  • Log rollout-time log-probs, correct with capped weights, and monitor the mismatch.

🚶 Walkthrough: one bad token

Rollout log-prob \(-3.0\), trainer log-prob \(-1.5\). Raw weight \(e^{1.5}=4.48\), capped at \(C=2\). Without the cap, this one token would count 4.5\(\times\) a normal token in the gradient.

Common mistakes

  • Using the trainer’s log-probs as the behaviour policy (the mismatch disappears from view, but not from the data).

  • No cap (rare large weights dominate the gradient).

  • Not logging the mismatch: a sudden jump often means a sync bug.

Solutions

import torch


def async_ppo_loss(logp_new, logp_old, logp_rollout, adv, mask, eps=0.2, cap=2.0):
    ratio = (logp_new - logp_old).exp()                        # PPO ratio vs trainer's old policy
    tis = (logp_old - logp_rollout).exp().clamp(max=cap).detach()   # truncated IS: rollout engine mismatch
    surr = torch.min(ratio * adv, ratio.clamp(1 - eps, 1 + eps) * adv)
    return -(tis * surr * mask).sum() / mask.sum()


# 4 tokens. The rollout engine's log-probs differ slightly from the trainer's (kernels, precision, staleness).
logp_rollout = torch.tensor([-1.0, -2.0, -0.5, -3.0])
logp_old = torch.tensor([-1.0, -1.9, -0.6, -1.5])              # last token: big mismatch
logp_new = logp_old.clone().requires_grad_()
adv, mask = torch.tensor([1.0, 1.0, -1.0, 1.0]), torch.ones(4)
tis = (logp_old - logp_rollout).exp()
print("raw IS weights      :", [round(x, 3) for x in tis.tolist()])
print("truncated (cap=2.0) :", [round(x, 3) for x in tis.clamp(max=2.0).tolist()])
loss = async_ppo_loss(logp_new, logp_old, logp_rollout, adv, mask)
loss.backward()
print("grad per token      :", [round(x, 3) for x in logp_new.grad.tolist()])

Output:

raw IS weights      : [1.0, 1.105, 0.905, 4.482]
truncated (cap=2.0) : [1.0, 1.105, 0.905, 2.0]
grad per token      : [-0.25, -0.276, 0.226, -0.5]

At \(\theta=\theta_{\text{old}}\) each gradient is \(-w_t\hat A_t/4\): the last token’s weight is capped at 2 instead of 4.48.

Check answers

  1. Different numerical kernels, precision and sampling implementations in the inference engine.

  2. A small bias (large-weight tokens are undercounted) for bounded gradient variance.

Retrieval answers: (1) Importance weights, capped to bound variance from off-policy data. (2) Exactly 1.

Takeaway: at scale, “on-policy” is an approximation. Record what the sampler actually computed and correct for the gap.
