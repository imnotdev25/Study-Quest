🧩 Analogy: changing a recipe gradually

Instead of switching to a brand-new recipe overnight, a cautious chef changes 20% of the dishes, checks reviews, then 40%, and so on. Conservative policy mixing blends the deployed policy with a candidate, and moves only as far as the logs can still vouch for.

The lower bound peaks at a moderate \(\alpha\) (0.4 here): further steps gain estimate but lose evidence.

2. Interpolate between the deployed and candidate policies

Suppose behavior policy \(\mu\) produced the logs, while candidate policy \(\pi\) is more aggressive. Instead of immediately deploying \(\pi\), define:

\[\pi_\alpha(a\mid s) = (1-\alpha)\mu(a\mid s) + \alpha\pi(a\mid s), \qquad 0\leq\alpha\leq1\]

Here:

  • \(\alpha=0\): unchanged behavior policy;

  • \(\alpha=1\): complete candidate policy;

  • intermediate \(\alpha\): conservative movement toward the candidate.

For a logged decision, its importance ratio is:

\[\rho_i(\alpha) = \frac{\pi_\alpha(a_i\mid s_i)} {\mu(a_i\mid s_i)} = 1+\alpha \left[ \frac{\pi(a_i\mid s_i)} {\mu(a_i\mid s_i)} -1 \right]\]

Estimate the mixture’s value with:

\[\hat J(\pi_\alpha) = \frac1N\sum_i\rho_i(\alpha)r_i\]

Use paired improvement contributions because every policy is evaluated on the same rows:

\[D_i(\alpha) = \rho_i(\alpha)r_i-r_i\]

\[\hat\Delta_\alpha=\bar D_\alpha, \qquad \operatorname{SE}_\alpha = \frac{s_{D_\alpha}}{\sqrt N}\]

If searching \(K\) fixed mixture strengths, a conservative simultaneous lower bound uses:

\[z= \Phi^{-1}\left(1-\frac{\delta}{K}\right)\]

\[\operatorname{LCB}_\alpha = \hat\Delta_\alpha-z\operatorname{SE}_\alpha\]

Also require adequate effective sample size:

\[N_{\text{eff}}(\alpha) = \frac{\left(\sum_i\rho_i\right)^2} {\sum_i\rho_i^2}\]

Mixing weakens distribution shift; it cannot repair missing support. If \(\mu(a\mid s)=0\) while \(\pi(a\mid s)>0\), every \(\alpha>0\) remains unevaluable for that action.

Tensor shapes:

  • mixture strengths: [K]

  • logged actions and rewards: [N]

  • mixture probabilities, weights and contributions: [K, N]

  • estimates, lower bounds and ESS: [K]

For an LLM agent, distinguish:

  • stepwise mixing: blend token or tool probabilities at every decision;

  • episode routing: randomly select one complete policy per prompt.

These define different trajectory probabilities and require different propensity calculations.

DPO may produce the candidate from fixed preference pairs. Policy mixing and environmental OPE are deployment controls; DPO’s preference loss does not certify online reward improvement.

🔍 Deeper: why mixing helps

\(\pi_\alpha=(1-\alpha)\pi_0+\alpha\pi_1\). The ratio against the logger \(\pi_0\) is \(\frac{\pi_\alpha}{\pi_0}=1-\alpha+\alpha\frac{\pi_1}{\pi_0}\), so small \(\alpha\) keeps weights near 1 and the ESS high. Procedure: for a grid of \(\alpha\), compute an OPE estimate and its lower bound, then choose the largest \(\alpha\) with LCB above the baseline (with multiple-testing correction across the grid).

🔑 Key ideas

  • Interpolate toward a candidate and stop when evidence or coverage weakens.

  • A smaller supported improvement is more deployable than a big unsupported one.

🚶 Walkthrough: choose \(\alpha\)

Estimates (gain over baseline, LCB): \(\alpha=0.2\): \((0.04,0.03)\); \(0.4\): \((0.08,0.04)\); \(0.6\): \((0.12,0.03)\); \(1.0\): \((0.20,-0.05)\). The best LCB is at \(\alpha=0.4\). Full switching has the biggest estimate and a negative lower bound.

Common mistakes

  • Picking \(\alpha\) by point estimate.

  • No correction for trying several \(\alpha\) values.

  • Assuming the LCB is monotone in \(\alpha\).

  • Scale rewards by 100 but leave a nonzero minimum-improvement threshold unchanged.

  • Implement episode-level routing but calculate probabilities as if the policies were mixed at every token.

Solutions

Mixture and selected-action probabilities:

mixed_one_probabilities = (
    (1.0 - alphas)
    * behavior_one_probability
    + alphas
    * candidate_one_probability
)

behavior_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        behavior_one_probability
    ),
    torch.tensor(
        1.0 - behavior_one_probability
    ),
)

mixed_action_probabilities = torch.where(
    actions[None, :] == 1,
    mixed_one_probabilities[:, None],
    1.0 - mixed_one_probabilities[:, None],
)

Weights and paired contributions:

log_weights = (
    mixed_action_probabilities.log()
    - behavior_action_probabilities[
        None, :
    ].log()
)

weights = log_weights.exp()

mixture_contributions = (
    weights * rewards[None, :]
)

behavior_contributions = (
    rewards[None, :].expand(
        num_candidates,
        -1,
    )
)

estimated_values = (
    mixture_contributions.mean(dim=1)
)

paired_differences = (
    mixture_contributions
    - behavior_contributions
)

estimated_improvements = (
    paired_differences.mean(dim=1)
)

Simultaneous lower bounds:

paired_standard_errors = (
    paired_differences.std(
        dim=1,
        correction=1,
    )
    / math.sqrt(num_samples)
)

simultaneous_z = standard_normal.icdf(
    torch.tensor(
        1.0
        - family_delta / num_tests
    )
)

simultaneous_lcbs = (
    estimated_improvements
    - simultaneous_z
    * paired_standard_errors
)

ESS diagnostics:

effective_sample_sizes = (
    weights.sum(dim=1).square()
    / weights.square().sum(dim=1)
)

effective_sample_fractions = (
    effective_sample_sizes
    / num_samples
)

maximum_weights = (
    weights.max(dim=1).values
)

Selection and oracle values:

feasible = (
    (
        simultaneous_lcbs
        > minimum_improvement
    )
    & (
        effective_sample_fractions
        >= minimum_ess_fraction
    )
)

chosen_index = torch.where(
    feasible
)[0][-1]

chosen_alpha = alphas[
    chosen_index
]

behavior_policy = torch.tensor([
    1.0 - behavior_one_probability,
    behavior_one_probability,
])

exact_behavior_value = (
    behavior_policy * reward_means
).sum()

exact_mixture_values = (
    (
        1.0
        - mixed_one_probabilities
    ) * reward_means[0]
    + mixed_one_probabilities
    * reward_means[1]
)

The mixture chooses action 1 with probability:

\[p_\alpha=0.1+0.8\alpha\]

Therefore:

\[J(\pi_\alpha) = (1-p_\alpha)0.4+p_\alpha0.8 = 0.44+0.32\alpha\]

The endpoints are:

\[J(\mu)=0.44, \qquad J(\pi)=0.76\]

The two possible importance weights are:

\[\rho(1)=1+8\alpha\]

\[\rho(0)=1-\frac89\alpha\]

Their second moment under the behavior policy is:

\[\mathbb E_\mu[\rho^2] = 1+\frac{64}{9}\alpha^2\]

Thus the approximate ESS fraction is:

\[\frac{N_{\text{eff}}}{N} \approx \frac{1}{ 1+\frac{64}{9}\alpha^2 }\]

Requiring this to be at least 0.25 gives:

\[\alpha\lesssim0.6495\]

The largest grid value should therefore be 0.6, with exact value:

\[J(\pi_{0.6}) = 0.44+0.32(0.6) = 0.632\]

Check answers

  1. Larger \(\alpha\) places more probability on actions rare under the behavior policy, concentrating importance weights on fewer logged rows.

  2. Pairing preserves shared reward noise and directly estimates the deployment-relevant difference \(J(\pi_\alpha)-J(\mu)\).

  3. It covers the fixed grid’s repeated comparisons under the normal approximation. It does not correct candidate training on evaluation data, support failure, distribution shift or invalid propensity logs.

  4. Report \(\alpha\), value improvement, simultaneous LCB, ESS, weight quantiles and maximum, action support, behavior-policy version, reward scale, safety costs and subgroup results.

Retrieval answers

  1. Unsupported target mass is the probability the target policy assigns to actions with no logged coverage.

  2. Ensemble members share data and modeling assumptions, so their spread need not have any stated statistical coverage.

Takeaway: interpolate toward a candidate and stop when either evidence or coverage becomes weak. A smaller supported improvement is more deployable than a large estimate dominated by a handful of unlikely logged actions.
