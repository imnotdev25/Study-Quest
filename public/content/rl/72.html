🧩 Analogy: a prepaid metro card

A prepaid metro card doesn’t “discourage” you from riding beyond your balance. The gate just won’t open. For that to work, the gate has to know your current balance. Hard tool budgets need the same two pieces: remaining budget in the state, and a mask that blocks unaffordable actions.

2. Expected constraints are not hard limits

A Lagrangian can keep average cost near a budget, but one trajectory may still overspend. For a hard per-request limit, remaining budget must be part of the state:

\[\tilde s_t=(s_t,b_t)\]

After action \(a_t\) with cost \(c(a_t)\):

\[b_{t+1}=b_t-c(a_t)\]

An action is feasible only when:

\[M_t(a)=\mathbf 1[c(a)\le b_t]\]

Mask infeasible actions before sampling:

\[\pi^M(a\mid s_t,b_t) = \frac{ \pi(a\mid s_t)M_t(a) }{ \sum_{a'}\pi(a'\mid s_t)M_t(a') }\]

This is like a debit-card authorization: the transaction is blocked before execution, not merely penalized afterward.

The shield changes the policy distribution. PPO must therefore use masked rollout and training probabilities:

\[r_t(\theta) = \exp\left( \log\pi_\theta^M(a_t\mid s_t,b_t) - \log\pi_{\text{old}}^M(a_t\mid s_t,b_t) \right)\]

Using an unmasked numerator creates false ratios even when model weights are unchanged.

Practical limits:

  • always provide a zero-cost fallback such as “answer” or “abort”;

  • reconstruct the exact budget and mask during training;

  • for stochastic costs, reserve a safe upper bound before execution;

  • log requested, reserved and actual cost separately.

Tensor shapes:

  • logits and masks: [B, T, A]

  • action costs: [A]

  • actions and log-probabilities: [B, T]

  • remaining-budget history: [B, T+1]

DPO can prefer budget-compliant traces, but it cannot prevent an online sample from exceeding a runtime budget. The environment or policy shield must enforce that boundary.

🔍 Deeper: budget-augmented state

Augment the state: \(\tilde s_t=(s_t,b_t)\) with \(b_{t+1}=b_t-c(a_t)\). Mask: \(v_a(\tilde s)=\mathbb 1[c(a)\le b]\).

  • Without \(b\) in the state, the process isn’t Markov: the same observation with 1 or 10 calls left needs different actions.

  • The mask guarantees \(\sum_tc(a_t)\le b_0\) on every episode, a guarantee the Lagrangian can’t give.

  • Always keep a free fallback action (“answer now”) so the mask is never empty.

🔑 Key ideas

  • Average constraints shape behaviour, and a budget-aware shield enforces it.

  • Update \(b\) after every action and reproduce the exact mask in training.

🚶 Walkthrough: budget 3

Search costs 2, calculator costs 1, answer costs 0. Start \(b=3\). After one search: \(b=1\), so search is masked, while calculator and answer stay legal. After a calculator call: \(b=0\), and only answer is left.

Common mistakes

  • The budget not in the observation.

  • Decrementing \(b\) for a call that failed to execute.

  • The training mask computed from the final budget instead of the per-step budget.

4. Checks for understanding

  1. Why must remaining budget be included in the policy state?

  2. How does a hard shield differ from a Lagrangian constraint?

  3. Why must PPO reconstruct the same mask used during rollout?

  4. What should be logged when tool costs are stochastic?

Solutions

Dynamic feasibility:

valid = (
    action_costs[None, :]
    <= remaining[:, None]
)

Shielded sampling and budget update:

masked_logits = logits[
    :, time
].masked_fill(
    ~valid,
    -torch.inf,
)

policy = Categorical(
    logits=masked_logits
)

sampled_actions = policy.sample()

sampled_log_probs = policy.log_prob(
    sampled_actions
)

sampled_costs = action_costs[
    sampled_actions
]

remaining = (
    remaining - sampled_costs
)

Correct recomputation:

recomputed_masked_logits = (
    logits.masked_fill(
        ~valid_masks,
        -torch.inf,
    )
)

correct_log_probs = Categorical(
    logits=recomputed_masked_logits
).log_prob(actions)

correct_ratios = torch.exp(
    correct_log_probs
    - old_log_probs.detach()
)

Incorrect unmasked recomputation:

wrong_log_probs = Categorical(
    logits=logits
).log_prob(actions)

wrong_ratios = torch.exp(
    wrong_log_probs
    - old_log_probs.detach()
)

Loss and diagnostics:

policy_loss = -(
    correct_log_probs
    * advantages.detach()
).mean()

selected_are_valid = (
    valid_masks.gather(
        dim=-1,
        index=actions.unsqueeze(-1),
    )
    .squeeze(-1)
    .all()
)

maximum_correct_ratio_error = (
    correct_ratios - 1.0
).abs().max()

mean_wrong_ratio_error = (
    wrong_ratios - 1.0
).abs().mean()

maximum_invalid_gradient = (
    logit_gradients[~valid_masks]
    .abs()
    .max()
)

Because parameters and masks are unchanged:

\[r_t^{\text{correct}}=1\]

The unmasked policy includes unaffordable actions in its softmax denominator, so its selected-action probability differs from the rollout probability. Its apparent PPO ratio can therefore be far from one.

Known deterministic costs and pre-sampling masks guarantee:

\[b_t\ge0\]

Infeasible logits receive zero direct gradient through this masked distribution. Shared model parameters can still change through valid logits elsewhere.

Check answers

  1. The same observation can have different legal actions depending on earlier spending.

  2. A Lagrangian regulates average behavior; a shield makes forbidden actions impossible on each decision.

  3. The PPO numerator and denominator must describe the same action space and conditioning state.

  4. Log quoted cost, reserved cost, actual cost, overruns, remaining budget, fallback frequency and failures by tool.

Retrieval answers

  1. A fixed penalty defines a trade-off, but the resulting cost changes with rewards, policy capacity and environment distribution.

  2. Increase \(\lambda\) when cost exceeds the budget; expensive behavior then receives a stronger penalty.

Takeaway: average constraints shape behavior, while a budget-aware shield enforces the boundary. Update remaining budget after every action and reproduce the exact mask during training.
