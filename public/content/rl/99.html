🧩 Analogy: a class average with missing grades

You know 80% of a class’s grades, averaging 70. The other 20% are missing. Without assumptions, the true class average could be anywhere from \(0.8\times70+0.2\times0=56\) to \(0.8\times70+0.2\times100=76\). That range is honest. Any single number would be a guess dressed up as a fact.

Manski bounds. The baseline sits inside the interval, so promotion is blocked.

2. Missing support creates uncertainty that more fitting cannot remove

Imagine evaluating a vehicle using city-road data when 20% of deployment will be off-road. Predicting off-road performance with a flexible model may produce a number, but the logs did not identify that number.

Let target group probabilities be \(p(g)\), group outcomes be \(\mu_g\), and \(S\) be the groups represented in the logs:

\[J = \sum_{g\in S}p(g)\mu_g + \sum_{g\notin S}p(g)\mu_g\]

Suppose rewards are known to satisfy:

\[L\le R\le U\]

Define the supported contribution and unsupported target mass:

\[C=\sum_{g\in S}p(g)\hat\mu_g, \qquad u=\sum_{g\notin S}p(g)\]

Then the defensible identification bounds are:

\[C+uL \le J\le C+uU\]

Their width is:

\[u(U-L)\]

More samples from already-supported groups reduce sampling error in \(C\), but cannot reduce this identification width. To narrow it, collect data in missing groups, narrow the target population, or add an explicit structural assumption.

These are different uncertainties:

  • Sampling uncertainty: we observed a group but estimated its mean imperfectly.

  • Identification uncertainty: we never observed the required group-policy outcome.

Tensor shapes:

  • logged groups and rewards: [N]

  • one-hot membership: [N, G]

  • counts, means and target probabilities: [G]

  • final value bounds: scalars

For LLM agents, missing support can involve languages, tool schemas, long-horizon tasks or prompt families. Token-level similarity does not establish outcome support.

DPO can keep a policy close to a reference on preference data, but that does not reveal its deployment reward in an unseen group. A model prediction is an extrapolation assumption, not online RL evidence.

🔍 Deeper: Manski-style bounds

Let a fraction \(s\) of target traffic be supported by the logs (estimate \(\hat V_s\)) and \(1-s\) unsupported, with rewards in \([r_{\min},r_{\max}]\). Then \[V\in\big[s\hat V_s+(1-s)r_{\min},\ s\hat V_s+(1-s)r_{\max}\big].\] The width \((1-s)(r_{\max}-r_{\min})\) shrinks only with new data on the unsupported traffic, not with better models of the old data. Assumptions such as monotonicity or a bounded effect can narrow the bounds, but state them.

🔑 Key ideas

  • When target traffic leaves the logs’ support, report a range.

  • Modelling can’t substitute for missing interventions.

🚶 Walkthrough: 20% unsupported blocks promotion

Supported 80% with \(\hat V_s=0.70\), rewards in \([0,1]\): \(V\in[0.56,0.76]\). The baseline 0.65 lies inside, so the candidate could be worse. Collect canary data on the unsupported 20%.

Common mistakes

  • Extrapolating a model into the unsupported region and reporting a point estimate.

  • Unstated assumptions that narrow the bounds.

  • Forgetting the reward range when rewards are unbounded (the bounds become infinite).

⚙️ Algorithm: Partial-identification promotion check
Input: supported fraction \(s\), supported estimate \(\hat V_s\) (with its CI), reward range \([r_{\min},r_{\max}]\), baseline \(V_0\)
\(L\gets s\cdot\mathrm{LCB}(\hat V_s)+(1-s)r_{\min}\)
\(U\gets s\cdot\mathrm{UCB}(\hat V_s)+(1-s)r_{\max}\)
if \(L>V_0\) then promote
else if \(U<V_0\) then reject
else inconclusive: collect data on the unsupported traffic
end

3. PyTorch exercise — an unsupported 20% blocks promotion

Predict before running:

  1. What is the unsupported target mass?

  2. Ignoring sampling error, should the value bounds be near [0.59, 0.79]?

  3. Can the candidate robustly beat a baseline value of 0.62?

Hints

  • F.one_hot(..., num_classes=3) preserves the absent group as an all-zero column.

  • Support is group_counts > 0.

  • Use counts.clamp_min(1) to avoid division by zero, but retain NaN for unsupported means.

  • Sum target-weighted means only over supported groups.

  • For independent Bernoulli group means:

\[SE(C) = \sqrt{ \sum_{g\in S} p(g)^2 \frac{\hat\mu_g(1-\hat\mu_g)}{n_g} }\]

  • Imputation produces a point estimate only by assuming something about the unseen group.

Debugging experiments

  • Divide by the zero count and let a NaN contaminate every result.

  • Replace the missing mean with zero and describe that choice as data-driven.

  • Let a reward model’s extrapolation erase the identification interval.

  • Bootstrap logged rows and expect missing support to reappear.

  • Rescale rewards without changing \(L\) and \(U\).

  • Treat one rare observation as strong support; nonzero support can still be extremely weak.

Solutions

Safe group summaries:

group_one_hot = F.one_hot(
    logged_groups,
    num_classes=num_groups,
).to(torch.float64)

group_counts = group_one_hot.sum(dim=0)

group_reward_sums = (
    group_one_hot
    * rewards[:, None]
).sum(dim=0)

supported_groups = (
    group_counts > 0
)

estimated_group_values = torch.where(
    supported_groups,
    group_reward_sums
    / group_counts.clamp_min(1.0),
    torch.full_like(
        group_counts,
        float("nan"),
    ),
)

Identification bounds:

unsupported_target_mass = (
    target_group_probabilities[
        ~supported_groups
    ].sum()
)

supported_contribution = (
    target_group_probabilities[
        supported_groups
    ]
    * estimated_group_values[
        supported_groups
    ]
).sum()

identification_lower_bound = (
    supported_contribution
    + unsupported_target_mass
    * reward_minimum
)

identification_upper_bound = (
    supported_contribution
    + unsupported_target_mass
    * reward_maximum
)

identification_width = (
    identification_upper_bound
    - identification_lower_bound
)

Sampling uncertainty:

supported_standard_error = torch.sqrt(
    (
        target_group_probabilities[
            supported_groups
        ].square()
        * estimated_group_values[
            supported_groups
        ]
        * (
            1.0
            - estimated_group_values[
                supported_groups
            ]
        )
        / group_counts[
            supported_groups
        ]
    ).sum()
)

combined_lower_bound = (
    identification_lower_bound
    - z_value * supported_standard_error
)

combined_upper_bound = (
    identification_upper_bound
    + z_value * supported_standard_error
)

Promotion decision:

lower_improvement_bound = (
    combined_lower_bound
    - baseline_target_value
)

upper_improvement_bound = (
    combined_upper_bound
    - baseline_target_value
)

robustly_improves = (
    lower_improvement_bound > 0.0
)

Imputation and oracle comparison:

global_logged_mean = rewards.mean()

imputed_group_values = torch.where(
    supported_groups,
    estimated_group_values,
    global_logged_mean,
)

imputed_target_value = (
    target_group_probabilities
    * imputed_group_values
).sum()

oracle_target_value = (
    target_group_probabilities
    * true_candidate_group_values
).sum()

oracle_improvement = (
    oracle_target_value
    - baseline_target_value
)

Ignoring sampling noise, the supported contribution is:

\[C = 0.5(0.70)+0.3(0.80) = 0.59\]

Because 20% of target traffic is unsupported and rewards lie in \([0,1]\):

\[J\in[0.59,\;0.59+0.20]=[0.59,0.79]\]

Relative to the baseline:

\[J-0.62\in[-0.03,0.17]\]

The data therefore cannot certify improvement. Yet the simulation’s hidden oracle value is:

\[J_{\text{oracle}} = 0.5(0.70)+0.3(0.80)+0.2(0.30) = 0.65\]

So the candidate truly improves by 0.03, but robust promotion still fails. That is an appropriate “insufficient evidence” conclusion, not a claim that the candidate is worse.

Check answers

  1. Additional observations reduce estimation error for supported groups but provide no outcomes for the unsupported group.

  2. It is the irreducible worst-case uncertainty contributed by unsupported target mass under the stated reward range.

  3. Collect representative outcomes, exclude unsupported traffic from the target, or defend a stronger assumption that restricts unseen outcomes.

  4. Yes. Truth and identifiability differ: a beneficial policy may remain uncertifiable from inadequate data.

Retrieval answers

  1. Aggregate change decomposes into traffic-composition change and within-group performance change.

  2. Tool usage may be caused by the policy and mediate its real effect. Controlling for it can remove part of the policy outcome rather than isolate external drift.

Takeaway: when target traffic leaves the support of your logs, report a range rather than manufacture a point estimate. More modeling cannot substitute for the missing intervention data.
