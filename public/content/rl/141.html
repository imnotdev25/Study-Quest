2. A bootstrap cannot invent an event absent from the logs

For one-step OPE, each logged episode contributes:

\[Z_i = \underbrace{ \frac{\pi(A_i)}{\mu(A_i)} }_{\text{target-to-behavior probability ratio}} \underbrace{R_i}_{\text{observed reward}}\]

and:

\[\hat V_{\mathrm{IPS}} = \underbrace{ \frac1N\sum_{i=1}^{N}Z_i }_{\text{average importance-weighted contribution}}\]

Positive support,

\[\pi(a)>0 \Longrightarrow \underbrace{\mu(a)>0}_{\text{behavior can sample the action}},\]

is necessary but not sufficient for useful finite-sample evaluation.

Suppose behavior selects an important action with probability 0.01. With \(N=100\), the probability of seeing it zero times is:

\[P(K=0) = \underbrace{(1-0.01)^{100}}_{\text{no rare action in any episode}} \approx 0.366\]

If that action receives 50% of target-policy probability, its importance weight is:

\[w(1) = \underbrace{\frac{0.50}{0.01}}_{\text{target mass divided by logging mass}} = 50\]

When a dataset contains no such episode, a nonparametric bootstrap only resamples the observed common episodes:

\[K=0 \quad\Longrightarrow\quad \underbrace{\hat V_b^*=0\;\text{for every }b}_{\text{degenerate bootstrap distribution}}\]

The interval [0, 0] means “the empirical dataset contains no variation,” not “the policy value is known exactly.”

For LLM agents, the missing event might be a rare tool call, escalation path or high-stakes prompt type. Resampling existing trajectories cannot manufacture that branch. Likewise, bootstrapping a DPO preference dataset cannot evaluate response modes absent from its prompts and candidate completions.

Tensor shapes:

  • actions, weights and contributions: [R, N]

  • rare-action counts and estimates: [R]

  • bootstrap indices: [B, N]

  • bootstrap estimates: [B]

Hints

The action is rare when a uniform sample falls below behavior_policy[1].

The second moment is:

\[E_\mu[Z^2] = \underbrace{ \sum_a \mu(a) \left[ \frac{\pi(a)}{\mu(a)}R(a) \right]^2 }_{\text{behavior expectation of squared contribution}}\]

For the sample-size calculation, solve:

\[(1-\mu_1)^N<0.05\]

The usual ESS diagnostic is:

\[N_{\mathrm{eff}} = \underbrace{ \frac{\left(\sum_iw_i\right)^2} {\sum_iw_i^2} }_{\text{concentration of observed weights}}\]

Debugging experiments

  • Inspect ESS without checking whether importance_weights.mean() is near one.

  • Clip the weight 50 to 10 and continue claiming unbiased evaluation.

  • Bootstrap individual agent tokens instead of complete trajectories.

  • Increase bootstrap replicates while leaving the logged dataset unchanged.

  • Treat population support as proof that the realized dataset has adequate coverage.

Solutions

Logged episodes:

actions = (
    torch.rand(
        num_repetitions,
        episodes_per_repetition,
    )
    < behavior_policy[1]
).to(torch.long)

rewards = reward_by_action[actions]

importance_weights = (
    target_policy[actions]
    / behavior_policy[actions]
)

contributions = (
    importance_weights * rewards
)

ips_estimates = contributions.mean(dim=1)

rare_counts = (
    actions == 1
).sum(dim=1)

Population uncertainty:

exact_target_value = (
    target_policy * reward_by_action
).sum()

all_action_contributions = (
    target_policy
    / behavior_policy
    * reward_by_action
)

second_moment = (
    behavior_policy
    * all_action_contributions.square()
).sum()

true_variance = (
    second_moment
    - exact_target_value.square()
)

true_standard_error = torch.sqrt(
    true_variance
    / episodes_per_repetition
)

empirical_standard_error = (
    ips_estimates.std(correction=1)
)

zero_rare_fraction = (
    (rare_counts == 0)
    .to(torch.float64)
    .mean()
)

Normal intervals:

estimated_standard_errors = (
    contributions.std(
        dim=1,
        correction=1,
    )
    / math.sqrt(
        episodes_per_repetition
    )
)

lower_bounds = (
    ips_estimates
    - z_value * estimated_standard_errors
)

upper_bounds = (
    ips_estimates
    + z_value * estimated_standard_errors
)

normal_coverage = (
    (
        (lower_bounds <= exact_target_value)
        & (exact_target_value <= upper_bounds)
    )
    .to(torch.float64)
    .mean()
)

Episode bootstrap:

zero_study_index = torch.nonzero(
    rare_counts == 0,
    as_tuple=False,
)[0, 0]

one_study_index = torch.nonzero(
    rare_counts == 1,
    as_tuple=False,
)[0, 0]


def bootstrap_study(study_index):
    indices = torch.randint(
        low=0,
        high=episodes_per_repetition,
        size=(
            num_bootstrap_samples,
            episodes_per_repetition,
        ),
    )

    bootstrap_estimates = (
        contributions[
            study_index,
            indices,
        ].mean(dim=1)
    )

    standard_error = (
        bootstrap_estimates.std(
            correction=1
        )
    )

    interval = bootstrap_estimates.quantile(
        torch.tensor([0.025, 0.975])
    )

    return (
        bootstrap_estimates,
        standard_error,
        interval,
    )


zero_bootstrap = bootstrap_study(
    zero_study_index
)

one_bootstrap = bootstrap_study(
    one_study_index
)

Expected results:

\[V^\pi = \underbrace{0.5(0)}_{\text{common action}} + \underbrace{0.5(1)}_{\text{rare under behavior}} = 0.5\]

The true standard error is:

\[SE = \sqrt{ \frac{ \underbrace{0.01(50^2)}_{E[Z^2]=25} - \underbrace{0.5^2}_{E[Z]^2} }{100} } \approx 0.498\]

Typical diagnostics:

  • mean IPS estimate: near 0.50;

  • empirical SD: near 0.50;

  • datasets with no rare action: about 36.6%;

  • normal-interval coverage: roughly 63%;

  • zero-event bootstrap: SE 0, interval [0, 0];

  • one-event bootstrap: SE near 0.50, usually interval around [0, 1.5];

  • zero-event mean weight: 0.505, exposing missing target mass;

  • zero-event ESS: misleadingly 100;

  • one-event ESS: approximately 3.96;

  • episodes needed to make \(P(K=0)<5\%\): 299.

Check answers

  1. Yes. IPS remains unbiased across repeated datasets because population support exists.

  2. [0, 0]: every bootstrap sample contains only zero contributions.

  3. Yes. All observed weights are identical, so ESS reports perfect balance while ignoring the missing rare stratum.

  4. Approximately 0.50; one rare episode changes the estimate by 0.50.

  5. No. Clipping reduces variance by changing the weights, generally introducing bias.

Retrieval answers

  1. Tokens within an episode share history and latent task difficulty; resampling them separately destroys that dependence.

  2. The episode-level component \(\sigma_U^2/N\) remains. More steps refine existing episodes but do not create additional independent episodes.

Takeaway: more bootstrap draws cannot compensate for missing logged events. Inspect per-branch counts, target mass, mean weights and maximum weights—not ESS alone—and collect targeted data when a consequential policy branch is rare.
