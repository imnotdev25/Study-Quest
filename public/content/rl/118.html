2. KL coefficient as a feedback controller

A KL-regularized RLHF objective is:

\[J(\theta) = E[R]-\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\text{ref}})\]

Here, \(\beta\) determines how expensive policy drift is:

  • larger \(\beta\): stronger reference constraint;

  • smaller \(\beta\): task reward dominates.

Rather than fixing \(\beta\), choose a target KL \(D^*\) and update it from a detached rollout-level measurement \(\hat D_n\):

\[e_n=\frac{\hat D_n}{D^*}-1\]

A useful multiplicative controller is:

\[\log\beta_{n+1} = \log\beta_n+ \eta\,\operatorname{clip}(e_n,-c,c)\]

Equivalently:

\[\beta_{n+1} = \beta_n \exp\left( \eta\,\operatorname{clip}(e_n,-c,c) \right)\]

The sign is crucial:

\[\hat D>D^* \Rightarrow e>0 \Rightarrow \beta\uparrow \Rightarrow \text{future KL}\downarrow\]

Updating in log space keeps \(\beta>0\). Clipping the controller error limits sudden coefficient jumps; this is distinct from PPO ratio clipping.

The policy responds with delay. A large controller gain \(\eta\) can therefore alternate between excessive and insufficient regularization. A noisy minibatch KL can also make \(\beta\) wander. Update it from globally aggregated valid response tokens, usually once per rollout rather than once per minibatch.

Tensor shapes:

  • token KL and response mask: [B, T]

  • globally aggregated KL and \(\beta\): scalars

  • simulated controller histories: [C, S + 1]

The KL target must match the reduction: nats per response token, per response or sequence-summed KL are different units. Reward rescaling also changes the relative influence of \(\beta\).

DPO’s \(\beta\) scales preference log-ratio margins in a fixed-data loss. It is not normally a feedback coefficient updated from online rollout KL.

Solutions

Analytic equilibrium:

expected_beta = (
    unregularized_kl / target_kl - 1.0
) / regularization_gain

This gives:

\[\beta^* = \frac{0.50/0.10-1}{4} = 1\]

History initialization:

betas = torch.empty(
    num_controllers,
    num_steps + 1,
)

true_kls = torch.empty_like(betas)

measured_kls = torch.empty(
    num_controllers,
    num_steps,
)

normalized_errors = torch.empty_like(
    measured_kls
)

betas[:, 0] = initial_beta
true_kls[:, 0] = initial_kl

measurement_noise = (
    measurement_noise_sd[:, None]
    * torch.randn(
        num_controllers,
        num_steps,
    )
)

Measurement and error:

measured_kl = (
    true_kls[:, step].detach()
    + measurement_noise[:, step]
).clamp_min(0.0)

normalized_error = (
    measured_kl / target_kl - 1.0
)

controlled_error = normalized_error.clamp(
    -error_clip,
    error_clip,
)

measured_kls[:, step] = measured_kl
normalized_errors[:, step] = (
    normalized_error
)

Controller and delayed policy response:

next_log_beta = (
    betas[:, step].log()
    + controller_signs
    * controller_rates
    * controlled_error
)

next_log_beta = next_log_beta.clamp(
    min=math.log(beta_minimum),
    max=math.log(beta_maximum),
)

next_beta = next_log_beta.exp()

betas[:, step + 1] = next_beta

equilibrium_kl = (
    unregularized_kl
    / (
        1.0
        + regularization_gain
        * next_beta
    )
)

true_kls[:, step + 1] = (
    true_kls[:, step]
    + policy_response_rate
    * (
        equilibrium_kl
        - true_kls[:, step]
    )
)

Diagnostics:

tail_mean_kl = (
    true_kls[:, -tail_length:]
    .mean(dim=1)
)

tail_mean_absolute_error = (
    true_kls[:, -tail_length:]
    .sub(target_kl)
    .abs()
    .mean(dim=1)
)

tail_mean_beta = (
    betas[:, -tail_length:]
    .mean(dim=1)
)

signed_errors = (
    true_kls - target_kl
)

target_crossings = (
    (
        signed_errors[:, 1:]
        * signed_errors[:, :-1]
    ) < 0.0
).sum(dim=1)

beta_saturation_fraction = (
    (
        (betas <= beta_minimum * 1.001)
        | (betas >= beta_maximum * 0.999)
    )
    .to(torch.float64)
    .mean(dim=1)
)

Expected behavior:

  • Stable aggregated: \(\beta\) rises from 0.05 toward roughly 1, while KL approaches 0.10.

  • Too aggressive: delayed policy response causes repeated overshoot and target crossings.

  • Noisy minibatch: the average direction is correct, but \(\beta\) wanders more.

  • Wrong sign: high KL decreases \(\beta\), weakening the penalty and creating positive feedback. It approaches the lower bound while KL approaches the unregularized value 0.50.

Check answers

  1. Controller gain governs feedback speed relative to delayed policy response; excessive gain destabilizes the closed loop.

  2. The coefficient update is an outer control decision, not part of the policy’s backpropagation graph.

  3. Globally sum valid token KL and valid-token count, then divide once. Prompt-balanced control instead needs per-response statistics followed by a global response mean.

  4. The target may be unreachable, reward/KL scales may be mismatched, the sign may be wrong, or the measurement may not match the intended KL.

  5. The statistic may use stale-policy samples, the wrong mask or reduction, or a biased clipped estimator.

Retrieval answers

  1. Old actions follow \(\mu\), while forward current-policy KL requires expectation under \(p\); without valid importance correction, these are different measures.

  2. A low ESS means a small number of high-weight samples dominate, producing high variance and weak effective support.

Takeaway: adaptive KL is a delayed feedback loop. Measure one clearly defined detached KL over the full rollout, increase \(\beta\) when that KL is too high, and tune controller speed using oscillation, saturation and measurement-noise diagnostics.
