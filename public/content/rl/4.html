🧩 Analogy: how GPS finds your route

GPS doesn’t try every route from your house. It works backward from the destination: “cells next to the goal are 1 step away, cells next to those are 2 away…” Value iteration does the same thing. Value flows outward from rewarding states like ripples on a pond, and the best action is to walk uphill on that value map.

Value \(=-\)(steps to goal) with reward \(-1\) per step. Darker means more valuable. The arrows show the greedy policy: always move to a darker neighbour.

2. Evaluation versus control

Last session, we evaluated a fixed policy:

\[V^\pi(s) = \sum_a \pi(a\mid s)Q^\pi(s,a)\]

That answers:

How good is my current policy?

But an RL agent usually wants control:

What is the best policy I can construct?

Define the optimal values:

\[V^*(s)=\max_\pi V^\pi(s)\]

\[Q^*(s,a) = \mathbb E\left[ R_{t+1}+\gamma V^*(S_{t+1}) \mid S_t=s,A_t=a \right]\]

The optimal Bellman equation is:

\[V^*(s) = \max_a \sum_{s'}P(s'\mid s,a) \left[ R(s,a,s')+\gamma V^*(s') \right]\]

Intuition: planning backward from good destinations

Imagine a route planner.

At every junction, it asks:

  1. What does each road cost immediately?

  2. How good is the destination reached by that road?

  3. Which road has the best combined score?

\[Q(s,a) = \text{immediate reward} + \gamma\text{ future value}\]

Then:

\[V(s)=\max_a Q(s,a)\]

Initially, future values may be zero. After repeated backups, information about a distant goal propagates backward through earlier states.

This is value iteration:

\[V_{k+1}(s) = \max_a \sum_{s'}P(s'\mid s,a) \left[ R(s,a,s')+\gamma V_k(s') \right]\]

After convergence, extract a greedy policy:

\[\pi^*(s)=\arg\max_a Q^*(s,a)\]

Value iteration is dynamic programming, not SGD:

  • It does not define a differentiable loss.

  • It does not call backward().

  • It assumes the transition and reward model are known.

  • Its repeated Bellman operation converges toward a fixed point.

Policy iteration versus value iteration

Policy iteration alternates:

  1. Evaluate the current policy.

  2. Make it greedy with respect to its values.

Value iteration performs shortened evaluation and improvement together by applying the max backup repeatedly.

LLM connection

If we had exact \(Q(\text{prefix},\text{token})\), we could select the token with the best expected final outcome.

In practice:

  • the vocabulary is large;

  • possible continuations grow exponentially;

  • rewards may only arrive after the full response;

  • the transition/reward model is not available as a manageable table.

That is why LLM RL uses sampling and learned approximations rather than tabular value iteration.

🔍 Deeper: why value iteration must converge

The Bellman optimality operator \((TV)(s)=\max_a\sum_{s'}P(s'|s,a)[r+\gamma V(s')]\) is a \(\gamma\)-contraction: \[|(TV)(s)-(TU)(s)|\le\max_a\Big|\gamma\sum_{s'}P(s'|s,a)\big(V(s')-U(s')\big)\Big|\le\gamma\|V-U\|_\infty .\] (The step uses \(|\max f-\max g|\le\max|f-g|\).) By Banach’s fixed-point theorem there’s exactly one fixed point \(V^*\), and \(\|V_k-V^*\|\le\gamma^k\|V_0-V^*\|\).

How many sweeps? To shrink the error by \(10^{-3}\) you need \(k\ge\ln(10^{-3})/\ln\gamma\): about 66 sweeps for \(\gamma=0.9\), but about 690 for \(\gamma=0.99\).

Policy improvement theorem: if \(\pi'\) is greedy with respect to \(Q^\pi\), then \(Q^\pi(s,\pi'(s))\ge V^\pi(s)\) for all \(s\), which implies \(V^{\pi'}\ge V^\pi\) everywhere. That’s why policy iteration never gets worse.

🔑 Key ideas

  • Evaluation: “how good is my plan?” Control: “what’s the best plan?”

  • Contraction \(\Rightarrow\) a unique answer and geometric convergence, but a patient \(\gamma\) means slow convergence.

🚶 Walkthrough: value iteration on a 2-cell corridor

Cells \(s_1,s_2\), goal on the right. Moving right from \(s_2\) pays \(+10\) and ends. Every other move pays 0. Moving left from \(s_1\) stays in \(s_1\). \(\gamma=0.9\).

  • Sweep 1: \(V(s_2)=\max(10,\ 0.9\cdot0)=10\), \(V(s_1)=0\) (it still sees old values).

  • Sweep 2: \(V(s_1)=\max(0.9V(s_2),\ 0.9V(s_1))=9\). Converged: \(V=(9,10)\), greedy policy \(=\) right, right.

Value travels one cell per sweep, like a ripple.

Common mistakes

  • Taking \(\max\) over next states instead of over actions.

  • Stopping after a fixed sweep count without checking \(\Delta\).

  • Extracting the policy from a \(V\) that hasn’t converged.

⚙️ Algorithm: Value iteration
Input: transitions \(P\), rewards \(r\), discount \(\gamma\), tolerance \(\theta\)
\(V(s)\gets0\) for every state
repeat
\(\Delta\gets0\)
for each state \(s\) do
\(v\gets V(s)\)
\(V(s)\gets\max_a\sum_{s'}P(s'|s,a)\big[r(s,a,s')+\gamma V(s')\big]\) ▷ max instead of average
\(\Delta\gets\max(\Delta,|v-V(s)|)\)
end
until \(\Delta<\theta\)
\(\pi(s)\gets\arg\max_a\sum_{s'}P(s'|s,a)\big[r(s,a,s')+\gamma V(s')\big]\) for every \(s\)
return \(V\approx V^*\), greedy policy \(\pi\)

4. Checks for understanding

  1. What is the key mathematical difference between a Bellman expectation backup and an optimality backup?

  2. Why can a reward several steps away change the value of the initial state?

  3. Does argmax produce an exploratory policy?

  4. If two actions have equal \(Q\), which one does PyTorch argmax select?

Solutions

values = torch.zeros(3)

for iteration in range(100):
    expected_next_values = transitions @ values
    q_values = rewards + gamma * expected_next_values
    new_values = q_values.max(dim=1).values

    delta = (new_values - values).abs().max()
    values = new_values

    if delta < 1e-6:
        break

q_values = rewards + gamma * (transitions @ values)
optimal_actions = q_values.argmax(dim=1)

For the terminal state, both actions tie at zero. argmax returns the first one, so its reported action has no real significance.

The reward reaches:

  • state 1 during the first backup;

  • state 0 during the second backup.

Using max(dim=0) maximizes across states and returns one value per action. We need to maximize across actions separately for every state.

Check answers

  1. Expectation uses the policy-weighted average; optimality uses the maximum action value.

  2. Each Bellman backup carries estimated future value one step backward.

  3. No. It produces a deterministic greedy choice unless exploration is added separately.

  4. The first maximal index.

  5. Floating-point calculations may approach the fixed point without becoming bit-for-bit identical.

Retrieval answers

  1. \(V^\pi(s)\) is the expected return from state \(s\) when the agent follows policy \(\pi\).

  2. \(V^\pi(s)=\sum_a\pi(a\mid s)Q^\pi(s,a)\).

Takeaway: policy evaluation asks how good the current behavior is; value iteration repeatedly chooses the best-looking action and propagates its consequences backward.
