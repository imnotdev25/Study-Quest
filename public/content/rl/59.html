2. A tool agent has state-dependent legal actions

For a tool-using agent, actions might be:

  • answer the user;

  • call search;

  • query a database;

  • execute code;

  • finish.

Not every action is valid in every state. For example, finish may be invalid before required evidence is collected, or a tool may be unavailable for a particular user.

Let \(M(s,a)\in\{0,1\}\) indicate whether action \(a\) is valid. Mask invalid logits before constructing the policy:

\[\tilde z_a= \begin{cases} z_a,&M(s,a)=1\\ -\infty,&M(s,a)=0 \end{cases}\]

Then:

\[\pi(a\mid s) = \operatorname{softmax}(\tilde z)_a\]

Invalid actions receive exactly zero probability, while valid actions are renormalized.

Masking only the loss is insufficient. If the original policy samples an invalid action, removing its training loss does not undo the invalid environment interaction.

For a sampled valid action:

\[L_\pi = -\log\pi_\theta(a_t\mid s_t) \hat A_t\]

A positive advantage increases its probability; a negative advantage decreases it. Advantages should remain detached.

Practical cautions:

  • every state must have at least one valid action;

  • generation and training must use the identical mask;

  • masking syntax does not guarantee semantic correctness;

  • environment rejection should still be handled explicitly;

  • log invalid probability mass before masking—it reveals what the unconstrained model wanted to do.

Tensor shapes:

  • logits and valid-action mask: [B, A]

  • sampled actions and advantages: [B]

  • selected log-probabilities: [B]

  • policy loss: scalar

DPO can prefer valid tool traces over invalid ones, but it trains on fixed comparisons. Tool-use RL receives fresh observations and rewards from actual interaction.

🔍 Deeper: state-dependent masks

\(\pi_\theta(a|s)=\dfrac{v_a(s)\,e^{z_a(s)}}{\sum_bv_b(s)\,e^{z_b(s)}}\), where \(v(s)\in\{0,1\}^k\) is computed from the state, e.g. from the tool registry and the current context.

  • Store \(v(s)\) with each rollout step. Recomputing it at training time from a changed registry silently changes the policy.

  • Masked logits get exactly zero gradient (Topic 36), so the agent never learns to avoid invalid tools by penalty. It never sees them.

  • Monitor the unmasked probability mass on invalid actions. If it’s high, the network hasn’t learned the structure, and a mask bug would be catastrophic.

🔑 Key ideas

  • Masks belong inside the distribution used for rollout and training.

  • Every state needs a legal fallback, such as “answer” or “stop.”

🚶 Walkthrough: how much mass does the mask remove?

Logits: search \(1\), answer \(0\), summarize \(3\). Summarize is illegal: no document yet. Masked: \(\pi=(0.731,0.269)\). Unmasked, the network would put \(e^3/(e+1+e^3)=84\%\) on the illegal action, so the logits have learned almost nothing about legality.

Common mistakes

  • Recomputing masks at training time.

  • No legal action in some states.

  • Penalizing invalid actions instead of masking them.

Debugging experiments

Mask the loss but construct Categorical from the original logits. Invalid actions remain sampleable even though some loss elements are ignored.

Reverse the mask:

masked_logits = logits.masked_fill(
    valid_mask,
    -torch.inf,
)

The policy now permits precisely the forbidden actions.

Create a row with no valid action. An all-\(-\infty\) softmax is undefined, producing invalid probabilities. Validate masks before sampling and define a safe fallback such as “abort.”

Finally, use different masks during rollout and training. Stored actions may become impossible under the training policy, making log-probabilities and PPO ratios invalid.

4. Checks for understanding

  1. Why must masking happen before sampling?

  2. Does zero probability for an action imply zero gradient for every model parameter?

  3. Why log invalid probability mass before applying the mask?

  4. When is environment rejection still needed?

Solutions

Invalid probability mass:

invalid_mass = (
    unmasked_probs
    * (~valid_mask).to(
        unmasked_probs.dtype
    )
).sum(dim=-1)

Validate the mask:

assert bool(
    valid_mask.any(dim=-1).all()
), "Every state needs a valid action"

Mask logits:

masked_logits = logits.masked_fill(
    ~valid_mask,
    -torch.inf,
)

Policy loss:

selected_log_probs = policy.log_prob(
    actions
)

policy_loss = -(
    selected_log_probs
    * advantages.detach()
).mean()

Diagnostics:

invalid_probability_max = (
    masked_probs[~valid_mask]
    .abs()
    .max()
)

invalid_gradient_max = (
    logits.grad[~valid_mask]
    .abs()
    .max()
)

All invalid actions should have:

\[\pi(a_{\text{invalid}}\mid s)=0\]

and their individual logits should receive zero gradient in this direct categorical parameterization.

The negative-advantage action contributes:

\[-\log\pi(a\mid s)(-1) = \log\pi(a\mid s)\]

Minimizing this decreases its log-probability relative to other valid actions.

In a shared neural network, parameters used by an invalid action’s representation can still change because they are shared with valid states or actions. Zero gradient for one masked logit does not freeze the corresponding model parameters globally.

Check answers

  1. The environment must never receive the invalid action; ignoring its loss after execution is too late.

  2. No. Shared parameters can receive gradients through other valid outputs, states or auxiliary losses.

  3. It measures how strongly the unconstrained policy prefers illegal behavior and can reveal distribution shift or insufficient training.

  4. Masks usually enforce known syntactic constraints. Runtime failures, permissions, stale schemas and semantic preconditions still require environment validation.

Retrieval answers

  1. Training proxy reward rises while independent quality peaks, stalls or falls.

  2. KL constrains movement from a reference policy, but reward errors can still be exploited inside that permitted region.

Takeaway: action masks belong inside the policy distribution used for both rollout and training. Validate that each state has a legal fallback, detach advantages and monitor the probability mass the unconstrained agent assigns to invalid tools.
