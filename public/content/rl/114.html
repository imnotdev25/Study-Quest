2. Centering and scaling do different things

A common PPO preprocessing step is:

\[\tilde A_i = \frac{A_i-\mu_A} {\sigma_A+\epsilon}\]

This combines two operations:

  • dividing by \(\sigma_A\) rescales gradient magnitude;

  • subtracting \(\mu_A\) acts like a batch-estimated baseline and can change individual advantage signs.

Under ideal on-policy expectation, an action-independent baseline does not change the expected policy gradient:

\[E[ \nabla_\theta\log\pi_\theta(a\mid s)b(s) ] =0\]

In a finite batch, however, centering changes the sampled gradient. Its statistics must therefore be calculated from exactly the intended valid population.

For a response mask \(m_{b,t}\):

\[\mu_A = \frac{\sum_{b,t}m_{b,t}A_{b,t}} {\sum_{b,t}m_{b,t}}\]

\[\sigma_A^2 = \frac{ \sum_{b,t}m_{b,t}(A_{b,t}-\mu_A)^2 }{ \sum_{b,t}m_{b,t} }\]

Padding zeros are not neutral observations. Including them changes both the baseline and scale.

Tensor shapes:

  • advantages and response mask: [B, T]

  • valid count, mean and variance: scalars

  • normalized advantages: [B, T]

In distributed PPO, compute global sums, squared sums and counts. Averaging independently whitened worker batches gives different normalization when workers contain different lengths or reward mixtures.

GRPO constructs relative advantages within each prompt group, so zero-variance groups provide no relative learning signal. DPO has no rollout advantages; its \(\beta\) scales preference log-ratio margins and is not equivalent to PPO advantage whitening.

  • Correct variance divides by valid_count.

  • Detach advantages inside the actor objective.

Debugging experiments

  • Normalize zero-padded [B, T] tensors directly.

  • Forget epsilon for a zero-variance GRPO group.

  • Whiten independently on every distributed worker.

  • Recompute normalization from different minibatches during every PPO epoch.

  • Backpropagate through GAE or normalization statistics.

  • Mix reward sources with incompatible scales without monitoring them separately.

  • Normalize rewards and advantages twice, then compensate with a larger learning rate.

Solutions

Masking:

token_positions = torch.arange(
    maximum_length
)[None, :]

response_mask = (
    token_positions
    < lengths[:, None]
)

padded_advantages = torch.where(
    response_mask,
    dense_advantages,
    torch.tensor(float("nan")),
)

safe_advantages = torch.where(
    response_mask,
    padded_advantages,
    torch.zeros_like(
        padded_advantages
    ),
)

Correct statistics:

float_mask = response_mask.to(
    torch.float64
)

valid_count = float_mask.sum()

masked_mean = (
    safe_advantages.sum()
    / valid_count
)

centered_valid_advantages = torch.where(
    response_mask,
    padded_advantages - masked_mean,
    torch.zeros_like(
        padded_advantages
    ),
)

masked_variance = (
    centered_valid_advantages
    .square()
    .sum()
    / valid_count
)

masked_standard_deviation = (
    masked_variance.sqrt()
)

correct_whitened_advantages = (
    centered_valid_advantages
    / (
        masked_standard_deviation
        + epsilon
    )
).detach()

Incorrect padded statistics:

wrong_mean = (
    safe_advantages.mean()
)

wrong_variance = (
    (
        safe_advantages
        - wrong_mean
    )
    .square()
    .mean()
)

wrong_standard_deviation = (
    wrong_variance.sqrt()
)

wrong_whitened_advantages = torch.where(
    response_mask,
    (
        safe_advantages
        - wrong_mean
    )
    / (
        wrong_standard_deviation
        + epsilon
    ),
    torch.zeros_like(
        safe_advantages
    ),
).detach()

Actor gradient:

def actor_gradient(advantages):
    theta = torch.tensor(
        0.0,
        requires_grad=True,
    )

    old_log_probabilities = (
        F.logsigmoid(
            torch.zeros_like(
                safe_features
            )
        )
    )

    new_log_probabilities = (
        F.logsigmoid(
            theta * safe_features
        )
    )

    probability_ratios = torch.exp(
        new_log_probabilities
        - old_log_probabilities
    )

    objective = (
        probability_ratios
        * advantages.detach()
        * float_mask
    ).sum() / valid_count

    loss = -objective
    loss.backward()

    ascent_gradient = (
        -theta.grad.detach()
    )

    return (
        objective.detach(),
        ascent_gradient,
    )

There are ten valid tokens:

\[\mu_{\text{valid}} = \frac{-2-1+8(1)}{10} = 0.5\]

The correct variance is:

\[\sigma_{\text{valid}}^2 = \frac{ (-2.5)^2+(-1.5)^2+8(0.5)^2 }{10} = 1.05\]

so:

\[\sigma_{\text{valid}} \approx1.025\]

Including six padded zeros instead gives:

\[\mu_{\text{wrong}} = \frac5{16} = 0.3125\]

and approximately:

\[\sigma_{\text{wrong}} \approx0.845\]

Consequently, incorrectly whitened valid tokens no longer have mean zero. In this constructed finite batch, correct and padding-contaminated baselines produce actor gradients with opposite signs.

This does not mean whitening generally reverses the true expected policy gradient. It demonstrates that finite-batch normalization is part of the estimator, and corrupting its statistics can materially alter an update.

Check answers

  1. Mean subtraction; standard-deviation division only applies a positive rescaling.

  2. Masking determines which tokens enter the statistics. It does not decide whether long responses or prompts receive equal outer weight.

  3. Aggregate valid count, advantage sum and squared-deviation information—or equivalent numerically stable sufficient statistics.

  4. Usually normalize the collected rollout advantages once and keep them fixed across PPO epochs. Changing statistics per minibatch makes repeated passes optimize shifting targets.

Retrieval answers

  1. Token averaging weights responses by their valid-token counts; prompt averaging gives each response equal outer weight.

  2. No. Clipping bounds probability-ratio effects but does not change which tokens, responses or prompts dominate the reduction.

Takeaway: advantage whitening is not a harmless .mean() and .std(). Freeze detached statistics over the intended valid population, synchronize them across workers and log zero-variance groups before they silently erase or invent policy-gradient signal.
