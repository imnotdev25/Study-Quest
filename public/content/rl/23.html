🧩 Analogy: rehearsing a conversation in your head

Before a tough talk, you rehearse it mentally: “if I say this, they’ll probably say that.” That’s planning inside a learned model of the other person. It’s cheap and can help a lot, but each imagined exchange rests on the previous one, so a small misjudgment early can lead to a wildly wrong imagined ending.

2. Replace trial-and-error with prediction

A model-free agent learns values or a policy directly. A model-based agent also learns how the environment changes:

\[\hat S_{t+1}=f_\phi(S_t,A_t)\]

It may additionally learn rewards:

\[\hat R_{t+1}=r_\psi(S_t,A_t)\]

Think of the model as a flight simulator. The agent can test action sequences cheaply inside the simulator before performing one in the real environment.

Fit the dynamics model from transitions:

\[L_{\text{model}} = \frac1N\sum_i \left\| f_\phi(s_i,a_i)-s'_i \right\|^2\]

Then search for the sequence with maximum predicted return:

\[(a_0^*,\ldots,a_{H-1}^*) = \arg\max_{a_{0:H-1}} \sum_{t=0}^{H-1} \gamma^t\hat R_{t+1}\]

where imagined states are generated recursively:

\[\hat S_{t+1} = f_\phi(\hat S_t,A_t)\]

This reuse is the attraction: one learned model can evaluate many hypothetical trajectories.

The danger: compounding model error

Each predicted state becomes the input for the next prediction. Small errors can accumulate:

\[\hat S_1 \rightarrow \hat S_2 \rightarrow \hat S_3 \rightarrow\cdots\]

The planner may also deliberately find regions where the model is wrong but predicts excellent rewards. This resembles offline Q-learning selecting an erroneously optimistic unseen action.

Common defenses include:

  • short planning horizons;

  • frequent replanning from real observations;

  • model ensembles and uncertainty penalties;

  • collecting data where the model is uncertain;

  • comparing imagined and real rollout outcomes.

Model predictive control plans several steps but executes only the first action. After observing the real next state, it plans again. This prevents yesterday’s prediction error from controlling the entire trajectory.

Tensor shapes for today:

  • model inputs: [N, 2] for scalar state and action;

  • predicted next states: [N, 1];

  • candidate sequences: [plans, horizon];

  • imagined state and return: [plans].

LLM connection

An agentic LLM may predict what a tool call will return and plan around that prediction. But imagined search results, code execution or database responses are not substitutes for actual tool outputs. Replanning after each real tool result is the model-predictive-control pattern.

🔍 Deeper: compounding model error

If the model’s next-state distribution is off by \(\varepsilon\) (in total variation) per step, then after \(H\) steps the imagined state distribution can be off by up to \(H\varepsilon\). The value error then scales, up to constants, like \(\varepsilon\,R_{\max}/(1-\gamma)^2\) (the “simulation lemma”). With deterministic models and sensitive dynamics, errors can grow exponentially:

Why methods like MBPO only imagine short rollouts that branch from real states.

The planner is an adversary: optimizing actions inside \(\hat P\) will find wherever the model is wrong in your favour. Use ensembles and treat their disagreement as uncertainty.

🔑 Key ideas

  • Learn a simulator and plan in it to save real interaction.

  • Short rollouts plus uncertainty penalties keep the planner honest.

🚶 Walkthrough: random shooting

Three candidate plans, scored in the model: \(4.0,6.5,5.1\). Execute the first action of plan 2 only, observe the real result, then replan. If plan 2’s real reward is far below the model’s prediction, add that transition to the data, because that is where the model is wrong.

Common mistakes

  • Executing the whole plan open-loop.

  • Evaluating the model on its own training data only.

  • Using long horizons with a single (non-ensemble) model.

⚙️ Algorithm: Model-based control: learned model + random-shooting MPC
Input: real environment, dataset \(\mathcal D\), horizon \(H\), number of candidate plans \(K\)
loop
fit model \(f_\psi(s,a)\to(\hat s',\hat r)\) on \(\mathcal D\) by supervised regression
for each real step from state \(s\) do
sample \(K\) action sequences \(a^{(k)}_{0:H-1}\)
roll each one out inside \(f_\psi\) from \(s\); score \(\sum_h\gamma^h\hat r_h\)
execute only the first action of the best sequence ▷ replan every step
add the real transition to \(\mathcal D\)
end
end

3. PyTorch exercise — learn dynamics and search action sequences

The environment has scalar dynamics:

\[S_{t+1}=S_t+A_t,\qquad A_t\in\{-1,+1\}\]

The goal is state 2. Reward is the negative squared distance after each transition:

\[R_{t+1}=-(S_{t+1}-2)^2\]

Learn the dynamics, then evaluate all eight three-action plans.

import torch
import torch.nn.functional as F

torch.manual_seed(7)

goal_state = 2.0

The training loss may still become tiny, but predictions for action +1 are underdetermined. Compare:

test = torch.tensor([

This is model-based distribution shift: low one-step training loss does not guarantee reliable planning over novel actions.

Solutions

Construct the training inputs and loss:

model_inputs = torch.stack(
    [train_states, train_actions],
    dim=-1,
)

model_loss = F.mse_loss(
    predictions,
    train_next_states,
)

Predict each next state:

planning_inputs = torch.stack(
    [imagined_states, actions_t],
    dim=-1,
)

imagined_states = model(
    planning_inputs
).squeeze(-1)

Calculate rewards and returns:

predicted_rewards = -(
    imagined_states - goal_state
).pow(2)

predicted_returns = (
    predicted_returns
    + gamma**t * predicted_rewards
)

Select the plan:

best_index = predicted_returns.argmax()
best_sequence = candidate_sequences[best_index]

best_predicted_return = predicted_returns[
    best_index
]

The true dynamics are:

\[S_{t+1}=1\cdot S_t+1\cdot A_t+0\]

so the learned layer should approach:

weight ≈ [[1.0, 1.0]]
bias   ≈ [0.0]

The best sequence is:

[+1, +1, +1]

It produces states:

start: -1
step 1: 0
step 2: 1
step 3: 2

Its true discounted return is:

\[-4 + 0.9(-1) + 0.9^2(0) = -4.9\]

Planning does not require gradients here because all eight discrete sequences are enumerated. Continuous-action planners may optimize actions through a differentiable dynamics model.

The predicted and true return should be extremely close, but finite optimization can leave a small difference.

Check answers

  1. Optimization searches for the highest predicted return, so it preferentially discovers optimistic model mistakes.

  2. Every prediction changes the input to the following prediction, allowing errors to accumulate or move the rollout out of distribution.

  3. Real observations replace accumulated imagined states, limiting how long errors propagate unchecked.

  4. Measure multi-step rollout error and predicted-versus-real return, ideally on held-out states and actions—not only one-step training MSE.

Retrieval answers

  1. Unseen actions receive no direct corrective targets, yet maximization may select their arbitrary estimates.

  2. After genuine termination there is no future trajectory, so the target equals immediate reward.

Takeaway: model-based RL learns a simulator and plans within it. Planning can reduce real interaction, but optimization will exploit the simulator’s inaccuracies unless coverage, uncertainty and rollout error are carefully controlled.
