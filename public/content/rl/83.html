🧩 Analogy: survey weights rescaled every wave

A long panel survey reweights respondents each wave so the weights add up to the population size. Without that, a few extreme weights from early waves snowball. Weighted PDIS does the same: at every timestep it normalizes the cumulative weights to sum to one.

2. Importance-weight scale becomes noisy over long horizons

Per-decision importance sampling estimates:

\[\hat J_{\text{PDIS}} = \frac1N \sum_i\sum_t \gamma^t\rho_{0:t}^{(i)}r_t^{(i)}\]

where:

\[\rho_{0:t} = \prod_{j=0}^{t} \frac{\pi(a_j\mid s_j)} {\mu(a_j\mid s_j)}\]

In expectation, the importance weights average to one. In a finite batch, a few rare trajectories may receive enormous weights while most receive almost zero weight.

Weighted PDIS normalizes weights separately at each timestep:

\[\tilde\rho_{i,t} = \frac{\rho_{0:t}^{(i)}} {\sum_j\rho_{0:t}^{(j)}}\]

\[\hat J_{\text{WPDIS}} = \sum_t\gamma^t \sum_i \tilde\rho_{i,t}r_t^{(i)}\]

This is the sequential version of self-normalized importance sampling:

  • PDIS is unbiased under correct propensities and support assumptions.

  • WPDIS is generally biased at finite \(N\).

  • WPDIS often has much lower variance and can therefore have lower mean-squared error.

  • Both become consistent as the sample size grows under suitable conditions.

Normalize each timestep independently because \(\rho_{0:1}\) and \(\rho_{0:10}\) have very different distributions.

For numerical stability, normalize in log-space:

\[\log\tilde\rho_{i,t} = \log\rho_{i,t} - \operatorname{logsumexp}_j \log\rho_{j,t}\]

Effective sample size at timestep \(t\) is:

\[N_{\text{eff},t} = \frac{1} {\sum_i\tilde\rho_{i,t}^2}\]

An ESS of 4 means the weighted estimate contains roughly as much information as four evenly weighted episodes—even if the batch contains hundreds.

Tensor shapes:

  • actions, rewards and step log-ratios: [R, B, T]

  • normalized weights: [R, B, T]

  • ESS: [R, T]

  • repeated value estimates: [R]

For variable-length agent traces, include only active episodes in each denominator. Padded rows with artificial weight one will corrupt normalization.

DPO does not use environmental importance weights or estimate online return. A DPO-trained checkpoint can be evaluated as a target policy, but WPDIS remains an off-policy evaluation method, not a preference-training objective.

🔍 Deeper: WPDIS

\[\hat V_{\text{WPDIS}}=\sum_t\gamma^t\,\frac{\sum_i\rho^{(i)}_{0:t}r^{(i)}_{t+1}}{\sum_i\rho^{(i)}_{0:t}} .\] Each timestep’s term is a weighted average of observed rewards, so it stays inside the reward range. It’s biased for finite \(n\) (it equals \(b\)’s average at \(n=1\)) but consistent, and usually much lower variance. It cannot repair missing coverage. If no trajectory resembles \(\pi\), the normalized average describes whatever was logged.

🔑 Key ideas

  • WPDIS trades a small bias for much lower variance.

  • It stabilizes weak coverage, but can’t create coverage.

🚶 Walkthrough: PDIS can leave the reward range

Two trajectories, one step, rewards in \([0,1]\). Weights \((3,0.2)\), rewards \((1,0)\). PDIS \(=\frac{3+0}{2}=1.5\) (impossible). WPDIS \(=\frac{3}{3.2}=0.94\).

Common mistakes

  • Normalizing over the whole trajectory instead of per timestep.

  • Dividing by \(n\) at some steps and by \(\sum\rho\) at others.

  • Using WPDIS to claim value for actions the logs never took.

3. PyTorch exercise — lower variance by normalizing each timestep

Hints

  • Reward is simply actions.to(torch.float64).

  • Use gamma ** torch.arange(time_steps).

  • Selected action probability is \(p\) for action 1 and \(1-p\) for action 0.

  • Use torch.cumsum(..., dim=-1) for prefix log-ratios.

  • PDIS averages weighted discounted rewards across episodes.

  • Subtract torch.logsumexp(..., dim=1, keepdim=True) before exponentiating.

  • With normalized weights, ESS is 1 / sum(weight**2) across episodes.

Debugging experiments

  • Normalize over both episodes and timesteps. Later rewards then compete with earlier rewards for total weight.

  • Normalize raw exponentiated weights after increasing the horizon to 100. Overflow may occur before normalization.

  • Treat padded steps as real episodes with log-weight zero. They enter the denominator with weight one.

  • Increase the target probability to 0.95. Observe weight concentration and faster ESS collapse.

  • Clip prefix ratios before PDIS. Variance falls, but clipping introduces another source of bias.

  • Recompute behavior probabilities from current policy weights. The denominator must remain the detached rollout-policy probability.

Solutions

Rewards and discounts:

rewards = actions.to(
    torch.float64
)

discounts = (
    gamma
    ** torch.arange(
        time_steps,
        dtype=torch.float64,
    )
)

discounted_rewards = (
    rewards
    * discounts[None, None, :]
)

Importance ratios:

behavior_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        behavior_one_probability
    ),
    torch.tensor(
        1.0 - behavior_one_probability
    ),
)

target_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        target_one_probability
    ),
    torch.tensor(
        1.0 - target_one_probability
    ),
)

step_log_ratios = (
    target_action_probabilities.log()
    - behavior_action_probabilities.log()
)

prefix_log_ratios = torch.cumsum(
    step_log_ratios,
    dim=-1,
)

prefix_ratios = (
    prefix_log_ratios.exp()
)

Naive and PDIS estimates:

naive_estimates = (
    discounted_rewards
    .sum(dim=-1)
    .mean(dim=1)
)

pdis_estimates = (
    prefix_ratios
    * discounted_rewards
).sum(dim=-1).mean(dim=1)

Stable weighted PDIS:

normalized_log_weights = (
    prefix_log_ratios
    - torch.logsumexp(
        prefix_log_ratios,
        dim=1,
        keepdim=True,
    )
)

normalized_weights = (
    normalized_log_weights.exp()
)

weighted_pdis_estimates = (
    normalized_weights
    * discounted_rewards
).sum(dim=(1, 2))

Diagnostics:

effective_sample_sizes = (
    1.0
    / normalized_weights
    .square()
    .sum(dim=1)
)

mean_ess_by_time = (
    effective_sample_sizes.mean(dim=0)
)

ess_fraction_by_time = (
    mean_ess_by_time / batch_size
)

exact_target_value = (
    torch.tensor(
        target_one_probability
    )
    * discounts.sum()
)

means = all_estimates.mean(dim=0)

biases = (
    means - exact_target_value
)

standard_deviations = (
    all_estimates.std(
        dim=0,
        correction=1,
    )
)

rmses = (
    (
        all_estimates
        - exact_target_value
    )
    .square()
    .mean(dim=0)
    .sqrt()
)

normalization_error = (
    normalized_weights.sum(dim=1)
    - 1.0
).abs().max()

maximum_prefix_weights = (
    prefix_ratios
    .reshape(-1, time_steps)
    .max(dim=0)
    .values
)

The exact target return is:

\[J(\pi) = 0.75 \sum_{t=0}^{4}0.9^t\]

\[J(\pi) = 0.75(4.0951) = 3.071325\]

The naive behavior value is only:

\[0.25(4.0951)=1.023775\]

For one decision, the importance ratio is either:

\[\frac{0.75}{0.25}=3\]

or:

\[\frac{0.25}{0.75}=\frac13\]

Therefore, maximum prefix weights grow as:

\[[3,\;9,\;27,\;81,\;243]\]

The approximate ESS fraction falls geometrically:

\[\frac{N_{\text{eff},t}}{N} \approx \left(\frac37\right)^{t+1}\]

By the final step, 256 logged episodes may have an ESS of only about four. WPDIS limits the effect of random total-weight fluctuations, but cannot create information absent from the logs.

Check answers

  1. It divides two random quantities—the weighted reward sum and weight sum—so their ratio is not generally unbiased.

  2. Every prefix length has a different importance-weight distribution and represents a different reward expectation.

  3. No. If the behavior policy never sampled a target-supported action, normalization has no evidence to reweight.

  4. Log ESS by position, maximum and quantile prefix weights, normalization error, support violations, estimator variance, horizon, masks, reward scale and PDIS-versus-WPDIS sensitivity.

Retrieval answers

  1. Pairing retains the covariance caused by shared episode difficulty, often producing a much tighter estimate of policy improvement.

  2. The apparent gain may be sampling noise or OPE bias; deployment should require an appropriate lower confidence bound to clear the chosen margin.

Takeaway: WPDIS exchanges finite-sample bias for lower variance by making importance weights sum to one at each step. It stabilizes weak-but-usable coverage; it cannot repair missing coverage.
