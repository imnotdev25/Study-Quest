🧩 Analogy: learning which ingredient ruined the dish

You only ever hear “good meal” or “bad meal,” never which ingredient was wrong. But after many meals you notice that every bad one had the same spice. You’ve learned a per-ingredient score from per-meal verdicts. PRIME trains a model that gives every token a reward, using only right/wrong labels for whole answers.

2. The idea (Cui et al., 2025, PRIME)

Parameterize the reward as a log-ratio, like DPO’s implicit reward: \[r_\phi(y_t)=\beta\log\frac{\pi_\phi(y_t|y_{<t})}{\pi_{\text{ref}}(y_t|y_{<t})},\qquad r_\phi(y)=\sum_tr_\phi(y_t).\] Train \(\pi_\phi\) as an outcome reward model with cross-entropy on whether the full answer was correct: \(\mathcal L=\operatorname{BCE}\big(\sigma(r_\phi(y)),\ \text{correct}(y)\big)\). Because the sequence score is a sum of token terms, the per-token \(r_\phi(y_t)\) becomes a process reward for free. Online: the PRM is updated during RL on fresh policy rollouts with their outcome labels, so it keeps up with the policy, which makes it harder to hack than a frozen PRM. Process and outcome rewards are then combined in the advantage (the paper uses RLOO-style estimates).

🔑 Key ideas

  • A log-ratio reward model trained on outcome labels yields dense per-token rewards.

  • Update it online, so it isn’t a fixed target to exploit.

🚶 Walkthrough: reading the learned rewards

In this topic’s toy, an answer is correct iff it never contains token 3. After training on outcome labels only, the per-token rewards are about \((+0.28,+0.34,+0.24,-5.66)\): the model has found the “bad step” with no step labels.

Common mistakes

  • Freezing the implicit PRM (the policy learns to exploit it).

  • Training the PRM on the same responses you then score (leakage).

  • Adding process rewards so strongly that they outweigh the verified outcome.

Solutions

import torch
import torch.nn.functional as F

torch.manual_seed(0)
V, T, N = 4, 3, 512          # vocab, length, number of sequences; token 3 is the "bad step"
seqs = torch.randint(0, V, (N, T))
label = (seqs != 3).all(1).float()               # outcome only: correct iff no bad token

phi = torch.zeros(V, requires_grad=True)         # implicit PRM (context-free for the toy)
ref_logp = torch.full((V,), -torch.log(torch.tensor(float(V))))   # uniform reference
beta = 1.0
opt = torch.optim.Adam([phi], lr=0.05)
for _ in range(300):
    token_reward = beta * (phi.log_softmax(-1) - ref_logp)        # r_t = beta log pi_phi / pi_ref
    seq_score = token_reward[seqs].sum(1)                         # outcome = sum of process rewards
    loss = F.binary_cross_entropy_with_logits(seq_score, label)   # trained on outcome labels only
    opt.zero_grad()
    loss.backward()
    opt.step()

with torch.no_grad():
    r = beta * (phi.log_softmax(-1) - ref_logp)
print("per-token implicit rewards:", [round(x, 2) for x in r.tolist()])

Output:

per-token implicit rewards: [0.28, 0.34, 0.24, -5.66]

Check answers

  1. The only way to fit the outcome labels is to assign blame to the tokens that predict failure, so the per-token terms carry that blame.

  2. A fixed reward model is a fixed target the policy can hack (Topic 33). Updating it on the policy’s own new outputs keeps it calibrated where the policy actually is.

Retrieval answers: (1) Each intermediate step. (2) \(\beta\log\frac{\pi_\theta}{\pi_{\text{ref}}}\).

Takeaway: dense credit doesn’t require dense labels. Shape the reward model so outcome training produces step-level scores.
