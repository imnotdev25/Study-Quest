2. Value clipping limits how quickly the critic may change

PPO’s policy-ratio clipping and value clipping are separate mechanisms.

Save the critic prediction made during rollout collection:

\[V_{\text{old}}(s_t)\]

During PPO optimization, compute:

\[V_{\text{clip}} = V_{\text{old}} + \operatorname{clip} \left( V_{\text{new}}-V_{\text{old}}, -\epsilon_v,\epsilon_v \right)\]

A common value loss is:

\[L_V = \frac12 \mathbb E_{\text{valid}} \left[ \max \left( (V_{\text{new}}-\hat R)^2, (V_{\text{clip}}-\hat R)^2 \right) \right]\]

The maximum prevents the optimizer from claiming a large improvement by moving far outside the permitted interval.

Suppose:

\[V_{\text{old}}=0,\qquad \hat R=10,\qquad \epsilon_v=1\]

At \(V_{\text{new}}=2\):

\[(V_{\text{new}}-\hat R)^2=64\]

but:

\[V_{\text{clip}}=1,\qquad (V_{\text{clip}}-\hat R)^2=81\]

The clipped branch wins. Because clamp is flat beyond 1, that sample supplies zero value gradient. The critic can therefore stall for the remainder of the PPO epochs. A later rollout refreshes \(V_{\text{old}}\), permitting another step.

This brake can stabilize critic updates, but it is scale-dependent: an \(\epsilon_v=1\) clip is large for returns near 1 and extremely restrictive for returns near 100.

Tensor shapes:

  • new values, old values, returns, response mask: [B, T]

  • per-token value losses: [B, T]

  • masked value loss: scalar

Detach both old values and return targets. Sanitize padding before arithmetic because NaN * 0 remains NaN.

Useful diagnostics include value loss, value clip fraction, prediction bias, and:

\[\text{explained variance} = 1- \frac{\operatorname{Var}(\hat R-V)} {\operatorname{Var}(\hat R)}\]

Values near 1 are good, 0 resembles predicting the mean, and negative values indicate predictions worse than that baseline. It is unstable when return variance is nearly zero.

DPO has no critic, bootstrapped return, GAE, or value clipping. It directly optimizes preference margins from fixed pairs.

Critic optimization:

def train_critic(
    use_value_clipping,
    refresh_old_each_step=False,
):
    value = torch.tensor(
        0.0,
        requires_grad=True,
    )

    saved_old_value = torch.tensor(0.0)

    history = [
        value.detach().clone()
    ]

    for _ in range(num_epochs):
        ordinary_loss = (
            0.5
            * (value - target_return).square()
        )

        if use_value_clipping:
            clipped_value = (
                saved_old_value
                + torch.clamp(
                    value - saved_old_value,
                    -clip_range,
                    clip_range,
                )
            )

            clipped_loss = (
                0.5
                * (
                    clipped_value
                    - target_return
                ).square()
            )

            loss = torch.maximum(
                ordinary_loss,
                clipped_loss,
            )
        else:
            loss = ordinary_loss

        loss.backward()

        with torch.no_grad():
            value -= (
                learning_rate
                * value.grad
            )

            value.grad.zero_()

            if refresh_old_each_step:
                saved_old_value = (
                    value.detach().clone()
                )

        history.append(
            value.detach().clone()
        )

    return torch.stack(history)


unclipped_history = train_critic(
    use_value_clipping=False,
)

fixed_old_clipped_history = train_critic(
    use_value_clipping=True,
)

fresh_rollout_history = train_critic(
    use_value_clipping=True,
    refresh_old_each_step=True,
)

    (
        (
            safe_new_values

The unclipped critic approaches 10 geometrically:

\[0,\;2,\;3.6,\;4.88,\ldots\]

The fixed-old clipped critic moves from 0 to 2, then stalls. Once its prediction exceeds the allowed interval, the clipped error is larger and locally flat.

Refreshing the snapshot after every update produces the same sequence as the unclipped example. In real PPO, however, the snapshot should refresh only after collecting a new rollout—not between minibatches from one rollout.

The relative clip sizes are:

\[[1,\;0.1,\;0.01]\]

Thus the same absolute clip becomes one hundred times more restrictive relative to a return gap that grew from 1 to 100.

The masked example has finite loss, zero padding gradients, and a valid-token clip fraction of:

\[\frac13\]

Check answers

  1. It prevents a large prediction change from being counted as an improvement, while the ordinary branch still penalizes changes that make the prediction worse.

  2. No. It can stabilize an overactive critic, but it can also slow or freeze correction of a badly initialized or newly rescaled critic.

  3. The clip is measured directly in value units; changing reward magnitude changes its relative size.

  4. The critic predicts returns worse than a constant mean predictor on that sample.

  5. DPO has no learned value function or bootstrapped return target; it optimizes preference log-probability margins directly.

Retrieval answers

  1. A blind critic gives similar next-state values after good and bad actions, so early TD residuals contain little action information. Low \(\lambda\) prevents distant terminal evidence from reaching that decision.

  2. The advantage is a fixed policy-gradient weight. Detaching it prevents the actor loss from changing the critic or differentiating through the return estimator.

Takeaway: value clipping limits critic movement relative to rollout-time predictions, not relative to truth. Track its clip fraction and reward scale—a safety rail that is too narrow can leave the actor learning from a critic that is known to be wrong.
