2. Combine prediction with observed residuals

Suppose context \(x\) might be a prompt, action \(a\) a completion, and \(R\) the trusted outcome.

Define the conditional action value:

\[q(x,a) = \underbrace{ E[R\mid x,a] }_{\text{expected trusted outcome for this prompt and action}}\]

The direct method uses a learned approximation \(\hat q\):

\[\hat V_{\mathrm{DM}} = \underbrace{ \frac1n \sum_{i=1}^{n} \sum_a \pi(a\mid x_i)\hat q(x_i,a) }_{\text{predict every target-policy action's outcome}}\]

It can have low variance but is biased when \(\hat q\) is wrong.

Importance sampling instead uses observed rewards:

\[\hat V_{\mathrm{IPS}} = \frac1n\sum_i \underbrace{ \frac{\pi(a_i\mid x_i)} {\mu(a_i\mid x_i)} }_{\text{target-to-behavior probability ratio}} R_i\]

It is unbiased with correct propensities and support, but can have high variance.

The doubly robust estimator combines both:

\[\hat V_{\mathrm{DR}} = \frac1n\sum_i \left[ \underbrace{ \sum_a\pi(a\mid x_i)\hat q(x_i,a) }_{\text{reward-model baseline}} + \underbrace{ \frac{\pi(a_i\mid x_i)} {\mu(a_i\mid x_i)} \left( R_i-\hat q(x_i,a_i) \right) }_{\text{importance-weighted correction of observed residual}} \right]\]

It is consistent if either:

  • the behavior propensity \(\mu(a\mid x)\) is correct; or

  • the outcome model \(\hat q(x,a)\) is correct.

If both are wrong, the guarantee disappears. Weight clipping also generally breaks exact double robustness.

Think of \(\hat q\) as a map and the residual correction as checking the map against landmarks actually encountered. Either an accurate map or accurate knowledge of how the landmarks were sampled can rescue the estimate.

Tensor shapes:

  • contexts, actions and rewards: [R, N]

  • policy and value tables: [S, A]

  • gathered propensities and weights: [R, N]

  • repeated value estimates: [R]

For LLMs, exact sequence propensities may be unstable. DR can reduce variance when the outcome model explains much of the reward, but it cannot repair missing support.

DPO trains from offline preferences; it does not directly estimate deployment outcomes. A DPO policy can be the target policy \(\pi\) in DR evaluation, but the outcome model and logged behavior propensities remain separate requirements.

Solutions

Exact target value:

exact_target_value = (
    context_probabilities[:, None]
    * target_policy
    * true_action_values
).sum()

This gives:

\[V^\pi = \underbrace{ 0.5(0.1\cdot0.2+0.9\cdot0.8) }_{\text{context 0 contribution}} + \underbrace{ 0.5(0.9\cdot0.6+0.1\cdot0.4) }_{\text{context 1 contribution}} = 0.66\]

Logged data:

contexts = torch.multinomial(
    context_probabilities,
    num_samples=(
        num_repetitions
        * episodes_per_repetition
    ),
    replacement=True,
).reshape(
    num_repetitions,
    episodes_per_repetition,
)

behavior_action_one_probabilities = (
    behavior_policy[
        contexts,
        1,
    ]
)

actions = (
    torch.rand(
        num_repetitions,
        episodes_per_repetition,
    )
    < behavior_action_one_probabilities
).to(torch.long)

reward_probabilities = (
    true_action_values[
        contexts,
        actions,
    ]
)

rewards = (
    torch.rand(
        num_repetitions,
        episodes_per_repetition,
    )
    < reward_probabilities
).to(torch.float64)

Probabilities and weights:

target_propensities = target_policy[
    contexts,
    actions,
]

behavior_propensities = behavior_policy[
    contexts,
    actions,
]

wrong_behavior_propensities = (
    misspecified_behavior_policy[
        contexts,
        actions,
    ]
)

correct_importance_weights = (
    target_propensities
    / behavior_propensities
)

wrong_importance_weights = (
    target_propensities
    / wrong_behavior_propensities
)

Estimators:

def direct_method(action_value_model):
    target_action_values = (
        target_policy[contexts]
        * action_value_model[contexts]
    ).sum(dim=-1)

    return target_action_values.mean(
        dim=1
    )


def importance_sampling(weights):
    return (
        weights * rewards
    ).mean(dim=1)


def doubly_robust(
    action_value_model,
    weights,
):
    model_baseline = (
        target_policy[contexts]
        * action_value_model[contexts]
    ).sum(dim=-1)

    logged_action_predictions = (
        action_value_model[
            contexts,
            actions,
        ]
    )

    residual_correction = (
        weights
        * (
            rewards
            - logged_action_predictions
        )
    )

    return (
        model_baseline
        + residual_correction
    ).mean(dim=1)

Why the two routes work:

  • If \(\hat q=q\), then:

\[E[ R-\hat q(x,a) \mid x,a ] = \underbrace{0}_{\text{residual correction has zero mean}}\]

even when the propensity model is wrong.

  • If \(\mu\) is correct, importance weighting makes the residual correction exactly compensate for errors in \(\hat q\).

When both components are wrong, neither mechanism repairs the other.

Check answers

  1. It replaces noisy outcomes with predictions; stable but systematically incorrect predictions create persistent bias.

  2. Rare behavior-policy actions can receive very large target-to-behavior ratios.

  3. Either the outcome model is correct or the behavior propensities are correct, with adequate support.

  4. Clipping changes the importance ratios, so the correction no longer exactly represents the target policy.

  5. No. Weak support, long-horizon ratios, model misspecification and high-stakes decisions still favor fresh on-policy confirmation.

Retrieval answers

  1. The new policy changes the frequency of regions where reward-model error may differ; old traffic weights the wrong mixture.

  2. Clipping reduces variance and raises ESS by biasing the estimate back toward the behavior distribution.

Takeaway: doubly robust does not mean “robust to everything.” It means one of two components may be wrong—not both—and neither route can recover outcomes absent from the logs.
