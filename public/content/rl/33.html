🧩 Analogy: a hospital’s average improves

A hospital reports better average recovery rates. Great news, until you find the children’s ward got worse and the average only rose because more easy adult cases came in. Statisticians call related effects Simpson’s paradox. An RL-trained model can win overall while quietly breaking one capability.

A hypothetical eval: the headline \(+2.1\) hides a \(-8\) safety regression.

2. Training reward is not evaluation

An RL run directly optimizes training reward:

\[\max_\theta\; \mathbb E[R_{\text{train}}(x,y)]\]

Therefore, increasing \(R_{\text{train}}\) mainly confirms that the optimizer found behaviour rewarded by that signal.

Evaluation should use independent measurements:

\[M_1(x,y),M_2(x,y),\ldots,M_k(x,y)\]

For an LLM, these might measure:

  • task success;

  • factual accuracy;

  • safety or false-acceptance rate;

  • calibration;

  • tool execution success;

  • response length and latency;

  • KL from the reference policy;

  • reward–evaluation correlation.

Paired policy comparison

Evaluate the baseline and RL policy on the same prompts. For prompt \(i\):

\[d_i=M_i^{\text{RL}}-M_i^{\text{base}}\]

The estimated improvement is:

\[\bar d=\frac1N\sum_i d_i\]

with standard error:

\[\operatorname{SE}(\bar d) = \frac{s_d}{\sqrt N}\]

A rough 95% confidence interval is:

\[\bar d\pm1.96\operatorname{SE}(\bar d)\]

Pairing removes some variation caused by evaluating different prompt sets.

Aggregate versus slice metrics

Suppose routine prompts are 60% of the benchmark and safety prompts are only 10%. A large routine improvement can hide a severe safety regression.

Always compare:

  • micro average: every example has equal weight;

  • macro average: every category has equal weight;

  • worst-category performance;

  • category-level deltas.

Also keep generation settings fixed: temperature, decoding method, maximum tokens, tool budget and number of samples.

For \(P\) policies, \(C\) categories and \(N\) prompts:

  • success outcomes: [P, N]

  • category IDs: [N]

  • category scores: [P, C]

  • paired differences: [N]

The same evaluation requirements apply to PPO, GRPO and DPO. The training method does not validate its own outcome.

🔍 Deeper: paired comparisons and slices

Evaluate both models on the same prompts and work with the differences \(d_i=s^{\text{new}}_i-s^{\text{old}}_i\): \(\bar d\pm1.96\,\dfrac{\operatorname{sd}(d)}{\sqrt n}\). Pairing removes prompt difficulty from the noise, which gives much tighter intervals than comparing two independent averages.

The aggregate is a weighted sum: \(\Delta_{\text{all}}=\sum_kw_k\Delta_k\). A big regression in a slice with small weight \(w_k\) barely moves the total. Set a minimum bar for every critical slice, not just for the total.

🔑 Key ideas

  • Training reward is not evaluation. Use independent metrics on matched settings.

  • Check paired differences, confidence intervals and every critical slice.

🚶 Walkthrough: a paired CI on five prompts

Differences \(d=(0.10,-0.05,0.20,0.00,0.15)\). Mean \(0.08\), sd \(0.104\), SE \(0.046\). 95% CI \(\approx0.08\pm1.96(0.046)=[-0.011,0.171]\). It includes 0, so this isn’t evidence yet.

Common mistakes

  • Comparing models on different prompt samples.

  • Selecting the checkpoint and reporting its score on the same set.

  • Reporting only the aggregate, with no slices.

Debugging experiment

Report only:

print(micro_scores)

The RL run now looks unambiguously successful because routine prompts dominate the dataset.

Then accidentally reverse the paired difference:

paired_differences = outcomes[0] - outcomes[1]

Every reported improvement changes sign. This is a simple but consequential evaluation-pipeline bug; keep policy ordering explicit in metric names.

Solutions

Category IDs:

category_ids = torch.arange(
    num_categories
).repeat_interleave(category_counts)

Micro scores:

micro_scores = outcomes.mean(dim=1)

Category scores:

category_scores = torch.stack([
    outcomes[
        :, category_ids == category
    ].mean(dim=1)
    for category in range(num_categories)
], dim=1)

Macro scores and deltas:

macro_scores = category_scores.mean(dim=1)

category_deltas = (
    category_scores[1]
    - category_scores[0]
)

Paired comparison:

paired_differences = (
    outcomes[1] - outcomes[0]
)

mean_delta = paired_differences.mean()

standard_error = (
    paired_differences.std(unbiased=False)
    / num_prompts**0.5
)

ci_low = mean_delta - 1.96 * standard_error
ci_high = mean_delta + 1.96 * standard_error

Before sampling noise, the expected micro scores are approximately:

\[M_{\text{base}} = 0.6(0.65)+0.2(0.55)+0.1(0.75)+0.1(0.60) = 0.635\]

\[M_{\text{RL}} = 0.6(0.82)+0.2(0.72)+0.1(0.40)+0.1(0.62) = 0.738\]

So the aggregate improvement is about:

\[0.738-0.635=0.103\]

But safety changes by:

\[0.40-0.75=-0.35\]

The expected macro scores are:

\[M_{\text{base,macro}} = \frac{0.65+0.55+0.75+0.60}{4} = 0.6375\]

\[M_{\text{RL,macro}} = \frac{0.82+0.72+0.40+0.62}{4} = 0.64\]

The macro improvement is nearly zero because categories receive equal weight. The micro score looked much better because routine prompts dominated the benchmark.

Check answers

  1. Otherwise, the “evaluation” may reproduce the same blind spots or exploitable correlations used during training.

  2. When rare categories matter independently of their dataset frequency, especially safety or robustness slices.

  3. More samples, tokens or tool calls can increase success independently of model quality.

  4. Inspect high-reward outputs, reward–metric correlations, prompt slices, decoding settings and possible evaluator exploitation.

Retrieval answers

  1. Training reward rises while an independent measure of intended utility falls.

  2. If all responses receive identical rewards, subtracting the group mean gives every response zero advantage.

Takeaway: a statistically significant aggregate win can coexist with a severe capability regression. Evaluate RL-trained models using independent metrics, matched settings, paired prompts and explicit slices—not training reward alone.
