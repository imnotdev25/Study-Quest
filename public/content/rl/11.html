2. The moving-target problem

Suppose a student writes an answer while the answer key is being rewritten after every sentence. Even if gradients do not flow into the key, the destination keeps moving.

Using one network for both sides creates this target:

\[Y_t= R_{t+1} +\gamma(1-D_t) \max_{a'}Q_\theta(S_{t+1},a')\]

An SGD update changes \(Q_\theta(S_t,A_t)\), but also changes the network used to calculate future targets.

DQN maintains two networks:

  • Online network \(Q_\theta\): trained every optimizer step.

  • Target network \(Q_{\bar\theta}\): held fixed temporarily.

The target becomes:

\[Y_t= R_{t+1} +\gamma(1-D_t) \max_{a'}Q_{\bar\theta}(S_{t+1},a')\]

The loss is:

\[L(\theta)= \frac1B\sum_i \operatorname{Huber} \left( Q_\theta(S_i,A_i)-Y_i \right)\]

Notice the separation:

  • gradients update \(\theta\);

  • no gradients update \(\bar\theta\);

  • periodically, \(\theta\) is copied into \(\bar\theta\).

Hard and soft updates

A hard update every \(C\) steps is:

\[\bar\theta\leftarrow\theta\]

A soft update makes a small change every step:

\[\bar\theta \leftarrow (1-\tau)\bar\theta+\tau\theta\]

For example, \(\tau=0.005\) moves the target network 0.5% toward the online network.

There is a trade-off:

  • update too frequently: targets move rapidly;

  • update too slowly: targets become stale.

What now makes this DQN?

The core recipe is:

  1. neural Q-function;

  2. replay buffer;

  3. detached bootstrapped targets;

  4. separate target network;

  5. exploratory behaviour policy.

Together, these form the basic DQN training structure.

LLM connection

Target networks are common in value-based deep RL, but they are not the same thing as the frozen reference model used in RLHF. A DQN target network supplies bootstrapped value targets; an RLHF reference model usually constrains policy drift through a KL penalty.

🔍 Deeper: hard copies, Polyak averaging, and the full loss

Hard update: \(\theta^-\leftarrow\theta\) every \(C\) steps. Soft (Polyak) update: \(\theta^-\leftarrow\tau\theta+(1-\tau)\theta^-\) every step. The target lags by roughly \(1/\tau\) steps, so \(\tau=0.005\) is about a 200-step lag.

Stylized picture: a hard target jumps in steps, while a Polyak target follows smoothly with a lag.

DQN loss: \(\mathcal L=\mathbb E_{\mathcal D}\big[\ell_{\text{Huber}}\big(y-Q_\theta(s,a)\big)\big]\). The \((1-d)\) factor zeroes the bootstrap at true terminal states, and Huber loss limits the gradient size on big TD errors.

🔑 Key ideas

  • Replay stabilizes the inputs, and the target network stabilizes the labels.

  • Copying rarely makes learning stable but slow. Copying often makes it fast but wobbly.

🚶 Walkthrough: three targets for one transition

\(r=1\), \(\gamma=0.9\). Target net at \(s'\): \((2.0,2.8,1.9)\). Online net at \(s'\): \((1.0,0.5,3.0)\).

  • DQN: \(1+0.9\cdot2.8=3.52\).

  • Double DQN (online picks \(a_3\), target scores it): \(1+0.9\cdot1.9=2.71\).

  • If \(d=1\): target \(=1\), whatever the networks say.

Common mistakes

  • Computing targets with the online network (no stabilization).

  • Forgetting torch.no_grad() around the target computation.

  • Copying \(\theta^-\gets\theta\) every step, which removes the point of having a target.

⚙️ Algorithm: Deep Q-Network (DQN)
Input: network \(Q_\theta\), copy period \(C\), replay buffer \(\mathcal D\), \(\epsilon\) schedule
\(\theta^-\gets\theta\) ▷ target network
for \(t=1,2,\dots\) do
act \(\epsilon_t\)-greedily with \(Q_\theta\); store \((s,a,r,s',d)\) in \(\mathcal D\)
sample a minibatch from \(\mathcal D\)
\(y_j\gets r_j+\gamma(1-d_j)\max_{a'}Q_{\theta^-}(s'_j,a')\) ▷ labels from the frozen network
\(\theta\gets\theta-\eta\nabla_\theta\frac1B\sum_j\operatorname{Huber}\big(y_j-Q_\theta(s_j,a_j)\big)\)
if \(t\bmod C=0\) then \(\theta^-\gets\theta\) ▷ or Polyak: \(\theta^-\gets\tau\theta+(1-\tau)\theta^-\)
end
end

3. PyTorch exercise — train with a frozen target network

This replay dataset contains every possible nonterminal transition in a four-state line world:

import copy
import random

import torch
from torch import nn

random.seed(7)
torch.manual_seed(7)

num_states = 4
num_actions = 2
gamma = 0.95
batch_size = 16
target_update_every = 20

# (state, action, reward, next_state, done)
replay = [
    (0, 0, -0.01, 0, False),
    (0, 1, -0.01, 1, False),
    (1, 0, -0.01, 0, False),
    (1, 1, -0.01, 2, False),
    (2, 0, -0.01, 1, False),
    (2, 1,  1.00, 3, True),

    return torch.tensor(
        states, dtype=torch.float32
    ).unsqueeze(1) / (num_states - 1)

    nn.ReLU(),
    nn.Linear(32, num_actions),

4. Checks for understanding

  1. How is detaching a target different from using a target network?

  2. Why should the optimizer receive only online-network parameters?

  3. What happens if the target network is never synchronized?

  4. Does a low training loss alone prove that the greedy policy is good?

Solutions

target_net = copy.deepcopy(online_net)
target_net.requires_grad_(False)

Inside the training loop:

predictions = online_net(states).gather(
    dim=1,
    index=actions,
)

with torch.no_grad():
    best_next_q = (
        target_net(next_states)
        .max(dim=1, keepdim=True)
        .values
    )

    targets = (
        rewards
        + gamma * (1.0 - dones) * best_next_q
    )

Measure drift and synchronize:

drift = max(
    (online_param - target_param).abs().max().item()
    for online_param, target_param
    in zip(online_net.parameters(), target_net.parameters())
)

drifts_before_sync.append(drift)

target_net.load_state_dict(
    online_net.state_dict()
)

The expected greedy actions are:

state 0: right
state 1: right
state 2: right

Parameter drift should normally be positive immediately before synchronization because the online network has received optimizer updates while the target network remained fixed. Immediately after copying, corresponding parameters should match.

You can verify this with:

post_sync_drift = max(
    (p - tp).abs().max().item()
    for p, tp in zip(
        online_net.parameters(),
        target_net.parameters(),
    )
)

assert post_sync_drift == 0.0

Check answers

  1. Detaching blocks gradients through one target calculation; a target network also keeps the numerical target function unchanged across multiple updates.

  2. Only the online network minimizes the loss. Target parameters are updated by copying, not gradient descent.

  3. Its targets eventually become severely outdated, preventing newer value information from propagating properly.

  4. No. The network may fit biased targets or an unrepresentative replay distribution; evaluate episode return and greedy behaviour too.

Retrieval answers

  1. Replay reduces sequential sample correlation and improves sample efficiency by reusing transitions.

  2. Detachment blocks gradients but does not freeze the online network’s parameters between optimizer steps.

Takeaway: replay stabilizes the data; the target network stabilizes the labels. Basic DQN needs both.
