🧩 Analogy: a better average, a worse ward

A hospital’s average waiting time drops, but in the children’s ward it doubles. The average is a mixture, and a big win in a large group can hide a loss in a small one. Always ask “who pays for this improvement?”

2. The average is a weighted mixture

Suppose prompt group \(g\) has policy effect:

\[\tau_g = E[Y(1)-Y(0)\mid G=g]\]

The deployment-wide average effect is:

\[\tau_{\text{micro}} = \sum_g P(G=g)\tau_g\]

A common group can dominate this average. Consequently:

\[\tau_{\text{micro}}>0\]

does not imply:

\[\tau_g>0\quad\text{for every }g\]

An equal-group summary answers a different question:

\[\tau_{\text{macro}} = \frac1K\sum_{g=1}^{K}\tau_g\]

  • Micro weighting describes expected change under the deployment traffic mixture.

  • Macro weighting gives every specified group equal influence.

  • Neither replaces reporting the individual effects.

A conservative deployment gate might require:

\[\operatorname{LCB}_{\text{overall}}>0\]

and, for every prespecified group,

\[\operatorname{LCB}_g > \Delta_{g,\min}\]

The group floor can be zero or a justified noninferiority margin. Because checking several groups creates several chances for a false claim, use simultaneous bounds—for example:

\[z= \Phi^{-1}\left(1-\frac{\delta}{K}\right)\]

\[\operatorname{LCB}_g = \hat\tau_g-z\,\operatorname{SE}(\hat\tau_g)\]

Small groups have wider bounds. “Insufficient evidence” is different from “evidence of harm,” although either may block deployment under a strict gate.

Tensor shapes:

  • group, assignment and reward: [N]

  • one-hot group membership: [N, K]

  • group counts, effects and bounds: [K]

Prespecify meaningful groups such as language, prompt family, tool type or difficulty band. Mining hundreds of groups after observing outcomes requires additional correction and independent confirmation.

Under adaptive routing, replace raw subgroup differences with propensity-aware estimators such as subgroup AIPW, and audit overlap inside every group.

DPO can improve aggregate preference accuracy while degrading one prompt group’s actual task success. Preference optimization neither identifies nor prevents heterogeneous online harm.

🔍 Deeper: the average is a weighted mixture

\(\tau=\sum_gw_g\tau_g\). A positive \(\tau\) is compatible with \(\tau_g<0\) for small-\(w_g\) groups. Do: prespecify the important slices, report each \(\tau_g\) with its own CI, and correct for many slices if you search for regressions. Small groups have wide intervals, so “not significantly worse” there usually means “we don’t know” (Topic 97).

🔑 Key ideas

  • Averages answer “better on average?”; subgroup effects answer “who pays?”

  • Prespecify slices and never let an aggregate authorize a concentrated regression.

🚶 Walkthrough: the mixture

\(0.9\times0.05+0.1\times(-0.10)=0.045-0.010=0.035\). Overall up 3.5 points, and group B down 10.

Common mistakes

  • Slices defined after looking at the results.

  • Slices based on post-treatment behaviour.

  • Reading a wide CI in a small group as “no effect.”

Hints

  • Overall effect is candidate mean minus control mean.

  • F.one_hot(groups, num_groups).to(torch.float64) has shape [N, K].

  • Multiply one-hot membership by each assignment mask.

  • A Bernoulli sample variance is \(\hat p(1-\hat p)n/(n-1)\).

  • Use 1 - family_delta / num_groups in the normal quantile.

  • The deployment gate requires both the overall and every-group conditions.

Debugging experiments

  • Inspect only the overall mean and miss the rare-group regression.

  • Discover groups after seeing their effects but report uncorrected intervals.

  • Define groups using response length or tool usage produced after assignment.

  • Treat tokens from one episode as independent observations.

  • Oversample a rare group, then forget to restore deployment weights for the micro effect.

  • Drop episodes with unknown group labels instead of reporting their rate and sensitivity.

  • Misalign group IDs and reward masks during batch filtering.

Solutions

Overall estimate:

candidate_rewards = rewards[
    candidate_mask
]

control_rewards = rewards[
    control_mask
]

candidate_count = candidate_mask.sum().to(
    torch.float64
)

control_count = control_mask.sum().to(
    torch.float64
)

overall_candidate_mean = (
    candidate_rewards.mean()
)

overall_control_mean = (
    control_rewards.mean()
)

overall_effect = (
    overall_candidate_mean
    - overall_control_mean
)

overall_standard_error = torch.sqrt(
    candidate_rewards.var(
        correction=1
    ) / candidate_count
    +
    control_rewards.var(
        correction=1
    ) / control_count
)

overall_lcb = (
    overall_effect
    - overall_z * overall_standard_error
)

Group effects:

group_one_hot = F.one_hot(
    groups,
    num_classes=num_groups,
).to(torch.float64)

candidate_membership = (
    group_one_hot
    * candidate_mask[:, None]
)

control_membership = (
    group_one_hot
    * control_mask[:, None]
)

candidate_group_counts = (
    candidate_membership.sum(dim=0)
)

control_group_counts = (
    control_membership.sum(dim=0)
)

candidate_group_means = (
    (
        candidate_membership
        * rewards[:, None]
    ).sum(dim=0)
    / candidate_group_counts
)

control_group_means = (
    (
        control_membership
        * rewards[:, None]
    ).sum(dim=0)
    / control_group_counts
)

group_effects = (
    candidate_group_means
    - control_group_means
)

Group uncertainty:

candidate_group_variances = (
    candidate_group_means
    * (1.0 - candidate_group_means)
    * candidate_group_counts
    / (candidate_group_counts - 1.0)
)

control_group_variances = (
    control_group_means
    * (1.0 - control_group_means)
    * control_group_counts
    / (control_group_counts - 1.0)
)

group_standard_errors = torch.sqrt(
    candidate_group_variances
    / candidate_group_counts
    +
    control_group_variances
    / control_group_counts
)

Simultaneous bounds:

simultaneous_z = standard_normal.icdf(
    torch.tensor(
        1.0
        - family_delta / num_groups
    )
)

group_lcbs = (
    group_effects
    - simultaneous_z
    * group_standard_errors
)

Summaries and gates:

observed_group_frequencies = (
    group_one_hot.mean(dim=0)
)

standardized_micro_effect = (
    observed_group_frequencies
    * group_effects
).sum()

macro_effect = group_effects.mean()

overall_gate_passes = (
    overall_lcb > 0.0
)

group_gate_passes = (
    group_lcbs
    >= minimum_group_effect
).all()

promote_candidate = (
    overall_gate_passes
    & group_gate_passes
)

exact_group_effects = (
    candidate_success_probabilities
    - control_success_probabilities
)

exact_control_value = (
    group_probabilities
    * control_success_probabilities
).sum()

exact_candidate_value = (
    group_probabilities
    * candidate_success_probabilities
).sum()

exact_micro_effect = (
    exact_candidate_value
    - exact_control_value
)

exact_macro_effect = (
    exact_group_effects.mean()
)

The group effects are:

\[[0.66-0.60,\;0.56-0.50,\;0.22-0.40] = [0.06,\;0.06,\;-0.18]\]

The deployment-weighted values are:

\[J_0 = 0.7(0.60)+0.2(0.50)+0.1(0.40) = 0.56\]

\[J_1 = 0.7(0.66)+0.2(0.56)+0.1(0.22) = 0.596\]

Therefore:

\[\tau_{\text{micro}} = 0.596-0.56 = 0.036\]

The equal-group effect is:

\[\tau_{\text{macro}} = \frac{0.06+0.06-0.18}{3} = -0.02\]

The overall lower bound should be positive, but the rare group’s bound will be decisively negative. The candidate therefore fails the every-group gate despite improving average deployment reward.

Check answers

  1. The average weights effects by traffic frequency. Large positive groups can outweigh a serious loss in a smaller group.

  2. Micro effect predicts the change for the deployment traffic mixture; macro effect gives each specified group equal influence.

  3. They control false claims across a prespecified family of subgroup comparisons. They do not legitimize unlimited post-hoc subgroup searching.

  4. Use logged conditional propensities—often subgroup AIPW—and verify overlap, ESS and policy support separately inside each group.

Retrieval answers

  1. AIPW is consistent when either the logged propensity model is correct or the conditional outcome models are correct, under the remaining identification assumptions.

  2. No. Neither predictions nor weighting recover a counterfactual policy outcome where that policy had zero probability.

Takeaway: deployment averages answer “Does traffic improve on average?” Subgroup effects answer “Who pays for that improvement?” Report both, prespecify the important slices, and never let a strong aggregate metric silently authorize a concentrated regression.
