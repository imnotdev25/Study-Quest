2. Targeted audits change the sample mixture

Suppose human review is expensive, so you audit 80% of judge-positive cases but only 5% of judge-negative cases. This is sensible for finding failures, but the audited sample no longer represents deployment.

Let:

  • \(Y_i\): human label or judge-error indicator;

  • \(S_i\in\{0,1\}\): whether episode \(i\) was audited;

  • \(\pi_i=P(S_i=1\mid\text{logged information})\): its audit probability.

The deployment mean is:

\[\mu=\frac1N\sum_{i=1}^N Y_i\]

The Horvitz–Thompson estimator is:

\[\hat\mu_{\text{HT}} = \frac1N \sum_{i=1}^N \frac{S_iY_i}{\pi_i}\]

Each rare audit represents \(1/\pi_i\) similar episodes. A commonly more stable, self-normalized version is the Hájek estimator:

\[\hat\mu_{\text{H}} = \frac{ \sum_i S_iY_i/\pi_i }{ \sum_i S_i/\pi_i }\]

HT is unbiased when its assumptions hold and \(N\) is known. Hájek has small finite-sample ratio bias but remains within the outcome range.

Weight concentration reduces effective sample size:

\[N_{\text{eff}} = \frac{(\sum_i w_i)^2} {\sum_i w_i^2}, \qquad w_i=\frac{S_i}{\pi_i}\]

Requirements:

  • record the actual conditional audit probability;

  • require \(\pi_i>0\) for every deployment stratum;

  • treat clipping as a bias–variance tradeoff, not a free stabilization;

  • retain masks and episode IDs so labels and propensities cannot become misaligned.

Tensor shapes:

  • truth, judge output, audit mask and propensity: [N]

  • weights and weighted outcomes: [N]

  • population estimates: scalars

For DPO, deliberately reviewing high-loss or disagreement pairs is useful for data collection. But an error rate computed directly on those pairs describes the targeted sample, not the deployment preference distribution. DPO remains fixed-data preference optimization, not online exploration.

Hints

  • Use torch.where(true_incidents, judge_tpr, judge_fpr).

  • Audit probability depends on the recorded judge output.

  • The naive estimates use only rows where audited is true.

  • Set unaudited weights to zero with audited.float() / audit_probability.

  • Estimate TPR by dividing weighted true positives by weighted actual positives.

  • Compute weighted sums in float64; extreme inverse propensities can overflow or dominate in lower precision.

Debugging experiments

  • Set the negative-case audit probability to zero.

  • Shuffle labels without shuffling their audit propensities.

  • Replace actual adaptive propensities with the original planned rates.

  • Clip weight 20 to 5 and still claim unbiasedness.

  • Report raw audit counts without weight or ESS diagnostics.

  • Assume human labels are perfect despite reviewer disagreement.

Solutions

Simulation:

true_incidents = (
    torch.rand(num_episodes)
    < true_incident_rate
)

judge_positive_probabilities = torch.where(
    true_incidents,
    torch.tensor(judge_tpr),
    torch.tensor(judge_fpr),
)

judge_positive = (
    torch.rand(num_episodes)
    < judge_positive_probabilities
)

Targeted audit:

audit_probabilities = torch.where(
    judge_positive,
    torch.tensor(
        audit_rate_if_judge_positive
    ),
    torch.tensor(
        audit_rate_if_judge_negative
    ),
)

audited = (
    torch.rand(num_episodes)
    < audit_probabilities
)

num_audited = audited.sum()

positive_judge_audits = (
    audited & judge_positive
).sum()

negative_judge_audits = (
    audited & ~judge_positive
).sum()

Naive estimates:

naive_incident_rate = (
    truth[audited].mean()
)

naive_judge_error_rate = (
    judge_errors[audited].mean()
)

Weighted estimates:

audit_weights = (
    audited.to(torch.float64)
    / audit_probabilities
)

ht_incident_rate = (
    audit_weights * truth
).sum() / num_episodes

hajek_incident_rate = (
    audit_weights * truth
).sum() / audit_weights.sum()

weighted_judge_error_rate = (
    audit_weights * judge_errors
).sum() / audit_weights.sum()

Diagnostics and calibration:

effective_audit_size = (
    audit_weights.sum().square()
    / audit_weights.square().sum()
)

effective_audit_fraction = (
    effective_audit_size
    / num_audited
)

maximum_weight = audit_weights.max()

estimated_tpr = (
    audit_weights
    * truth
    * judge
).sum() / (
    audit_weights * truth
).sum()

estimated_fpr = (
    audit_weights
    * (1.0 - truth)
    * judge
).sum() / (
    audit_weights
    * (1.0 - truth)
).sum()

Oracle quantities:

oracle_incident_rate = truth.mean()

oracle_judge_error_rate = (
    judge_errors.mean()
)

oracle_tpr = (
    truth * judge
).sum() / truth.sum()

oracle_fpr = (
    (1.0 - truth) * judge
).sum() / (
    1.0 - truth
).sum()

The expected judge-positive rate is:

\[q = 0.08(0.80)+0.92(0.10) = 0.156\]

The expected audit fraction is:

\[0.156(0.80)+0.844(0.05) = 0.167\]

True incidents enter the audit with probability:

\[0.08[ 0.80(0.80)+0.20(0.05) ] = 0.052\]

Therefore, the naive audited incident rate is approximately:

\[\frac{0.052}{0.167} \approx0.311\]

The population judge-error rate is:

\[0.08(0.20)+0.92(0.10) = 0.108\]

But targeted auditing disproportionately includes false positives, making the naive audited error rate approximately:

\[\frac{ 0.08(0.20)(0.05) + 0.92(0.10)(0.80) }{ 0.167 } \approx0.446\]

Inverse-probability weighting should recover incident rate 0.08, judge error 0.108, TPR 0.80 and FPR 0.10. Audited positive and negative predictions receive weights 1.25 and 20, respectively. Those uneven weights make ESS substantially smaller than the raw audit count.

Check answers

  1. Judge-positive cases contain more true incidents and are deliberately overrepresented; the unweighted sample estimates the audit mixture.

  2. Log the probability actually used for that episode, conditional on all information that influenced selection.

  3. No. Division cannot reconstruct outcomes from a stratum that was never eligible for review.

  4. A few observations with large weights carry much of the estimate, increasing variance and reducing independent information.

Retrieval answers

\[p=\frac{q-\text{FPR}} {\text{TPR}-\text{FPR}}\]

  1. Inverting the measurement equation divides noise by a small number, sharply amplifying standard errors and calibration uncertainty.

Takeaway: targeted audits are excellent for finding failures, but raw audit percentages are not deployment rates. Log inclusion probabilities, inverse-weight population claims, and report weight concentration and support.
