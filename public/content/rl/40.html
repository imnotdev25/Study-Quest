🧩 Analogy: checking a restaurant bill three ways

To check a bill, you can use a calculator, do rough mental math, or add up the items yourself. If all three agree, you trust it. If one disagrees, something’s wrong. Gradient checks do the same: autograd (the calculator), finite differences (rough math), and the REINFORCE estimate (the sampled answer) should all point the same way on a tiny problem.

2. Three views of the same gradient

For a small categorical policy, expected reward can be calculated exactly:

\[J(\theta) = \sum_a \pi_\theta(a)R(a)\]

Its gradient with respect to logit \(z_k\) is:

\[\frac{\partial J}{\partial z_k} = \pi_\theta(k) \left[ R(k)-J(\theta) \right]\]

Therefore:

  • above-average actions have positive ascent gradients;

  • below-average actions have negative ascent gradients;

  • all logit gradients sum to zero because adding a constant to every logit leaves softmax unchanged.

Finite-difference slope

For one parameter:

\[\frac{\partial J}{\partial z_k} \approx \frac{ J(z+\epsilon e_k)-J(z-\epsilon e_k) }{ 2\epsilon }\]

This is the familiar line-slope idea applied one coordinate at a time. It is slow but valuable for testing tiny implementations.

Sampled REINFORCE gradient

When exact expectation is unavailable:

\[\nabla_\theta J = \mathbb E_{A\sim\pi_\theta} \left[ (R(A)-b) \nabla_\theta\log\pi_\theta(A) \right]\]

A Monte Carlo estimate should approach the exact gradient as sample count grows. It will not match exactly because actions are sampled.

PyTorch optimizers minimize, so the actor loss is:

\[L_{\text{actor}} = -\frac1B\sum_i \log\pi_\theta(A_i)\hat A_i\]

Tensor shapes:

  • logits, probabilities and exact gradient: [actions]

  • sampled actions, rewards and advantages: [B]

  • policy loss: scalar

DPO has a differentiable preference loss over fixed pairs rather than a sampled REINFORCE estimator. Finite-difference checks remain useful for either objective.

🔍 Deeper: finite-difference error: the V-shaped curve

Central difference: \(\frac{f(\theta+h)-f(\theta-h)}{2h}=f'(\theta)+\frac{h^2}{6}f'''(\theta)+O(h^4)\), so the truncation error is \(O(h^2)\). Forward difference has \(O(h)\). But floating-point roundoff adds about \(\varepsilon_{\text{mach}}|f|/h\). Too-small \(h\) makes things worse:

Model curves (float64, \(|f|,|f''|,|f'''|\sim1\)). The best \(h\) is about \(10^{-5}\) for central and \(10^{-8}\) for forward differences. In float32 everything is roughly \(10^9\times\) worse, so run checks in float64.

REINFORCE check: its standard error shrinks like \(1/\sqrt N\). Compare with cosine similarity, and expect agreement in direction within a few standard errors, not equality.

🔑 Key ideas

  • Autograd checks code, finite differences check autograd, REINFORCE checks the estimator.

  • Use float64, central differences and \(h\approx10^{-5}\).

🚶 Walkthrough: central difference

\(f(\theta)=\theta^3\) at \(\theta=1\), \(h=10^{-3}\): \(\frac{1.003001-0.997001}{0.002}=3.000001\). The true value is 3, so the error \(10^{-6}=h^2\cdot f'''/6\). (checks out)

Common mistakes

  • Float32 with \(h=10^{-6}\) (roundoff dominates).

  • Dropout or random sampling inside \(f\) (the two evaluations differ).

  • Comparing REINFORCE estimates elementwise instead of by direction and standard error.

Hints

  • Exact probabilities use softmax(dim=-1).

  • Expected reward is the probability-weighted reward sum.

  • Convert a minimization gradient to an ascent gradient by negating .grad.

  • Index rewards using sampled action IDs.

  • Detach advantages in the actor loss.

  • Perturb using += epsilon and -= epsilon.

  • The central difference denominator is 2 * epsilon.

Debugging experiments

Remove the negative sign:

mc_loss = (
    sampled_log_probs
    * advantages.detach()
).mean()

Gradient descent now moves opposite the reward-maximizing direction.

Next, remove .detach() while making the baseline depend on mc_logits. Autograd then differentiates through the credit signal, so the result no longer represents the intended score-function actor gradient.

Finally, reduce:

num_samples = 50

The code remains mathematically correct, but sampling variance can make individual gradient components noisy or even temporarily have the wrong sign.

Solutions

Exact objective:

exact_probs = exact_logits.softmax(
    dim=-1
)

exact_expected_reward = (
    exact_probs * action_rewards
).sum()

exact_loss = -exact_expected_reward

Exact ascent gradient:

exact_ascent_gradient = (
    -exact_logits.grad.detach().clone()
)

Sampled quantities:

sampled_rewards = action_rewards[
    sampled_actions
]

sampled_log_probs = mc_policy.log_prob(
    sampled_actions
)

REINFORCE loss:

advantages = (
    sampled_rewards - baseline
)

mc_loss = -(
    sampled_log_probs
    * advantages.detach()
).mean()

mc_ascent_gradient = (
    -mc_logits.grad.detach().clone()
)

Finite differences:

positive_logits[index] += epsilon
negative_logits[index] -= epsilon
finite_difference_gradient[index] = (
    positive_value - negative_value
) / (
    2.0 * epsilon
)

The exact gradient has the form:

\[\nabla_{z_k}J = \pi(k)[R(k)-J]\]

Action 2 has reward 3, well above the expected reward, so its logit receives the largest positive ascent gradient.

Actions 0 and 1 are below the expected reward and receive negative ascent gradients. Increasing action 2 necessarily takes probability mass from the other actions.

Finite difference should match autograd very closely. REINFORCE should be nearby but retain Monte Carlo sampling error.

The gradient sum is approximately zero:

\[\sum_k \pi(k)[R(k)-J] = \mathbb E[R]-J = 0\]

Check answers

  1. It needs at least two forward evaluations per parameter; billions of parameters make that prohibitively expensive.

  2. The sampled loss may have the wrong sign, wrong log-probabilities, non-detached credit signals or excessive sampling variance.

  3. The differentiable objective or tensor operations may be incorrect; also inspect finite-difference \(\epsilon\) and numerical precision.

  4. A reversed or otherwise incorrect objective can decrease perfectly while optimizing the wrong behavior.

Retrieval answers

  1. Advantages are fixed credit signals for the actor update. Differentiating through them introduces unintended paths and can let the target move with the policy.

  2. For an action-independent baseline:

\[\mathbb E[ b\nabla\log\pi(A) ] = b\nabla\sum_a\pi(a) = 0\]

Takeaway: on a tiny problem, triangulate policy gradients three ways. Autograd checks the implementation, finite differences check autograd’s result, and REINFORCE checks whether the sampled estimator points in the same reward-improving direction.
