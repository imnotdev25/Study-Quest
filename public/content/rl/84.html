🧩 Analogy: a GPS that recomputes at every checkpoint

A road-trip GPS doesn’t just give one ETA at the start. At each checkpoint it notes “I’m 5 minutes behind” and adjusts. Sequential DR starts from a model’s value prediction and, at each step, corrects it with importance-weighted TD surprises: only the model’s error gets reweighted.

2. Predict most of the return; importance-weight only the error

PDIS applies cumulative importance ratios directly to rewards:

\[\hat J_{\text{PDIS}} = \frac1N\sum_i\sum_t \gamma^t\rho_{0:t}^{(i)}r_t^{(i)}\]

This can have high variance. Sequential doubly robust evaluation first predicts returns using a model, then importance-weights only the model’s error.

Let:

\[\hat V(s_t) = \sum_a\pi(a\mid s_t)\hat Q(s_t,a)\]

The model’s one-step TD residual is:

\[\delta_t = r_t+\gamma\hat V(s_{t+1}) -\hat Q(s_t,a_t)\]

The sequential DR estimator is:

\[\hat J_{\text{DR}} = \frac1N\sum_i \left[ \hat V(s_0^{(i)}) + \sum_t \gamma^t \rho_{0:t}^{(i)} \delta_t^{(i)} \right]\]

Think of \(\hat V(s_0)\) as an estimated invoice. Each observed transition supplies a correction. If the model is useful, the residuals are much smaller than raw rewards, so large importance weights amplify less noise.

It is “doubly robust” because it can remain consistent when either:

  • the behavior propensities are correct, or

  • the conditional \(Q/V\) model is correct.

It does not rescue missing action support. If both components are wrong, no guarantee remains.

At terminal states:

\[\hat V(s_T)=0\]

Otherwise, the model accidentally bootstraps beyond the episode.

Tensor shapes:

  • actions, rewards, ratios and residuals: [R, B, T]

  • next state at time one: [R, B]

  • \(Q_0\) table: [A]

  • \(Q_1\) table: [S, A]

  • repeated estimates: [R]

Freeze or detach all model predictions during evaluation. OPE statistics should not backpropagate into the outcome model.

DPO optimizes preference log-ratios on fixed response pairs. It does not learn an environmental \(Q\)-function or provide sequential DR estimates. A DPO checkpoint can be the target policy being evaluated, but its preference margin is not the TD residual used here.

🔍 Deeper: the recursion

Jiang & Li (2016), backward over a trajectory: \[\hat V^{\text{DR}}_t=\hat V(s_t)+\rho_t\Big(r_{t+1}+\gamma\hat V^{\text{DR}}_{t+1}-\hat Q(s_t,a_t)\Big),\qquad\hat V^{\text{DR}}_T=0,\] with \(\hat V(s)=\sum_a\pi(a|s)\hat Q(s,a)\). With a perfect \(\hat Q\), every bracket has mean 0, which gives low variance. With exact \(\rho\), the estimate is unbiased whatever \(\hat Q\) is. At \(T=1\) this is exactly the one-step DR of Topic 39.

🔑 Key ideas

  • Predict most of the return and importance-weight only the error.

  • A better model lowers variance, and valid propensities protect against model bias.

🚶 Walkthrough: one step

\(\hat V(s_0)=0.8\), \(\hat Q(s_0,a_0)=0.7\), \(\rho_0=2\), \(r_1=1\), terminal next (\(\hat V^{\text{DR}}_1=0\)). \(\hat V^{\text{DR}}_0=0.8+2(1-0.7)=1.4\). PDIS would give \(2\times1=2\): a larger swing from the same data.

Common mistakes

  • Using \(\hat V\) under the logging policy instead of \(\pi\).

  • Recursing forward instead of backward.

  • The same data fitting \(\hat Q\) and evaluating (Topic 86).

⚙️ Algorithm: Sequential doubly robust OPE
Input: logged trajectories, propensities \(b\), target \(\pi\), model \(\hat Q\) fit on separate data
for each trajectory do
\(v\gets0\)
for \(t=T-1\) down to \(0\) do
\(\hat V_t\gets\sum_a\pi(a|s_t)\hat Q(s_t,a)\); \(\rho_t\gets\pi(a_t|s_t)/b(a_t|s_t)\)
\(v\gets\hat V_t+\rho_t\big(r_{t+1}+\gamma v-\hat Q(s_t,a_t)\big)\)
end
record \(v\) for this trajectory
end
return mean of the recorded \(v\) (and a bootstrap CI over trajectories)

\[s_1=a_0\]

\[r_0=a_0, \qquad r_1=\mathbf1[a_1=s_1]\]

Hints

  • state_one is the first action.

  • Stack reward_zero and reward_one on the final dimension.

  • Use cumulative sums of selected-action log-ratios.

  • Compute v_hat_one by averaging each \(Q\) row under target_policy.

  • next_v_zero is v_hat_one[state_one].

  • The terminal next-state value for the second reward is zero.

  • Add v_hat_initial once per episode, then add importance-weighted residuals.

Debugging experiments

  • Use only the current-step ratio for each residual. Earlier actions still determine later state occupancy.

  • Reverse the residual sign. The correction moves the estimate away from the observed outcome.

  • Use q_hat_one[state, logged_action] as \(\hat V(s_1)\). \(V\) must average all actions under the target policy.

  • Bootstrap past the terminal state instead of using zero.

  • Train the model on these evaluation episodes and report the same-data result. Use held-out data or cross-fitting.

  • Allow gradients through q_hat. Evaluation then silently becomes model fitting.

  • Set a behavior probability to zero for a target-supported action. Neither DR nor a perfect-looking residual diagnostic repairs missing support.

Solutions

States, rewards and discounts:

state_one = actions[:, :, 0]

reward_zero = (
    actions[:, :, 0]
    .to(torch.float64)
)

reward_one = (
    actions[:, :, 1]
    == state_one
).to(torch.float64)

rewards = torch.stack(
    [reward_zero, reward_one],
    dim=-1,
)

discounts = torch.tensor([
    1.0,
    gamma,
])

Importance ratios:

behavior_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        behavior_one_probability
    ),
    torch.tensor(
        1.0 - behavior_one_probability
    ),
)

target_action_probabilities = torch.where(
    actions == 1,
    torch.tensor(
        target_one_probability
    ),
    torch.tensor(
        1.0 - target_one_probability
    ),
)

step_log_ratios = (
    target_action_probabilities.log()
    - behavior_action_probabilities.log()
)

prefix_log_ratios = torch.cumsum(
    step_log_ratios,
    dim=-1,
)

prefix_ratios = (
    prefix_log_ratios.exp()
)

Model values:

v_hat_one = (
    q_hat_one
    * target_policy[None, :]
).sum(dim=-1)

v_hat_initial = (
    q_hat_zero
    * target_policy
).sum()

logged_q_zero = (
    q_hat_zero[
        actions[:, :, 0]
    ]
)

logged_q_one = (
    q_hat_one[
        state_one,
        actions[:, :, 1],
    ]
)

next_v_zero = (
    v_hat_one[state_one]
)

TD residuals:

residual_zero = (
    reward_zero
    + gamma * next_v_zero
    - logged_q_zero
)

# The next state is terminal, so V(s_2) = 0.
residual_one = (
    reward_one
    - logged_q_one
)

model_residuals = torch.stack(
    [residual_zero, residual_one],
    dim=-1,
)

Estimators and diagnostics:

trajectory_returns = (
    rewards
    * discounts[None, None, :]
).sum(dim=-1)

naive_estimates = (
    trajectory_returns.mean(dim=1)
)

direct_estimates = (
    v_hat_initial.expand(
        num_repetitions
    )
)

pdis_estimates = (
    prefix_ratios
    * rewards
    * discounts[None, None, :]
).sum(dim=-1).mean(dim=1)

dr_episode_terms = (
    v_hat_initial
    + (
        prefix_ratios
        * model_residuals
        * discounts[None, None, :]
    ).sum(dim=-1)
)

dr_estimates = (
    dr_episode_terms.mean(dim=1)
)

target_match_probability = (
    target_one_probability ** 2
    + (
        1.0
        - target_one_probability
    ) ** 2
)

exact_target_value = torch.tensor(
    target_one_probability
    + gamma
    * target_match_probability
)

means = all_estimates.mean(dim=0)

biases = (
    means - exact_target_value
)

standard_deviations = (
    all_estimates.std(
        dim=0,
        correction=1,
    )
)

rmses = (
    (
        all_estimates
        - exact_target_value
    )
    .square()
    .mean(dim=0)
    .sqrt()
)

The model predicts:

\[\hat V(s_0) = 0.2(0.25)+0.8(1.55) = 1.29\]

The true target value is:

\[J(\pi) = 0.8 + 0.9(0.8^2+0.2^2) = 1.412\]

Thus, direct modeling has approximately -0.122 bias.

With correct behavior propensities, the weighted residuals correct this error. Typical results are:

  • PDIS mean near 1.412, standard deviation around 0.17;

  • sequential DR mean near 1.412, standard deviation around 0.03.

Exact numbers vary, but DR should be substantially more stable because it importance-weights prediction errors rather than the entire reward.

Check answers

  1. A useful model explains most return variation, leaving smaller residuals for large importance ratios to amplify.

  2. We are estimating the value of the target policy, so its action probabilities define the next-state value.

  3. Correct behavior propensities or correct conditional \(Q/V\) predictions, assuming adequate support and suitable estimation conditions.

  4. Report estimate variance, residual magnitude by timestep, prefix-weight quantiles, ESS, support violations, model calibration, terminal masking, horizon and PDIS-versus-DR sensitivity.

Retrieval answers

  1. WPDIS divides a random weighted-reward sum by a random weight sum, making it a biased finite-sample ratio estimator.

  2. Low ESS means a small number of logged trajectories dominate that timestep’s estimate; nominal batch size greatly overstates usable evidence.

Takeaway: sequential DR starts from a model prediction and uses cumulative importance ratios to correct its TD errors. A better model reduces variance, while valid propensities protect against model bias.
