🧩 Analogy: tonight’s choice changes tomorrow’s state

Staying up scrolling until 2 am feels rewarding now, but it moves you into the state “tired tomorrow,” where every action pays less. That is the jump from bandits to MDPs: actions change where you’ll be, not just what you get.

The discount \(\gamma\) is your patience. \(\gamma=0\) is “I want it now.” \(\gamma=0.99\) is “I’ll invest for the future.” Humans tend to discount the near future too steeply, which is a big part of why procrastination feels so natural.

A tiny MDP. Scrolling pays the most right now but moves you into a worse state.

2. From bandits to MDPs

A bandit repeatedly presents essentially the same situation. In a full RL problem, your current action changes the next situation.

Think of chess:

  • The board position is the state.

  • Moving a piece is the action.

  • Your move changes the board.

  • That new board affects which moves become possible later.

This is modeled as a Markov Decision Process, commonly written:

\[\mathcal{M}=(\mathcal{S},\mathcal{A},P,R,\gamma)\]

Component Meaning
Component Meaning
\(\mathcal S\) Possible states
\(\mathcal A\) Possible actions
\(P(s'\mid s,a)\) Distribution over the next state
\(R(s,a,s')\) Reward produced by the transition
\(\gamma\) Discount factor

The Markov property says that the current state contains the information needed to predict the next state:

\[P(S_{t+1}\mid S_t,A_t,\text{history}) = P(S_{t+1}\mid S_t,A_t)\]

This does not mean the past is irrelevant. It means its relevant information must already be represented in \(S_t\).

Trajectories

Interaction produces a trajectory:

\[\tau=(S_0,A_0,R_1,S_1,A_1,R_2,\ldots)\]

A policy generates actions, while the environment generates subsequent states and rewards:

\[A_t\sim\pi(\cdot\mid S_t)\]

\[S_{t+1}\sim P(\cdot\mid S_t,A_t)\]

Discounted return

The return from time \(t\) is:

\[G_t = R_{t+1} +\gamma R_{t+2} +\gamma^2R_{t+3} +\cdots\]

Equivalently:

\[G_t=R_{t+1}+\gamma G_{t+1}\]

This recursive form is fundamental. Bellman equations and temporal-difference learning will reuse the same structure.

For rewards [1, 0, 2] and \(\gamma=0.9\):

\[G_0=1+0.9(0)+0.9^2(2)=2.62\]

A useful analogy is the present value of future money: receiving something later may count less than receiving it now. But in RL, discounting can also:

  • make infinite reward sums finite;

  • prioritize near-term consequences;

  • represent uncertainty about whether interaction continues.

With \(\gamma=0\), only the next reward matters. As \(\gamma\to1\), distant rewards matter increasingly.

Realized versus expected return

\(G_t\) is the return from one sampled trajectory. The policy objective averages across possible trajectories:

\[J(\pi)=\mathbb{E}_{\tau\sim\pi}[G_0]\]

One successful episode does not prove that a policy is good, just as one lucky bandit pull does not prove an arm is best.

LLM connection

For an autoregressive LLM:

  • state: prompt plus tokens generated so far;

  • action: next token;

  • policy: next-token probability distribution;

  • trajectory: completed token sequence;

  • reward: often assigned to the completed answer.

A token changes the prefix seen at the next step, so generation is sequential—not a bandit. A poor early token can place the model in a bad region of future possible sequences.

🔍 Deeper: discounting as a geometric series

\(G_t=\sum_{k=0}^{\infty}\gamma^k r_{t+k+1}\). Three facts follow:

  1. Recursion: \(G_t=r_{t+1}+\gamma G_{t+1}\). This is why the exercise computes returns backward.

  2. Bounded: if \(|r|\le R_{\max}\), then \(|G_t|\le R_{\max}\sum_k\gamma^k=\dfrac{R_{\max}}{1-\gamma}\).

  3. Effective horizon: the weights \(\gamma^k\) sum to \(1/(1-\gamma)\), so the agent “sees” about that many steps: 10 steps for \(\gamma=0.9\), 100 for \(\gamma=0.99\).

Markov property: \(P(s_{t+1}\mid s_t,a_t)=P(s_{t+1}\mid s_0,a_0,\dots,s_t,a_t)\). The state must contain everything needed to predict the future. For an LLM, the state is the whole prompt plus every token generated so far.

🔑 Key ideas

  • MDP = states + actions + transitions + rewards + \(\gamma\).

  • \(G_t=r_{t+1}+\gamma G_{t+1}\), and the horizon is roughly \(1/(1-\gamma)\) steps.

🚶 Walkthrough: batched returns with an episode boundary

\(\gamma=0.9\). Rewards \([1,0,2\,|\,1,1]\) with done after step 3. Go backward: \(G_5=1\); \(G_4=1+0.9(1)=1.9\); at step 3 the episode ended, so reset: \(G_3=2\); \(G_2=0+0.9(2)=1.8\); \(G_1=1+0.9(1.8)=2.62\). Result: \([2.62,1.8,2,1.9,1]\). Without the reset, \(G_3\) would wrongly become \(2+0.9(1.9)=3.71\).

Common mistakes

  • Looping forward (each step would need all future rewards).

  • Forgetting \((1-d)\), so returns leak across episodes.

  • Discounting the first reward: \(G_t\) starts with \(r_{t+1}\), not \(\gamma r_{t+1}\).

⚙️ Algorithm: Discounted returns, computed backward
Input: rewards \(r_1,\dots,r_T\), discount \(\gamma\), done flags \(d_1,\dots,d_T\)
\(G\gets0\)
for \(t=T-1\) down to \(0\) do
\(G\gets r_{t+1}+\gamma(1-d_{t+1})\,G\) ▷ reset the sum at episode boundaries
\(G_t\gets G\)
end
return \(G_0,\dots,G_{T-1}\)

Solutions

import torch

rewards = torch.tensor([
    [1.0, 0.0, 2.0, 99.0],
    [0.0, 1.0, 1.0,  3.0],
])

valid = torch.tensor([
    [1.0, 1.0, 1.0, 0.0],
    [1.0, 1.0, 1.0, 1.0],
])

gamma = 0.9
returns = torch.zeros_like(rewards)
running_return = torch.zeros(rewards.shape[0])

for t in reversed(range(rewards.shape[1])):
    running_return = rewards[:, t] + gamma * running_return
    running_return = running_return * valid[:, t]
    returns[:, t] = running_return

undiscounted_total = (rewards * valid).sum(dim=1)

print(returns)
print(undiscounted_total)

Approximate output:

tensor([
    [2.6200, 1.8000, 2.0000, 0.0000],
    [3.8970, 4.3300, 3.7000, 3.0000]
])

tensor([3., 5.])

When gamma = 0.0, every valid return equals its immediate reward:

[1, 0, 2] and [0, 1, 1, 3]

When gamma = 1.0, each return becomes the undiscounted sum of all subsequent rewards:

[3, 2, 2] and [5, 5, 4, 3]

This masking approach assumes padding follows the terminal transition. More general replay data usually carries an explicit done or continuation mask for every transition.

Check answers

  1. The next browser state may also depend on page content, authentication, open dialogs, previous actions and other information absent from the URL.

  2. No. Discounting changes how the objective weights rewards; it does not alter the observed reward itself.

  3. \(G_t\) depends on \(G_{t+1}\), so the later value must already be available.

  4. The padding reward contaminates the sum before masking can remove it. Mask elementwise first.

  5. Every earlier token action receives the final reward in its return when there are no intermediate rewards and \(\gamma=1\).

Retrieval answers

  1. A stationary bandit presents the same decision repeatedly; actions produce rewards but do not create meaningful next states.

  2. Exploitation selects the currently best-known action, while exploration gathers information that may correct the current estimates.

Takeaway: In an MDP, an action matters twice: it can produce an immediate reward and it can move the agent into a better or worse future state.
