🧩 Analogy: four house rules for a study group

A study group sets four rules. (1) Let quiet members speak up more than loud members can shout. (2) Skip questions everyone already got right, or everyone got wrong, since nobody learns from those. (3) Count every sentence equally, not every speaker. (4) Gently penalize rambling before cutting off someone who goes too long. Those are DAPO’s four techniques.

Clip-higher: a good token’s probability may grow a bit more before the gradient stops.

2. The four techniques (Yu et al., 2025)

DAPO (“Decoupled Clip and Dynamic sAmpling Policy Optimization”) is built on GRPO and drops the KL penalty entirely, arguing that a long-reasoning model is supposed to drift far from its starting point.

  1. Clip-higher: \(\operatorname{clip}(\rho,1-\epsilon_{\text{low}},1+\epsilon_{\text{high}})\) with \(\epsilon_{\text{low}}=0.2\), \(\epsilon_{\text{high}}=0.28\). A symmetric clip caps how fast a rare useful token can grow (going from \(p=0.01\) to \(0.012\) already hits \(1.2\)), which speeds up entropy collapse. Raising only the upper bound helps exploration. Raising the lower bound too would let tokens be pushed toward zero.

  2. Dynamic sampling: drop prompts whose \(G\) samples are all correct or all wrong (their advantages are all 0), and keep sampling until the batch is full of informative prompts: \(0<|\{\text{correct}\}|<G\).

  3. Token-level loss: normalize by \(\sum_i|o_i|\), the total tokens in the group, instead of averaging per response. Long responses then get weight proportional to their length, so a long, rambling wrong answer is penalized per token as hard as a short one.

  4. Overlong reward shaping: mask the loss of truncated responses, and add a soft length penalty \[R_{\text{len}}(y)=\begin{cases}0 & |y|\le L_{\max}-L_{\text{cache}}\\ \frac{(L_{\max}-L_{\text{cache}})-|y|}{L_{\text{cache}}} & L_{\max}-L_{\text{cache}}<|y|\le L_{\max}\\ -1 & |y|>L_{\max}\end{cases}\] with \(L_{\max}=20{,}480\) and \(L_{\text{cache}}=4{,}096\) in the paper.

🔍 Deeper: the full objective

\[\mathcal J_{\text{DAPO}}=\mathbb E\Big[\frac{1}{\sum_i|o_i|}\sum_{i=1}^G\sum_{t=1}^{|o_i|}\min\big(\rho_{i,t}\hat A_{i,t},\ \operatorname{clip}(\rho_{i,t},1-\epsilon_{\text{low}},1+\epsilon_{\text{high}})\hat A_{i,t}\big)\Big]\] subject to \(0<|\{o_i\text{ correct}\}|<G\), with \(\hat A_{i,t}=\frac{R_i-\operatorname{mean}(R)}{\operatorname{std}(R)}\) and a rule-based reward \(R\in\{-1,+1\}\). There is no KL term.

🔑 Key ideas

  • Clip-higher protects rare exploration tokens, and dynamic sampling removes zero-signal groups.

  • Token-level loss plus overlong shaping control length without hiding long failures.

🚶 Walkthrough: the soft length penalty

Toy settings \(L_{\max}=20\), \(L_{\text{cache}}=4\), so the penalty starts after 16 tokens. Length 10: \(0\). Length 18: \(\frac{16-18}{4}=-0.5\). Length 20: \(-1\). Length 25: \(-1\) (and that sample is also masked as truncated).

Common mistakes

  • Raising \(\epsilon_{\text{low}}\) along with \(\epsilon_{\text{high}}\).

  • Dynamic sampling that drops groups but doesn’t refill the batch (the effective batch shrinks).

  • Applying the length penalty but still training on truncated responses.

⚙️ Algorithm: DAPO training step
Input: policy \(\pi_\theta\), group size \(G\), clip \(\epsilon_{\text{low}},\epsilon_{\text{high}}\), batch size \(B\)
\(\pi_{\text{old}}\gets\pi_\theta\); batch \(\gets\emptyset\)
while \(|\text{batch}|<B\) do
sample a prompt \(x\) and \(G\) responses; reward \(R_i=\pm1\) plus \(R_{\text{len}}\)
if \(0<\#\text{correct}<G\) then add the group to the batch ▷ dynamic sampling
end
end
mask out truncated responses; \(\hat A_i\gets(R_i-\bar R)/\operatorname{std}(R)\)
gradient steps on \(-\mathcal J_{\text{DAPO}}\) with one denominator \(\sum_i|o_i|\) ▷ token-level

Solutions

import torch


def dapo_loss(logp_new, logp_old, adv, mask, eps_low=0.2, eps_high=0.28):
    ratio = (logp_new - logp_old).exp()
    unclipped = ratio * adv
    clipped = ratio.clamp(1 - eps_low, 1 + eps_high) * adv
    per_token = torch.min(unclipped, clipped)
    return -(per_token * mask).sum() / mask.sum()   # token-level: one denominator for the group


def keep_group(rewards):                            # dynamic sampling
    solved = (rewards > 0).float().mean()
    return bool(0 < solved < 1)


def overlong_penalty(length, l_max=20, l_cache=4):
    if length <= l_max - l_cache:
        return 0.0
    if length <= l_max:
        return ((l_max - l_cache) - length) / l_cache
    return -1.0


# A rare "exploration" token whose probability rose 25% after one update, with A > 0.
logp_old = torch.tensor([-3.0])
logp_new = (logp_old + torch.log(torch.tensor(1.25))).requires_grad_()
adv, mask = torch.tensor([1.0]), torch.tensor([1.0])
for eps_high in (0.2, 0.28):
    if logp_new.grad is not None:
        logp_new.grad = None
    dapo_loss(logp_new, logp_old, adv, mask, eps_high=eps_high).backward()
    print(f"eps_high={eps_high}: grad on logp = {logp_new.grad.item():.3f}")

print("keep [1,1,1,1]:", keep_group(torch.tensor([1., 1, 1, 1])),
      " keep [1,0,1,0]:", keep_group(torch.tensor([1., 0, 1, 0])))
print("penalties for lengths 10, 18, 20, 25:", [overlong_penalty(n) for n in (10, 18, 20, 25)])

Output:

eps_high=0.2: grad on logp = 0.000
eps_high=0.28: grad on logp = -1.250
keep [1,1,1,1]: False  keep [1,0,1,0]: True
penalties for lengths 10, 18, 20, 25: [0.0, -0.5, -1.0, -1.0]

Check answers

  1. The clip is relative: a token at \(p=0.01\) is capped at \(0.012\) per update, so rare useful tokens can barely grow, which favors already-likely tokens and collapses entropy.

  2. Otherwise the effective batch shrinks as training progresses (more prompts become all-correct), and gradient noise rises.

  3. Long reasoning legitimately moves far from the base model, and the KL penalty held that back. Without it you lose an explicit guard against drift, so monitoring matters more.

Retrieval answers: (1) When \(\rho>1+\epsilon\). (2) Token mean weights each token equally, while sequence mean weights each response equally.

Takeaway: DAPO is GRPO with four engineering fixes: asymmetric clipping, informative-only batches, token-level loss, and soft length control.
