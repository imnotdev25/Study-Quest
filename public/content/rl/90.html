🧩 Analogy: betting against the safety hypothesis

Start with $1 and bet, observation by observation, against the claim “the canary is safe.” If the claim is true, your wealth can’t grow on average. If your wealth ever reaches $20, you have strong evidence against it, and that’s true whenever you choose to look. That’s an e-process. Ordinary confidence intervals break if you keep peeking and stop when they look good.

Illustrative. The alarm fires at the first crossing, at any time, with error at most 5%.

2. Ordinary confidence intervals assume a planned stopping time

Suppose the unacceptable incident-rate boundary is:

\[p_0=0.04\]

Checking an ordinary 95% interval after every batch and stopping when it first falls below \(p_0\) creates many chances for a lucky fluctuation.

An e-value provides evidence that remains valid under continuous monitoring. Think of it as betting wealth against:

\[H_0:p\ge p_0\]

Choose a prespecified safer alternative \(q<p_0\). After \(S_n\) incidents in \(n\) episodes:

\[E_n(q) = \left(\frac q{p_0}\right)^{S_n} \left( \frac{1-q}{1-p_0} \right)^{n-S_n}\]

Each incident multiplies wealth by \(q/p_0<1\). Each non-incident multiplies it by \((1-q)/(1-p_0)>1\).

Under any unsafe rate \(p\ge p_0\), this wealth is a nonnegative supermartingale. Ville’s inequality gives:

\[P_{H_0} \left( \sup_n E_n\ge\frac1\delta \right) \le\delta\]

Thus, with \(\delta=0.05\), certify the rate as below the limit whenever:

\[E_n\ge20\]

You may check after every episode without invalidating this guarantee.

A single \(q\) can be underpowered when the true safe rate differs from it. Prespecify several alternatives and average their e-values:

\[E_n^{\text{mix}} = \frac1M\sum_{m=1}^{M}E_n(q_m)\]

The average remains valid. Compute it in log-space:

\[\log E_n^{\text{mix}} = \operatorname{logsumexp}_m \log E_n(q_m) -\log M\]

Tensor shapes:

  • simulated incidents: [conditions, repetitions, time]

  • checkpoint counts: [conditions, repetitions, looks]

  • component log e-values: [conditions, alternatives, repetitions, looks]

  • mixture log e-values: [conditions, repetitions, looks]

An e-value answers “Is there anytime-valid evidence against the unsafe boundary?” It does not estimate the incident rate or effect size. Continue reporting rates, counts, subgroup results and practical severity.

A DPO checkpoint may be the candidate being monitored, but preference optimization supplies no guarantee about deployment incidents. The e-process uses actual online outcomes.

🔍 Deeper: Ville’s inequality

An e-process \(E_t\) is a nonnegative process with \(\mathbb E[E_t]\le1\) under the null at every stopping time. Ville: \(P_{H_0}(\exists t:E_t\ge1/\alpha)\le\alpha\). Likelihood-ratio example for incidents \(X_i\in\{0,1\}\), null rate \(p_0\), alternative \(p_1>p_0\): \(\log E_t=\sum_i\big[X_i\log\frac{p_1}{p_0}+(1-X_i)\log\frac{1-p_1}{1-p_0}\big]\). Compute it in log space, fix \(p_1\) before the canary, and keep estimating the effect separately from testing the safety boundary.

🔑 Key ideas

  • Ordinary intervals assume one look. E-processes let you keep watching.

  • Prespecify the alternative, and work in log space.

🚶 Walkthrough: per-observation updates

\(p_0=0.01\), \(p_1=0.02\). An incident adds \(\ln2=0.693\). A clean request adds \(\ln(0.98/0.99)=-0.0102\). Alarm at \(\ln20=3.0\): about 5 incidents in the first 50 requests would trigger it (\(5(0.693)-45(0.0102)=3.0\)).

Common mistakes

  • Choosing \(p_1\) after seeing data.

  • Multiplying raw probabilities (underflow).

  • Reading the e-value as an effect size.

⚙️ Algorithm: Anytime-valid canary safety monitor
Input: null incident rate \(p_0\), alternative \(p_1>p_0\) (both fixed in advance), level \(\alpha\)
\(L\gets0\)
for each canary request with incident flag \(X\in\{0,1\}\) do
\(L\gets L+X\log\frac{p_1}{p_0}+(1-X)\log\frac{1-p_1}{1-p_0}\)
if \(L\ge\log(1/\alpha)\) then stop the canary: evidence the rate exceeds \(p_0\)
end
end

Debugging experiments

  • Compute long products directly rather than summing log-ratios. Expect underflow or overflow.

  • Add an alternative \(q>p_0\). The process no longer supports the stated composite safety test.

  • Choose the best \(q\) after examining outcomes instead of prespecifying or mixing alternatives.

  • Treat thousands of correlated tokens as independent safety observations.

  • Change the candidate policy midway without resetting and versioning the evidence.

  • Monitor ten safety metrics independently at 5% without correcting the expanded decision rule.

Solutions

Simulation and cumulative counts:

incidents = (
    torch.rand(
        true_rates.numel(),
        num_repetitions,
        horizon,
    )
    < true_rates[:, None, None]
)

incident_counts = (
    incidents
    .to(torch.float64)
    .cumsum(dim=-1)[
        :,
        :,
        checkpoint_indices,
    ]
)

empirical_rates = (
    incident_counts
    / sample_sizes[None, None, :]
)

Repeated pointwise Wilson bounds:

wilson_denominator = (
    1.0
    + pointwise_z ** 2
    / sample_sizes[None, None, :]
)

wilson_center = (
    empirical_rates
    + pointwise_z ** 2
    / (
        2.0
        * sample_sizes[None, None, :]
    )
)

wilson_radius = (
    pointwise_z
    * torch.sqrt(
        empirical_rates
        * (
            1.0 - empirical_rates
        )
        / sample_sizes[None, None, :]
        + pointwise_z ** 2
        / (
            4.0
            * sample_sizes[
                None, None, :
            ].square()
        )
    )
)

pointwise_upper_bounds = (
    wilson_center + wilson_radius
) / wilson_denominator

pointwise_certificates = (
    pointwise_upper_bounds
    < safety_limit
)

Component log e-processes:

expanded_counts = (
    incident_counts[:, None, :, :]
)

expanded_sample_sizes = (
    sample_sizes[
        None, None, None, :
    ]
)

expanded_alternatives = (
    alternative_rates[
        None, :, None, None
    ]
)

component_log_e_values = (
    expanded_counts
    * torch.log(
        expanded_alternatives
        / safety_limit
    )
    + (
        expanded_sample_sizes
        - expanded_counts
    )
    * torch.log(
        (
            1.0
            - expanded_alternatives
        )
        / (
            1.0 - safety_limit
        )
    )
)

Mixture and threshold:

mixture_log_e_values = (
    torch.logsumexp(
        component_log_e_values,
        dim=1,
    )
    - math.log(num_alternatives)
)

log_e_threshold = math.log(
    1.0 / family_delta
)

anytime_certificates = (
    mixture_log_e_values
    >= log_e_threshold
)

Certification summaries:

For the component with \(q=0.02\), each incident multiplies wealth by:

\[\frac{0.02}{0.04}=0.5\]

Each non-incident multiplies it by:

\[\frac{0.98}{0.96}\approx1.0208\]

When the true rate is \(0.02\), expected log-growth per episode is:

\[0.02\log(0.5) + 0.98\log\left(\frac{0.98}{0.96}\right) \approx0.00634\]

Evidence therefore tends to grow. At the null boundary, expected log-growth is negative, although random paths can temporarily rise. Ville’s inequality controls the probability that any such path ever crosses the threshold.

The equal mixture pays an initial \(\log 5\) penalty relative to selecting the best component in advance, but it avoids having to know the true safe rate.

The repeatedly inspected Wilson procedure will generally show an inflated false-clearance rate. Its intervals were constructed for one fixed checkpoint, not the event “any interval across 100 checkpoints clears the limit.”

Check answers

  1. Its nonnegative supermartingale structure lets Ville’s inequality bound the probability of crossing at any stopping time.

  2. Different alternatives provide power against different genuinely safe rates while preserving validity through a prespecified average.

  3. No. Crossing rejects \(p\ge p_0\); it does not identify the true rate or eliminate the need to report an effect estimate.

  4. Correlated observations treated as independent, unlogged policy changes, selective outcome removal, nonstationary traffic, post-hoc alternative selection, interference between users, or an incorrect incident definition can invalidate the interpretation.

Retrieval answers

  1. Random assignment makes candidate and control traffic comparable, so their direct on-policy sample means estimate their respective deployment outcomes.

  2. Rare-event uncertainty shrinks with the number of independent candidate episodes, not with token count or total control traffic.

Takeaway: ordinary intervals answer “What if I inspect once?” An e-process answers “May I keep watching?” Compute it in log-space, prespecify the alternatives, and keep effect estimation separate from evidence against the safety boundary.
