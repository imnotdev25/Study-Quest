🧩 Analogy: a 70% exam score

Scoring 70% feels amazing if you expected 50%, and awful if you expected 90%. What teaches you is the surprise, not the raw score.

Brains work this way. In famous monkey experiments, dopamine neurons fired when juice arrived unexpectedly, stopped firing once the juice was predicted, and dipped when predicted juice didn’t come. Advantage \(=\) actual \(-\) expected is the RL version of that signal.

2. Return alone lacks context

Suppose you score 70 on an exam:

  • if the usual score is 40, that result is excellent;

  • if the usual score is 95, it is disappointing.

The raw result is the return. The expected result is a baseline. Their difference is an advantage:

\[A_t=G_t-b(S_t)\]

Interpretation:

  • \(A_t>0\): the sampled action led to a better-than-expected outcome;

  • \(A_t<0\): worse than expected;

  • \(A_t\approx0\): unsurprising outcome.

The policy loss becomes:

\[L_{\text{policy}} = -\frac1B \sum_{b,t} A_{b,t} \log\pi_\theta(A_{b,t}\mid S_{b,t})\]

Positive advantage increases an action’s probability. Negative advantage decreases it.

Why a baseline does not change the expected gradient

If the baseline depends on the state but not the sampled action:

\[\mathbb E_{a\sim\pi} \left[ b(s)\nabla_\theta\log\pi_\theta(a\mid s) \right] =0\]

because:

\[\sum_a \pi(a\mid s)\nabla_\theta\log\pi(a\mid s) = \nabla_\theta\sum_a\pi(a\mid s) = \nabla_\theta 1 = 0\]

So subtracting a suitable baseline preserves the expected policy gradient while usually reducing its variance.

Baseline is not reward shaping

Reward shaping changes the task’s reward signal. A baseline changes only the gradient estimator:

\[G_t \quad\rightarrow\quad G_t-b(S_t)\]

The environment reward and optimization objective remain the same.

Today we use an exponential moving average of previous returns. Later, a critic will learn the state-dependent baseline:

\[b(S_t)\approx V_\phi(S_t)\]

Tensor shapes

  • returns: [B, T]

  • baseline: [T], broadcast across the batch

  • advantages: [B, T]

  • log-probabilities: [B, T]

  • policy loss: scalar

LLM connection

If an LLM completion receives reward 0.7, that number alone is hard to interpret. If similar completions usually score 0.2, its advantage is positive.

Group-relative LLM methods use related responses to construct baselines. We will revisit this idea when discussing GRPO.

🔍 Deeper: baselines don’t add bias, and the variance curve

Unbiased for any \(b(s)\): \(\mathbb E_{a\sim\pi}[b(s)\nabla\log\pi(a|s)]=b(s)\nabla\sum_a\pi(a|s)=0\). Subtracting \(b\) changes the variance only.

Example: returns are 10 or 11 with equal chance. With \(b=0\), every action is pushed up hard and the signal is buried in the shared \(+10\). With \(b=10.5\), the advantages are \(\pm0.5\): a clean “better or worse” signal.

Advantage: \(A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s)\), and \(\mathbb E_{a\sim\pi}[A^\pi(s,a)]=0\). The truly variance-optimal constant baseline is \(b^*=\frac{\mathbb E[\|\nabla\log\pi\|^2G]}{\mathbb E[\|\nabla\log\pi\|^2]}\), but \(V(s)\) is the practical choice.

🔑 Key ideas

  • Learn from “better or worse than expected,” not “good or bad.”

  • Any state-only baseline keeps the gradient unbiased.

🚶 Walkthrough: a moving baseline catches up

Returns are always \(G=10\). Baseline \(b\gets b+0.1(G-b)\), starting at \(b=0\). Advantages \(G-b\): \(10\to9\to8.1\to7.29\to\dots\to0\). Early on, \(b\) lags, so every action looks great. Once \(b\approx\mathbb E[G]\), only real differences remain.

Common mistakes

  • Letting the baseline depend on the action taken (it creates bias).

  • Not detaching \(V(s)\) inside the actor’s advantage.

  • Updating \(b\) with \(G\) before computing that same sample’s advantage (a slight self-baseline, see Topic 42).

⚙️ Algorithm: REINFORCE with a learned baseline
Input: policy \(\pi_\theta\), value network \(V_\phi\) (or a running mean \(b\))
for each iteration do
collect episodes with \(\pi_\theta\); compute \(G_t\)
\(A_t\gets G_t-V_\phi(s_t)\) ▷ detached: the baseline is not trained by the actor loss
actor step on \(-\sum_t\log\pi_\theta(a_t|s_t)\,A_t\)
critic step on \(\sum_t\big(G_t-V_\phi(s_t)\big)^2\)
end

Debugging experiment

Reverse the subtraction:

advantages = baseline - returns

Successful trajectories now receive negative advantage and become less likely. This is the policy-gradient equivalent of reversing the TD-error sign.

Also try updating the baseline before calculating advantages. The current batch then influences both its return and its baseline. This is common in approximate implementations, but using the previous baseline keeps today’s dependency cleaner.

4. Checks for understanding

  1. Why can a failed trajectory now produce a useful gradient?

  2. What restriction must a valid baseline satisfy?

  3. Does a positive return always imply positive advantage?

  4. Why should the advantage normally be detached in the policy loss?

Solutions

advantages = returns - baseline
loss = -(
    log_probs * advantages.detach()
).sum(dim=1).mean()
grad_norm = logits.grad.norm().item()

Moving-baseline update:

with torch.no_grad():
    batch_mean_return = returns.mean(dim=0)

    baseline = (
        baseline_decay * baseline
        + (1.0 - baseline_decay)
        * batch_mean_return
    )

At the beginning, the baseline is zero:

successful return = 1
advantage = 1 - 0 = 1

After the baseline becomes, for example, 0.6:

success: advantage = 1 - 0.6 =  0.4
failure: advantage = 0 - 0.6 = -0.6

Successes increase their sampled action probabilities; failures decrease theirs.

The mean advantage will not be exactly zero because the baseline is a delayed moving estimate. A slowly updating baseline is stable but stale; a rapidly updating baseline follows recent noise.

Check answers

  1. Once the baseline is positive, a zero-return failure has negative advantage and its sampled actions become less probable.

  2. It must not depend on which current action was sampled in a way that introduces action-dependent bias.

  3. No. A positive return below the expected baseline has negative advantage.

  4. Advantages are supervision for the policy. Gradient flow into their construction would add unintended optimization paths.

Retrieval answers

  1. \(\displaystyle L=-\sum_tG_t\log\pi_\theta(A_t\mid S_t)\).

  2. Its return × log_probability term is zero.

Takeaway: return asks, “How well did this trajectory do?” Advantage asks the more useful question: “How much better or worse was it than expected?”
