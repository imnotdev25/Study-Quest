🧩 Analogy: a GPS ETA corrected by what actually happened

Your GPS predicts arrival at 6:00. On a few logged trips you know the real arrival. Average the GPS’s errors on those trips and correct its prediction. If the GPS is good, the corrections are small and stable. If it’s biased, the corrections fix the bias. That’s doubly robust evaluation for routers (Topic 39 introduced it). Here the focus is when it beats each parent method.

2. Combine two imperfect estimators

A direct-model estimator learns expected reward:

\[\hat q(s,a)\approx\mathbb E[R\mid s,a]\]

It evaluates the target policy using:

\[\hat J_{\mathrm{DM}} = \frac1N\sum_i \sum_a \pi(a\mid s_i)\hat q(s_i,a)\]

This has low variance but is biased when \(\hat q\) is wrong.

Importance sampling instead uses real logged rewards:

\[\hat J_{\mathrm{IS}} = \frac1N\sum_i \rho_i r_i, \qquad \rho_i= \frac{\pi(a_i\mid s_i)} {\mu(a_i\mid s_i)}\]

It avoids reward-model bias when propensities are correct, but can have high variance.

The doubly robust estimator combines them:

\[\hat J_{\mathrm{DR}} = \frac1N\sum_i \left[ \underbrace{ \sum_a\pi(a\mid s_i)\hat q(s_i,a) }_{\text{model prediction}} + \underbrace{ \rho_i \left( r_i-\hat q(s_i,a_i) \right) }_{\text{logged correction}} \right]\]

Think of \(\hat q\) as an initial invoice estimate. The observed outcome supplies a correction, reweighted to represent the target policy.

“Doubly robust” means the estimate is consistent if either:

  • the behavior propensities are correct, or

  • the reward model is correct.

It does not mean both components may be wrong. Support is still required.

Tensor shapes in the exercise:

  • contexts, actions and rewards: [R, N];

  • per-context target probabilities and \(Q\) values: [R, N, A];

  • importance weights: [R, N];

  • repeated value estimates: [R].

Freeze or detach the outcome model during evaluation. If it was trained on these same rewards, use held-out data or cross-fitting to avoid evaluating memorization.

DPO optimizes preference log-ratios. A DPO preference score is not automatically an environmental reward model suitable for doubly robust evaluation.

🔍 Deeper: why DR has lower variance

\(\hat V_{\text{DR}}=\frac1n\sum_i\Big[\hat q(x_i,\pi)+\rho_i\big(r_i-\hat q(x_i,a_i)\big)\Big]\) with \(\hat q(x,\pi)=\sum_a\pi(a|x)\hat q(x,a)\). Roughly, \(\operatorname{Var}[\text{IPS term}]\propto\mathbb E[\rho^2r^2]\) while \(\operatorname{Var}[\text{DR correction}]\propto\mathbb E[\rho^2(r-\hat q)^2]\). If \(\hat q\) explains most of \(r\), the residual is small, so the variance is small. DR can’t fix: missing support (\(\rho\) is undefined) or both \(\hat q\) and \(p\) being wrong.

🔑 Key ideas

  • Use the outcome model as a baseline and let weighted residuals correct it.

  • DR reduces variance, but it can’t rescue missing support.

🚶 Walkthrough: DM vs IPS vs DR

True value 0.70. A good model (residual sd 0.1) and a logger with \(\rho\in\{0,2.5\}\): DM \(\approx0.68\) (bias \(-0.02\), tiny variance). IPS: unbiased, sd \(\approx2.5\times0.46/\sqrt n\). DR: unbiased, sd \(\approx2.5\times0.1/\sqrt n\), about 4.6\(\times\) smaller than IPS.

Common mistakes

  • Fitting \(\hat q\) on the evaluation logs (Topic 86).

  • Reporting DR with no ESS or weight diagnostics.

  • Assuming DR is unbiased when the propensities are wrong and the model is wrong.

Hints

  • Selected-action probability uses p for action 1 and 1-p for action 0.

  • Stack target probabilities for actions 0 and 1 along the final dimension.

  • Indexing estimated_q[contexts] produces shape [R, N, A].

  • Logged \(Q\) values use estimated_q[contexts, actions].

  • The correction residual is reward - logged_q, not the reverse.

  • Compute bias and RMSE across repetitions.

Debugging experiments

  • Reverse the residual to q - reward. The correction pushes model error in the wrong direction.

  • Index the outcome model using the target policy’s greedy action rather than the logged action.

  • Remove importance weights from the residual. The correction then follows the behavior policy.

  • Train estimated_q on these exact rewards and report the same-batch DR result. Use held-out folds or cross-fitting instead.

  • Set a behavior probability to zero for a target-supported action. DR cannot repair missing action support.

Solutions

Selected-action probabilities and ratios:

behavior_action_probabilities = torch.where(
    actions == 1,
    behavior_tool_probability,
    1.0 - behavior_tool_probability,
)

target_action_probabilities = torch.where(
    actions == 1,
    target_tool_probability,
    1.0 - target_tool_probability,
)

log_weights = (
    target_action_probabilities.log()
    - behavior_action_probabilities.log()
)

weights = log_weights.exp()

Direct-model estimate:

target_probabilities_all_actions = (
    torch.stack(
        [
            1.0 - target_tool_probability,
            target_tool_probability,
        ],
        dim=-1,
    )
)

estimated_q_for_contexts = (
    estimated_q[contexts]
)

direct_terms = (
    target_probabilities_all_actions
    * estimated_q_for_contexts
).sum(dim=-1)

direct_estimates = direct_terms.mean(
    dim=1
)

Importance sampling:

is_estimates = (
    weights * rewards
).mean(dim=1)

Doubly robust correction:

estimated_q_for_logged_actions = (
    estimated_q[
        contexts,
        actions,
    ]
)

residuals = (
    rewards
    - estimated_q_for_logged_actions
)

dr_terms = (
    direct_terms
    + weights * residuals
)

dr_estimates = dr_terms.mean(
    dim=1
)

Exact value and diagnostics:

exact_target_value = (
    context_distribution[:, None]
    * target_policy_table
    * true_q
).sum()

biases = (
    all_estimates.mean(dim=0)
    - exact_target_value
)

standard_deviations = (
    all_estimates.std(
        dim=0,
        correction=1,
    )
)

rmses = (
    (
        all_estimates
        - exact_target_value
    )
    .square()
    .mean(dim=0)
    .sqrt()
)

The true target value is:

\[J(\pi)=0.73\]

The inaccurate outcome model predicts:

\[\hat J_{\mathrm{DM}} = \frac12[ 0.2(0.5)+0.8(0.8) + 0.8(0.6)+0.2(0.6) ] = 0.67\]

Therefore, direct modeling has low variance but approximately -0.06 bias.

Because the logged propensities are correct, the weighted residual corrects that model error:

\[\mathbb E[ \rho(R-\hat q) ] = J(\pi)-J_{\mathrm{DM}}\]

IS and DR should both center near 0.73, but DR should have substantially lower variance because its residuals are smaller than raw rewards.

Check answers

  1. More evaluation logs reduce sampling variance but cannot remove systematic error in a fixed \(\hat q\).

  2. Correct behavior propensities or a correct conditional outcome model.

  3. Large importance weights can amplify even small outcome-model residuals.

  4. Freeze the target policy and outcome model; store behavior log-probabilities, masks, conditioning history, rewards, policy versions and episode boundaries.

Retrieval answers

  1. Every action supported by the target policy must also have positive probability under the behavior policy.

  2. Low ESS means a small fraction of logged decisions dominates the estimate, producing high variance and weak coverage.

Takeaway: use the outcome model as a baseline and let importance-weighted observations correct it. DR reduces variance, but it cannot rescue missing support or two simultaneously wrong models.
