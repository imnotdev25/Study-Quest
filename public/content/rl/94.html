🧩 Analogy: ten opinions from one friend

Asking one friend the same question ten times doesn’t give you ten opinions. Turns from the same user are correlated (same writing style, same task, same patience), so 2000 turns from 100 users carry much less information than 2000 independent users.

Effective sample size \(=N/\text{DEFF}\).

2. Ten turns from one user are not ten independent users

Suppose each user completes ten agent episodes. Outcomes from the same user share prompt style, ability, preferences and environment.

They are like ten readings from one thermometer—not ten independent thermometers.

A simple model is:

\[Y_{u,t} = \tau Z_u+b_u+\epsilon_{u,t}\]

where:

  • \(Z_u\) is the user-level policy assignment;

  • \(\tau\) is the policy effect;

  • \(b_u\) is a shared user effect;

  • \(\epsilon_{u,t}\) is episode-specific noise.

The intraclass correlation is:

\[\rho = \frac{\sigma_b^2} {\sigma_b^2+\sigma_\epsilon^2}\]

With \(m\) observations per user, the approximate design effect is:

\[D = 1+(m-1)\rho\]

Therefore:

\[N_{\text{effective}} \approx \frac{N_{\text{rows}}}{D}\]

If \(\rho=0.7\) and every user contributes ten episodes, treating all rows as independent can understate the standard error by roughly:

\[\sqrt{1+9(0.7)} \approx2.7\]

A simple solution for equally sized clusters is:

  1. average outcomes within each user;

  2. compare the independent user means;

  3. use the number of users—not episodes or tokens—for inference.

For unequal cluster sizes or covariate adjustment, use user-clustered sandwich errors or bootstrap complete users.

Tensor shapes:

  • user assignments: [R, U]

  • episode outcomes: [R, U, M]

  • flattened rows: [R, U*M]

  • user-average outcomes: [R, U]

  • effect estimates and standard errors: [R]

For LLM agents, the cluster may be a user, conversation, prompt template, organization or task instance. Use the highest level that shares assignment or latent outcome noise.

DPO preference pairs can also cluster by annotator and prompt family. A large pair count does not imply an equally large independent sample—and DPO training loss still does not replace clustered online outcome evaluation.

🔍 Deeper: clusters set the sample size

With \(m\) turns per user and intra-cluster correlation \(\rho\): \(\mathrm{DEFF}=1+(m-1)\rho\) and \(n_{\text{eff}}=N/\mathrm{DEFF}\). Fixes: randomize whole users (or conversations), compute cluster-robust standard errors or a cluster bootstrap (resample users), and log stable user and conversation IDs.

🔑 Key ideas

  • A million correlated turns aren’t a million experiments.

  • Randomize and resample at the unit that actually received the policy.

🚶 Walkthrough: 2000 turns, 100 users

\(m=20\), ICC \(0.3\): \(\mathrm{DEFF}=1+19(0.3)=6.7\), so \(n_{\text{eff}}\approx299\). The naive SE is \(\sqrt{6.7}=2.6\times\) too small.

Common mistakes

  • Randomizing turns while users see both arms.

  • i.i.d. standard errors on clustered data.

  • Missing user IDs in logs (clustering can’t be fixed later).

Hints

  • Expand user assignments across the episode dimension before flattening.

  • User outcomes are averaged with .mean(dim=-1).

  • The point estimates match because every user contributes the same number of episodes.

  • A two-sided false positive occurs when abs(z_score) > 1.96.

  • The predicted standard-error ratio is design_effect ** 0.5.

Debugging experiments

  • Treat generated tokens as independent evaluation samples.

  • Randomize users but calculate uncertainty from individual turns.

  • Bootstrap rows instead of complete users or conversations.

  • Split one conversation across evaluation folds.

  • Use request ID as the cluster when several requests share one user.

  • Ignore that the candidate changes episode counts through early stopping.

  • Combine users and organizations without checking organization-level correlation.

Solutions

Correlated outcomes and theoretical diagnostics:

user_effects = (
    user_effect_standard_deviation
    * torch.randn(
        num_repetitions,
        num_users,
    )
)

episode_noise = (
    episode_noise_standard_deviation
    * torch.randn(
        num_repetitions,
        num_users,
        episodes_per_user,
    )
)

outcomes = (
    true_effect
    * assignment[:, :, None]
    + user_effects[:, :, None]
    + episode_noise
)

user_variance = (
    user_effect_standard_deviation ** 2
)

episode_variance = (
    episode_noise_standard_deviation ** 2
)

intraclass_correlation = (
    user_variance
    / (
        user_variance
        + episode_variance
    )
)

design_effect = (
    1.0
    + (
        episodes_per_user - 1
    ) * intraclass_correlation
)

effective_episode_count = (
    num_users * episodes_per_user
    / design_effect
)

Naive episode-level calculation:

flat_outcomes = outcomes.reshape(
    num_repetitions,
    -1,
)

flat_assignment = (
    assignment[:, :, None]
    .expand(
        -1,
        -1,
        episodes_per_user,
    )
    .reshape(
        num_repetitions,
        -1,
    )
)

flat_control_assignment = (
    1.0 - flat_assignment
)

candidate_episode_counts = (
    flat_assignment.sum(dim=1)
)

control_episode_counts = (
    flat_control_assignment.sum(dim=1)
)

naive_candidate_means = masked_mean(
    flat_outcomes,
    flat_assignment,
)

naive_control_means = masked_mean(
    flat_outcomes,
    flat_control_assignment,
)

naive_effects = (
    naive_candidate_means
    - naive_control_means
)

naive_standard_errors = torch.sqrt(
    masked_variance(
        flat_outcomes,
        flat_assignment,
    ) / candidate_episode_counts
    +
    masked_variance(
        flat_outcomes,
        flat_control_assignment,
    ) / control_episode_counts
)

User-level calculation:

user_mean_outcomes = outcomes.mean(
    dim=-1
)

control_assignment = (
    1.0 - assignment
)

candidate_user_counts = assignment.sum(
    dim=1
)

control_user_counts = (
    control_assignment.sum(dim=1)
)

cluster_candidate_means = masked_mean(
    user_mean_outcomes,
    assignment,
)

cluster_control_means = masked_mean(
    user_mean_outcomes,
    control_assignment,
)

cluster_effects = (
    cluster_candidate_means
    - cluster_control_means
)

cluster_standard_errors = torch.sqrt(
    masked_variance(
        user_mean_outcomes,
        assignment,
    ) / candidate_user_counts
    +
    masked_variance(
        user_mean_outcomes,
        control_assignment,
    ) / control_user_counts
)

False-positive comparison:

naive_z_scores = (
    naive_effects
    / naive_standard_errors
)

cluster_z_scores = (
    cluster_effects
    / cluster_standard_errors
)

naive_false_positives = (
    naive_z_scores.abs()
    > two_sided_z
)

cluster_false_positives = (
    cluster_z_scores.abs()
    > two_sided_z
)

naive_false_positive_rate = (
    naive_false_positives
    .to(torch.float64)
    .mean()
)

cluster_false_positive_rate = (
    cluster_false_positives
    .to(torch.float64)
    .mean()
)

Diagnostics:

maximum_effect_difference = (
    naive_effects
    - cluster_effects
).abs().max()

mean_naive_standard_error = (
    naive_standard_errors.mean()
)

mean_cluster_standard_error = (
    cluster_standard_errors.mean()
)

empirical_se_ratio = (
    mean_cluster_standard_error
    / mean_naive_standard_error
)

predicted_se_ratio = (
    design_effect ** 0.5
)

Here:

\[\rho = \frac{1.5^2}{1.5^2+1^2} = \frac{2.25}{3.25} \approx0.692\]

Therefore:

\[D = 1+9(0.692) \approx7.23\]

and:

\[\sqrt D\approx2.69\]

Although the dataset contains 2,000 episode rows, their information is approximately:

\[N_{\text{effective}} \approx \frac{2000}{7.23} \approx277\]

Because every user contributes ten episodes, the naive and clustered point estimates are effectively identical. Their uncertainty estimates are not: the naive method counts the shared user effect ten times.

Typical results:

  • mean naive SE: approximately 0.08;

  • mean clustered SE: approximately 0.22;

  • naive false-positive rate: roughly 0.45;

  • clustered false-positive rate: near 0.05.

Check answers

  1. Equal cluster sizes give every user the same weight under either calculation. Clustering changes the estimated number of independent observations, not their mean difference.

  2. It increases with observations per cluster and with within-cluster correlation.

  3. Unequal episode counts, time-varying effects, covariate adjustment, multiple assignment levels or an episode-weighted estimand may require cluster-robust regression or cluster bootstrap.

  4. Randomize at the highest level where carryover or interference is plausible—commonly the user or complete conversation—and analyze uncertainty at that level.

Retrieval answers

  1. Micro averaging weights groups by deployment frequency; macro averaging gives each specified group equal weight.

  2. Simultaneous bounds account for the multiple opportunities to make a false subgroup claim across a prespecified family.

Takeaway: a million correlated turns are not a million independent experiments. Log stable user and conversation identifiers, randomize complete clusters, and make uncertainty reflect the unit that actually received the policy.
