2. Clipping controls variance by changing the estimator

An IPS contribution is:

\[Z_i = \underbrace{w_i}_{\pi(A_i)/\mu(A_i)} \underbrace{R_i}_{\text{observed reward}}\]

A large \(w_i\) makes one episode dominate. Weight clipping replaces it with:

\[\tilde w_i(c) = \underbrace{\min(w_i,c)}_{\text{importance weight capped at }c}\]

giving:

\[\hat V_c = \underbrace{ \frac1N\sum_{i=1}^{N}\tilde w_i(c)R_i }_{\text{clipped importance-sampling estimate}}\]

For nonnegative rewards:

\[V^\pi-E_\mu[\hat V_c] = \underbrace{ E_\mu[(w-c)_+R] }_{\text{expected reward contribution removed by clipping}} \ge 0\]

where:

\[(w-c)_+ = \underbrace{\max(w-c,0)}_{\text{weight mass above the threshold}}\]

If \(0\le R\le R_{\max}\), the bias has the bound:

\[0 \le V^\pi-E_\mu[\hat V_c] \le \underbrace{ R_{\max}E_\mu[(w-c)_+] }_{\text{worst-case omitted tail value}}\]

Lower \(c\) usually means lower variance but greater bias. Therefore, always report a threshold-sensitivity curve rather than one convenient threshold.

This clipping has a different purpose from:

  • PPO clipping: limits policy-update size; it is not unbiased OPE.

  • DPO’s \(\beta\): controls preference strength relative to a reference model; it is not an importance-weight threshold.

  • Reward clipping: changes reward scale and possibly the optimized task.

Tensor shapes:

  • actions, rewards and weights: [R, N]

  • clipped weights and estimates: [R, N, C] and [R, C]

  • threshold diagnostics: [C]

Hints

Broadcast the thresholds over the final dimension:

importance_weights[..., None]
clip_thresholds[None, None, :]

The oracle clipped value is:

\[V_c = \underbrace{ \sum_a \mu(a) \min\left( \frac{\pi(a)}{\mu(a)},c \right) R(a) }_{\text{population expectation of the clipped estimator}}\]

The RMSE is:

\[\operatorname{RMSE} = \underbrace{ \sqrt{ E[(\hat V_c-V^\pi)^2] } }_{\text{combined bias and variance}}\]

For the tail bound, calculate the behavior expectation of (weight - threshold).clamp_min(0).

Debugging experiments

  • Clip weights and label the result “unbiased IPS.”

  • Choose \(c\) after inspecting which threshold gives the preferred conclusion.

  • Report the fraction clipped without reporting how much target mass those rows carry.

  • Normalize clipped weights and assume this removes clipping bias.

  • Backpropagate through an OPE computation that should be a detached evaluation.

  • Compare PPO’s clipped loss directly with a clipped OPE estimate.

Solutions

Logged data:

actions = (
    torch.rand(
        num_repetitions,
        episodes_per_repetition,
    )
    < behavior_policy[1]
).to(torch.long)

rewards = reward_by_action[actions]

importance_weights = (
    target_policy[actions]
    / behavior_policy[actions]
)

exact_target_value = (
    target_policy * reward_by_action
).sum()

Clipped estimates:

clipped_weights = torch.minimum(
    importance_weights[..., None],
    clip_thresholds[None, None, :],
)

clipped_contributions = (
    clipped_weights
    * rewards[..., None]
)

clipped_estimates = (
    clipped_contributions.mean(dim=1)
)

Repeated-sampling diagnostics:

mean_estimates = clipped_estimates.mean(
    dim=0
)

biases = (
    mean_estimates
    - exact_target_value
)

standard_deviations = (
    clipped_estimates.std(
        dim=0,
        correction=1,
    )
)

rmses = (
    (
        clipped_estimates
        - exact_target_value
    )
    .square()
    .mean(dim=0)
    .sqrt()
)

clipped_fractions = (
    (
        importance_weights[..., None]
        > clip_thresholds
    )
    .to(torch.float64)
    .mean(dim=(0, 1))
)

Oracle expectations:

action_importance_weights = (
    target_policy
    / behavior_policy
)

oracle_clipped_action_weights = torch.minimum(
    action_importance_weights[:, None],
    clip_thresholds[None, :],
)

oracle_clipped_values = (
    behavior_policy[:, None]
    * oracle_clipped_action_weights
    * reward_by_action[:, None]
).sum(dim=0)

oracle_downward_biases = (
    exact_target_value
    - oracle_clipped_values
)

Bias bounds:

tail_bias_upper_bounds = (
    behavior_policy[:, None]
    * (
        action_importance_weights[:, None]
        - clip_thresholds[None, :]
    ).clamp_min(0.0)
    * reward_upper_bound
).sum(dim=0)

For \(c=10\):

\[E[\hat V_{10}] = \underbrace{0.01(10)(1)}_{\text{rare action contribution}} = 0.10\]

Only about 1% of logged rows are clipped, but they represent:

\[\underbrace{50\%}_{\text{target probability of rare action}}\]

of the true policy value. Row fraction is therefore a poor measure of clipping impact.

Thresholds near 20–30 have lower RMSE in this finite-sample simulation. That does not make them unbiased, and the best threshold cannot normally be identified because the true value is unknown.

Check answers

  1. Yes. The maximum possible weight is 50, so threshold 50 leaves every weight unchanged.

  2. Approximately 0.10; clipping removes four-fifths of the rare action’s contribution.

  3. About 1%, despite those observations carrying half the target-policy value.

  4. Yes. A deliberate bias can reduce variance enough to lower finite-sample MSE.

  5. Pre-specify thresholds and report the sensitivity curve. Selecting one using final outcomes introduces another layer of selection bias.

Retrieval answers

  1. A bootstrap samples from the empirical distribution. If the rare event is absent, every bootstrap sample also omits it.

  2. ESS measures concentration among observed weights. When all observed episodes are common-action episodes, their identical weights produce maximal ESS even though target mass is missing.

Takeaway: clipping can make OPE numerically calmer, but it does not create information. Treat the threshold as an explicit bias–variance choice, report sensitivity, and collect targeted data when conclusions depend on the clipped tail.
