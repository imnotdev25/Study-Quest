🧩 Analogy: learning to drive from dashcam videos

Suppose you learn to drive only by watching dashcam footage of careful drivers. You’ve never seen anyone floor it at a red light, so you have no evidence about what happens. A naive learner might imagine it’s great. Offline RL has exactly this risk: actions the dataset never tried can look amazing because nothing ever corrected the estimate.

Inside the data (green) the estimate is right. Outside it extrapolates upward, and \(\arg\max_a\) happily picks those imaginary peaks.

2. Learning without new interaction

Online RL can try an action, observe that its value estimate was wrong, and collect corrective data.

Offline RL receives only a fixed dataset:

\[\mathcal D= \{(S_t,A_t,R_{t+1},S_{t+1},D_t)\}\]

The agent cannot request another transition.

Suppose the dataset was generated by behaviour policy \(\mu\), but the learned policy \(\pi\) begins choosing different actions. If those actions are poorly represented in \(\mathcal D\), their values are uncertain. This is distribution shift.

Ordinary Q-learning uses:

\[Y_t = R_{t+1} +\gamma(1-D_t) \max_{a'}Q(S_{t+1},a')\]

The maximum considers every action—including unseen ones. If function approximation accidentally assigns an unseen action a large value, max selects it. That imaginary value then propagates backward through Bellman targets.

It creates a feedback loop:

  1. unseen action receives an erroneous high Q-value;

  2. Bellman backup selects it;

  3. predecessor values become inflated;

  4. the learned policy increasingly prefers unsupported actions;

  5. no online interaction is available to correct the error.

A low TD loss does not detect this: the critic can accurately fit targets that it invented itself.

Coverage and pessimism

The central offline-RL question is:

\[\pi(a\mid s)>0 \quad\Rightarrow\quad \text{does }\mathcal D\text{ adequately cover }(s,a)?\]

Common defenses include:

  • constrain the policy toward the behaviour policy;

  • penalize Q-values for unsupported actions;

  • use uncertainty-aware pessimistic values;

  • compare against a behaviour-cloning baseline.

Today we use an exact support mask. Real continuous or language action spaces rarely provide such a clean binary mask, so this is an illustration rather than a complete algorithm.

Tensor shapes:

  • Q-table and support mask: [states, actions]

  • dataset fields: [N]

  • predictions and targets: [N]

LLM and DPO distinction

A fixed preference dataset also has coverage limits: optimizing far beyond its response distribution can exploit errors in a learned preference model.

DPO uses static chosen/rejected response pairs to adjust relative log-probabilities. It is offline preference optimization, not online RL: it does not interact with an environment, estimate returns, train a critic, or perform Bellman backups.

🔍 Deeper: why it compounds, and three fixes

The Bellman target \(\max_{a'}Q(s',a')\) selects the most overestimated action, including unseen ones. Then that error becomes the label for the previous state, and so on. With no new data, nothing ever corrects it.

Fixes, all of which stay near the data:

  • Policy constraint (e.g. TD3+BC): \(\max_\pi\ \mathbb E[Q(s,\pi(s))]-\lambda\,\|\pi(s)-a_{\mathcal D}\|^2\).

  • Conservative Q (CQL): add \(\alpha\big(\mathbb E_s\log\sum_ae^{Q(s,a)}-\mathbb E_{(s,a)\sim\mathcal D}Q(s,a)\big)\), which pushes unseen actions down and seen ones up.

  • In-sample learning (IQL): never query \(Q\) at unseen actions. It uses an expectile of \(Q(s,a_{\mathcal D})\) as a soft max.

🔑 Key ideas

  • “Estimated good” is not “supported by evidence.”

  • Offline methods make the agent pessimistic about what the data never showed.

🚶 Walkthrough: the CQL penalty

\(Q(s,\cdot)=(1,2,5)\), but the dataset action is \(a_1\) (\(Q=1\)). Action \(a_3\) was never seen. \(\log\sum e^Q=\log(e+e^2+e^5)\approx5.066\). Penalty \(=5.066-1=4.066\). Its gradient \(=\operatorname{softmax}(Q)-e_{a_1}\approx(0.017,0.047,0.936)-(1,0,0)\), which pushes \(Q(a_3)\) down hardest and \(Q(a_1)\) up.

Common mistakes

  • An \(\alpha\) so large that the agent just copies the data.

  • Evaluating with online rollouts while claiming “offline.”

  • Applying the penalty to next-state actions instead of current-state actions.

⚙️ Algorithm: Conservative Q-Learning (CQL), discrete actions
Input: fixed dataset \(\mathcal D\) (no new interaction), network \(Q_\theta\), penalty weight \(\alpha\)
for each training step do
sample a minibatch \((s,a,r,s',d)\) from \(\mathcal D\)
\(y\gets r+\gamma(1-d)\max_{a'}Q_{\theta^-}(s',a')\)
\(L_{\text{TD}}\gets\big(Q_\theta(s,a)-y\big)^2\)
\(L_{\text{CQL}}\gets\log\sum_{a''}\exp Q_\theta(s,a'')-Q_\theta(s,a)\) ▷ push all actions down, data actions up
gradient step on \(L_{\text{TD}}+\alpha L_{\text{CQL}}\); update target \(\theta^-\)
end
return greedy policy \(\pi(s)=\arg\max_aQ_\theta(s,a)\)

Hints

  • Select predictions with q[states, actions].

  • Mask unsupported values using masked_fill.

  • Targets belong inside torch.no_grad().

  • Avoid computing 0 * -inf: it produces nan, which is why terminal rows are handled separately.

Solutions

Ordinary next-state values and targets:

standard_next_values[nonterminal] = (
    q_standard[next_states[nonterminal]]
    .max(dim=-1)
    .values
)

standard_targets = (
    rewards + gamma * standard_next_values
)

standard_predictions = q_standard[
    states, actions
]

Support-constrained backup:

masked_next_q = next_q.masked_fill(
    ~next_support,
    -torch.inf,
)

supported_next_values[nonterminal] = (
    masked_next_q.max(dim=-1).values
)

supported_targets = (
    rewards + gamma * supported_next_values
)

Greedy actions:

standard_greedy = q_standard[:2].argmax(dim=-1)
supported_raw_greedy = q_supported[:2].argmax(dim=-1)

supported_scores = q_supported[:2].masked_fill(
    ~support[:2],
    -torch.inf,
)

supported_greedy = supported_scores.argmax(dim=-1)

Ordinary Q-learning sees the unsupported estimate:

\[Q(1,1)=5\]

and therefore learns:

\[Q(0,0) \rightarrow 0+0.9\max(1,5) = 4.5\]

The support-aware target uses only action 0:

\[Q(0,0) \rightarrow 0+0.9Q(1,0) = 0.9\]

Expected approximate tables:

Ordinary:
[[4.5, 5.0],
 [1.0, 5.0],
 [0.0, 0.0]]

Support-aware:
[[0.9, 5.0],
 [1.0, 5.0],
 [0.0, 0.0]]

Neither loss updates action 1, because it never appears in the dataset. Its value remains 5. Consequently, even the support-aware critic needs a constrained policy or a conservative mechanism: unrestricted argmax still chooses action 1.

Check answers

  1. max preferentially selects positive estimation errors, then bootstrapping copies those errors into earlier states.

  2. Interaction is unavailable; the fixed dataset is the entire source of environmental evidence.

  3. No. TD loss covers dataset transitions, while deployment may choose unsupported actions.

  4. Tokens and complete responses have graded, context-dependent similarity; “supported” is rarely an exact binary property.

Retrieval answers

  1. SAC’s critic is off-policy and can learn from stored transitions generated by earlier actors.

  2. Detachment keeps the bootstrap label fixed instead of allowing gradient descent to move both prediction and target.

Takeaway: offline RL must distinguish “estimated to be good” from “supported by evidence.” Without new interaction, optimism about unseen actions can reinforce itself indefinitely.
