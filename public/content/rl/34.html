2. An LLM agent has actions beyond ordinary tokens

For a tool-using agent, the state includes the prompt and interaction history:

\[S_t= (x,\;y_{<t},\;\text{previous tool calls},\;\text{tool results})\]

An action may be:

  • produce another language token;

  • issue a structured tool call;

  • return the final answer;

  • terminate or ask for clarification.

When the agent calls a tool, the environment executes it and returns an observation:

\[A_t=\texttt{search(query)}\]

\[O_{t+1}=\text{actual search result}\]

The tool result is not an action selected by the policy. It is new environmental evidence used to construct the next state.

A trajectory might be:

\[\text{prompt} \rightarrow \text{search call} \rightarrow \text{search result} \rightarrow \text{database call} \rightarrow \text{database result} \rightarrow \text{answer}\]

Rewards and costs

An agent objective often includes outcome reward and interaction costs:

\[G = R_{\text{success}} - c_{\text{tool}}N_{\text{calls}} - c_{\text{token}}N_{\text{tokens}} - c_{\text{invalid}}N_{\text{invalid}}\]

Without costs, an agent may call tools repeatedly. With excessive costs, it may guess rather than retrieve necessary evidence.

The policy-gradient loss is still:

\[L = -\mathbb E \left[ \hat A \sum_t M_t \log\pi_\theta(A_t\mid S_t) \right]\]

Here \(M_t\) marks actions that actually occurred. Once an episode terminates, later placeholder actions must be masked.

Tool use creates delayed credit: a search call may have immediate cost but enable a correct final answer later.

For batch size \(B\) and maximum two decisions:

  • states and actions: [B, 2]

  • action-validity mask: [B, 2]

  • rewards per step: [B, 2]

  • episode returns: [B]

Why offline demonstrations are not enough

SFT or DPO can teach what a good tool-call trace looks like. They do not, by themselves, let the policy discover how its current calls affect a live environment.

Online agent RL repeatedly:

  1. samples a tool call;

  2. executes it;

  3. observes the real result;

  4. continues from that result;

  5. rewards the final outcome.

Never substitute an imagined tool result for the actual environment response during evaluation.

🔍 Deeper: the trajectory objective

\(\log\pi_\theta(\tau)=\sum_tm_t\log\pi_\theta(\text{token}_t\mid\text{history}_{<t})\), with \(m_t=1\) only on agent-generated tokens. Tool outputs are transitions: \(s_{t+1}=s_t\oplus\text{call}\oplus\text{tool}(\text{call})\).

Reward with costs: \(R=\mathbb 1[\text{correct}]-c\cdot\#\text{tool calls}\). Without \(c\), the agent may learn to search 40 times. With \(c\) too high, it never searches.

Delayed credit: the search call’s credit comes from the final answer several turns later. This is plain REINFORCE/GAE credit assignment across turns, with masks so steps after termination never count.

🔑 Key ideas

  • Agent tokens are actions, and tool outputs are observations.

  • Explicit costs and strict masks define what “good tool use” means.

🚶 Walkthrough: tool cost changes the best plan

One search gives success 0.70. Five searches give 0.80. With cost \(c=0.05\) per call: \(0.70-0.05=0.65\) vs \(0.80-0.25=0.55\), so one call wins. With \(c=0.01\): \(0.69\) vs \(0.75\), so five calls win. The cost defines the trade-off.

Common mistakes

  • Training on tool-output tokens.

  • Tools leaking the answer (for example, search over the test set).

  • Steps after the final answer still counted in returns.

⚙️ Algorithm: Tool-use rollout with an action mask
Input: policy \(\pi_\theta\), tools, max turns \(H\), cost per tool call \(c\)
\(h\gets\) question; mask \(\gets\) all zeros for the question; calls \(\gets0\)
for turn \(=1,\dots,H\) do
generate segment \(g\sim\pi_\theta(\cdot|h)\) until a tool call or a final answer
append \(g\) to \(h\) with mask \(1\) ▷ agent tokens are actions
if \(g\) is a tool call then
\(o\gets\) tool output; append \(o\) to \(h\) with mask \(0\); calls \(\gets\) calls \(+1\) ▷ observation
else
break
end
end
\(R\gets\mathbb 1[\text{answer correct}]-c\cdot\text{calls}\)
train with a masked policy gradient on mask \(=1\) tokens only

3. PyTorch exercise — learn “search, then answer”

There are two states and three actions:

state 0: before searching
state 1: after receiving evidence

action 0: answer
action 1: search
action 2: irrelevant lookup

The successful trajectory is search → answer.

Hints

  • Sample with policy.sample((batch_size,)).

  • The second step occurs only when actions_0 == 1.

  • Use nested torch.where for first-step rewards.

  • Index second_action_rewards using actions_1.

  • Multiply both the second reward and log-probability by step_1_mask.

  • Advantages are fixed trajectory-level credit.

Debugging experiment

Remove the mask:

trajectory_log_probs = (
    log_probs_0 + log_probs_1
)

Now an arbitrary second action receives credit even when the episode terminated after the first action. Training can appear numerically healthy while optimizing actions that never occurred.

Also remove the tool cost:

rewards_0 = torch.zeros(batch_size)

This particular environment may still learn the correct path, but there is no pressure against unnecessary calls. In a larger environment, repeated harmless-looking tool use can become the easiest reward strategy.

Solutions

First decision:

actions_0 = policy_state_0.sample(
    (batch_size,)
)

log_probs_0 = policy_state_0.log_prob(
    actions_0
)

Second-step mask:

step_1_mask = (
    actions_0 == 1
).float()

Second decision:

actions_1 = policy_state_1.sample(
    (batch_size,)
)

log_probs_1 = policy_state_1.log_prob(
    actions_1
)

First-step rewards:

rewards_0 = torch.where(
    actions_0 == 1,
    torch.tensor(-0.05),
    torch.where(
        actions_0 == 2,
        torch.tensor(-0.2),
        torch.tensor(0.0),
    ),
)

Masked second-step rewards:

rewards_1 = (
    second_action_rewards[actions_1]
    * step_1_mask
)

Trajectory log-probabilities:

trajectory_log_probs = (
    log_probs_0
    + step_1_mask * log_probs_1
)

The successful return is:

\[G(\text{search}\rightarrow\text{answer}) = -0.05+1 = 0.95\]

Although search has a negative immediate reward, it enables the later success reward. The same trajectory advantage updates both actions:

\[\hat A \left[ \nabla\log\pi(\text{search}\mid S_0) + \nabla\log\pi(\text{answer}\mid S_1) \right]\]

Training should approach:

state 0: search dominates
state 1: answer dominates

Episodes that answer immediately have step_1_mask = 0. Their sampled second actions contribute neither reward nor gradient.

Check answers

  1. The policy chooses the call, but the external system determines what the call returns.

  2. Otherwise, artificial actions after termination enter the return and policy loss.

  3. The agent may avoid useful tools and guess directly because evidence acquisition becomes too expensive.

  4. Track tool-call count, invalid-call rate, latency, token cost, success per step budget, repeated calls and claimed-versus-verified success.

Retrieval answers

  1. Different tool or token budgets change the opportunity to solve the task, confounding policy quality with inference compute.

  2. The optimizer can successfully exploit a proxy that diverges from intended utility.

Takeaway: tool-use RL trains decisions across an interaction, not just isolated text. Correct trajectories require real observations, delayed credit, explicit costs and strict masks so nonexistent post-termination actions never influence learning.
