🧩 Analogy: shuffled flashcards beat rereading one chapter

If you only study today’s chapter over and over, you get great at today’s chapter and forget last week’s. Shuffled flashcards from the whole course make your learning steadier. A replay buffer is a shuffled flashcard deck of past experience.

Your brain does this too: during sleep, the hippocampus “replays” the day’s experiences. DQN’s replay buffer was partly inspired by that.

Data goes in chronologically and comes out shuffled.

2. Why online neural Q-learning can be unstable

Last session trained on transitions in their observed order:

state 0 → state 1 → state 2 → goal
state 0 → state 1 → ...

Adjacent samples are strongly correlated. It is like studying only today’s last three events instead of shuffling flashcards from many days. Each update pushes the network toward the latest narrow slice of experience.

A replay buffer stores transitions:

\[(S_t,A_t,R_{t+1},S_{t+1},D_t)\]

Training samples random minibatches from this history.

For batch size \(B\):

  • states: [B, features]

  • actions: [B, 1]

  • rewards: [B, 1]

  • next states: [B, features]

  • terminal flags: [B, 1]

  • selected Q-values: [B, 1]

The batched target is:

\[Y_i = R_i+\gamma(1-D_i)\max_{a'}Q_\theta(S'_i,a')\]

and:

\[L(\theta) = \frac1B\sum_{i=1}^{B} \operatorname{Huber}\left( Q_\theta(S_i,A_i)-Y_i \right)\]

What replay provides

  • Less correlation: random batches mix different episodes and states.

  • Data reuse: one expensive environment transition can train the network multiple times.

  • Off-policy data: Q-learning can learn from older exploratory behaviour.

But replay is not automatically unbiased. A buffer can overrepresent common, boring transitions and dilute rare successes. Buffer size, warm-up length and sampling distribution are real hyperparameters.

Is this already DQN?

DQN is neural Q-learning stabilized primarily with:

  1. experience replay;

  2. a separate target network.

Today we add replay. The target still comes from the rapidly changing online network. Next session will separate the target network.

LLM connection

LLM RL also reuses stored prompts, responses, rewards and log-probabilities. But old language-model trajectories can become stale quickly as the policy changes. Later, importance ratios and PPO will make that policy mismatch explicit.

🔍 Deeper: why correlated batches are bad

If a batch of \(B\) gradient samples has variance \(\sigma^2\) and pairwise correlation \(\rho\), then \[\operatorname{Var}\Big[\tfrac1B\textstyle\sum_i g_i\Big]=\frac{\sigma^2}{B}\big(1+(B-1)\rho\big), \qquad B_{\text{eff}}=\frac{B}{1+(B-1)\rho}.\]

Consecutive frames are highly correlated: a batch of 32 can carry the information of about 2 samples.

Why replay needs an off-policy method: old transitions came from an older \(\epsilon\)-greedy policy. Q-learning’s target \(\max_{a'}Q(s',a')\) doesn’t care which policy collected the data, so reusing it is valid. SARSA’s target would be stale.

🔑 Key ideas

  • Replay = decorrelation + data reuse.

  • It works because Q-learning is off-policy.

🚶 Walkthrough: FIFO buffer, capacity 4

Push transitions \(t_1\ldots t_6\) into a buffer of capacity 4: \(t_1,t_2\) are evicted, leaving \(\{t_3,t_4,t_5,t_6\}\). Without replay, a batch of 2 is always \((t_5,t_6)\): two adjacent, correlated frames. With uniform replay, each of the \(\binom42=6\) pairs is equally likely, and only 3 of the 6 are adjacent.

Common mistakes

  • Storing the reset observation as \(s'\) at an episode end.

  • Training before the buffer has a reasonable warm-up size.

  • Storing tensors that still carry gradients (memory blow-up).

⚙️ Algorithm: Neural Q-learning with an experience replay buffer
Input: buffer capacity \(C\), batch size \(B\), warm-up size \(W\), network \(Q_\theta\)
\(\mathcal D\gets\) empty FIFO buffer of capacity \(C\)
for each environment step do
act \(\epsilon\)-greedily; store \((s,a,r,s',d)\) in \(\mathcal D\) ▷ oldest item evicted when full
if \(|\mathcal D|\ge W\) then
sample a minibatch \(\{(s_j,a_j,r_j,s'_j,d_j)\}_{j=1}^B\) uniformly from \(\mathcal D\)
\(y_j\gets r_j+\gamma(1-d_j)\max_{a'}Q_\theta(s'_j,a')\) ▷ no gradient
gradient step on \(\frac1B\sum_j\big(y_j-Q_\theta(s_j,a_j)\big)^2\)
end
end

Solutions

def train_batch():
    batch = random.sample(buffer, batch_size)

    states, actions, rewards, next_states, dones = zip(*batch)

    states = encode(states)
    next_states = encode(next_states)
    actions = torch.tensor(actions).unsqueeze(1)
    rewards = torch.tensor(
        rewards, dtype=torch.float32
    ).unsqueeze(1)
    dones = torch.tensor(
        dones, dtype=torch.float32
    ).unsqueeze(1)

    predictions = q_net(states).gather(1, actions)

    with torch.no_grad():
        best_next_q = (
            q_net(next_states)
            .max(dim=1, keepdim=True)
            .values
        )

        targets = (
            rewards
            + gamma * (1.0 - dones) * best_next_q
        )

    assert predictions.shape == targets.shape == (batch_size, 1)

    loss = nn.functional.smooth_l1_loss(
        predictions,
        targets,
    )

    optimizer.zero_grad()
    loss.backward()
    nn.utils.clip_grad_norm_(q_net.parameters(), 5.0)
    optimizer.step()

    return loss.item()

Store each transition with:

buffer.append(
    (state, action, reward, next_state, done)
)

The greedy actions for nonterminal states should normally be:

state 0: right
state 1: right
state 2: right

The terminal row can contain arbitrary network outputs because no action is taken there. Correct terminal masking prevents those outputs from entering the target.

Check answers

  1. Each transition’s state depends directly on the preceding transition, so nearby samples contain similar information.

  2. Stored transitions can participate in multiple gradient updates.

  3. Its greedy target policy is separate from the behaviour policy that collected the transition.

  4. No. Detaching blocks gradients; the online network’s changing parameters can still produce different target values later.

Retrieval answers

  1. The target is supervision for the current prediction; target-side gradients would let optimization move both sides.

  2. Updating shared parameters for one state can unintentionally change predictions for other states.

Takeaway: Experience replay turns a chronological stream into shuffled training batches. It reduces correlation and reuses data, but the targets are still moving—so DQN needs one more stabilizer: a target network.
