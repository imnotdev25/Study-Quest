🧩 Analogy: averaging two class averages

Class A has 2 students averaging 90. Class B has 30 averaging 60. “The average of the two averages” is 75, but the true average student scored about 62. Gradient accumulation makes the same mistake when each microbatch is averaged on its own and the chunks hold different numbers of tokens.

Averaging each chunk first gives chunk A’s tokens 4\(\times\) the weight of chunk B’s.

2. Gradient accumulation is not automatically exact

Large LLM rollouts rarely fit in one device batch, so they are divided into microbatches.

Suppose the intended objective is a global valid-token mean:

\[L = \frac{ \sum_{i,t}M_{i,t}\ell_{i,t} }{ \sum_{i,t}M_{i,t} }\]

For microbatch \(k\), define:

\[N_k=\sum_{(i,t)\in k}M_{i,t}\ell_{i,t}, \qquad D_k=\sum_{(i,t)\in k}M_{i,t}\]

The correct accumulated loss is:

\[L=\frac{\sum_k N_k}{\sum_k D_k}\]

Therefore, each microbatch may backpropagate:

\[\frac{N_k}{D_{\text{global}}}\]

A common bug averages independently normalized microbatches:

\[L_{\text{naive}} = \frac1K\sum_k\frac{N_k}{D_k}\]

This gives every microbatch equal weight even when one contains two valid tokens and another contains hundreds. It is equivalent only when all \(D_k\) are equal.

The denominator must follow the chosen objective:

  • token mean: number of valid tokens;

  • sequence mean: number of responses;

  • DPO: usually number of preference pairs, after forming each response’s masked sequence log-probability.

In distributed training, workers must agree on the global numerator and denominator. Averaging rank-local means can overweight workers receiving shorter responses.

Tensor shapes:

  • actions and masks: [B, T]

  • token losses: [B, T]

  • microbatch numerator and denominator: scalar

  • accumulated parameter gradient: [num_parameters]

🔍 Deeper: mean of means is not the mean

Chunks \(k=1..K\) with \(n_k\) valid tokens and loss sums \(S_k\). The intended objective is \(\frac{\sum_kS_k}{\sum_kn_k}\). The common bug computes \(\frac1K\sum_k\frac{S_k}{n_k}\). They agree only when all \(n_k\) are equal.

Fix: each chunk backpropagates \(S_k/N\), where \(N=\sum_kn_k\) is the global count of valid tokens (or sequences), computed before the accumulation loop. With data parallelism, \(N\) must be the count summed over all ranks.

🔑 Key ideas

  • Matching the nominal batch size isn’t enough. Match the objective.

  • Accumulate unnormalized sums and divide by one global count.

🚶 Walkthrough: two unequal chunks

Chunk A: 2 tokens with loss 1 each. Chunk B: 8 tokens with loss 3 each. Correct: \(\frac{2+24}{10}=2.6\). Mean of chunk means: \(\frac{1+3}{2}=2.0\).

Common mistakes

  • Dividing by \(K\) and also by \(n_k\).

  • Different ranks normalizing by their own local token counts.

  • Changing microbatch size and seeing “different results” (the bug shows up exactly then).

Hints

  • The mask is positions < lengths[:, None].

  • The global loss divides the sum of both numerators by the sum of both denominators.

  • The naive loss averages numerator / denominator across microbatches.

  • For exact accumulation, divide every numerator by the same global denominator before .backward().

  • PyTorch adds gradients across repeated backward calls unless they are zeroed.

Debugging experiments

Replace the global denominator with the padded tensor size:

global_denominator = actions.numel()

The gradient direction remains unchanged here, but its scale is too small because four nonexistent tokens enter the denominator.

Next, split the long response into several microbatches while leaving the short response alone. Naively averaging local means changes the gradient again—even though the underlying rollout data is identical.

Finally, combine actor and value losses with different normalization rules. Their effective relative weight can change with response lengths, padding rate and microbatch construction even when \(c_V\) remains fixed.

Solutions

Mask:

mask = (
    positions < lengths[:, None]
)

Full-batch loss:

loss = (
    numerators[0] + numerators[1]
) / global_denominator

Naive microbatch loss:

loss = 0.5 * (
    numerators[0] / denominators[0]
    + numerators[1] / denominators[1]
)

Correct accumulation:

for numerator in numerators:
    (
        numerator / global_denominator
    ).backward()

Calculate the gradients:

full_gradient, full_loss = (
    compute_gradient("full_batch")
)

naive_gradient, naive_loss = (
    compute_gradient("naive_microbatch")
)

accumulated_gradient, _ = (
    compute_gradient(
        "correct_accumulation"
    )
)

At uniform probabilities, an action- 0 token contributes loss gradient:

\[[-0.5,\;0.5]\]

while an action- 1 token contributes:

\[[0.5,\;-0.5]\]

The global token mean contains two action- 0 tokens and six action- 1 tokens:

\[g_{\text{global}} = \frac{ 2[-0.5,0.5] + 6[0.5,-0.5] }{8} = [0.25,-0.25]\]

Gradient descent therefore increases the action- 1 logit.

The naive calculation first averages within each response. Each response then contributes equally, so the opposing gradients cancel:

\[g_{\text{naive}}=[0,0]\]

Correct accumulation matches the full-batch gradient because differentiation is linear:

\[\nabla \frac{\sum_kN_k}{D_{\text{global}}} = \sum_k \nabla\frac{N_k}{D_{\text{global}}}\]

Check answers

  1. Its locally normalized gradient receives the same outer weight as a much larger microbatch.

  2. When microbatches have equal objective weight—such as identical valid counts—or their losses have already been scaled by their proper global weights.

  3. Different splits can change local denominators, padding composition or optimizer-step frequency, making naive accumulation optimize a different weighted objective.

  4. Log valid tokens and responses per microbatch/rank, loss numerators, denominators, accumulated gradient norm and results across alternative batch partitions.

Retrieval answers

  1. Shared parameters receive \(g_\pi+c_Vg_V\). If the weighted critic gradient dominates and conflicts with the actor gradient, the combined update can move against the actor.

  2. Padding represents no executed action. Including it creates fictitious loss terms or dilutes real gradients through an inflated denominator.

Takeaway: matching the nominal batch size is insufficient. To reproduce the intended objective, accumulate unnormalized loss contributions and divide by the correct global count.
