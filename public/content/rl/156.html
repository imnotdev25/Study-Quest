2. The old policy and reference policy have different jobs

LLM PPO commonly keeps two frozen models:

  • \(\pi_{\text{old}}\): the snapshot that generated the current rollouts;

  • \(\pi_{\text{ref}}\): usually the original SFT policy.

Think of the old policy as a step-size ruler and the reference policy as a behavioural anchor.

The PPO update ratio is:

\[\rho_t = \underbrace{ \frac{\pi_\theta(a_t\mid s_t)} {\pi_{\text{old}}(a_t\mid s_t)} }_{\text{movement during this PPO update}}\]

Its KL diagnostic is typically:

\[D_{\mathrm{update}} = \underbrace{ D_{\mathrm{KL}} \left( \pi_{\text{old}}\Vert\pi_\theta \right) }_{\text{have PPO epochs moved too far?}}\]

Reference regularization instead measures:

\[D_{\mathrm{ref}} = \underbrace{ D_{\mathrm{KL}} \left( \pi_\theta\Vert\pi_{\text{ref}} \right) }_{\text{has the policy drifted far from SFT?}}\]

A policy can be very close to \(\pi_{\text{old}}\) while both are already far from \(\pi_{\text{ref}}\).

A common rollout-time KL reward is:

\[k_t = \underbrace{ \log\pi_{\text{old}}(a_t\mid s_t) - \log\pi_{\text{ref}}(a_t\mid s_t) }_{\text{sampled reference log-ratio}}\]

\[r_t^{\text{shaped}} = \underbrace{r_t^{\text{task}}}_{\text{reward-model or verifier reward}} - \underbrace{\beta k_t}_{\text{reference-drift cost}}\]

Individual sampled \(k_t\) values may be negative. Their expectation under the policy is a nonnegative KL.

An adaptive controller can update \(\beta\):

\[e = \underbrace{ \frac{\widehat D_{\mathrm{ref}}} {D_{\mathrm{target}}}-1 }_{\substack{>0:\text{ too far from reference}\\<0:\text{ overly constrained}}}\]

\[\beta \leftarrow \underbrace{ \beta\exp\!\left( \eta_\beta\operatorname{clip}(e,-c,c) \right) }_{\text{smooth positive update}}\]

Do not simultaneously apply this rollout reward penalty and the same differentiable KL penalty again in the actor loss unless double regularization is intentional.

DPO also uses policy-versus-reference log-ratios, but its \(\beta_{\text{DPO}}\) scales a preference-classification margin. It is not PPO’s old-policy ratio or automatically an adaptive KL controller.

Shapes:

  • logits: [B, T, V]

  • sampled tokens and chosen log-probabilities: [B, T]

  • token KL rewards and masks: [B, T]

  • KL means and \(\beta\): scalar []

Solutions

Masked mean and categorical KL:

def masked_mean(values, mask):
    return (
        values * mask
    ).sum() / mask.sum()


def categorical_kl(
    p_logits,
    q_logits,
):
    p_log_probabilities = torch.log_softmax(
        p_logits,
        dim=-1,
    )

    q_log_probabilities = torch.log_softmax(
        q_logits,
        dim=-1,
    )

    p_probabilities = torch.exp(
        p_log_probabilities
    )

    return (
        p_probabilities
        * (
            p_log_probabilities
            - q_log_probabilities
        )
    ).sum(dim=-1)

Frozen rollout data:

with torch.no_grad():
    actions = old_distribution.sample()

    old_chosen_log_probabilities = (
        old_distribution.log_prob(actions)
    )

    reference_chosen_log_probabilities = (
        reference_distribution.log_prob(
            actions
        )
    )

Exact and sampled KLs:

update_kl_tokens = categorical_kl(
    old_logits,
    new_logits,
)

reference_kl_tokens = categorical_kl(
    new_logits,
    reference_logits,
)

mean_update_kl = masked_mean(
    update_kl_tokens,
    valid_mask,
)

mean_reference_kl = masked_mean(
    reference_kl_tokens,
    valid_mask,
)

sampled_reference_log_ratios = (
    old_chosen_log_probabilities
    - reference_chosen_log_probabilities
) * valid_mask

sampled_reference_kl = masked_mean(
    sampled_reference_log_ratios,
    valid_mask,
)

negative_sample_fraction = masked_mean(
    (
        sampled_reference_log_ratios < 0.0
    ).to(torch.float64),
    valid_mask,
)

KL-shaped rewards:

shaped_rewards = (
    task_rewards
    - kl_coefficient
    * sampled_reference_log_ratios
) * valid_mask

task_sequence_rewards = (
    task_rewards * valid_mask
).sum(dim=1)

shaped_sequence_rewards = (
    shaped_rewards * valid_mask
).sum(dim=1)

Independent controllers:

ppo_should_stop = (
    mean_update_kl
    > update_kl_target
)

relative_reference_error = (
    sampled_reference_kl
    / reference_kl_target
    - 1.0
)

clipped_controller_error = (
    relative_reference_error.clamp(
        -controller_error_clip,
        controller_error_clip,
    )
)

updated_kl_coefficient = (
    kl_coefficient
    * torch.exp(
        controller_lr
        * clipped_controller_error
    )
)

The intended pattern is:

\[\underbrace{ D_{\mathrm{KL}}(\pi_{\text{old}}\Vert\pi_{\text{new}}) }_{\text{one small PPO step}} <0.01\]

while:

\[\underbrace{ D_{\mathrm{KL}}(\pi_{\text{new}}\Vert\pi_{\text{ref}}) }_{\text{accumulated drift across rollouts}} >0.25\]

Thus PPO epochs can continue according to the update-KL rule while the reference controller independently increases \(\beta\).

Check answers

  1. Each rollout can make a small step, while many previous rollout updates have accumulated substantial reference drift.

  2. A sampled action may be more likely under the reference policy. Only the expectation under the policy equals a nonnegative KL.

  3. Ratios no longer compare against the policy that generated the data, invalidating PPO’s importance correction.

  4. No. KL only limits distributional drift; a nearby reference policy can itself be incorrect or unsafe.

Retrieval answers

  1. Target-KL stopping measures and limits observed movement but does not solve a formally constrained trust-region optimization.

  2. Repeating the update would count the same cost observations multiple times and distort the dual dynamics.

Takeaway: LLM PPO has two separate anchors. The old policy controls how far one optimization phase moves; the reference policy controls cumulative drift from SFT. Monitor and tune them independently.
