🧩 Analogy: a calorie budget, not a per-meal ban

“Average about 2000 calories a day” is a budget: a big dinner is fine if lunch was light. That’s an expected constraint, and a Lagrangian handles it well. It doesn’t stop one terrible day, though. For that you need a hard limit (Topic 73).

2. An adaptive price for expensive actions

Suppose tool use improves answers but must satisfy an average cost budget \(d\). This is a constrained MDP:

\[\max_\theta J_R(\theta) \quad\text{subject to}\quad J_C(\theta)\le d\]

A fixed shaped reward such as \(r-0.2c\) expresses one trade-off, but does not guarantee any particular budget.

Instead introduce a nonnegative multiplier \(\lambda\):

\[\mathcal L(\theta,\lambda) = J_R(\theta) - \lambda\left(J_C(\theta)-d\right)\]

Think of \(\lambda\) as the price of tool usage:

  • cost above budget: increase the price;

  • cost below budget: decrease the price;

  • \(\lambda\ge0\): never reward violations with a negative price.

For sampled policy gradients, the actor uses:

\[L_\pi = -\mathbb E\left[ \log\pi_\theta(a_t\mid s_t) \left( \hat A_t^R-\lambda\hat A_t^C \right) \right]\]

The dual update is:

\[\lambda \leftarrow \left[ \lambda+\eta_\lambda(J_C-d) \right]_+\]

Detach \(\lambda\) during the actor update and detach the measured cost during the dual update. These are alternating optimization steps.

An expected-cost constraint does not guarantee that every trajectory respects the budget. Strict per-request limits still need environment enforcement, action masks or forced termination.

Tensor shapes in a rollout implementation:

  • rewards, costs and masks: [B, T]

  • reward and cost advantages: [B, T]

  • sequence costs: [B]

  • multiplier \(\lambda\): scalar

DPO can prefer cheaper traces in fixed comparison data, but it does not automatically enforce a live tool budget or adapt a multiplier from new interactions.

🔍 Deeper: what the multiplier means

For \(\max_\pi J_R(\pi)\) s.t. \(J_C(\pi)\le d\), the optimal multiplier satisfies \(\lambda^*=\partial J_R^*/\partial d\): the reward gained per extra unit of budget.

  • \(\lambda^*=0\): the constraint isn’t binding (you’re under budget anyway).

  • Large \(\lambda^*\): the budget is expensive, and loosening it would buy a lot.

Dynamics: plain dual ascent oscillates if \(\eta_\lambda\) is too large. PID-style updates (adding a damping term on \(\Delta\hat C\)) are a common fix. And the constraint holds on average: some episodes can still exceed \(d\).

🔑 Key ideas

  • A Lagrangian enforces averages, not per-episode limits.

  • \(\lambda\) is a price, and you should log it like a metric.

🚶 Walkthrough: reading \(\lambda\)

\(\lambda=0.8\) at convergence: one more expensive-tool call per episode on average would buy about \(0.8\) reward. If a call costs you $0.50 and a reward unit is worth $1, the budget is too tight.

Common mistakes

  • Expecting a Lagrangian to guarantee every episode is under budget.

  • Resetting \(\lambda\) to 0 at each training restart.

  • Normalizing cost advantages together with reward advantages.

3. PyTorch exercise — enforce an average expensive-tool budget

  • action 0: direct answer, reward 0.5, cost 0;

The expensive action may be used only 30% of the time on average.

Hints

  • Use logits.softmax(dim=-1).

  • Clamp probabilities before taking log.

  • Entropy is -(p * log_p).sum().

  • Maximization becomes minimization by negating the objective.

  • Actor objective is reward minus price times budget violation, plus entropy.

  • Update with lambda += dual_lr * (cost - budget).

  • Project using clamp_(min=0.0).

Debugging experiments

Hold lambda_value fixed at zero. The constrained policy becomes unconstrained and nearly always uses the expensive tool.

Reverse the dual-update sign. Violations then decrease the price, making the violation progressively worse.

Remove the nonnegative projection. A sufficiently under-budget policy can make \(\lambda<0\), turning tool cost into a bonus.

Increase the dual learning rate substantially. Cost and \(\lambda\) may oscillate; inspect a moving average rather than trusting one final step.

4. Checks for understanding

  1. Why doesn’t a fixed cost penalty guarantee a target budget?

  2. Why separate actor and multiplier gradients?

  3. Does satisfying expected cost prevent individual expensive trajectories?

  4. What should a constrained-RL training dashboard report?

Solutions

Policy statistics:

probabilities = logits.softmax(
    dim=-1
)

log_probabilities = (
    probabilities.clamp_min(1e-12).log()
)

entropy = -(
    probabilities * log_probabilities
).sum()

expected_reward = (
    probabilities * rewards
).sum()

expected_cost = (
    probabilities * costs
).sum()

Unconstrained loss:

unconstrained_loss = -(
    unconstrained_reward
    + entropy_coefficient
    * unconstrained_entropy
)

Constrained actor:

actor_objective = (
    expected_reward
    - lambda_value.detach()
    * (expected_cost - budget)
    + entropy_coefficient
    * constrained_entropy
)

actor_loss = -actor_objective

Projected multiplier update:

updated_probs = constrained_logits.softmax(
    dim=-1
)

observed_cost = (
    updated_probs * costs
).sum()

lambda_value.add_(
    dual_learning_rate
    * (observed_cost - budget)
)

lambda_value.clamp_(
    min=0.0
)

Final diagnostics:

final_unconstrained = policy_statistics(
    unconstrained_logits
)

final_constrained = policy_statistics(
    constrained_logits
)

recent_average_cost = torch.stack(
    recent_costs
).mean()

The unconstrained policy should assign nearly all probability to the expensive action:

\[P(a=1)\approx1\]

The constrained policy should approach:

\[P(a=1)\approx0.30\]

because its expected cost equals that probability. With entropy coefficient 0.05, the equilibrium multiplier is approximately:

\[\lambda = 0.5+ 0.05\log\frac{0.7}{0.3} \approx0.542\]

Small primal-dual oscillations are normal; the recent average is often more informative than the final step.

Check answers

  1. A fixed penalty specifies a trade-off whose resulting cost changes with rewards, policies and environment distribution.

  2. The actor optimizes behavior at the current price; the dual update adjusts that price from detached constraint measurements.

  3. No. An average constraint permits individual violations. Hard per-request budgets require environment enforcement.

  4. Raw reward, raw cost, budget violation, \(\lambda\), action frequencies, cost quantiles, moving-average cost and reward/cost gradient norms.

Retrieval answers

  1. The manager sampled the option once. Repeating its log-probability incorrectly weights long options more heavily.

  2. Manager advantage evaluates which option was chosen; worker advantage evaluates how well each internal action executed it.

Takeaway: treat limited tool usage as a measurable constraint. Let violations raise an adaptive price, but enforce hard per-request limits in the environment.
