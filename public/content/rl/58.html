2. Optimizing a proxy changes its error distribution

Let \(U(y)\) be the behavior we actually want and \(R(y)\) the available reward:

\[R(y)=U(y)+e(y)\]

Ordinary evaluation samples outputs and measures their errors. RL does something stronger:

\[\theta_{k+1} = \theta_k + \alpha\nabla_\theta \mathbb E_{y\sim\pi_\theta}[R(y)]\]

The policy actively searches for outputs with high \(R\). If some behaviors receive positive reward-model error \(e(y)\), optimization can concentrate probability on them.

Consequently, training may show:

\[R(\pi_{\theta_k})\uparrow \qquad\text{while}\qquad U(\pi_{\theta_k})\downarrow\]

This is reward overoptimization. It resembles repeatedly studying the exact answer key: answer-key performance keeps improving, while general understanding may peak and then decline.

Practical responses include:

  • checkpoint using an independent validation signal;

  • stop when proxy and held-out evaluation diverge;

  • constrain movement using KL regularization;

  • diversify rewards and adversarially test high-reward outputs;

  • inspect reward components rather than only their sum.

KL regularization can reduce search pressure, but it cannot make an incorrect reward correct.

DPO can similarly overfit fixed preferences, although it does not perform online reward search. Use held-out preference data and independent capability and safety evaluations.

Tensor shapes:

  • policy parameter: [1]

  • behavior, proxy reward and true utility: scalar

  • training histories: [steps]

  • real LLM rollout rewards: usually [B] or [B, T]

🔍 Deeper: the shape of overoptimization

Gao et al. (2022) fit true (gold) reward as a function of \(d=\sqrt{\mathrm{KL}(\pi\|\pi_{\text{ref}})}\): best-of-\(N\): \(R(d)=d(\alpha-\beta d)\). RL: \(R(d)=d(\alpha-\beta\log d)\). Both rise, peak and fall, while the proxy keeps rising. Selection is also optimization: choosing the best of 20 checkpoints on one held-out set overstates the winner (Topic 102). Use one set to select and a fresh set to confirm.

🔑 Key ideas

  • Save checkpoints by independent quality, not training reward.

  • Proxy up with held-out flat or down is a failure signal.

🚶 Walkthrough: choose a checkpoint

Proxy \((0.60,0.75,0.85)\), held-out \((0.55,0.62,0.58)\). Pick checkpoint 2 by held-out. Then confirm on a fresh set: say \(0.60\), a bit lower, which is the winner’s curse at work.

Common mistakes

  • Early stopping on training reward.

  • A held-out “judge” that’s the same reward model.

  • Reporting the selection-set score as final.

Debugging experiments

Use loss = proxy_reward. Gradient descent now minimizes reward—the classic policy-gradient sign error.

Remove the sigmoid constraint. Because the exploitable cubic term eventually dominates, optimization may run toward enormous values or numerical overflow.

Add a reference penalty:

reference_behavior = 1.0
kl_like_penalty = 0.5 * (
    behavior - reference_behavior
).square()

regularized_reward = (
    proxy_reward
    - beta * kl_like_penalty
)

Try several beta values. Stronger regularization slows drift, but an excessive value can also prevent genuine improvement.

Finally, select the checkpoint using proxy reward. It will favor the most exploited model, demonstrating why the training signal cannot serve as an independent stopping criterion.

The true utility is:

\[U(x)=-(x-2)^2\]

so its maximum occurs at:

\[x=2\]

The proxy is:

\[R(x)=-(x-2)^2+0.12x^3\]

Its derivative is:

\[R'(x) = -2(x-2)+0.36x^2\]

This derivative is positive throughout the allowed interval, so proxy optimization keeps pushing behavior toward 6. After passing 2, true utility declines even though proxy reward continues improving.

Check answers

  1. Aggregate reward-model accuracy measures typical fixed-distribution examples; optimization searches specifically for rare, systematically over-scored outputs.

  2. No. It may indicate real improvement, reward-scale drift, evaluator exploitation or a masking and normalization bug.

  3. Training reward continues rising while independent evaluation peaks, plateaus or declines; reward-model disagreement and unusual high-reward behaviors may also increase.

  4. KL limits distance from the reference, not error in the reward. Within the permitted region, the policy can still exploit misspecification.

Retrieval answers

  1. Selection favors candidates combining genuine quality with unusually positive reward noise; the selected noise is therefore no longer zero-mean.

  2. Reusing the selection model preserves its optimistic errors. An independent evaluator supplies a less selection-biased estimate.

Takeaway: save checkpoints by independent quality, not only training reward. When proxy reward rises faster than held-out performance—or moves in the opposite direction—treat it as a training failure signal, not progress.
