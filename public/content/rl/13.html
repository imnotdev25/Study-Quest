🧩 Analogy: a football team after a win

After a 2–1 win, everyone gets credit, including the defender who made a terrible pass. Over many games, the good passes show up in wins more often, so credit sorts itself out on average. That’s REINFORCE: slow and noisy, but correct on average.

One rule makes it smarter: a goal in minute 80 can’t be caused by a pass in minute 85. Each action only gets credit for the rewards after it (“reward-to-go”).

Reward-to-go: each action is credited only with the rewards that come after it.

2. From one action to a trajectory

A bandit has one decision. In an MDP, the policy produces a sequence:

\[\tau=(S_0,A_0,R_1,S_1,A_1,R_2,\ldots)\]

REINFORCE is a Monte Carlo policy-gradient algorithm. It waits until an episode finishes, computes returns, and reinforces each action using what happened afterward.

The return-to-go is:

\[G_t = R_{t+1} +\gamma R_{t+2} +\gamma^2R_{t+3} +\cdots\]

The loss is:

\[L_{\text{policy}} = -\frac1B \sum_{b=1}^{B} \sum_{t=0}^{T-1} G_{b,t}\log\pi_\theta(A_{b,t}\mid S_{b,t})\]

Why use return-to-go?

Imagine a two-stage project:

  1. choose a research direction;

  2. choose an evaluation method;

  3. receive a final paper score.

The final score contains information about both earlier decisions, although it does not tell us precisely which one deserves credit.

An action at time \(t\) should be influenced only by rewards after that action. Past rewards cannot be caused by a later action. Therefore, use \(G_t\), not the episode’s total reward including the past.

When reward appears only at the end and \(\gamma=1\), every action receives the same return. This is valid but blunt credit assignment.

REINFORCE is conceptually clean but noisy. Baselines and critics will reduce that variance in later sessions.

Tensor shapes

For a batch of fixed-length trajectories:

  • logits: [B, T, actions]

  • actions: [B, T]

  • log-probabilities: [B, T]

  • rewards: [B, T]

  • returns: [B, T]

  • loss: scalar

LLM connection

For an autoregressive LLM:

  • state: prompt plus current prefix;

  • action: sampled next token;

  • trajectory: complete response;

  • terminal reward: response-level score.

A basic sequence-level REINFORCE loss resembles:

\[-R(y)\sum_t \log\pi_\theta(y_t\mid x,y_{<t})\]

This assigns the final score to every generated token. Later methods add critics, token masks, KL penalties and more refined credit signals.

🔍 Deeper: why dropping past rewards is free

REINFORCE: \(\nabla J=\mathbb E\Big[\sum_t\nabla\log\pi(a_t|s_t)\,G_t\Big]\), with \(G_t=\sum_{t'\ge t}\gamma^{t'-t}r_{t'+1}\).

Proof sketch. A reward \(r\) that arrived before \(a_t\) was chosen is fixed given \(s_t\). Then \(\mathbb E\big[r\,\nabla\log\pi(a_t|s_t)\mid s_t\big]=r\sum_a\pi(a|s_t)\nabla\log\pi(a|s_t)=r\,\nabla\sum_a\pi(a|s_t)=r\nabla1=0\). So past rewards add only noise. Removing them keeps the gradient unbiased and lowers the variance.

Variance grows with length: the estimator sums \(T\) noisy terms, each multiplied by a noisy return. Long episodes mean much noisier gradients, which motivates baselines next.

🔑 Key ideas

  • Every action’s log-probability is weighted by its reward-to-go.

  • Unbiased, but high variance. That’s the problem the next three topics attack.

🚶 Walkthrough: same total, different credit

Two-step episode, \(\gamma=1\), \(\pi(a_0)=0.5\), \(\pi(a_1)=0.8\).

  • Rewards \((0,1)\): \(G_0=1,G_1=1\). Both actions get credit.

  • Rewards \((1,0)\): \(G_0=1,G_1=0\). Only \(a_0\) gets credit, since \(a_1\) came after the reward.

Loss for the first case: \(-(1\cdot\ln0.5+1\cdot\ln0.8)=0.693+0.223=0.916\).

Common mistakes

  • Using the full-episode return \(G_0\) for every step.

  • Averaging over steps in one episode but summing in another.

  • Not detaching \(G_t\) (it shouldn’t need gradients, but some code builds it from network outputs).

⚙️ Algorithm: REINFORCE
Input: policy \(\pi_\theta\), learning rate \(\eta\), discount \(\gamma\)
for each iteration do
collect episodes \(\tau=(s_0,a_0,r_1,\dots,s_T)\) by following \(\pi_\theta\)
compute reward-to-go \(G_t\) backward (Topic 3)
\(\mathcal L(\theta)\gets-\frac{1}{\#\text{episodes}}\sum_\tau\sum_t\log\pi_\theta(a_t|s_t)\,G_t\)
\(\theta\gets\theta-\eta\nabla_\theta\mathcal L\)
end

-(log_probs * returns).sum(dim=1).mean()

Debugging experiment

Replace:

returns[:, t] = running_return

with:

returns[:, t] = rewards[:, t]

The first action then receives zero learning signal because its immediate reward is always zero. The policy cannot learn that the first decision contributes to final success.

4. Checks for understanding

  1. Why does the first action receive the terminal reward in its return?

  2. Why should rewards that occurred before action \(A_t\) not weight its log-probability?

  3. Why are unsuccessful trajectories unchanged in this particular zero-reward setup?

  4. Why can REINFORCE have high variance?

Solutions

actions = policy.sample()
log_probs = policy.log_prob(actions)

Return calculation:

for t in reversed(range(num_steps)):
    running_return = (
        rewards[:, t]
        + gamma * running_return
    )
    returns[:, t] = running_return

Policy loss:

loss = -(
    log_probs * returns.detach()
).sum(dim=1).mean()

Initially, every action has probability \(0.5\), so:

\[P(\text{success}) = 0.5\times0.5 = 0.25\]

For a successful episode:

rewards = [0, 1]
returns = [1, 1]

For an unsuccessful episode:

rewards = [0, 0]
returns = [0, 0]

Both step-specific policies should eventually assign high probability to action 1.

Notice a limitation: unsuccessful trajectories produce zero gradient here. The algorithm reinforces successes but does not explicitly push away from failures. A negative failure reward or a baseline can provide a more informative signal.

If \(\gamma=0.5\), a successful trajectory has:

returns = [0.5, 1.0]

The earlier action receives a weaker signal.

Check answers

  1. The first action can influence whether the final successful trajectory occurs, so the terminal reward is part of its future return.

  2. A later action cannot causally change an already observed reward.

  3. Their return is zero, making return × log_prob zero.

  4. Different sampled trajectories can receive very different returns, producing noisy gradient estimates.

Retrieval answers

  1. Its sampled reward—or, in sequential RL, its future return.

  2. Optimizers minimize losses, while the policy objective maximizes expected return.

Takeaway: REINFORCE turns a completed trajectory into training data by multiplying each action’s log-probability by its future return. It solves delayed credit assignment, but only coarsely and with high variance.
