🧩 Analogy: rating the starter, not the dessert

If you rate a chef’s starter, your rating shouldn’t change based on which dessert was served afterwards. The dessert came later. Per-decision IS applies that to rewards: a reward earned at step \(t\) is reweighted only by the actions taken up to step \(t\).

2. Use only the ratios relevant to each reward

Logged trajectories come from behavior policy \(\mu\), while we want to evaluate target policy \(\pi\).

Full-trajectory importance sampling uses:

\[W_{0:T-1} = \prod_{k=0}^{T-1} \frac{\pi(A_k\mid S_k)} {\mu(A_k\mid S_k)}\]

and estimates:

\[\hat V_{\text{trajectory}} = \frac1N\sum_i W_{0:T-1}^{(i)}G_i\]

The problem is that a reward received at time \(t=0\) cannot be affected by actions taken at \(t=1\) or \(t=2\). Yet trajectory IS multiplies that early reward by their ratios.

Per-decision importance sampling instead uses only ratios up to each reward:

\[W_{0:t} = \prod_{k=0}^{t} \frac{\pi(A_k\mid S_k)} {\mu(A_k\mid S_k)}\]

\[\hat V_{\text{PDIS}} = \frac1N \sum_i \sum_{t=0}^{T-1} \gamma^t W_{0:t}^{(i)} R_{i,t}\]

This is like correcting receipts individually: the first purchase is corrected using the first decision, not decisions made later in the shopping trip.

Compute cumulative weights in log space:

\[\log W_{0:t} = \sum_{k=0}^{t} \left[ \log\pi(A_k\mid S_k) - \log\mu(A_k\mid S_k) \right]\]

cumulative_log_weights = step_log_ratios.cumsum(dim=-1)
cumulative_weights = cumulative_log_weights.exp()

PDIS remains vulnerable to large weights late in long trajectories, but early rewards avoid unnecessary future ratios.

Important limit: if all reward arrives at the final step, PDIS and trajectory IS become identical.

Tensor shapes:

  • actions, rewards, step log-ratios: [trials, B, T]

  • cumulative weights: [trials, B, T]

  • estimates across repeated trials: [trials]

DPO does not use these estimators: it optimizes fixed preference comparisons rather than estimating environment return from behavior-policy logs.

🔍 Deeper: why future ratios can be dropped

Trajectory IS: \(\rho_{0:T-1}\sum_t\gamma^tr_{t+1}\). Per-decision IS: \[\hat V_{\text{PDIS}}=\frac1N\sum_i\sum_t\gamma^t\,\rho^{(i)}_{0:t}\,r^{(i)}_{t+1},\qquad\rho_{0:t}=\prod_{k=0}^t\frac{\pi(a_k|s_k)}{b(a_k|s_k)}.\] Why it’s still unbiased: given everything up to the reward \(r_{t+1}\), each later ratio has conditional expectation \(\mathbb E_b[\pi(a|s)/b(a|s)\mid s]=\sum_ab(a|s)\frac{\pi(a|s)}{b(a|s)}=1\). Multiplying \(r_{t+1}\) by those future ratios adds noise with mean 1: no bias removed, only variance added. So PDIS drops them.

Early rewards now get short products, which means less variance, especially for long trajectories.

🔑 Key ideas

  • Weight each reward by the ratios that could have caused it, and no more.

  • Same expectation as trajectory IS, usually far lower variance.

🚶 Walkthrough: trajectory IS vs PDIS

Two steps, \(\gamma=1\), ratios \(\rho_0=2,\rho_1=0.5\), rewards \(r_1=1,r_2=1\). Trajectory IS: \(2\cdot0.5\cdot(1+1)=2.0\). PDIS: \(2\cdot1+(2\cdot0.5)\cdot1=3.0\). Different numbers on one sample, but both have the same expectation. PDIS has lower variance on average.

Common mistakes

  • Applying \(\rho_{t+1}\) to \(r_{t+1}\) (off by one).

  • Not resetting the product at a new episode.

  • Reporting PDIS without ESS diagnostics.

⚙️ Algorithm: Per-decision importance sampling (PDIS)
Input: logged trajectories, target \(\pi\), logging policy \(b\), discount \(\gamma\)
for each trajectory \(i\) do
\(\rho\gets1,\ \hat V_i\gets0\)
for \(t=0,\dots,T-1\) do
\(\rho\gets\rho\cdot\pi(a_t|s_t)/b(a_t|s_t)\) ▷ only ratios up to this step
\(\hat V_i\gets\hat V_i+\gamma^t\rho\,r_{t+1}\)
end
end
return \(\frac1N\sum_i\hat V_i\)

Debugging experiments

Reverse the log-ratio:

step_log_ratios = (
    behavior_log_probs[actions]
    - target_log_probs[actions]
)

The estimator now reweights target behavior toward the logging policy—the opposite of the required correction.

Next, move all reward to the last step:

rewards = torch.zeros_like(rewards)
rewards[..., -1] = (
    actions[..., -1] == 1
).float()
returns = rewards.sum(dim=-1)

PDIS and trajectory IS now use the same final cumulative weight and should match.

For variable-length agent traces, introduce a mask:

step_log_ratios = step_log_ratios * trajectory_mask
rewards = rewards * trajectory_mask

Post-termination placeholder actions must affect neither cumulative weights nor rewards.

4. Checks for understanding

  1. Why are future action ratios unnecessary for an earlier reward?

  2. Does PDIS completely solve importance-weight variance?

  3. When are PDIS and trajectory IS identical?

  4. What happens if cumulative log-weights are exponentiated after hundreds of large token-level ratios?

Solutions

Step log-ratios:

step_log_ratios = (
    target_log_probs[actions]
    - behavior_log_probs[actions]
)

Cumulative weights:

cumulative_log_weights = (
    step_log_ratios.cumsum(dim=-1)
)

cumulative_weights = (
    cumulative_log_weights.exp()
)

Full trajectory weights:

trajectory_weights = (
    cumulative_weights[..., -1]
)

PDIS estimates:

pdis_estimates = (
    cumulative_weights * rewards
).sum(dim=-1).mean(dim=1)

Trial comparison:

trajectory_errors = (
    trajectory_estimates
    - true_target_value
).abs()

pdis_errors = (
    pdis_estimates
    - true_target_value
).abs()

pdis_wins = (
    pdis_errors < trajectory_errors
).float().mean()

The behavior policy’s expected logged return is:

\[3(0.2)=0.6\]

The target policy’s expected return is:

\[3(0.7)=2.1\]

Both IS estimators should average near \(2.1\) across repeated datasets. PDIS should normally have lower variance because the first reward uses one ratio, the second uses two, and only the final reward uses all three.

A selected action 1 has ratio:

\[\frac{0.7}{0.2}=3.5\]

Therefore, the largest final weight is:

\[3.5^3=42.875\]

A rare [1,1,1] behavior-policy trajectory consequently receives substantial influence.

Check answers

  1. Future actions cannot causally change a reward that has already been observed; their ratios add variance without correcting its distribution.

  2. No. Later cumulative products can still become extreme, especially for long trajectories or distant policies.

  3. When reward exists only at the final step, both multiply it by the full trajectory ratio.

  4. The exponential may overflow, while other trajectories underflow toward zero. Accumulate in log space, inspect ranges, and consider safer estimators or constrained policy distance.

Retrieval answers

  1. Whenever \(\pi(a\mid s)>0\), the logging policy must also satisfy \(\mu(a\mid s)>0\).

  2. Most weight is concentrated on a small number of rare trajectories, making the estimate noisy and sample-sensitive.

Takeaway: trajectory IS applies every action ratio to every reward. Per-decision IS respects reward timing, often reducing variance by preventing future actions from reweighting outcomes that occurred before them.
