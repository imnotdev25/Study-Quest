2. Reward placement is not credit assignment

An LLM reward model or verifier often returns one score \(R_b\) for an entire response. To create token rewards, place that score once at the final valid token:

\[r^{\text{task}}_{b,t} = \mathbf 1[t=L_b-1]R_b\]

Then reward-to-go distributes it backward:

\[G_{b,t} = \sum_{k=t}^{L_b-1} \gamma^{k-t}r_{b,k}\]

With \(\gamma=1\):

\[G_{b,t}=R_b\]

for every earlier valid token. The return calculation—not reward broadcasting—assigns credit to preceding actions.

If \(R_b\) is copied to every token:

\[r_{b,t}=R_b\]

then:

\[G_{b,t}=(L_b-t)R_b\]

and total immediate task reward becomes \(L_bR_b\). Longer responses silently receive larger rewards or penalties.

With token-level KL shaping:

\[r_{b,t} = -\beta k_{b,t} + \mathbf 1[t=L_b-1]R_b\]

The KL cost occurs at each generated token; the sequence score occurs once.

Tensor shapes:

  • sequence scores and lengths: [B]

  • response mask, token rewards and returns: [B, T]

  • final valid indices: [B, 1]

Never place every score at tensor column T-1: shorter responses end earlier. Empty outputs and truncated responses require explicit policies rather than clamping their lengths silently.

DPO uses one preference label with sequence log-probability sums. It does not construct temporal rewards or returns, so it is preference optimization rather than online token-level credit assignment.

Solutions

Mask and final positions:

token_positions = torch.arange(
    maximum_length
)[None, :]

response_mask = (
    token_positions
    < lengths[:, None]
)

assert (
    (lengths >= 1)
    & (lengths <= maximum_length)
).all()

final_valid_indices = (
    lengths - 1
)[:, None]

Immediate rewards:

correct_token_rewards = torch.zeros(
    batch_size,
    maximum_length,
).scatter(
    dim=1,
    index=final_valid_indices,
    src=sequence_rewards[:, None],
)

broadcast_token_rewards = torch.where(
    response_mask,
    sequence_rewards[:, None],
    torch.zeros(
        batch_size,
        maximum_length,
    ),
)

fixed_slot_rewards = torch.zeros(
    batch_size,
    maximum_length,
)

fixed_slot_rewards[:, -1] = sequence_rewards

fixed_slot_rewards = torch.where(
    response_mask,
    fixed_slot_rewards,
    torch.zeros_like(
        fixed_slot_rewards
    ),
)

Masked return calculation:

def calculate_returns(token_rewards):
    returns = torch.zeros_like(
        token_rewards
    )

    running_return = torch.zeros(
        batch_size
    )

    for token_index in reversed(
        range(maximum_length)
    ):
        candidate_return = (
            token_rewards[:, token_index]
            + discount * running_return
        )

        running_return = torch.where(
            response_mask[:, token_index],
            candidate_return,
            torch.zeros_like(
                candidate_return
            ),
        )

        returns[:, token_index] = (
            running_return
        )

    return returns

Correct immediate reward sums remain:

\[[-1.0,\;0.4]\]

Broadcasting instead produces:

\[[2(-1.0),\;8(0.4)] = [-2.0,\;3.2]\]

With correct placement and \(\gamma=1\), returns are:

\[[-1,-1]\]

and:

\[[0.4,0.4,\ldots,0.4]\]

Their prompt-balanced signal is:

\[\frac{-1+0.4}{2} = -0.3\]

Broadcasting gives per-prompt mean returns:

\[\frac{-2-1}{2}=-1.5\]

and:

\[\frac{3.2+2.8+\cdots+0.4}{8} = 1.8\]

Therefore:

\[\frac{-1.5+1.8}{2} = 0.15\]

The apparent update direction reverses solely because one sequence score was counted repeatedly. Fixed-column placement discards the short response’s negative reward entirely.

Check answers

  1. Reward-to-go, TD or GAE propagates the final outcome backward to earlier actions.

  2. Apply the KL cost at each valid generated token and add the task score once at the final valid token.

  3. Broadcasting makes early-token returns proportional to remaining response length, so even each response’s mean return changes with length.

  4. For task rewards alone:

\[\sum_t r^{\text{task}}_{b,t}=R_b\]

for every nonempty response. 5. Store finish reason, true generated length, whether EOS was produced, truncation limit and the scoring rule for incomplete responses.

Retrieval answers

  1. Use either detached KL reward shaping or an explicit differentiable KL loss. Applying both normally doubles the penalty.

  2. PPO repeatedly optimizes one collected rollout. Recomputing rewards or advantages makes its training target change between epochs.

Takeaway: a sequence score belongs in the token-reward tensor once. Returns provide temporal credit; broadcasting the score manufactures a length-dependent objective and can reverse the policy update.
