🧩 Analogy: a school’s falling average

A school’s average test score falls. Did teaching get worse, or did more struggling students enrol? Those need opposite responses. Drift decomposition splits a metric change into “who arrived” (mix) and “how well we served each group” (within-group performance).

2. One aggregate metric hides two kinds of change

At time \(t\), let:

  • \(p_t(g)\): fraction of traffic in group \(g\);

  • \(\mu_t(g)\): policy performance within group \(g\).

Overall performance is:

\[J_t = \sum_g p_t(g)\mu_t(g)\]

A metric can fall because:

  1. composition drift: deployment receives more difficult prompts;

  2. conditional performance drift: the policy becomes worse within the same prompt groups.

Using the baseline as the reference:

\[J_1-J_0 = \underbrace{ \sum_g [p_1(g)-p_0(g)]\mu_0(g) }_{\text{composition effect}} + \underbrace{ \sum_g p_1(g)[\mu_1(g)-\mu_0(g)] }_{\text{performance effect}}\]

The intermediate counterfactual is:

\[J_{\text{mix-only}} = \sum_g p_1(g)\mu_0(g)\]

It asks: “What would current aggregate performance be if only the traffic mixture changed and baseline conditional performance remained?”

This decomposition is algebraically exact, but attribution depends on the chosen reference period. Reversing the reference changes the two components, though not their sum.

Tensor shapes:

  • group and reward rows: [N]

  • one-hot membership: [N, G]

  • frequencies, conditional values and contributions: [G]

For an LLM evaluation platform, useful pre-treatment groups include domain, language, task type, prompt difficulty and input modality. Keep group definitions and judge versions stable across periods.

For agent RL, later states may be caused by the policy. A change in state visitation can be a genuine policy effect, so do not automatically “control it away” as ordinary traffic drift.

DPO may improve performance on its preference-data mixture while current deployment shifts toward prompt groups where the policy is weaker. Aggregate preference accuracy cannot distinguish these two sources of drift.

🔍 Deeper: a two-part decomposition

With group shares \(w_g\) and group metrics \(\mu_g\) in periods 1 and 2: \[\Delta=\underbrace{\textstyle\sum_g(w_{2g}-w_{1g})\,\mu_{1g}}_{\text{mix}}+\underbrace{\textstyle\sum_gw_{2g}\,(\mu_{2g}-\mu_{1g})}_{\text{within-group}} .\] The split depends on which period’s weights you use as the reference, so report the convention (or average both orderings, like a Shapley split). Keep the reward or judge definition fixed across periods, or the “within” term mixes in measurement drift.

🔑 Key ideas

  • Aggregate drift is a symptom, not a diagnosis.

  • Monitor both who arrives and how each stable group is served.

🚶 Walkthrough: an 11-point drop

Easy: 90%, hard: 50%. Period 1 mix 65/35: \(58.5+17.5=76\). Period 2 mix 35/65 with easy 91%, hard 51%: \(31.85+33.15=65\). Mix: \((-0.3)(90)+(0.3)(50)=-12\). Within: \(0.35(1)+0.65(1)=+1\). Total \(-11\). The policy improved slightly, and the traffic got harder.

Common mistakes

  • The judge model changed between periods.

  • Groups defined with post-treatment variables.

  • Hiding the reference-period convention.

⚙️ Algorithm: Mix vs within-group drift decomposition
Input: per-group shares \(w_{1g},w_{2g}\) and metrics \(\mu_{1g},\mu_{2g}\) (same metric definition in both periods)
\(\text{mix}\gets\sum_g(w_{2g}-w_{1g})\,\mu_{1g}\)
\(\text{within}\gets\sum_gw_{2g}\,(\mu_{2g}-\mu_{1g})\)
check: \(\text{mix}+\text{within}=\sum_gw_{2g}\mu_{2g}-\sum_gw_{1g}\mu_{1g}\)
return both terms, with bootstrap CIs over independent units

Hints

  • One-hot membership has shape [N, G].

  • Conditional value is each group’s reward sum divided by its count.

  • The mix-only value uses current frequencies with baseline conditional values.

  • Composition contribution is (current_frequency - baseline_frequency) * baseline_value.

  • Performance contribution is current_frequency * (current_value - baseline_value).

  • The decomposition residual should be numerically near zero.

Debugging experiments

  • Monitor only aggregate success and blame the model for every drop.

  • Change group taxonomy between periods.

  • Compare scores produced by different judge versions.

  • Treat response length or tool count as pre-treatment traffic attributes.

  • Drop unknown-language or unclassified prompts.

  • Compare duplicated episodes as though they were independent users.

  • Ignore new groups with no baseline support.

  • Use current traffic weights when the decision concerns a different target population.

Solutions

Period summarization:

def summarize_period(
    groups,
    rewards,
):
    one_hot = F.one_hot(
        groups,
        num_classes=num_groups,
    ).to(torch.float64)

    counts = one_hot.sum(dim=0)

    frequencies = (
        counts / counts.sum()
    )

    conditional_values = (
        (
            one_hot
            * rewards[:, None]
        ).sum(dim=0)
        / counts
    )

    overall_value = rewards.mean()

    return (
        counts,
        frequencies,
        conditional_values,
        overall_value,
    )

Aggregate change:

estimated_total_change = (
    estimated_current_overall
    - estimated_baseline_overall
)

Counterfactual and decomposition:

composition_only_current_value = (
    estimated_current_frequencies
    * estimated_baseline_values
).sum()

estimated_composition_effect = (
    composition_only_current_value
    - estimated_baseline_overall
)

estimated_performance_effect = (
    estimated_current_overall
    - composition_only_current_value
)

Per-group contributions:

composition_contributions = (
    (
        estimated_current_frequencies
        - estimated_baseline_frequencies
    )
    * estimated_baseline_values
)

performance_contributions = (
    estimated_current_frequencies
    * (
        estimated_current_values
        - estimated_baseline_values
    )
)

decomposed_change = (
    composition_contributions.sum()
    + performance_contributions.sum()
)

decomposition_residual = (
    estimated_total_change
    - decomposed_change
)

    * current_group_values

    exact_current_overall

)

    (
        current_group_probabilities

    current_group_probabilities
    * (
        current_group_values
        - baseline_group_values

The baseline value is:

\[J_0 = 0.6(0.8)+0.3(0.6)+0.1(0.4) = 0.70\]

The current value is:

\[J_1 = 0.4(0.78)+0.35(0.58)+0.25(0.30) = 0.59\]

So:

\[J_1-J_0=-0.11\]

Holding conditional performance at baseline levels while changing the mixture gives:

\[J_{\text{mix-only}} = 0.4(0.8)+0.35(0.6)+0.25(0.4) = 0.63\]

Therefore:

\[\text{composition effect} = 0.63-0.70 = -0.07\]

and:

\[\text{performance effect} = 0.59-0.63 = -0.04\]

Both changed: harder traffic explains seven points of the decline, and within-group degradation explains four points.

Check answers

  1. It estimates current performance if current traffic had arrived but baseline conditional performance had remained unchanged.

  2. Easier traffic can offset declining conditional performance—or harder traffic can hide genuine improvements.

  3. The decomposition moves first along one dimension and then the other. Changing that order changes attribution when both dimensions move.

  4. Bootstrap complete users or other independent clusters, recomputing the entire decomposition within every bootstrap replicate.

Retrieval answers

  1. Randomization balances policies within sampled traffic; it does not make the sample’s group mixture equal to deployment.

  2. The target estimand is unsupported. Collect data for that group, narrow the target population or report explicit partial bounds rather than silently extrapolating.

Takeaway: aggregate drift is a symptom, not a diagnosis. Monitor both who is arriving and how the policy performs within stable, pre-treatment groups—using the same reward and judge definitions across time.
