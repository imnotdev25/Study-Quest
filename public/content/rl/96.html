🧩 Analogy: “no cracks found” after a quick look

A bridge inspector who glanced for ten seconds and found no cracks hasn’t certified the bridge. “We didn’t detect harm” isn’t “we showed harm is small.” Noninferiority testing makes the claim explicit: the upper bound on harm must sit below a margin you chose in advance.

2. Failing to detect harm does not bound the harm

Suppose an incident rate may increase by at most:

\[\Delta_{\max}=0.015\]

Define harm as:

\[d=p_{\text{candidate}}-p_{\text{control}}\]

Positive \(d\) is worse.

A common but invalid rule is:

The candidate was not significantly worse, so it is safe.

A nonsignificant result may simply have a wide confidence interval containing both zero and severe harm.

Noninferiority asks the correct question:

\[H_0:d\geq\Delta_{\max}\]

\[H_1:d<\Delta_{\max}\]

With estimated harm \(\hat d\) and standard error \(SE\), construct a one-sided upper bound:

\[U_d = \hat d+z_{1-\alpha}SE\]

Certify noninferiority only when:

\[U_d<\Delta_{\max}\]

Three distinct conclusions are possible:

  • \(U_d<0\): evidence the candidate is safer;

  • \(0\le U_d<\Delta_{\max}\): possibly worse, but bounded within the accepted margin;

  • \(U_d\ge\Delta_{\max}\): insufficient evidence to rule out unacceptable harm.

The margin must be chosen before observing results. It represents a product or safety judgment, not something statistics can select automatically.

Tensor shapes:

  • conditions and repeated experiments: [C, R]

  • incident counts and rates: [C, R]

  • harm estimates, bounds and decisions: [C, R]

  • summary rates across sample sizes: [S, C]

For rare incidents, the normal approximation used below is instructional. Production analyses may need score, exact, bootstrap or cluster-aware bounds.

DPO preference improvements do not establish noninferiority for incidents, hallucinations or subgroup regressions. Those require outcome-specific margins and evaluation data.

🔍 Deeper: the noninferiority test

\(H_0:\Delta\le-M\) vs \(H_1:\Delta>-M\). Declare noninferior iff the lower confidence bound \(\mathrm{LCB}(\Delta)>-M\). \(M\) is a product and safety decision, fixed before the study, and the study must be powered for it (Topic 96). A non-significant difference from 0 says nothing about whether \(\Delta>-M\).

🔑 Key ideas

  • Safety needs a bound on possible harm, not just no significant p-value.

  • Precommit the margin, power for it, and call inconclusive results inconclusive.

🚶 Walkthrough: the middle case

Estimate \(-0.5\), 95% CI \([-2.5,1.5]\), margin \(M=1\). The interval includes 0 (no significant harm) and includes \(-2.5\) (harm beyond the margin). That’s inconclusive, not safe.

Common mistakes

  • Setting \(M\) after seeing the data.

  • Treating “\(p>0.05\)” as evidence of safety.

  • Using an underpowered canary for a noninferiority claim.

  • Ignore user-level clustering when users generate several incidents.

  • Repeatedly inspect fixed-horizon bounds and stop at the first pass.

Solutions

Candidate rates:

candidate_incident_rates = (
    control_incident_rate
    + true_harms
)

Simulation:

candidate_probabilities = (
    candidate_incident_rates[:, None]
    .expand(
        -1,
        num_repetitions,
    )
)

control_counts = (
    torch.distributions.Binomial(
        total_count=sample_size,
        probs=control_probabilities,
    ).sample()
)

candidate_counts = (
    torch.distributions.Binomial(
        total_count=sample_size,
        probs=candidate_probabilities,
    ).sample()
)

control_rates = (
    control_counts / sample_size
)

candidate_rates = (
    candidate_counts / sample_size
)

Harm estimates and bounds:

estimated_harms = (
    candidate_rates
    - control_rates
)

standard_errors = torch.sqrt(
    candidate_rates
    * (1.0 - candidate_rates)
    / sample_size
    +
    control_rates
    * (1.0 - control_rates)
    / sample_size
)

harm_lower_bounds = (
    estimated_harms
    - one_sided_z * standard_errors
)

harm_upper_bounds = (
    estimated_harms
    + one_sided_z * standard_errors
)

Decision rules:

significantly_worse_than_zero = (
    harm_lower_bounds > 0.0
)

naive_no_detected_harm = (
    ~significantly_worse_than_zero
)

passes_noninferiority = (
    harm_upper_bounds
    < maximum_acceptable_harm
)

Summaries:

mean_estimates.append(
    estimated_harms.mean(dim=1)
)

mean_upper_bounds.append(
    harm_upper_bounds.mean(dim=1)
)

naive_pass_rates.append(
    naive_no_detected_harm
    .to(torch.float64)
    .mean(dim=1)
)

noninferiority_pass_rates.append(
    passes_noninferiority
    .to(torch.float64)
    .mean(dim=1)
)

Stacking:

mean_estimates = torch.stack(
    mean_estimates,
    dim=0,
)

mean_upper_bounds = torch.stack(
    mean_upper_bounds,
    dim=0,
)

naive_pass_rates = torch.stack(
    naive_pass_rates,
    dim=0,
)

noninferiority_pass_rates = torch.stack(
    noninferiority_pass_rates,
    dim=0,
)

With 500 observations per arm, the standard error is large. The candidate with unacceptable 0.025 harm may still show no statistically significant harm in roughly 40–50% of experiments. The naive rule would incorrectly call those experiments safe.

The valid noninferiority rule behaves differently:

  • true harm 0.005: small samples often remain inconclusive; around 5,000 observations per arm provide roughly 80% power;

  • true harm 0.015: certification occurs near the chosen 5% error rate;

  • true harm 0.025: certification is rare because the effect exceeds the permitted margin.

As sample size grows, the acceptable candidate may become significantly worse than control because its true harm is positive:

\[d=0.005>0\]

Yet it can simultaneously be noninferior because:

\[0.005<0.015\]

Those claims are not contradictory. “Exactly no harm” and “no more than acceptable harm” are different hypotheses.

Check answers

  1. The first test asks whether there is evidence of any harm. Noninferiority asks whether the data rule out harm at or above a specified unacceptable level.

  2. Yes. A precise estimate can establish both \(d>0\) and \(d<\Delta_{\max}\).

  3. It means unacceptable harm has not been ruled out. It does not prove that the candidate is harmful.

  4. Choose it before evaluation using domain severity, baseline risk, user impact and deployment trade-offs—not the observed estimate or desired statistical outcome.

Retrieval answers

  1. Because \(n\propto1/\Delta_*^2\), halving the target effect requires approximately four times the independent sample.

  2. It has low probability of detecting meaningful real effects, producing false negatives. Its false-positive rate remains controlled if its analysis and stopping rule are valid.

Takeaway: safety requires an upper bound on possible harm, not merely the absence of a small p-value. Precommit the acceptable margin, power the study for it, and treat inconclusive evidence as inconclusive.
