🧩 Analogy: two routes with the same number of turns

Two routes home both take 3 turns, but one takes 10 minutes and the other 40. Counting decisions says they’re equal. Counting time says they’re not. Tool calls work like that: a calculator answers in milliseconds, a web crawl in a minute. If slow is costly, discount by elapsed time, not by number of steps.

2. Tool actions do not have equal duration

Ordinary MDP notation treats every transition as one equally sized step:

\[G_t=r_t+\gamma G_{t+1}\]

For a tool agent, actions may take very different amounts of time:

  • local calculation: \(0.1\) seconds;

  • web search: \(2\) seconds;

  • database job: \(20\) seconds;

  • human approval: several minutes.

A semi-Markov decision process associates action \(a_t\) with duration \(\tau_t\). If \(\gamma\) is the discount per unit of time:

\[G_t = r_t+ \gamma^{\tau_t}G_{t+1}\]

The TD target becomes:

\[y_t = r_t+ \gamma^{\tau_t} (1-\text{terminated}_t) V(s_{t+1})\]

When \(\tau_t=1\), this reduces to the ordinary TD target.

An equivalent continuous-time form is:

\[\gamma^{\tau_t} = e^{-\beta\tau_t}\]

where:

\[\beta=-\log\gamma\]

Per-decision discounting charges a quick calculation and a slow external call equally. Duration-aware discounting prefers earlier outcomes when latency is part of the objective.

This is a modeling choice:

  • If latency matters to users, duration-aware discounting or an explicit latency cost is appropriate.

  • If latency does not affect task value, adding time discounting changes the objective unnecessarily.

  • Monetary cost, failure risk and latency may need separate reward components rather than being hidden inside one discount factor.

Specify the duration unit. Using seconds instead of minutes with the same \(\gamma\) produces a completely different effective discount.

Tensor shapes:

  • rewards, durations and masks: [B, T];

  • duration discounts: [B, T];

  • returns and TD targets: [B, T].

DPO can learn a latency preference when preferred traces are consistently faster, but it does not directly model durations, environment transitions or online tool latency.

🔍 Deeper: semi-Markov discounting

If action \(a\) takes duration \(\tau\) with reward rate (or reward) \(r\), the SMDP Q-learning target is \[Q(s,a)\leftarrow Q(s,a)+\alpha\Big[r+\gamma^{\tau}\max_{a'}Q(s',a')-Q(s,a)\Big],\] where \(\gamma\) is now a per-time-unit discount. Rewards earned during the action can be discounted within it too: \(\sum_{k<\tau}\gamma^kr_k\). Units: the duration must be in the same unit at rollout, training and evaluation.

🔑 Key ideas

  • Decision count and elapsed time are different quantities.

  • Model duration explicitly when slow outcomes are worth less.

🚶 Walkthrough: fast vs slow tool

\(\gamma=0.95\) per second, both tools lead to a state worth \(V=10\), no immediate reward. Fast (1 s): \(0.95\cdot10=9.5\). Slow (5 s): \(0.95^5\cdot10=7.74\). Per-decision discounting would score both at 9.5.

Common mistakes

  • Logging durations in ms in one place and s in another.

  • Using wall-clock durations that include queueing noise as if they were policy-caused.

  • Forgetting the duration exponent in GAE (\(\gamma^{\tau_t}\) per step).

⚙️ Algorithm: SMDP Q-learning
Input: per-time-unit discount \(\gamma\), step size \(\alpha\)
for each decision do
choose \(a\) (e.g. \(\epsilon\)-greedy) in state \(s\); run it until it finishes
observe accumulated discounted reward \(R=\sum_{k<\tau}\gamma^kr_k\), duration \(\tau\), next state \(s'\), done \(d\)
\(Q(s,a)\gets Q(s,a)+\alpha\big[R+\gamma^{\tau}(1-d)\max_{a'}Q(s',a')-Q(s,a)\big]\)
\(s\gets s'\)
end

Hints

  • Ordinary discount is gamma at every tensor position.

  • Duration discount is torch.exp(math.log(gamma) * durations).

  • Recurse with reward + discount * running_return.

  • Multiply the running return by the current validity mask.

  • TD bootstrap mask is ~terminated.

  • Detach next_values when constructing a critic target.

Debugging experiments

Remove the validity mask from the return recursion. The padded reward propagates backward and overwhelms both trajectories.

Set durations to milliseconds while keeping the same per-second \(\gamma\). Discounts underflow toward zero because the units no longer match.

Use gamma ** durations with extremely large durations in low precision. Compare it with the logarithmic form and inspect underflow.

Finally, add both a strong duration discount and a large explicit latency penalty. The agent may be charged twice for the same preference.

Solutions

Per-decision discounts:

per_decision_discounts = torch.full_like(
    durations,
    gamma,
)

Duration-aware discounts:

duration_discounts = torch.exp(
    math.log(gamma) * durations
)

Return recursion:

def calculate_returns(discounts):
    returns = torch.zeros_like(rewards)

    running_return = torch.zeros(
        rewards.shape[0]
    )

    for time in reversed(
        range(rewards.shape[1])
    ):
        running_return = (
            rewards[:, time]
            + discounts[:, time]
            * running_return
        )

        running_return = (
            running_return
            * valid[:, time]
        )

        returns[:, time] = running_return

    return returns

Both returns:

per_decision_returns = calculate_returns(
    per_decision_discounts
)

duration_aware_returns = calculate_returns(
    duration_discounts
)

TD targets:

td_targets = (
    rewards
    + duration_discounts
    * (~terminated).to(rewards.dtype)
    * next_values.detach()
)

With ordinary per-decision discounting, both trajectories receive:

\[G_0 = \gamma^2 = 0.9^2 = 0.81\]

For the quick trajectory:

\[G_0 = \gamma^{1+1} = 0.81\]

For the slow trajectory:

\[G_0 = \gamma^{5+5} = 0.9^{10} \approx0.349\]

The trajectories contain the same number of decisions, but the second takes five times as long at each nonterminal step.

Check answers

  1. An SMDP allows the environment to transition after actions with unequal durations.

  2. It is the remaining-value multiplier after \(\tau_t\) units of elapsed time.

  3. A cost is clearer when latency should trade off linearly against success, or when stakeholders need a directly interpretable price per second.

  4. Log duration distribution by tool, end-to-end latency, timeouts, reward versus latency, cost versus latency and performance across duration buckets.

Retrieval answers

  1. Use \(1-\text{terminated}\); artificial truncation may still bootstrap from the boundary-state value.

  2. GAE must stop its sampled recursion at termination, truncation and padding boundaries even when a truncated TD target bootstraps.

Takeaway: decision count and elapsed time are different quantities. Model duration explicitly when slow outcomes are less valuable, and keep time units consistent across rollout, training and evaluation.
