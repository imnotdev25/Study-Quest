🧩 Analogy: a coffee taste test

Ask someone to rate a coffee out of 10 and you’ll get “7.3?” that drifts with their mood. Ask “which of these two do you prefer?” and you get a reliable answer. Reward models learn from those pairwise choices. Chess Elo ratings use the same math: one number per player, fitted from who beat whom.

2. Learning reward from comparisons

For many LLM tasks, writing a numerical reward is difficult. A person may find it easier to compare two responses:

Prompt: x
Preferred response: y_w
Rejected response: y_l

A reward model assigns each prompt-response pair a scalar:

\[r_\phi(x,y)\in\mathbb R\]

The Bradley–Terry model converts the score difference into a preference probability:

\[P(y_w\succ y_l\mid x) = \sigma\left( r_\phi(x,y_w)-r_\phi(x,y_l) \right)\]

where:

\[\sigma(z)=\frac{1}{1+e^{-z}}\]

If the preferred response scores much higher, the probability approaches one. If both scores are equal, it is \(0.5\).

The pairwise loss is:

\[L_{\text{RM}} = -\log\sigma(r_w-r_l)\]

A numerically stable equivalent is:

\[L_{\text{RM}} = \operatorname{softplus}(-(r_w-r_l))\]

This is binary cross-entropy applied to the score margin.

Only score differences are identified

Adding the same constant to every reward changes nothing:

\[(r_w+c)-(r_l+c)=r_w-r_l\]

Therefore, preference data identifies relative scores, not an absolute zero. In a linear reward model, the shared bias cancels completely.

Reward scale also matters. A policy optimizer reacts differently to rewards around 0.1 versus 100, even when their ranking is identical. Real systems commonly normalize rewards and separately monitor their mean, standard deviation and extremes.

What reward-model accuracy misses

High held-out pairwise accuracy does not prove that the reward model represents human intent. Problems include:

  • inconsistent or biased annotators;

  • position and presentation bias;

  • train/test prompt leakage;

  • narrow response coverage;

  • spurious cues such as length or confident wording;

  • policy-generated responses moving beyond the training distribution.

Once optimized, the policy searches for responses that the reward model scores highly—including mistakes in the reward model.

Tensor shapes for today:

  • chosen and rejected features: [B, features]

  • chosen and rejected scores: [B]

  • score margins: [B]

  • preference loss: scalar

DPO connection

DPO uses a similar logistic comparison, but replaces explicit reward scores with policy-versus-reference log-probability differences:

\[\log\sigma\left( \beta \left[ \log\frac{\pi_\theta(y_w\mid x)} {\pi_{\text{ref}}(y_w\mid x)} - \log\frac{\pi_\theta(y_l\mid x)} {\pi_{\text{ref}}(y_l\mid x)} \right] \right)\]

DPO directly trains the policy on fixed preference pairs. It does not first train a reward model, sample new rollouts, or perform online RL updates.

🔍 Deeper: the pairwise loss and its gradient

\(P(y_w\succ y_l\mid x)=\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big)\), with loss \(\mathcal L=-\log\sigma(\Delta)\), \(\Delta=r_w-r_l\).

\(\frac{\partial\mathcal L}{\partial\Delta}=-(1-\sigma(\Delta))=-\sigma(-\Delta)\): big pushes when the model ranks the pair wrong, and almost none when it’s already confidently right. Numbers: \(\Delta=0\) gives loss \(\ln2\approx0.693\). \(\Delta=2\) gives \(\ln(1+e^{-2})\approx0.127\).

Shift invariance: adding any constant to all rewards for a prompt leaves every probability unchanged. Absolute reward values are therefore meaningless: normalize them before RL.

🔑 Key ideas

  • Reward model = logistic regression on “which is better.”

  • It learns ranking, not truth, and the RL policy will hunt for its blind spots.

🚶 Walkthrough: three pairs

Margins \(\Delta=(2,0,-1)\). Losses \(-\log\sigma(\Delta)=(0.127,0.693,1.313)\), mean \(0.711\). Gradient weights \(\sigma(-\Delta)=(0.12,0.50,0.73)\): the wrongly ranked pair pushes hardest. Accuracy \(=1/3\) (only \(\Delta>0\) counts).

Common mistakes

  • Swapping chosen and rejected columns.

  • Scoring a padding token instead of the last real token.

  • Reading raw reward magnitudes as meaningful across prompts.

⚙️ Algorithm: Train a pairwise (Bradley–Terry) reward model
Input: preference data \(\{(x,y_w,y_l)\}\) where \(y_w\) was preferred, reward model \(r_\phi\)
for each minibatch do
\(\Delta\gets r_\phi(x,y_w)-r_\phi(x,y_l)\)
gradient step on \(-\operatorname{mean}\log\sigma(\Delta)\)
end
report held-out accuracy \(P(\Delta>0)\) and normalize rewards before using them in RL

3. PyTorch exercise — train a tiny pairwise reward model

Each synthetic response has two features:

[correctness, verbosity]

Debugging experiments

Reverse the margin:

margins = rejected_scores - chosen_scores

The model learns the opposite preference rule: correctness receives a negative weight and verbosity tends to receive a positive one.

Also replace the stable loss with:

loss = -torch.log(torch.sigmoid(margins)).mean()

This is mathematically equivalent, but very negative margins can make sigmoid underflow toward zero and log(0) produce -inf. softplus is safer.

Solutions

Orient the sampled preferences:

chosen = torch.where(
    a_wins.unsqueeze(-1),
    features_a,
    features_b,
)

rejected = torch.where(
    a_wins.unsqueeze(-1),
    features_b,
    features_a,
)

Calculate scores and margins:

chosen_scores = reward_model(
    chosen_train
).squeeze(-1)

rejected_scores = reward_model(
    rejected_train
).squeeze(-1)

margins = chosen_scores - rejected_scores

Stable pairwise loss:

loss = F.softplus(
    -margins
).mean()

Validation accuracy:

validation_accuracy = (
    valid_margins > 0
).float().mean()

The model should learn approximately the same direction as:

correctness weight: positive
verbosity weight:   negative

The exact values need not equal [2.0, -0.5]. Finite noisy comparisons and optimization determine the learned scale.

The bias has no effect:

\[(w^\top x_w+b)-(w^\top x_l+b) = w^\top(x_w-x_l)\]

Consequently, its gradient should be zero or numerically indistinguishable from zero. Its initial random value may remain unchanged.

Validation accuracy will remain below one because preferences were sampled probabilistically. Even when response A has greater latent utility, the simulated annotator sometimes selects B.

At margin zero:

\[\sigma(0)=0.5\]

The reward model considers both responses equally likely to be preferred.

Check answers

  1. Adding a constant to both scores leaves every pairwise probability unchanged.

  2. Policy optimization can generate out-of-distribution responses that exploit spurious signals the fixed validation set never tests.

  3. A large positive margin approaches probability one; a large negative margin approaches zero.

  4. DPO directly adjusts policy log-ratios using fixed chosen/rejected pairs. Reward-model RL trains a separate scorer and uses its outputs to optimize newly sampled policy responses.

Retrieval answers

  1. One scalar outcome does not reveal which particular generated decisions caused success or failure.

  2. A negative advantage produces a gradient update that decreases the sampled token’s log-probability.

Takeaway: a reward model learns relative human preference, not objective truth. Pairwise loss teaches ranking; reward calibration, data coverage and resistance to policy exploitation determine whether that ranking remains useful during RL.
