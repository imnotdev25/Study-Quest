  1. Under equal collection costs, what allocation minimizes the variance of a target-weighted stratified estimate?

  2. Why is the raw pooled mean generally biased after deliberate group oversampling?

Answers are near the end.

2. The best observed checkpoint contains the best noise

Suppose \(K\) checkpoints have estimated values:

\[\hat J_k=J_k+\epsilon_k\]

Selecting:

\[\hat k=\arg\max_k\hat J_k\]

also selects unusually positive noise. Even when every checkpoint has identical true value \(J\):

\[E[\hat J_{\hat k}]>J\]

This is the winner’s curse. With roughly independent Gaussian estimation errors of standard deviation \(s\), its size grows approximately like:

\[s\sqrt{2\log K}\]

More candidates and noisier evaluations produce greater optimism.

An independent confirmation set repairs the claim:

  1. use development data to choose \(\hat k\);

  2. lock the checkpoint, decoding settings and metric;

  3. estimate \(J_{\hat k}\) on untouched confirmation data.

Alternatively, a simultaneous correction such as Bonferroni tests each candidate using:

\[\alpha_k=\frac{\alpha}{K}\]

This controls the probability that any null candidate is falsely promoted, although it can be conservative when candidates are correlated.

Tensor shapes:

  • selection scores: [R, K]

  • selected checkpoint IDs: [R]

  • selected and confirmation scores: [R]

  • promotion decisions: [R]

For DPO, choosing the best checkpoint, \(\beta\), seed and prompt template on one preference set and reporting that same score is still selection bias. Preference optimization does not turn reused evaluation data into independent evidence.

3. PyTorch exercise — 20 identical candidates produce a “winner”

Hints

  • Create selection probabilities with shape [R, K].

  • Sample counts with torch.distributions.Binomial.

  • Use .max(dim=1) to obtain scores and indices.

  • Confirmation data are independent; because all candidates are identical, their probabilities remain 0.60.

  • The instructional null standard error is:

\[SE_0=\sqrt{\frac{p_0(1-p_0)}{n}}\]

  • Promotion occurs when a lower bound exceeds the baseline.

  • Bonferroni changes the critical value, not the point estimate.

Debugging experiments

  • Search hundreds of checkpoints and report the largest validation score as a final estimate.

  • Select the best random seed and present it as typical performance.

  • Tune the judge prompt, rubric and threshold on the claimed test set.

  • Repeatedly inspect the “fresh” confirmation set and keep modifying the policy.

  • Leak confirmation prompts into SFT, DPO or RL training.

  • Ignore checkpoint correlation: Bonferroni remains valid but may be unnecessarily conservative.

4. Checks for understanding

  1. Why is the selected score biased upward when every individual score is unbiased?

  2. Does collecting more candidates reduce the winner’s curse?

  3. Why does independent confirmation work?

  4. What must be locked before confirmation begins?

Solutions

Selection data:

selection_probabilities = torch.full(
    (
        num_repetitions,
        num_candidates,
    ),
    true_value.item(),
)

selection_counts = (
    torch.distributions.Binomial(
        total_count=selection_size,
        probs=selection_probabilities,
    ).sample()
)

selection_scores = (
    selection_counts / selection_size
)

Winner selection:

(
    selected_selection_scores,
    selected_indices,
) = selection_scores.max(dim=1)

The selected IDs are useful for auditing, even though all simulated candidates have the same true value.

Fresh confirmation:

confirmation_probabilities = torch.full(
    (num_repetitions,),
    true_value.item(),
)

confirmation_counts = (
    torch.distributions.Binomial(
        total_count=confirmation_size,
        probs=confirmation_probabilities,
    ).sample()
)

confirmation_scores = (
    confirmation_counts
    / confirmation_size
)

Promotion rules:

selection_null_standard_error = torch.sqrt(
    promotion_baseline
    * (1.0 - promotion_baseline)
    / selection_size
)

confirmation_null_standard_error = torch.sqrt(
    promotion_baseline
    * (1.0 - promotion_baseline)
    / confirmation_size
)

naive_selection_lower_bounds = (
    selected_selection_scores
    - single_test_z
    * selection_null_standard_error
)

bonferroni_lower_bounds = (
    selected_selection_scores
    - bonferroni_z
    * selection_null_standard_error
)

confirmation_lower_bounds = (
    confirmation_scores
    - single_test_z
    * confirmation_null_standard_error
)

naive_promotions = (
    naive_selection_lower_bounds
    > promotion_baseline
)

bonferroni_promotions = (
    bonferroni_lower_bounds
    > promotion_baseline
)

confirmation_promotions = (
    confirmation_lower_bounds
    > promotion_baseline
)

naive_false_promotion_rate = (
    naive_promotions
    .to(torch.float64)
    .mean()
)

bonferroni_false_promotion_rate = (
    bonferroni_promotions
    .to(torch.float64)
    .mean()
)

confirmation_false_promotion_rate = (
    confirmation_promotions
    .to(torch.float64)
    .mean()
)

Optimism diagnostics:

single_candidate_mean = (
    selection_scores[:, 0].mean()
)

selected_selection_mean = (
    selected_selection_scores.mean()
)

confirmation_mean = (
    confirmation_scores.mean()
)

selection_optimism = (
    selected_selection_mean
    - true_value
)

selection_confirmation_gap = (
    selected_selection_scores
    - confirmation_scores
).mean()

One candidate’s selection score remains centered near:

\[0.60\]

Its standard error is:

\[\sqrt{\frac{0.6(0.4)}{200}} \approx0.0346\]

The maximum of 20 such noisy scores typically lies near 0.66. Fresh confirmation returns near 0.60 because it does not inherit the selection noise.

For one nominal 5% test, the false-promotion probability is about 5%. Searching 20 approximately independent candidates makes the probability that at least one crosses roughly:

\[1-(1-0.05)^{20} \approx0.64\]

Therefore, typical results are:

  • naive selected-checkpoint promotion: roughly 60%;

  • Bonferroni-adjusted promotion: near or below 5%;

  • independent confirmation: near 5%.

Check answers

  1. Selection conditions on unusually positive errors; the maximum of unbiased estimates is not itself unbiased.

  2. No. Holding per-candidate noise fixed, searching more candidates increases expected optimism.

  3. Conditional on the locked selection, fresh outcomes contain independent noise centered on that checkpoint’s true value.

  4. Lock the checkpoint, decoding configuration, evaluator, aggregation rule, target population, primary metric and stopping rule.

Retrieval answers

  1. With equal costs, Neyman allocation uses \(n_g\propto p_g\sigma_g\).

  2. The pooled mean weights groups by evaluation frequency. After oversampling, that frequency differs from deployment probability.

Takeaway: development data may choose the winner; it cannot also provide an unbiased victory margin. Lock the full evaluation contract, then confirm once on genuinely untouched data.
