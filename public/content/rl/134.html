2. Correct only the decisions that precede each reward

Data were generated by behavior policy \(\mu\), but we want to evaluate target policy \(\pi\). For the action at step \(t\):

\[\rho_t = \underbrace{ \frac{\pi(A_t\mid S_t)} {\mu(A_t\mid S_t)} }_{\text{correction for action }t}\]

The likelihood ratio for the history through step \(t\) is:

\[\rho_{0:t} = \underbrace{ \prod_{k=0}^{t}\rho_k }_{\text{all decisions preceding reward }R_t}\]

Ordinary trajectory importance sampling weights the entire return using the final product:

\[\hat V_{\text{TIS}} = \frac1N \sum_{i=1}^{N} \underbrace{\rho_{0:T-1}^{(i)}}_{\text{full-trajectory weight}} \underbrace{ \sum_{t=0}^{T-1}\gamma^tR_t^{(i)} }_{\text{discounted return}}\]

This lets decisions late in the episode reweight rewards received earlier. That is unbiased, but needlessly noisy: a future tool call cannot cause a past reward.

Per-decision importance sampling instead uses only the history preceding each reward:

\[\hat V_{\text{PDIS}} = \frac1N \sum_{i=1}^{N} \sum_{t=0}^{T-1} \underbrace{\gamma^t}_{\text{discount}} \underbrace{\rho_{0:t}^{(i)}}_{\text{history through }t} \underbrace{R_t^{(i)}}_{\text{reward after action }t}\]

Both estimators require correct behavior propensities and support:

\[\mu(a\mid s)>0 \quad\text{whenever}\quad \pi(a\mid s)>0\]

For LLM agents, a step could be a token, tool call, or reasoning action. If reward exists only at the final token, PDIS reduces to trajectory IS—there are no earlier rewards from which future ratios can be removed.

Practical details:

  • Exclude padding and post-termination actions from both products and rewards.

  • For long sequences, accumulate log-ratios and exponentiate carefully.

  • Store the exact behavior log-probabilities used during sampling.

  • Importance weights are data corrections; detach them during evaluation.

  • DPO is offline preference optimization. Its reference-policy ratio is not an off-policy correction for logged trajectories.

Tensor shapes:

  • actions, rewards and step ratios: [R, N, T]

  • cumulative ratios: [R, N, T]

  • repeated value estimates: [R]

\[ESS = \underbrace{ \frac{\left(\sum_i w_i\right)^2} {\sum_i w_i^2} }_{\text{equivalent number of equally weighted episodes}}\]

Solutions

actions = (
    torch.rand(
        num_repetitions,
        episodes_per_repetition,
        maximum_horizon,
    )
    < behavior_action_one_probability
)

rewards = actions.to(torch.float64)

Ratios and discounts:

action_one_ratio = (
    target_action_one_probability
    / behavior_action_one_probability
)

action_zero_ratio = (
    (1.0 - target_action_one_probability)
    / (1.0 - behavior_action_one_probability)
)

step_ratios = torch.where(
    actions,
    torch.tensor(action_one_ratio),
    torch.tensor(action_zero_ratio),
)

cumulative_ratios = step_ratios.cumprod(
    dim=-1
)

discount_powers = gamma ** torch.arange(
    maximum_horizon
)

Estimator summary:

def summarize(estimates, exact_value):
    mean = estimates.mean()
    bias = mean - exact_value

    standard_deviation = estimates.std(
        correction=1
    )

    rmse = (
        (estimates - exact_value)
        .square()
        .mean()
        .sqrt()
    )

    return torch.stack([
        mean,
        bias,
        standard_deviation,
        rmse,
    ])

Main comparison:

estimate_rows = []
diagnostic_rows = []

for horizon in horizons:
    exact_target_value = (
        target_action_one_probability
        * discount_powers[:horizon].sum()
    )

    discounted_rewards = (
        rewards[..., :horizon]
        * discount_powers[:horizon]
    )

    behavior_returns = (
        discounted_rewards.sum(dim=-1)
    )

    final_trajectory_weights = (
        cumulative_ratios[..., horizon - 1]
    )

    behavior_estimates = (
        behavior_returns.mean(dim=1)
    )

    trajectory_is_estimates = (
        final_trajectory_weights
        * behavior_returns
    ).mean(dim=1)

    per_decision_is_estimates = (
        cumulative_ratios[..., :horizon]
        * discounted_rewards
    ).sum(dim=-1).mean(dim=1)

    for estimator_id, estimates in enumerate([
        behavior_estimates,
        trajectory_is_estimates,
        per_decision_is_estimates,
    ]):
        statistics = summarize(
            estimates,
            exact_target_value,
        )

        estimate_rows.append(torch.cat([
            torch.tensor([
                float(horizon),
                float(estimator_id),
            ]),
            exact_target_value[None],
            statistics,
        ]))

    trajectory_ess = (
        final_trajectory_weights.sum(dim=1)
        .square()
        / final_trajectory_weights.square()
        .sum(dim=1)
    )

    diagnostic_rows.append(torch.stack([
        torch.tensor(float(horizon)),
        final_trajectory_weights.mean(),
        final_trajectory_weights.var(
            correction=0

        trajectory_ess.mean()

Both corrected estimators remain approximately unbiased. Full-trajectory IS becomes extremely noisy because every reward inherits all eight ratios. PDIS gives an early reward only the ratios needed to transport its preceding history.

Check answers

  1. Future action ratios add variance to past rewards without changing their expectation; PDIS omits those unnecessary factors.

  2. They coincide for a one-step problem or when all reward occurs only after the final action.

  3. No. If \(\mu(a\mid s)=0\) where \(\pi(a\mid s)>0\), no finite ratio recovers the missing outcome.

  4. Padding is not an environment decision. Including it invents likelihood factors and can make estimates depend on batch length.

  5. Report weight distributions and ESS, preferably by horizon or timestep—not just the estimated mean.

Retrieval answers

  1. Doubly robust evaluation is consistent if either the outcome model is correct or the importance-ratio model is correct, subject to regularity and support conditions.

  2. Products magnify small probability mismatches exponentially with horizon, creating a few enormous weights and many negligible ones.

Takeaway: match each reward with only the policy decisions that could precede it. Per-decision weighting cannot eliminate long-horizon variance, but it avoids charging past rewards for future actions.
