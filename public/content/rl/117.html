2. PPO has three relevant policies

During repeated PPO epochs:

  • \(q\): reference policy used for KL regularization;

  • \(\mu=\pi_{\text{old}}\): rollout policy that generated the data;

  • \(p=\pi_\theta\): current policy after some optimizer steps.

The desired forward KL at a fixed state is:

\[D_{\mathrm{KL}}(p\|q) = E_{a\sim p} \left[ \log p(a)-\log q(a) \right]\]

But rollout actions came from \(\mu\). The naive rollout average therefore estimates:

\[E_{a\sim\mu} \left[ \log p(a)-\log q(a) \right]\]

This is generally not a KL and may be negative.

For a fixed state, importance sampling repairs the distribution:

\[D_{\mathrm{KL}}(p\|q) = E_{a\sim\mu} \left[ \frac{p(a)}{\mu(a)} \left(\log p(a)-\log q(a)\right) \right]\]

provided:

\[\mu(a)>0\quad\text{whenever}\quad p(a)>0\]

The cost is variance. Effective sample size diagnoses concentration:

\[\operatorname{ESS} = \frac{\left(\sum_i w_i\right)^2} {\sum_i w_i^2}, \qquad w_i=\frac{p(a_i)}{\mu(a_i)}\]

Clipping \(w_i\) lowers variance but changes the estimand. PPO’s clipped policy objective does not make a clipped KL estimate unbiased.

Tensor shapes:

  • policy probabilities and log-probabilities: [V]

  • sampled IDs, log-ratios and weights: [N]

  • LLM token quantities and response mask: [B, T]

For an autoregressive LLM, old rollouts also contain prefixes sampled from \(\mu\). Correcting the full current-policy prefix distribution requires products of token ratios:

\[W_t = \prod_{j<t} \frac{p(a_j\mid s_j)} {\mu(a_j\mid s_j)}\]

These products can explode with sequence length. Computing exact vocabulary KL at logged prefixes removes action-sampling noise, but it still measures KL along old-policy prefixes, not the complete current-policy trajectory distribution.

DPO’s \(\beta\) scales a fixed preference loss relative to a reference. Although DPO can be motivated using KL-regularized RL, its usual training loop has neither online rollouts nor a measured-KL controller.

Hints

  • The target integrand is current_log_probability - reference_log_probability.

  • The correction ratio is current_probability / rollout_probability.

  • Ordinary importance sampling averages weight * integrand.

  • Self-normalized importance sampling divides the weighted sum by the weight sum; it is consistent but biased at finite sample sizes.

  • Compute ratios through log-probability differences before exponentiating.

  • ESS is at most num_samples.

Debugging experiments

  • Accidentally use \(q/\mu\) rather than \(p/\mu\).

  • Reuse old rollouts across many epochs without monitoring ESS.

  • Clip importance weights and continue labeling the result exact KL.

  • Average full-vocabulary KL over padded or prompt positions.

  • Compute token means separately per worker instead of globally reducing numerator and valid-token count.

  • Let trajectory log-weights overflow before exponentiation.

  • Drive an adaptive KL coefficient from one noisy minibatch.

  • Backpropagate through a KL diagnostic or reward-shaped return unintentionally.

Solutions

Exact distributions:

reference_log_probabilities = F.log_softmax(
    reference_logits,
    dim=0,
)

rollout_log_probabilities = F.log_softmax(
    rollout_logits,
    dim=0,
)

current_log_probabilities = F.log_softmax(
    current_logits,
    dim=0,
)

reference_probabilities = (
    reference_log_probabilities.exp()
)

rollout_probabilities = (
    rollout_log_probabilities.exp()
)

current_probabilities = (
    current_log_probabilities.exp()
)

current_reference_log_ratios = (
    current_log_probabilities
    - reference_log_probabilities
)

exact_forward_kl = (
    current_probabilities
    * current_reference_log_ratios
).sum()

exact_stale_expectation = (
    rollout_probabilities
    * current_reference_log_ratios
).sum()

Stale rollout estimate:

rollout_samples = torch.multinomial(
    rollout_probabilities,
    num_samples=num_samples,
    replacement=True,
)

sampled_reference_log_ratios = (
    current_reference_log_ratios[
        rollout_samples
    ]
)

naive_stale_estimate = (
    sampled_reference_log_ratios.mean()
)

Importance correction:

sampled_log_importance_weights = (
    current_log_probabilities[
        rollout_samples
    ]
    - rollout_log_probabilities[
        rollout_samples
    ]
)

importance_weights = (
    sampled_log_importance_weights.exp()
)

importance_weighted_terms = (
    importance_weights
    * sampled_reference_log_ratios
)

importance_sampling_estimate = (
    importance_weighted_terms.mean()
)

self_normalized_estimate = (
    importance_weighted_terms.sum()
    / importance_weights.sum()
)

Clipping and fresh sampling:

clipped_weights = (
    importance_weights.clamp_max(
        weight_clip
    )
)

clipped_importance_estimate = (
    clipped_weights
    * sampled_reference_log_ratios
).mean()

fresh_current_samples = torch.multinomial(
    current_probabilities,
    num_samples=num_samples,
    replacement=True,
)

fresh_current_terms = (
    current_reference_log_ratios[
        fresh_current_samples
    ]
)

fresh_current_estimate = (
    fresh_current_terms.mean()
)

Diagnostics:

effective_sample_size = (
    importance_weights.sum().square()
    / importance_weights.square().sum()
)

effective_sample_fraction = (
    effective_sample_size / num_samples
)

maximum_weight = (
    importance_weights.max()
)

fraction_of_samples_clipped = (
    (importance_weights > weight_clip)
    .to(torch.float64)
    .mean()
)

exact_weights = (
    current_probabilities
    / rollout_probabilities
)

clipped_action_mask = (
    exact_weights > weight_clip
)

rollout_mass_at_clipped_actions = (
    rollout_probabilities[
        clipped_action_mask
    ].sum()
)

current_mass_at_clipped_actions = (
    current_probabilities[
        clipped_action_mask
    ].sum()
)

importance_sampling_se = (
    importance_weighted_terms.std(
        correction=0
    )
    / math.sqrt(num_samples)
)

fresh_current_se = (
    fresh_current_terms.std(
        correction=0
    )
    / math.sqrt(num_samples)
)

The action log-ratios are approximately:

\[[-0.693,\;-0.182,\;0.511,\;1.609]\]

Therefore:

\[D_{\mathrm{KL}}(p\|q) \approx0.311\]

But stale rollout weighting gives:

\[E_\mu[\log p-\log q] \approx-0.449\]

The exact importance weights are:

\[\frac p\mu = [0.357,\;1.25,\;3.125,\;12.5]\]

Ordinary and self-normalized importance sampling should return near 0.311, but the expected ESS is only about:

\[0.232N\]

The two rare rollout actions constitute only:

\[0.08+0.02=0.10\]

of old-policy data, yet they constitute:

\[0.25+0.25=0.50\]

of current-policy mass. Clipping their weights at 2.0 produces an expectation near -0.073, not the desired KL.

Check answers

  1. Its expectation is taken under \(\mu\), whereas forward KL requires actions from \(p\) or a valid correction to \(p\).

  2. Every action or trajectory possible under \(p\) must have positive probability under \(\mu\).

  3. Current-policy actions change later prefixes. Correcting their distribution requires cumulative prefix ratios, whose variance often grows rapidly with horizon.

  4. Detach or use no_grad for telemetry, controller updates and KL incorporated into rewards before return calculation. Direct gradients are appropriate only when intentionally optimizing an explicit differentiable KL loss.

  5. No. PPO clipping defines a conservative policy surrogate; clipping diagnostic importance weights introduces a different, biased estimator.

Retrieval answers

  1. Nonnegativity applies to the expectation. Individual tokens favored more by the reference have negative log-ratios.

  2. Samples must come from \(p\), the first argument of \(D_{\mathrm{KL}}(p\|q)\), unless importance weighting correctly changes the sampling measure.

Takeaway: once PPO updates away from its rollout policy, an unweighted rollout average is no longer current-policy KL. Track policy staleness, ESS and maximum ratios; refresh data or state clearly which old-prefix surrogate you are measuring.
