2. A loss mean silently decides who gets influence

For variable-length LLM responses, a token-average PPO objective is:

\[J_{\text{token}} = \frac{ \sum_{b,t}m_{b,t} \min( \rho_{b,t}A_{b,t}, \operatorname{clip}(\rho_{b,t})A_{b,t} ) }{ \sum_{b,t}m_{b,t} }\]

Every generated token receives equal weight. A response with 100 tokens contributes about ten times as many terms as one with 10.

A prompt-balanced objective first averages within each response:

\[J_{\text{prompt}} = \frac1B \sum_b \frac{ \sum_t m_{b,t}S_{b,t} }{ \sum_t m_{b,t} }\]

where \(S_{b,t}\) is the PPO surrogate.

These answer different questions:

  • token mean: improvement for a randomly selected generated token;

  • prompt mean: improvement for a randomly selected prompt or response.

PPO clipping limits policy-ratio changes:

\[\rho_{b,t} = \exp( \log\pi_\theta-\log\pi_{\text{old}} )\]

It does not correct unintended length weighting.

Tensor shapes:

  • log-probabilities, advantages and masks: [B, T]

  • response lengths: [B]

  • response objectives: [B]

Advantages must be detached so the actor objective does not update the critic through the GAE graph. Prompt tokens, padding and post-EOS positions must be masked.

DPO usually averages losses across preference pairs, while each sequence log-ratio is a sum over response tokens. Replacing that sum with a token mean also changes its objective. DPO remains fixed-data preference optimization, not online policy evaluation.

PPO quantities:

def ppo_objective_and_gradient(reduction):
    theta = torch.tensor(
        0.0,
        requires_grad=True,
    )

    old_theta = torch.tensor(0.0)

    old_log_probability = (
        F.logsigmoid(old_theta)
    )

    new_log_probability = (
        F.logsigmoid(theta)
    )

    old_log_probabilities = (
        old_log_probability.expand_as(
            safe_advantages
        )
    )

    new_log_probabilities = (
        new_log_probability.expand_as(
            safe_advantages
        )
    )

    probability_ratios = torch.exp(
        new_log_probabilities
        - old_log_probabilities
    )

    detached_advantages = (
        safe_advantages.detach()
    )

    unclipped_surrogate = (
        probability_ratios
        * detached_advantages
    )

    clipped_surrogate = (
        probability_ratios.clamp(
            1.0 - clip_epsilon,
            1.0 + clip_epsilon,
        )
        * detached_advantages
    )

    surrogate = torch.minimum(
        unclipped_surrogate,
        clipped_surrogate,
    )

    float_mask = response_mask.to(
        torch.float64
    )

    if reduction == "token":
        objective = (
            surrogate * float_mask
        ).sum() / float_mask.sum()

    elif reduction == "prompt":
        valid_counts = (
            float_mask.sum(dim=1)
            .clamp_min(1.0)
        )

        response_objectives = (
            (
                surrogate
                * float_mask
            ).sum(dim=1)
            / valid_counts
        )

        objective = (
            response_objectives.mean()
        )

    elif reduction == "padded":
        objective = (
            surrogate
            * float_mask
        ).mean()

    else:
        raise ValueError(reduction)

    loss = -objective
    loss.backward()

    ascent_gradient = (
        -theta.grad.detach()
    )

    return (
        objective.detach(),
        ascent_gradient,
    )

The long response contains:

\[\frac8{2+8}=0.8\]

of the valid tokens.

The token-average advantage is:

\[\bar A_{\text{token}} = \frac{2(-2)+8(1)}{10} = 0.4\]

so its update increases the sampled-action logit.

The prompt-average advantage is:

\[\bar A_{\text{prompt}} = \frac{-2+1}{2} = -0.5\]

so its update decreases that logit.

At \(\theta=0\):

\[\frac{\partial\log\sigma(\theta)} {\partial\theta} = 0.5\]

Therefore, expected ascent gradients are:

\[g_{\text{token}} = 0.5(0.4) = 0.20\]

\[g_{\text{prompt}} = 0.5(-0.5) = -0.25\]

The padded calculation divides the token sum by all 16 tensor positions:

\[J_{\text{padded}} = \frac4{16} = 0.25\]

giving gradient approximately 0.125. It preserves the token objective’s sign here but silently changes its scale according to padding.

Check answers

  1. Prompt reduction, assuming prompts are sampled from the target deployment distribution.

  2. No. Tokens determine each response’s mean, but every response receives the same total outer weight.

  3. The correct global token mean is the ratio of global sums. Averaging worker means overweights workers with fewer valid tokens.

  4. Yes. They represent different weighting schemes, and response length can correlate with advantage.

Retrieval answers

  1. Bootstrap with ~terminated; stop GAE recursion with ~(terminated | truncated) when the next row belongs to a reset episode.

  2. The actor should treat advantages as fixed credit signals. Without detachment, actor loss can unintentionally update the critic or reward-processing graph.

Takeaway: PPO’s final .mean() is part of the objective. Decide whether deployment cares about the average token or the average prompt, then make masks, distributed aggregation and diagnostics match that choice.
