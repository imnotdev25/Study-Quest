🧩 Analogy: the movie ended vs the battery died

If a movie ends, there’s no more story. If your laptop battery dies mid-movie, the story still goes on; you just didn’t see it. Termination means the episode truly ended, so future value is 0. Truncation means you stopped watching (a time limit or a token limit), so you still need to estimate the rest with \(V(s)\).

2. Two ways a rollout can stop

An episode is terminated when the environment reaches a genuine terminal state:

  • the model emits EOS;

  • an agent submits its final answer;

  • the task succeeds or fails irreversibly.

An episode is truncated when data collection stops for an external reason:

  • maximum token limit;

  • maximum tool-call budget;

  • worker timeout;

  • rollout buffer boundary.

This matters when constructing critic targets:

\[y_t = r_t + \gamma (1-d_t) V(s_{t+1})\]

Here \(d_t\) should represent genuine termination.

At a terminal state:

\[y_t=r_t\]

because no future state value exists.

At a truncated state:

\[y_t=r_t+\gamma V(s_{t+1})\]

because the underlying process could have continued. Setting the bootstrap value to zero incorrectly claims that truncation has no future value.

For GAE:

\[\delta_t = r_t + \gamma(1-d_t)V(s_{t+1}) - V(s_t)\]

\[\hat A_t = \delta_t + \gamma\lambda(1-d_t)\hat A_{t+1}\]

At the final recorded truncated step, there is no later sampled TD error, but its own TD error should still contain the bootstrap value.

Tensor shapes:

  • rewards, values and next values: [B, T]

  • terminated and truncated flags: [B, T]

  • TD targets, deltas and advantages: [B, T]

For an LLM, reaching max_new_tokens is not automatically semantically equivalent to emitting EOS. It may indicate an incomplete answer whose continuation still has value.

DPO trains from fixed response pairs and does not bootstrap environment returns. It still needs correct EOS and padding masks when calculating response log-probabilities.

🔍 Deeper: keeping the two flags separate

TD target: \(y_t=r_{t+1}+\gamma\,(1-\text{terminated}_{t+1})\,V(s_{t+1})\). On truncation, keep the bootstrap \(V(s_T)\). GAE: stop the backward recursion at either boundary, but at a truncation put \(\gamma V(s_T)\) into the last \(\delta\).

The bias if you get it wrong: treating a truncation as terminal sets the target too low by \(\gamma V(s_T)\). The agent learns “reaching the time limit is bad,” which is false.

LLM case: EOS is terminal. Hitting max_new_tokens is truncation, unless the task explicitly treats unfinished answers as failures, in which case say so and give a reward for it.

🔑 Key ideas

  • “The rollout stopped” is not the same as “the environment ended.”

  • Store terminated and truncated as separate fields all the way through.

🚶 Walkthrough: truncation bias

\(\gamma=0.99\), \(V(s_T)=50\), last reward \(r=0\). Correct target at a timeout: \(0+0.99\cdot50=49.5\). Treated as terminal: \(0\). Bias \(=49.5\) on that step, and it propagates backward.

Common mistakes

  • Using the auto-reset observation as \(s_T\).

  • One done field for both events.

  • Treating max_new_tokens as EOS by default.

⚙️ Algorithm: GAE with separate termination and truncation flags
Input: \(r_{1:T}\), \(V(s_0),\dots,V(s_T)\), flags \(\text{term}_{1:T}\), \(\text{trunc}_{1:T}\), \(\gamma\), \(\lambda\)
\(A\gets0\)
for \(t=T-1\) down to \(0\) do
\(v_{\text{next}}\gets(1-\text{term}_{t+1})\,V(s_{t+1})\) ▷ at a truncation, \(V\) of the real final state
\(\delta_t\gets r_{t+1}+\gamma v_{\text{next}}-V(s_t)\)
\(\text{cont}\gets1-\max(\text{term}_{t+1},\text{trunc}_{t+1})\) ▷ stop the recursion at either boundary
\(A\gets\delta_t+\gamma\lambda\,\text{cont}\cdot A\); \(\hat A_t\gets A\)
end
return \(\hat A_t\), \(\hat R_t=\hat A_t+V(s_t)\)

Debugging experiments

Treat every maximum-length response as terminal:

done = terminated | truncated

The critic learns that hitting the token limit destroys all future value. This can create artificial pressure toward short responses.

Next, incorrectly bootstrap genuine EOS states:

bootstrap_mask = torch.ones_like(
    rewards
)

Now arbitrary critic predictions after EOS leak into targets.

Finally, set the truncated bootstrap value to an extreme number:

next_values[1, -1] = 10.0

The target becomes very large. Bootstrapping avoids time-limit bias, but it relies on critic accuracy; log bootstrap-value distributions and clip gradients when necessary.

Solutions

Bootstrap mask:

bootstrap_mask = (
    ~terminated
).to(values.dtype)

TD targets and residuals:

td_targets = (
    rewards
    + gamma
    * bootstrap_mask
    * next_values
)

deltas = td_targets - values

GAE:

for time in reversed(range(rewards.shape[1])):
    running_advantage = (
        deltas[:, time]
        + gamma
        * gae_lambda
        * bootstrap_mask[:, time]
        * running_advantage
    )

    advantages[:, time] = (
        running_advantage
    )

Buggy targets:

buggy_bootstrap_mask = (
    ~done
).to(values.dtype)

buggy_targets = (
    rewards
    + gamma
    * buggy_bootstrap_mask
    * next_values
)

Lost bootstrap value:

target_error = (
    td_targets - buggy_targets
)

The final genuine terminal target is:

\[y_{\text{terminal}}=1\]

The final truncated target is:

\[y_{\text{truncated}} = 1+0.9(0.8) = 1.72\]

The buggy implementation gives both final steps target 1.0, underestimating the truncated trajectory by:

\[1.72-1.0=0.72\]

GAE propagates some of this difference backward, so confusing truncation with termination can bias several preceding token or tool decisions—not only the final one.

Check answers

  1. The environment could have continued, so \(V(s_{t+1})\) estimates the missing future return.

  2. Otherwise, rewards and values from the next prompt or episode leak backward into the previous trajectory.

  3. If the task explicitly defines exceeding the token budget as an irreversible failure with no continuation value.

  4. Store separate terminated, truncated, validity-mask, EOS, length and bootstrap-value fields rather than one overloaded done.

Retrieval answers

  1. Dividing each sequence gradient by its realized length changes the relative influence of short and long responses; length is partly policy-controlled.

  2. Those actions were never executed, so including them creates fictitious reward, KL and gradient contributions.

Takeaway: “the rollout stopped” does not always mean “the environment ended.” Bootstrap through external truncations, zero bootstrap at genuine terminal states, and keep termination and truncation as separate fields throughout the LLM-RL pipeline.
