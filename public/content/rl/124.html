2. “The rollout stopped” does not always mean “the episode ended”

Two events can end stored data:

  • Termination: the underlying episode truly ended—such as EOS or task completion.

  • Truncation: collection stopped externally—such as a rollout-length limit—while the state could still have future value.

For an \(L\)-step target:

\[G_0^{(L)} = \sum_{t=0}^{L-1}\gamma^t r_t + \gamma^L(1-z)V(s_L)\]

where \(z=1\) only for a true termination.

Consider a continuing process with:

\[r_t=1,\qquad \gamma=0.9\]

Its exact value is:

\[V(s)=\frac{1}{1-\gamma}=10\]

If collection is truncated after five steps, the correct target is:

\[1+0.9+\cdots+0.9^4+0.9^5(10)=10\]

If truncation is incorrectly treated as termination:

\[G_{\text{wrong}} = 1+0.9+\cdots+0.9^4 = 4.0951\]

The critic is taught that hitting the collection boundary destroys future value.

For GAE, distinguish two masks:

\[\delta_t = r_t+\gamma b_tV(s_{t+1})-V(s_t)\]

  • \(b_t=0\) for true termination;

  • \(b_t=1\) for truncation when a valid bootstrap state exists.

The trace recursion normally stops at any unlinked stored-sequence boundary:

\[A_t = \delta_t+\gamma\lambda c_tA_{t+1}\]

Here \(c_t=0\) prevents residuals from another episode or unrelated chunk leaking backward. At a truncated final step, the bootstrap belongs inside \(\delta_t\); that does not require continuing the GAE trace into an unrelated batch row.

Tensor shapes:

  • rewards and valid-token mask: [B, T]

  • terminated, truncated, bootstrap values: [B]

  • return targets: [B, T]

For LLMs, EOS is normally terminal. A max_new_tokens cutoff is truncation only if continuation remains part of the intended task. If the environment scores the cutoff as the final failed answer, it is effectively terminal. Store the reason explicitly.

DPO has no bootstrap target, but truncated completions still require explicit masks and should not silently be treated as natural EOS completions.

Solutions

Return calculation:

def calculate_returns(
    rewards,
    mask,
    bootstrap_values,
):
    returns = torch.zeros_like(rewards)

    running_returns = (
        bootstrap_values.detach().clone()
    )

    for token_index in reversed(
        range(maximum_length)
    ):
        candidate_returns = (
            rewards[:, token_index]
            + gamma * running_returns
        )

        running_returns = torch.where(
            mask[:, token_index],
            candidate_returns,
            running_returns,
        )

        returns[:, token_index] = torch.where(
            mask[:, token_index],
            running_returns,
            torch.zeros_like(running_returns),
        )

    return returns

Check answers

  1. done often combines true termination with an external cutoff; only true termination necessarily removes future value.

  2. The final truncated TD residual includes \(V(s_{t+1})\). Stopping the trace then prevents unrelated later residuals from leaking across the stored boundary.

  3. It depends on the task contract. It is truncation if valid continuation remains; it is terminal if the environment ends and scores the cutoff as final.

  4. Artificially low boundary values can make long responses, lengthy tool plans, or states near collection limits appear undesirable.

  5. Store termination, truncation, finish reason, valid length, final observation, bootstrap value, EOS status, timeout/context-limit status, and whether another chunk continues the same episode.

Retrieval answers

  1. Beyond the permitted value-change interval, the clipped error can dominate while its clamp branch is flat, producing zero gradient for that sample.

  2. Value clipping is measured in return units. Rescaling rewards changes the clip’s relative restrictiveness.

Takeaway: stop traces at storage boundaries, but zero future value only at genuine terminal states. Conflating truncation with termination can train a critic to fear the data collector’s chunk length rather than the environment’s actual outcomes.
