🧩 Analogy: a forecast plus the forecaster’s track record

A weather forecaster predicts each day, and you also know which days they got wrong and how often you checked. AIPW combines a prediction for every unit with an inverse-probability correction on the units you observed. Either a good forecast or correct checking probabilities is enough to stay on target.

2. Predict the outcome, then correct the prediction

Adaptive routing creates two problems:

  • unequal assignment probabilities can bias raw arm means;

  • noisy outcomes give inverse-propensity weighting high variance.

Augmented inverse-propensity weighting—AIPW—combines a context-based outcome model with logged propensities.

Let:

\[e(x)=P(Z=1\mid x)\]

and let \(m_1(x)\) and \(m_0(x)\) predict candidate and control outcomes. Define:

\[\phi_{1,i} = m_1(x_i) + \frac{Z_i}{e_i} \left[ Y_i-m_1(x_i) \right]\]

\[\phi_{0,i} = m_0(x_i) + \frac{1-Z_i}{1-e_i} \left[ Y_i-m_0(x_i) \right]\]

Then:

\[\hat\tau_{\text{AIPW}} = \frac1N \sum_i \left( \phi_{1,i}-\phi_{0,i} \right)\]

Each term has two parts:

  1. a prediction for every prompt;

  2. a propensity-weighted correction when that policy was actually observed.

AIPW is doubly robust:

  • correct propensities can correct an inaccurate outcome model;

  • correct conditional outcome models can tolerate inaccurate propensities;

  • if both are wrong, no guarantee remains.

Adequate overlap is still necessary. A learned outcome model should produce held-out or cross-fitted predictions. Persist them detached—evaluation should not backpropagate into the model.

Tensor shapes:

  • contexts, assignments, rewards and propensities: [R, N]

  • candidate/control predictions: [R, N]

  • influence contributions: [R, N]

  • repeated effect estimates: [R]

For history-adaptive routing, the point estimate uses the actual conditional assignment probability. Uncertainty should additionally respect temporal dependence or use appropriate martingale methods.

DPO may train the candidate from preferences, while AIPW estimates its causal effect on an online outcome. Preference margins are not \(m_1(x)\), unless they have been separately validated as conditional outcome predictions.

🔍 Deeper: AIPW

For a binary routing decision \(A\in\{0,1\}\) with propensity \(e(x)=P(A=1|x)\) and outcome models \(\hat\mu_a(x)\): \[\hat\tau=\frac1n\sum_i\Big[\hat\mu_1(x_i)-\hat\mu_0(x_i)+\frac{A_i(Y_i-\hat\mu_1(x_i))}{e(x_i)}-\frac{(1-A_i)(Y_i-\hat\mu_0(x_i))}{1-e(x_i)}\Big].\] It’s consistent if either \(e\) or \(\hat\mu\) is correct, and efficient when both are. In practice, cross-fit \(\hat\mu\) (Topic 86).

🔑 Key ideas

  • AIPW is “prediction plus correction.”

  • Either trustworthy propensities or trustworthy outcome models protect consistency.

🚶 Walkthrough: one treated, one control unit

Treated: \(\hat\mu_1=0.6\), \(\hat\mu_0=0.5\), \(Y=1\), \(e=0.5\): term \(=0.1+\frac{0.4}{0.5}=0.9\). Control: \(\hat\mu_1=0.6\), \(\hat\mu_0=0.5\), \(Y=0\), \(e=0.5\): term \(=0.1-\frac{0-0.5}{0.5}=0.1+1.0=1.1\). The control did worse than predicted, which counts as evidence that treatment helps. The average over these two units is \(1.0\). Single units are noisy, and the average over many is what matters.

Common mistakes

  • Propensities near 0 or 1 without trimming or overlap checks.

  • In-sample outcome models.

  • Swapping the signs of the two correction terms.

Hints

  • Arm means require masked sums divided by arm counts.

  • IPW candidate contribution is Z * reward / e.

  • An AIPW correction uses reward - prediction, not the reverse.

  • Add each correction to the corresponding prediction.

  • Average candidate terms minus control terms across episodes.

  • Compute ESS separately for each repetition, then average the ESS fractions.

Debugging experiments

  • Reverse the residual to prediction - reward.

  • Use the candidate outcome prediction for both policies.

  • Recompute assignment propensities from an updated router.

  • Train a flexible outcome model on the same evaluated outcomes without cross-fitting.

  • Clip small propensities but report the result as the original population effect.

  • Allow gradients through outcome predictions during evaluation.

  • Use candidate-generated response features as though they were pre-treatment context.

Solutions

Naive estimator:

candidate_counts = assignment.sum(
    dim=1
)

control_counts = (
    1.0 - assignment
).sum(dim=1)

naive_candidate_values = (
    assignment * rewards
).sum(dim=1) / candidate_counts

naive_control_values = (
    (1.0 - assignment) * rewards
).sum(dim=1) / control_counts

naive_effects = (
    naive_candidate_values
    - naive_control_values
)

Ordinary IPW:

ipw_candidate_contributions = (
    assignment
    * rewards
    / true_propensities
)

ipw_control_contributions = (
    (1.0 - assignment)
    * rewards
    / (1.0 - true_propensities)
)

ipw_effects = (
    ipw_candidate_contributions
    - ipw_control_contributions
).mean(dim=1)

AIPW implementation:

def aipw_effect(
    propensities,
    candidate_predictions,
    control_predictions,
):
    candidate_corrections = (
        assignment
        / propensities
        * (
            rewards
            - candidate_predictions
        )
    )

    control_corrections = (
        (1.0 - assignment)
        / (1.0 - propensities)
        * (
            rewards
            - control_predictions
        )
    )

    candidate_terms = (
        candidate_predictions
        + candidate_corrections
    )

    control_terms = (
        control_predictions
        + control_corrections
    )

    return (
        candidate_terms
        - control_terms
    ).mean(dim=1)

Four robustness combinations:

aipw_correct_both = aipw_effect(
    true_propensities,
    true_candidate_predictions,
    true_control_predictions,
)

aipw_correct_propensity = aipw_effect(
    true_propensities,
    wrong_candidate_predictions,
    wrong_control_predictions,
)

aipw_correct_outcomes = aipw_effect(
    wrong_propensities,
    true_candidate_predictions,
    true_control_predictions,
)

aipw_both_wrong = aipw_effect(

    assignment / true_propensities
)

    (1.0 - assignment)
    / (1.0 - true_propensities)

    candidate_weights.sum(
        dim=1
    ).square()
    / candidate_weights
    .square()
    .sum(dim=1)
)

    control_weights.sum(
        dim=1
    ).square()
    / control_weights
    .square()
    .sum(dim=1)

    candidate_ess
    / episodes_per_repetition

    control_ess
    / episodes_per_repetition

The population values are:

\[J_1 = \frac12(0.85+0.35) = 0.60\]

\[J_0 = \frac12(0.80+0.30) = 0.55\]

so the exact effect is:

\[\tau=0.05\]

Because the candidate receives approximately 80% easy prompts while control receives approximately 80% hard prompts, the naive estimate approaches:

\[0.8(0.85)+0.2(0.35) - \left[ 0.2(0.80)+0.8(0.30) \right] = 0.35\]

Expected results:

  • naive: biased near 0.35;

  • correct-propensity IPW: centered near 0.05, with relatively high variance;

  • AIPW with both components correct: centered near 0.05, usually lowest variance;

  • correct propensity plus wrong outcomes: centered near 0.05;

  • wrong propensity plus correct outcomes: centered near 0.05;

  • both components wrong: biased near 0.35.

With correct outcome models, AIPW importance-weights only Bernoulli residual noise rather than full reward levels. This is the same variance-reduction pattern as a useful critic or policy-gradient baseline.

Check answers

  1. With correct \(e(x)\), inverse weighting transforms observed residual corrections into their population expectations, correcting systematic errors in \(m_1\) and \(m_0\).

  2. If \(m_a(x)=E[Y\mid X=x,Z=a]\), its observed residual has conditional mean zero. Multiplying that residual by an imperfect finite propensity does not change its zero expectation.

  3. No. If a policy has zero probability in some context, neither residual correction nor double robustness supplies the missing counterfactual outcome.

  4. Report the estimate and interval, overlap and ESS, propensity ranges, weight quantiles, outcome-model held-out calibration, cross-fitting scheme, subgroup effects, clipping sensitivity, policy versions and randomization unit.

Retrieval answers

  1. A pre-treatment baseline is balanced between randomized arms in expectation, so its subtraction removes noise without systematically changing their difference.

  2. Post-treatment features can be caused by the policy. Conditioning on them can remove genuine policy effects or create collider bias.

Takeaway: AIPW is “prediction plus correction.” Either trustworthy routing probabilities or trustworthy conditional outcome predictions can protect consistency; having both usually gives the most stable estimate.
