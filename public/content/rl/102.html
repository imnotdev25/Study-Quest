2. Give both policies the same exam questions

Prompts differ greatly in difficulty. If candidate and control receive unrelated prompt samples, this variation becomes evaluation noise.

Instead, evaluate both policies on prompt \(i\), then form:

\[D_i=Y_i^{\text{candidate}}-Y_i^{\text{control}}\]

The paired effect estimator is:

\[\hat\tau_{\text{paired}} = \frac1N\sum_{i=1}^{N}D_i\]

Its variance is:

\[\operatorname{Var}(\hat\tau_{\text{paired}}) = \frac{ \sigma_1^2+\sigma_0^2 -2\operatorname{Cov}(Y_1,Y_0) }{N}\]

Both outputs usually rise on easy prompts and fall on difficult prompts, creating positive covariance. Subtraction cancels much of this shared difficulty.

For independent prompt sets, that covariance is absent:

\[\operatorname{Var}(\hat\tau_{\text{independent}}) = \frac{\sigma_1^2}{N} + \frac{\sigma_0^2}{N}\]

Pairing means sharing the same pre-treatment prompt or task—not necessarily forcing identical token-level RNG. Different models can diverge immediately even with the same random seed.

Tensor shapes:

  • outcomes and prompt effects: [R, N]

  • paired differences: [R, N]

  • estimates and standard errors: [R]

For LLM judges, randomize candidate/control presentation order to avoid position bias. Preserve stable prompt IDs; one accidental row shuffle destroys the pairing.

DPO also uses two completions for one prompt, but its pairwise loss optimizes preference likelihood. It does not directly estimate the candidate’s online reward improvement.

Hints

  • Broadcast no extra dimensions: every simulated tensor is [R, N].

  • Paired outcomes share one difficulty tensor but use independent response noise.

  • Independent outcomes use separate difficulty tensors.

  • A paired standard error uses paired_differences.std(dim=1) / sqrt(N).

  • An unpaired standard error adds the two sample variances divided by \(N\).

  • Detect improvement when the one-sided lower bound exceeds zero.

  • Flatten both paired outcome matrices before torch.corrcoef.

Debugging experiments

  • Shuffle only the candidate rows before differencing.

  • Match outputs by batch position rather than stable prompt ID.

  • Fill a missing candidate outcome with zero to preserve tensor shape.

  • Drop pairs with policy-dependent timeouts without analyzing missingness.

  • Treat paraphrases as independent when they share one underlying template.

  • Present the candidate first to the judge every time.

  • Force matching token seeds and assume this guarantees comparable trajectories.

    paired_candidate_outcomes

maximum_paired_identity_error = (
    paired_effects
    - paired_effects_as_difference_of_means

Each paired outcome has variance:

\[2^2+1^2=5\]

Their shared difficulty gives covariance:

\[\operatorname{Cov}(Y_1,Y_0)=2^2=4\]

so their correlation is approximately:

\[\rho=\frac45=0.8\]

The paired difference cancels difficulty:

\[D_i = 0.40+\epsilon_{1,i}-\epsilon_{0,i}\]

Therefore:

\[SE_{\text{paired}} = \sqrt{\frac{1^2+1^2}{100}} \approx0.141\]

Independent prompts retain difficulty noise:

\[SE_{\text{independent}} = \sqrt{\frac{2(2^2+1^2)}{100}} \approx0.316\]

Typical detection rates are roughly:

  • correct paired analysis: 0.88;

  • paired data with an unpaired SE: 0.20;

  • genuinely independent prompts: 0.35.

The unpaired formula applied to paired data does not change the point estimate. It discards the known covariance reduction and becomes severely conservative.

Check answers

  1. It enters the paired variance with a minus sign, cancelling prompt-level variation shared by both policies.

  2. No. It changes precision and experimental design, not the estimand.

  3. Pairing helps little when within-prompt stochasticity dominates or candidate/control outcomes have weak correlation.

  4. Preserve an explicit pair mask. Do not substitute zeros; investigate policy-dependent failures and use missing-data corrections or sensitivity bounds when complete pairs are not missing randomly.

Retrieval answers

  1. Selecting the maximum conditions on positive estimation noise, so the winning observed score exceeds its true value on average.

  2. Lock the checkpoint, decoding settings, evaluator, aggregation rule, target population, primary metric and stopping rule.

Takeaway: compare policies on the same prompts and analyze the differences. Prompt difficulty then becomes shared context to subtract away instead of noise you must overcome with more samples.
