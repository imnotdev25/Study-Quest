🧩 Analogy: seatbelt plus airbag

A seatbelt alone helps. An airbag alone helps. Together you’re protected if either one works. Doubly robust evaluation combines a reward model (biased, but smooth) with importance sampling (unbiased, but noisy). The IS part corrects the model’s mistakes, and the model keeps the IS noise small.

2. Two imperfect ways to evaluate a policy

Consider a one-step contextual bandit:

  • observe context \(x\);

  • choose action \(a\);

  • receive reward \(r\).

A direct-method evaluator learns a reward model:

\[\hat Q(x,a)\approx\mathbb E[R\mid x,a]\]

It estimates the target policy’s value as:

\[\hat V_{\text{DM}} = \frac1N \sum_i \sum_a \pi(a\mid x_i)\hat Q(x_i,a)\]

This has low variance but inherits reward-model bias.

Importance sampling instead uses logged rewards:

\[\rho_i = \frac{\pi(a_i\mid x_i)} {\mu(a_i\mid x_i)}\]

\[\hat V_{\text{IS}} = \frac1N\sum_i\rho_i r_i\]

It avoids a reward-model assumption, but rare actions can produce large, noisy ratios.

The doubly robust estimator combines them:

\[\hat V_{\text{DR}} = \frac1N\sum_i \left[ \underbrace{ \sum_a\pi(a\mid x_i)\hat Q(x_i,a) }_{\text{reward-model prediction}} + \underbrace{ \rho_i \left( r_i-\hat Q(x_i,a_i) \right) }_{\text{logged correction}} \right]\]

Think of \(\hat Q\) as an invoice estimate. Importance sampling corrects only the prediction error observed in the logged action.

Under standard assumptions, DR remains consistent if either:

  • the reward model is correct, or

  • the logged behavior propensities are correct and have target-policy support.

It is not magic: if both are wrong, the result can be biased. Extreme importance ratios also remain dangerous.

Tensor shapes for \(R\) repeated experiments, batch \(B\), actions \(A\):

  • contexts and logged actions: [R, B]

  • policy probabilities: [R, B, A]

  • rewards, ratios and DR terms: [R, B]

  • estimates: [R]

DPO trains a policy from chosen/rejected response pairs. Doubly robust estimation evaluates a policy using logged actions, rewards and logging probabilities.

🔍 Deeper: double robustness

One-step (bandit) form: \[\hat V_{\text{DR}}=\frac1N\sum_i\Big[\underbrace{\textstyle\sum_a\pi(a|x_i)\hat r(x_i,a)}_{\text{model}}+\underbrace{\rho_i\big(r_i-\hat r(x_i,a_i)\big)}_{\text{correction}}\Big].\]

  • If \(\rho\) is correct: \(\mathbb E_b[\rho(r-\hat r)]=\mathbb E_\pi[r]-\mathbb E_\pi[\hat r]\), so the model terms cancel and you get the truth.

  • If \(\hat r\) is correct: the residual \(r-\hat r\) has mean 0, so the correction vanishes on average whatever \(\rho\) is.

The bias is roughly (propensity error) \(\times\) (model error), so two decent components give a small bias. The variance comes from \(\rho\cdot\)residual, which is small when \(\hat r\) is good.

🔑 Key ideas

  • DR is unbiased if either the propensities or the reward model are right.

  • A good reward model shrinks IS variance, and IS fixes the model’s bias.

🚶 Walkthrough: one DR term

Model prediction for \(\pi\): \(\text{dm}=0.6\). Logged action: \(\hat r=0.5\), \(\rho=1.5\), observed \(r=1\). \(\text{dr}=0.6+1.5(1-0.5)=1.35\). Plain IS would give \(1.5\cdot1=1.5\). DR’s correction is smaller because the model explains part of the reward.

Common mistakes

  • Fitting \(\hat r\) on the same logs you evaluate (residuals look like 0, see Topic 86).

  • Computing \(\text{dm}\) under the logging policy instead of the target \(\pi\).

  • Clipping \(\rho\) without reporting the added bias.

⚙️ Algorithm: Doubly robust evaluation (one-step)
Input: logs \((x_i,a_i,r_i,b(a_i|x_i))\), reward model \(\hat r\) (fit on separate data), target \(\pi\)
for \(i=1,\dots,N\) do
\(\text{dm}_i\gets\sum_a\pi(a|x_i)\,\hat r(x_i,a)\) ▷ model’s prediction for \(\pi\)
\(\rho_i\gets\pi(a_i|x_i)/b(a_i|x_i)\)
\(\text{dr}_i\gets\text{dm}_i+\rho_i\big(r_i-\hat r(x_i,a_i)\big)\) ▷ correct the model’s error
end
return \(\frac1N\sum_i\text{dr}_i\) (and use the \(\text{dr}_i\) values for a bootstrap interval)

3. PyTorch exercise — repair a biased reward model

import torch
from torch.distributions import Categorical

torch.manual_seed(7)

num_trials = 200
batch_size = 512
num_contexts = 2
num_actions = 2

# True mean reward: [contexts, actions].
true_reward_means = torch.tensor([
    [0.2, 0.8],  # context 0 prefers action 1
    [0.7, 0.3],  # context 1 prefers action 0
])

# Logging policy poorly covers the better action.
behavior_probs = torch.tensor([
    [0.8, 0.2],
    [0.2, 0.8],
])

# Target policy usually chooses the better action.
target_probs = torch.tensor([
    [0.1, 0.9],
    [0.9, 0.1],
])

# Deliberately biased reward model.
estimated_q = torch.tensor([
    [0.35, 0.70],
    [0.55, 0.40],
])

# Independent logged datasets: [trials, batch].

    0,
    num_contexts,
    (num_trials, batch_size),
)

    probs=behavior_for_context
)

    contexts,
    logged_actions,
]

logged_rewards = torch.bernoulli(
    chosen_true_means
)

# TODO 2: Logged-action behavior and target probabilities.
chosen_behavior_probs = ...
chosen_target_probs = ...

# TODO 3: Target-to-behavior importance ratios.
ratios = ...

# Direct-method value for every context.
target_for_context = target_probs[contexts]
estimated_q_for_context = estimated_q[contexts]

# TODO 4: Expected Q under the target policy.
direct_terms = ...

direct_estimates = direct_terms.mean(dim=1)

importance_estimates = (
    ratios * logged_rewards
).mean(dim=1)

# TODO 5: Doubly robust correction.
chosen_estimated_q = ...
doubly_robust_estimates = ...

# Exact value for each sampled context batch.
true_q_for_context = true_reward_means[contexts]

true_values = (
    target_for_context
    * true_q_for_context
).sum(dim=-1).mean(dim=1)

def rmse(estimates):
    return (
        (estimates - true_values)
        .square()
        .mean()
        .sqrt()

print("Mean true value:", true_values.mean().item())

print(
    "Direct method:",
    f"mean={direct_estimates.mean().item():.3f}",
    f"RMSE={rmse(direct_estimates).item():.3f}",
)

print(
    "Importance sampling:",
    f"mean={importance_estimates.mean().item():.3f}",
    f"RMSE={rmse(importance_estimates).item():.3f}",
)

print(
    "Doubly robust:",
    f"mean={doubly_robust_estimates.mean().item():.3f}",
    f"RMSE={rmse(doubly_robust_estimates).item():.3f}",
)

print("Maximum importance ratio:", ratios.max().item())

Debugging experiments

Reverse the ratio:

ratios = (
    chosen_behavior_probs
    / chosen_target_probs
)

The correction no longer transforms behavior-policy samples into target-policy expectations.

Then remove the correction:

doubly_robust_estimates = direct_terms.mean(dim=1)

This reduces DR to the biased direct-method estimate.

Finally, corrupt both the behavior probabilities and reward model. The “doubly robust” guarantee no longer applies: two incorrect components do not cancel automatically.

In a real pipeline, avoid evaluating a highly flexible reward model on the exact samples used to fit it. Use held-out data or cross-fitting to reduce overfitting bias.

Solutions

Context-specific behavior probabilities:

behavior_for_context = (
    behavior_probs[contexts]
)

Selected probabilities and ratios:

chosen_behavior_probs = behavior_probs[
    contexts,
    logged_actions,
]

chosen_target_probs = target_probs[
    contexts,
    logged_actions,
]

ratios = (
    chosen_target_probs
    / chosen_behavior_probs
)

Direct-method terms:

direct_terms = (
    target_for_context
    * estimated_q_for_context
).sum(dim=-1)

Doubly robust estimate:

chosen_estimated_q = estimated_q[
    contexts,
    logged_actions,
]

corrections = ratios * (
    logged_rewards
    - chosen_estimated_q
)

doubly_robust_estimates = (
    direct_terms + corrections
).mean(dim=1)

For context 0, the target value is:

\[0.1(0.2)+0.9(0.8)=0.74\]

For context 1:

\[0.9(0.7)+0.1(0.3)=0.66\]

With equally common contexts:

\[V^\pi=\frac{0.74+0.66}{2}=0.70\]

The biased reward model predicts:

\[\frac{ [0.1(0.35)+0.9(0.70)] + [0.9(0.55)+0.1(0.40)] }{2} = 0.60\]

Thus the direct method is biased downward.

The largest ratio occurs when the target assigns probability 0.9 to an action receiving behavior probability 0.2:

\[\rho_{\max}=\frac{0.9}{0.2}=4.5\]

IS and DR should average near \(0.70\), but DR will normally have lower RMSE because it importance-weights the reward-model residual rather than the entire reward.

Check answers

  1. The model prediction supplies a low-variance starting value; the weighted residual corrects its observed error.

  2. Zero. Conditioned on context and action, \(E[R-\hat Q(x,a)]=0\).

  3. No. If the behavior policy never logs a target action, neither its reward nor its model error can be checked from data.

  4. Report reward-model held-out error, propensity calibration, weight percentiles, ESS, support violations, uncertainty intervals and estimates from DM, IS and DR separately.

Retrieval answers

  1. It avoids multiplying early rewards by ratios from future actions that could not have affected them.

  2. Evaluation is unidentified for those actions: no reweighting method can recover outcomes never observed under the logging policy.

Takeaway: direct evaluation trusts a reward model; importance sampling trusts logged propensities. Doubly robust evaluation uses both, letting weighted observations correct reward-model mistakes while usually reducing variance relative to pure importance sampling.
