2. Selecting the highest proxy score selects its errors too

Suppose true utility is \(r(y)\), while a reward model produces:

\[\hat r(y)=r(y)+\epsilon(y)\]

For a random completion, the error may average to zero:

\[E[\epsilon]\approx0\]

But best-of-\(N\) chooses:

\[y^*=\arg\max_{i\le N}\hat r(y_i)\]

The selected error is no longer centered:

\[E[\epsilon(y^*)]>0\]

This is the optimizer’s curse: selection actively searches for positive measurement errors.

Now suppose some completion contains an exploitable feature \(h(y)\):

\[\hat r(y) = r(y)+\epsilon(y)+b\,h(y)\]

If exploits occur independently with probability \(p\), the probability that at least one appears among \(N\) candidates is:

\[P(\text{exploit available}) = 1-(1-p)^N\]

Even with \(p=0.005\):

\[1-(0.995)^{256}\approx0.723\]

A rare exploit becomes common under enough search.

Best-of-\(N\) is not policy-gradient RL, but it isolates the same pressure. PPO changes the generation distribution to find high reward; if reward-model errors are systematic, later rollouts contain increasingly unusual and exploitable outputs.

Tensor shapes:

  • candidate rewards and proxy scores: [B, N]

  • selected candidate IDs: [B, 1]

  • selected proxy reward, true reward and exploit flag: [B]

The dangerous region is the optimized tail, not average validation traffic. Overall correlation can remain positive while top-scoring outputs are mostly failures.

Use an evaluator independent of the training reward model. Useful diagnostics include proxy–true gaps versus search budget, exploit frequency, ensemble disagreement, score-tail audits and human evaluation of top-reward outputs.

DPO does not perform online reward-model search, but it can still learn systematic shortcuts in preference data. It also requires independent evaluation outside the training preference pipeline.

Solutions

Candidate construction:

ordinary_true_rewards = torch.randn(
    num_prompts,
    maximum_candidates,
)

exploit_flags = (
    torch.rand(
        num_prompts,
        maximum_candidates,
    )
    < exploit_probability
)

true_rewards = torch.where(
    exploit_flags,
    torch.full_like(
        ordinary_true_rewards,
        exploit_true_reward,
    ),
    ordinary_true_rewards,
)

proxy_noise = (
    proxy_noise_sd
    * torch.randn_like(true_rewards)
)

clean_proxy_scores = (
    true_rewards + proxy_noise
)

vulnerable_proxy_scores = (
    clean_proxy_scores
    + exploit_proxy_bonus
    * exploit_flags.to(torch.float32)
)

Selection:

def select_candidates(
    selection_scores,
    candidate_count,
):
    scores = selection_scores[
        :, :candidate_count
    ]

    corresponding_true_rewards = true_rewards[
        :, :candidate_count
    ]

    corresponding_exploits = exploit_flags[
        :, :candidate_count
    ]

    selected_indices = scores.argmax(
        dim=1,
        keepdim=True,
    )

    selected_proxy_scores = scores.gather(
        dim=1,
        index=selected_indices,
    ).squeeze(1)

    selected_true_rewards = (
        corresponding_true_rewards.gather(
            dim=1,
            index=selected_indices,
        ).squeeze(1)
    )

    selected_exploits = (
        corresponding_exploits.gather(
            dim=1,
            index=selected_indices,
        ).squeeze(1)
    )

    return (
        selected_proxy_scores,
        selected_true_rewards,
        selected_exploits,
    )

The probability of encountering at least one exploit is approximately:

\(N\) \(1-(1-0.005)^N\)
\(N\) \(1-(1-0.005)^N\)
1 0.005
4 0.020
16 0.077
64 0.274
256 0.723

Because an exploit receives proxy score around:

\[-2+8=6\]

it usually wins whenever present. At large \(N\), vulnerable-proxy score rises while selected true reward eventually falls toward the exploit’s true value.

The clean noisy proxy exhibits ordinary selection bias: its selected proxy score is optimistic, but selected true quality generally improves because its errors are not systematically attached to a bad feature.

The vulnerable proxy’s aggregate correlation with truth can remain positive. The top-scoring tail nevertheless contains a far larger exploit fraction than the full candidate population.

Check answers

  1. Conditioning on the maximum preferentially selects candidates whose measurement error happened to be positive.

  2. Their appearance probability compounds with samples, rollout volume and optimization steps.

  3. Winner’s curse selects random positive noise; reward hacking exploits a repeatable feature that systematically raises proxy reward while harming true utility.

  4. Optimization moves probability mass toward rare score tails that random validation barely measures.

  5. Keep the training reward, final evaluator, human audit set, adversarial probes and confirmation data operationally independent.

Retrieval answers

  1. On separable data, every finite margin can be enlarged to reduce logistic loss, even after all pairwise rankings are correct.

  2. Temperature rescales confidence probabilities while preserving the ordering of every positive-temperature margin.

Takeaway: evaluate the reward model where optimization will take it. A proxy that looks adequate on random outputs can fail catastrophically once sampling or PPO repeatedly searches for its highest-scoring mistakes.
