2. PPO ratios depend on the policy’s memory

PPO uses the importance ratio:

\[r_t(\theta)= \exp\left( \log\pi_\theta(a_t\mid o_t,h_t) - \log\pi_{\text{old}}(a_t\mid o_t,h_t^{\text{old}}) \right)\]

If the current and rollout policies are identical and both reconstruct the same history, then:

\[r_t=1\]

A common recurrent-PPO bug is shuffling individual timesteps and resetting the hidden state for every sample. The numerator then uses:

\[\pi_\theta(a_t\mid o_t,h=0)\]

while the stored denominator came from:

\[\pi_{\text{old}}(a_t\mid o_t,h_t^{\text{old}})\]

Ratios can move away from one even though no parameters changed. PPO may report false clipping and false KL drift.

Train recurrent policies using sequence chunks:

  1. Start at an episode boundary with zero hidden state, or reconstruct the chunk’s initial state.

  2. Use a short burn-in prefix to rebuild memory.

  3. Compute loss only on the learning portion.

  4. Keep timestep order intact.

  5. Reset state at terminal boundaries and mask padding.

For a burn-in length \(L\):

\[h_c=f_\theta(o_{c-L:c},h_{c-L})\]

The prefix creates \(h_c\), but its tokens do not contribute directly to the PPO loss. The hidden state can be detached at the truncated-BPTT boundary while advantages and old log-probabilities remain detached everywhere.

Tensor shapes:

  • observations: [B, T, D];

  • recurrent states: [B, T, H];

  • initial hidden state: [layers, B, H];

  • actions, log-probabilities, advantages and masks: [B, T];

  • logits: [B, T, A].

For transformer policies, the same problem appears when response chunks are evaluated without their prompt or preceding tokens.

DPO also needs the complete conditioning context when computing chosen and rejected log-probabilities. It does not use PPO rollout ratios, burn-in advantages or online environment interaction.

🔍 Deeper: ratios need the same history

The ratio \(\rho_t=\pi_\theta(a_t|h_t)/\pi_{\text{old}}(a_t|h_t)\) requires recomputing \(h_t\) under \(\theta\) from the same sequence of past inputs. Practical recipe: split trajectories into chunks of length \(L\), store the rollout hidden state at the chunk’s start, and shuffle chunks, not timesteps. Optionally add a burn-in prefix to refresh stale stored states. Reset the hidden state only at true episode starts. Sanity check: before the first gradient step, every \(\rho_t\) must be exactly 1.

🔑 Key ideas

  • Recurrent PPO minibatches are sequences, not bags of steps.

  • At step 0 of an update, ratios must equal 1.

🚶 Walkthrough: unchanged weights, wrong ratio

At rollout: \(h_1\) from the cue gives \(\pi_{\text{old}}(\text{L}|h_1)=0.9\). In training, timestep 1 is evaluated alone with \(h=0\): \(\pi_\theta(\text{L}|0)=0.5\). So \(\rho=0.56\) with \(\theta=\theta_{\text{old}}\). PPO now “thinks” the policy changed a lot, clips it, and computes garbage gradients.

Common mistakes

  • Shuffling timesteps across sequences.

  • Using a zero hidden state at chunk starts.

  • Not checking \(\rho\equiv1\) at the start of each update.

Hints

  • Create the mask with torch.arange(time_steps) < lengths[:, None].

  • Categorical(logits=logits) accepts [B, T, A].

  • Flatten observations to [B*T, 1, D].

  • Restore isolated logits to [B, T, A].

  • Ratio is exp(current_log_prob - old_log_prob).

  • Apply mask before reducing diagnostics.

  • A typical PPO clipping interval is [0.8, 1.2].

Debugging experiments

Shuffle timesteps before passing them through the GRU. Tensor shapes remain valid, but hidden states no longer represent the rollout histories.

Process only observations[:, 2:] with zero initial state. This resembles starting a PPO chunk midway through an episode without burn-in.

Carry the final hidden state from one batch into a batch of unrelated prompts. This leaks information between episodes and makes results depend on batch ordering.

Finally, calculate clip fraction without mask. Arbitrary padded actions and recurrent outputs can dominate the diagnostic.

Solutions

Valid mask:

mask = (
    torch.arange(time_steps)[None, :]
    < lengths[:, None]
)

Rollout quantities:

rollout_states, _ = encoder(
    observations
)

rollout_logits = policy_head(
    rollout_states
)

rollout_policy = Categorical(
    logits=rollout_logits
)

actions = rollout_policy.sample()

old_log_probs = (
    rollout_policy.log_prob(actions)
    .detach()
)

Correct recomputation:

correct_states, _ = encoder(
    observations
)

correct_logits = policy_head(
    correct_states
)

correct_log_probs = Categorical(
    logits=correct_logits
).log_prob(actions)

Incorrect isolated recomputation:

isolated_observations = (
    observations.reshape(
        batch_size * time_steps,
        1,
        observation_dim,
    )
)

isolated_states, _ = encoder(
    isolated_observations
)

isolated_logits = policy_head(
    isolated_states[:, 0]
).reshape(
    batch_size,
    time_steps,
    num_actions,
)

isolated_log_probs = Categorical(
    logits=isolated_logits
).log_prob(actions)

Ratios and diagnostics:

correct_ratios = torch.exp(
    correct_log_probs - old_log_probs
)

incorrect_ratios = torch.exp(
    isolated_log_probs - old_log_probs
)

maximum_correct_error = (
    correct_ratios[mask] - 1.0
).abs().max()

mean_incorrect_error = (
    incorrect_ratios[mask] - 1.0
).abs().mean()

incorrect_clip_fraction = (
    (
        (incorrect_ratios[mask] < 0.8)
        | (incorrect_ratios[mask] > 1.2)
    )
    .to(torch.float64)
    .mean()
)

Correct ratios equal one because both evaluations use identical parameters and identical histories.

Isolated evaluation resets memory at every timestep. Later actions were originally conditioned on longer histories, so their incorrect ratios will generally deviate more.

Check answers

  1. The model must also receive the same history, reset boundaries, action mask and recurrent initialization.

  2. Burn-in reconstructs memory before the portion used for optimization.

  3. Detach stored old log-probabilities, returns and advantages. Detach recurrent state only at chosen truncated-BPTT boundaries.

  4. Check ratio error before any optimizer step, initial KL, clip fraction, results by trajectory position and sensitivity to chunk length or burn-in length.

Retrieval answers

  1. Observation aliasing occurs when different hidden states produce the same observation but require different actions.

  2. Reset at episode termination, padding boundaries and boundaries between unrelated prompts.

Takeaway: recurrent PPO minibatches are sequences, not bags of timesteps. If history reconstruction is wrong, ratios, clipping and KL diagnostics are already invalid before the first update.
