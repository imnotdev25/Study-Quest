🧩 Analogy: one day’s commute time

Your commute averages 30 minutes, but today took 22. Today’s “minutes over average” is \(-8\): negative, even though nobody thinks commuting takes negative time. A single sample of a quantity whose average is positive can still be negative. KL is like that: it’s always \(\ge0\) in expectation, but a single token’s sampled estimate can be negative.

2. Expected KL versus individual token estimates

For a state \(s\), forward KL is:

\[D_{\mathrm{KL}}(\pi\Vert\pi_{\mathrm{ref}}) = \sum_a \pi(a\mid s) \log \frac{\pi(a\mid s)} {\pi_{\mathrm{ref}}(a\mid s)} \ge 0\]

Enumerating an LLM vocabulary at every generated position is expensive. Instead, for a token sampled from the current policy:

\[A\sim\pi(\cdot\mid s)\]

use:

\[k_1(A) = \log\pi(A\mid s) - \log\pi_{\mathrm{ref}}(A\mid s)\]

Its expectation is the forward KL:

\[\mathbb E_{A\sim\pi}[k_1(A)] = D_{\mathrm{KL}}(\pi\Vert\pi_{\mathrm{ref}})\]

But an individual \(k_1\) can be negative. That merely means the sampled token was more probable under the reference policy. A negative minibatch estimate can therefore occur when the true KL is small and sampling noise is large.

A useful nonnegative estimator is:

\[k_3 = e^{-k_1}-1+k_1\]

Because \(e^{-x}\ge 1-x\), every \(k_3\ge0\). It has the same expectation:

\[\mathbb E_\pi[e^{-k_1}] = \sum_a\pi(a)\frac{\pi_{\mathrm{ref}}(a)}{\pi(a)} = 1\]

so:

\[\mathbb E_\pi[k_3] = D_{\mathrm{KL}}(\pi\Vert\pi_{\mathrm{ref}})\]

For variable-length responses:

\[\widehat{\mathrm{KL}}_i = \sum_t M_{i,t}k_{i,t}\]

The response mask \(M\) must exclude padding and post-termination positions.

Tensor shapes:

  • actions and token log-ratios: [B, T]

  • response mask: [B, T]

  • sequence KL estimates: [B]

  • batch estimate: scalar

DPO uses related policy-versus-reference log-ratios on fixed chosen and rejected responses. It does not estimate online rollout KL by sampling fresh tokens from the current policy.

🔍 Deeper: three KL estimators

With \(x\sim\pi\) and \(r=\pi_{\text{ref}}(x)/\pi(x)\), we want \(\mathrm{KL}(\pi\|\pi_{\text{ref}})=\mathbb E_\pi[-\log r]\).

  • \(k_1\): unbiased, but negative whenever \(r>1\), with high variance.

  • \(k_2\): always \(\ge0\) and low variance, but biased (good when \(\pi\approx\pi_{\text{ref}}\)).

  • \(k_3\): unbiased (since \(\mathbb E_\pi[r]=1\)) and always \(\ge0\) (since \(\log r\le r-1\)). This is the usual choice, e.g. in GRPO.

Keep the ratio direction explicit: swapping \(\pi\) and \(\pi_{\text{ref}}\) estimates the other KL.

🔑 Key ideas

  • KL is non-negative only in expectation, so negative tokens aren’t a bug.

  • Prefer \(k_3\), mask padding, and say whether you report token-average or sequence-total.

🚶 Walkthrough: one token, three estimates

\(\pi=0.5\), \(\pi_{\text{ref}}=0.6\), so \(r=1.2\). \(k_1=-\ln1.2=-0.182\) (negative). \(k_2=\tfrac12(0.182)^2=0.017\). \(k_3=0.2-0.182=0.018\).

Common mistakes

  • Clamping \(k_1\) at 0 (that biases it).

  • Mixing ratio directions between code paths.

  • Comparing token-mean KL with sequence-sum KL.

Hints

  • Exact KL is sum(policy_prob * (policy_log_prob - reference_log_prob)).

  • Compare each position with its corresponding sequence length.

  • Index the log-probability vectors using actions.

  • For \(k_3\), exponentiate the negative log-ratio.

  • Convert the Boolean mask to the estimator’s dtype before multiplication.

Debugging experiments

Reverse the log-ratio:

k1_tokens = (
    selected_reference_log_probs
    - selected_policy_log_probs
)

This no longer estimates \(D_{\mathrm{KL}}(\pi\Vert\pi_{\mathrm{ref}})\) under samples from \(\pi\). Ratio direction and sampling distribution must agree.

Next, compute:

k3_tokens = (
    k1_tokens.exp() - 1.0 - k1_tokens
)

This expression is nonnegative, but it corresponds to a different ratio convention. Mixing formulas can silently bias the KL estimate.

Finally, average valid tokens instead of summing per sequence:

token_mean = (
    k1_tokens[response_mask].mean()
)

This estimates average KL per token. The sequence sum estimates total response KL. They answer different questions and react differently to response length.

4. Checks for understanding

  1. How can a sampled KL contribution be negative when KL is nonnegative?

  2. Why can \(k_3\) be preferable for a noisy KL controller?

  3. Why should both per-token and per-sequence KL be reported?

  4. What numerical problem can exp(-k1_tokens) encounter?

Solutions

Exact KL:

exact_token_kl = (
    policy_probs
    * (
        policy_log_probs
        - reference_log_probs
    )
).sum()

Response mask:

response_mask = (
    positions < lengths[:, None]
)

Selected log-probabilities:

selected_policy_log_probs = (
    policy_log_probs[actions]
)

selected_reference_log_probs = (
    reference_log_probs[actions]
)

KL estimators:

k1_tokens = (
    selected_policy_log_probs
    - selected_reference_log_probs
)

k3_tokens = (
    torch.exp(-k1_tokens)
    - 1.0
    + k1_tokens
)

Masked sequence estimates:

mask = response_mask.to(
    k1_tokens.dtype
)

k1_sequences = (
    k1_tokens * mask
).sum(dim=-1)

k3_sequences = (
    k3_tokens * mask
).sum(dim=-1)

Both sampled means should approach:

\[\mathbb E[L]\, D_{\mathrm{KL}} (\pi\Vert\pi_{\mathrm{ref}})\]

where \(L\) is response length. Their finite-batch values need not match exactly.

The unmasked calculation always includes six sampled positions. Because the real mean length is approximately four, it generally overestimates total response KL by counting fictitious padding tokens.

Check answers

  1. KL is an expectation. Individual log-ratios may be negative even though their policy-weighted expectation is nonnegative.

  2. Its individual contributions are nonnegative, avoiding misleading negative controller measurements; its variance advantages are not universal.

  3. Per-token KL measures local drift, while sequence KL also reflects response length. A policy can reduce per-token KL but increase total KL by generating longer responses.

  4. A large negative \(k_1\) makes exp(-k1) overflow. Inspect log-ratio ranges and use higher precision or controlled clamping for diagnostics.

Retrieval answers

  1. Increase \(\beta\), strengthening the penalty that pulls the policy toward the reference.

  2. KL only measures policy distance. A nearby policy can still be unsafe, and a more distant policy can sometimes be better.

Takeaway: KL is nonnegative only after taking the correct expectation. Keep ratio direction explicit, mask nonexistent tokens, distinguish token-average from sequence-total KL, and avoid treating one noisy sampled estimate as ground truth.
