2. One valid interval inspected repeatedly is not repeatedly valid

Suppose \(d_i\) is an episode-level candidate-minus-control score and:

\[\Delta = \underbrace{E[d_i]}_{\text{true policy improvement}}\]

At one pre-specified sample size \(n\), a normal lower bound is:

\[LCB_n = \underbrace{\bar d_n}_{\text{estimated improvement}} - \underbrace{ z_{1-\alpha}\frac{s_n}{\sqrt n} }_{\text{single-look uncertainty margin}}\]

This has approximately \(1-\alpha\) coverage at that one look. If you inspect it after every evaluation batch and stop at the first positive bound:

\[P\!\left( \exists k:LCB_{n_k}>0 \mid\Delta=0 \right) > \alpha\]

Each look offers another opportunity to promote because of favorable noise.

Planned finite monitoring

For \(K\) planned looks, Bonferroni uses:

\[\alpha_k = \underbrace{\frac{\alpha}{K}}_{\text{error budget per look}}\]

\[LCB_k^{\mathrm{Bonf}} = \bar d_{n_k} - \underbrace{ z_{1-\alpha/K}\frac{s_{n_k}}{\sqrt{n_k}} }_{\text{wider multiplicity-adjusted margin}}\]

The union bound guarantees total false-promotion probability at most \(\alpha\), without requiring independent looks.

Indefinite bounded-score monitoring

Allocate error across looks using:

\[\alpha_k = \underbrace{ \frac{6\alpha}{\pi^2k^2} }_{\text{error budget at look }k}, \qquad \sum_{k=1}^{\infty}\alpha_k=\alpha\]

If every independent score satisfies \(a\le d_i\le b\), Hoeffding gives the radius:

\[r_k = \underbrace{ (b-a) \sqrt{ \frac{\log(1/\alpha_k)} {2n_k} } }_{\text{anytime-valid uncertainty margin}}\]

Therefore:

\[P\!\left( \exists k: \Delta < \underbrace{\bar d_{n_k}-r_k}_{LCB_k^{\mathrm{anytime}}} \right) \le\alpha\]

You may stop when this lower bound exceeds zero without invalidating the guarantee.

The boundedness assumption matters. Raw OPE scores can be enormous when importance weights are enormous. Clipping creates a bound but also changes the estimator and introduces bias.

For LLM evaluation, repeatedly checking held-out reward after each PPO or DPO checkpoint has the same optional-stopping problem. DPO’s held-out preference accuracy also remains a preference metric—not an estimate of online environment reward.

Tensor shapes:

  • simulated score sequences: [R, T]

  • running means at evaluation looks: [R, K]

  • confidence radii: [K]

  • promotion decisions: [R, K]

Hints

  • A one-sided 5% critical value is approximately 1.645.

  • Bonferroni uses family_alpha / num_looks.

  • Use:

6.0 * family_alpha / (
    math.pi**2 * look_indices.square()
)

  • The Hoeffding radius is:

score_range * torch.sqrt(
    torch.log(1.0 / alpha_spending)
    / (2.0 * look_sizes_float)
)

  • Select cumulative sums at indices look_sizes - 1.

  • “Repeated naive” means applying single_look_radii at every look.

Debugging experiments

  • Stop at the first favorable fixed-sample interval and report it as pre-specified.

  • Add more evaluation looks without changing the error budget.

  • Treat correlated tokens as independent observations.

  • Use a Hoeffding bound while unbounded importance weights remain.

  • Clip OPE scores but omit the resulting bias from the report.

  • Change the target policy, reward metric or judge during monitoring without accounting for the new search.

  • Select a checkpoint and certify it using the same repeatedly inspected data.

Solutions

Critical values:

single_look_z = standard_normal.icdf(
    torch.tensor(
        1.0 - family_alpha
    )
)

bonferroni_z = standard_normal.icdf(
    torch.tensor(
        1.0
        - family_alpha / num_looks
    )
)

Confidence radii:

look_sizes_float = look_sizes.to(
    torch.float64
)

# Under the null, scores are ±0.1,
# so their standard deviation is 0.1.
single_look_radii = (
    single_look_z
    * 0.10
    / torch.sqrt(look_sizes_float)
)

bonferroni_radii = (
    bonferroni_z
    * 0.10
    / torch.sqrt(look_sizes_float)
)

look_indices = torch.arange(
    1,
    num_looks + 1,
    dtype=torch.float64,
)

alpha_spending = (
    6.0
    * family_alpha
    / (
        math.pi**2
        * look_indices.square()
    )
)

anytime_radii = (
    score_range
    * torch.sqrt(
        torch.log(
            1.0 / alpha_spending
        )
        / (
            2.0 * look_sizes_float
        )
    )
)

Simulation:

def simulate_running_means(
    positive_probability,
):
    positive_events = (
        torch.rand(
            num_repetitions,
            maximum_episodes,
        )
        < positive_probability
    )

    scores = torch.where(
        positive_events,
        torch.tensor(positive_score),
        torch.tensor(negative_score),
    )

    cumulative_scores = scores.cumsum(
        dim=1
    )

    running_means = (
        cumulative_scores[
            :,
            look_sizes - 1,
        ]
        / look_sizes_float[None, :]
    )

    return running_means


null_running_means = (
    simulate_running_means(
        null_positive_probability
    )
)

alternative_running_means = (
    simulate_running_means(
        alternative_positive_probability
    )
)

Promotion rules:

def any_promotion_rate(
    running_means,
    radii,
):
    lower_bounds = (
        running_means
        - radii[None, :]
    )

    promoted = (
        lower_bounds > 0.0
    ).any(dim=1)

    return (
        promoted
        .to(torch.float64)
        .mean()
    )


null_single_final_rate = (
    (
        null_running_means[:, -1]
        - single_look_radii[-1]
        > 0.0
    )
    .to(torch.float64)

)

exact_null_effect = (
    null_positive_probability
    * positive_score
    + (
        1.0
        - null_positive_probability
    )
    * negative_score
)

    alternative_positive_probability
    * positive_score
    + (
        1.0

The effects are:

\[\Delta_{\mathrm{null}} = \underbrace{0.5(0.1)+0.5(-0.1)}_{\text{balanced score signs}} = 0\]

\[\Delta_{\mathrm{alt}} = \underbrace{0.54(0.1)+0.46(-0.1)}_{\text{slightly better candidate}} = 0.008\]

Typical results:

True condition Final only Repeated naive Bonferroni Anytime
True condition Final only Repeated naive Bonferroni Anytime
Null, \(\Delta=0\) 0.05 0.25 0.01 below 0.01
Alternative, \(\Delta=0.008\) 0.97 0.99 0.79 0.22

The exact Monte Carlo values vary by seed. The key result is that repeatedly using a nominal 5% bound produces a false-promotion rate around 25%, whereas the adjusted procedures remain below 5%.

The anytime method is particularly conservative because it uses only the known score range, not an estimated variance.

Check answers

  1. Yes. It is evaluated once at its pre-specified sample size.

  2. No. Repeated opportunities to cross zero inflate the family-wise false-promotion probability.

  3. The bounded Hoeffding sequence here; its guarantee uses limited distributional information.

  4. Yes. Optional stopping is permitted at the pre-declared looks under the confidence-sequence assumptions.

  5. The Hoeffding guarantee becomes invalid. A rare, larger score could cause much more uncertainty than the radius permits.

Retrieval answers

  1. Candidate and control scores share episode noise. Positive covariance appears with a minus sign in the variance of their difference.

  2. Pairing is invalid when rows do not represent the same task or independent sampling unit—for example, pairing unrelated episodes merely by batch position.

Takeaway: decide whether evaluation is fixed-horizon or continuously monitored. A fixed-sample confidence interval is not an anytime-valid deployment gate; repeated peeking must spend error budget or use a genuine confidence sequence.
