🧩 Analogy: grading on a curve per row of desks

Curve the exam per row of desks instead of for the whole class, and a solid student sitting in a row of geniuses gets marked “below average.” Advantage whitening per microbatch does exactly this: a genuinely good action can get a negative whitened advantage because its chunk happened to be strong.

Raw advantages \((1,2,-2.5,0.5)\), chunks \(\{a_1,a_2\}\) and \(\{a_3,a_4\}\). Per-chunk whitening makes the good action \(a_1\) look bad.

2. Whitening controls advantage scale

PPO implementations often standardize—or “whiten”—advantages:

\[\tilde A_i = \frac{A_i-\mu_A} {\sigma_A+\epsilon}\]

For masked token advantages:

\[\mu_A = \frac{\sum_{i,t}M_{i,t}A_{i,t}} {\sum_{i,t}M_{i,t}}\]

\[\sigma_A^2 = \frac{\sum_{i,t}M_{i,t}(A_{i,t}-\mu_A)^2} {\sum_{i,t}M_{i,t}}\]

Centering makes the batch-average advantage zero. Dividing by the standard deviation makes actor-gradient scale less sensitive to raw reward units.

But whitening is not harmless bookkeeping:

  • it changes gradient magnitude;

  • batch centering uses estimated—not exact—statistics;

  • tiny standard deviation can amplify noise;

  • padding must not enter the statistics;

  • local microbatch whitening can change gradient direction.

The rollout-wide statistics should normally be computed once, before PPO minibatch epochs. In distributed training, aggregate the valid count, sum and squared sum across workers.

Do not confuse this with GRPO’s per-prompt reward standardization. PPO advantage whitening usually normalizes a larger rollout batch; GRPO compares responses within the same prompt group.

Tensor shapes:

  • advantages and response mask: [B, T], or [B] for sequence advantages;

  • masked mean, variance and standard deviation: scalar;

  • normalized advantages: same shape as advantages;

  • policy gradient: [num_parameters]

DPO does not estimate advantages. It directly optimizes preference-pair log-ratios, although any custom example weighting still needs explicit normalization rules.

🔍 Deeper: masked global statistics

\(\mu=\frac{\sum_tm_tA_t}{\sum_tm_t}\), \(\sigma^2=\frac{\sum_tm_t(A_t-\mu)^2}{\sum_tm_t}\), \(\tilde A_t=\frac{A_t-\mu}{\sigma+\varepsilon}\). Compute this once over the whole rollout batch (all ranks), and detach it. Two traps. Padding with \(A=0\) included in \(\mu\) pulls the mean toward 0 and can flip signs. And whitening subtracts the mean, so in a batch where everything was good, half the actions are told they were bad. That’s fine for variance reduction, but be aware of it.

🔑 Key ideas

  • Whitening should describe the rollout batch, not an execution chunk.

  • Masked, global, detached, and monitored.

🚶 Walkthrough: local vs global

Raw \(A=(1,2,-2.5,0.5)\). Global \(\mu=0.25\), population \(\sigma=1.68\), so \(\tilde A=(0.45,1.04,-1.64,0.15)\). The signs are preserved. Per chunk: \(\{1,2\}\to(-1,1)\) and \(\{-2.5,0.5\}\to(-1,1)\). Action \(a_1\) (raw \(+1\)) is now \(-1\).

Common mistakes

  • Padding included in mean or std.

  • Whitening inside each microbatch.

  • Using whitened advantages to build value targets.

Hints

  • Use population standard deviation with unbiased=False.

  • Global whitening uses one mean and standard deviation for all four samples.

  • Compute local statistics only from local_values.

  • Use torch.nn.functional.cosine_similarity(..., dim=0).

  • Each local pair becomes approximately [-1, +1].

Debugging experiments

Include padded advantages set to zero when computing statistics. Enough padding drags the mean toward zero and changes every valid token’s normalized credit.

Next, use a microbatch containing identical advantages. Its standard deviation is zero; without epsilon the result becomes nan, while a very small epsilon can make tiny numerical differences dominate.

Finally, recompute advantage statistics independently for every PPO minibatch and epoch. Samples then receive different normalized credits depending on how the rollout is shuffled.

Solutions

Global statistics:

global_mean = raw_advantages.mean()

global_std = raw_advantages.std(
    unbiased=False
)

Global whitening:

global_advantages = (
    raw_advantages - global_mean
) / (
    global_std + epsilon
)

Local whitening:

for indices in microbatch_indices:
    local_values = raw_advantages[indices]

    local_mean = local_values.mean()

    local_std = local_values.std(
        unbiased=False
    )

    local_advantages[indices] = (
        local_values - local_mean
    ) / (
        local_std + epsilon
    )

Gradients:

raw_gradient = estimate_ascent_gradient(
    raw_advantages
)

global_gradient = estimate_ascent_gradient(
    global_advantages
)

local_gradient = estimate_ascent_gradient(
    local_advantages
)

Cosine similarities:

raw_global_cosine = (
    torch.nn.functional.cosine_similarity(
        raw_gradient,
        global_gradient,
        dim=0,
    )
)

raw_local_cosine = (
    torch.nn.functional.cosine_similarity(
        raw_gradient,
        local_gradient,
        dim=0,
    )
)

The raw advantages for action 1 sum to 30, while those for action 0 sum to 3. The raw gradient therefore strongly favors action 1.

Global whitening assigns below-average credits to the action- 0 responses and above-average credits to the action- 1 responses. It preserves the preference while changing gradient scale.

Local whitening produces approximately:

\[[-1,+1,-1,+1]\]

Within each microbatch, both responses selected the same action. Their opposite normalized credits therefore cancel, producing an approximately zero policy gradient.

Check answers

  1. The actor gradient is linear in advantage, so dividing advantages by \(\sigma_A\) scales the actor update by approximately \(1/\sigma_A\).

  2. Each microbatch receives its own offset and scale. This changes samples’ weights relative to samples in other microbatches.

  3. No. Value targets, KL penalties, entropy terms, clipping thresholds and verifier-reward composition can still depend on reward scale.

  4. Log valid count, raw and normalized mean/std, extrema, near-zero-variance rate, percentiles and actor-gradient norm.

Retrieval answers

  1. Clipping is nonlinear. Clipping individual gradients before they cancel changes their relative scales and can rotate the accumulated update.

  2. Each locally normalized chunk receives equal outer weight regardless of its valid count or original scale.

Takeaway: advantage whitening should describe the rollout batch, not an arbitrary execution chunk. Compute masked global statistics once, detach the result and monitor whether normalization is amplifying noise.
