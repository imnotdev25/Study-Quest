🧩 Analogy: zero food poisonings in 20 meals

A restaurant with zero food poisonings in 20 meals hasn’t proven it’s safe. The “rule of three” says that with 0 events in \(n\) tries, the true rate could still be as high as about \(3/n\) (95% confidence): 15% here. “20% error on this sample” isn’t “risk below 20%.”

The rule of three: proving a rate below 0.1% needs about 3000 clean samples.

2. Empirical risk is only an estimate

Suppose 2 of 10 directly answered requests are wrong:

\[\hat R=\frac{2}{10}=0.20\]

That does not establish that the population risk is at most 20%. Ten samples provide little evidence.

For a fixed threshold, Hoeffding’s inequality gives a simple upper confidence bound:

\[U_k = \min\left( 1,\; \hat R_k+ \sqrt{\frac{\log(1/\delta)}{2k}} \right)\]

Here:

  • \(k\) is the number of answered calibration requests;

  • \(\delta=0.05\) gives a 95% confidence level;

  • the margin shrinks as \(1/\sqrt{k}\).

If we inspect \(K\) thresholds and select the best-looking one, a pointwise bound is insufficient. A union-bound correction gives:

\[U_k^{\text{sim}} = \min\left( 1,\; \hat R_k+ \sqrt{ \frac{\log(K/\delta)}{2k} } \right)\]

Under IID calibration data and fixed candidate rules, all \(K\) bounds then hold simultaneously with probability at least \(1-\delta\).

Choose the largest coverage satisfying:

\[U_k^{\text{sim}}\le R_{\max}\]

This is intentionally conservative. Exact binomial and conformal risk-control methods can provide sharper guarantees.

Tensor shapes:

  • sorted confidence and errors: [B];

  • empirical risks and upper bounds: [B];

  • chosen threshold: scalar.

The guarantee does not cover distribution shift, incorrect labels, correlated samples or changing the model afterward. For tool agents, count independent prompts or episodes—not highly correlated timesteps—as statistical samples.

DPO can improve refusal behavior from preference data, but its loss does not provide a finite-sample guarantee on deployment risk.

🔍 Deeper: bounds with a safety margin

Hoeffding: for losses in \([0,1]\), with probability \(\ge1-\delta\), \(R\le\hat R+\sqrt{\ln(1/\delta)/(2n)}\). Search penalty: if you tried \(m\) thresholds and picked the best, use \(\delta/m\) (a union bound) or a method like Learn-then-Test. Tighter: Clopper–Pearson (exact binomial) bounds are better for small rates. The assumptions are i.i.d. samples from the deployment distribution, and drift breaks them.

🔑 Key ideas

  • Include finite-sample uncertainty and correct for threshold search.

  • State the assumptions behind any safety claim.

🚶 Walkthrough: does 15% clear a 20% target?

\(n=1000\), \(\hat R=0.15\), \(\delta=0.05\): margin \(=\sqrt{\ln20/2000}=0.055\), so the bound is \(0.205>0.20\). It fails, narrowly. After searching 10 thresholds: margin \(=\sqrt{\ln200/2000}=0.073\), so the bound is \(0.223\).

Common mistakes

  • Treating \(\hat R\) as the guarantee.

  • Searching thresholds without a correction.

  • Applying an i.i.d. bound to correlated turns from the same users.

Hints

  • Sort confidence descending and use the same indices for correctness.

  • Prefix risk is cumulative errors divided by prefix size.

  • Pointwise radius uses math.log(1 / delta).

  • Simultaneous radius uses math.log(K / delta).

  • Clamp upper bounds to at most one.

  • Select the final index whose risk or bound is at most maximum_risk.

Debugging experiments

  • Search 1,000 thresholds but use only the pointwise bound. This ignores multiple comparisons.

  • Treat every token or tool step as independent. Correlation makes the effective sample size much smaller.

  • Change the verifier after selecting the threshold. The bound no longer describes the deployed router.

  • Observe zero errors in a tiny prefix and report zero risk. The confidence radius should remain large.

  • Reuse training rollouts for calibration. Memorization can make the bound meaningless for new prompts.

Solutions

Sorting:

sorted_confidences, order = torch.sort(
    confidences,
    descending=True,
)

sorted_errors = (
    ~is_correct[order]
).to(confidences.dtype)

Empirical risks:

prefix_error_counts = (
    sorted_errors.cumsum(dim=0)
)

empirical_risks = (
    prefix_error_counts
    / answered_counts
)

coverages = (
    answered_counts
    / num_examples
)

Confidence bounds:

pointwise_radii = torch.sqrt(
    torch.full_like(
        answered_counts,
        math.log(1.0 / delta),
    )
    / (2.0 * answered_counts)
)

simultaneous_radii = torch.sqrt(
    torch.full_like(
        answered_counts,
        math.log(
            num_candidates / delta
        ),
    )
    / (2.0 * answered_counts)
)

pointwise_upper_bounds = (
    empirical_risks
    + pointwise_radii
).clamp(max=1.0)

simultaneous_upper_bounds = (
    empirical_risks
    + simultaneous_radii
).clamp(max=1.0)

Selecting operating points:

empirical_index = torch.where(
    empirical_risks
    <= maximum_risk
)[0][-1]

pointwise_index = torch.where(
    pointwise_upper_bounds
    <= maximum_risk
)[0][-1]

simultaneous_index = torch.where(
    simultaneous_upper_bounds
    <= maximum_risk
)[0][-1]

Reconstructing the router:

chosen_count = (
    simultaneous_index + 1
)

chosen_threshold = (
    sorted_confidences[
        simultaneous_index
    ]
)

answer_mask = (
    confidences
    >= chosen_threshold
)

realized_coverage = (
    answer_mask
    .to(confidences.dtype)
    .mean()
)

realized_risk = (
    (
        (~is_correct)
        & answer_mask
    )
    .to(confidences.dtype)
    .sum()
    / answer_mask.sum()
)

Empirical selection answers all 1,000 examples because:

\[\hat R_{1000} = \frac{150}{1000} = 0.15\]

The pointwise upper bound at that point is approximately:

\[0.15+ \sqrt{ \frac{\log 20}{2000} } \approx0.189\]

But that bound assumes the threshold was fixed in advance. It does not account for searching 1,000 candidates.

The simultaneous rule selects 850 examples:

\[\hat R_{850} = \frac{105}{850} \approx0.1235\]

\[U_{850}^{\text{sim}} \approx 0.1235+ \sqrt{ \frac{\log(20000)}{1700} } \approx0.1999\]

Thus coverage is 85% while the corrected upper bound remains just below 20%.

Check answers

  1. Searching creates multiple chances to find an artificially low empirical risk; the union correction covers all candidate thresholds together.

  2. With few observations, zero errors is weak evidence, so the \(1/\sqrt{k}\) margin remains large.

  3. No. It assumes deployment resembles the calibration distribution and that samples satisfy the independence assumptions.

  4. Report calibration size, error count, coverage, threshold, confidence level, number of candidates, sampling unit, subgroup bounds and evidence of distribution drift.

Retrieval answers

  1. Selective risk divides selected errors by the number of requests actually answered.

  2. Choosing and reporting on the same observations exploits sampling noise and produces an optimistic risk estimate.

Takeaway: “20% error on this sample” is not the same as “risk is below 20%.” Include finite-sample uncertainty, correct for threshold search and state the assumptions behind any safety claim.
