🧩 Analogy: a quiz contestant who passes

On a quiz show where wrong answers cost points, the best contestants pass on questions they’re unsure of. They answer fewer questions, but their accuracy on the ones they do answer is much higher. Selective prediction is the same: choose when to answer, when to use a tool, and when to abstain.

Stylized risk–coverage curve. Pick the largest coverage that stays under the target.

2. Confidence decides where the model acts

A calibrated outcome model might estimate:

\[c(x)=P(\text{direct answer is correct}\mid x)\]

A selective agent answers only when confidence exceeds threshold \(\tau\):

\[g_\tau(x)=\mathbf 1[c(x)\ge\tau]\]

Otherwise it uses a tool, asks for clarification or abstains.

Two quantities describe this router:

\[\operatorname{coverage}(\tau) = \frac1N\sum_i g_\tau(x_i)\]

\[\operatorname{risk}(\tau) = \frac{ \sum_i g_\tau(x_i)\ell_i }{ \sum_i g_\tau(x_i) }\]

For zero-one loss, selective risk is the error rate among answered examples—not among all examples.

Sorting by confidence produces a risk–coverage curve. For the top \(k\) examples:

\[C_k=\frac{k}{N}, \qquad R_k=\frac{\sum_{i=1}^{k}\ell_{(i)}}{k}\]

Higher thresholds usually reduce coverage and should reduce population risk if confidence is informative. Empirical risk need not decrease monotonically: one confident mistake can create a temporary spike.

Abstention is not free. If fallback calls a slow tool, the actual objective may be:

\[J(\tau) = \mathbb E[ g_\tau r_{\text{direct}} + (1-g_\tau)r_{\text{fallback}} ]\]

Tensor shapes:

  • confidence and correctness: [B];

  • answer mask: [B];

  • prefix coverage and risk: [B];

  • selected threshold: scalar.

For LLM agents, sequence likelihood is not necessarily correctness confidence. Use a calibrated verifier, reward model or outcome predictor.

DPO can teach refusal preferences from fixed comparisons, but does not guarantee a particular risk at a chosen coverage or adapt to live fallback costs.

🔍 Deeper: risk and coverage

With confidence score \(c(x)\) and threshold \(t\): coverage \(\kappa(t)=P(c\ge t)\), selective risk \(R(t)=P(\text{error}\mid c\ge t)\). Choose \(t^*=\arg\max_t\kappa(t)\) s.t. \(R(t)\le r^*\) on a validation set (with a finite-sample margin, Topic 79). Three actions (answer / tool / abstain) generalize this with costs: choose the action minimizing expected cost \(=P(\text{error})\cdot c_{\text{err}}+c_{\text{action}}\).

🔑 Key ideas

  • Abstention changes which requests the model handles, not what it knows.

  • Measure error among answered requests, on separate validation data.

🚶 Walkthrough: pick the threshold

10 validation items sorted by confidence. Correctness from most to least confident: \(1,1,1,1,0,1,0,1,0,0\). Answer the top 4: error 0%. Top 5: 1/5 \(=20\%\). Top 6: 1/6 \(=17\%\). Top 7: 2/7 \(=29\%\). With a 20% target, answer the top 6 (60% coverage).

Common mistakes

  • Reporting overall error instead of error among answered.

  • Tuning the threshold on test data.

  • Ignoring that abstained requests still need handling (cost, user experience).

Hints

  • Use torch.sort(..., descending=True).

  • Convert Boolean errors to the confidence dtype.

  • Prefix errors are a cumulative sum.

  • Choose the final index where prefix_risks <= maximum_risk.

  • The correct denominator is answer_mask.sum().

  • Threshold ties can select more examples than the chosen prefix.

Debugging experiments

  • Sort confidence ascending. The curve now answers the least confident requests first.

  • Divide selected errors by num_examples; abstentions incorrectly dilute the reported risk.

  • Clamp an empty selection’s denominator to one. This silently reports zero risk at zero coverage.

  • Tune and report the threshold on the same dataset. The selected risk becomes optimistically biased.

  • Apply the threshold after a distribution shift without recalibration. The original risk target may no longer hold.

Solutions

Sort confidence and correctness together:

sorted_confidences, order = torch.sort(
    confidences,
    descending=True,
)

sorted_correct = is_correct[order]

Construct the curve:

sorted_errors = (
    ~sorted_correct
).to(confidences.dtype)

prefix_errors = sorted_errors.cumsum(
    dim=0
)

prefix_risks = (
    prefix_errors / answered_counts
)

coverages = (
    answered_counts / num_examples
)

Choose the largest feasible prefix:

feasible = (
    prefix_risks
    <= maximum_risk + 1e-12
)

chosen_index = torch.where(
    feasible
)[0][-1]

chosen_count = chosen_index + 1

threshold = sorted_confidences[
    chosen_index
]

Apply it to the original ordering:

answer_mask = (
    confidences >= threshold
)

realized_coverage = (
    answer_mask.to(
        confidences.dtype
    ).mean()
)

realized_risk = (
    (
        (~is_correct)
        & answer_mask
    )
    .to(confidences.dtype)
    .sum()
    / answer_mask.sum()
)

The denominator bug:

buggy_risk = (
    (
        (~is_correct)
        & answer_mask
    )
    .to(confidences.dtype)
    .mean()
)

The selected operating point is:

\[\tau=0.69\]

It answers 10 of 15 requests:

\[\text{coverage}=\frac{10}{15}\approx0.667\]

Two selected answers are incorrect:

\[\text{selective risk}=\frac{2}{10}=0.20\]

The buggy calculation reports:

\[\frac{2}{15}\approx0.133\]

because it incorrectly allows five abstentions to dilute the error rate.

Check answers

  1. Calibration makes confidence match observed frequencies; selective prediction uses that confidence to decide where the model acts.

  2. Individual mistakes enter discrete prefixes, so observed risk can rise and later fall.

  3. When tool latency, monetary cost, failure probability or remaining budget affects the value of routing.

  4. Report coverage, selective risk, fallback rate, risk–coverage curves, subgroup results, confidence drift, fallback cost and zero-coverage cases.

Retrieval answers

  1. \(T>1\) softens probabilities while preserving their argmax.

  2. Policy probability describes action-selection frequency. Success probability requires an outcome model calibrated against observed results.

Takeaway: abstention changes which requests the model handles, not what the model knows. Measure errors among answered requests, validate thresholds on separate data and monitor the full risk–coverage trade-off.
