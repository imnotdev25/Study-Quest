2. The idea (Thinking Machines Lab, Oct 2025, building on GKD, Agarwal et al., 2024)

Sample from the student, score each sampled token with the teacher, and minimize the per-token reverse KL: \[\mathrm{KL}(\pi_\theta\|\pi_T)=\mathbb E_{y\sim\pi_\theta}\Big[\sum_t\log\pi_\theta(y_t|y_{<t})-\log\pi_T(y_t|y_{<t})\Big].\] In RL terms, the per-token advantage is \(-\big(\log\pi_\theta(y_t)-\log\pi_T(y_t)\big)\) with discount 0, so an existing RL loop with a KL term becomes distillation by swapping the reference model for a teacher. Why it’s attractive: feedback is dense (every token, not one bit per episode), it trains on states the student actually visits, and the reward can’t be hacked: low KL simply means teacher-like behaviour. The authors report reaching an RL-trained teacher’s performance at a small fraction of RL’s compute. Caveat: reverse KL only sharpens what the student can already sample, so do SFT or mid-training first to get the teacher’s behaviour within reach.

🔑 Key ideas

  • Student samples, teacher grades every token, and the advantage is minus the log-ratio.

  • Dense, on-policy and hard to hack, but it needs a teacher and a reasonable starting student.

🚶 Walkthrough: one token

The student samples a token with \(\log\pi_\theta=-0.5\). The teacher gives it \(\log\pi_T=-2.0\). Advantage \(=-(-0.5+2.0)=-1.5\): the teacher thinks this token is far less likely, so push it down. Another token with \(\log\pi_\theta=-3.0\), \(\log\pi_T=-1.0\): advantage \(+2.0\), push it up.

Common mistakes

  • Sampling from the teacher (that’s ordinary SFT distillation, with exposure bias).

  • Forgetting to detach the advantage.

  • A tokenizer mismatch between student and teacher (the log-probs are for different tokens).

Solutions

import torch

torch.manual_seed(0)
contexts, vocab = 3, 5
teacher_logits = torch.randn(contexts, vocab) * 2
student_logits = torch.zeros(contexts, vocab, requires_grad=True)
opt = torch.optim.Adam([student_logits], lr=0.05)


def reverse_kl():
    s = student_logits.log_softmax(-1)
    t = teacher_logits.log_softmax(-1)
    return (s.exp() * (s - t)).sum(-1).mean().item()


print(f"start reverse KL {reverse_kl():.3f}")
for step in range(301):
    ctx = torch.randint(0, contexts, (256,))
    with torch.no_grad():
        tok = torch.multinomial(student_logits.softmax(-1)[ctx], 1).squeeze(1)   # student samples
    logp_s = student_logits.log_softmax(-1)[ctx, tok]
    logp_t = teacher_logits.log_softmax(-1)[ctx, tok]                           # teacher scores them
    advantage = -(logp_s - logp_t).detach()                                       # dense per-token reward
    loss = -(advantage * logp_s).mean()
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 100 == 0:
        print(f"step {step}: reverse KL {reverse_kl():.3f}")

Check answers

  1. The student is corrected in the states its own mistakes lead to, which offline teacher data never covers.

  2. The objective is closeness to the teacher’s distribution itself. There’s no separate proxy whose errors could be exploited.

Retrieval answers: (1) \(-\beta(\log\pi_\theta-\log\pi_{\text{ref}})\). (2) It heavily penalizes putting mass where the target has little, so the student concentrates on the target’s main modes.

Takeaway: when a stronger model exists, on-policy distillation gives RL-style training with dense, trustworthy per-token feedback.
