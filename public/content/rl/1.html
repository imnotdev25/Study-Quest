2. The bandit problem

Imagine three unfamiliar restaurants. Each produces a different but noisy level of satisfaction:

  • Restaurant A is usually average.

  • Restaurant B is usually good.

  • Restaurant C varies considerably.

You do not know these properties initially.

Every evening, you must choose one restaurant and observe only the reward from that choice. You never see what the other restaurants would have produced.

This is a multi-armed bandit:

  • One state: choosing again.

  • Actions: the available arms.

  • Reward: noisy feedback from the chosen arm.

  • Objective: maximize total reward over repeated choices.

There are no meaningful state transitions, so this is simpler than a full MDP.

Estimated action value

For action \(a\), maintain the average reward observed so far:

\[Q(a)=\frac{\text{sum of rewards from }a} {\text{number of times }a\text{ was selected}}\]

This can be updated without storing every old reward:

\[Q_{n+1}(a) = Q_n(a)+\frac{1}{N(a)} \left(R_n-Q_n(a)\right)\]

The term

\[R_n-Q_n(a)\]

is the estimation error:

  • Positive error: the result was better than expected.

  • Negative error: it was worse than expected.

  • \(1/N(a)\): how much one new observation should influence the running average.

This resembles taking a small step toward a target:

\[\text{new estimate} = \text{old estimate} + \text{step size}\times\text{error}\]

But this is not gradient descent. Here, the formula directly updates a sample average; no loss is differentiated.

Exploration versus exploitation

A greedy policy always chooses:

\[a_t=\arg\max_a Q(a)\]

That exploits current knowledge, but an early lucky reward can make it commit to the wrong action.

An \(\epsilon\)-greedy policy chooses:

\[a_t = \begin{cases} \text{random action} & \text{with probability }\epsilon\\ \arg\max_a Q(a) & \text{otherwise} \end{cases}\]

With \(\epsilon=0.1\):

  • roughly 10% of choices explore;

  • roughly 90% exploit.

The realized fraction will not be exactly 10%.

LLM connection: Suppose an agent chooses among search, calculator, Python, or answering directly. Always selecting the tool with the best early score can trap the agent in a locally good but inferior tool-use policy.

🔍 Deeper: incremental means, recency, and the exploration ceiling

Incremental mean. \(Q_{n+1}=\frac1n\sum_{i=1}^n R_i=\frac1n\big(R_n+(n-1)Q_n\big)=Q_n+\frac1n(R_n-Q_n)\).

Constant step size. With fixed \(\alpha\), unrolling gives \(Q_{n+1}=(1-\alpha)^nQ_1+\sum_{i=1}^n\alpha(1-\alpha)^{n-i}R_i\): an exponentially weighted average where recent rewards count most. That’s what you want when the arms drift.

Exploration ceiling. With \(k\) arms, once the best arm is greedy, \(P(\text{best})=(1-\epsilon)+\epsilon/k\). For \(\epsilon=0.5,\ k=3\): \(0.667\), so the long-run average reward is at most \(0.5\cdot 1.0+0.5\cdot\frac{0.2+1.0+0.7}{3}\approx 0.82\).

Simulated on the exercise’s bandit (2000 seeds). Greedy gets stuck, too much exploration hits the 0.82 ceiling, and \(\epsilon=0.1\) approaches the best possible 1.0 (dashed).

🔑 Key ideas

  • New estimate = old + step \(\times\) (target \(-\) old). You’ll see this shape in every topic.

  • Too little exploration: you get stuck. Too much: you waste pulls. A small \(\epsilon\) usually wins.

🚶 Walkthrough: greedy gets stuck in four steps

True means \((0.2,1.0,0.7)\), \(\epsilon=0\), all \(Q=0\), ties go to arm 0.

  • Step 1: pull arm 0, reward \(+0.9\) (lucky). \(N=(1,0,0)\), \(Q=(0.9,0,0)\).

  • Step 2: arm 0 again, reward \(-0.4\). \(Q_0=0.9+\frac12(-0.4-0.9)=0.25\). Still the largest.

  • Steps 3+: arm 0 keeps winning while \(Q_0>0\). Arms 1 and 2 are never tried, so the best arm (\(\mu=1.0\)) is never discovered.

Common mistakes

  • Updating \(Q\) before incrementing \(N\) (divide-by-zero, or a wrong first average).

  • Not resetting \(Q,N\) between \(\epsilon\) settings or seeds.

  • Judging \(\epsilon\) from one seed instead of an average over many.

⚙️ Algorithm: \(\epsilon\)-greedy bandit with sample-average estimates
Input: \(k\) arms, exploration rate \(\epsilon\), number of steps \(T\)
\(Q(a)\gets0,\ N(a)\gets0\) for every arm \(a\)
for \(t=1,\dots,T\) do
if \(u<\epsilon\) where \(u\sim\mathcal U(0,1)\) then
\(a\gets\) uniformly random arm ▷ explore
else
\(a\gets\arg\max_aQ(a)\), ties broken randomly ▷ exploit
end
pull \(a\) and observe reward \(R\)
\(N(a)\gets N(a)+1\)
\(Q(a)\gets Q(a)+\frac{1}{N(a)}\big(R-Q(a)\big)\)
end

One clean way to compare epsilon settings:

import torch

def run_bandit(epsilon, seed, num_steps=1000):
    torch.manual_seed(seed)

    true_means = torch.tensor([0.2, 1.0, 0.7])
    q_estimates = torch.zeros(3)
    counts = torch.zeros(3, dtype=torch.long)
    total_reward = 0.0

    for _ in range(num_steps):
        if torch.rand(()) < epsilon:
            action = torch.randint(3, ())
        else:
            action = q_estimates.argmax()

        reward = true_means[action] + torch.randn(())

        counts[action] += 1
        error = reward - q_estimates[action]
        q_estimates[action] += error / counts[action]

        total_reward += reward.item()

    return q_estimates, counts, total_reward / num_steps


for epsilon in [0.0, 0.01, 0.1, 0.5]:
    estimates, counts, mean_reward = run_bandit(
        epsilon=epsilon,
        seed=7,
    )
    print(
        epsilon,
        estimates,
        counts,
        round(mean_reward, 3),
    )

For a fair experiment, repeat over many seeds and average the results.

Check answers

  1. Early noise can make a bad arm look best; greedy selection may never gather evidence from the others.

  2. The first observation should use \(N(a)=1\). Updating before incrementing would divide by zero.

  3. No. During exploration, the random choice can also select the optimal arm:

\[P(\text{optimal}) = (1-\epsilon)+\frac{\epsilon}{3}\]

assuming it is the unique greedy arm.

  1. Later epsilon settings inherit knowledge learned during earlier experiments, making the comparison invalid.

  2. \(1/N(a)\) approaches zero, so the estimate adapts extremely slowly when reward distributions change. A constant step size can track recent conditions better.

Retrieval answers

  1. A reward evaluates one transition; a return accumulates rewards over future transitions.

  2. Stochastic: it samples actions according to those probabilities.

Takeaway: exploitation uses what the agent currently believes; exploration improves those beliefs. Learning requires spending some actions on information rather than immediate reward.
