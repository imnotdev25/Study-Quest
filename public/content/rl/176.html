🧩 Analogy: different ways to learn taste

DPO learns from “A beat B.” IPO says “A should beat B by about this much, not infinitely.” KTO learns from single thumbs-up or thumbs-down, without pairs. SimPO and ORPO drop the reference model, like a critic who judges without comparing to a classic recipe.

2. Four variants

With \(h_w=\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}\) and \(h_l\) similarly:

  • DPO: \(-\log\sigma\big(\beta(h_w-h_l)\big)\).

  • IPO (Azar et al., 2023): \(\big((h_w-h_l)-\frac{1}{2\beta}\big)^2\). It targets a finite margin, so the loss rises again if the margin overshoots. That’s more robust when preferences are near-deterministic or noisy.

  • KTO (Ethayarajh et al., 2024): unpaired labels. For a desirable \(y\): \(\lambda_D\big(1-\sigma(\beta(h-z_0))\big)\). For an undesirable one: \(\lambda_U\big(1-\sigma(\beta(z_0-h))\big)\), with \(z_0\) a batch estimate of the KL to the reference. Inspired by prospect theory: losses and gains weigh differently.

  • SimPO (Meng et al., 2024): no reference model. The reward is the length-normalized log-prob: \(-\log\sigma\big(\frac{\beta}{|y_w|}\log\pi(y_w)-\frac{\beta}{|y_l|}\log\pi(y_l)-\gamma\big)\), with target margin \(\gamma\).

  • ORPO (Hong et al., 2024): no reference model and no separate SFT stage. The loss is SFT negative log-likelihood plus \(\lambda\cdot\big(-\log\sigma(\log\operatorname{odds}(y_w)-\log\operatorname{odds}(y_l))\big)\), with \(\operatorname{odds}(y)=\frac{p}{1-p}\) on the length-normalized probability.

🔑 Key ideas

  • IPO bounds the margin, KTO needs no pairs, and SimPO and ORPO need no reference model.

  • All are still offline: they only see the data they’re given (next topic).

🚶 Walkthrough: IPO’s target margin

\(\beta=0.1\), so the target is \(\frac1{2\beta}=5\). Margin 0: loss \(25\). Margin 5: loss 0. Margin 20: loss \(225\), pushed back. DPO at margin 20 still has a small but positive pull to grow it further.

Common mistakes

  • SimPO without length normalization (rewards long answers).

  • Mixing summed and mean log-probs across variants.

  • KTO with a badly skewed desirable/undesirable ratio and no \(\lambda\) tuning.

Solutions

import torch
import torch.nn.functional as F


def dpo(h_w, h_l, beta=0.1):
    return -F.logsigmoid(beta * (h_w - h_l))


def ipo(h_w, h_l, beta=0.1):
    return ((h_w - h_l) - 1 / (2 * beta)) ** 2


def simpo(logp_w, logp_l, len_w, len_l, beta=2.0, gamma=0.5):
    return -F.logsigmoid(beta * logp_w / len_w - beta * logp_l / len_l - gamma)


def orpo(mean_logp_w, mean_logp_l, lam=0.1):
    log_odds = lambda lp: lp - torch.log1p(-lp.exp())
    return -mean_logp_w - lam * F.logsigmoid(log_odds(mean_logp_w) - log_odds(mean_logp_l))


def kto(h, desirable, z_ref, beta=0.1, lam_d=1.0, lam_u=1.0):
    if desirable:
        return lam_d - lam_d * torch.sigmoid(beta * (h - z_ref))
    return lam_u - lam_u * torch.sigmoid(beta * (z_ref - h))


t = torch.tensor
for margin in (0.0, 5.0, 20.0):
    print(f"margin {margin:4.1f}:  DPO {dpo(t(margin), t(0.0)).item():.3f}   IPO {ipo(t(margin), t(0.0)).item():.3f}")
print("SimPO:", round(simpo(t(-20.0), t(-60.0), 20, 40).item(), 3))
print("ORPO :", round(orpo(t(-0.5), t(-1.2)).item(), 3))
print("KTO desirable / undesirable:", round(kto(t(2.0), True, t(0.5)).item(), 3), round(kto(t(-2.0), False, t(0.5)).item(), 3))

Check answers

  1. When your data is thumbs-up/down on single responses, not pairs.

  2. The anchor that limits drift: nothing ties the policy to its starting behaviour except the data and the margin.

Retrieval answers: (1) \(-\log\sigma(\beta(h_w-h_l))\). (2) \(-\log\sigma\) keeps decreasing as the margin grows, so there’s always a small push.

Takeaway: pick the variant by your data (pairs or single labels), your trust in the labels (bounded or unbounded margin), and whether you can afford a reference model.
