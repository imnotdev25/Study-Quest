A good vending machine greys out sold-out buttons. A bad one lets you press them and then flashes “ERROR.” The bad design wastes your attempts and teaches you through annoying penalties. Invalid-action masking is the good design: impossible actions get probability exactly zero before sampling.

2. Two different masks

Tool agents often have state-dependent action spaces.

For example:

before search:  search, query_database
after evidence: answer, submit
after terminal: no further action

Two masks serve different purposes:

  • Response/trajectory mask: which time steps actually occurred?

  • Action mask: which actions are legal at the current state?

Given action logits \(z(s,a)\), mask illegal actions before softmax:

\[\tilde z(s,a)= \begin{cases} z(s,a),&a\text{ is valid}\\ -\infty,&a\text{ is invalid} \end{cases}\]

Then:

\[\pi(a\mid s) = \operatorname{softmax}(\tilde z(s,\cdot))_a\]

An invalid action receives exactly zero probability.

Why masking must happen before sampling

Sampling first and rejecting illegal actions changes the effective policy distribution. The recorded log-probability must correspond to the distribution from which the executed action was actually sampled.

If valid actions are \(\mathcal A(s)\), the conditional policy is:

\[\pi_{\text{valid}}(a\mid s) = \frac{ \pi(a\mid s) }{ \sum_{a'\in\mathcal A(s)} \pi(a'\mid s) } \quad \text{for }a\in\mathcal A(s)\]

Masking followed by softmax calculates this normalization directly.

Practical dangers

  • An all-invalid row cannot define a categorical distribution.

  • Terminal states should not be sampled, or should expose an explicit termination action.

  • A mistaken mask can make the optimal action unreachable.

  • Using a large negative number such as -1e9 usually works in FP32, but behaviour varies with lower-precision types.

  • Manually computing \(0\log0\) can produce nan; use stable distribution entropy.

  • Invalid-action rewards must never matter, however large they are.

SFT or DPO can teach valid tool-call syntax, but runtime masks enforce hard environment constraints. Preference optimization does not guarantee that an invalid call receives zero probability.

Tensor shapes:

  • logits and valid-action mask: [states, actions]

  • probabilities: [states, actions]

  • entropy and expected reward: [states]

  • final objective: scalar

🔍 Deeper: masks change the gradient too

Masked logits: \(\tilde z_a=z_a\) if valid, else a huge negative number. Then \(\pi(a)=\operatorname{softmax}(\tilde z)_a\). Gradient of \(\log\pi(a_t)\) with respect to logit \(z_j\): \(\mathbb 1[j=a_t]-\pi(j)\). For an invalid \(j\), \(\pi(j)=0\) and \(a_t\neq j\), so the gradient is exactly \(0\). Invalid actions neither get sampled nor absorb learning signal.

Implementation: use torch.finfo(dtype).min, not \(-\infty\). If every action is masked, \(-\infty\) everywhere gives NaN. Treat “no legal action” as a bug or an explicit termination.

🔑 Key ideas

  • Trajectory masks say when the agent acted. Action masks say what was allowed.

  • Mask before softmax and sampling, never after.

🚶 Walkthrough: masked gradient

Valid logits \((2,1,0.5)\), invalid masked. \(\pi=(0.629,0.231,0.140,0)\). Sample \(a_1\). \(\nabla_z\log\pi(a_1)=e_1-\pi=(0.371,-0.231,-0.140,0)\). The invalid logit gets exactly 0.

Common mistakes

  • Masking after softmax (probabilities no longer sum to 1).

  • Different masks at rollout time and training time.

  • \(-\infty\) everywhere, which produces NaN.

⚙️ Algorithm: Sampling with invalid-action masking
Input: logits \(z\), validity mask \(v\in\{0,1\}^k\)
if \(\sum_av_a=0\) then
raise an error, or end the episode explicitly ▷ never sample from an empty set
end
\(\tilde z_a\gets z_a\) if \(v_a=1\), else the most negative float (torch.finfo(dtype).min)
\(\pi\gets\operatorname{softmax}(\tilde z)\); sample \(a\sim\pi\)
return \(a\) and \(\log\pi(a)\) ▷ use the same masked logits in the loss

3. PyTorch exercise — optimize only over legal actions

import torch
from torch.distributions import Categorical

torch.manual_seed(7)

num_states = 2
num_actions = 4
entropy_coefficient = 0.2

# Actions:
# 0=answer, 1=search, 2=database, 3=submit
valid_actions = torch.tensor([
    [False, True,  True,  False],  # state 0
    [True,  False, False, True ],  # state 1
])

# Invalid actions deliberately have tempting rewards.
# Correct masking must make those values irrelevant.
reward_table = torch.tensor([
    [99.0, 0.2, 0.8, 99.0],
    [ 1.0, 99.0, 99.0, 0.3],
])

policy_logits = torch.nn.Parameter(
    torch.zeros(num_states, num_actions)
)

optimizer = torch.optim.Adam(
    [policy_logits],
    lr=0.05,
)

for step in range(250):
    # TODO 1: Replace invalid logits with negative infinity.
    masked_logits = ...

    # TODO 2: Construct the legal categorical policies.
    policy = ...

    probabilities = policy.probs

    # TODO 3: Exact expected reward for each state.
    expected_reward_per_state = ...

    # TODO 4: Stable entropy for each state.
    entropy_per_state = ...

    objective = (
        expected_reward_per_state
        + entropy_coefficient * entropy_per_state
    ).mean()

    loss = -objective

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

    if step in [0, 1, 9, 49, 249]:
        print(
            f"step={step:3d}",
            f"reward={expected_reward_per_state.mean().item():.3f}",
            f"entropy={entropy_per_state.mean().item():.3f}",
            f"probs={probabilities.detach().tolist()}",
        )

with torch.no_grad():
    final_masked_logits = policy_logits.masked_fill(
        ~valid_actions,
        -torch.inf,
    )

    final_policy = Categorical(
        logits=final_masked_logits
    )

    final_probabilities = final_policy.probs

invalid_probability_max = final_probabilities[
    ~valid_actions
].max()

invalid_gradient_max = policy_logits.grad[
    ~valid_actions
].abs().max()

print("Final probabilities:\n", final_probabilities)
print("Maximum invalid probability:", invalid_probability_max)
print("Maximum invalid-logit gradient:", invalid_gradient_max)

Debugging experiments

First, remove the action mask:

policy = Categorical(
    logits=policy_logits
)

The policy will rapidly select invalid actions because their rewards are 99. The optimizer is behaving correctly; the environment interface is wrong.

Then calculate entropy manually:

log_probs = torch.log_softmax(
    masked_logits,
    dim=-1,
)

entropy_per_state = -(
    probabilities * log_probs
).sum(dim=-1)

At invalid actions this contains:

\[0\times(-\infty)\]

which produces nan. Categorical.entropy() handles this case stably.

Finally, append an all-invalid terminal state. Constructing a categorical distribution for it is undefined. Skip that row using a trajectory mask or provide one explicit terminal/no-op action.

Solutions

Masked logits and policy:

masked_logits = policy_logits.masked_fill(
    ~valid_actions,
    -torch.inf,
)

policy = Categorical(
    logits=masked_logits
)

Expected rewards:

expected_reward_per_state = (
    probabilities * reward_table
).sum(dim=-1)

Stable entropy:

entropy_per_state = policy.entropy()

The valid reward choices are:

state 0:
  search   → 0.2
  database → 0.8

state 1:
  answer → 1.0
  submit → 0.3

Therefore, the final policies should prefer:

state 0 → database
state 1 → answer

With entropy regularization, the soft-optimal valid policy is:

\[\pi(a\mid s) \propto \exp\left( \frac{R(s,a)} {\alpha} \right)\]

For state 0, the two valid logits are proportional to:

\[[0.2/0.2,\;0.8/0.2]=[1,4]\]

so the approximate valid probabilities are:

search:   0.047
database: 0.953

For state 1:

\[[1.0/0.2,\;0.3/0.2]=[5,1.5]\]

giving approximately:

answer: 0.971
submit: 0.029

Every invalid action should have exactly zero probability and zero gradient. Its reward is irrelevant because the probability multiplying it is zero.

Check answers

  1. An action mask removes illegal choices within a valid state; a trajectory mask removes time steps that never occurred.

  2. The executed action comes from a renormalized conditional distribution, so its log-probability is not the original unmasked log-probability.

  3. If the mask incorrectly removes a useful call, no amount of RL can discover or select it.

  4. Log valid-action counts, all-invalid rows, invalid probability mass, selected action legality, pre-mask logits and gradients on invalid logits.

Retrieval answers

  1. Those actions never occurred, so including their rewards or log-probabilities creates fictitious gradient paths.

  2. The policy chooses the request, while the external environment determines the returned evidence.

Takeaway: trajectory masks say when the agent acted; action masks say what it was allowed to do. Apply action masks before normalization and sampling, and treat all-invalid states as an environment bug or explicit termination case.
