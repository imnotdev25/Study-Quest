2. Two valid routes to KL regularization

Consider:

\[J(\theta) = E_{\pi_\theta}[R] - \beta D_{\mathrm{KL}} (\pi_\theta\|\pi_{\text{ref}})\]

There are two common implementations.

Route A — reward shaping

For a sampled token:

\[r_t^{\text{shaped}} = r_t^{\text{task}} - \beta \left[ \log\pi_\theta(a_t|s_t) - \log\pi_{\text{ref}}(a_t|s_t) \right]\]

Freeze this reward, calculate returns or advantages, then use the ordinary policy-gradient objective:

\[E[ \nabla_\theta\log\pi_\theta(a_t|s_t) \operatorname{stopgrad}(A_t) ]\]

Route B — explicit KL loss

Keep task rewards unshaped and optimize:

\[J_{\text{actor}} = J_{\text{task}} - \beta D_{\mathrm{KL}} (\pi_\theta\|\pi_{\text{ref}})\]

Both routes represent one KL penalty under ideal on-policy expectations. Applying both normally counts it twice.

Why is detaching the shaped KL reward valid? For:

\[x_\theta(a)=\log\pi_\theta(a)-\log q(a)\]

the direct derivative contributes:

\[E_{\pi_\theta}[ \nabla_\theta x_\theta(a) ] = E_{\pi_\theta}[ \nabla_\theta\log\pi_\theta(a) ] =0\]

The score-function path already supplies the expected KL gradient. Leaving the reward attached inside log_prob * advantage introduces an additional finite-sample gradient path.

For PPO, calculate shaped rewards at rollout collection and freeze them across PPO epochs. Recomputing them after every update makes the advantages move while optimizing them.

Tensor shapes:

  • sampled actions, rewards and log-probabilities: [N]

  • LLM task rewards, token KL and mask: [B, T]

  • full categorical logits for explicit KL: [B, T, V]

Apply token KL only to valid response tokens. Sequence-level task reward is usually placed once, often at the final valid token—not repeated at every position.

DPO already incorporates reference log-ratios inside its preference loss. Adding an additional PPO-style KL reward produces a new hybrid objective, not standard DPO.

Solutions

Bernoulli utilities:

def sampled_log_probability(logit, actions):
    return torch.where(
        actions.bool(),
        F.logsigmoid(logit),
        F.logsigmoid(-logit),
    )


def exact_bernoulli_kl(
    policy_logit,
    reference_logit,
):
    policy_probability = torch.sigmoid(
        policy_logit
    )

    policy_log_probability = F.logsigmoid(
        policy_logit
    )

    policy_log_complement = F.logsigmoid(
        -policy_logit
    )

    reference_log_probability = F.logsigmoid(
        reference_logit
    )

    reference_log_complement = F.logsigmoid(
        -reference_logit
    )

    return (
        policy_probability
        * (
            policy_log_probability
            - reference_log_probability
        )
        + (1.0 - policy_probability)
        * (
            policy_log_complement
            - reference_log_complement
        )
    )

Exact objective:

Gradient paths:

def estimate_gradient(mode):
    theta = (
        policy_snapshot_logit
        .detach()
        .clone()
        .requires_grad_(True)
    )

    current_log_probabilities = (
        sampled_log_probability(
            theta,
            actions,
        )
    )

    task_surrogate = (
        current_log_probabilities
        * task_rewards
    ).mean()

    current_exact_kl = (
        exact_bernoulli_kl(
            theta,
            reference_logit,
        )
    )

    if mode == "detached_reward":
        objective = (
            current_log_probabilities
            * shaped_rewards.detach()
        ).mean()

    elif mode == "explicit_kl":
        objective = (
            task_surrogate
            - beta * current_exact_kl
        )

    elif mode == "double_counted":
        objective = (
            (
                current_log_probabilities
                * shaped_rewards.detach()
            ).mean()
            - beta * current_exact_kl
        )

    elif mode == "live_reward":
        live_shaped_rewards = (
            task_rewards
            - beta
            * (
                current_log_probabilities
                - reference_sample_log_probabilities
            )
        )

        objective = (
            current_log_probabilities
            * live_shaped_rewards
        ).mean()

    else:
        raise ValueError(mode)

    objective.backward()

    return theta.grad.detach()

At \(p=0.8\) and \(q=0.5\):

\[\nabla J_{\text{task}} = 0.8(0.2) = 0.16\]

The KL gradient is:

\[\nabla D_{\mathrm{KL}} = 0.8(0.2)\log(4) \approx0.2218\]

Therefore, one KL penalty gives:

\[0.16-0.5(0.2218) \approx0.0491\]

The policy still moves toward action 1, but cautiously.

Counting KL twice gives:

\[0.16-2(0.5)(0.2218) \approx-0.0618\]

The update direction reverses. In this particular uniform-reference example, leaving the shaped reward attached produces approximately the same incorrect gradient as explicit double-counting.

Check answers

  1. The score-function gradient through the fixed shaped reward already supplies the KL gradient; the omitted direct term has zero expectation.

  2. They are closest with on-policy samples, fixed rewards, matching reductions, full support and sufficiently large batches.

  3. It sums over the complete action distribution rather than relying on sampled token log-ratios, though [B,T,V] computation can be expensive.

  4. Rollout actions, old log-probabilities, shaped rewards, returns, advantages, masks and normalization statistics.

  5. Compare task-only, KL-only and total gradients; log raw versus shaped reward, KL coefficient, KL loss, gradient norms and update direction.

Retrieval answers

  1. Increase \(\beta\): a stronger penalty should reduce future KL.

  2. Minibatches are noisy and can have different valid-token counts. Aggregate the intended numerator and denominator globally before updating the controller.

Takeaway: choose one KL gradient path. Either freeze sampled KL inside reward-shaped advantages or apply an explicit differentiable KL loss; doing both—or leaving the reward attached—can turn cautious improvement into an update in the opposite direction.
