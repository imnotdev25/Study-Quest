2. A timeout needs bootstrapping—but must stop the trace

GAE builds an advantage from TD residuals:

\[\delta_t = r_t + \gamma b_tV(s_{t+1}) - V(s_t)\]

\[A_t = \delta_t + \gamma\lambda c_tA_{t+1}\]

Two masks serve different jobs:

\[b_t = 1-\mathbb{1}[\text{terminated}_t]\]

The bootstrap mask retains \(V(s_{t+1})\) at collector truncations because the underlying task may continue.

\[c_t = 1-\mathbb{1}[ \text{terminated}_t \lor \text{truncated}_t ]\]

The trace mask stops GAE at an episode boundary. Otherwise, an auto-reset environment can propagate the next episode’s reward backward into the previous episode.

Therefore, at a timeout:

  • bootstrap from the timeout’s final observation;

  • stop recursive advantage propagation before the reset episode.

Tensor shapes:

  • rewards, values and masks: [B, T]

  • running backward advantage: [B]

  • policy loss:

\[L_\pi = - \frac{ \sum_{b,t} m_{b,t}\log\pi_\theta(a_{b,t}\mid s_{b,t}) \operatorname{stopgrad}(A_{b,t}) }{ \sum_{b,t}m_{b,t} }\]

valid_mask handles padding. It is distinct from both GAE masks.

For LLM agents, a new prompt after max_new_tokens, timeout or tool-budget exhaustion must not contribute credit to the previous response. DPO does not calculate GAE, but truncated and accidentally concatenated completions still corrupt its fixed preference data; DPO is not online RL.

Solutions

Masks:

episode_boundary = (
    terminated | truncated
)

correct_bootstrap_mask = (
    ~terminated
).to(torch.float64)

wrong_done_bootstrap_mask = (
    ~episode_boundary
).to(torch.float64)

correct_trace_mask = (
    ~episode_boundary
).to(torch.float64)

leaky_trace_mask = (
    ~terminated
).to(torch.float64)

GAE implementation:

def compute_gae(
    bootstrap_mask,
    trace_mask,
):
    td_errors = (
        rewards
        + gamma
        * bootstrap_mask
        * next_values
        - values
    )

    advantages = torch.zeros_like(
        rewards
    )

    running_advantage = torch.zeros(
        rewards.shape[0]
    )

    for time_index in reversed(
        range(rewards.shape[1])
    ):
        running_advantage = (
            td_errors[:, time_index]
            + gamma
            * gae_lambda
            * trace_mask[:, time_index]
            * running_advantage
        )

        running_advantage = torch.where(
            valid_mask[:, time_index],
            running_advantage,
            torch.zeros_like(
                running_advantage
            ),
        )

        advantages[:, time_index] = (
            running_advantage
        )

    return td_errors, advantages

At the truncated transition:

\[\delta_2 = 1+0.9(10)-0 = 10\]

Correct GAE stops there:

\[A_2=10\]

\[A_1=0+(0.9)(0.95)(10)=8.55\]

\[A_0=(0.9)(0.95)(8.55)\approx7.31\]

Thus the correct advantages are approximately:

\[[7.31,\;8.55,\;10,\;100,\;0]\]

Treating the timeout as terminal removes its bootstrap:

\[[0.73,\;0.86,\;1,\;100,\;0]\]

Failing to stop the trace lets the new episode’s reward leak backward:

\[A_2 = 10+(0.9)(0.95)(100) = 95.5\]

producing approximately:

\[[69.81,\;81.65,\;95.5,\;100,\;0]\]

This can create a large policy-gradient update crediting actions from the first episode for reward earned after reset.

Check answers

  1. The final observation still contains future value, but the next buffer row belongs to a different episode.

  2. The critic bootstraps from the wrong state, usually introducing arbitrary bias determined by the reset-state distribution.

  3. Bootstrap at the chunk’s final observation, then stop the stored backward recursion unless the next chunk is explicitly joined to the same trajectory.

  4. Inspect advantage magnitudes around boundaries, reward/advantage correlations across episode IDs, finish-reason-specific statistics and unexpected advantage spikes before resets.

Retrieval answers

  1. Use ~terminated; collector truncations normally retain the next-state value.

  2. Validity decides whether a tensor position exists. Continuation decides whether future value belongs in that transition’s target.

Takeaway: GAE needs two boundary decisions. At a timeout, bootstrap from the real final observation, but never let the reset episode’s rewards flow backward across that boundary.
