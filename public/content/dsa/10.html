👋 Intro

How to trust recursion (the “leap of faith”), the choose–explore–unchoose template behind subsets, permutations, combinations, and constraint puzzles, pruning and branch-and-bound, meet in the middle, and divide-and-conquer beyond sorting.

Trusting Recursion

🌱 Beginner

To climb a staircase of 100 steps, you do not plan all 100. You trust that you know how to climb 99, and you take one step. Recursion is that trust: solve the smallest case directly, and assume the function already works on anything smaller.

🔧 Intermediate

Every recursive function needs three things:

  1. A base case that is answered directly.

  2. A reduction: each call works on a strictly smaller input.

  3. A combination: build this answer from the smaller answers.

Prove it correct by induction: the base case is right, and if the calls on smaller inputs are right, the combination is right. Cost = (number of calls) \(\times\) (work per call). Draw the recursion tree to count calls; if the same arguments appear in many branches, memoize (Chapter 12).

The Backtracking Template

The decision tree for subsets of {1,2,3}.

Backtracking template

function Backtrack(\(state\))
if \(state\) is a complete solution then
record a copy of \(state\); return
end
for each choice \(c\) available in \(state\) do
if \(c\) is invalid or cannot lead to a solution then
continue ▷ prune
end
apply \(c\) to \(state\) ▷ choose
▷ explore
undo \(c\) ▷ unchoose
end
end
🔧 Intermediate

The three canonical problems differ only in what a “choice” is:

Problem Choice at each step Count
Subsets include or skip element \(i\) (or: pick the next element from index \(\ge start\)) \(2^n\)
Combinations (\(k\) of \(n\)) pick the next element from index \(\ge start\); stop at size \(k\) \(\binom{n}{k}\)
Permutations pick any unused element \(n!\)
Combination sum (reuse allowed) pick element \(\ge\) current index (same index allowed) varies

Duplicates in the input (“subsets II,” “permutations II”): sort first, and at the same tree level skip an element equal to the previous one that was not used in this branch: if i > start and A[i] == A[i-1]: continue. That prevents generating the same multiset twice.

📡 Interview signals

“Return all” combinations, permutations, partitions, or paths; constraint puzzles (Sudoku, N-Queens, word search); \(n \le 15\)–20; “generate valid parentheses” (choose ( if opens remain, ) if it would not exceed opens). If the question asks for a count or best value rather than all solutions, check for overlapping subproblems: it is probably DP.

Pruning and Branch and Bound

🧠 Expert

  • Feasibility pruning: stop when the partial solution already breaks a constraint (sum exceeds target, with sorted candidates you can break instead of continue).

  • Ordering: try the most constrained choice first (Sudoku: the cell with the fewest candidates). This often shrinks the tree by orders of magnitude.

  • Branch and bound for optimization: keep the best solution so far and an optimistic bound for each partial solution; prune when the bound cannot beat the best. Used for TSP, knapsack, and integer programming solvers.

  • Memoize failure: in word break or “partition to \(k\) equal sum subsets,” remember states (e.g., a bitmask of used items) that are known to fail.

Meet in the Middle

🔧 Intermediate

For \(n \approx 40\), \(2^{40}\) subsets are too many, but \(2^{20} \approx 10^6\) is fine. Split the items into halves, enumerate all subset sums of each half, sort one list, and for each sum in the other list binary search for a complement. \(O(2^{n/2}\, n)\). Solves subset sum, “closest subsequence sum,” and partition into two equal-sized halves with minimum difference.

Divide and Conquer

🔧 Intermediate

Split into independent subproblems, solve recursively, combine. The combine step is where the cleverness is:

  • Merge sort and inversion counting (Chapter 10).

  • Closest pair of points: sort by \(x\), solve halves, then check only points within distance \(\delta\) of the dividing line, sorted by \(y\); each needs comparing to at most a constant number (7) of neighbors. \(O(n\log n)\).

  • Karatsuba multiplication: three half-size multiplications instead of four, \(O(n^{1.585})\).

  • Fast exponentiation: \(x^n = (x^{n/2})^2\), \(O(\log n)\) multiplications; with matrices, \(n\)-th Fibonacci in \(O(\log n)\).

  • Strassen matrix multiplication: 7 instead of 8 sub-multiplications, \(O(n^{2.81})\); numerically less stable, rarely used for ML (GPUs use blocked classical multiplication).

🤖 ML connection

  • Grid search over hyperparameters is exhaustive enumeration (a Cartesian product); random search and Bayesian optimization exist because the tree is too large.

  • Beam search is backtracking with a width limit: keep only the best \(B\) partial sequences instead of exploring everything.

  • Tree-of-thoughts and agent planning explore a tree of partial reasoning steps with pruning by a value estimate: branch and bound with an LLM as the heuristic.

  • Constrained decoding prunes tokens that would violate a grammar, the same “prune invalid choices early” idea.

  • Divide and conquer underlies parallel reductions on GPUs (tree reductions for sums and softmax) and distributed all-reduce.

🎤 Interview: Word search II

“Find all dictionary words on a letter grid (adjacent cells, no reuse).” Naive: run a DFS for each word, \(O(W\cdot RC\cdot 4^L)\). Better: insert all words into a trie, then DFS from each cell while walking the trie in parallel; stop as soon as the current path is not a prefix (pruning). Mark cells visited in place and restore on return (choose/unchoose). When a word is found, record it and remove its end marker to avoid duplicates; delete trie nodes that become leaves to prune further. Complexity is bounded by \(RC\cdot 4\cdot 3^{L-1}\) in the worst case but is far smaller in practice thanks to prefix pruning.

🔑 Takeaways

  • Recursion = base case + smaller subproblem + combine; prove it by induction.

  • Backtracking = choose, explore, unchoose; prune early and skip duplicates after sorting.

  • “All solutions” suggests backtracking; “count” or “best” suggests DP.

  • Meet in the middle turns \(2^n\) into \(2^{n/2}\); divide and conquer hinges on a clever combine.
