👋 Intro

How to think recursively about trees (“what do I need from my children?”), the four traversals and their iterative forms, BST operations and validation, balanced trees (AVL, red-black, B-trees), lowest common ancestor, and serialization. Trees are also the backbone of decision trees, KD-trees, and hierarchical clustering in ML.

Thinking Recursively About Trees

🌱 Beginner

Ask a manager for the size of their department. They ask each team lead, add the answers, and add one for themselves. Nobody needs to see the whole company; each person only talks to their direct reports. Almost every tree algorithm is this conversation.

🔧 Intermediate

There are two ways information moves in a tree DFS:

  • Bottom-up (return values): each node computes its answer from its children’s answers. Height, size, “is balanced,” diameter, maximum path sum, subtree sums.

  • Top-down (parameters): each node receives information from its ancestors. Depth, the path so far, valid value range for BST validation, “root-to-leaf path sum equals target.”

Many hard problems use both: pass constraints down, return summaries up. The key design question is always: what must a child tell its parent?

Diameter of a binary tree (bottom-up with a global answer)

\(best \gets 0\)
function Depth(\(node\)) ▷ returns height in edges+1; updates \(best\)
if \(node =\) null then
return 0
end
\(L \gets\) ; \(R \gets\)
\(best \gets \max(best, L + R)\) ▷ longest path bending at this node
return \(1 + \max(L, R)\) ▷ a parent can extend only one side
end
; return \(best\)
❓ Why

Every path in a tree has a unique highest node where it “bends.” At that node the longest such path is the deepest chain on the left plus the deepest chain on the right. Visiting every node once and checking this covers every path. The returned value and the recorded answer differ: a parent can only continue one branch upward. The same shape solves maximum path sum (return \(\max(0, \text{best child chain}) + \text{value}\), record \(\text{value} + \max(0,L) + \max(0,R)\)). Time: \(O(n)\) Space: \(O(h)\) where \(h\) is tree height.

Traversals

A BST and its four traversals.

🔧 Intermediate

Pre-order (node, left, right): copying or serializing a tree. In-order (left, node, right): sorted order for BSTs. Post-order (left, right, node): when a node needs its children’s results (deletion, evaluating expression trees, computing sizes). Level-order (BFS with a queue): anything about levels or “closest to the root”: right side view, zigzag order, minimum depth, connect next pointers.

Iterative in-order traversal

\(S \gets\) empty stack; \(cur \gets root\)
while \(cur \ne\) null or \(S\) not empty do
while \(cur \ne\) null do
push \(cur\); \(cur \gets cur.left\) ▷ go as far left as possible
end
\(cur \gets\) pop\((S)\); visit \(cur\)
\(cur \gets cur.right\)
end
🧠 Expert

Morris traversal does in-order in \(O(1)\) extra space by temporarily threading each node’s in-order predecessor’s right pointer back to the node, then removing the thread on the second visit. Every edge is traversed at most a constant number of times, so time stays \(O(n)\). It modifies the tree during the walk, so it is not safe with concurrent readers.

Binary Search Trees

🔧 Intermediate

A BST keeps every key in the left subtree smaller than the node and every key in the right subtree larger. Search, insert, and delete follow one root-to-leaf path: \(O(h)\), which is \(O(\log n)\) only if the tree is balanced and \(O(n)\) if it degenerates into a chain (inserting sorted keys).

Delete has three cases: a leaf (remove it), one child (splice the child up), two children (replace the key with its in-order successor, the leftmost node of the right subtree, then delete the successor, which has at most one child).

Validate a BST by passing bounds down

function Valid(\(node, lo, hi\))
if \(node =\) null then
return true
end
if \(node.key \le lo\) or \(node.key \ge hi\) then
return false
end
return and
end
return
⚠️ Pitfall

The classic bug is checking only node.left.key < node.key < node.right.key. A tree with root 5, left child 3, and 3’s right child 7 passes that local check but is invalid: 7 is in 5’s left subtree. Every node must respect all ancestors, which is why bounds are passed down (or why an in-order traversal must be strictly increasing).

📡 Interview signals

“Sorted” plus “dynamic inserts” \(\to\) balanced BST / ordered set. “\(k\)-th smallest” \(\to\) in-order with a counter (or store subtree sizes for \(O(h)\) order statistics). “Closest value,” “floor/ceiling,” “range count” \(\to\) BST walk. “Convert sorted array to balanced BST” \(\to\) pick the middle as root recursively.

Balanced Trees

🔧 Intermediate

  • AVL tree: heights of a node’s two subtrees differ by at most 1. After an insert or delete, rotations restore balance. Height \(\le 1.44\log_2 n\). Strictly balanced, so lookups are fast.

  • Red-black tree: nodes are red or black; no red node has a red child; every root-to-leaf path has the same number of black nodes. Height \(\le 2\log_2(n+1)\). Fewer rotations on updates. Used by C++ std::map, Java TreeMap, and the Linux scheduler.

  • B-tree / B+tree: each node holds hundreds of keys sized to a disk page, so the tree is only 3–4 levels deep even for billions of keys. B+trees keep all values in linked leaves for fast range scans. Used by almost every relational database index and file system.

  • Treap / skip list: randomized balance with simpler code; skip lists back Redis sorted sets.

A rotation changes shape but preserves in-order (sorted) order: \(a < x < b < y < c\).

Lowest Common Ancestor

LCA in a binary tree

function LCA(\(node, p, q\))
if \(node =\) null or \(node = p\) or \(node = q\) then
return \(node\)
end
\(L \gets\) ; \(R \gets\)
if \(L \ne\) null and \(R \ne\) null then
return \(node\) ▷ split point
end
return \(L\) if \(L \ne\) null else \(R\)
end
❓ Why

The function returns “the LCA if both are in this subtree, otherwise whichever of \(p\), \(q\) is in it, otherwise null.” At the first node where \(p\) and \(q\) come from different sides, that node is the deepest common ancestor. If one is an ancestor of the other, it is returned as soon as it is reached. In a BST it is simpler: walk from the root; if both keys are smaller go left, if both larger go right, else stop.

🧠 Expert

For many LCA queries on a static tree, binary lifting precomputes \(up[v][j]\) = the \(2^j\)-th ancestor of \(v\) in \(O(n\log n)\); each query lifts the deeper node to the same depth and then both nodes jump by decreasing powers of two, \(O(\log n)\). An Euler tour plus a sparse table (Chapter 7) gives \(O(1)\) queries. Binary lifting also answers “\(k\)-th ancestor” and path aggregates.

Serialization and Construction

🔧 Intermediate

Serialize with pre-order, writing a marker for null children (1,2,#,#,3,4,#,#,5,#,#); deserialize by reading tokens in the same pre-order with a recursive function that consumes one token per call. Construct from pre-order and in-order: the first pre-order element is the root; its position in in-order splits left and right subtrees; recurse. Use a hash map from value to in-order index for \(O(n)\) total. In-order alone cannot determine the tree; pre-order plus in-order (with distinct values) can.

🤖 ML connection

  • Decision trees (Chapter 17) are binary trees whose internal nodes test a feature threshold; prediction is a root-to-leaf walk, training is recursive splitting, and gradient-boosted ensembles are forests of them.

  • KD-trees and ball trees split space by coordinates to speed up nearest-neighbor search in low dimensions; they degrade in high dimensions, which is why embeddings use HNSW instead (Chapter 18).

  • Hierarchical softmax arranges a vocabulary in a binary (Huffman) tree so computing a word’s probability costs \(O(\log V)\) instead of \(O(V)\).

  • Parse trees and ASTs represent code for code models; tree traversals produce tokens for training and evaluation.

  • Beam search trees and Monte Carlo tree search (reasoning and game-playing systems) are search over trees of partial solutions.

🎤 Interview: Binary tree maximum path sum

Clarify: node values can be negative; a path can start and end anywhere but cannot fork. Brute force tries every pair of nodes, \(O(n^2)\). Key insight: every path has a highest node. Define gain(node) = the best sum of a downward chain starting at the node; a negative child chain is better ignored, so gain = val + max(0, gain(left), gain(right)). At each node, the best path bending there is val + max(0, gain(left)) + max(0, gain(right)); keep a global maximum. One post-order pass: \(O(n)\) time, \(O(h)\) stack. Edge case: all negative values, so the global answer must start at \(-\infty\), not 0. Follow-up: return the path itself (track which children were used).

🔑 Takeaways

  • Decide what each child returns and what each parent passes down.

  • In-order on a BST is sorted; validation needs ancestor bounds, not local checks.

  • Balanced trees guarantee \(O(\log n)\); B-trees power databases.

  • LCA, diameter, and path sums all use the “bend at the highest node” idea.
