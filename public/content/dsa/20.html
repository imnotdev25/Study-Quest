Walkthroughs

🎤 Interview: 1. LRU cache (DSA + design)

Clarify capacity, get/put semantics, \(O(1)\) requirement. Hash map from key to node plus a doubly linked list ordered by recency with sentinel head and tail. get: move to front. put: update or insert at front; evict the node before the tail and delete its key from the map. Test capacity 1, overwrite of an existing key, and get of a missing key. Extensions: TTL (store expiry, check on get), LFU (frequency buckets), thread safety (single lock, then striping).

🎤 Interview: 2. Top \(k\) frequent words (heap + hashing)

Count with a hash map (\(O(n)\)). Either a size-\(k\) min-heap keyed by (count, reverse word order for tie-breaking), \(O(n\log k)\), or bucket sort by count, \(O(n)\). Clarify tie-breaking (lexicographic). For a stream too large for memory: count-min sketch plus a heap of candidates (approximate heavy hitters), or MapReduce counts then global top-\(k\).

🎤 Interview: 3. Number of islands, then islands II (BFS/DFS + union-find)

Static grid: DFS or BFS from each unvisited land cell, counting starts, \(O(RC)\). Follow-up where land is added one cell at a time with the count after each addition: union-find over cells; adding land increments the count, and each union with a land neighbor that succeeds decrements it. \(O(k\,\alpha(RC))\) for \(k\) additions.

🎤 Interview: 4. Implement logistic regression and evaluate it (ML coding)

Shapes, standardization with training statistics, stable sigmoid and loss from logits, vectorized gradient \(X^\top(p - y)/n + \lambda w\), convergence check. Evaluate with ROC-AUC from ranks and log loss; check calibration. Test: on separable data loss decreases and accuracy approaches 1; with \(\lambda > 0\) weights stay bounded. Discuss class imbalance (weights, threshold choice) and why AUC alone is insufficient.

🎤 Interview: 5. Top-\(p\) sampling with a KV cache (LLM coding)

Generation loop: prefill the prompt to fill the cache, then each step computes logits for the last token only, applies temperature and top-\(p\) (sort, cumulative sum, keep the smallest prefix reaching \(p\), renormalize), samples via CDF, appends to the sequence and cache. Stop on EOS or max tokens. Test that \(p \to 0\) equals greedy and that the cache gives the same logits as full recomputation. Discuss batching sequences of different lengths (padding masks), and speculative decoding.

🎤 Interview: 6. Leakage-free split and target encoding (data)

Data: user events with timestamps and a categorical merchant field; predict fraud. Split by time with a gap equal to label delay; within training, out-of-fold target encoding of merchant with smoothing; fit scalers on training only; group by user inside cross-validation folds. Explain each leak these prevent, and how you would detect leakage if results look too good.

🎤 Interview: 7. Course schedule with minimum semesters (graphs)

Kahn’s algorithm by levels: each BFS level is one semester; if not all courses are output, there is a cycle. \(O(V+E)\). Follow-up with at most \(k\) courses per semester: the greedy choice is no longer always optimal; for small \(n\) use BFS/DP over bitmasks of completed courses.

🎤 Interview: 8. Design a dynamic batching inference server (LLD)

API, bounded queue with backpressure, batcher loop flushing on size \(B\) or timeout \(T\), per-request futures, deadline dropping, padding by length buckets, error isolation, metrics. Choosing \(B\) and \(T\) from a latency budget. Extension to LLMs: continuous batching per decode step and KV cache memory as the admission limit.

Reviewing Your Mock Interviews

🔧 Intermediate

After every timed attempt, label each miss with one category and practice that category next:

  • Pattern: did not recognize the technique \(\to\) redo problems in that pattern, then mixed sets.

  • Implementation: knew the idea, code was buggy \(\to\) write the invariant first; practice off-by-one-prone patterns (binary search, windows).

  • Complexity: wrong or missing analysis \(\to\) state it before coding.

  • Communication: long silences \(\to\) narrate in practice sessions.

  • Testing: no edge cases \(\to\) always test empty, one element, duplicates, extremes, and one normal case.

Cap stuck time at 15–20 minutes, study the solution, and redo the problem from scratch within 48 hours. Depth beats count: 300 problems understood well beat 400 seen once.

🔑 Takeaways

  • Map signals to patterns; practice recognizing the pattern on mixed sets.

  • Mix DSA, ML coding, data, and design every week rather than in separate blocks.

  • Review each mock by mistake category and fix the weakest one first.
