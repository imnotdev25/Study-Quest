👋 Intro

How a binary heap stores a tree in an array, why building a heap is \(O(n)\), and the patterns heaps solve: top-\(k\), \(k\)-way merge, the two-heap median, and scheduling. In ML, heaps power top-\(k\) retrieval, beam search, and merging results from shards.

The Binary Heap

🌱 Beginner

A hospital emergency room does not treat patients in arrival order; the most urgent patient is always next. A priority queue keeps everyone sorted “just enough” to always know who is most urgent, without fully sorting the room.

A min-heap as a tree and as an array.

🔧 Intermediate

A binary min-heap is a complete binary tree where every parent is \(\le\) its children, stored level by level in an array. The minimum is at index 0.

  • Push: append at the end, then sift up (swap with the parent while smaller). \(O(\log n)\).

  • Pop: take the root, move the last element to the root, then sift down (swap with the smaller child while larger). \(O(\log n)\).

  • Peek: \(O(1)\).

  • Heapify an array of \(n\) items: sift down every non-leaf from the last one to the root. \(O(n)\).

Sift down (min-heap)

function SiftDown(\(H, i, n\))
loop
\(s \gets i\); \(l \gets 2i+1\); \(r \gets 2i+2\)
if \(l < n\) and \(H[l] < H[s]\) then
\(s \gets l\)
end
if \(r < n\) and \(H[r] < H[s]\) then
\(s \gets r\)
end
if \(s = i\) then
return ▷ heap property holds
end
swap \(H[i], H[s]\); \(i \gets s\)
end
end
❓ Why

Why heapify is \(O(n)\), not \(O(n\log n)\). Half the nodes are leaves (no work), a quarter are one level up (at most 1 swap), an eighth at most 2 swaps, and so on. Total work \(\le \sum_{h} \frac{n}{2^{h+1}} h = n\sum_h \frac{h}{2^{h+1}} = O(n)\), because the series converges to 1. Most nodes are near the bottom, where sifting down is cheap. (Pushing items one by one is \(O(n\log n)\) because sifting up is expensive for the many bottom nodes.)

Pattern: Top-\(k\)

\(k\) largest elements of a stream

\(H \gets\) empty min-heap
for each \(x\) in the stream do
if \(|H| < k\) then
push \(x\)
else if \(x > \text{peek}(H)\) then
pop; push \(x\) ▷ evict the smallest of the top \(k\)
end
end
return \(H\) ▷ the \(k\) largest; \(\text{peek}(H)\) is the \(k\)-th largest
❓ Why

Invariant: the heap holds the \(k\) largest items seen so far, and its root is the smallest of them, the bar a new item must beat. Time: \(O(n\log k)\) Space: \(O(k)\). The surprising part is the min-heap for the largest items: you need fast access to the one you would throw away.

🔧 Intermediate

Choosing a top-\(k\) method:

Method Time Notes
Sort everything \(O(n\log n)\) simplest; fine for small \(n\)
Size-\(k\) heap \(O(n\log k)\) streaming; memory \(O(k)\)
Quickselect \(O(n)\) expected in-memory, unordered result (Chapter 10)
Bucket counting \(O(n)\) “top \(k\) frequent” with bounded counts
Partial merge of sorted shards \(O(k\log s)\) \(s\) sorted sources (below)

Pattern: \(k\)-Way Merge

Merge \(k\) sorted lists

\(H \gets\) min-heap of \((\text{first value}, \text{list id})\) for each non-empty list
while \(H\) not empty do
\((v, j) \gets\) pop\((H)\); output \(v\)
if list \(j\) has a next element \(w\) then
push \((w, j)\)
end
end
🔧 Intermediate

The heap always holds one candidate per list, so the smallest remaining item overall is at the root. Time: \(O(N\log k)\) Space: \(O(k)\) for \(N\) total items. Same pattern: smallest range covering one element from each of \(k\) lists; \(k\)-th smallest in a sorted matrix (treat rows as lists); \(k\) smallest pair sums; external merge sort.

Pattern: Two Heaps for the Running Median

Add a number and keep the median

function Add(\(x\))
push \(x\) to \(lo\) ▷ max-heap
move top of \(lo\) to \(hi\) ▷ ensures every \(lo \le\) every \(hi\)
if \(|hi| > |lo|\) then
move top of \(hi\) to \(lo\)
end
end
function Median()
if \(|lo| > |hi|\) then return top\((lo)\)
else  return \((\text{top}(lo) + \text{top}(hi))/2\)
end
end
🧠 Expert

Sliding window median needs deletion of arbitrary elements. Options: lazy deletion (keep a “to delete” count map and discard stale tops when they surface, rebalancing by valid sizes), or an order-statistics structure (two balanced multisets, or a Fenwick tree over compressed values for \(O(\log n)\) \(k\)-th element queries). Indexed priority queues support decrease-key in \(O(\log n)\) by tracking each item’s position; most library heaps lack this, so Dijkstra implementations push duplicates and skip stale entries instead.

Pattern: Scheduling and Greedy with Heaps

🔧 Intermediate

  • Meeting rooms II (minimum rooms): sort meetings by start; a min-heap of end times; reuse a room if the earliest end \(\le\) start. Heap size at the end is the answer.

  • Task scheduler with cooldown: always run the most frequent remaining task (max-heap), parking used tasks in a queue until cooldown ends.

  • IPO / maximize capital: sort projects by required capital; as capital grows, push affordable projects into a max-heap by profit and take the best.

  • Reorganize string (no two adjacent equal): repeatedly take the two most frequent characters.

  • Dijkstra and Prim (Chapter 9) are heap-driven greedy algorithms.

📡 Interview signals

“\(k\) largest / smallest / most frequent / closest,” “merge sorted,” “median of a stream,” “schedule with the earliest finishing / most urgent first,” “repeatedly take the best available option,” “shortest path with weights.”

🤖 ML connection

  • Top-\(k\) retrieval: a vector search returns the \(k\) nearest neighbors by maintaining a bounded heap of candidates; HNSW search keeps a candidate heap and a result heap (Chapter 18).

  • Sharded retrieval: each shard returns its local top-\(k\); a coordinator merges them with a \(k\)-way merge. Only \(k\) per shard is needed.

  • Beam search keeps the \(B\) highest-scoring partial sequences at each step: a bounded top-\(k\) over expanded candidates.

  • Top-\(k\) sampling selects the \(k\) highest-probability tokens (on GPUs usually with a partial sort or radix select rather than a heap).

  • Schedulers in training clusters and inference servers use priority queues (shortest job first, deadline-aware batching).

🎤 Interview: \(k\) closest points to the origin

Clarify: return any order? ties? \(k \le n\)? Options: sort by distance, \(O(n\log n)\); a size-\(k\) max-heap keyed by squared distance (no square root needed), \(O(n\log k)\), streaming-friendly; quickselect on distances, \(O(n)\) expected but modifies the array and is \(O(n^2)\) worst case. I would code the heap for clarity and mention quickselect. Follow-ups: points arrive as a stream (heap works as is); billions of points across machines (each machine computes local top-\(k\), then merge); high-dimensional embeddings (approximate nearest neighbor indexes).

🔑 Takeaways

  • A heap is a complete tree in an array: push/pop \(O(\log n)\), heapify \(O(n)\).

  • Top-\(k\) largest uses a min-heap of size \(k\).

  • \(k\)-way merge and two-heap median are the other core patterns.

  • Heaps underlie top-\(k\) retrieval, beam search, and shard merging in ML systems.
