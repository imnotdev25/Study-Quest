👋 Intro

A recipe for designing any DP (state, transition, base case, order, answer), then the major families: linear, knapsack, subsequences, two-sequence (edit distance, LCS), grids, intervals, trees, bitmasks, state machines, digits, and probability. Ends with optimizations and the DP algorithms used in ML: Viterbi, CTC, and dynamic time warping.

What DP Is

🌱 Beginner

If someone asks you \(1+1+1+1+1\), you count five. If they add another \(+1\), you do not recount; you remember five and say six. Dynamic programming is remembering answers to smaller questions so you never solve the same one twice.

🔧 Intermediate

DP applies when a problem has:

  • Optimal substructure: an optimal solution is built from optimal solutions of subproblems.

  • Overlapping subproblems: the same subproblems recur many times in the naive recursion.

Two implementations: top-down (recursion plus memoization: natural, computes only needed states) and bottom-up (fill a table in dependency order: no recursion limit, easier to optimize space).

The Five-Step Recipe

Designing a DP.

🔧 Intermediate

The state must capture everything needed to make the remaining decisions optimally, and nothing more. The transition usually comes from asking “what is the last decision?” (did I take item \(i\)? what was the last character matched? where was the last cut?). Complexity = (number of states) \(\times\) (transitions per state). If that is too slow, either the state has redundant information or the transition can be accelerated (prefix maxima, monotonic deque, binary search).

Linear DP

🔧 Intermediate

House robber: \(dp[i] = \max(dp[i-1], dp[i-2] + A[i])\) (skip house \(i\), or rob it and skip \(i-1\)). Climbing stairs / decode ways: count by the last step. Word break: \(dp[i]\) = can the prefix of length \(i\) be segmented; \(dp[i] = \exists j: dp[j] \wedge s[j..i) \in \text{dict}\), bounded by the longest word. Coin change (minimum coins): \(dp[a] = 1 + \min_c dp[a - c]\). All are \(O(1)\) space when only the last few values are used.

Knapsack

0/1 knapsack with a 1D array

Input: weights \(w\), values \(v\), capacity \(C\)
\(dp[0..C] \gets 0\) ▷ \(dp[c]\) = best value with capacity \(c\) using items so far
for each item \(i\) do
for \(c \gets C\) down to \(w_i\) do ▷ backward: each item used at most once
\(dp[c] \gets \max(dp[c], dp[c - w_i] + v_i)\)
end
end
return \(dp[C]\)
❓ Why

In the 2D form, \(dp[i][c] = \max(dp[i-1][c], dp[i-1][c-w_i] + v_i)\): either skip item \(i\) or take it. With one array, iterating \(c\) downward guarantees \(dp[c - w_i]\) still holds the value from before item \(i\), so the item is not reused. Iterating upward gives the unbounded knapsack (items reusable), because \(dp[c-w_i]\) may already include item \(i\). Time: \(O(nC)\) Space: \(O(C)\). This is pseudo-polynomial: polynomial in the numeric value \(C\), exponential in its bit length; knapsack is NP-hard in general.

📡 Interview signals

“Choose a subset with a budget/target,” partition equal subset sum (target \(= \sum/2\), boolean knapsack), target sum with \(\pm\) signs (count subsets with sum \((\text{total} + \text{target})/2\)), coin change (unbounded), “ones and zeroes” (two-dimensional capacity). Counting combinations vs permutations: items in the outer loop counts combinations; amount in the outer loop counts ordered sequences.

Subsequences: LIS

Longest increasing subsequence in \(O(n\log n)\) (patience sorting)

\(tails \gets []\) ▷ \(tails[k]\) = smallest tail of an increasing subsequence of length \(k{+}1\)
for each \(x\) in \(A\) do
\(i \gets\) lower bound of \(x\) in \(tails\) ▷ first \(tails[i] \ge x\)
if \(i = |tails|\) then
append \(x\)
else  
\(tails[i] \gets x\)
end
end
return \(|tails|\)
❓ Why

\(tails\) stays strictly increasing. Replacing \(tails[i]\) with a smaller \(x\) keeps the same length but lowers the bar for extending it, which can only help later. The array is not itself an LIS, but its length equals the LIS length. The simpler \(O(n^2)\) DP: \(dp[i] = 1 + \max_{j<i, A[j]<A[i]} dp[j]\). Variants: non-decreasing (use upper bound), Russian doll envelopes (sort by width ascending and height descending, then LIS on heights), number of LIS (track counts).

Two Sequences: Edit Distance and LCS

Edit distance (Levenshtein)

Input: strings \(a\) (length \(m\)), \(b\) (length \(n\))
\(dp[i][0] \gets i\); \(dp[0][j] \gets j\) ▷ delete all / insert all
for \(i \gets 1\) to \(m\) do
for \(j \gets 1\) to \(n\) do
if \(a_i = b_j\) then
\(dp[i][j] \gets dp[i-1][j-1]\)
else
\(dp[i][j] \gets 1 + \min(dp[i-1][j],\ dp[i][j-1],\ dp[i-1][j-1])\)
delete insert replace
end
end
end
return \(dp[m][n]\)

Edit distance table for “kitten” \(\to\) “sitting”: 3 edits.

🔧 Intermediate

LCS: \(dp[i][j] = dp[i-1][j-1] + 1\) if characters match, else \(\max(dp[i-1][j], dp[i][j-1])\). Space: each row depends only on the previous row, so \(O(\min(m,n))\) space; recovering the actual alignment needs the full table or Hirschberg’s divide-and-conquer trick. Related: longest common substring (reset to 0 on mismatch), distinct subsequences (count), regular expression and wildcard matching (states \((i,j)\) with special transitions for *), interleaving strings, shortest common supersequence (\(m + n - \text{LCS}\)).

🤖 ML connection

Word error rate (speech recognition) and character error rate (OCR) are edit distance between hypothesis and reference, divided by reference length. BLEU/ROUGE-L use LCS. Sequence alignment in bioinformatics (Needleman–Wunsch, Smith–Waterman) is the same DP with scores. Dynamic time warping aligns two time series with \(dp[i][j] = d(x_i, y_j) + \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])\).

Grids, Intervals, and Trees

🔧 Intermediate

Grid DP: unique paths, minimum path sum, maximal square (\(dp[i][j] = 1 + \min(\text{up}, \text{left}, \text{up-left})\) if the cell is 1), dungeon game (fill from the bottom-right, because the needed health depends on the future).

Interval DP: \(dp[i][j]\) = best for the subarray \([i, j]\), iterating by increasing length; transition picks a split point \(k\). \(O(n^3)\). Burst balloons: choose the balloon \(k\) burst last in \((i, j)\), so its neighbors at that moment are \(i\) and \(j\): \(dp[i][j] = \max_k dp[i][k] + dp[k][j] + A_i A_k A_j\). Thinking “last” instead of “first” makes subproblems independent. Also: matrix chain multiplication, palindrome partitioning, minimum cost to cut a stick, optimal BST.

Tree DP: each node returns a small tuple to its parent. House robber III: return (best if this node is robbed, best if not). Rerooting: compute answers for every node as root in \(O(n)\) with one pass down and one pass up (sum of distances in a tree).

Bitmask DP

🔧 Intermediate

When \(n \le 20\), a subset of items fits in an integer mask. Travelling salesman: \(dp[mask][v]\) = minimum cost to visit exactly the cities in \(mask\), ending at \(v\); \(dp[mask \cup \{u\}][u] = \min(dp[mask][v] + d(v, u))\). \(O(2^n n^2)\) instead of \(O(n!)\). Others: assign \(n\) people to \(n\) tasks, partition into \(k\) equal subsets, shortest path visiting all nodes, “number of ways to wear hats.” Enumerate submasks of \(m\) with s = (s - 1) & m; iterating all submasks of all masks is \(O(3^n)\).

State Machines

Stock trading with cooldown as a state machine.

🔧 Intermediate

Define one DP value per state per day and transitions along the arrows: \(hold' = \max(hold, rest - p)\), \(cool' = hold + p\), \(rest' = \max(rest, cool)\). All stock problems fit this: at most \(k\) transactions adds a transaction counter to the state; a fee subtracts on sell. The same idea models “paint houses with no two adjacent the same color” (state = last color) and regex matching (state = position in the pattern automaton).

Probability and Expected Value DP

🔧 Intermediate

\(dp[s]\) = probability (or expected cost) from state \(s\), combining successor states weighted by transition probabilities. Knight probability on a chessboard (\(dp[k][r][c] = \frac18\sum\) of the 8 predecessors), soup servings, new 21 game (sliding-window sum of probabilities). Expected value DP is a finite-horizon Bellman equation: \(V(s) = \max_a \big[r(s,a) + \sum_{s'} P(s'|s,a)V(s')\big]\), the core of value iteration in reinforcement learning.

Digit DP

🧠 Expert

“Count integers in \([0, N]\) with property \(P\)” (no repeated digits, digit sum divisible by \(k\), no consecutive ones in binary). State: (position, a “tight” flag meaning the prefix equals \(N\)’s prefix so the next digit is bounded, plus whatever summary \(P\) needs: digit sum mod \(k\), mask of used digits, last digit). Process digits from most significant; answer for \([L, R]\) is \(f(R) - f(L-1)\). \(O(\text{digits}\times\text{states}\times 10)\).

DP Optimizations

🧠 Expert

  • Space rolling: keep only the rows the recurrence touches.

  • Monotonic deque for \(dp[i] = \max_{j \in [i-k, i)} dp[j] + c\): \(O(nk) \to O(n)\) (Chapter 4). Example: jump game VI, constrained subsequence sum.

  • Binary search / data structures on the transition (LIS, weighted interval scheduling: sort by end time, binary search the last compatible interval).

  • Convex hull trick / Li Chao tree: transitions of the form \(\min_j (m_j x_i + b_j)\) become \(O(\log n)\) or amortized \(O(1)\).

  • Knuth and divide-and-conquer optimization: when the optimal split point is monotone, interval DP drops from \(O(n^3)\) to \(O(n^2)\) and some partition DPs from \(O(kn^2)\) to \(O(kn\log n)\).

  • Matrix exponentiation for linear recurrences with huge \(n\): \(O(k^3\log n)\).

DP in ML: Viterbi and CTC

Viterbi: most likely hidden state sequence in an HMM

Input: initial \(\pi\), transitions \(T[s'][s]\), emissions \(E[s][o]\), observations \(o_1..o_n\)
\(V[1][s] \gets \log\pi_s + \log E[s][o_1]\) for all \(s\)
for \(t \gets 2\) to \(n\) do
for each state \(s\) do
\(V[t][s] \gets \log E[s][o_t] + \max_{s'} \big(V[t-1][s'] + \log T[s'][s]\big)\)
\(back[t][s] \gets\) the maximizing \(s'\)
end
end
backtrack from \(\arg\max_s V[n][s]\) using \(back\)
🤖 ML connection

  • Viterbi (\(O(nS^2)\)) decodes HMMs and CRFs for part-of-speech tagging and named entity recognition. Replacing \(\max\) with log-sum-exp gives the forward algorithm, which computes the total probability of the observations; forward-backward computes posteriors for training.

  • CTC loss (speech, handwriting) sums over all alignments of a label sequence to input frames using a forward DP over an extended label sequence with blanks.

  • Beam search is a greedy approximation to Viterbi when the state space (all possible prefixes of an LLM output) is too large for exact DP.

  • Bellman equations power value iteration, Q-learning, and the advantage estimates (GAE) used in PPO for RLHF.

  • Work in log space to avoid underflow from multiplying many probabilities.

🎤 Interview: Coin change, done well

“Fewest coins to make amount \(A\), or \(-1\).” Greedy fails (coins {1,3,4}, amount 6: greedy \(4+1+1\), optimal \(3+3\)), so show that counterexample first. State \(dp[a]\) = fewest coins for amount \(a\); transition: the last coin is some \(c\), so \(dp[a] = 1 + \min_c dp[a - c]\); base \(dp[0] = 0\), others \(\infty\); order: increasing \(a\); answer \(dp[A]\) or \(-1\) if infinite. \(O(A\cdot|coins|)\) time, \(O(A)\) space. Alternative view: BFS on amounts where each coin is an edge, since all edges have weight 1. Follow-ups: count the number of combinations (coins in the outer loop), reconstruct the coins (store the chosen coin per amount), huge \(A\) with few coins (math / BFS with pruning).

🔑 Takeaways

  • Design every DP with the five steps: state, transition, base, order, answer.

  • Find the transition by asking “what was the last decision?”

  • Recognize the families: knapsack, LIS, two-sequence, interval, tree, bitmask, state machine.

  • Viterbi, CTC, DTW, WER, and Bellman equations are DP inside ML systems.
