👋 Intro

Four advanced structures that turn slow problems into fast ones: tries for prefixes, union-find for dynamic connectivity, Fenwick and segment trees for range queries with updates, and sparse tables for static range minimum. Plus ordered sets and coordinate compression, the glue that makes them usable.

Tries (Prefix Trees)

🌱 Beginner

A dictionary’s thumb tabs let you jump to all words starting with “C,” then “CA,” then “CAT.” A trie is a tree of those tabs: each edge is a letter, and following edges spells a prefix.

A trie storing “cat,” “car,” and “dog.”

Trie insert and prefix search

function Insert(\(word\))
\(node \gets root\)
for each character \(c\) in \(word\) do
if \(c \notin node.children\) then
\(node.children[c] \gets\) new node
end
\(node \gets node.children[c]\); \(node.count \gets node.count + 1\) ▷ words through here
end
\(node.isEnd \gets\) true
end
function StartsWith(\(prefix\))
\(node \gets root\)
for each \(c\) in \(prefix\) do
if \(c \notin node.children\) then
return false
end
\(node \gets node.children[c]\)
end
return true
end
🔧 Intermediate

Operations cost \(O(L)\) for a word of length \(L\), independent of how many words are stored. Patterns: autocomplete (walk to the prefix node, then DFS, or store the top-\(k\) completions at each node for \(O(L)\) queries); word search on a grid (DFS on the board while walking the trie, pruning dead prefixes); longest common prefix; replace words with roots; XOR maximization (a binary trie over bits: to maximize \(x \oplus y\), at each bit prefer the opposite child). Memory: a node with 26 child pointers wastes space; use hash maps, or a radix (compressed) trie that merges single-child chains.

🤖 ML connection

Tokenizers match the longest vocabulary entry at each position using a trie (WordPiece’s greedy longest-match, SentencePiece’s lookup). Constrained decoding for structured output or a fixed set of allowed strings walks a trie of valid token sequences and masks every token not on an allowed edge. Search engines’ query autocomplete stores popularity-ranked completions in tries.

Union-Find (Disjoint Set Union)

🌱 Beginner

Each group of friends picks a representative. To check whether two people are in the same group, ask each for their representative and compare. To merge two groups, one representative agrees to report to the other.

Union-find with path compression and union by rank

function Find(\(x\))
if \(parent[x] \ne x\) then
\(parent[x] \gets\) ▷ path compression
end
return \(parent[x]\)
end
function Union(\(a, b\))
\(ra \gets\) ; \(rb \gets\)
if \(ra = rb\) then
return false ▷ already connected: an edge here makes a cycle
end
if \(rank[ra] < rank[rb]\) then
swap \(ra, rb\)
end
\(parent[rb] \gets ra\) ▷ attach shorter tree under taller
if \(rank[ra] = rank[rb]\) then
\(rank[ra] \gets rank[ra] + 1\)
end
return true
end
❓ Why

Union by rank alone keeps trees of height \(O(\log n)\): a tree’s rank only grows when merging two equal ranks, which at least doubles its size. Path compression flattens trees during finds. Together, \(m\) operations cost \(O(m\,\alpha(n))\) where \(\alpha\) is the inverse Ackermann function, at most 4 for any realistic \(n\): effectively constant. (Tarjan’s analysis; you only need to state the result.)

📡 Interview signals

“Number of connected components” with edges arriving over time, “are these two connected,” “redundant connection” (first edge whose endpoints are already connected), Kruskal’s MST, “accounts merge” (union emails that share an account), “number of islands II” (cells added one at a time), equations like a==b, b!=c (union equalities, then check inequalities). Union-find cannot easily delete edges; process deletions in reverse as additions when possible.

Fenwick Tree (Binary Indexed Tree)

🔧 Intermediate

Prefix sums answer range queries in \(O(1)\) but an update costs \(O(n)\). A Fenwick tree balances both at \(O(\log n)\). Index \(i\) (1-based) stores the sum of the range ending at \(i\) of length \(\text{lowbit}(i) = i \,\&\, (-i)\), the lowest set bit.

Fenwick tree update and prefix query

function Add(\(i, \delta\)) ▷ \(A[i] \mathrel{+}= \delta\)
while \(i \le n\) do
\(T[i] \gets T[i] + \delta\); \(i \gets i + (i \,\&\, -i)\)
end
end
function PrefixSum(\(i\)) ▷ \(A[1] + \dots + A[i]\)
\(s \gets 0\)
while \(i > 0\) do
\(s \gets s + T[i]\); \(i \gets i - (i \,\&\, -i)\)
end
return \(s\)
end
❓ Why

Removing the lowest set bit repeatedly breaks \([1, i]\) into at most \(\log_2 n\) disjoint ranges, one per set bit of \(i\), so a query touches \(O(\log n)\) cells. An update must touch every cell whose range covers \(i\); adding the lowest set bit walks exactly those, again \(O(\log n)\). Range sum \(= \text{PrefixSum}(r) - \text{PrefixSum}(l-1)\).

🔧 Intermediate

Classic use: counting inversions or “count of smaller numbers after self.” Process the array from the right; for each value, query how many smaller values have been inserted, then insert it. Values must be coordinate compressed (replace each value with its rank among sorted distinct values) so the tree has size \(n\) instead of the value range.

Segment Tree

A segment tree over [5,2,3,5] storing range sums.

🔧 Intermediate

Each node stores an aggregate (sum, min, max, gcd, count) over a range; children split the range in half. A query or point update visits \(O(\log n)\) nodes. Any associative combine function works, which makes segment trees more general than Fenwick trees (which need invertible operations like sum for range queries). Lazy propagation supports range updates (“add 5 to every element in \([l, r]\)”): store a pending update at a node that fully covers the range, and push it to children only when a later operation needs to go deeper. Both range update and range query become \(O(\log n)\).

Segment tree range query (sum)

function Query(\(node, nl, nr, l, r\)) ▷ \(node\) covers \([nl, nr]\)
if \(r < nl\) or \(nr < l\) then
return 0 ▷ no overlap
end
if \(l \le nl\) and \(nr \le r\) then
return \(T[node]\) ▷ full overlap
end
\(m \gets \lfloor (nl + nr)/2 \rfloor\)
return \(+\)
end

Sparse Table

🔧 Intermediate

For a static array and an idempotent operation (min, max, gcd), precompute \(st[j][i] = \min(A[i..i+2^j-1])\) in \(O(n\log n)\). Any range \([l, r]\) is covered by two overlapping power-of-two blocks: with \(j = \lfloor\log_2(r-l+1)\rfloor\), answer \(\min(st[j][l], st[j][r-2^j+1])\) in \(O(1)\). Overlap is fine because \(\min(x,x)=x\); it would double-count for sums.

Choosing a Range Structure

Structure Use when Query Update
Prefix sums static array, sums \(O(1)\) \(O(n)\)
Sparse table static array, min/max/gcd \(O(1)\) rebuild
Fenwick tree point updates, prefix sums, inversion counts \(O(\log n)\) \(O(\log n)\)
Segment tree any associative op, range updates with lazy propagation \(O(\log n)\) \(O(\log n)\)
Ordered set / balanced BST dynamic sorted data, rank and \(k\)-th queries \(O(\log n)\) \(O(\log n)\)
Sqrt decomposition simpler alternative, offline tricks (Mo’s algorithm) \(O(\sqrt n)\) \(O(1)\)–\(O(\sqrt n)\)
🧠 Expert

Ordered sets (C++ std::set, Java TreeSet, Python’s sortedcontainers) solve many “sliding window with ordering” problems: “contains duplicate III” (is there a value within \(t\) of the current one in the last \(k\) elements: query the ceiling of \(x-t\)), sliding window median, and calendar booking (find the neighboring intervals). Know which your interview language provides; Python has none built in, so a heap with lazy deletion or a bucket trick is the usual substitute. Persistent segment trees keep every historical version by copying only the \(O(\log n)\) changed nodes per update, answering “\(k\)-th smallest in a subarray” queries.

🎤 Interview: Count of smaller numbers after self

Brute force: for each index, scan to the right, \(O(n^2)\). Two \(O(n\log n)\) ideas: (1) process right to left with a Fenwick tree over compressed values: answer for \(i\) = prefix count of values strictly less than \(A[i]\), then add \(A[i]\); (2) merge sort on indices, counting how many elements from the right half move before each left-half element. I would compress values (sort distinct values, map each to its rank), then use the Fenwick tree. Edge cases: duplicates (query rank \(-1\) for strictly smaller), negatives (compression handles them). This is the same computation as counting inversions, which measures how “unsorted” a ranking is, related to Kendall’s tau for comparing rankings in search evaluation.

🔑 Takeaways

  • Tries: \(O(L)\) prefix operations; core of autocomplete and tokenizers.

  • Union-find: near-constant connectivity merges; Kruskal, components, cycles.

  • Fenwick for prefix sums with updates; segment tree for any associative range query and range updates.

  • Coordinate compression makes value-indexed structures practical.
