👋 Intro

Merge sort, quicksort, and heap sort with their invariants; stability; the linear-time sorts; quickselect and median-of-medians; and binary search done properly, including binary search on the answer, which solves a large family of optimization problems.

Merge Sort

Merge sort

function MergeSort(\(A, l, r\)) ▷ sorts \(A[l..r)\)
if \(r - l \le 1\) then
return
end
\(m \gets \lfloor (l + r)/2 \rfloor\)
;
merge the sorted halves into a buffer: repeatedly take the smaller front
element, taking from the left half on ties (keeps it stable); copy back
end
🔧 Intermediate

\(T(n) = 2T(n/2) + O(n) = O(n\log n)\) in every case. Counting inversions during the merge: when an element from the right half is taken while \(k\) elements remain in the left half, it forms \(k\) inversions. The same merge-with-counting trick solves “count of smaller numbers after self” and “reverse pairs.” External sort: sort chunks that fit in memory, write them as runs, then \(k\)-way merge the runs with a heap (Chapter 6). This is how databases and MapReduce sort data larger than RAM.

Quicksort and Partitioning

Lomuto partition and quicksort

function Partition(\(A, l, r\)) ▷ pivot \(A[r]\); returns its final index
swap a uniformly random element of \(A[l..r]\) into \(A[r]\)
\(p \gets A[r]\); \(i \gets l\) ▷ \(A[l..i)\) \(< p\) ; \(A[i..j)\) \(\ge p\)
for \(j \gets l\) to \(r-1\) do
if \(A[j] < p\) then
swap \(A[i], A[j]\); \(i \gets i + 1\)
end
end
swap \(A[i], A[r]\); return \(i\)
end

❓ Why

The comment is the invariant: everything before \(i\) is smaller than the pivot, everything between \(i\) and \(j\) is at least the pivot. When \(j\) reaches \(r\), placing the pivot at \(i\) puts it in its final sorted position. Expected \(O(n\log n)\) with a random pivot: any two elements are compared at most once, and elements of rank \(i\) and \(j\) are compared with probability \(2/(j-i+1)\) (only if one of them is the first pivot chosen from the range between them); summing gives \(\approx 2n\ln n\). The worst case \(O(n^2)\) happens with consistently bad pivots (sorted input with a fixed first or last pivot). Many duplicates: Lomuto degrades to \(O(n^2)\) on all-equal input; three-way (Dutch flag) partitioning fixes it.

🧠 Expert

Production sorts are hybrids. Introsort (C++ std::sort) runs quicksort, switches to heap sort if recursion gets too deep (guaranteeing \(O(n\log n)\)), and uses insertion sort for small ranges. pdqsort adds pattern detection. Timsort finds already-sorted runs and merges them, giving \(O(n)\) on nearly sorted data, which is common in practice. Recurse on the smaller partition first to bound stack depth at \(O(\log n)\).

Linear-Time Sorting

🔧 Intermediate

Counting sort: count occurrences of each key in \([0,k)\), prefix-sum the counts to get positions, place items (iterating backward keeps it stable). Radix sort: stable-sort by each digit from least significant to most; stability ensures earlier digit orders are preserved. Bucket sort: for uniformly distributed reals, put each into one of \(n\) buckets and sort each, \(O(n)\) expected. These beat the \(\Omega(n\log n)\) comparison bound by examining key structure, not just comparing. “Top \(k\) frequent elements” uses bucket sort by frequency.

Selection: Quickselect

Quickselect: \(k\)-th smallest (0-indexed)

\(l \gets 0\); \(r \gets n - 1\)
while true do
\(q \gets\) ▷ random pivot
if \(q = k\) then
return \(A[q]\)
else if \(q < k\) then
\(l \gets q + 1\)
else
\(r \gets q - 1\)
end
end
❓ Why

Unlike quicksort it recurses into one side only. Expected work is \(n + n/2 + n/4 + \dots \approx 2n\), so \(O(n)\) expected. The worst case is \(O(n^2)\). Median of medians picks a pivot guaranteed to be between the 30th and 70th percentile (medians of groups of 5, then the median of those recursively), giving worst-case \(T(n) \le T(n/5) + T(7n/10) + O(n) = O(n)\). It is rarely used in practice because constants are large, but it is a common “can you guarantee linear time?” follow-up.

Binary Search, Properly

🌱 Beginner

Guessing a number between 1 and 1,000 with “higher/lower” hints needs at most 10 guesses if you always guess the middle. Binary search works on anything where a yes/no question splits the possibilities into “all no” then “all yes.”

🔧 Intermediate

The general form: find the first index (or value) where a monotone predicate \(P\) becomes true: \(P = \text{false}, \dots, \text{false}, \text{true}, \dots, \text{true}\). The lower-bound algorithm in Chapter 2 is this with \(P(i) = (A[i] \ge x)\). Every binary search variant is a choice of predicate:

  • First occurrence of \(x\): \(P(i) = A[i] \ge x\), then check equality.

  • Last occurrence: first index with \(A[i] > x\), minus one.

  • Rotated sorted array: at each step, one half is sorted; check whether the target lies in that sorted half’s range to decide the direction. Minimum of a rotated array: \(P(i) = A[i] \le A[n-1]\).

  • Peak element: \(P(i) = A[i] > A[i+1]\); moving toward the higher neighbor always leads to a peak.

  • Median of two sorted arrays in \(O(\log\min(m,n))\): binary search the partition of the smaller array so that left parts total half the elements and every left element \(\le\) every right element.

Binary Search on the Answer

Minimum capacity to ship packages within \(D\) days

function Feasible(\(cap\)) ▷ greedy: fill each day until the next package does not fit
\(days \gets 1\); \(load \gets 0\)
for each weight \(w\) do
if \(load + w > cap\) then
\(days \gets days + 1\); \(load \gets 0\)
end
\(load \gets load + w\)
end
return \(days \le D\)
end
\(lo \gets \max(w)\); \(hi \gets \sum w\) ▷ answer lies in \([lo, hi]\)
while \(lo < hi\) do
\(mid \gets \lfloor (lo + hi)/2 \rfloor\)
if then
\(hi \gets mid\)
else  
\(lo \gets mid + 1\)
end
end
return \(lo\)
❓ Why

Feasibility is monotone: if capacity \(c\) works, any larger capacity works. So the predicate “feasible” flips once from false to true, and binary search finds the smallest feasible value with \(O(\log(\text{range}))\) calls to an \(O(n)\) check. Time: \(O(n\log(\sum w))\) Space: \(O(1)\).

📡 Interview signals

“Minimize the maximum” or “maximize the minimum,” “smallest \(x\) such that…,” a feasibility check that is easy given a candidate answer, and a huge answer range. Examples: Koko eating bananas, split array largest sum, minimum days to make bouquets, aggressive cows / magnetic balls (maximize minimum distance), \(k\)-th smallest in a multiplication table (count entries \(\le x\)), smallest divisor. On real numbers, iterate a fixed number of times (e.g. 100) instead of using \(lo < hi\).

🤖 ML connection

  • ROC-AUC is computed by sorting scores; AUC equals the fraction of positive-negative pairs ranked correctly, computable from ranks in \(O(n\log n)\) (Chapter 17).

  • Quantiles and percentile features use selection or sorting; streaming quantiles use sketches (Chapter 15).

  • Weighted sampling: binary search a uniform random number in the prefix-sum CDF, \(O(\log n)\) per sample (Chapter 15).

  • Threshold tuning: binary search the decision threshold for a target precision or false-positive rate on a sorted score list.

  • Batch size and learning-rate search: find the largest batch that fits in GPU memory by binary search on a monotone “fits” predicate.

  • Bucketized features (binning continuous values) use binary search over bucket boundaries.

🎤 Interview: Split array largest sum

“Split an array of non-negative integers into \(k\) contiguous parts minimizing the largest part sum.” Brute force over split points is exponential; DP is \(O(kn^2)\). Observation: if the largest sum can be at most \(S\), a greedy pass determines the minimum number of parts needed, and that number decreases as \(S\) grows: monotone. Binary search \(S\) in \([\max A, \sum A]\); the greedy check counts parts. \(O(n\log\sum A)\). Explain why the greedy check is optimal: extending the current part as long as possible never increases the number of parts (exchange argument). Edge cases: \(k = n\) (answer is \(\max A\)), \(k = 1\) (answer is \(\sum A\)).

🔑 Takeaways

  • Merge sort: stable, \(O(n\log n)\) always, foundation of external sorting and inversion counting.

  • Quicksort and quickselect rely on partition invariants and random pivots.

  • Binary search = find where a monotone predicate flips; write the invariant first.

  • “Minimize the maximum” with an easy check means binary search on the answer.
