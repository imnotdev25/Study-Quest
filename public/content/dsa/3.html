👋 Intro

Pointer manipulation on linked lists, the fast/slow pointer technique and its proof, stacks for nesting and expression evaluation, the monotonic stack and monotonic deque, and the LRU cache that combines a list with a hash map.

Linked Lists

🔧 Intermediate

A singly linked list is a chain of nodes, each holding a value and a pointer to the next. Insert or delete after a known node is \(O(1)\); finding the \(k\)-th node is \(O(k)\). A dummy (sentinel) head node removes special cases for the first element. Most list problems are about careful pointer order: save next before overwriting it.

Reverse a linked list in place

\(prev \gets\) null; \(cur \gets head\)
while \(cur \ne\) null do
\(nxt \gets cur.next\) ▷ save before breaking the link
\(cur.next \gets prev\)
\(prev \gets cur\); \(cur \gets nxt\)
end
return \(prev\)
❓ Why

Invariant: prev is the head of the already-reversed prefix and cur the head of the untouched suffix. Each step moves one node from suffix to prefix. When cur is null, prev heads the fully reversed list. Time: \(O(n)\) Space: \(O(1)\).

Fast and Slow Pointers

Floyd’s cycle detection and cycle start

\(slow \gets head\); \(fast \gets head\)
while \(fast \ne\) null and \(fast.next \ne\) null do
\(slow \gets slow.next\); \(fast \gets fast.next.next\)
if \(slow = fast\) then ▷ they met inside the cycle
\(p \gets head\)
while \(p \ne slow\) do
\(p \gets p.next\); \(slow \gets slow.next\)
end
return \(p\) ▷ start of the cycle
end
end
return null ▷ no cycle
❓ Why

They meet: once both are in the cycle, the gap shrinks by one each step, so they meet within one lap. The start: let \(a\) = distance from head to cycle start, \(b\) = distance from start to the meeting point, \(c\) = cycle length. Slow walked \(a+b\), fast walked \(2(a+b)\), and fast’s extra distance is whole laps: \(a + b = k c\). So \(a = kc - b\): walking \(a\) steps from the meeting point lands on the cycle start, exactly where a pointer from the head arrives after \(a\) steps. The same algorithm finds a duplicate in an array of \(n+1\) values in \([1,n]\) by treating \(i \to A[i]\) as a linked list.

📡 Interview signals

Middle of a list (fast moves 2, slow 1), cycle detection, \(k\)-th from end (lead pointer \(k\) ahead), palindrome list (find middle, reverse second half, compare), intersection of two lists (switch heads when reaching the end; both walk \(a+b+c\)), merge \(k\) sorted lists (heap, Chapter 6).

Stacks

🌱 Beginner

A stack is a pile of plates: you only add or remove from the top. It is perfect for anything nested, like brackets, function calls, or undo history, because the most recent unfinished thing is always the next one to finish.

Valid parentheses

\(S \gets\) empty stack; \(match \gets \{\texttt{)}{:}\texttt{(},\ \texttt{]}{:}\texttt{[},\ \texttt{\}}{:}\texttt{\{}\}\)
for each character \(c\) do
if \(c\) is an opening bracket then
push \(c\)
else if \(S\) is empty or pop\((S) \ne match[c]\) then
return false
end
end
return \(S\) is empty
🔧 Intermediate

Expression evaluation. For 3 + 4 * 2, keep a stack of numbers and the last operator: on +/- push the (signed) number; on *// pop, combine, and push; sum the stack at the end. Parentheses push the current state and start fresh. The general method is Dijkstra’s shunting-yard algorithm: an operator stack converts infix to postfix by precedence, and postfix is evaluated with one number stack. Min stack: store (value, min so far) pairs, so getMin is \(O(1)\). Queue from two stacks: push to in; pop from out, refilling out from in only when empty (amortized \(O(1)\), each element moves once).

Monotonic Stack

🌱 Beginner

People stand in a line facing right. Each wants to know the first taller person in front of them. Walk the line and keep a stack of people still waiting. When a taller person appears, everyone shorter at the top of the stack has found their answer and leaves.

Next greater element for every index

\(ans[0..n-1] \gets -1\); \(S \gets\) empty stack of indices ▷ values decreasing bottom to top
for \(i \gets 0\) to \(n-1\) do
while \(S\) not empty and \(A[\text{top}(S)] < A[i]\) do
\(ans[\text{pop}(S)] \gets A[i]\) ▷ \(A[i]\) is the first greater for it
end
push \(i\)
end
return \(ans\)
❓ Why

Correctness: an index stays on the stack exactly until the first larger element appears, because everything above it on the stack is smaller than it (the stack is decreasing), so they cannot block it. Complexity: each index is pushed once and popped at most once, so total work is \(O(n)\) despite the nested loop (an aggregate amortized argument).

Largest rectangle in histogram [2,1,5,6,2,3].

🔧 Intermediate

Largest rectangle in a histogram: keep an increasing stack of indices. When bar \(i\) is shorter than the top, pop the top bar \(h\); its rectangle extends from just after the new top to \(i-1\), width \(= i - \text{newtop} - 1\). Push a sentinel bar of height 0 at the end to flush the stack. \(O(n)\). This is the building block for “maximal rectangle of 1s in a matrix” (run it per row on column heights). Other uses: daily temperatures, stock span, trapping rain water, sum of subarray minimums (each element’s contribution \(=\) value \(\times\) number of subarrays where it is the minimum, from previous/next smaller indices), and “remove \(k\) digits to make the smallest number.”

Queues, Deques, and the Monotonic Deque

Sliding window maximum with a monotonic deque

Input: array \(A\), window size \(k\)
\(D \gets\) empty deque of indices ▷ values decreasing front to back
for \(i \gets 0\) to \(n-1\) do
if \(D\) not empty and \(\text{front}(D) \le i - k\) then
pop front ▷ left the window
end
while \(D\) not empty and \(A[\text{back}(D)] \le A[i]\) do
pop back ▷ can never be a max again
end
push \(i\) to back
if \(i \ge k-1\) then
output \(A[\text{front}(D)]\)
end
end
❓ Why

An element smaller than a newer element can never be the maximum of any future window (the newer one stays longer and is larger), so it is safe to discard. The deque thus holds the candidates in decreasing order and the front is the maximum. Each index enters and leaves once: Time: \(O(n)\) Space: \(O(k)\). A heap would give \(O(n\log k)\). The same deque speeds up DP transitions of the form \(dp[i] = \max_{i-k \le j < i} dp[j] + c_i\) from \(O(nk)\) to \(O(n)\).

LRU Cache: Combining Structures

LRU cache = hash map for \(O(1)\) lookup + doubly linked list for \(O(1)\) reordering.

LRU cache operations

function Get(\(key\))
if \(key \notin map\) then return miss
end
move \(map[key]\) to the front of the list ▷ \(O(1)\): unlink and relink
return \(map[key].value\)
end
function Put(\(key, value\))
if \(key \in map\) then
update value; move node to front; return
end
if size \(=\) capacity then
\(old \gets\) node before tail; unlink it; delete \(map[old.key]\)
end
create node at front; \(map[key] \gets\) node
end
🧠 Expert

  • The node must store its key, so eviction can delete the map entry.

  • LFU (least frequently used) in \(O(1)\): a map from key to node, and a map from frequency to a doubly linked list of nodes with that frequency, plus the current minimum frequency.

  • Thread safety: a single lock around both structures is simplest; sharded caches (lock per segment) scale better; reads also mutate order, so a read-write lock does not help directly. Production caches (Caffeine) buffer access events and apply them in batches.

  • Real LRU is often approximated (Redis samples a few keys and evicts the oldest) because exact LRU bookkeeping is expensive.

🤖 ML connection

  • KV cache block management in LLM serving (PagedAttention) keeps free lists of blocks and evicts cached prefixes with LRU-like policies.

  • Embedding caches and feature caches in online serving use LRU/LFU.

  • Monotonic deques compute rolling max/min features in streaming pipelines in \(O(1)\) amortized per event.

  • Autograd uses a stack-like structure (the tape) to replay operations in reverse during backpropagation (Chapter 18).

🎤 Interview: Daily temperatures

“For each day, how many days until a warmer one?” Brute force scans forward from each day, \(O(n^2)\). Observation: a day is waiting for the first larger value to its right, the next-greater pattern. Keep a stack of indices with decreasing temperatures; when today is warmer than the top, pop it and set its answer to today - index. Each index is pushed and popped once, \(O(n)\) time, \(O(n)\) space. Trace [73,74,75,71,69,72,76]: answers [1,1,4,2,1,1,0]. Follow-up: “days until a temperature at least 5 degrees warmer” breaks the simple stack because the condition is not just “greater than”; discuss a segment tree over temperature values or a reverse scan with a lookup by value.

🔑 Takeaways

  • Lists: use a dummy head, save next before relinking, and know fast/slow pointers.

  • Stacks handle nesting; monotonic stacks answer “next greater/smaller” in \(O(n)\).

  • Monotonic deques give sliding-window max/min and speed up windowed DP.

  • LRU = hash map + doubly linked list; know eviction, LFU, and concurrency follow-ups.
