👋 Intro

How arrays and hash tables really work, and the five patterns that solve most array problems: frequency counting, prefix sums, two pointers, sliding windows, and Kadane’s algorithm. Each comes with pseudocode, an invariant, and the signals that tell you to use it.

Arrays and Dynamic Arrays

🔧 Intermediate

An array is a contiguous block of memory: element \(i\) lives at \(\text{base} + i\times\text{size}\), so indexing is \(O(1)\) and scans are cache-friendly. Inserting or deleting in the middle shifts elements, \(O(n)\). A dynamic array (Python list, C++ vector, Java ArrayList) grows by a constant factor, giving amortized \(O(1)\) append (Chapter 2).

Operation Array / dynamic array Hash table (expected)
Access by index / key \(O(1)\) \(O(1)\)
Search by value \(O(n)\) (\(O(\log n)\) if sorted) \(O(1)\)
Insert / delete at end \(O(1)\) amortized \(O(1)\)
Insert / delete in middle \(O(n)\) n/a
Ordered iteration yes no (insertion order in some languages)
🤖 ML connection

A tensor is a multi-dimensional array described by a shape and strides: how many elements to skip to move one step along each dimension. A transpose or slice usually just changes strides (no copy), which is why some operations need a “contiguous” copy first. Understanding strides explains view vs reshape, why channels-last layouts can be faster for convolutions, and why memory layout matters for GPU kernels.

Hash Tables

🌱 Beginner

A hash table is a coat check. You hand in your coat (the value) and get a numbered ticket computed from your name (the hash of the key). To get the coat back, compute the same number and go straight to that hook. No searching.

🔧 Intermediate

A hash function maps a key to an integer; modulo the table size gives a bucket. Two keys can land in the same bucket (a collision):

  • Chaining: each bucket holds a small list (Java HashMap, which switches long chains to balanced trees).

  • Open addressing: on collision, probe other slots (linear probing, quadratic probing, Robin Hood hashing). Python’s dict uses open addressing with a perturbed probe sequence.

The load factor \(\alpha = n/m\) (items per slot) controls performance. When it passes a threshold (often 0.66–0.75), the table doubles and rehashes all keys, amortized \(O(1)\) per insert.

🧠 Expert

  • With linear probing, expected probes for an unsuccessful search are about \(\tfrac12\left(1 + 1/(1-\alpha)^2\right)\): 2.5 at \(\alpha=0.5\), 50 at \(\alpha=0.9\). That is why load factors stay well below 1.

  • Hash flooding: an attacker who knows the hash function can send keys that all collide, turning \(O(1)\) into \(O(n)\) and a server into a denial-of-service target. Languages use randomized seeds (SipHash) for strings.

  • Keys must be immutable (or their hash must not change), and equal keys must have equal hashes.

  • Floating-point keys are dangerous: 0.1+0.2 != 0.3.

Pattern: Frequency Counting and Complement Lookup

Two Sum with a hash map

Input: array \(A\), target \(t\)
Output: indices \((i, j)\) with \(A[i] + A[j] = t\), or none
\(seen \gets\) empty map from value to index
for \(j \gets 0\) to \(n-1\) do
if \(t - A[j] \in seen\) then
return \((seen[t - A[j]], j)\)
end
\(seen[A[j]] \gets j\) ▷ insert after checking, so \(i \ne j\)
end
return none
❓ Why

Invariant: before processing \(j\), seen contains every value in \(A[0..j-1]\). If a valid pair \((i, j)\) exists with \(i<j\), then when the loop reaches \(j\), \(A[i]\) is already in seen, so the pair is found. Time: \(O(n)\) Space: \(O(n)\). Sorting plus two pointers gives \(O(n\log n)\) time and \(O(1)\) extra space but loses original indices unless you sort index pairs.

📡 Interview signals

“Find a pair/complement,” “count occurrences,” “group anagrams” (key = sorted letters or a 26-count vector), “first unique,” “have we seen this before,” “longest consecutive sequence” (a set plus only starting from sequence starts gives \(O(n)\)).

Pattern: Prefix Sums

🌱 Beginner

To answer “how much did I spend from day 3 to day 9?” you do not re-add every day. Keep a running total; the answer is \(\text{total}(9) - \text{total}(2)\).

🔧 Intermediate

Define \(P[0] = 0\) and \(P[i+1] = P[i] + A[i]\). Then \(\text{sum}(A[l..r]) = P[r+1] - P[l]\) in \(O(1)\) after \(O(n)\) preprocessing. In 2D, \(P[i][j]\) is the sum of the rectangle above-left; a rectangle sum uses inclusion-exclusion of four corners.

Count subarrays with sum \(k\) (values may be negative)

Input: array \(A\), integer \(k\)
\(count \gets 0\); \(prefix \gets 0\)
\(freq \gets\) map with \(freq[0] = 1\) ▷ the empty prefix
for each \(x\) in \(A\) do
\(prefix \gets prefix + x\)
\(count \gets count + freq[prefix - k]\) ▷ earlier prefixes \(p\) with \(prefix - p = k\)
\(freq[prefix] \gets freq[prefix] + 1\)
end
return \(count\)
❓ Why

A subarray \(A[i..j]\) sums to \(k\) exactly when \(P[j+1] - P[i] = k\), i.e. when an earlier prefix equals \(P[j+1] - k\). The map counts how many earlier prefixes have each value, so each position adds the number of valid starting points. Time: \(O(n)\) Space: \(O(n)\).

📡 Interview signals

“Sum (or XOR, or count) over a range,” many range queries on a static array, “subarray sum equals \(k\)” with negatives, “divisible by \(k\)” (store prefix mod \(k\)), “equal number of 0s and 1s” (map 0 to \(-1\), find prefix sum 0). For range queries with updates, use a Fenwick or segment tree (Chapter 7).

Pattern: Two Pointers

🔧 Intermediate

Two indices move through the data so that each step discards possibilities that cannot be the answer. Three common shapes:

  • Opposite ends on sorted data: pair sum, three-sum (fix one, two-pointer the rest, \(O(n^2)\)), container with most water, trapping rain water.

  • Same direction (fast/slow): remove duplicates in place, move zeros, partition, merge two sorted arrays from the back.

  • Two sequences: merging, intersection, is-subsequence.

Container with most water

Input: heights \(H[0..n-1]\)
\(l \gets 0\); \(r \gets n-1\); \(best \gets 0\)
while \(l < r\) do
\(best \gets \max(best, (r-l)\cdot\min(H[l], H[r]))\)
if \(H[l] < H[r]\) then
\(l \gets l+1\) ▷ the shorter wall limits every narrower pair
else
\(r \gets r-1\)
end
end
return \(best\)
❓ Why

Suppose \(H[l] < H[r]\). Any container using wall \(l\) and a wall \(r' < r\) is narrower and its height is still at most \(H[l]\), so it cannot beat the current one. Wall \(l\) can therefore be discarded safely. Each step discards one wall, so the loop runs \(n-1\) times: Time: \(O(n)\) Space: \(O(1)\). This “discard what cannot win” argument is the proof template for every opposite-ends two-pointer algorithm.

Pattern: Sliding Window

🌱 Beginner

Look at a long street through a window frame that you slide along. You can stretch the frame to see more or shrink it to see less, but you never jump backward. Every house enters the frame once and leaves once.

Variable-size sliding window template (longest valid window)

\(l \gets 0\); \(best \gets 0\); \(state \gets\) empty
for \(r \gets 0\) to \(n-1\) do
add \(A[r]\) to \(state\) ▷ expand
while \(state\) is invalid do
remove \(A[l]\) from \(state\); \(l \gets l+1\) ▷ shrink until valid
end
\(best \gets \max(best, r - l + 1)\)
end
return \(best\)
🔧 Intermediate

Longest substring without repeating characters: state is a count map; invalid when any count \(> 1\). Minimum window containing all of \(T\): expand until valid, then shrink while still valid, recording the minimum; track a counter of how many required characters are satisfied so validity is \(O(1)\). At most \(K\) distinct: invalid when the map has more than \(K\) keys. Exactly \(K\): \(\text{atMost}(K) - \text{atMost}(K-1)\).

❓ Why

Requires monotonicity: if a window is invalid, every larger window containing it is also invalid (and if valid, every smaller window inside is valid). Then for each right end, the best left end only moves right. Each element is added and removed at most once, so total work is \(O(n)\) even with the inner while. With negative numbers, “sum \(\le k\)” is not monotonic, which is why those problems need prefix sums instead.

📡 Interview signals

“Longest/shortest contiguous subarray or substring such that…,” “at most \(K\),” fixed window of size \(k\) (moving average, max sum of \(k\) consecutive), “all anagrams of \(p\) in \(s\)” (fixed window of frequency counts).

Pattern: Kadane’s Algorithm (Maximum Subarray)

Maximum subarray sum (Kadane)

\(cur \gets A[0]\); \(best \gets A[0]\)
for \(i \gets 1\) to \(n-1\) do
\(cur \gets \max(A[i], cur + A[i])\) ▷ best sum of a subarray ending at \(i\)
\(best \gets \max(best, cur)\)
end
return \(best\)
❓ Why

This is a DP: \(\text{end}[i] = \max(A[i], \text{end}[i-1] + A[i])\). A subarray ending at \(i\) either starts fresh at \(i\) or extends the best subarray ending at \(i-1\); extending anything worse cannot help. Only the previous value is needed, so space is \(O(1)\). Variants: maximum product (track both max and min, since a negative times the min can become the max); circular array (answer is \(\max(\text{kadane}, \text{total} - \text{min subarray})\), unless all negative).

In-Place Tricks

🔧 Intermediate

  • Dutch national flag (sort 0s, 1s, 2s in one pass): three pointers low, mid, high; invariant: \([0,low)\) are 0, \([low,mid)\) are 1, \((high, n-1]\) are 2.

  • Cyclic sort / index as hash: when values are in \([1, n]\), place value \(v\) at index \(v-1\); finds missing and duplicate numbers in \(O(n)\) time, \(O(1)\) space. First missing positive uses the same idea.

  • Rotate by \(k\): reverse all, reverse first \(k\), reverse rest.

  • Boyer–Moore majority vote: keep a candidate and a counter; increment on match, decrement otherwise, replace at zero. Finds an element appearing \(> n/2\) times in \(O(n)\), \(O(1)\) (verify with a second pass).

🤖 ML connection

  • Feature hashing (the “hashing trick”) maps millions of sparse categorical values into a fixed-size vector with a hash function, accepting collisions instead of storing a vocabulary.

  • Sliding windows compute streaming features: clicks in the last 5 minutes, rolling means, and rate limits on API tokens.

  • Prefix sums implement cumulative distributions for weighted sampling (binary search on the CDF), cumulative probabilities in top-p sampling, and integral images in computer vision.

  • Deduplication of training data starts with exact hashing of normalized text before near-duplicate methods (Chapter 15).

🎤 Interview: Longest substring with at most \(K\) distinct characters

Clarify: lowercase only? \(K = 0\)? Empty string? Brute force checks every substring, \(O(n^2)\) with incremental counts. Observation: if a window has more than \(K\) distinct characters, extending it keeps it invalid (monotonic), so a sliding window applies. State: a map from character to count in the window. Expand right, add its count; while the map has more than \(K\) keys, decrement the left character and delete it at zero, move left. Record the window length. Complexity \(O(n)\) time, \(O(K)\) space. Trace "eceba", \(K=2\): windows e, ec, ece (len 3), then eceb invalid \(\to\) shrink to eb... answer 3. Follow-up: streaming input where you cannot store the string: the same algorithm works with a deque of the window.

➕ Follow-ups

  • What if values can be negative? (Window no longer works; use prefix sums.)

  • What is the worst case of your hash map, and how would you defend against it?

  • Can you do it with \(O(1)\) extra space? (Often by sorting or using the array itself.)

  • What if the array does not fit in memory? (External sort, streaming, sketches.)

🔑 Takeaways

  • Arrays are fast because they are contiguous; hash tables trade order for \(O(1)\) lookup.

  • Prefix sums for range queries and “sum equals \(k\)” with negatives.

  • Two pointers when sorted or when one side can be discarded each step.

  • Sliding windows need monotonic validity; each element enters and leaves once.
