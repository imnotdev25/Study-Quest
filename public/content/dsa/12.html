Greedy Algorithms

🌱 Beginner

A greedy algorithm always takes the best-looking option right now and never reconsiders. It is fast and simple, but it only works when the local best choice is guaranteed to be part of a global best answer. The skill is knowing when that guarantee holds.

❓ Why

The exchange argument is the standard proof. Take any optimal solution \(O\). Show that if \(O\) differs from the greedy solution \(G\) at the first choice, you can swap \(O\)’s choice for \(G\)’s without making \(O\) worse. Repeat until \(O = G\). Therefore \(G\) is optimal. If you cannot write that swap, test small counterexamples; coin change with {1, 3, 4} breaks greedy.

Intervals

Maximum number of non-overlapping intervals (activity selection)

sort intervals by end time; \(count \gets 0\); \(lastEnd \gets -\infty\)
for each \([s, e]\) in sorted order do
if \(s \ge lastEnd\) then
\(count \gets count + 1\); \(lastEnd \gets e\)
end
end
return \(count\) ▷ minimum removals \(= n - count\)
❓ Why

Exchange: let \(O\) be optimal and suppose its first interval is not the one ending earliest. Replace it with the earliest-ending interval: it ends no later, so it conflicts with nothing else in \(O\). The size stays the same. Induct on the rest. Sorting by start or by length fails; know a counterexample for each.

Sweep Line

🔧 Intermediate

Turn each interval into events \((s, +1)\) and \((e, -1)\), sort events (at equal times, process ends before starts if intervals are half-open), and sweep while maintaining a counter. The maximum counter value is the maximum overlap (meeting rooms, car pooling, flights in the air). With a heap of active heights instead of a counter, the same sweep solves the skyline problem: on a start push the height, on an end remove it (lazy deletion), and output a key point whenever the maximum height changes. \(O(n\log n)\).

More Greedy Classics

🔧 Intermediate

  • Jump game: track the farthest reachable index; jump game II counts BFS-like levels (the end of the current jump range).

  • Gas station: if total gas \(\ge\) total cost a solution exists; start after the last point where the running tank went negative.

  • Candy / trapping rain water: two passes (left-to-right and right-to-left) and combine.

  • Partition labels: record each letter’s last index; cut when the current index equals the max last index seen.

  • Fractional knapsack: sort by value/weight; greedy is optimal (unlike 0/1 knapsack).

  • Scheduling to minimize lateness: earliest deadline first.

Huffman Coding

Huffman coding

\(H \gets\) min-heap of leaf nodes keyed by symbol frequency
while \(|H| > 1\) do
\(a \gets\) pop; \(b \gets\) pop ▷ the two least frequent
push a new node with children \(a\), \(b\) and frequency \(a.f + b.f\)
end
codes: left edge \(=0\), right edge \(=1\), read root-to-leaf paths
❓ Why

The two least frequent symbols can always be siblings at the deepest level of some optimal prefix-free code (exchange them with whatever is deepest; this cannot increase cost). Merging them reduces the problem to \(n-1\) symbols. The result minimizes expected code length, which comes within 1 bit of the entropy \(H = -\sum p_i\log_2 p_i\).

🤖 ML connection

Byte-pair encoding (Chapter 14) also merges the most frequent pair repeatedly, a greedy compression heuristic, though it optimizes vocabulary rather than code length. Entropy and cross-entropy come from the same coding view: cross-entropy loss is the expected number of bits to encode true labels with the model’s distribution. Greedy decoding in LLMs picks the most probable token at every step and is not globally optimal, which is why beam search and sampling exist.

Bit Manipulation

Expression Meaning
x & (x-1) clear the lowest set bit (count bits; test power of two: result 0)
x & -x isolate the lowest set bit (Fenwick trees)
x >> k & 1 test bit \(k\)
x | (1 << k), x & ~(1 << k) set / clear bit \(k\)
a ^ b ^ b = a XOR cancels pairs
s = (s-1) & m next submask of \(m\)
🔧 Intermediate

Single number: XOR all values; pairs cancel. Single number III (two unique): XOR all to get \(a \oplus b\), split by any set bit of it, XOR each group. Single number II (others appear three times): count each bit position mod 3. Counting bits for \(0..n\): \(bits[i] = bits[i \gg 1] + (i \,\&\, 1)\). Missing number: XOR of indices and values, or sum formula. Sum without +: XOR is sum without carry, AND shifted left is the carry; repeat until no carry.

Number Theory

🔧 Intermediate

  • GCD (Euclid): \(\gcd(a, b) = \gcd(b, a \bmod b)\), \(O(\log\min(a,b))\); \(\text{lcm}(a,b) = a / \gcd(a,b) \cdot b\) (divide first to avoid overflow).

  • Fast modular exponentiation: square and multiply, \(O(\log n)\).

  • Modular inverse for prime \(p\): \(a^{p-2} \bmod p\) (Fermat). Needed for \(\binom{n}{k} \bmod p\) via factorials.

  • Sieve of Eratosthenes: primes up to \(n\) in \(O(n\log\log n)\); start crossing out at \(p^2\).

  • Overflow: in languages with fixed-width integers, compute mid = lo + (hi - lo)/2 and take mod after every multiplication.

Combinatorics and Probability

🔧 Intermediate

  • \(\binom{n}{k}\) via Pascal’s rule \(\binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k}\) (DP).

  • Grid paths from \((0,0)\) to \((m,n)\): \(\binom{m+n}{m}\).

  • Catalan numbers \(C_n = \frac{1}{n+1}\binom{2n}{n}\) count valid parentheses, BST shapes with \(n\) nodes, and polygon triangulations.

  • Linearity of expectation solves many “expected number of…” questions without independence: expected fixed points of a random permutation is 1.

  • Birthday bound: with \(n\) items hashed into \(m\) buckets, collisions become likely around \(n \approx \sqrt{m}\), which sizes hash IDs (64-bit IDs are safe for billions of items; 32-bit are not).

rand7() from rand5() by rejection sampling

loop
\(x \gets 5\cdot(\text{rand5}() - 1) + \text{rand5}()\) ▷ uniform on 1..25
if \(x \le 21\) then
return \(((x - 1) \bmod 7) + 1\) ▷ 21 = 3 full copies of 1..7
end
end
❓ Why

Two calls give 25 equally likely outcomes. Keeping only the first 21 keeps each of 7 values exactly 3 times, so the result is uniform. Rejecting 4/25 of the time means the expected number of loops is \(25/21\). The same idea, rejection sampling, draws from any distribution you can bound by an easier one, and appears in ML in sampling algorithms and in speculative decoding’s acceptance rule.

Geometry

🔧 Intermediate

  • Cross product \((b-a)\times(c-a)\): sign tells whether \(c\) is left or right of the line \(ab\) (orientation), the basis of convex hull (Andrew’s monotone chain, \(O(n\log n)\)) and segment intersection tests.

  • Points on a line: normalize slopes as reduced fractions \((dy/g, dx/g)\) with a sign convention, not floating-point.

  • Rectangle overlap / area: overlap width \(= \max(0, \min(r_1,r_2) - \max(l_1,l_2))\).

  • IoU of boxes = intersection area / union area, used in detection metrics and non-max suppression (Chapter 18).

  • Rotate a matrix 90°: transpose, then reverse each row.

🎤 Interview: Merge intervals

Sort by start (\(O(n\log n)\)). Keep a result list; for each interval, if it starts after the last merged interval ends, append it; otherwise extend the last end to \(\max(\text{last end}, \text{current end})\). Clarify whether touching intervals ([1,2],[2,3]) merge. Why sort by start: after sorting, any interval that overlaps the current merged block must come immediately after it. Follow-ups: intervals arrive as a stream (an ordered map from start to end, merge neighbors on insert, \(O(\log n)\)); count of overlapping at each point (sweep line).

🔑 Takeaways

  • Use greedy only with an exchange argument; otherwise look for a counterexample.

  • Intervals: sort by end for selection, by start for merging; sweep lines for overlap counts.

  • Know the core bit tricks and XOR cancellation.

  • GCD, fast exponentiation, rejection sampling, and cross products cover most math rounds.
