👋 Intro

Pattern matching (KMP, Z-algorithm, Rabin–Karp), multi-pattern matching (Aho–Corasick), suffix arrays, palindromes (Manacher), and the tokenization algorithms every LLM depends on: BPE, WordPiece, and Unigram.

Why Naive Matching Is Slow

🔧 Intermediate

Checking every alignment of a pattern \(P\) (length \(m\)) against a text \(T\) (length \(n\)) costs \(O(nm)\) in the worst case (aaaa...ab in aaaa...a). The fast algorithms all avoid re-comparing characters already known to match.

KMP: Using the Pattern’s Own Structure

🌱 Beginner

Searching for “ABABC” you have matched “ABAB” and then see a mismatch. You do not restart from scratch: the last “AB” you read is also the beginning of the pattern, so you already have 2 characters matched. KMP precomputes those overlaps.

Prefix function (failure function) and KMP search

function PrefixFunction(\(P\)) ▷ \(\pi[i]\) = longest proper prefix of \(P[0..i]\) that is also a suffix
\(\pi[0] \gets 0\); \(k \gets 0\)
for \(i \gets 1\) to \(m-1\) do
while \(k > 0\) and \(P[i] \ne P[k]\) do
\(k \gets \pi[k-1]\) ▷ fall back to a shorter border
end
if \(P[i] = P[k]\) then
\(k \gets k + 1\)
end
\(\pi[i] \gets k\)
end
return \(\pi\)
end
function KMPSearch(\(T, P\))
\(\pi \gets\) ; \(k \gets 0\)
for \(i \gets 0\) to \(n-1\) do
while \(k > 0\) and \(T[i] \ne P[k]\) do
\(k \gets \pi[k-1]\)
end
if \(T[i] = P[k]\) then
\(k \gets k + 1\)
end
if \(k = m\) then
report match at \(i - m + 1\); \(k \gets \pi[k-1]\)
end
end
end
❓ Why

\(k\) is the length of the longest prefix of \(P\) that ends at the current text position. On a mismatch, the next candidate prefix must be a border (prefix that is also a suffix) of the matched part, and \(\pi\) lists borders from longest down. Linear time: \(k\) increases by at most 1 per character and every fallback decreases it, so total fallbacks \(\le n\). Time: \(O(n+m)\) Space: \(O(m)\). A neat trick: run the prefix function on P + "#" + T; positions where \(\pi = m\) are matches. The prefix function also gives the shortest period of a string (\(m - \pi[m-1]\)) and “shortest palindrome” (prefix function of \(s + \#+ \text{reverse}(s)\)).

Z-Algorithm

🔧 Intermediate

\(Z[i]\) = length of the longest substring starting at \(i\) that matches a prefix of the string. Computed in \(O(n)\) by maintaining the rightmost matched window \([l, r)\) and reusing \(Z[i - l]\) inside it. Pattern matching: compute \(Z\) on \(P \# T\); matches where \(Z[i] = m\). Often easier to remember than KMP.

Rabin–Karp: Rolling Hashes

🔧 Intermediate

Treat a window as a number in base \(b\) modulo a large prime \(q\): \(h = (c_0 b^{m-1} + \dots + c_{m-1}) \bmod q\). Sliding by one character: \(h' = ((h - c_{\text{out}} b^{m-1})\, b + c_{\text{in}}) \bmod q\), \(O(1)\). Compare hashes first and verify characters only when hashes match. Expected \(O(n+m)\).

🧠 Expert

Collisions: with modulus \(q \approx 10^9\), false matches among \(n\) windows are rare but possible, and adversarial inputs can force them. Use two independent moduli (or 64-bit overflow arithmetic with a random base) and verify on match. Rolling hashes solve “longest duplicate substring” (binary search on the length, then a hash set of windows: \(O(n\log n)\)), “repeated DNA sequences,” and substring equality in \(O(1)\) after \(O(n)\) preprocessing of prefix hashes.

Aho–Corasick: Many Patterns at Once

🔧 Intermediate

Build a trie of all patterns, then add failure links (by BFS): each node links to the longest proper suffix of its string that is also a trie node, KMP’s prefix function generalized to a trie. Scanning the text walks the automaton, following failure links on mismatch and reporting every pattern that ends at the current node (via output links). \(O(n + \sum m + \text{matches})\).

🤖 ML connection

Aho–Corasick is how large keyword blocklists, PII detectors (lists of names, known secrets), and profanity filters scan text in one pass. Data pipelines use it to filter training documents containing benchmark questions (contamination checks with known n-grams) or banned terms. Stop sequences in LLM serving (“stop when any of these strings appears”) use the same idea over the decoded text stream.

Suffix Arrays and LCP

🔧 Intermediate

A suffix array lists the starting indices of all suffixes of \(s\) in sorted order. Built in \(O(n\log n)\) by prefix doubling (sort by the first \(2^k\) characters using ranks from the previous round) or \(O(n)\) with SA-IS. The LCP array (Kasai, \(O(n)\)) stores the longest common prefix of adjacent suffixes. Then:

  • Pattern search: binary search the suffix array, \(O(m\log n)\).

  • Longest repeated substring: maximum of the LCP array.

  • Number of distinct substrings: \(\frac{n(n+1)}{2} - \sum \text{LCP}\).

  • Longest common substring of two strings: build on \(a\#b\); maximum LCP between adjacent suffixes from different strings.

🤖 ML connection

Exact-substring deduplication of LLM training data (removing any repeated span longer than, say, 50 tokens across a corpus) is done with suffix arrays over the concatenated, tokenized corpus; this was used in published work on deduplicating large web datasets. Suffix arrays also power n-gram language models over trillions of tokens and memorization checks (“did the model output a span verbatim from training data?”).

Palindromes

🔧 Intermediate

Expand around center: for each of the \(2n-1\) centers, expand while both sides match. \(O(n^2)\), \(O(1)\) space; usually enough in interviews. Manacher’s algorithm finds the longest palindromic substring in \(O(n)\): insert separators so all palindromes have odd length, keep the rightmost palindrome \([c - r, c + r]\), and initialize each new radius from its mirror \(2c - i\), expanding only past the known boundary.

Tokenization: How LLMs See Text

🌱 Beginner

A model cannot read letters directly; it reads numbers. Tokenization chops text into pieces from a fixed vocabulary of about 30K–250K entries. Common words become one token; rare words split into pieces (“unhappiness” \(\to\) “un”, “happiness”).

Training byte-pair encoding (BPE)

Input: corpus split into words (with counts); target vocabulary size \(V\)
represent each word as a sequence of bytes (or characters); \(vocab \gets\) all bytes
\(merges \gets []\)
while \(|vocab| < V\) do
count every adjacent pair of symbols across all words, weighted by word count
\((a, b) \gets\) the most frequent pair
replace every occurrence of \(a\,b\) with the new symbol \(ab\)
append \((a, b)\) to \(merges\); add \(ab\) to \(vocab\)
end
return \(merges\) ▷ encoding applies merges in the learned order
🔧 Intermediate

Encoding new text applies the merges in priority order (the earliest learned merge first) until none apply. Efficient training: maintain pair counts and an index from pair to positions; update only the neighbors of each merge, with a heap keyed by count, instead of recounting everything. Byte-level BPE (GPT-2 onward) starts from 256 bytes, so any input is representable and there is no unknown token. A regex pre-tokenizer first splits on spaces, digits, and punctuation so merges never cross those boundaries.

🔧 Intermediate

WordPiece (BERT) chooses merges by likelihood gain \(\frac{\text{count}(ab)}{\text{count}(a)\,\text{count}(b)}\) instead of raw frequency, and encodes with greedy longest-match from the left (a trie). Unigram LM (SentencePiece) starts with a large vocabulary and prunes tokens that least reduce the corpus likelihood; encoding finds the most probable segmentation with Viterbi (Chapter 12) and can sample segmentations for regularization.

🧠 Expert

Tokenization explains many LLM behaviors: arithmetic errors (numbers split into irregular chunks; some tokenizers split digits individually to help), poor performance on character-level tasks (counting letters in a word the model sees as one token), higher cost for non-English text (more tokens per word), and “glitch tokens” that were in the vocabulary but nearly absent from training. Changing tokenizers requires retraining embeddings. In interviews, you may be asked to implement BPE training on a small corpus: get the pair counting, the merge replacement (scan left to right, do not double-merge overlapping pairs like aaa), and tie-breaking right.

🎤 Interview: Implement BPE training on a toy corpus

Corpus: low \(\times 5\), lower \(\times 2\), newest \(\times 6\), widest \(\times 3\). Represent words as character tuples with an end-of-word marker. Round 1: count pairs weighted by frequency; (e, s) appears \(6 + 3 = 9\) times, the most frequent; merge to es. Round 2: (es, t) with 9; merge. Continue until the vocabulary size is reached. Discuss: complexity of naive recount per merge, \(O(\text{merges} \times \text{corpus})\); the incremental pair-count update; deterministic tie-breaking; and how encoding uses the merge rank.

🔑 Takeaways

  • KMP and Z are linear because they never re-read matched characters.

  • Rolling hashes give \(O(1)\) substring comparison; guard against collisions.

  • Aho–Corasick for many patterns; suffix arrays for repeats and deduplication.

  • BPE is greedy frequent-pair merging; tokenization shapes cost and model behavior.
