A repeatable method for solving unseen problems, how to analyze time and space (including amortized analysis and the master theorem), how to read constraints to guess the target complexity, and how to argue an algorithm is correct with invariants.

A Method for Unseen Problems

🌱 Beginner

Strong candidates do not “see” answers instantly. They follow a routine: make sure they understand the question, try small examples by hand, find a slow but correct idea, then ask “what work am I repeating?” to make it fast. The routine is what you practice.

The problem-solving loop used throughout this book.

🔧 Intermediate

Questions to ask in step 1: How large can the input be? Can values be negative, zero, or duplicated? Is the input sorted? What should happen on empty input? Is there always a valid answer? Do we need one answer or all answers? Can I modify the input? Is the data streaming or all available?

Step 4 is where the pattern library pays off. Brute force is usually “try every pair / every subarray / every subset.” Ask:

  • Am I recomputing a range? \(\to\) prefix sums or a sliding window.

  • Am I searching for a complement? \(\to\) hash map.

  • Is the data sorted or can I sort it? \(\to\) two pointers or binary search.

  • Do I need the best few items repeatedly? \(\to\) heap.

  • Do subproblems overlap? \(\to\) dynamic programming.

  • Is it about connections or dependencies? \(\to\) graph traversal.

  • Is the answer monotonic in some parameter? \(\to\) binary search on the answer.

Asymptotic Analysis

🔧 Intermediate

Big-O describes how cost grows with input size \(n\), ignoring constants. \(f(n) = O(g(n))\) means \(f\) grows no faster than \(g\) (an upper bound); \(\Omega\) is a lower bound; \(\Theta\) is a tight bound. Interviews use “Big-O” loosely to mean the tight bound for the worst case.

Complexity Name Typical source
\(O(1)\) constant hash lookup, array index
\(O(\log n)\) logarithmic binary search, balanced tree, heap operation
\(O(n)\) linear single pass, BFS/DFS on \(n\) nodes and edges
\(O(n\log n)\) linearithmic sorting, \(n\) heap operations
\(O(n^2)\) quadratic all pairs, 2D DP
\(O(n^3)\) cubic Floyd–Warshall, matrix multiply, interval DP
\(O(2^n)\) exponential all subsets, bitmask DP
\(O(n!)\) factorial all permutations

Reading Constraints

Input size \(n\) Likely target complexity (about \(10^8\) simple operations per second)
\(n \le 10\)–\(12\) \(O(n!)\) or \(O(n\cdot 2^n)\): permutations, brute force
\(n \le 20\)–\(25\) \(O(2^n)\) or \(O(n^2 2^n)\): subsets, bitmask DP, meet in the middle
\(n \le 500\) \(O(n^3)\): interval DP, Floyd–Warshall
\(n \le 5{,}000\) \(O(n^2)\): 2D DP, all pairs
\(n \le 10^5\)–\(10^6\) \(O(n\log n)\) or \(O(n)\): sort, heap, two pointers, hashing
\(n \ge 10^9\) or value range \(O(\log n)\) or \(O(1)\): binary search on answer, math

Constraints reveal the intended solution.

Amortized Analysis

🌱 Beginner

A dynamic array doubles its capacity when full. Copying is expensive, but it happens rarely. Spread the cost of copies over all the cheap appends and each append costs a constant amount on average. That “average over a sequence” is amortized cost.

❓ Why

Aggregate method for array doubling. Appending \(n\) items triggers copies of sizes \(1, 2, 4, \dots, n/2\), totaling less than \(n\). Plus \(n\) writes, the total is under \(3n\), so each append is amortized \(O(1)\).

Potential method. Define potential \(\Phi = 2\cdot\text{size} - \text{capacity}\). A cheap append raises \(\Phi\) by 2 (amortized cost 3). A resizing append costs \(\text{size}\) to copy, but \(\Phi\) drops by about \(\text{size}\), so amortized cost stays constant. The same idea proves the monotonic stack (each element pushed and popped once) and union-find bounds.

Why growth factor matters. Growing by a constant amount (e.g. \(+10\)) gives \(O(n^2)\) total copying. Any constant factor greater than 1 gives \(O(1)\) amortized. Many libraries use 1.5 or 2.

Recurrences and the Master Theorem

🔧 Intermediate

Divide-and-conquer algorithms have recurrences \(T(n) = a\,T(n/b) + f(n)\): split into \(a\) subproblems of size \(n/b\) with \(f(n)\) extra work. Compare \(f(n)\) to \(n^{\log_b a}\) (the work at the leaves):

  • \(f(n)\) smaller: leaves dominate, \(T(n) = \Theta(n^{\log_b a})\).

  • Equal: every level costs the same, \(T(n) = \Theta(n^{\log_b a}\log n)\).

  • \(f(n)\) larger (and regular): root dominates, \(T(n) = \Theta(f(n))\).

Examples: merge sort \(T = 2T(n/2) + n \Rightarrow \Theta(n\log n)\); binary search \(T = T(n/2)+1 \Rightarrow \Theta(\log n)\); Karatsuba \(T = 3T(n/2)+n \Rightarrow \Theta(n^{\log_2 3}) \approx n^{1.585}\); Strassen \(7T(n/2)+n^2 \Rightarrow n^{2.81}\); a tree traversal \(T = 2T(n/2) + 1 \Rightarrow \Theta(n)\).

🧠 Expert

Not every recurrence fits: \(T(n) = T(n-1) + n\) is \(\Theta(n^2)\) (unbalanced quicksort); \(T(n) = 2T(n-1) + 1\) is \(\Theta(2^n)\) (naive Fibonacci-style recursion); \(T(n) = T(n/3) + T(2n/3) + n\) is \(\Theta(n\log n)\) (recursion tree: each level costs \(n\), depth \(\log_{3/2} n\)). Use the recursion-tree method when splits are uneven. For recursive DP, total cost = number of states \(\times\) work per state, which is usually simpler than solving a recurrence.

Lower Bounds

❓ Why

Comparison sorting needs \(\Omega(n\log n)\) comparisons. A comparison sort is a binary decision tree; it must distinguish all \(n!\) orderings, so it needs at least \(n!\) leaves and height \(\log_2(n!) = \Theta(n\log n)\) (Stirling). Counting and radix sort beat this only by not comparing (they use the values’ digits). Element distinctness also needs \(\Omega(n\log n)\) in the comparison model, which is why a hash set (\(O(n)\) expected) is the fastest practical approach. Knowing a lower bound tells you when to stop optimizing and say so in the interview.

Proving Correctness with Invariants

🌱 Beginner

An invariant is a promise that is true before every step of a loop. If it is true at the start, each step keeps it true, and at the end it implies the answer, then the algorithm is correct. It is the same as induction.

Binary search for the first index with \(A[i] \ge x\) (lower bound)

Input: sorted array \(A[0..n-1]\), target \(x\)
Output: smallest \(i\) with \(A[i]\ge x\), or \(n\) if none
\(lo \gets 0\), \(hi \gets n\) ▷ answer is always in \([lo, hi]\)
while \(lo < hi\) do
\(mid \gets lo + \lfloor (hi - lo)/2 \rfloor\)
if \(A[mid] < x\) then
\(lo \gets mid + 1\) ▷ \(mid\) and everything left of it are too small
else
\(hi \gets mid\) ▷ \(mid\) is a candidate; the answer is \(\le mid\)
end
end
return \(lo\)
❓ Why

Invariant: every index \(< lo\) has \(A[i] < x\), and every index \(\ge hi\) has \(A[i] \ge x\) (or is \(n\)). Initially true (empty ranges). Each branch keeps it true by the comments above. The interval \([lo, hi)\) shrinks every iteration, so the loop ends with \(lo = hi\), which is exactly the first index with \(A[i] \ge x\). Writing the invariant first is how you avoid off-by-one errors in binary search.

🔧 Intermediate

Other proof tools you will use:

  • Induction for recursion: assume the call works on smaller inputs, show it works on this one.

  • Exchange argument for greedy: any optimal solution can be transformed into the greedy one without getting worse (Chapter 13).

  • Cut and paste for DP: an optimal solution contains optimal solutions to subproblems (Chapter 12).

  • Potential functions for amortized bounds.

Space, Recursion, and the Machine

🧠 Expert

  • Recursion uses stack space equal to its depth. DFS on a \(10^6\)-node path recurses \(10^6\) deep and overflows default stacks (Python’s default limit is 1,000); convert to an explicit stack.

  • Memory hierarchy: an \(O(n)\) scan over contiguous memory can be 10–100\(\times\) faster than an \(O(n)\) walk over a linked list, because of cache lines and prefetching. This is why arrays beat linked lists in practice, and why ML frameworks care about contiguous tensors and memory layout.

  • Hidden costs: string concatenation in a loop (\(O(n^2)\) total in many languages), slicing (copies), in on a list (\(O(n)\)), sorting inside a loop.

  • Expected vs worst case: hash tables are \(O(1)\) expected, \(O(n)\) worst case; quicksort \(O(n\log n)\) expected, \(O(n^2)\) worst. Say which one you mean.

🎤 Interview: Communicating your solution

“I’ll restate the problem: given an array of up to \(10^5\) integers, return the length of the longest subarray with sum \(k\), values can be negative. Negative values rule out a sliding window, because shrinking the window does not monotonically reduce the sum. Brute force over all subarrays with prefix sums is \(O(n^2)\), which is too slow for \(10^5\). If I store the first index at which each prefix sum appears, then for each position I look up whether \(\text{prefix}-k\) appeared earlier. That is \(O(n)\) time and \(O(n)\) space. Edge cases: a subarray starting at index 0, so I seed the map with prefix \(0\) at index \(-1\); and I store only the first occurrence to maximize length. Let me code it, then trace [1,-1,5,-2,3], \(k=3\).”

🔑 Takeaways

  • Follow the same loop every time: understand, examples, brute force, remove repeated work, plan, code, test.

  • Use constraints to infer the intended complexity.

  • Amortized analysis and the master theorem cover most complexity questions.

  • State invariants; they prevent off-by-one errors and prove correctness.
