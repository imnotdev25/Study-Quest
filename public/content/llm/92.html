Sequence length vs batch size

✏️ Derivation: When attention starts to dominate compute

Step 1. Per layer and per token, the dense parts (QKV, output, MLP with a \(4d\) hidden size) cost about \(2\cdot12d^2=24d^2\) forward FLOPs.

Step 2. Attention scores \(QK^\top\) and the weighted sum \(AV\) each cost \(2Td\) per token, so \(4Td\).

Step 3. Ratio \(\boxed{\frac{4Td}{24d^2}=\frac{T}{6d}}\) (halve it with causal masking that skips the upper triangle). At \(d=4096\), \(T=4096\) adds 17%; at \(T=65{,}536\) attention costs 2.7\(\times\) the rest of the layer.

At a fixed number of tokens per batch, longer sequences cost more FLOPs and, without FlashAttention, \(O(BT^2)\) memory for the score matrices. That is why pretraining starts with short sequences and extends context in a short final phase (Architectures part, long context).

SwiGLU: two projections and a gate

\(\operatorname{SwiGLU}(x)=W_{\downarrow}\big(\operatorname{SiLU}(W_gx)\odot W_ux\big)\), with \(\operatorname{SiLU}(z)=z\sigma(z)\). One projection decides how much to let through, the other what. Three matrices instead of two, so the hidden size shrinks from \(4d\) to \(\tfrac83d\) to keep parameters equal: \(3\cdot d\cdot\tfrac83d=8d^2=2\cdot d\cdot4d\). LLaMA rounds \(\tfrac83\cdot4096\) up to 11008.

Tiny recursive models

Recursive models such as HRM and TRM (2025) reuse one small network many times, refining a latent state \(z\) and a current answer \(y\): \(z\leftarrow f(x,z,y)\), \(y\leftarrow y+g(z)\). Depth comes from iteration, not parameters. Deep supervision grades the answer after every iteration, so each pass learns to improve the previous one.

The experiment below makes the point sharply. The task is prefix parity of 12 bits. The update is a convolution with kernel 3, so one pass can only move information one position. The same 1,442-parameter network is trained with \(K=1\), 4 and 16 iterations:

"""Toolkit ch. 9: sequence length vs batch size, SwiGLU, and a tiny recursive model."""
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# 1. Same token budget, different shapes. Per layer: dense FLOPs ~ 24 N d^2, attention ~ 4 N T d
#    (forward, N = tokens in the batch). Ratio attention/dense = T / (6 d).
d, tokens = 4096, 2**19
print("[seq] T       B    attn/dense FLOPs   attn-score memory (bf16, 32 heads, naive)")
for T in (1024, 4096, 16384, 65536):
    B = tokens // T
    ratio = (4 * tokens * T * d) / (24 * tokens * d * d)
    mem = B * 32 * T * T * 2 / 2**30
    print(f"[seq] {T:<6d} {B:4d}   {ratio:6.1%}            {mem:8.1f} GiB per layer")

# 2. SwiGLU: three matrices, so hidden = 8d/3 matches a 4d GELU MLP in parameters.
d = 4096
print(f"[swiglu] GELU 4d: {2 * d * 4 * d / 1e6:.1f}M params  SwiGLU 8d/3 (11008): {3 * d * 11008 / 1e6:.1f}M params")
x = torch.linspace(-4, 4, 9)
print(f"[swiglu] silu(x) {[round(v, 2) for v in F.silu(x).tolist()]}")


# 3. Tiny recursive model: one small network applied K times, refining a latent z and an answer y.
#    Task: prefix parity of 12 bits. The update is local (kernel 3), so one step can only move
#    information one position: the only way to get depth is to apply the same block again.
class TinyRec(nn.Module):
    def __init__(self, h=32):
        super().__init__()
        self.f = nn.Sequential(nn.Conv1d(3, h, 3, padding=1), nn.GELU(), nn.Conv1d(h, h, 1), nn.GELU(),
                               nn.Conv1d(h, 2, 1))

    def forward(self, x, K):
        z = torch.zeros_like(x); y = torch.zeros_like(x); outs = []
        for _ in range(K):
            dz, dy = self.f(torch.stack([x, z, y], 1)).unbind(1)
            z = torch.tanh(z + dz)
            y = y + dy
            outs.append(y)                         # deep supervision: every step is graded
        return outs


def batch(m, n=12):
    x = torch.randint(0, 2, (m, n)).float()
    return x, torch.cumsum(x, 1) % 2


for K in (1, 4, 16):
    torch.manual_seed(0)
    model = TinyRec()
    opt = torch.optim.AdamW(model.parameters(), lr=3e-3)
    for step in range(2000):
        x, t = batch(256)
        outs = model(x * 2 - 1, K)
        loss = sum(F.binary_cross_entropy_with_logits(o, t) for o in outs) / K
        opt.zero_grad(); loss.backward(); opt.step()
    with torch.no_grad():
        x, t = batch(4096)
        o = model(x * 2 - 1, K)[-1]
        bit = ((o > 0).float() == t).float().mean().item()
        exact = ((o > 0).float() == t).all(1).float().mean().item()
    params = sum(p.numel() for p in model.parameters())
    print(f"[trm] K={K:2d}: {params:,} params (same net)  bit acc {bit:.3f}  exact-match {exact:.3f}")

[seq] 1024    512     4.2%                32.0 GiB per layer

[seq] 16384    32    66.7%               512.0 GiB per layer
[seq] 65536     8   266.7%              2048.0 GiB per layer
[swiglu] GELU 4d: 134.2M params  SwiGLU 8d/3 (11008): 135.3M params
[swiglu] silu(x) [-0.07, -0.14, -0.24, -0.27, 0.0, 0.73, 1.76, 2.86, 3.93]
[trm] K= 1: 1,442 params (same net)  bit acc 0.582  exact-match 0.001

🔑 Key ideas

  • Same weights, more iterations: exact-match goes from 0.1% (\(K=1\)) to 100% (\(K=16\)). With \(K=4\) information can travel only a few positions, so long prefixes fail.

  • This is the idea behind test-time compute in a small form: spending more computation per input can substitute for more parameters, when the task needs sequential steps.
