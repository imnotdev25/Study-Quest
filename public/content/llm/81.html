🚀 Starting point

Selective prediction lets a model abstain. With confidence \(s_i=\max_cp_{ic}\) and threshold \(\tau\), it answers when \(s_i\ge\tau\). Coverage is the fraction answered, and selective risk is the error rate among answered items. Raising \(\tau\) trades coverage for lower risk.

Total: 20 minutes

A selective predictor may answer or abstain based on confidence. Given logits:

\[Z\in\mathbb{R}^{N\times C}\]

compute:

\[p_{ic}=\operatorname{softmax}(Z_i)_c\]

\[\hat y_i=\arg\max_c p_{ic}, \qquad s_i=\max_c p_{ic}\]

For threshold \(\tau\), answer only when:

\[A_i(\tau)=\mathbf 1[s_i\ge\tau]\]

Coverage is the fraction answered:

\[\operatorname{Coverage}(\tau) = \frac1N\sum_iA_i(\tau)\]

Selective risk is error conditional on answering:

\[\operatorname{Risk}(\tau) = \frac{ \sum_i A_i(\tau)\mathbf1[\hat y_i\ne y_i] }{ \sum_iA_i(\tau) }\]

Increasing \(\tau\) normally lowers both coverage and risk—but only if confidence ranks examples usefully.

Risk must always be interpreted with coverage. A system can obtain zero observed risk by refusing everything.

Confidence thresholds are also calibration-dependent. Temperature scaling changes:

\[p_i(T)=\operatorname{softmax}\left(\frac{Z_i}{T}\right)\]

without changing the predicted class. Thus two models with identical predictions can have different coverage at the same confidence threshold.

✏️ Derivation: the risk–coverage trade-off

Step 1. Sort items by confidence, highest first. Answering the top \(k\) gives coverage \(k/N\) and risk \(\frac1k\sum_{i\le k}\mathbb 1[\text{wrong}_i]\).

Step 2. If confidence ranks correctness well (wrong answers tend to have low \(s\)), risk rises as \(k\) grows. It’s a curve, not one number.

Step 3. Choosing \(\tau\): the largest coverage with risk \(\le r^*\) on a validation set. Using the test set to pick \(\tau\) makes the reported risk optimistic.

Step 4. AURC (area under the risk–coverage curve) summarizes the whole trade-off. Lower is better.

Step 5. Risk is a ratio of counts. When few items are answered (\(k\) small), it’s very noisy: report \(k\) with it.

⚙️ Algorithm: pick a confidence threshold for a risk target
Input: validation confidences \(s_i\), correctness \(c_i\), target risk \(r^*\)
sort by \(s\) descending
for \(k=1,\dots,N\) do
\(\text{risk}_k\gets\frac1k\sum_{i\le k}(1-c_i)\)
end
\(k^*\gets\max\{k:\text{risk}_k\le r^*\}\); \(\tau\gets s_{(k^*)}\)
report coverage \(k^*/N\) and risk on a separate test set

probabilities = F.softmax(
    model_logits,

confidence, predictions = probabilities.max(

correct = predictions.eq(labels)

Selective metrics:

def selective_metrics(confidence, correct, threshold):
    accepted = confidence >= threshold

    coverage = accepted.float().mean()

    risk = (
        1.0
        - correct[accepted].float().mean()
    )

    return torch.stack([
        threshold,
        coverage,
        risk,
    ])

Overconfidence experiment:

overconfident_logits = (

over_correct = over_predictions.eq(labels)

Accepted errors:

base_accepted = confidence >= threshold

base_answered_errors = (
    base_accepted & ~correct
).sum()

over_answered_errors = (
    over_accepted & ~over_correct
).sum()

Positive scaling does not change the largest logit:

\[\arg\max_c z_c = \arg\max_c 3z_c\]

so predictions and ordinary accuracy remain identical. But softmax probabilities become sharper, moving more examples above \(0.9\). This increases coverage and can expose more users to confidently answered errors.

A risk–coverage curve evaluates ranking quality: useful confidence should place correct predictions above incorrect ones. Calibration instead asks whether a stated confidence such as \(0.9\) corresponds to roughly 90% correctness. A model can rank examples well while still being overconfident.

Thresholds should be selected on a validation set under a constraint such as:

\[\min_\tau \operatorname{Risk}(\tau) \quad \text{subject to} \quad \operatorname{Coverage}(\tau)\ge c_{\min}\]

Then both risk and coverage are reported once on untouched test data.

Check answers:

  1. Risk can be reduced trivially by answering fewer examples; coverage reveals this trade-off.

  2. Coverage usually approaches zero, unless some predictions have confidence exactly one.

  3. Positive temperature scaling does not change top-1 decisions, but it can substantially change which examples cross a confidence threshold.

  4. Inspect confidence calibration, logit scale, temperature, and whether provider scores have comparable semantics.

  5. Searching thresholds on the test set overfits sampling noise and makes the reported test risk optimistically biased.

Retrieval answers:

  • Simpson’s paradox arises when different group mixtures overwhelm consistent within-group improvements.

  • Removing failures changes the evaluated population and can reward unreliable systems by excluding their hardest cases.
