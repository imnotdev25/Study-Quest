🚀 Starting point

AGENTS.md is a plain Markdown file at the root of a repository that tells coding agents what a new teammate would need on day one: how to build and test, the conventions, and the traps. It is an open convention read by several agents (Codex, Cursor, and others); Claude Code reads CLAUDE.md and Gemini CLI GEMINI.md, which can simply point to or import AGENTS.md. The harness loads it into the context at the start of every session, so it is the one piece of context you fully control.

What belongs in it

# AGENTS.md

## Commands
- Install: `uv sync`            - Test: `make test` (single file: `pytest tests/test_x.py -q`)
- Lint/format: `make lint`      - Type check: `make typecheck`
Run test + lint before saying a task is done.

## Layout
- src/api/      FastAPI routes; one file per resource
- src/core/     business logic, no I/O
- db/migrations generated with `make new-migration name=<slug>`, never edited by hand

## Conventions
- Type hints on public functions; errors are raised as AppError subclasses (src/core/errors.py).
- New endpoints need a test in tests/api/ using the `client` fixture.

## Gotchas
- Integration tests need Docker running (they start Postgres).
- `config/flags.yaml` is read at startup: restart the server after changing it.

## Boundaries
- Do not modify files under vendor/ or .github/workflows/ without asking.
- Never commit secrets; .env is local only.

Practices

  • Short and specific. Every line is read on every task and costs context. Exact commands beat descriptions; “use make test” beats “we value testing”.

  • Write what the agent got wrong. The best entries come from real mistakes: when an agent repeats an error, add one line.

  • Nest in monorepos. A file per package; the closest one to the file being edited wins, so package rules override root rules.

  • Don’t duplicate the code. Point to files (“error types: src/core/errors.py”) instead of pasting them; pasted code goes stale.

  • Keep it true. Review it like code, in pull requests. A wrong instruction is worse than none: the agent will follow it.

  • Personal vs project. Team conventions go in the repo; your preferences (tone, editor, review style) go in your user-level file.

  • Instructions, not secrets. It is committed and sent to model providers.
