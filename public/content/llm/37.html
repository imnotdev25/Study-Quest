🚀 Starting point

Floating point stores \(\pm\,\text{mantissa}\times2^{\text{exponent}}\). FP16 has 5 exponent bits: its largest value is 65,504, the smallest normal is \(2^{-14}\approx6.1\times10^{-5}\), and the smallest subnormal is \(2^{-24}\approx6\times10^{-8}\). Anything smaller becomes 0 (underflow), and anything larger becomes \(\infty\) (overflow). BF16 has FP32’s 8 exponent bits, so its range is huge but its precision is low.

Mixed-precision training typically combines:

  • FP16 or BF16 computation for faster matrix operations and lower activation memory.

  • FP32 master parameters and optimizer state for reliable updates.

  • FP32 accumulation for numerically sensitive reductions.

FP16 has limited range. A sufficiently small gradient can underflow to zero, while a large value can overflow to infinity.

Loss scaling multiplies the loss before backpropagation:

\[L_{\text{scaled}}=sL\]

Therefore:

\[\nabla_\theta L_{\text{scaled}} = s\nabla_\theta L\]

Before the optimizer update, divide by the same scale:

\[g=\frac{g_{\text{scaled}}}{s}\]

Mathematically this changes nothing, but it moves small intermediate gradients into FP16’s representable range.

The correct update sequence is:

scaled backward
→ unscale gradients
→ check for inf/nan
→ clip gradients
→ optimizer step

If overflow is detected, skip the optimizer step and reduce the scale. BF16 has a much wider exponent range than FP16 and usually does not require loss scaling, though it has lower mantissa precision than FP32.

✏️ Derivation: loss scaling preserves the update

Step 1. Backprop is linear in the loss: \(\nabla_\theta(SL)=S\nabla_\theta L\) for a constant \(S\).

Step 2. So compute \(g_s=\nabla(SL)\) in FP16, where small gradients are now \(S\) times larger and above the underflow limit.

Step 3. Unscale in FP32: \(g=g_s/S\). The update \(\theta-\eta g\) is mathematically identical to an unscaled run.

Step 4. Example: a gradient of \(10^{-8}\) underflows in FP16. With \(S=2^{16}=65{,}536\), it becomes \(6.6\times10^{-4}\), which is representable.

Step 5. Overflow: if \(S\) is too large, some \(g_s=\infty\). Then the step must be skipped (no update), and \(S\) reduced. A dynamic scaler halves \(S\) on overflow and doubles it after \(N\) clean steps, staying near the largest safe value.

Step 6. BF16 rarely needs scaling, because its range matches FP32.

⚙️ Algorithm: dynamic loss scaling
Input: initial scale \(S\), growth interval \(N\), FP32 master weights
for each step do
forward in FP16; backward on \(S\cdot L\)
\(g\gets g_s/S\) in FP32
if any \(g\) is \(\infty\) or NaN then
skip the update; \(S\gets S/2\); reset clean-step counter
else
optimizer step on \(g\); after \(N\) clean steps, \(S\gets2S\)
end
end

def simulated_amp_step(parameter, gradient, scale):
    scaled_gradient_fp16 = (
        gradient * scale
    ).to(torch.float16)

    gradients_finite = (
        torch.isfinite(scaled_gradient_fp16)
        .all()
        .item()
    )

    if not gradients_finite:
        return parameter.clone(), False, None

    recovered_gradient = (
        scaled_gradient_fp16.float() / scale
    )

    updated_parameter = parameter - lr * recovered_gradient
    return updated_parameter, True, recovered_gradient


direct_fp16 = gradient.to(torch.float16).float()

updated, stepped, recovered = simulated_amp_step(
    parameter, gradient, scale
)

large_gradient = gradient.clone()
large_gradient[-1] = 1e4

updated_overflow, stepped, recovered = simulated_amp_step(
    parameter,
    large_gradient,
    scale,
)

new_scale = scale / 2 if not stepped else scale

For the tiny gradient:

\[10^{-8}\times1024\approx10^{-5}\]

The scaled value fits in FP16. It can then be converted to FP32 and safely divided by 1024.

For the large gradient:

\[10^4\times1024=1.024\times10^7\]

This exceeds FP16’s largest finite value, approximately \(6.55\times10^4\), producing infinity. The update must be skipped; otherwise the parameters and optimizer state would be corrupted.

Check answers:

  1. Multiplication by \(s\) during backward and division by \(s\) before updating cancel algebraically.

  2. Clipping scaled gradients would compare \(s\lVert g\rVert\) against the threshold, effectively changing the clipping threshold.

  3. Overflows become more frequent, causing repeated skipped updates and stalled training.

  4. Inspect gradient finiteness, the current loss scale, activation ranges, gradient norms, and the first operation producing inf or nan.

  5. Lower-precision activations and saved backward tensors use less memory. FP32 master weights and Adam’s moment states may remain FP32 and unchanged in size.

Retrieval answers:

  • Bias correction compensates for moment estimates being initialized at zero.

  • With zero task gradient, AdamW applies:

\[\theta_t=(1-\eta\lambda)\theta_{t-1}\]
