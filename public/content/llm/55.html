🚀 Starting point

MLA stores one small latent vector per token instead of full keys and values, and reconstructs per-head keys and values from it with up-projections. The trick that makes it fast is that the up-projections can be folded into the query and output matrices, so the full keys are never materialized during decoding.

Multi-head latent attention caches only the red box. Per-head keys and values are implied by the latent, and their up-projections fold into the query and output matrices.

✏️ Derivation: MLA and why RoPE needs a separate part

Step 1. Latent: \(c_t=x_tW_{DKV}\in\mathbb R^{d_c}\) (\(d_c=512\) in V3). Per head \(h\): \(k_{t,h}=c_tW_{UK}^{(h)}\), \(v_{t,h}=c_tW_{UV}^{(h)}\). Cache only \(c_t\).

Step 2. Score: \(q_{t,h}^\top k_{s,h}=(x_tW_Q^{(h)})(c_sW_{UK}^{(h)})^\top=x_t\underbrace{W_Q^{(h)}W_{UK}^{(h)\top}}_{\text{precompute}}c_s^\top\). Attention runs directly against the cached latents.

Step 3. Similarly \(\sum_sa_{ts}v_{s,h}W_O^{(h)}=\big(\sum_sa_{ts}c_s\big)W_{UV}^{(h)}W_O^{(h)}\): fold \(W_{UV}\) into \(W_O\).

Step 4. RoPE breaks step 2: with RoPE, \(q^\top k=x_tW_QR_{t}^\top R_{s}W_{UK}^\top c_s^\top\), and the position-dependent \(R_{s-t}\) sits between \(W_Q\) and \(W_{UK}\), so they can no longer be merged.

Step 5. Fix: decoupled RoPE. Add a small extra key \(k^R_s=\operatorname{RoPE}(x_sW_{KR})\in\mathbb R^{64}\), shared across heads, and an extra query part. Score \(=q^{C\top}k^C+q^{R\top}k^R\): content part absorbed, position part tiny.

Step 6. Cache per token (V3: 61 layers, BF16): \((512+64)\cdot61\cdot2=70{,}272\) bytes \(\approx69\) KB, versus about 3.8 MB for full MHA with 128 heads of 128 dimensions: \(\approx57\times\) smaller.

DeepSeek-V3 (Dec 2024) 671B total / 37B active; 61 layers, \(D=7168\), 128 heads; MLA with \(d_c=512\), RoPE dim 64; first 3 layers dense, then MoE with 256 routed experts (top-8) + 1 shared; aux-loss-free balancing; multi-token prediction (MTP) depth 1; FP8 mixed-precision training; 14.8T tokens.

Bytes the decoder must keep per token of context. “DSV3 as MHA” is the same model with full 128-head keys and values. DSV4.1-Flash’s 0.87 KB (890 bytes) is from its model card.

✏️ Derivation: multi-token prediction

Step 1. Besides predicting \(x_{t+1}\), an extra module (sharing the embedding and output head) predicts \(x_{t+2}\) from the main model’s hidden state at \(t\) combined with the embedding of \(x_{t+1}\).

Step 2. Loss \(L=L_{\text{main}}+\lambda\cdot\frac1D\sum_{d=1}^{D}L_{\text{MTP}}^{(d)}\), each term an ordinary next-token NLL shifted by \(d\) more positions.

Step 3. More predictions per token means a denser training signal. At inference the MTP head can be dropped, or used to draft the next token for speculative decoding.
