🚀 Starting point

Instead of attending to all \(T\) previous tokens, sparse attention picks a small subset per query. The selection must itself be cheap, so it’s done by a small, low-precision indexer. DeepSeek-V4 goes further and compresses the KV sequence before selecting.

✏️ Derivation: DeepSeek Sparse Attention (V3.2): a lightning indexer and top-\(k\)

Step 1. Indexer score between query \(t\) and earlier token \(s\): \(I_{t,s}=\sum_{h=1}^{H_I}w_{t,h}\operatorname{ReLU}(q^I_{t,h}\cdot k^I_s)\), with few heads and small dimension, run in low precision.

Step 2. Select \(\mathcal S_t=\operatorname{TopK}_s(I_{t,s})\) (\(k=2048\) in V3.2), and run ordinary MLA attention over only those tokens.

Step 3. Main attention drops from \(O(T^2)\) to \(O(Tk)\). The indexer is still \(O(T^2)\), but with a tiny constant.

Step 4. The indexer is trained to match the dense model’s attention distribution (a KL loss), then the main model adapts to the sparse pattern.

What one CSA query reads: a few selected compressed blocks plus its recent raw tokens. HCA layers compress \(m'=128\) tokens per entry and read all entries with no selection.

✏️ Derivation: DeepSeek-V4: Compressed Sparse Attention (CSA) and Heavily Compressed Attention (HCA)

From the V4 technical report (arXiv 2606.19348) and V4-Flash’s config.json.

Step 1. Compress the sequence: group every \(m\) consecutive tokens into one entry, as a learned softmax-weighted average of their projected states: \(C^{\text{Comp}}_i=\sum_jS_j\odot C_j\) over the block (CSA uses two overlapping series so blocks blend with their neighbour). The KV sequence shrinks by \(m\).

Step 2. CSA (\(m=4\)): a lightning indexer over the compressed entries picks the top-\(k\) (index_topk: 512), and attention reads only those. HCA (\(m'=128\)): compress 128\(\times\) and attend densely with no indexer.

Step 3. V4-Flash alternates them: its 43 layers have compression ratios \(0,0,4,128,4,128,\dots,4,0\). Layers 1, 2 and 43 are uncompressed.

Step 4. Sliding window: a query can’t see tokens inside its own unfinished compressed block, so every layer also attends to the last 128 raw tokens (sliding_window: 128).

Step 5. Shared-KV MQA: one compressed entry serves as both key and value (num_key_value_heads: 1, head_dim: 512), with RoPE on the last 64 dimensions only.

Step 6. Effect (report, V4-Pro at 1M tokens vs V3.2): 27% of the per-token inference FLOPs and 10% of the KV cache.

DeepSeek-V4.1-Flash (released October 2026, this book’s newest model) is described on its model card as: a 552B-parameter backbone activating 8B parameters per token in prefill and 16B in decode; a 40-layer causal encoder–decoder (20 + 20) in which the decoder’s global KV cache is built from the encoder’s final hidden states, which makes long-prompt prefill cheap; CSA2, where each layer either computes its own sparse selection (Full), re-ranks a candidate pool from an earlier layer (Reindex), or reuses another layer’s top-\(k\) indices (Reuse); an FP4 KV cache of about 890 bytes per token (about \(\tfrac14\) of V4-Flash); 1 shared + 384 routed experts with 6 active; a 196B-parameter “Engram” memory accessed by token lookup; and 45T pre-training tokens. I took these from the model card only; the formulas behind CSA2 and Engram are in its report, which I haven’t reviewed.
