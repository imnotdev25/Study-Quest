🚀 Starting point

Multi-head attention runs \(H\) small attentions in parallel, each with width \(d_h=D/H\), so different heads can attend to different things. It costs the same parameters as one wide head: the \(D\)-wide projections are just cut into \(H\) slices. The heads’ outputs are concatenated and mixed by \(W_O\).

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. Why are attention logits divided by \(\sqrt{d_k}\)?

  2. What value should replace causally forbidden logits before softmax?

For \(X\in\mathbb{R}^{B\times T\times D}\), choose \(H\) heads with:

\[d_h=\frac{D}{H}\]

After projection, each tensor is reshaped:

\[Q,K,V:\ [B,T,D] \rightarrow[B,T,H,d_h] \rightarrow[B,H,T,d_h]\]

Each head independently computes:

\[A_h= \operatorname{softmax} \left( \frac{Q_hK_h^\top}{\sqrt{d_h}}+M \right) \in\mathbb{R}^{B\times H\times T\times T}\]

\[C_h=A_hV_h \in\mathbb{R}^{B\times H\times T\times d_h}\]

Heads are concatenated and projected:

\[C:\ [B,H,T,d_h]\rightarrow[B,T,D]\]

\[Y=CW_O,\qquad W_O\in\mathbb{R}^{D\times D}\]

At fixed \(D\), adding heads changes how features are partitioned but does not change the leading attention compute:

\[O(BHT^2d_h)=O(BT^2D)\]

However, explicitly stored attention probabilities require \(O(BHT^2)\) memory.

✏️ Derivation: heads as slices, and the cost of attention

Step 1. Reshape \(Q\in\mathbb R^{B\times T\times D}\) to \([B,T,H,d_h]\), then transpose to \([B,H,T,d_h]\). Head \(h\) uses columns \(h d_h,\dots,(h+1)d_h-1\) of \(W_Q\): no new parameters.

Step 2. Per head: \(C_h=\operatorname{softmax}(Q_hK_h^\top/\sqrt{d_h}+M)V_h\in\mathbb R^{B\times T\times d_h}\).

Step 3. Concatenate and project: \(Y=[C_1,\dots,C_H]W_O=\sum_hC_hW_O^{(h)}\), where \(W_O^{(h)}\) are the matching \(d_h\) rows of \(W_O\). So MHA is a sum of per-head contributions.

Step 4. Parameters: \(W_Q,W_K,W_V,W_O\) are each \(D\times D\), giving \(4D^2\) regardless of \(H\).

Step 5. Compute for scores: \(H\) heads \(\times\) \(T^2\) pairs \(\times\) \(d_h\) multiply-adds \(=T^2D\) per example, the same as one head of width \(D\). Memory for \(A\): \(B\cdot H\cdot T^2\) numbers, which does grow with \(H\) and is why fused kernels avoid storing it.

Step 6. Layout bug: reshaping \([B,T,D]\to[B,H,T,d_h]\) directly (without the transpose) silently mixes tokens and features. Shapes still match, so no error is raised.

⚙️ Algorithm: multi-head attention
Input: \(X\in\mathbb R^{B\times T\times D}\), heads \(H\), \(d_h=D/H\)
\(Q,K,V\gets XW_Q,XW_K,XW_V\), each reshaped \([B,T,H,d_h]\) then transposed to \([B,H,T,d_h]\)
\(C\gets\operatorname{softmax}(QK^\top/\sqrt{d_h}+M)V\) ▷ all heads at once
\(C\gets\) transpose to \([B,T,H,d_h]\), reshape to \([B,T,D]\)
\(Y\gets CW_O\)

Solution — open after attempting

def split_heads(x):
    x = x.view(B, T, H, d_h)
    return x.transpose(1, 2)


def multi_head_attention(X):
    qkv = X @ W_qkv
    q, k, v = qkv.chunk(3, dim=-1)

    q = split_heads(q)
    k = split_heads(k)
    v = split_heads(v)

    scores = q @ k.transpose(-2, -1)
    scores = scores / math.sqrt(d_h)

    causal_mask = torch.tril(
        torch.ones(T, T, dtype=torch.bool)
    )[None, None, :, :]

    scores = scores.masked_fill(~causal_mask, float("-inf"))
    weights = torch.softmax(scores, dim=-1)
    context = weights @ v

    merged = (
        context.transpose(1, 2)
        .contiguous()
        .view(B, T, D)
    )
    output = merged @ W_o

    return output, weights, q, k, v

The incorrect calculation produces:

[B, T, H, H]

Because the layout remains [B, T, H, d_h], the matrix multiplication compares heads within each token. The intended layout [B, H, T, d_h] compares token positions independently within each head.

transpose() returns a view with changed strides. Calling contiguous() before view() creates the expected physical layout. Using reshape() can also work, but it may silently allocate a copy.

Check answers:

  1. Each head receives \(d_h=D/H\) features, which must be an integer for equal-sized heads.

  2. [1, 1, T, T].

  3. The [B,T,H,d_h] → [B,H,T,d_h] transpose is missing.

  4. QKV contains \(3D^2\) parameters and the output projection contains \(D^2\), totaling:

    \[4D^2\]

  5. Score memory grows by \(4\times\), since it scales as \(T^2\).

Retrieval answers:

  • Scaling by \(\sqrt{d_k}\) prevents dot-product magnitude from growing with head dimension and saturating softmax.

  • Forbidden logits should be replaced by \(-\infty\), or a sufficiently negative finite value supported by the computation dtype.
