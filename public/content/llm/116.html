🚀 Starting point

Frontier models (the latest Claude, GPT and Gemini families) follow instructions literally, reason internally before answering, call tools in parallel, and can work for hours on one task. Most old prompting tricks are unnecessary; what matters is the brief, the tools, the checks and the context.

  1. Brief like a senior colleague: the goal, why it matters, the constraints, what done looks like, and what to do when blocked. Explicit beats implied: if you want the model to make changes rather than suggest them, say so.

  2. Let it think: set the reasoning effort or thinking budget for hard tasks instead of writing “think step by step”. Ask it to plan before large changes.

  3. Give verification: tests, a script that checks the output, screenshots for UI. A model that can check its work iterates to correct; one that can’t stops at plausible.

  4. Good tools: few, general, well-named tools with typed schemas and descriptions that say when to use them; errors that tell the model how to recover. Let independent calls run in parallel.

  5. Structured outputs via the API’s schema mode, not “reply in JSON please”.

  6. State in files for long work: a progress log, a todo list and git commits, so work survives context resets and can be resumed by a fresh session.

  7. Subagents for breadth: searching a large codebase or the web in parallel keeps the lead agent’s context clean.

  8. Calm instructions: no ALL CAPS or “you MUST”. Strong models over-apply emphasised rules; one clear sentence with a reason works better.

  9. Pick the model per step: a fast cheap model for routing, extraction and simple edits; the strongest model for planning, hard debugging and review. Cache the stable prefix.

  10. Review the diff, not the summary: agents report confidently. Read changes to tests, configs and security-relevant code yourself.

  11. Measure: keep a small eval set of your own tasks; re-run it when you change the model, the prompt or the harness, and compare paired.

  12. Security: treat web pages, documents and tool outputs as untrusted data (prompt injection); keep credentials out of the agent’s environment; sandbox shells; require approval for irreversible or outward-facing actions.
