🚀 Starting point

Two kinds of quantities live in an RL step. Data (rewards, advantages, returns, old log-probs) describe what happened during the rollout and must be constants. The model’s current log-probabilities are what we differentiate. A stop-gradient (.detach()) is the boundary between them.

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. Where should a sequence-level reward be inserted in a padded response tensor?

  2. How can two computations have identical forward values but different gradients?

A post-training rollout pipeline should have a clear graph boundary:

\[\text{rollout policy} \rightarrow \text{rewards} \rightarrow \text{returns/advantages} \quad\text{(fixed)}\]

\[\text{current policy} \rightarrow \text{log-probabilities} \rightarrow L_{\text{policy}} \quad\text{(differentiable)}\]

For stored rollout log-probabilities:

\[\ell_{\text{rollout}},\ell_{\text{ref}} \in\mathbb{R}^{B\times T}\]

the shaped reward may be:

\[r_t = -\beta \left( \ell_{\text{rollout},t} - \ell_{\text{ref},t} \right) + r_t^{\text{terminal}}\]

These rewards produce fixed returns \(G_t\). A simple actor loss is:

\[L_{\text{actor}} = -\frac1N\sum_t M_tG_t \log\pi_\theta(a_t\mid s_t)\]

Its intended gradient is:

\[\nabla_\theta L_{\text{actor}} = -\frac1N\sum_t M_tG_t \nabla_\theta\log\pi_\theta(a_t\mid s_t)\]

A subtle bug occurs if rewards are recomputed from the current trainable log-probabilities:

\[G_t=G_t(\theta)\]

Then:

\[\nabla_\theta[-G_t(\theta)\ell_t(\theta)] = -G_t\nabla_\theta\ell_t -\ell_t\nabla_\theta G_t\]

The second term is not part of the intended policy-gradient estimator.

A differentiable KL loss can be valid when explicitly designed as a separate regularizer. The bug is accidentally allowing gradients through reward or advantage construction.

✏️ Derivation: what goes wrong without the stop-gradient

Step 1. Intended loss: \(L=-A\,\ell_\theta\) with \(A\) a constant, so \(\nabla L=-A\nabla\ell_\theta\): policy gradient.

Step 2. Bug: build the KL-shaped reward from the current policy, \(A(\theta)=R-\beta(\ell_\theta-\ell_{\text{ref}})\), without detaching.

Step 3. Product rule: \(\nabla L=-A(\theta)\nabla\ell_\theta-\ell_\theta\nabla A(\theta)=-A\nabla\ell_\theta+\beta\,\ell_\theta\nabla\ell_\theta\).

Step 4. The extra term \(\beta\ell_\theta\nabla\ell_\theta=\frac{\beta}{2}\nabla(\ell_\theta^2)\) minimizes \(\ell_\theta^2\), pushing \(\log\pi\) toward 0, i.e. toward probability 1 for the sampled tokens. That’s an objective nobody asked for.

Step 5. Rule: rewards, advantages, returns, \(\ell_{\text{old}}\) and \(\ell_{\text{ref}}\) are computed under no_grad or detached. Gradient flows only through \(\ell_\theta\) in the ratio (and through an explicit KL loss term, if you use one).

⚙️ Algorithm: correct graph boundary in an RL update
Input: rollout data
with no gradient: compute \(\ell_{\text{rollout}},\ell_{\text{ref}}\), shaped rewards, advantages and returns
for each minibatch do
\(\ell_\theta\gets\) current log-probs (with gradient)
\(L\gets\) PPO loss using \(\exp(\ell_\theta-\ell_{\text{rollout}})\) and the fixed advantages
check: advantages.requires_grad is False
end

def return_to_go(rewards, gamma):
    running = torch.zeros(
        rewards.shape[0],
        dtype=rewards.dtype,
        device=rewards.device,
    )

    reversed_returns = []

    for t in reversed(range(rewards.shape[1])):
        running = (
            rewards[:, t]
            + gamma * running
        )

        reversed_returns.append(running)

    return torch.stack(
        reversed_returns[::-1],
        dim=1,
    )

At initialization:

\[\ell_{\text{current}} = \ell_{\text{rollout}}\]

so both programs produce identical KL values, returns, and scalar losses.

Their graphs differ. The correct loss differentiates only through the explicit log-probability:

\[\nabla_\theta L_{\text{correct}} = -\frac1N\sum_tG_t\nabla_\theta\ell_t\]

The buggy loss also differentiates through return construction:

\[\nabla_\theta L_{\text{bad}} = -\frac1N\sum_t \left( G_t\nabla_\theta\ell_t + \ell_t\nabla_\theta G_t \right)\]

Because each return contains future KL rewards, a token log-probability may also affect the return assigned to earlier tokens.

If all trainable log-probabilities were initialized to zero, the extra product-rule term:

\[-\ell_t\nabla_\theta G_t\]

could vanish at that point. The bug would reappear after the log-probabilities moved away from zero, making zero-valued synthetic tests potentially misleading.

Check answers:

  1. They were estimated using the behavior policy’s completed rollout and define fixed targets for subsequent optimization.

  2. The additional term is: \[-\ell_t\nabla_\theta G_t\]

  3. Autograd follows graph dependencies, not only numerical values. Equal values can result from graphs with different derivatives.

  4. Inspect whether current policy log-probabilities flow into KL rewards, returns, advantages, reward normalization, or value targets.

  5. Differentiation is appropriate when KL is intentionally included as an explicit regularization objective, with a clearly defined KL direction and coefficient—not accidentally routed through sampled reward targets.

Retrieval answers:

  • Terminal reward belongs at the final valid response token, length - 1.

  • Forward equality does not determine gradient equality; the computation graph determines which derivative paths exist.
