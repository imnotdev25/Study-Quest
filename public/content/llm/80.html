🚀 Starting point

Micro accuracy pools all instances: \(\frac{\text{total correct}}{\text{total evaluated}}\). Macro accuracy averages per-group accuracies, giving each group equal weight. They answer different questions (“how often is a random instance right?” vs “how good is the model on a typical group?”), and they can disagree in direction.

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. If five prompt variants share one entity, what unit should a cluster bootstrap resample?

  2. With unequal variants per entity, why must you define the estimand before averaging?

Suppose evaluation results are divided into \(G\) groups, such as entity types, contexts, or domains. For model \(m\):

\[C_{mg},N_{mg}\in\mathbb{R}^{M\times G}\]

are correct and evaluated counts, with group accuracy:

\[a_{mg}=\frac{C_{mg}}{N_{mg}}\]

Micro accuracy weights every evaluated instance equally:

\[a_m^{\text{micro}} = \frac{\sum_g C_{mg}}{\sum_g N_{mg}} = \sum_g \frac{N_{mg}}{\sum_jN_{mj}}a_{mg}\]

Macro accuracy weights every group equally:

\[a_m^{\text{macro}} = \frac1G\sum_ga_{mg}\]

Neither is universally correct:

  • Micro answers: “How accurate was the model over this observed instance mixture?”

  • Macro answers: “How accurate was the model for an equally likely group?”

  • Target-weighted evaluation uses explicit deployment weights \(w_g\):

\[a_m^{\text{target}} = \sum_gw_ga_{mg}, \qquad \sum_gw_g=1\]

If models are evaluated on different group mixtures—perhaps because of API failures, filtering, or missing predictions—their raw micro scores are not directly comparable. Simpson’s paradox can occur: one model improves in every group yet has worse aggregate accuracy because it was evaluated mainly on harder groups.

✏️ Derivation: micro is a weighted macro, and Simpson’s paradox

Step 1. \(a^{\text{micro}}=\frac{\sum_gC_g}{\sum_gN_g}=\sum_g\frac{N_g}{\sum_jN_j}a_g\): a weighted average of group accuracies, with weights equal to each group’s share of instances.

Step 2. If two models are evaluated on different group mixes, their micro accuracies use different weights, so they can disagree with every per-group comparison.

Step 3. Example: Model A: easy 80/100, hard 10/50, micro \(90/150=0.60\). Model B: easy 45/50, hard 25/100, micro \(70/150=0.47\).

Step 4. B is better in both groups (0.90 vs 0.80 and 0.25 vs 0.20), yet worse in micro, because B was given more hard items.

Step 5. Macro: A \(=0.50\), B \(=0.575\). Macro, or micro with a common fixed mix, removes the mix effect.

⚙️ Algorithm: report micro, macro and per-group accuracy
Input: counts \(C_{mg},N_{mg}\) for models \(m\) and groups \(g\)
\(a_{mg}\gets C_{mg}/N_{mg}\)
micro \(\gets\sum_gC_{mg}/\sum_gN_{mg}\); macro \(\gets\frac1G\sum_ga_{mg}\)
standardized \(\gets\sum_gw_ga_{mg}\) with one fixed mix \(w\) shared by all models
flag any group where models’ order disagrees with the aggregate

Solution — open after attempting

def micro_accuracy(rates, counts):
    correct = rates * counts
    return correct.sum() / counts.sum()


baseline_micro = micro_accuracy(
    baseline_rates,
    baseline_counts,
)

new_micro = micro_accuracy(
    new_rates,
    new_counts,
)

within_group_delta = (
    new_rates - baseline_rates
)

Common weighting:

rates = torch.stack([
    baseline_rates,
    new_rates,
])

macro_scores = rates.mean(dim=1)

target_scores = rates @ target_weights

Observed mixtures and contributions:

baseline_mix = (
    baseline_counts / baseline_counts.sum()
)

new_mix = (
    new_counts / new_counts.sum()
)

baseline_contributions = (
    baseline_mix * baseline_rates
)

new_contributions = (
    new_mix * new_rates
)

The new model improves within every group:

\[[0.97-0.95,\ 0.78-0.75,\ 0.50-0.45] = [0.02,\ 0.03,\ 0.05]\]

But the baseline is evaluated primarily on easy examples, while the new model is evaluated primarily on hard examples. The naive micro comparison therefore confounds model quality with evaluation composition.

Macro and target-weighted scores use common weights, so they reveal the improvement. Macro weighting is not automatically correct, however: it defines a hypothetical population in which every group is equally likely. If deployment is 99% easy traffic, deployment-weighted performance may be the more useful primary estimand.

For failed or missing evaluations, report at least:

  • expected count by model and group;

  • completed count;

  • timeout/error rate;

  • score on a common matched subset;

  • a predefined policy for treating missing predictions.

Silently dropping failures lets model reliability alter both the score and its denominator.

Check answers:

  1. Micro accuracy describes performance over the observed instance distribution; macro accuracy describes the average of group-level performances.

  2. They are identical when all groups have equal counts, assuming the same groups and ordinary unweighted macro averaging.

  3. The models can be evaluated under different group weights, allowing composition effects to dominate every positive within-group difference.

  4. Inspect per-group attempted and completed counts. Hard failures may have been removed from both the numerator and denominator.

  5. The headline result changes depending on whether entity types, contexts, entities, or individual prompts receive equal weight. The weights define the scientific claim.

Retrieval answers:

  • Resample the entity ID and retain its complete collection of variants.

  • Unequal variant counts cause instance-level averaging to give entities with more variants greater influence; entity-balanced and instance-weighted averages therefore estimate different quantities.
