🚀 Starting point

Two different costs: memory traffic (reading the \(T\times T\) attention matrix and the KV cache) and arithmetic (\(O(T^2)\) dot products). A sliding window limits each query to the last \(W\) keys, which cuts both. FlashAttention computes exact attention without ever storing the \(T\times T\) matrix, which cuts memory traffic only.

Each row is a query. With a window, a token reads only its last \(W\) neighbours directly; stacking layers extends the reach to \(L\cdot W\).

✏️ Derivation: sliding-window attention still sees far

Step 1. Mask: query \(i\) attends to \(j\in[i-W+1,i]\). Cost per layer \(O(TW)\), and the cache holds only \(W\) entries.

Step 2. Information moves at most \(W\) positions per layer, so after \(L\) layers a token can be influenced by tokens up to \(L\cdot W\) back.

Step 3. Mistral 7B: \(W=4096\), 32 layers \(\Rightarrow\) theoretical receptive field \(131{,}072\) tokens.

Step 4. Pure windows lose precise long-range recall, so modern models mix them: Gemma 2 alternates local and global 1:1, Gemma 3 and Gemma 4 use 5 local : 1 global, gpt-oss alternates a 128-token window with full attention.

✏️ Derivation: online softmax: the identity behind FlashAttention

Step 1. Goal: \(o=\sum_j\frac{e^{s_j}}{\sum_ke^{s_k}}v_j\) for one query, processing keys in blocks, never holding all \(s\).

Step 2. Keep three running values: max \(m\), normalizer \(\ell=\sum e^{s_j-m}\), and unnormalized output \(a=\sum e^{s_j-m}v_j\).

Step 3. A new block with scores \(s^{(b)}\): \(m'=\max(m,\max s^{(b)})\). Every old term had \(e^{s-m}\), and it now needs \(e^{s-m'}=e^{s-m}e^{m-m'}\). So rescale by \(c=e^{m-m'}\): \(\ell'=c\,\ell+\sum_je^{s^{(b)}_j-m'}\), \(\ a'=c\,a+\sum_je^{s^{(b)}_j-m'}v^{(b)}_j\).

Step 4. After the last block, \(o=a/\ell\), exactly the softmax result (checked numerically below to \(10^{-16}\)).

Step 5. Blocks fit in fast on-chip SRAM, so the \(T^2\) scores never touch slow HBM. Backward stores only \(m\) and \(\ell\) per row and recomputes scores, trading cheap FLOPs for expensive memory traffic.

import math
import torch

s, v = torch.randn(37, dtype=torch.float64), torch.randn(37, 4, dtype=torch.float64)
m, l, acc = torch.tensor(-math.inf, dtype=torch.float64), 0.0, torch.zeros(4, dtype=torch.float64)
for sb, vb in zip(s.split(8), v.split(8)):          # process keys 8 at a time
    m_new = torch.maximum(m, sb.max())
    c = torch.exp(m - m_new)                         # rescale old sums to the new max
    l = l * c + torch.exp(sb - m_new).sum()
    acc = acc * c + (torch.exp(sb - m_new)[:, None] * vb).sum(0)
    m = m_new
print((acc / l - torch.softmax(s, 0) @ v).abs().max())   # ~1e-16

FlashAttention tiles the \(T\times T\) score matrix. No tile is ever written to slow memory; the online-softmax update above stitches the tiles together exactly.

⚙️ Algorithm: FlashAttention forward (one query block)
Input: query block \(Q_i\), key/value blocks \(K_j,V_j\) streamed from memory
\(m\gets-\infty\); \(\ell\gets0\); \(A\gets0\)
for each key block \(j\) (skip blocks entirely in the masked future) do
\(S\gets Q_iK_j^\top/\sqrt d\) (+ mask); \(m'\gets\max(m,\operatorname{rowmax}S)\)
\(P\gets e^{S-m'}\); \(c\gets e^{m-m'}\)
\(\ell\gets c\ell+\operatorname{rowsum}P\); \(A\gets cA+PV_j\); \(m\gets m'\)
end
\(O_i\gets A/\ell\); save \(\LSE_i=m+\log\ell\) for backward
