🚀 Starting point

Order matters in a mixed-precision step: several operations (unscaling, overflow checking, clipping) are only correct when applied to the true gradient \(g\), not the scaled \(Sg\). The scale \(S\) exists only to protect the backward pass. Everything after it should see unscaled values.

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. Why must accumulated token losses share one global denominator?

  2. When is averaging independently normalized microbatch losses valid?

Mixed precision accelerates tensor operations and reduces activation memory, but FP16 has limited range. Small gradients may underflow to zero; large scaled values may overflow to infinity.

For parameters and gradients:

\[\theta,g\in\mathbb{R}^{P}\]

loss scaling computes:

\[L_s=S L\]

so that:

\[g_s = \nabla_\theta L_s = S\nabla_\theta L = Sg\]

After backward:

\[g=\frac{g_s}{S}\]

Scaling preserves the mathematical update while moving intermediate values into a safer numerical range.

The correct step order is:

\[\text{scaled backward} \rightarrow \text{unscale} \rightarrow \text{finite check} \rightarrow \text{clip} \rightarrow \text{optimizer step}\]

Clipping before unscaling is wrong. If:

\[\|g_s\|=S\|g\|\]

and you clip \(g_s\) to threshold \(c\), the effective unscaled threshold becomes:

\[\frac{c}{S}\]

Dynamic scaling reduces \(S\) after overflow and may increase it after sustained successful steps. If any microbatch overflows during gradient accumulation, the complete accumulated update is normally discarded.

BF16 has fewer mantissa bits than FP16 but approximately FP32’s exponent range, so it generally needs less loss scaling.

✏️ Derivation: why unscale before clipping

Step 1. After backward, the stored gradient is \(g_s=Sg\), with norm \(\|g_s\|=S\|g\|\).

Step 2. Clipping \(g_s\) at threshold \(\tau\) uses coefficient \(c=\min(1,\tau/(S\|g\|))\). In true units that’s a threshold of \(\tau/S\): with \(S=65{,}536\), almost every step gets clipped to a tiny update.

Step 3. Unscale first, \(g=g_s/S\), then clip: \(c=\min(1,\tau/\|g\|)\), the intended threshold.

Step 4. Overflow check before the step: if any \(g_s\) is infinite, \(g\) is too, and the whole update must be skipped. Clipping an infinite norm gives \(c=0\) or NaN, which silently wastes or corrupts the step.

Step 5. Scaler update last: decide to halve or grow \(S\) only after knowing whether this step overflowed.

⚙️ Algorithm: mixed-precision training step (correct order)
Input: model, optimizer, scaler with scale \(S\), clip threshold \(\tau\)
forward under autocast; backward on \(S\cdot L\) (accumulate microbatches if needed)
unscale: \(g\gets g_s/S\) ▷ scaler.unscale_(optimizer)
if any \(g\) is \(\infty\) or NaN then
skip the step; \(S\gets S/2\)
else
clip global norm of \(g\) to \(\tau\); optimizer step; possibly grow \(S\)
end
zero gradients

def simulate_scaled_backward(coefficients, scale):
    parameter = torch.ones(
        coefficients.numel(),
        requires_grad=True,
    )

    loss = (
        parameter * coefficients
    ).sum()

    scaled_gradient = torch.autograd.grad(
        scale * loss,
        parameter,
    )[0]

    stored_gradient = scaled_gradient.half()

    return stored_gradient


dynamic_scale = 2.0**14

for attempt in range(3):

correct_clipped = clip_by_global_norm(

The first gradient, \(10^{-8}\), disappears when directly represented in FP16. Scaling by \(4096\) moves it to approximately:

\[4.096\times10^{-5}\]

which survives low-precision storage. Dividing in FP32 recovers an approximation of the original gradient. Scaling does not create information or improve the exact gradient; it prevents representable information from being prematurely lost.

The initial dynamic scale overflows:

\[8\cdot2^{14}=131072\]

which exceeds the largest finite FP16 value, approximately \(65504\). The update must be skipped because unscaling an infinity does not recover the original value. Halving twice produces \(S=4096\), where the scaled gradient is finite.

For clipping, the correct result has norm \(2\). Clipping first in scaled space produces:

\[\left\| \frac{\operatorname{clip}(Sg,2)}{S} \right\| = \frac{2}{1024}\]

so the update is almost eliminated.

Check answers:

  1. Multiplying and subsequently dividing by the same scale leaves the intended gradient unchanged while shifting intermediate magnitudes into the representable range.

  2. The effective threshold is \(1/4096\).

  3. Inspect gradients before and after unscaling, the first nonfinite layer, the current scale, skipped-step count, activation ranges, and whether the forward loss hides an overflowing backward operation.

  4. Changing scale between microbatches makes accumulated gradients represent different units; one unscale operation can no longer recover their sum correctly.

  5. BF16 retains FP32’s broad exponent range, making overflow and underflow less frequent, although its reduced mantissa precision introduces different rounding concerns.

Retrieval answers:

  • Accumulated token losses require one global denominator so every valid token receives equal weight.

  • Averaging microbatch means is valid when their effective observation counts are equal, or when each mean is explicitly weighted by its count.
