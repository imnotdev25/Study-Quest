🚀 Starting point

Training happens once; inference happens every time anyone uses the model. Inference engineering is making that cheap and fast without changing the answers. Real-life version: a restaurant kitchen. The recipe (the model) is fixed. What you control is how many orders the cooks work on at once (batching), how much counter space each order takes (KV memory), whether two orders that start the same share prep (prefix caching), and whether a junior cook can prepare a guess that the head chef just checks (speculative decoding).

The inference stack. Levels of the craft go bottom-up: using an engine, tuning it, changing it, writing kernels.

Levels

  1. Run a model and serve it over HTTP (Hugging Face generate, then vLLM or SGLang).

  2. Measure: TTFT, TPOT, throughput, goodput under an SLO, at realistic load.

  3. Tune one GPU: batch limits, memory fraction, chunked prefill, prefix caching, quantisation.

  4. Scale: tensor, pipeline, expert and context parallelism; prefill/decode disaggregation; routing.

  5. Build: kernels in Triton or CUDA, scheduler changes, a new engine feature.

Prerequisites, and where they are in this book

Memory math is bytes per parameter times parameters (below). Vectors, dot products, softmax and sampling: Toolkit I and the decoding sessions. Transformers, RoPE, GQA and MLA: Sessions 6–10 and the Architectures part. Running remotely on a GPU: the post-training book’s Modal chapter (no SSH or driver setup needed; nvidia-smi inside a Modal function shows the GPU). The first lab is the minimal path:

pip install vllm==0.32.0
vllm serve Qwen/Qwen3-8B --max-model-len 8192 --gpu-memory-utilization 0.9
curl localhost:8000/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model": "Qwen/Qwen3-8B", "messages": [{"role": "user", "content": "Hi"}], "stream": true}'

vllm serve has no authentication by default; pass --api-key or keep it behind a private network.
