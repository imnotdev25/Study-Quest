🚀 Starting point

Gradient accumulation splits a batch that doesn’t fit in memory into \(K\) microbatches, runs backward on each, and lets PyTorch add the gradients into .grad. It reproduces the full batch exactly only if each microbatch’s loss is scaled so that the scaled losses sum to the full-batch loss.

Total: 20 minutes

1. Concept refresh — 5 minutes

Quick retrieval:

  1. Why can changing .mean() to .sum() destabilize optimization?

  2. In LoRA, why does initializing \(B=0\) preserve the pretrained function?

Suppose a batch contains \(N\) loss elements:

\[L=\frac{1}{N}\sum_{i=1}^{N}\ell_i\]

Split it into \(K\) microbatches. Exact gradient accumulation computes:

\[\nabla_\theta L = \sum_{k=1}^{K} \nabla_\theta \left( \frac{\sum_{i\in\mathcal M_k}\ell_i}{N} \right)\]

Because PyTorch accumulates into .grad, calling backward() once per microbatch produces the full-batch gradient—provided the scaling is correct.

A common approximation is:

\[\frac{1}{K}\sum_{k=1}^{K}\operatorname{mean}_{i\in\mathcal M_k}\ell_i\]

This is exact only when every microbatch has the same number of contributing elements. For language modeling, sequences may contain different numbers of unmasked tokens, so averaging per-microbatch means can incorrectly give short examples more weight.

Practical sequence:

zero gradients → backward each scaled microbatch
→ clip accumulated gradients → optimizer step → scheduler step

Gradient accumulation reduces activation memory by processing fewer examples at once. It does not reduce parameter or optimizer-state memory.

✏️ Derivation: exact accumulation, and when the shortcut is wrong

Step 1. Full-batch loss \(L=\frac1N\sum_{i=1}^N\ell_i\). Gradients are linear: \(\nabla L=\frac1N\sum_i\nabla\ell_i\).

Step 2. Group the sum by microbatch \(\mathcal M_k\): \(\nabla L=\sum_k\nabla\Big(\frac{1}{N}\sum_{i\in\mathcal M_k}\ell_i\Big)\). So microbatch \(k\) should backpropagate \(\frac{S_k}{N}\), with \(S_k\) its loss sum and \(N\) the global count.

Step 3. The common shortcut backpropagates \(\frac{1}{K}\cdot\frac{S_k}{n_k}\) (its own mean, divided by \(K\)). Comparing coefficients, element \(i\in\mathcal M_k\) gets weight \(\frac{1}{Kn_k}\) instead of \(\frac1N\).

Step 4. They agree iff \(Kn_k=N\) for all \(k\), i.e. every microbatch has the same size. With masks (variable valid tokens), they almost never do.

Step 5. Example: \(n=(2,8)\), losses 1 and 3 per element. Correct: \(\frac{2+24}{10}=2.6\). Shortcut: \(\frac12(1+3)=2.0\).

⚙️ Algorithm: exact gradient accumulation
Input: microbatches \(\mathcal M_1..\mathcal M_K\) with per-element losses and masks
\(N\gets\) total valid elements over all microbatches (and all ranks)
zero gradients
for \(k=1,\dots,K\) do
\(S_k\gets\sum_{i\in\mathcal M_k}m_i\ell_i\); backward on \(S_k/N\)
end
one optimizer step

2. PyTorch exercise — 10 minutes

Compare one full-batch gradient with accumulation over uneven microbatches.

import copy
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(71)

B, D, C = 7, 5, 3
X = torch.randn(B, D)
target = torch.randn(B, C)

base = nn.Linear(D, C, bias=False)
initial_state = copy.deepcopy(base.state_dict())

microbatches = [
    (X[:2], target[:2]),   # 2 examples
    (X[2:], target[2:]),   # 5 examples
]


def fresh_model():
    model = nn.Linear(D, C, bias=False)
    model.load_state_dict(initial_state)
    return model


# Reference: one full batch
full = fresh_model()
full_loss = ...                              # TODO 1: global mean MSE
full_loss.backward()
full_grad = full.weight.grad.clone()          # [C, D]


# Correct accumulation
accum = fresh_model()
accum.zero_grad(set_to_none=True)

for xb, yb in microbatches:
    micro_loss_sum = ...                      # TODO 2: summed MSE
    scaled_loss = ...                         # TODO 3: divide by global count
    ...                                       # TODO 4: accumulate backward

accum_grad = accum.weight.grad.clone()


# Common bug: equally average unequal microbatch means
wrong = fresh_model()
wrong.zero_grad(set_to_none=True)

for xb, yb in microbatches:
    wrong_loss = ...                          # TODO 5
    wrong_loss.backward()

wrong_grad = wrong.weight.grad.clone()

print("full vs exact:",
      (full_grad - accum_grad).abs().max().item())
print("full vs wrong:",
      (full_grad - wrong_grad).abs().max().item())

assert torch.allclose(full_grad, accum_grad, atol=1e-6)
assert not torch.allclose(full_grad, wrong_grad, atol=1e-6)

3. Checks for understanding — 5 minutes

  1. With four equal-sized microbatches, how can each mean-reduced loss be scaled to reproduce the full-batch mean gradient?

  2. Why is that rule insufficient when microbatches contain different numbers of valid tokens?

  3. Debugging: accumulated gradients are exactly four times larger than expected. What scaling step was probably omitted?

  4. Should gradient clipping happen after every microbatch or after the complete accumulation window? Why?

  5. If one optimizer update covers eight microbatches, how often should a per-update learning-rate scheduler normally advance?

Solution — open after attempting

# Reference
full = fresh_model()
full_loss = F.mse_loss(full(X), target, reduction="mean")
full_loss.backward()
full_grad = full.weight.grad.clone()


# Exact accumulation
accum = fresh_model()
accum.zero_grad(set_to_none=True)

for xb, yb in microbatches:
    micro_loss_sum = F.mse_loss(
        accum(xb), yb, reduction="sum"
    )
    scaled_loss = micro_loss_sum / target.numel()
    scaled_loss.backward()

accum_grad = accum.weight.grad.clone()


# Incorrect weighting
wrong = fresh_model()
wrong.zero_grad(set_to_none=True)

for xb, yb in microbatches:
    wrong_loss = (
        F.mse_loss(wrong(xb), yb, reduction="mean")
        / len(microbatches)
    )
    wrong_loss.backward()

wrong_grad = wrong.weight.grad.clone()

Putting zero_grad() inside the loop erases earlier contributions, leaving only the final microbatch’s gradient.

For token-level training, the exact denominator is usually:

\[N_{\text{valid}} = \sum_{b,t}\mathbf 1[y_{b,t}\neq\text{ignore\_index}]\]

Each microbatch should contribute its summed valid-token loss divided by the total valid-token count across the accumulation window.

Check answers:

  1. Divide every microbatch’s mean loss by four before backward().

  2. Equal averaging weights microbatches equally rather than weighting every valid token equally.

  3. The loss was probably not divided by the number of accumulation steps or the appropriate global element count.

  4. Clip after all microbatches; clipping each one separately changes their vector sum and therefore the update direction.

  5. Once per optimizer update, not once per microbatch.

Retrieval answers:

  • .sum() multiplies gradient scale by the number of contributing elements relative to .mean().

  • With \(B=0\), the initial LoRA update \(BA\) is zero, so the layer initially matches its frozen base model.
