🚀 Starting point

A rotation by angle \(\theta\) in the plane is \(R(\theta)=\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix}\). Rotations keep lengths, satisfy \(R(\theta)^\top=R(-\theta)\), and compose by adding angles: \(R(a)R(b)=R(a+b)\). RoPE rotates each pair of query and key features by an angle proportional to the token’s position.

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. At decoding step \(t\), what are the shapes of the query and KV cache?

  2. Why can cached decoding diverge from full decoding even when the cached keys and values are concatenated correctly?

Self-attention alone is permutation-equivariant: without positional information, it cannot distinguish different token orders.

Rotary Position Embeddings (RoPE) rotate pairs of query and key features according to their positions. For one feature pair:

\[R(\theta_m) \begin{bmatrix} x_0\\x_1 \end{bmatrix} = \begin{bmatrix} \cos\theta_m&-\sin\theta_m\\ \sin\theta_m&\cos\theta_m \end{bmatrix} \begin{bmatrix} x_0\\x_1 \end{bmatrix}\]

For head dimension \(d_h\), RoPE uses \(d_h/2\) frequencies:

\[\omega_i=10000^{-2i/d_h}\]

\[\theta_{m,i}=m\omega_i\]

Given:

\[Q,K\in\mathbb{R}^{B\times H\times T\times d_h}\]

RoPE preserves the same tensor shape and vector norms. Its useful property is:

\[(R_mq)^\top(R_nk) = q^\top R_{n-m}k\]

Thus attention scores encode relative displacement \(n-m\), despite applying absolute-position rotations.

During cached decoding:

  • Cached keys retain the rotations for their original positions.

  • The new query and key must use the current absolute position.

  • After a prefill of length \(P\), the first generated token uses position \(P\), not zero.

A wrong cache position offset often produces plausible but incorrect outputs—more dangerous than an immediate shape error.

✏️ Derivation: RoPE scores depend only on relative position

Step 1. For one feature pair at frequency \(\omega\), position \(m\) uses \(R_m=R(m\omega)\).

Step 2. Score between query at \(m\) and key at \(n\): \((R_mq)^\top(R_nk)=q^\top R_m^\top R_nk\).

Step 3. \(R_m^\top R_n=R(-m\omega)R(n\omega)=R((n-m)\omega)=R_{n-m}\).

Step 4. So the score is \(q^\top R_{n-m}k\): absolute positions entered, but only the offset \(n-m\) survives. The full head applies \(d_h/2\) such pairs with \(\omega_i=10000^{-2i/d_h}\).

Step 5. Norm preservation: \(\|R_mq\|=\|q\|\), so RoPE doesn’t change the scale of scores (Session 7’s \(\sqrt d\) argument still holds).

Step 6. Cache offset: after a prefill of length \(P\), the first new token must use \(m=P\). Using \(m=0\) makes it look like the start of the sequence relative to every cached key, giving plausible but wrong outputs.

⚙️ Algorithm: apply RoPE with a cache offset
Input: \(Q,K\in\mathbb R^{B\times H\times T\times d_h}\), starting position \(p_0\) (\(=\) cache length)
positions \(m\gets p_0,\dots,p_0+T-1\); \(\omega_i\gets10000^{-2i/d_h}\)
\(\theta_{m,i}\gets m\omega_i\)
for each pair \((x_{2i},x_{2i+1})\) of \(Q\) and \(K\) do
\((x_{2i},x_{2i+1})\gets(x_{2i}\cos\theta-x_{2i+1}\sin\theta,\ x_{2i}\sin\theta+x_{2i+1}\cos\theta)\)
end
cache the rotated \(K\); never re-rotate cached keys

def apply_rope(x, positions):
    L = x.shape[-2]

    angles = positions[:, None] * inv_freq[None, :]

    cos = angles.cos()[None, None, :, :]
    sin = angles.sin()[None, None, :, :]

    pairs = x.view(B, H, L, d_h // 2, 2)
    even = pairs[..., 0]
    odd = pairs[..., 1]

    rotated_even = even * cos - odd * sin
    rotated_odd = even * sin + odd * cos

    rotated_pairs = torch.stack(
        [rotated_even, rotated_odd],
        dim=-1,
    )

    return rotated_pairs.flatten(-2)


def full_attention():
    positions = torch.arange(T)

    q = apply_rope(Q, positions)
    k = apply_rope(K, positions)

    scores = (
        q @ k.transpose(-2, -1)
    ) / math.sqrt(d_h)

    mask = torch.tril(
        torch.ones(T, T, dtype=torch.bool)
    )

    scores = scores.masked_fill(~mask, float("-inf"))
    weights = torch.softmax(scores, dim=-1)

    return weights @ V

    V_cache = None

A rotation is orthogonal, so it preserves vector norms:

\[\lVert R_mx\rVert_2=\lVert x\rVert_2\]

The buggy implementation assigns position zero to every token. Position zero still matches because its correct angle is zero. Later tokens lose their relative-position rotations, changing attention scores and outputs.

Check answers:

  1. RoPE divides features into two-dimensional pairs, so an unpaired feature is not supported here.

  2. The query-key dot product contains the relative rotation: \[R_m^\top R_n=R_{n-m}\]

  3. No. If both use the identical rotation: \[(R_mq)^\top(R_mk)=q^\top k\]

  4. The generation position probably restarted at zero rather than continuing from the prefill length.

  5. Cached keys already encode their original positions. Rotating them again changes those positions and performs unnecessary work.

Retrieval answers:

  • At step \(t\), the query is [B,H,1,d_h]; each cache is [B,H,t+1,d_h].

  • Correct cache contents are insufficient if the new query/key use the wrong positional index.
