🚀 Starting point

Every model in this part is a stack of the blocks from Sessions 6–10: attention to mix tokens, an MLP to process each token, normalization, and residual connections. Architectures differ in four choices: (1) which tokens may attend to which (bidirectional, causal, or both), (2) the training objective, (3) how attention is made cheaper for long inputs, and (4) how parameters are spent (dense or mixture-of-experts).

Three families

  • Encoder-only (BERT, RoBERTa, ELECTRA): bidirectional attention, so every token sees every other. Great for understanding tasks such as classification and retrieval, but it can’t generate text left to right.

  • Encoder–decoder (T5, BART): a bidirectional encoder reads the input, and a causal decoder writes the output while cross-attending to the encoder.

  • Decoder-only (GPT, LLaMA, DeepSeek, Qwen, Kimi): causal attention and next-token prediction (Session 11). This family won: one objective, any task phrased as text, and scaling that keeps paying off.

✏️ Derivation: what every block costs (the numbers the rest of this part tries to reduce)

Step 1. Parameters per dense block \(\approx12D^2\) (Session 10): \(4D^2\) attention, \(8D^2\) MLP.

Step 2. Attention compute per layer, per sequence: \(QK^\top\) and \(AV\) each cost \(T^2D\) multiply-adds, so \(O(T^2D)\). Quadratic in length.

Step 3. KV cache per token per layer: \(2\cdot n_{kv}\cdot d_h\) numbers (keys and values, Session 23). With full multi-head attention, \(n_{kv}d_h=D\).

Step 4. The rest of this part attacks these one at a time: MoE cuts the active share of step 1, GQA/MLA/compression cut step 3, and sliding windows, sparse attention and linear attention cut step 2.
