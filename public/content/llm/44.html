🚀 Starting point

Autoregressive decoding generates one token at a time and feeds it back in. Under a causal mask, the keys and values of past tokens never change once computed. A KV cache stores them, so each new step computes only the new token’s \(q,k,v\) and attends over the cache.

Total: 20 minutes

1. Retrieval + concept refresh — 5 minutes

Quick retrieval:

  1. In causal attention, why can token \(t\) attend only to keys \(0,\ldots,t\)?

  2. If a shared parameter is used by two computation-graph branches, how are its gradient contributions combined?

During full-sequence causal attention:

\[Q,K,V\in\mathbb{R}^{B\times T\times d}\]

\[O=\operatorname{softmax} \left( \frac{QK^\top}{\sqrt d}+M \right)V\]

During autoregressive generation, previous tokens do not change. Recomputing their keys and values at every decoding step is wasteful, so each layer caches them.

At step \(t\):

\[q_t\in\mathbb{R}^{B\times1\times d}\]

\[K_{\le t},V_{\le t}\in\mathbb{R}^{B\times(t+1)\times d}\]

\[S_t=\frac{q_tK_{\le t}^{\top}}{\sqrt d} \in\mathbb{R}^{B\times1\times(t+1)}\]

\[o_t=\operatorname{softmax}(S_t)V_{\le t} \in\mathbb{R}^{B\times1\times d}\]

No causal mask is required for this single newest query: the cache contains no future tokens.

The cache avoids repeatedly projecting old tokens and computing outputs that will be discarded. Attention for the new token still reads the entire prefix, however, so total attention work across \(T\) generated tokens remains quadratic.

For \(L\) layers and \(H\) heads, KV-cache storage is proportional to:

\[2BLHTd_h\]

The factor two represents keys and values. Cache layout, position offsets, dtype, and beam reordering are common inference correctness bugs.

✏️ Derivation: the cache gives the same answer, and what it costs

Step 1. Full causal attention, row \(t\): \(o_t=\sum_{j\le t}\operatorname{softmax}_j\big(q_t^\top k_j/\sqrt d\big)v_j\). It depends only on \(q_t\) and \(k_{\le t},v_{\le t}\).

Step 2. Each \(k_j=x_jW_K\) depends only on token \(j\) (within one layer, and its input depends only on tokens \(\le j\)). So \(k_{<t}\) computed at earlier steps is identical. Caching them changes nothing mathematically.

Step 3. Projection cost without a cache: step \(t\) recomputes \(t\) keys and values, \(O(tD^2)\), so generating \(T\) tokens costs \(O(T^2D^2)\). With a cache: \(O(TD^2)\) for projections plus \(O(T^2D)\) for attention.

Step 4. Memory: \(2\times\text{layers}\times H\times d_h\times T\times B\) numbers. Example: 32 layers, 32 heads, \(d_h=128\), \(T=4096\), \(B=1\), FP16: \(2\cdot32\cdot32\cdot128\cdot4096\cdot2\) bytes \(=2\) GiB.

Step 5. Why outputs can still differ: different kernels and orders of summation (one long matmul vs many small ones) round differently. Expect tiny numerical gaps, not a different argmax every token.

⚙️ Algorithm: greedy decoding with a KV cache
Input: prompt \(x_{0:P-1}\), max new tokens \(N\)
prefill: run the model on the whole prompt, store \(K,V\) per layer; \(y\gets\arg\max\) of the last logits
for \(n=1,\dots,N\) do
run one token \(y\) at position \(P+n-1\): per layer compute \(q,k,v\), append \(k,v\) to the cache, attend \(q\) over the cache
\(y\gets\arg\max(\text{logits})\); stop at EOS
end

Solution — open after attempting

def full_causal_attention(X):
    Q = X @ W_q
    K = X @ W_k
    V = X @ W_v

    scores = (
        Q @ K.transpose(-2, -1)
    ) / math.sqrt(d)

    mask = torch.tril(
        torch.ones(T, T, dtype=torch.bool)
    )

    scores = scores.masked_fill(~mask, float("-inf"))
    weights = torch.softmax(scores, dim=-1)

    return weights @ V


def cached_attention(X, replace_cache=False):
    K_cache = None
    V_cache = None
    outputs = []

    for t in range(T):
        x_t = X[:, t:t + 1]

        q_t = x_t @ W_q
        k_t = x_t @ W_k
        v_t = x_t @ W_v

        if K_cache is None or replace_cache:
            K_cache = k_t
            V_cache = v_t
        else:
            K_cache = torch.cat([K_cache, k_t], dim=1)
            V_cache = torch.cat([V_cache, v_t], dim=1)

        scores_t = (
            q_t @ K_cache.transpose(-2, -1)
        ) / math.sqrt(d)

        weights_t = torch.softmax(scores_t, dim=-1)
        output_t = weights_t @ V_cache

        outputs.append(output_t)

    return torch.cat(outputs, dim=1), K_cache, V_cache

At t=3, four tokens have been processed:

\[q_t:[B,1,d],\qquad K_{\text{cache}}:[B,4,d]\]

\[S_t:[B,1,4]\]

When the cache is replaced, every query attends only to its current token. Position zero still matches because it has no earlier context anyway. Later positions differ because all previous keys and values have been discarded.

Check answers:

  1. At zero-based step \(t\):

    \[q_t:[B,1,d],\quad K_{\text{cache}}:[B,t+1,d],\quad S_t:[B,1,t+1]\]

  2. The cache contains only the current and previous tokens; no future key exists to mask.

  3. Cache memory doubles because it is linear in length. Total attention work grows by roughly four because \(\sum_{t=1}^{T}t=O(T^2)\).

  4. Likely causes include replacing instead of appending the cache, concatenating on the wrong dimension, caching queries instead of keys, using an incorrect positional offset, or mismatching cached and full-pass dtypes.

  5. Each cache entry belongs to a particular hypothesis. Reordering beams without identically reordering their caches attaches the wrong history to each continuation.

Retrieval answers:

  • Causal masking prevents a query from reading keys belonging to future positions.

  • Contributions from multiple branches into a shared parameter are added.
