🚀 Starting point

Rank: a matrix \(BA\) with \(B\in\mathbb R^{d_{\text{out}}\times r}\), \(A\in\mathbb R^{r\times d_{\text{in}}}\) has rank at most \(r\): it maps everything through an \(r\)-dimensional bottleneck. LoRA assumes fine-tuning changes a weight matrix by a low-rank amount, \(\Delta W=\frac{\alpha}{r}BA\), and trains only \(A,B\) while \(W\) stays frozen.

Total: 20 minutes

1. Concept refresh — 5 minutes

Quick retrieval:

  2. Why can prompt embeddings receive gradients when prompt labels are ignored?

A full linear layer uses:

\[y=xW^\top\]

with:

\[x\in\mathbb{R}^{B\times d_{\text{in}}}, \qquad W\in\mathbb{R}^{d_{\text{out}}\times d_{\text{in}}}\]

LoRA freezes \(W\) and learns a low-rank update:

\[W'=W+\frac{\alpha}{r}BA\]

where:

\[A\in\mathbb{R}^{r\times d_{\text{in}}}, \qquad B\in\mathbb{R}^{d_{\text{out}}\times r}\]

The forward pass becomes:

\[y=xW^\top+\frac{\alpha}{r}xA^\top B^\top\]

Instead of training \(d_{\text{out}}d_{\text{in}}\) parameters, LoRA trains:

\[r(d_{\text{in}}+d_{\text{out}})\]

Typically, \(A\) starts small and random while \(B=0\). Therefore, the adapter initially changes nothing:

\[BA=0\]

This preserves the pretrained model’s initial outputs. A subtle consequence is that \(A\)’s first-step gradient is zero because the backward path passes through the zero-initialized \(B\).

✏️ Derivation: LoRA gradients and why \(B\) starts at zero

Forward: \(y=xW^\top+\frac{\alpha}{r}\,(xA^\top)B^\top\), with upstream \(G=\partial L/\partial y\in\mathbb R^{N\times d_{\text{out}}}\). Let \(u=xA^\top\in\mathbb R^{N\times r}\).

Step 1. \(y\) is linear in \(B^\top\) with input \(u\): \(\frac{\partial L}{\partial B}=\frac{\alpha}{r}G^\top u\in\mathbb R^{d_{\text{out}}\times r}\).

Step 2. Gradient flowing to \(u\): \(\frac{\partial L}{\partial u}=\frac{\alpha}{r}GB\in\mathbb R^{N\times r}\).

Step 3. \(u=xA^\top\): \(\frac{\partial L}{\partial A}=\big(\tfrac{\partial L}{\partial u}\big)^\top x=\frac{\alpha}{r}(GB)^\top x\in\mathbb R^{r\times d_{\text{in}}}\).

Step 4. Init: \(A\) random, \(B=0\). Then \(\Delta W=0\), so the model starts exactly at the pretrained weights. At step 0, \(\partial L/\partial A=0\) (it contains \(B\)) but \(\partial L/\partial B=\frac{\alpha}{r}G^\top xA^\top\ne0\), so \(B\) moves first and then \(A\) starts learning.

Step 5. Parameter count: \(r(d_{\text{in}}+d_{\text{out}})\) instead of \(d_{\text{in}}d_{\text{out}}\). For \(d=4096\), \(r=8\): 65,536 vs 16.8M, which is 0.39%.

Step 6. Why \(\alpha/r\): with \(A\) entries of fixed scale, \(BA\) sums \(r\) terms, so dividing by \(r\) keeps the update’s size roughly independent of the rank you choose.

⚙️ Algorithm: LoRA linear layer
Input: frozen \(W\), rank \(r\), scale \(\alpha\)
init \(A\sim\) Kaiming-uniform \((r\times d_{\text{in}})\), \(B\gets0\) \((d_{\text{out}}\times r)\); only \(A,B\) require gradients
forward: \(y\gets xW^\top+\frac{\alpha}{r}(xA^\top)B^\top\)
after training, merge for inference: \(W\gets W+\frac{\alpha}{r}BA\)

Solution — open after attempting

class LoRALinear(nn.Module):
    def __init__(self, in_features, out_features, rank=2, alpha=4):
        super().__init__()

        self.rank = rank
        self.scale = alpha / rank

        self.base = nn.Linear(
            in_features,
            out_features,
            bias=False,
        )
        self.base.weight.requires_grad_(False)

        self.A = nn.Parameter(
            torch.randn(rank, in_features) * 0.02
        )

        self.B = nn.Parameter(
            torch.zeros(out_features, rank)
        )

    def forward(self, x):
        base_output = self.base(x)
        low_rank = x @ self.A.T
        adapter_output = low_rank @ self.B.T

        return base_output + self.scale * adapter_output

Weight merging:

with torch.no_grad():
    merged_weight = (
        layer.base.weight
        + layer.scale * (layer.B @ layer.A)
    )

    merged_output = F.linear(x, merged_weight)

Initially \(B=0\). For the adapter path:

\[y_{\text{adapter}}=xA^\top B^\top\]

The gradient into \(A\) contains \(B\), so:

\[\frac{\partial L}{\partial A}=0\]

on the first step. The gradient into \(B\) depends on \(xA^\top\), which is generally nonzero. Once \(B\) updates, gradients can reach \(A\).

Check answers:

  1. LoRA trains:

\[8(4096+4096)=65{,}536\]

parameters instead of:

\[4096^2=16{,}777{,}216\]

This is about \(256\times\) fewer parameters for that matrix.

  1. Since \(B=0\), \(BA=0\), so the adapter initially adds exactly zero.

  2. The first update makes \(B\) nonzero, opening a gradient path into \(A\).

  3. Possible causes include detaching the adapter output, excluding adapters from the optimizer, running under no_grad(), setting the LoRA scale to zero, or both factors being zero-initialized.

  4. LoRA reduces trainable-parameter gradients, optimizer state, and checkpoint size. Activation memory and backpropagation through the frozen model can remain substantial.

Retrieval answers:

  • Logit position \(s-1\) predicts the first response token at position \(s\).

  • Response loss propagates through causal attention into the prompt representations, even when prompt tokens have no direct loss.
