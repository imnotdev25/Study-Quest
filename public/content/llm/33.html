🚀 Starting point

Supervised fine-tuning trains on (prompt \(x\), response \(y\)) pairs. We want the model to learn how to respond, not to imitate prompts, so the objective is the conditional likelihood \(p_\theta(y\mid x)\). In code, this is the next-token loss with the prompt positions masked out (label \(-100\) in PyTorch).

Total: 20 minutes

1. Concept refresh — 5 minutes

Quick retrieval:

  1. For causal LM training, which logits predict input_ids[:, 1:]?

  2. Why should padding targets contribute zero gradient?

An SFT sequence commonly contains:

\[[\text{prompt},\ \text{response},\ \text{EOS},\ \text{padding}]\]

For response-only training, labels for prompt and padding tokens are replaced by -100:

\[\text{labels} = [-100,\ldots,-100,\ y_1,\ldots,y_R,\text{EOS},-100,\ldots]\]

The shifted objective is:

\[L= -\frac{1}{N} \sum_{(b,t)\in\mathcal V} \log p_\theta(\text{labels}_{b,t+1}\mid x_{b,\leq t})\]

If the response begins at position \(s\), its first token is predicted by:

\[\text{logits}[:,s-1,:]\]

This boundary is easy to mask incorrectly.

Important distinction: ignoring prompt labels removes direct prompt-token prediction losses. It does not prevent prompt representations or embeddings from receiving gradients, because response predictions depend on the prompt through causal attention.

✏️ Derivation: response-only loss is conditional likelihood

Step 1. Chain rule over the concatenation: \(\log p_\theta(x,y)=\underbrace{\sum_{t\in\text{prompt}}\log p(x_t\mid x_{<t})}_{\log p_\theta(x)}+\underbrace{\sum_{t\in\text{resp}}\log p(y_t\mid x,y_{<t})}_{\log p_\theta(y\mid x)}\).

Step 2. Masking prompt labels deletes the first sum, leaving \(\log p_\theta(y\mid x)\): exactly the conditional we want.

Step 3. Boundary: if the response starts at position \(s\), its first token \(y_1=x_s\) is predicted by logits at \(s-1\), the last prompt position. That logit must be kept. Masking it drops the model’s most important decision: how to begin.

Step 4. EOS: including EOS as a label teaches \(p(\text{stop}\mid x,y)\). Without it, the model never learns to end.

Step 5. Reduction: dividing by the number of response tokens \(N=\sum M\) gives each response token equal weight. Dividing by \(B\cdot T\) shrinks the loss of short responses and changes the effective learning rate between batches.

⚙️ Algorithm: build response-only SFT labels
Input: prompt ids \(p_{1:P}\), response ids \(r_{1:R}\), EOS id, pad length
\(\text{input}\gets[p,r,\text{EOS},\text{pad}\dots]\)
\(\text{labels}\gets[-100]^P\,\|\,[r,\text{EOS}]\,\|\,[-100]^{\text{pad}}\)
loss \(=\) causal LM loss with the usual shift; labels \(-100\) are ignored
check: \(\sum M=R+1\) per example, and the first unmasked label is \(r_1\)

3. Checks for understanding — 5 minutes

  1. Why should EOS generally remain a supervised response token?

  2. If a response starts at index \(s\), which logit position predicts its first token?

  3. Why can prompt embeddings receive gradients even when every prompt label is -100?

  4. Debugging: responses are fluent but rarely stop naturally. Which masking error should you investigate?

  5. Token averaging and example averaging produce different training weights. Which one gives long responses greater influence?

Solution — open after attempting

positions = torch.arange(T)[None, :]

response_mask = positions >= response_start[:, None]
response_mask &= input_ids.ne(pad_id)

labels = input_ids.clone()
labels = labels.masked_fill(
    ~response_mask,
    ignore_index,
)

shift_logits = logits[:, :-1, :]
shift_labels = labels[:, 1:]

valid_tokens = shift_labels.ne(ignore_index).sum()

The resulting labels are:

[-100, -100, -100, 21, 22, 2, -100, -100]
[-100, -100,   31, 32, 33, 2, -100, -100]

There are seven supervised targets:

  • Row 0: 21, 22, EOS

  • Row 1: 31, 32, 33, EOS

The incorrect prediction-position mask drops the first response token from each sequence:

  • 21 from row 0

  • 31 from row 1

The correct mask supervises target positions. Once labels are constructed correctly, the normal causal shift automatically pairs the preceding prompt logit with the first response token.

Check answers:

  1. EOS teaches the model when to terminate. Masking it can encourage unnecessarily long or truncated-by-limit generations.

  2. Position \(s-1\).

  3. Response states attend to prompt states, so response loss backpropagates through the prompt’s contextual computation.

  4. Check whether EOS labels were masked, removed during preprocessing, or truncated.

  5. Token averaging gives longer responses more influence because each valid token receives equal weight.

Retrieval answers:

  • Use logits[:, :-1, :] to predict input_ids[:, 1:].

  • Padding targets must be ignored because they are batching artifacts rather than desired model outputs.
