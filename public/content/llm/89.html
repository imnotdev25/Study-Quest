🚀 Starting point

Why fine-tune? Prompting changes what the model is asked; fine-tuning changes what it does by default: format, tone, domain vocabulary, tool use. Try prompting and retrieval first. Fine-tune when you need consistent behaviour, lower latency (shorter prompts), or a smaller model to match a bigger one on a narrow task.

LoRA

✏️ Derivation: LoRA’s update, its initialisation and its cost

Step 1. Freeze \(W\in\mathbb R^{d_o\times d_i}\) and learn \(\Delta W=\frac\alpha rBA\) with \(B\in\mathbb R^{d_o\times r}\), \(A\in\mathbb R^{r\times d_i}\).

Step 2. Initialise \(B=0\), \(A\) random: at step 0, \(\Delta W=0\) and the model is exactly the base model. \(B\) still gets a gradient, \(\partial L/\partial B=\frac\alpha r\,G^\top(XA^\top)\), which is nonzero because \(A\ne0\).

Step 3. Trainable parameters \(r(d_i+d_o)\) instead of \(d_id_o\): for \(d=256,r=8\) that is 4,096 vs 65,536; for a 4096-wide layer at \(r=16\), 0.8%.

Step 4. After training, merge \(W'=W+\frac\alpha rBA\): zero extra inference cost.

QLoRA and NF4

QLoRA stores the frozen \(W\) in 4 bits and trains LoRA adapters in bf16 on top; the forward pass dequantises each block on the fly. Pretrained weights are roughly normal, so NF4 puts its 16 levels at quantiles of \(\mathcal N(0,1)\) (each level gets about equal probability mass), scaled to \([-1,1]\), with an exact zero. Each block of 64 weights stores one absmax scale. Double quantisation stores those scales in 8 bits with one fp32 scale per 256 blocks: \[4+\tfrac{32}{64}=4.5\ \text{bits/param}\quad\longrightarrow\quad4+\tfrac{8}{64}+\tfrac{32}{64\cdot256}\approx4.127\ \text{bits/param}.\]

"""Toolkit ch. 7: LoRA from scratch, and the NF4 quantisation inside QLoRA."""
import math
import torch

torch.manual_seed(0)


class LoRALinear(torch.nn.Module):
    """y = x W^T + (alpha/r) x A^T B^T, with W frozen, A random, B zero (so it starts as W)."""

    def __init__(self, base: torch.nn.Linear, r=8, alpha=16):
        super().__init__()
        self.base = base.requires_grad_(False)
        self.A = torch.nn.Parameter(torch.randn(r, base.in_features) / math.sqrt(base.in_features))
        self.B = torch.nn.Parameter(torch.zeros(base.out_features, r))
        self.scale = alpha / r

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T) @ self.B.T

    def merge(self):
        return self.base.weight + self.scale * self.B @ self.A


d = 256
base = torch.nn.Linear(d, d, bias=False)
delta = 0.1 * torch.randn(d, 4) @ torch.randn(4, d) / 2          # the "task" is a rank-4 change
target = base.weight.detach() + delta
layer = LoRALinear(base, r=8)
X = torch.randn(4096, d)
print(f"[lora] starts equal to base: {torch.allclose(layer(X[:4]), base(X[:4]))}")
print(f"[lora] trainable {sum(p.numel() for p in layer.parameters() if p.requires_grad):,}"
      f" vs full {d * d:,}")
opt = torch.optim.Adam([layer.A, layer.B], lr=3e-3)
for step in range(601):
    idx = torch.randint(0, len(X), (256,))
    loss = ((layer(X[idx]) - X[idx] @ target.T) ** 2).mean()
    opt.zero_grad(); loss.backward(); opt.step()
    if step % 200 == 0:
        print(f"[lora] step {step:3d}  loss {loss.item():.5f}")
with torch.no_grad():
    print(f"[lora] merged weight error {(layer.merge() - target).norm() / delta.norm():.3f} (relative to ||delta||)")


# NF4: 16 levels at quantiles of N(0,1), rescaled to [-1, 1], with an exact zero.
def nf4_levels(offset=0.9677083):
    icdf = lambda p: math.sqrt(2) * torch.erfinv(2 * p - 1)
    pos = icdf(torch.linspace(offset, 0.5, 9)[:-1])                # 8 positive levels
    neg = -icdf(torch.linspace(offset, 0.5, 8)[:-1])               # 7 negative levels
    v = torch.cat([pos, torch.zeros(1), neg]).sort().values
    return v / v.abs().max()


def quantize(w, levels, block=64):
    wb = w.reshape(-1, block)
    absmax = wb.abs().max(1, keepdim=True).values                  # one scale per block
    codes = ((wb / absmax)[..., None] - levels).abs().argmin(-1)   # 4-bit index per weight
    return (levels[codes] * absmax).reshape(w.shape)


NF4 = nf4_levels()
INT4 = torch.linspace(-1, 1, 16)
print(f"[nf4] levels {[round(v, 3) for v in NF4.tolist()]}")
W = torch.randn(4096, 4096) * 0.02
for name, lv in (("int4 uniform", INT4), ("nf4", NF4)):
    err = (quantize(W, lv) - W).pow(2).mean() / W.pow(2).mean()
    print(f"[nf4] {name:12s} relative MSE {err:.4f}")

# Memory: 4 bits per weight + fp32 absmax per 64 weights, or 8-bit absmax with one fp32 per 256 blocks.
plain = 4 + 32 / 64
double = 4 + 8 / 64 + 32 / (64 * 256)
print(f"[nf4] bits/param: single quant {plain:.3f}, double quant {double:.3f}")
for name, params in (("8B", 8e9), ("70B", 70e9)):
    print(f"[mem] {name}: bf16 weights {params * 2 / 2**30:6.1f} GiB  nf4+dq {params * double / 8 / 2**30:5.1f} GiB")

Data, hyperparameters and evaluation

  • Data: a few thousand clean, deduplicated examples beat a large noisy set. Format with the model’s own chat template, and mask the loss to assistant tokens only (Part 0’s masking rules).

  • Hyperparameters: LoRA learning rates are about 10\(\times\) full fine-tuning (\(1\text{--}2\times10^{-4}\)); \(r=16\), \(\alpha=16\text{--}32\), adapters on all linear layers; 1–3 epochs; cosine schedule with a short warmup.

  • Evaluation: hold out a test set before you look at the data; compare against the base model with a good prompt; track a general benchmark too, to catch forgetting; report confidence intervals (Sessions 43–47).

  • Deployment: merge the adapter, or serve many adapters over one base model (vLLM supports this).
