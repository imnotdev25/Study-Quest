Model lifecycle

  • Package: a container with a pinned engine version; weights pulled from object storage or a volume at start (not baked into the image), verified by checksum.

  • Warm-up: load weights, capture CUDA graphs, run a few requests; only then report ready. Separate liveness (process alive) from readiness (can serve within SLO).

  • Versioning and canaries: every response carries the model version; send 1–5% of traffic to a new version, compare error rate, latency and an online quality signal, then ramp or roll back.

  • Multi-model: many LoRA adapters over one base (next chapter), or separate replicas per model with a router in front.

Routing and autoscaling

A load balancer that ignores the cache throws away prefix hits: consecutive turns of one conversation land on different replicas and re-prefill. Prefix-aware routing sends a request to the replica that holds its prefix (hash of the conversation or the longest cached prefix), with a load guard that falls back to the least-loaded replica when the preferred one is backed up. Queue-aware routing uses each replica’s waiting count and KV usage, not just open connections. Autoscale on queue depth or KV usage, not GPU utilisation (which reads near 100% at any load), and keep warm capacity because a cold start (pull weights, load, capture graphs) takes minutes. Ray Serve and Kubernetes (with KServe or llm-d) provide the machinery.

"""Inference chs. 'Routing and Autoscaling', 'Economics': prefix-aware routing simulation and cost math."""
from collections import OrderedDict

import numpy as np

rng = np.random.default_rng(0)

# Routing: 8 replicas, each with an LRU prefix cache. Requests continue Zipf-popular conversations.
R, N_CONV, N_REQ, CACHE = 8, 400, 6000, 25
ranks = np.arange(1, N_CONV + 1)
popularity = 1 / ranks**1.1 / (1 / ranks**1.1).sum()
conv_len = np.zeros(N_CONV)
arrivals = np.cumsum(rng.exponential(1 / 40, N_REQ))     # 40 req/s
convs = rng.choice(N_CONV, N_REQ, p=popularity)


def simulate(policy):
    caches = [OrderedDict() for _ in range(R)]
    free_at = np.zeros(R)
    clen = np.zeros(N_CONV)
    ttft, hits, total, rr = [], 0, 0, 0
    for t, c in zip(arrivals, convs):
        prompt = clen[c] + rng.integers(100, 400)
        backlog = np.maximum(free_at - t, 0)
        if policy == "round robin":
            r = rr % R; rr += 1
        elif policy == "least loaded":
            r = int(backlog.argmin())
        else:                                               # prefix-aware with a load guard
            r = c % R
            if backlog[r] > backlog.min() + 0.5:
                r = int(backlog.argmin())
        cached = caches[r].get(c, 0)                       # prefix this replica holds for c
        hits += cached; total += prompt
        service = (prompt - cached) * 25e-6 + 0.02          # prefill only what is not cached
        start = max(t, free_at[r])
        free_at[r] = start + service
        ttft.append(free_at[r] - t)
        caches[r][c] = prompt; caches[r].move_to_end(c)
        if len(caches[r]) > CACHE:
            caches[r].popitem(last=False)
        clen[c] = prompt + rng.integers(100, 300)
    ttft = np.array(ttft)
    return hits / total, np.median(ttft), np.percentile(ttft, 99)


for pol in ("round robin", "least loaded", "prefix-aware"):
    h, p50, p99 = simulate(pol)
    print(f"[route] {pol:13s}  prefix hit rate {h:5.1%}  TTFT p50 {p50 * 1e3:6.1f} ms  p99 {p99 * 1e3:7.1f} ms")

🔑 Key ideas

  • In the simulation, round robin and least-loaded both miss the right replica often enough that uncached prefills build queues: p99 TTFT of 13–26 s. Prefix-aware routing keeps p99 near 110 ms on the same 8 replicas.

  • Cost per token is GPU price divided by goodput. The prices in the code are placeholders; the method is the point.

Observability, reliability and security

Track request metrics (TTFT, ITL, E2E percentiles, goodput, error rate), engine metrics (running, waiting, KV usage, preemptions, prefix hit rate) and GPU metrics (DCGM: memory, SM activity, temperature, XID errors). Trace a request across router, engine and tokenizer with one trace id. Protect the service with admission control (reject early with 429 when the queue would break the SLO, rather than accepting work you will time out), per-request timeouts and max-token limits, and retries only for idempotent failures. Chaos-test by killing a replica under load and checking that the router drains it. Security: authenticate every request, rate-limit per key, cap prompt and output length, never log raw prompts that may hold user data without a retention policy, and treat model output fed to tools as untrusted input.

Inference economics

\[\text{\$ per 1M tokens}=\frac{\text{\$/GPU-hour}}{\text{goodput tokens/s}\times3600}\times10^6,\] \[\text{replicas}=\Big\lceil\frac{\text{peak rate}}{\text{SLO-good rate per replica}}\times\text{headroom}\Big\rceil.\] Epoch AI’s Inference economics of language models makes the deeper point: there is a frontier between speed per user and cost per token, set by batch size, and serving at very low latency costs much more per token because it forfeits batching.
