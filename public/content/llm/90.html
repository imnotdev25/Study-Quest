🚀 Starting point

A research paper is an argument: one claim, the evidence for it, and the strongest objections answered. The code and the writing are the same project.

  1. Claim first. Write the one-sentence contribution before running anything. It decides which experiment is the main one.

  2. Baselines that could win. Tune the baseline with the same budget as your method. Most “improvements” disappear against a tuned baseline.

  3. Seeds and intervals. Run at least 3–5 seeds and report mean \(\pm\) a bootstrap 95% interval (Session 43). On benchmarks with \(n\) items, the standard error of accuracy is \(\sqrt{p(1-p)/n}\): on 500 questions at 70%, about 2 points. Gaps smaller than that are noise.

  4. Ablations. Remove one component at a time; each row of the table should answer “is this part needed?”.

  5. Reproducibility. Pin versions, log configs and commits with every run (MLflow or W&B), and release code with one command per table.

  6. Writing order: figures and tables, then method, experiments, introduction, abstract last. Post to arXiv; submit to a venue or workshop for review.
